# 第四批 crosschunk data 结构优化

生成时间：2026-03-25 13:13:54
文件名：2026-03-25_131354_第四批crosschunk_data结构优化.md

## 任务背景

命令层与配置层的主拆分已基本完成，当前最大的结构债已转移到 `crosschunk data` 簇。
其中 `CrossChunkDispatchService.java` 约 1500 行，同时承担“排队入口、重试循环、目标区块唤醒、强制加载票据、常驻票据同步、状态缓存”等多重职责，继续放大会显著拉低可维护性与回归可读性。

本批目标是在**不改变既有行为、协议、命令语义与测试口径**的前提下，先对 `CrossChunkDispatchService` 做第一轮 helper 化收口。

## 方案详情

### 现状分析

- `CrossChunkDispatchService` 当前包含两块最重职责：
  1. 排队入口与批量 upsert 组装；
  2. 运行时 pending 刷队列、重试退避、目标区块加载唤醒。
- 当前测试中大量使用反射直接访问 `CrossChunkDispatchService` 的私有方法与内部记录/状态类，因此不适合一次性把这些内部结构完全移出服务壳。
- 强制加载票据 / resident 白名单票据逻辑虽然也较重，但与 ticket 常量、服务态缓存耦合更深，适合作为下一步再拆。

### 技术方案

本轮只做一阶拆分，不改行为：

1. 新增 `CrossChunkDispatchQueueSupport`
   - 承担：
     - activation/sync queue policy 解析
     - ttl / expire tick 计算
     - 单条与批量 queue 组装
     - 批量 rejected 结果构造
   - `CrossChunkDispatchService` 保留原方法名，仅改为委托到 helper，保证反射测试入口不变。

2. 新增 `CrossChunkDispatchRuntimeSupport`
   - 承担：
     - pending 快照刷队列
     - tryDispatch
     - retry state 裁剪 / 清理
     - retry failure 记录与 staged backoff
     - 目标区块加载唤醒索引维护
   - 同样保留 `CrossChunkDispatchService` 现有私有方法名，对测试仍可见。

3. `CrossChunkDispatchService` 本轮保留：
   - 公开 API
   - 服务端事件注册
   - `STATE_BY_SERVER`
   - 强制加载 / resident ticket 相关方法
   - 内部状态类与记录类型

4. 为让 helper 能复用现有内部状态类型，放宽部分嵌套记录 / 状态类访问级别到包内可见，但**不改类名、不改签名、不改语义**。

### 影响范围

- `src/main/java/com/makomi/data/CrossChunkDispatchService.java`
- `src/main/java/com/makomi/data/CrossChunkDispatchQueueSupport.java`（新增）
- `src/main/java/com/makomi/data/CrossChunkDispatchRuntimeSupport.java`（新增）
- 如有必要，补充少量测试/注释同步

## 原子步骤清单

### 步骤 1：提取排队入口 helper
- **操作对象**：`CrossChunkDispatchService.java`
- **具体动作**：把 queue policy、ttl、单条/批量 upsert 组装迁移到 `CrossChunkDispatchQueueSupport`
- **预期结果**：服务壳中的 queue 入口只保留参数路由与测试兼容入口
- **关键里程碑**：是

### 步骤 2：提取运行时重试 helper
- **操作对象**：`CrossChunkDispatchService.java`
- **具体动作**：把 pending 刷队列、重试状态、目标区块唤醒迁移到 `CrossChunkDispatchRuntimeSupport`
- **预期结果**：服务壳中的运行时循环只保留委托关系
- **关键里程碑**：是

### 步骤 3：最小化开放内部状态类型
- **操作对象**：`CrossChunkDispatchService.java`
- **具体动作**：将 helper 必需的嵌套记录/状态类改为包内可见，保持名称与结构不变
- **预期结果**：helper 可复用现有类型，反射测试仍成立
- **关键里程碑**：否

### 步骤 4：静态与局部测试验证
- **操作对象**：相关源码与测试
- **具体动作**：做语法解析与最小测试回归
- **预期结果**：确认本轮仅为结构重组，无行为回归
- **关键里程碑**：是

## 预期结果

- `CrossChunkDispatchService` 明显瘦身，职责边界更清晰。
- 现有 `CrossChunkDispatchServiceTest` 的反射入口尽量保持不变。
- 强制加载票据与 resident ticket 逻辑留作下一轮继续拆分，避免本轮改动面过大。
