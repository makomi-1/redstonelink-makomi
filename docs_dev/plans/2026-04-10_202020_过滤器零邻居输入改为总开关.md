# 过滤器零邻居输入改为总开关

生成时间：2026-04-10 20:20:20
文件名：2026-04-10_202020_过滤器零邻居输入改为总开关.md

## 任务背景

当前过滤器体系已经改为“放置态参与”，邻居输入不再决定过滤器是否存在。但现有实现中，邻居输入为 0 时过滤器仍会继续参与节点集、黑白名单和信号阈值求值，这与本轮需求不一致。用户要求把邻居输入零态恢复为过滤总开关：当邻居输入为 0 时，该过滤器整体关闭；同时同步修改单测、调度层测试与游戏内自动化用例，并补足“总开关”覆盖，最终以新增相关用例跑通作为本轮收尾条件。

## 方案详情

### 现状分析

- 运行期过滤入口为 `LinkDispatchFilterService -> PlacedLinkFilterSavedData.collectFilters(...) -> LinkFilterRuleEvaluator.allows(...)`。
- `PlacedLinkFilterSavedData` 当前负责按放置态与物理覆盖范围收集过滤器，更适合保留“过滤器存在性”职责。
- `LinkFilterRuleEvaluator` 当前没有对 `neighborSignalStrength <= 0` 做整体门控，因此 zero 邻居下节点集与阈值规则仍会生效。
- 部分单测和游戏内用例已经固化旧契约，尤其是基于 zero 邻居只影响阈值、不影响过滤参与的断言。

### 技术方案

- 在 `LinkFilterRuleEvaluator` 增加统一总开关判断：`neighborSignalStrength <= 0` 时，该过滤器整条规则跳过，等价于未启用。
- 保持 `PlacedLinkFilterSavedData.collectFilters(...)` 不变，仍收集已放置过滤器；这样“是否存在”和“是否启用”职责分离，便于复用现有索引与同步协调逻辑。
- 调整基础单测，使其表达“collect 仍可见，但 zero 邻居下 allows 总体放行”。
- 补充调度层测试，验证 zero 邻居状态切换会传递到 `allowsByKind(...)` 与 `sync` 失效/补发。
- 修改游戏内 `x24/x26` 以匹配新语义，并新增 dedicated `nodeSet` 总开关用例覆盖 send/receive 两侧。

### 影响范围

- 运行期过滤求值：`src/main/java/com/makomi/data/LinkFilterRuleEvaluator.java`
- 基础/调度层测试：`src/test/java/com/makomi/data/**`
- 游戏内自动化 case 与 suite：`tools/bench/cases/functional/**`、`tools/bench/functional-matrix.json`、`tools/bench/suites/regression-core.json`

## 原子步骤清单

### 步骤 1：调整过滤总开关求值
- **操作对象**：`LinkFilterRuleEvaluator`
- **具体动作**：在过滤规则求值入口增加 zero 邻居整体禁用判断，确保节点集、黑白名单、上下界与邻居最大输入等规则在邻居输入为 0 时全部不生效。
- **预期结果**：zero 邻居下过滤器行为等价于“未启用”。
- **关键里程碑**：是

### 步骤 2：更新基础单测
- **操作对象**：`PlacedLinkFilterSavedDataTest`、`LinkFilterRuleEvaluatorTest`
- **具体动作**：调整旧断言并补充恢复非零后重新生效的测试，明确 zero 邻居只关闭过滤器、不删除已放置过滤器视图。
- **预期结果**：基础测试与新语义一致。
- **关键里程碑**：是

### 步骤 3：补充调度层与 sync 测试

- **预期结果**：运行期协调路径被测试覆盖。
- **关键里程碑**：是

### 步骤 4：修改并新增游戏内自动化用例
- **操作对象**：`x24`、`x26` 与新增 dedicated `nodeSet` case
- **具体动作**：把 zero 邻居断言改为“过滤器关闭后链路恢复未过滤状态”，并为 send/receive 新增 `nodeSet` 总开关专用 case。
- **预期结果**：游戏内能直接验证 zero 邻居关闭与恢复启用。
- **关键里程碑**：是
