# 无线化活塞节点搬运与转化器修复

生成时间：2026-05-04 09:12:15
文件名：2026-05-04_091215_无线化活塞节点搬运与转化器修复.md

## 任务背景

上一轮已经落地“无线化转化器 + 无线化拉杆/石按钮/石压力板/活塞/红石灯”的最小闭环，但运行验证中暴露出两类问题：
- 无线化活塞在伸缩和活塞头异常破坏场景下，会触发节点下线、待退役甚至重新分配 serial
- 无线化转化器会消耗连接原件，但没有产出目标物，同时客户端持续打印 `Unknown recipe category`

本轮目标是在不改贴图资源的前提下，修复现有闭环并补一个低风险 core 原型：
- 修复无线化转化器的服务端合成链与客户端 recipe category 映射
- 为无线化活塞补齐“节点搬运而非节点销毁”的移动语义
- 新增无线化海晶灯，作为可被 triggerSource 控制亮灭的 core 方块

## 方案详情

### 现状分析

当前实现中：
- 无线化活塞自己复制了原版 `MOVING_PISTON` 伸缩流程，但节点系统仍把“方块被替换”视为真实物理移除
- `WirelessBlockNodeSupport.unregisterOnRemove(...)` 在方块替换时会直接执行 `markPhysicalRemovalInProgress() + unregisterNode(true)`
- 因此无论是无线化活塞本体，还是被它推动/拉回的无线节点，都会被当成下线甚至待退役对象

无线化转化器这边，运行日志表明：
- 自定义 `wireless_conversion` 配方已经被资源管理器加载
- `Unknown recipe category` 更像客户端配方书分类缺失，不足以单独解释“不会产出”
- 服务端“不产出”更可能落在炉式配方匹配、菜单/配方书桥接，或配方结果读取链路上

### 技术方案

#### 1. 无线化转化器修复

拆成两层修复：
- 服务端合成链：
  - 核对 `WirelessConversionRecipe`、`RecipeType`、`RecipeSerializer` 与 `AbstractFurnaceBlockEntity` 的匹配方式
  - 如需要，补专用菜单/方块实体对 recipe 查找或进度计算的适配
  - 新增无线化海晶灯对应的转化配方
- 客户端分类链：
  - 为 `wireless_conversion` 接入炉类 recipe book category 映射，消除 `Unknown recipe category`
  - 保持当前简化 screen，不额外引入新的图形资源

这样能把“能合成”和“能正确显示分类”分开修正，避免误把客户端警告当作服务端根因。

#### 2. 无线化活塞节点搬运语义

不修改原版活塞，而是只在无线化活塞自己的 `moveBlocks(...)` 路径内增加“节点搬运上下文”：
- 对无线化活塞本体：
  - 伸缩/回缩前提取本体 `core` 身份
  - 伸缩结束后恢复同一 serial，避免本体在移动期间被退役或重分配
- 对被推动/拉回的无线节点：
  - 仅识别本模组无线节点方块实体
  - 在替换前提取 `nodeType + serial + 必要链接快照`
  - 标记为“搬运中”，跳过常规 `unregisterOnRemove(..., enqueuePendingRetire=true)` 路径
  - 目标位置落地后恢复原 serial 并重新注册

实现重点不是“复制一个 NBT”，而是给节点生命周期新增“移动迁移”语义，把“搬运”与“销毁”严格区分。

#### 3. 无线化海晶灯原型

新增 `wireless_sea_lantern`：
- 节点身份：`core`
- 行为：仅响应已连接 `triggerSource` 的激活态
- 发光：用可控 `LIT`/等价状态控制亮度
- 邻居红石：不读取、不输出
- 资源：复用原版海晶灯模型/贴图

该原型可以直接复用无线化红石灯的 core 侧设计，只需替换为海晶灯外壳和状态映射。

## 原子步骤清单

### 步骤 1：修复无线化转化器服务端与客户端链路
- **操作对象**：无线化转化器方块实体、菜单、recipe type/serializer、客户端分类映射
- **具体动作**：核对炉式配方命中逻辑，修复不会产出问题，并为 `wireless_conversion` 增加正确的 recipe category 映射
- **预期结果**：无线化转化器既能实际产出目标物，也不再打印未知分类警告
- **关键里程碑**：是

### 步骤 2：实现无线化节点搬运上下文
- **操作对象**：无线化节点公共支持层、生命周期辅助类
- **具体动作**：新增“节点搬运中”识别、身份提取、目标落地恢复与异常兜底
- **预期结果**：搬运与销毁语义分离，移动中的节点不会被错误退役
- **关键里程碑**：是

### 步骤 3：修复无线化活塞本体 serial 稳定性
- **操作对象**：`WirelessPistonBlock`、`WirelessPistonBlockEntity`
- **具体动作**：在活塞伸缩/回缩链路中保持本体 core serial 不变，并兼容活塞头异常破坏场景
- **预期结果**：无线化活塞自身不再因伸缩而退役或重分配 serial
- **关键里程碑**：是

### 步骤 4：支持无线化活塞推拉无线节点
- **操作对象**：`WirelessPistonBlock.moveBlocks(...)` 及相关辅助类
- **具体动作**：在推/拉前捕获无线节点身份，在目标位置恢复并重新上线注册
- **预期结果**：无线化活塞可推拉无线节点，移动前后保持同一节点身份
- **关键里程碑**：是

### 步骤 5：新增无线化海晶灯最小原型
- **操作对象**：新方块、方块实体、注册、资源与转化配方
- **具体动作**：复用无线化 core 语义实现海晶灯的可控亮灭
- **预期结果**：形成新的低风险 core 原型，并接入无线化转化器
- **关键里程碑**：否

### 步骤 6：回归验证与审查文档

- **关键里程碑**：是

## 预期结果

完成后将达到以下状态：
- 无线化转化器能够正确消耗连接原件并产出无线化目标物
- `wireless_conversion` 不再触发客户端未知 recipe category 警告
- 无线化活塞自身在伸缩和异常场景下保持同一 `core` serial

## 语义对齐说明

- 命名是否仅使用 `triggerSource/core`：是
- 输入/输出结构是否保持方向一致：是，固定为 `triggerSource -> core`
- 文案与注释是否无旧术语泄漏：新增内容要求保持无旧术语输出
- 与 `LinkNodeType` 映射是否一一对应：是，`triggerSource=TRIGGER_SOURCE`，`core=CORE`
- 兼容层是否仅“读旧写新”：是
- 残余风险：
  - 无线化活塞的节点搬运需要跨越 `MOVING_PISTON` 非稳态，若异常中断路径遗漏，仍可能残留少量边界场景
  - 客户端配方书分类映射修复后，若上游 1.21.1 对自定义烹饪配方还有额外限制，可能需要补一轮客户端兼容适配
