# 补充过滤器游戏内测试并执行非压测回归

生成时间：2026-04-10 14:37:52
文件名：2026-04-10_143752_补充过滤器游戏内测试并执行非压测回归.md

## 任务背景

当前 `pn` 提交历史中的过滤器第一版相关实现，已经补齐了运行期失效/补发与实时拦截补偿，但现有游戏内自动化测试仍主要覆盖 attach replay、来源脱附与物理移除等历史链路，缺少“过滤器运行期变化后如何回推既有 `triggerSource -> core` 的 `sync` 贡献”这条新增语义的 dedicated functional 证据。

同时，仓库内已有多套 non-pressure dedicated suite，但并没有单一入口覆盖全部非压测游戏内用例。现有 `regression-full` 仍缺少同区块延迟专项、mixed 逐 tick 专项、mixed 重启专项、OCC 专项与权限专项，因此需要先补齐过滤器自动化用例，再按组合方式完成一轮完整的非压测游戏内回归。

## 方案详情

### 现状分析

- `tools/bench/cases/functional/x14`、`x15`、`x16` 已覆盖过滤器对 attach replay 的筛选边界，但未覆盖运行期过滤器变化。
- `tools/bench/functional-matrix.json` 当前没有任何 case 直接验证本轮新增的过滤器 runtime 失效/补发语义。
- `tools/bench/suites/regression-full.json` 未纳入 `x20/x21/x22/x23`、`x25/r05`、`o01-o04`、`c07/c08`，不能直接代表“所有非压测游戏内测试”。
- 过滤器配置当前主要依赖方块实体配置快照与持久化 `PlacedLinkFilterSavedData`；若 bench 不能稳定通过现有命令/NBT 通道驱动该配置，需要补最小 bench/internal 测试命令兜底。

### 技术方案

1. 先验证过滤器配置是否能通过现有 `command_assert` + `setblock` / `data merge block` 稳定驱动。
2. 若现有路径不足以可靠刷新运行时过滤器真值，则新增最小 bench/internal 过滤器配置命令，只服务测试：
   - 仅接受过滤器位置、过滤器种类与配置快照字段
   - 内部直接调用过滤器方块实体的快照应用入口
   - 不改变业务实现、不新增普通玩家命令入口
3. 新增 2 个 dedicated functional case：
   - send 过滤器运行期变化 case
   - receive 过滤器运行期变化 case
4. 将新增过滤器 case 接入 `functional-matrix.json` 与常规回归 suite。
5. 补齐 dedicated non-pressure 回归执行集合：
   - `regression-full`
   - `restart-mixed-replay`
   - `functional-samechunk-latency-debug`
   - `functional-mixed-direct-debug`
   - `functional-mixed-combinations-direct-debug`
   - `occ-conflict-regression`
   - `server-basic-permission`
6. 按项目规则先构建当前工作区运行 jar，再同步 server jar；如需客户端桥，则复用同一构建产物同步 client jar。
