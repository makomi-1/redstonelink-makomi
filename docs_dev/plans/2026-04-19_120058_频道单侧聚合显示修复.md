# 频道单侧聚合显示修复

生成时间：2026-04-19 12:00:58
文件名：2026-04-19_120058_频道单侧聚合显示修复.md

## 任务背景

当前 graph 前端的频道模式已经支持 `channelHub` 与两类聚合块，但用户反馈：当某个频道只有一侧成员时，画布里不会出现对应聚合块。与此同时，用户还希望明确说明当前“一步撤回草稿”的实现原理。

## 方案详情

### 现状分析

- 频道模式聚合入口在 `buildChannelGraphCanvasView(...)`。
- 当前 `core aggregate` 的生成条件是：
  - `triggerSource` 数量至少为 1
  - `core` 数量至少为 2
- 当前 `triggerSource aggregate` 的生成条件是：
  - `core` 数量至少为 1
  - `triggerSource` 数量至少为 2
- 因此，只要频道里只有单侧成员，即便同侧已经达到聚合人数门槛，也不会生成聚合块。

### 技术方案

本轮只调整频道模式聚合块的显示门槛：

1. 频道 `core aggregate` 仅要求 `core` 成员数量达到聚合门槛。
2. 频道 `triggerSource aggregate` 仅要求 `triggerSource` 成员数量达到聚合门槛。
3. 对侧成员数量不再作为频道聚合块生成的必要条件。
4. 聚合块的连接对象仍保持为 `channelHub`，不改真实保存语义，也不引入新的画布节点类型。

### 技术取舍

- 不改序号模式聚合规则，只修频道模式。
- 不改撤回实现；撤回部分仅在结果汇报中解释“单槽草稿快照”的现有原理。
- 不新增更复杂的频道专属聚合语义，保持复用现有 `GraphCanvasAggregateNode` 与 `channelHub` 结构。

### 影响范围

- `webapp/src/components/graphViewer/canvas.tsx`
- 审查文档与任务汇报

## 原子步骤清单

### 步骤 1：放宽频道单侧聚合门槛
- **操作对象**：`webapp/src/components/graphViewer/canvas.tsx`
- **具体动作**：移除频道两类聚合对“对侧至少 1 个成员”的硬要求，仅保留本侧成员数量门槛
- **预期结果**：频道里只有 `triggerSource` 或只有 `core` 时，也能出现对应聚合块
- **关键里程碑**：是

- **操作对象**：graph 前端频道视图

- **预期结果**：单侧频道聚合块能稳定显示，不引入新的显示错乱
- **关键里程碑**：是
