生成时间：2026-04-10 17:43:48

## 任务背景

现有过滤器 functional case 已覆盖单过滤器的范围、节点集、非零低态与运行期重配置，但还没有验证多过滤器同时存在时的叠加语义。当前需要补三类双过滤器场景：
- `1s1r`：一个 send 过滤器与一个 receive 过滤器叠加到同一路径
- `2r`：两个 receive 过滤器叠加到同一目标
- `2s`：两个 send 过滤器叠加到同一来源

本轮目标是在不改业务实现的前提下，新增有足够判别力的游戏内 case，并仅跑通这些新增双过滤器用例。

## 方案详情

### 现状分析

- 过滤器叠加求值由 `PlacedLinkFilterSavedData.collectFilters -> LinkFilterRuleEvaluator.allows` 统一处理。
- 同侧多过滤器对信号规则采用“所有命中过滤器都必须通过”的收口逻辑。
- send / receive 跨侧路径采用“send 放行且 receive 放行”才允许派发的逻辑。
- 当前 bench 已具备稳定的单过滤器 functional 模板，可直接复用。

### 技术方案

- 新增三条 functional case，而不是把双过滤器叠加到现有 `x27/x28`，以保持断言和定位清晰。
- 设计差异策略：
  - `1s1r`：通过分别让 send 阻断、receive 阻断、两侧同时恢复，验证跨侧 AND。
  - `2r`：用两个 receive 过滤器的不同固定阈值，让“低值只被 lower_bound 挡”“高值只被 upper_bound 挡”“中值同时放行”。
  - `2s`：与 `2r` 对称，验证两个 send 过滤器叠加后的信号收口。
- 以 `fixed_input upper_bound + fixed_input lower_bound` 为主，减少 `neighbor_max_input` 带来的采样抖动。
- 保留“配置切换后补邻居刷新”的测试模板动作，避免 `data merge block` 后运行态真值未及时刷新。
