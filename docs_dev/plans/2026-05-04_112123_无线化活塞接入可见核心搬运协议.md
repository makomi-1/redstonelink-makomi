# 无线化活塞接入可见核心搬运协议

生成时间：2026-05-04 11:21:23
文件名：2026-05-04_112123_无线化活塞接入可见核心搬运协议.md

## 任务背景

当前无线化活塞已经可以推动无线化海晶灯，并且移动后的节点身份可以恢复，说明“移动快照捕获 -> Moving Piston 过渡 -> 落地恢复 serial/NBT”这条链路本身成立。  
但现有可见核心块 `link_redstone_core` 与 `link_redstone_core_transparent` 仍然无法被无线化活塞推动。对比分析后确认，阻塞点不在活塞头，而在两层协议缺口：

1. 结构解析白名单没有放行这两类可见核心，所以仍被原版“带方块实体不可推”限制挡住；
2. 即便强行进入推进链，`LinkCoreBlock.onRemove(...)` 仍会把“被活塞暂时替换成移动方块”当成真实物理销毁，直接注销节点并进入待退役链。

本轮只做最小修复，把可见核心块接入无线化活塞搬运协议，不扩展到 `link_redstone_dust_core`，因为它仍带附着/支撑面生存语义，复杂度更高。

## 方案详情

### 现状分析

- `WirelessPistonStructureResolver` 当前只对白名单无线化原型块放宽 `hasBlockEntity` 限制。
- `LinkCoreBlock.onRemove(...)` 没有区分“真实销毁”与“无线化活塞搬运中”，会直接 `markPhysicalRemovalInProgress()` 并 `unregisterNode(true)`。
- `WirelessPistonNodeMoveSupport.restoreMovedNode(...)` 已能恢复任意 `PairableNodeBlockEntity` 的快照，但恢复后的“core 外显状态校正”目前只特判 `WirelessCoreBlockEntity`，没有覆盖现有 `LinkCoreBlockEntity` 体系。

### 技术方案

1. 在 `WirelessPistonStructureResolver` 中把 `link_redstone_core` 与 `link_redstone_core_transparent` 纳入可搬运白名单。
2. 在 `LinkCoreBlock.onRemove(...)` 中接入“搬运中豁免”：
   - 若当前坐标处于 `WirelessPistonNodeMoveSupport.isMoveInProgress(...)`，则不执行节点注销；
   - 同时跳过这次移除导致的主动邻居扇出，避免把“搬运中的临时替换”误判为真实拆除。
3. 在 `WirelessPistonNodeMoveSupport.restoreMovedNode(...)` 中把“恢复后 blockstate 同步”从 `WirelessCoreBlockEntity` 放宽到基类 `ActivatableTargetBlockEntity`，这样现有可见核心块落地后也能按自身派生态校正外显状态。

### 影响范围

- 无线化活塞结构解析：`WirelessPistonStructureResolver`
- 可见核心块移除语义：`LinkCoreBlock`
- 节点移动恢复后的外显状态校正：`WirelessPistonNodeMoveSupport`
- 继承关系影响：`LinkTransparentCoreBlock` 由于继承 `LinkCoreBlock`，会自动获得同样修复

## 原子步骤清单

### 步骤 1：放行可见核心进入无线化活塞结构解析
- **操作对象**：`WirelessPistonStructureResolver`
- **具体动作**：把 `link_redstone_core` 与 `link_redstone_core_transparent` 纳入可搬运节点白名单
- **预期结果**：无线化活塞在结构解析阶段不再因 `hasBlockEntity` 限制拒绝这两类核心块
- **关键里程碑**：是

### 步骤 2：为可见核心补“搬运中不是销毁”语义
- **操作对象**：`LinkCoreBlock`
- **具体动作**：在 `onRemove(...)` 中识别 `WirelessPistonNodeMoveSupport.isMoveInProgress(...)`，移动中跳过注销与移除扇出
- **预期结果**：可见核心被无线化活塞替换成移动方块时不再退役、不再误触发拆除链
- **关键里程碑**：是

### 步骤 3：恢复后统一校正 core 外显状态
- **操作对象**：`WirelessPistonNodeMoveSupport`
- **具体动作**：把恢复后 blockstate 校正从 `WirelessCoreBlockEntity` 放宽到 `ActivatableTargetBlockEntity`
- **预期结果**：可见核心落地后也能正确恢复 active/blockstate 外显
- **关键里程碑**：否

### 步骤 4：编译与回归验证
- **操作对象**：Gradle 构建与测试任务
- **具体动作**：串行执行 `compileJava`、`compileClientJava`，再执行全标签测试门禁
- **预期结果**：确认修复未引入编译回归，并记录测试结果
- **关键里程碑**：是

## 预期结果

完成后，无线化活塞应当能够推动 `link_redstone_core` 与 `link_redstone_core_transparent`，并在搬运过程中保留原 serial 与节点功能；回缩或移动结束后，核心块不会因临时替换被误退役或误当作拆除处理。
