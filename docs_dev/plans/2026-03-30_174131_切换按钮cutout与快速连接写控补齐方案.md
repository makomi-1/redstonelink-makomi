# 切换按钮cutout与快速连接写控补齐方案

生成时间：2026-03-30 17:41:31
文件名：2026-03-30_174131_切换按钮cutout与快速连接写控补齐方案.md

## 任务背景

上一轮已经将连接同步拉杆与连接脉冲按钮切到 `cutout` 渲染，但连接切换按钮仍保留半透明链路。同时，快速连接工具虽然部分复用了写控服务，但在“将一批 triggerSource 应用到 core”时仍未正确接入 limited 模式的“最大设置量”限制，需要补齐到与现有 `link set` 语义一致。

## 方案详情

### 现状分析

- `LINK_TOGGLE_BUTTON` 仍注册在 `RenderType.translucent()`，相关 block/item model 也保留 `minecraft:translucent`。
- `QuickLinkApplyService` 在 `triggerSource -> core` 批量应用路径里逐个来源调用写控，但 `setSize` 固定传 `1`，导致 limited 模式的批量限制失效。
- 你已明确：写控失败反馈继续保留笼统的“没有足够权限”，不做 readonly/limited/protected 细分提示。

### 技术方案

1. 将 `LINK_TOGGLE_BUTTON` 的客户端渲染层和相关模型统一改为 `cutout`。
2. 在 quick-link 的 `triggerSource 缓存 -> core` 路径中，按本次缓存批量数量传递 `setSize` 给 `LinkWriteControlService`。
3. 将 quick-link 写控拒绝统一映射为 `message.redstonelink.permission.insufficient`。
4. 补最小测试与使用说明，保证行为可追溯。

### 影响范围

- 连接切换按钮的世界渲染与物品栏渲染
- quick-link 服务端应用写控语义
- quick-link 测试与使用说明

## 原子步骤清单

### 步骤 1：调整连接切换按钮渲染层
- **操作对象**：`RedstoneLinkClient` 与 `link_toggle_button` 相关模型
- **具体动作**：将 `LINK_TOGGLE_BUTTON` 改为 `cutout`，并同步修改 block / inventory / item model 的 `render_type`。
- **预期结果**：切换按钮不再使用半透明混合。
- **关键里程碑**：是

### 步骤 2：补齐 quick-link limited 写控
- **操作对象**：`QuickLinkApplyService`
- **具体动作**：在 `triggerSource 缓存 -> core` 路径中，将写控判定的 `setSize` 改为本次缓存数量。
- **预期结果**：quick-link 批量应用真正受 `limited.maxSetSize` 限制。
- **关键里程碑**：是

### 步骤 3：统一 quick-link 权限失败反馈
- **操作对象**：`QuickLinkApplyService`
- **具体动作**：将 quick-link 写控拒绝统一映射为笼统权限不足提示。
- **预期结果**：反馈符合当前交互要求。
- **关键里程碑**：否

### 步骤 4：补测试与说明
- **操作对象**：quick-link 测试、`docs_dev/使用说明.md`
- **具体动作**：补最小测试，并在使用说明中补记 quick-link 也受服务端写控限制。
- **预期结果**：本轮规则调整具备回归证据和说明文档。
- **关键里程碑**：否

## 预期结果

- 连接切换按钮的放置态与物品栏渲染将与前两种按钮/拉杆保持一致，统一去半透明。
- quick-link 在将一批 triggerSource 应用到 core 时，会正确受服务端写控 limited 模式限制。
- quick-link 写控失败时继续给出统一的权限不足提示。
