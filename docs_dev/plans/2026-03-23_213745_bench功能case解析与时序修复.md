# bench功能case解析与时序修复

生成时间：2026-03-23 21:37:45

## 任务背景
- bench 功能 suite 在重新安装 datapack 后已能正常构场并执行 case，但输入器相关 case 仍大量失败。
- 失败结果显示两类问题叠加：
  1. bench 对批量 `node trace` 回显的解析不正确，同一行多条采样只保留了最后一条。
  2. 输入器 case 仍使用 `node trace latest` 做即时判定，容易被 RCON 命令延迟打乱相位，导致高低相断言错位。

## 方案详情

### 现状分析
- `tools/bench/run-bench.ps1` 的 `Parse-NodeTraceSamples` 仅按换行切分回显，而当前 RCON 返回会把多条 `[RedstoneLink/NodeTrace]` 拼接在同一行。
- 输入器功能矩阵 `tools/bench/functional-matrix.json` 在 `input start` 后立即执行 `trace latest`，对真实世界 tick 的相位没有对齐能力。
- `triggerSource` 的 trace 采样实现位于 `NodeRuntimeProbe`，当前读取的是 emitter 实时输入强度；从代码看它应能包含输入器模拟输入，因此现象更像 bench 采样时序问题，而不是节点语义错误。

### 技术方案
- 修复 bench 的 trace 文本切分与字段解析：
  - 支持单行多条 `[RedstoneLink/NodeTrace]` 结果。
  - 支持带逗号的 `pos=x, y, z` 字段，避免字段截断。
- 在 bench 新增基于 `node trace read` 的窗口断言能力：
  - 面向每个 serial 单独读取最近 N 条采样。
  - 在窗口内查找“期望周期序列”的任意循环位移，规避命令到达时刻的不确定相位。
- 将输入器相关 case 改为“挂载 sampler + 等待窗口积累 + read 序列断言”：
  - 保留 `pulse`/`toggle` 现有 case，仅依赖解析修复即可恢复通过。
  - `sync` 类 case 主要断言 `core` 输出序列，必要时保留 `triggerSource` 输入序列校验。
