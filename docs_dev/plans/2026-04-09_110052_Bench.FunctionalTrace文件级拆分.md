# Bench.FunctionalTrace 文件级拆分

生成时间：2026-04-09 11:00:52
文件名：2026-04-09_110052_Bench.FunctionalTrace文件级拆分.md

## 任务背景

上一轮已经把 `Invoke-FunctionalPhases` 从超长 `switch` 重构为分发器与独立 handler，但 `tools/bench/lib/Bench.FunctionalTrace.ps1` 整体仍然过大，当前仍承载 serial 解析、模板替换、trace/latency parser、expectation builder、phase runtime 全部职责，文件体量和维护成本依旧偏高。

本轮目标是在不改变外部加载入口、不改变 bench 行为语义和 phase 结构的前提下，把 `Bench.FunctionalTrace.ps1` 进一步重构为“聚合加载器 + 多职责实现文件”。

## 方案详情

### 现状分析

- `Bench.FunctionalTrace.ps1` 当前约 3595 行，函数分布已形成明显职责簇。
- bench 外部依赖面很窄，`Bench.EntryPoint.ps1` 实际只通过 `Invoke-FunctionalPhases` 间接使用该模块。
- `run-bench.ps1` 目前只 dot-source `lib\\Bench.FunctionalTrace.ps1`，因此最稳妥的拆法是保留该入口文件路径不变，把实现下沉到新的子文件。

### 技术方案

- 保留 `tools/bench/lib/Bench.FunctionalTrace.ps1`，改成小型加载器，按固定顺序 dot-source 新文件。
- 新增 4 个职责文件：
  - `Bench.FunctionalTrace.Common.ps1`：serial 解析、模板替换、command/assert 基础 helper
  - `Bench.FunctionalTrace.Trace.ps1`：trace/latency parser、统计、共享 trace helper
  - `Bench.FunctionalTrace.Expectations.ps1`：expectation builder、tick window 匹配
  - `Bench.FunctionalTrace.Phases.ps1`：执行上下文、phase handler、分发器、`Invoke-FunctionalPhases`
- 所有函数名、phase kind、result/check 字段结构、DryRun 行为保持兼容。
- 新文件仍使用 UTF-8（无 BOM）；考虑 Windows PowerShell 5.1 的点载兼容性，注释控制为 ASCII 安全写法，避免再次触发解析问题。

### 影响范围

- `tools/bench/lib/Bench.FunctionalTrace.ps1`
- `tools/bench/lib/Bench.FunctionalTrace.Common.ps1`
- `tools/bench/lib/Bench.FunctionalTrace.Trace.ps1`
- `tools/bench/lib/Bench.FunctionalTrace.Expectations.ps1`
- `tools/bench/lib/Bench.FunctionalTrace.Phases.ps1`
- `docs_dev/plans/`
- `docs_dev/reviews/`
- 必要时 `docs_dev/experiences/`

- **操作对象**：`tools/bench/lib/Bench.FunctionalTrace.ps1`

- **预期结果**：对外加载路径保持不变。
- **关键里程碑**：是

- **操作对象**：`tools/bench/lib/Bench.FunctionalTrace.*.ps1`

- **预期结果**：单文件复杂度显著下降，职责边界清晰。
- **关键里程碑**：是

### 步骤 3：验证 bench 加载链路
- **操作对象**：`run-bench.ps1` 与新拆分文件
- **具体动作**：使用真实 PowerShell 点载方式确认 `Invoke-FunctionalPhases` 仍能通过原入口被加载。
- **预期结果**：文件级拆分不破坏 bench 装载流程。
- **关键里程碑**：是

- **关键里程碑**：是
