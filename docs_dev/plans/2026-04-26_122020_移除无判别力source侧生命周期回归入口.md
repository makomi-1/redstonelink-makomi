## 任务背景

前一轮 dedicated bench 已确认 `x60/r07` 在 same-dimension source-side 拓扑下缺乏独立判别力：远端 `triggerSource` 卸载后，本地 `core` 会随目标上线自动同步来源信息并保持高态，导致用例无法证明“恢复高态”是否真的依赖 `activator`。用户已确认这两个 source-side 生命周期用例可以不再作为有效回归目标。

## 方案详情

### 现状分析

- `repeater-lifecycle-regression.json` 当前仍包含 `x60/r07` 的 `force_load/resident` 四组 prepare 与四组 restart 入口。
- `functional-matrix.json` 仍把 `x60/r07` 作为可执行 functional case 暴露给 bench。
- `docs_dev/保留问题.md` 目前保留了“`x60/r07` 待重设计”的风险条目，但既然确认这两个用例不再需要作为回归目标，这条记录应从风险池移除。

### 技术方案

- 最小化收口，不删除 case 文件本身，只移除回归入口：
  - 从 `tools/bench/suites/repeater-lifecycle-regression.json` 中删除全部 `x60/r07` entries；
  - 从 `tools/bench/functional-matrix.json` 中移除 `x60` 与 `r07` 的 casePath；
  - 更新 suite 描述，明确生命周期专项当前只覆盖 target-side `x61/r08`。
- 同步清理文档：
  - 从 `docs_dev/保留问题.md` 移除 `x60/r07` 这条保留问题；
  - 通过审查文档记录“为何移除而不是继续修”。
