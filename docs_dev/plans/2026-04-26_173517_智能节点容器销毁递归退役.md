# 智能节点容器销毁递归退役

生成时间：2026-04-26 17:35:17
文件名：2026-04-26_173517_智能节点容器销毁递归退役.md

## 任务背景

当前智能节点容器内部库存只是作为 NBT 嵌套存放。容器物品实体被伤害销毁或自然消失时，内部节点物品会一起丢失，但不会进入现有节点退役主流程，导致序号仍保持已分配/未退役状态。需要把容器接入真实销毁判定链，并在销毁时递归退役内部节点。

## 方案详情

### 现状分析

- `SmartNodeContainerItem` 仅负责 GUI、类型切换与出栈放置，没有销毁钩子。
- `LinkNodeRetireEvents` 当前只识别“直接就是节点栈”的物品实体，不会递归展开容器内部物品。
- `LinkRetireCoordinator` 已经能够统一处理普通节点与转发器双身份退役，适合作为递归退役的唯一入口。

### 技术方案

- 给智能节点容器补 `onDestroyed(ItemEntity)`，沿用现有物品销毁判定中的“伤害触发 DISCARDED 标记”语义。
- 在 `LinkNodeRetireEvents` 的物品实体卸载主流程中增加容器分支：对 `KILLED`、伤害导致的 `DISCARDED` 与自然消失路径递归读取容器内部节点并退役；低年龄拾取/主动丢弃路径继续跳过。
- 新增一个专门的容器递归退役辅助服务，读取容器内部 `ItemStack`，筛出有效节点/转发器，逐个调用 `LinkRetireCoordinator.retireAndSyncWhitelist(...)`，并跳过仍在线的节点序号，避免误删已放置节点。
- 补一组最小回归测试，覆盖“容器内部节点销毁递归退役”和“转发器双身份一起退役”。

### 影响范围

- 物品销毁入口：`SmartNodeContainerItem`
- 节点退役主流程：`LinkNodeRetireEvents`
- 新增容器递归退役服务：`data` 层
- 测试：`src/test/java/com/makomi/data/`

## 原子步骤清单

### 步骤 1：接入容器销毁标记
- **操作对象**：`SmartNodeContainerItem`、`LinkNodeRetireEvents`
- **具体动作**：为容器物品实体补充销毁标记能力，并复用现有“低年龄 DISCARDED 不退役”的边界判定。
- **预期结果**：容器物品实体能被正确识别为真实销毁还是拾取卸载。
- **关键里程碑**：是

### 步骤 2：实现容器内部节点递归退役
- **操作对象**：新增 `data` 辅助服务、`LinkRetireCoordinator`
- **具体动作**：读取容器内容，筛出有效节点和转发器并逐个退役，跳过空槽、非法栈与仍在线节点。
- **预期结果**：容器销毁时，内部节点不再静默丢失而是进入统一退役流程。
- **关键里程碑**：是

### 步骤 3：接入物品实体卸载主流程
- **操作对象**：`LinkNodeRetireEvents`
- **具体动作**：在现有普通节点销毁退役旁新增容器分支，并记录日志 outcome。
- **预期结果**：容器在 `KILLED`、伤害 `DISCARDED`、自然消失时都能递归退役内部节点。
- **关键里程碑**：是

### 步骤 4：补测试与验证
- **操作对象**：测试、Gradle 全量回归
- **具体动作**：补单测，执行 `compileJava/compileClientJava` 与 `test testIntegration testClient testSlow`。
- **预期结果**：容器销毁递归退役行为有自动化证据支撑。
- **关键里程碑**：是

## 预期结果

- 智能节点容器物品实体被真实销毁后，内部节点会自动退役。
- 玩家拾取或正常持有容器时，不会误触退役。
- 转发器内部节点仍遵循 `core/triggerSource` 双身份统一退役语义。
