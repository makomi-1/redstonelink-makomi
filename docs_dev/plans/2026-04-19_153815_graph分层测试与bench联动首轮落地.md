# graph分层测试与bench联动首轮落地

生成时间：2026-04-19 15:38:15
文件名：2026-04-19_153815_graph分层测试与bench联动首轮落地.md

## 任务背景

当前仓库已经接入 graph 前端单测、组件测试与浏览器级 E2E 冒烟，但 graph 成功链路覆盖仍不完整；后端 graph 导出与保存协议也缺少成体系的 JSON 契约测试；bench functional 侧尚未具备 graph 专用的稳定入口，无法在 dedicated server 场景下验证 graph 导出、预检、保存的真实链路。

本轮目标是按分层顺序推进：

1. 先补齐第 1 层前端稳定测试和第 2 层前后端契约测试；
2. 在第 1、2 层全部跑通后，再实现第 3 层 bench functional 联动；
3. 全过程保持 `triggerSource/core` 语义，不引入 `com.makomi.api.v1.*` 依赖，不改业务真值语义。

## 方案详情

### 现状分析

- 前端已具备 `Vitest + jsdom + @testing-library/react + user-event + Playwright` 基础设施，`GraphViewer`、`GraphPage`、`App`、`graphTypes`、`draft`、`search`、`canvas` 已有基础回归。
- 后端已有 `GraphSnapshotJsonSupportTest`、`StatePanelNetworkPayloadTest` 等图相关稳定契约测试，但缺少 `GraphWriteJsonSupport` 与 `GraphWriteService` 的成体系测试。
- bench functional 已有成熟的 `RunFunctionalCase`、`command_assert`、`trace`、`suite` 基础设施，但还没有 graph 导出/保存专用命令树与对应 case。

### 技术方案

#### 第 1 层：前端稳定层

- 在现有 `GraphViewer.test.tsx` 与 `graph.smoke.spec.ts` 基础上补高价值成功链路用例。
- 重点覆盖：
  - 草稿恢复；
  - 预检成功与保存成功后的页面状态；
  - 搜索/模式切换等关键交互在成功链路下的状态收敛。

#### 第 2 层：前后端契约层

- 新增 `GraphWriteJsonSupport` 契约测试，覆盖：
  - 请求 JSON 解析；
  - 非法操作拒绝；
  - preview/applied/rejected/conflict 返回体结构；
  - `updatedNodes` 最小回包与完整回包字段口径。
- 视需要补强 `GraphSnapshotJsonSupportTest`，确保导出 JSON 结构与文件名/校验码语义稳定。
- 保持与前端 `graphTypes.ts` 解析口径对齐，形成“后端真实 JSON -> 前端可消费”的稳定契约。

#### 第 3 层：bench functional 联动层

- 新增 `bench graph` 命令树，而不是直接把 Playwright 绑到真实网页桥。
- bench graph 命令直接调用：
  - `GraphSnapshotExportService`
  - `GraphWriteService.preview`
  - `GraphWriteService.submit`
- 命令统一输出 machine-readable summary，供 `command_assert` 稳定断言。
- 先只覆盖 serial 主链路：`triggerSource -> core` 的 graph 导出、预检、保存与结果校验。

### 影响范围

- `webapp/src/components/GraphViewer.test.tsx`

- `src/test/java/com/makomi/command/bench/*`

- `tools/bench/functional-matrix.json`

## 原子步骤清单

### 步骤 1：补前端 graph 成功链路测试
- **操作对象**：`webapp/src/components/GraphViewer.test.tsx`、`webapp/e2e/graph.smoke.spec.ts`、相关 mock 支撑
- **具体动作**：新增草稿恢复、预检成功、保存成功等回归用例
- **预期结果**：第 1 层前端稳定层覆盖关键成功路径
- **关键里程碑**：是

### 步骤 2：补 graph 后端 JSON 契约测试
- **操作对象**：`src/test/java/com/makomi/data/GraphWriteJsonSupportTest.java`、现有 graph 测试文件
- **具体动作**：补请求解析与返回体结构测试，必要时补强导出 JSON 契约测试
- **预期结果**：第 2 层对 graph 导出/保存 JSON 口径形成稳定回归
- **关键里程碑**：是

### 步骤 3：跑通第 1、2 层
- **操作对象**：`webapp` 与 Gradle 测试入口
- **具体动作**：执行前端 typecheck/test/e2e 与 Gradle 全标签测试
- **预期结果**：第 1、2 层全部通过后再进入第 3 层
- **关键里程碑**：是

### 步骤 4：新增 bench graph 命令面
- **操作对象**：`src/main/java/com/makomi/command/bench/*`、对应 `src/test/java`
- **具体动作**：实现 graph export/preview/save 命令与稳定 summary，并补命令 summary 单测
- **预期结果**：dedicated functional 可直接调用 graph 真链路
- **关键里程碑**：是

### 步骤 5：新增 graph functional case
- **操作对象**：`tools/bench/cases/functional/*.json`、`tools/bench/functional-matrix.json`
- **具体动作**：增加 graph serial 主链路 dedicated case，并接入矩阵
- **预期结果**：第 3 层具备可执行的 graph dedicated 回归入口
- **关键里程碑**：是

### 步骤 6：构建、同步并跑通第 3 层
- **操作对象**：当前工作区构建产物与本地 bench dedicated 环境
- **具体动作**：先构建当前工作区运行 jar，再同步 server jar，然后执行新增 functional case
- **预期结果**：第 3 层 dedicated graph 联动真实跑通
- **关键里程碑**：是

## 预期结果

- graph 前端稳定层覆盖成功链路与关键交互；
- graph 后端 JSON 契约具备稳定回归；
- dedicated bench functional 能验证 graph 导出、preview、save 与真实连线结果；
- 所有新增实现均保持 `triggerSource/core` 命名与方向隔离，兼容层不向外泄漏旧术语。
