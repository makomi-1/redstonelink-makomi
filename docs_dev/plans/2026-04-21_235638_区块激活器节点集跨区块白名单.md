# 区块激活器节点集跨区块白名单

生成时间：2026-04-21 23:56:38
文件名：2026-04-21_235638_区块激活器节点集跨区块白名单.md

## 任务背景
当前跨区块白名单仅支持手动命令写入，存储结构是扁平的 `role/type/serial` 集合，无法表达“多个区块激活器对白名单的并集贡献”，也无法安全回收单个激活器失效后的那部分影响。  
本次需要新增“强加载/常驻 区块激活器”：激活器持久化一个节点集，节点集容量上限为 `32`；当激活器处于有效激活态时，按自身配置把节点集内 `triggerSource` 加入跨区块白名单。多个激活器对同一节点的作用取并集。  
同时，激活器需要具备独立的配置 GUI、别名与 tooltip，并在激活态变化、配置变化、物理破坏等生命周期事件中同步维护白名单贡献。  
最新确认语义为：**激活态失效则该激活器贡献立即失效**，不采用“激活后即锁存到破坏前”的设计。

## 方案详情

### 现状分析
- `CrossChunkWhitelistSavedData` 目前只保存手动白名单真值，无法记录“谁贡献了某条白名单”，直接复用会导致并集场景下无法按来源回收。
- `CrossChunkDispatchTicketSupport` 与 `NodeSnapshotQueryService` 分别负责运行态强加载/resident 命中与节点状态展示，它们都直接读取白名单，说明本轮必须补统一的“有效白名单口径”。
- 过滤器链路已经具备成熟模式：`AbstractLinkFilterBlockEntity`/`PlacedLinkFilterSavedData`/`LinkFilterNetwork`/`LinkFilterBlockItem` 共同提供“方块持久化真值 + GUI + 别名 + tooltip + 真实破坏才回收”的完整骨架。
- `LinkSignalEmitterBlock` 已经有邻居信号采样与 `POWERED` 外显逻辑，可为激活器的激活态检测与 UI 外显提供参考。

### 技术方案
- 新增一套“区块激活器”专用实现：
  - 方块、方块实体、物品、客户端编辑界面、网络 payload、物品数据读写。
- 新增一份世界级 `SavedData`，按 `dimension + blockPos` 持久化每个激活器的配置与运行态真值：
  - 模式：`FORCE_LOAD / RESIDENT`
  - 节点集表达式与解析后的 `triggerSource` 序号集合
  - 节点集容量上限：`32`
  - 展示别名
  - 当前是否激活
- 在该 `SavedData` 内维护：
  - 激活器条目主表
  - `triggerSource serial -> activatorKey集合` 的反向索引
  - “当前激活中的激活器对白名单的贡献计数/聚合结果”缓存
- 保留 `CrossChunkWhitelistSavedData` 作为“手动真值层”，新增统一查询层，将：
  - 手动白名单
  - 激活器激活贡献
  - preset
  聚合成最终有效白名单口径，供强加载命中、resident 票据同步与节点状态展示共用。
- 激活器生命周期语义：
  - 放置/读档附着：恢复激活器真值，不因普通区块卸载删除配置。
  - 激活态变化：立即增量刷新自身节点集贡献。
  - 配置变化：按旧集合移除、按新集合加入，保持并集正确。
  - 物理破坏：删除激活器真值、索引与贡献。
  - 普通区块卸载：只脱离上下文，不删除激活器真值；但最终是否生效以持久化激活态为准。

### 影响范围
- 新增区块激活器 block / block entity / item / saved data / network / screen / lang / model / loot / recipe / blockstate 等模块
- 更新跨区块有效白名单查询与 resident 票据同步逻辑
- 更新状态查询口径与必要测试

## 预期结果
新增一个可配置节点集的区块激活器。激活时，按“强加载/常驻”配置把节点集中的 `triggerSource` 纳入跨区块有效白名单；激活态失效时立即撤销自身贡献；多个激活器对同一节点按并集生效；方块具备 GUI、别名与 tooltip，并通过测试保证生命周期与跨区块口径一致。
