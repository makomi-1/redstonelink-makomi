# 修复过滤器启动期阻塞与非阻塞补采样

生成时间：2026-04-10 10:23:37
文件名：2026-04-10_102337_修复过滤器启动期阻塞与非阻塞补采样.md

## 任务背景
提交 `210b24d819358a8c9421118e6061a78eba1020e4` 把过滤器真值改为 `SavedData` 持久化后，`AbstractLinkFilterBlockEntity.clearRemoved()` 在读档附着阶段会直接调用 `LinkDispatchFilterService.upsertFilter(...)`，而该入口又会同步采样 `level.getBestNeighborSignal(...)`。这条链路落在世界进入的启动关键阶段，命中过滤器时可能触发同步等待区块就绪，表现为带过滤器的存档无法进入。

## 方案详情

### 现状分析
- `clearRemoved()` 当前既负责恢复“已放置过滤器真值”，又同步采样邻居输入，职责过重。
- `neighborSignalStrength` 仅用于 `signalThresholdSource = NEIGHBOR_MAX_INPUT` 的阈值比较，不决定过滤器是否存在。
- 仅保留 `neighborChanged/onPlace` 更新虽能避免阻塞，但不能覆盖“读档恢复后第一时间补齐阈值”这一场景。
- 项目既有经验已明确要求：启动关键路径禁止任何可能触发同步等待 chunk 的读取；恢复逻辑应采用非阻塞探测。

### 技术方案
1. 拆分 `upsertFilter(...)` 的职责：保留“登记/刷新过滤器持久化真值”能力，但把“是否采样邻居输入”做成显式参数或独立入口。
2. 调整过滤器方块实体生命周期：
   - `clearRemoved()` 只恢复放置态真值，不再同步采样邻居输入；
   - `applySnapshot(...)`、`neighborChanged(...)`、`onPlace(...)` 继续走“配置或世界态变更时即时采样”的路径。
3. 在 `LinkDispatchFilterService.register()` 挂接 `SERVER_STARTED` 后的非阻塞补采样任务：
   - 只遍历 `PlacedLinkFilterSavedData` 中实际存在的过滤器条目；
   - 只对 `signalThresholdSource = NEIGHBOR_MAX_INPUT` 的条目做补采样；
   - 通过 `server.getLevel(...) + getChunkNow(...) + EntityCreationType.CHECK` 非阻塞定位已加载过滤器方块实体，未就绪则跳过，不允许触发阻塞式取块。
4. 补充测试，覆盖“clearRemoved 不再做同步邻居采样”和“SERVER_STARTED 补采样只在已加载过滤器上更新”的边界。

## 原子步骤清单

### 步骤 1：拆分过滤器 upsert 入口
- **操作对象**：`LinkDispatchFilterService`、`PlacedLinkFilterSavedData`
- **具体动作**：把“写入持久化真值”与“邻居输入采样”解耦，提供无采样 upsert 与带采样 refresh 两种入口
- **预期结果**：启动附着链路可以只恢复真值，不触发同步邻居读取
- **关键里程碑**：是

### 步骤 2：调整过滤器生命周期调用点
- **操作对象**：`AbstractLinkFilterBlockEntity`、`AbstractLinkFilterBlock`
- **具体动作**：让 `clearRemoved()` 改为无采样恢复；保留配置保存、放置和邻居变化时的即时采样刷新
- **预期结果**：世界进入阶段去阻塞，运行期世界态变化仍能及时更新阈值
- **关键里程碑**：是

### 步骤 3：增加 SERVER_STARTED 后非阻塞补采样
- **操作对象**：`LinkDispatchFilterService`
- **具体动作**：注册 `SERVER_STARTED` 事件，按持久化条目做一次非阻塞补采样并写回最新阈值
- **预期结果**：已放置过滤器在重启后不会长期沿用旧的 `neighborSignalStrength`
- **关键里程碑**：是

### 步骤 4：补自动化测试
- **操作对象**：`src/test/java/com/makomi/data/`、`src/test/java/com/makomi/block/entity/`
- **具体动作**：增加启动补采样与无采样恢复的测试，覆盖已加载/未加载/非邻居阈值三类边界
- **预期结果**：本轮修复可回归、可防止同类阻塞问题再引入
- **关键里程碑**：是

## 预期结果
过滤器在读档附着阶段只恢复“仍处于放置态”的持久化真值，不再同步采样邻居输入；`NEIGHBOR_MAX_INPUT` 阈值改由运行期增量更新与 `SERVER_STARTED` 后的非阻塞补采样共同维护，从而既修复带过滤器存档无法进入的问题，又尽量保持阈值语义完整。
