# x21延迟专项补窗口断言

生成时间：2026-04-01 19:07:32
文件名：2026-04-01_190732_x21延迟专项补窗口断言.md

## 任务背景
当前同区块 `sync` 延迟专项 `x21` 已经能稳定产出 `triggerSource/core` 的延迟统计和 `windowCoverage`，但这些窗口结论仍需人工读取结果文件判断，无法作为自动化验证例直接判定“`windowTicks>=0` 时延迟是否正确”。本轮目标是把这条新例改造成可直接验收的专项。

## 方案详情

### 现状分析
- `trace_sync_latency_collect` 已会计算 `windowCoverage`，但默认只做 `matchedRatio` 检查。
- `x21` 已能稳定得到：`triggerSource` 绝对延迟约为 `1 tick`，`core` 相对 `triggerSource` 延迟为 `0 tick`。
- 当前缺少把这些结论转成 case 级自动检查的能力。

### 技术方案
- 给 `trace_sync_latency_collect` 增加可选配置 `windowCoverageChecks`。
- 每个检查项按 `windowTicks` 找到对应覆盖率，并按 `expectedMinimum/expectedMaximum` 自动产出 `checks`。
- 只在 `x21` 新例上启用这组检查，保持旧例默认行为不变。
- `x21` 断言口径：
  - `triggerSource`：`window=0` 覆盖率必须为 `0`；`window=1` 覆盖率必须为 `1`
  - `core`：`window=0` 覆盖率必须为 `1`

### 影响范围
- `tools/bench/lib/Bench.FunctionalTrace.ps1`
- `tools/bench/cases/functional/x21/sync_samechunk_latency_1024_to_1024_banded16_single_burst.json`
- 自动化测试与 x21 定向专项结果

## 原子步骤清单

### 步骤 1：补窗口覆盖断言能力
- **操作对象**：`Bench.FunctionalTrace.ps1`
- **具体动作**：解析 `windowCoverageChecks`，并在 `trace_sync_latency_collect` 中为每条窗口断言输出 check
- **预期结果**：专项可以自动判定 `windowTicks` 下的覆盖率是否满足预期
- **关键里程碑**：是

### 步骤 2：改造 x21 新例
- **操作对象**：`sync_samechunk_latency_1024_to_1024_banded16_single_burst.json`
- **具体动作**：为 source/core 两段采样补上窗口断言
- **预期结果**：x21 从“分析用例”升级为“验证用例”
- **关键里程碑**：是

### 步骤 3：执行回归验证
- **操作对象**：全标签测试与 x21 定向专项
- **具体动作**：运行 `.\gradlew.bat test testIntegration testClient testSlow --no-daemon`，再跑 x21 定向专项
- **预期结果**：新能力不影响旧逻辑，x21 断言全部通过
- **关键里程碑**：是

## 预期结果
- x21 新例能够直接验证 `windowTicks>=0` 口径下的延迟与覆盖率是否正确
- `triggerSource/core` 相对传播结论保持不变，只是专项验收能力增强
