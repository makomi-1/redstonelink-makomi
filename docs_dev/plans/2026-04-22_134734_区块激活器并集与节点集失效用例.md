# 区块激活器并集与节点集失效用例

生成时间：2026-04-22 13:47:34
文件名：2026-04-22_134734_区块激活器并集与节点集失效用例.md

## 任务背景
当前区块激活器已经完成 `triggerSource/core` 两种作用类型与 resident/force_load 生命周期实现，也已经有单侧 3 节点 dedicated functional 用例。本轮需要继续补齐游戏内回归测试，覆盖：
- `triggerSource/core` 同时存在时的并集作用
- 运行期修改节点集后，旧节点贡献失效、新节点贡献生效

用户已明确确认可直接实现并跑通，无需再次确认方案。

## 方案详情

### 现状分析
- 现有 resident 生命周期模板已经在 `x45` 与 `x48` 中分别覆盖 `triggerSource` 与 `core` 单侧场景。
- 现有运行期节点集重算节奏已经在 `x32` 与 `x33` 中验证过滤器的“切配置后失效/补发”行为。
- dedicated bench 支持通过 `layout.step` 在 `cuboid` 布局里跨区块稀疏布点，适合构造“节点集切换后旧区块是否失效”的场景。

### 技术方案
- 新增 `x49`：同时放置两个区块激活器，一个配置为 `triggerSource/resident`，一个配置为 `core/resident`，分别覆盖 3 个节点。通过移除目标区块和激活器自身区块的 `forceload`，验证两类贡献可并集生效；再重新加载并失活，验证两类贡献同时撤销。
- 新增 `x50`：放置一个 `core/resident` 区块激活器，3 个目标核心分布在 3 个不同区块。先配置命中 `[0,1]`，再改为 `[1,2]`，每次都在卸载激活器自身区块后观测在线状态，验证旧节点失效与新节点接管。
- 将两个新用例注册到 `tools/bench/functional-matrix.json`、`tools/bench/suites/regression-lifecycle.json`、`tools/bench/suites/regression-full.json`。
- 按项目规则执行“构建当前工作区 jar -> 同步 server jar -> 仅跑新增 case dedicated 验证”。

### 影响范围
- `tools/bench/cases/functional/x49/**`
- `tools/bench/cases/functional/x50/**`
- `tools/bench/functional-matrix.json`
- `tools/bench/suites/regression-lifecycle.json`
- `tools/bench/suites/regression-full.json`
- `docs_dev/reviews/**`
