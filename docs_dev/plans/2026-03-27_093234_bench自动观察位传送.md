# bench 自动观察位传送

生成时间：2026-03-27 09:32:34
文件名：2026-03-27_093234_bench自动观察位传送.md

## 任务背景

现有带玩家的 bench 自动化仅支持在玩家就绪后执行 `PlayerSetupCommands`，常见用法是手动切旁观并传送到固定坐标。该方式存在两个问题：

1. 不同 case 的主结构坐标并不一致，固定坐标无法稳定观察当前场景。
2. 玩家初始化发生在节点放置前，无法根据当前 case 实际放置出的 `triggerSource/core` 结构自动选取观察位。

本次任务目标是在单 case 与 suite 中新增一个默认关闭的可选开关，使带玩家运行时能在放置和建链完成后，将玩家自动传送到“主要放置方块最小轴向包围盒顶面中心上方”的合适观察位。

## 方案详情

### 现状分析

- 单 case 参数入口位于 `tools/bench/run-bench.ps1`。
- suite 参数入口位于 `tools/bench/run-bench-suite.ps1`，并通过 `tools/bench/lib/BenchSuite.EntryPoint.ps1` 组装单 case 参数。
- 玩家上下文准备与初始化命令执行位于 `tools/bench/lib/Bench.Rcon.ps1` 的 `Ensure-PlayerContextReadyAndSetup`。
- 节点放置、取号、建链与驱动主流程位于 `tools/bench/lib/Bench.EntryPoint.ps1`。
- 已有 `tools/bench/lib/Bench.World.ps1` 的坐标与包围盒辅助函数可直接复用。

现有执行顺序是“玩家就绪与初始化 -> 清场 -> 放置 -> 建链 -> 驱动”。因此自动观察位传送必须挂在“放置与建链完成后、驱动开始前”。

### 技术方案

1. 新增可选开关 `AutoTeleportPlayerToObservationPoint`，默认关闭。
2. 单 case 与 suite 都支持该开关，suite 仅负责透传，不改变既有一例一档流程。
3. 基于当前 case 实际放置出的全部 `triggerSource/core` 位置集合计算最小轴向包围盒：
   - `X/Z` 取顶面中心。
   - `Y` 取包围盒顶面以上的自适应观察高度。
4. 自适应观察高度采用与场景跨度相关的简单规则，避免小场景过高、大场景过低：
   - `offsetY = clamp(ceil(max(spanX, spanZ) / 3), 8, 32)`
   - 最终观察位：`topY + 1 + offsetY`
5. 自动观察位传送不覆盖 `PlayerSetupCommands` 的语义：
   - `PlayerSetupCommands` 仍在玩家就绪后优先执行，适合做 `gamemode/tag` 等初始化。
   - 若启用自动观察位，则在放置与建链完成后再执行一次自动 `tp`，作为最终观察位置。
6. 若用户启用该开关但未提供 `AsPlayer`，则明确报错，避免静默失效。
