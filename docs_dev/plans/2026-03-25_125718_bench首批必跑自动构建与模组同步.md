# bench 首批必跑自动构建与模组同步

生成时间：2026-03-25 12:57:18

## 任务背景

当前首批必跑 suite 需要手动把最新 RedstoneLink `.jar` 复制到 dedicated server 的 `mods` 目录。
若忘记同步，就会出现“bench 结果来自旧模组版本”的问题，影响游戏内自动化测试的可信度。
本次需要在不破坏现有手动流程的前提下，为 `run-bench-suite.ps1` 增加可选自动构建与自动同步能力，并提供两个可直接执行的包装脚本。

## 方案详情

### 现状分析

- `tools/bench/run-bench-suite.ps1` 当前负责 suite 编排、切换世界、启停服和结果汇总，适合作为构建/同步的前置入口。
- `tools/bench/run-bench.ps1` 只负责单 case 运行，不适合承担服务器 `mods` 管理职责。
- 当前 `build/libs` 已存在标准 Fabric 产物，适合通过 `remapJar` 生成服务端运行 jar。

### 技术方案

1. 在 `run-bench-suite.ps1` 增加默认关闭的可选参数：
   - `SyncLatestModJar`
   - `BuildBeforeSyncLatestModJar`
   - `BuildTask`
   - `GradleWrapperPath`
   - `ModJarPath`
   - `ServerModsDir`
2. 在 suite 启动前增加一次性前置流程：
   - 若启用 `BuildBeforeSyncLatestModJar`，先执行 `gradlew.bat <BuildTask> --no-daemon`
   - 若启用 `SyncLatestModJar`，自动解析本地运行 jar，并复制到服务器 `mods` 目录
   - 同步前清理服务器旧的 `redstonelink*.jar`
3. 将本次构建/同步信息写入 suite summary，便于复盘。
4. 新增两个“首批必跑”包装脚本：
   - 纯运行版：不构建、不复制
   - 构建并复制版：先 `remapJar` 再同步到服务器
5. 更新 `docs_dev/使用说明.md`，补充新参数和新脚本用法。

### 影响范围

- `tools/bench/run-bench-suite.ps1`
- `tools/bench/*.ps1` 新增包装脚本
- `docs_dev/使用说明.md`
