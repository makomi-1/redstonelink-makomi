# triggerSource位置列表任务与命令开关拆分

生成时间：2026-03-23 17:56:08
文件名：2026-03-23_175608_triggerSource位置列表任务与命令开关拆分.md

## 任务背景

上一轮已把 `core/triggerSource` 的加载后自愈从阻塞式路径改成异步、非阻塞消费，但还存在两点可继续收敛：

1. `triggerSource` 仍采用“区块入队、消费时再扫区块实体”的模型，成功路径上仍有一次额外扫描。
2. `input` 与 `node trace` 当前仍共用 `benchmarkMode`，测试/诊断命令的配置粒度不够细。

本轮目标是：

- 将 `triggerSource` 自愈任务改成“`chunk + 位置列表`”
- 将 `input` 与 `node trace` 命令开关独立出来，默认开启

## 方案详情

### 现状分析

- `TriggerSourceInputStateResyncService` 现在 `CHUNK_LOAD` 只判断区块内是否存在 pending emitter，然后入一个 `chunk` 任务；消费时再二次扫描该 chunk 的方块实体。
- `LinkTriggerSourceBlockEntity` 已有节点级 `pendingLoadInputStateResync` 标记，可作为精细扫描基础。
- `NodeStateTraceService` 与 `InputPlaybackService` 目前按 `benchmarkMode` 注册；对应命令根也按 `benchmarkMode` 控制。

### 技术方案

1. 在 `CHUNK_LOAD` 时直接做一次精细扫描，收集当前 chunk 内所有 pending emitter 的 `BlockPos` 列表。
2. 将 `PendingChunkTask` 扩展为：
   - `dimension`
   - `chunkPos`
   - `targetPositions`
   - `attempt`
3. 消费时仍只对 chunk 做一次 `getChunkNow(...)`，随后按 `targetPositions` 逐个 `CHECK` block entity，并执行静默重采样。
4. 新增两个独立配置项：
   - `server.command.input.enabled=true`
   - `server.command.nodeTrace.enabled=true`
5. `benchmarkMode` 保持原职责，只继续服务 bench / RCON 直执行等压测语义，不再控制 `input` / `node trace`。
6. 配置模板与使用说明中补充推荐关系：
   - 若 `server.runtime.loadResync.triggerSource.enabled=true`，推荐保持 `server.command.input.enabled=true`
   - 若 `server.runtime.loadResync.core.enabled=true` 或 `server.runtime.loadResync.triggerSource.enabled=true`，推荐保持 `server.command.nodeTrace.enabled=true`

## 预期结果

- `triggerSource` 自愈在 chunk 已就绪后的成功路径不再二次全扫方块实体。
- `input` 与 `node trace` 命令和服务开关独立，默认可用。
- `benchmarkMode` 语义收敛回 bench / 压测专用，不再挟持普通诊断命令。
