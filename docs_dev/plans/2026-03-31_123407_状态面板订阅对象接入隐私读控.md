# 状态面板订阅对象接入隐私读控

生成时间：2026-03-31 12:34:07
文件名：2026-03-31_123407_状态面板订阅对象接入隐私读控.md

## 任务背景

当前状态面板工具已支持订阅、刷新与删除订阅项，但其服务端读取链路尚未接入现有“当前连接隐私”读控体系。现状会导致受控节点仍可被新增到状态面板，且快照会直接把运行态字段下发到客户端，和命令读取、近外显已有的隐私语义不一致。

本次目标是在不扩展到其他 GUI/工具的前提下，让状态面板订阅对象并入现有隐私读控系统，保持 `hidden/masked/plain` 与 `viewPermissionLevel` 规则一致。

## 方案详情

### 现状分析

- `StatePanelNetworkServerHandlerSupport` 当前只校验序号合法性、已分配、未退役和订阅上限，没有隐私读控判定。
- 状态面板快照构建直接读取 `NodeIdentitySnapshot` 与 `NodeRuntimeSnapshot`，会把状态字段原样回给客户端。
- `CurrentLinksPrivacyService` 已经承载服务端隐私规则，是命令与近外显读路径的现有规则层。
- `StatePanelToolScreen` 当前没有“受控隐藏”显示分支，只会把快照字段直接渲染成状态文本。
- `StatePanelSnapshotEntry` 目前缺少“此条是否可读”的协议字段，客户端无法分辨“真实离线”和“因隐私被隐藏”。

### 技术方案

1. 在 `CurrentLinksPrivacyService` 中补一个更中性的“节点状态是否允许读取”入口，底层仍复用当前 `hidden/masked/plain + viewPermissionLevel` 规则。
2. 在状态面板新增订阅时，对“本次新增序号”补做隐私读控校验；若存在无权限读取的节点，则整批拒绝，不写入订阅数据。
3. 对已存在于状态面板物品里的订阅，不做自动删除；刷新快照时保留该行，但把状态字段按隐私规则脱敏。
4. 扩展 `StatePanelSnapshotEntry`，加入可读标记，让客户端可区分“状态真实可读”与“受控隐藏”。
5. 调整 `StatePanelToolScreen` 的状态列渲染，受控条目显示固定文案，不再把 `online/active/input/output` 拼成普通状态字符串。
6. 更新状态面板文案、使用说明与定向测试，保证行为可追溯。

### 技术取舍

- 不复用 `overlayResponsePermissionLevel`：该权限是近外显整包回传门槛，状态面板属于显式读取 GUI，更应复用 `viewPermissionLevel` 读权限语义。
- 不在刷新时直接过滤整行：否则历史订阅会变成“看不见也删不掉”的幽灵数据，管理性较差。
- 不自动迁移或改写物品订阅数据：本次仅收口读取和新增订阅校验，不引入额外持久化变更。
- 不引入 `com.makomi.api.v1.*`：继续走内部实现路径。

## 原子步骤清单

### 步骤 1：补状态面板可复用的读控判定
- **操作对象**：`CurrentLinksPrivacyService`
- **具体动作**：新增“节点状态是否允许读取”的通用判定入口，并保留现有 current-links 包装方法
- **预期结果**：状态面板与命令/近外显共用同一套隐私规则
- **关键里程碑**：是

### 步骤 2：接入新增订阅隐私校验
- **操作对象**：`StatePanelNetworkServerHandlerSupport`
- **具体动作**：对本次新增序号补做隐私读控校验；若存在不可读节点则整批拒绝并回传反馈
- **预期结果**：无权限玩家不能新增受控订阅
- **关键里程碑**：是

### 步骤 3：扩展快照协议并做服务端脱敏
- **操作对象**：`StatePanelNetwork`、`StatePanelNetworkPayloadSupport`、`StatePanelNetworkServerHandlerSupport`
- **具体动作**：为快照条目增加可读标记；已有受控订阅保留条目但不下发真实状态字段
- **预期结果**：客户端能正确区分“隐藏”与“真实离线/空闲”
- **关键里程碑**：是

### 步骤 4：适配客户端状态面板渲染
- **操作对象**：`StatePanelToolScreen`
- **具体动作**：新增受控状态显示分支，并处理打开瞬间的占位行表现
- **预期结果**：状态面板列表对隐私受控条目有明确、稳定的显示
- **关键里程碑**：是

### 步骤 5：补文案、测试与使用说明
- **操作对象**：语言文件、测试文件、`docs_dev/使用说明.md`
- **具体动作**：新增反馈与状态文案，补 payload/隐私回归测试，补充状态面板读取规则
- **预期结果**：行为可回归、说明可追溯
- **关键里程碑**：否

## 预期结果

- 状态面板新增订阅会受现有隐私读控约束。
- 历史上已存在的受控订阅仍可见、可移除，但状态字段会被隐藏。
- `hidden/masked/plain` 在状态面板、命令与近外显上的读取语义保持一致。

## 语义对齐说明

- 命名统一使用 `triggerSource/core`。
- 输入/输出结构不改变方向语义。
- 与 `LinkNodeType.TRIGGER_SOURCE/CORE` 保持一一映射。
- 不引入 `com.makomi.api.v1.*`。
- 兼容层仅扩展状态面板读取协议，不修改持久化键。
- 残余风险：若后续希望连订阅序号也一并隐藏，需要单独再设计“整行隐藏/可管理性”方案；本次不处理。
