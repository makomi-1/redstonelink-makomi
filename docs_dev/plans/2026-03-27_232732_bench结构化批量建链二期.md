# bench 结构化批量建链二期

生成时间：2026-03-27 23:27:32
文件名：2026-03-27_232732_bench结构化批量建链二期.md

## 任务背景
bench 当前虽然已经支持 `broadcast_all`、`fan_in_first`、`banded` 三类规则图，但建链仍在 PowerShell 侧展开成大量 `redstonelink link set ...` 命令。  
在 `1024 -> 1`、`1024 -> 1024 banded16`、`mixed_1024 -> 1024` 这类重压场景里，建链准备阶段的命令往返已经成为主要额外耗时来源之一。  
本期目标是把“规则图”提升为 bench 的一等输入，让 bench 能以单条结构化请求下发整批链接规则，并在不污染普通玩家命令树的前提下保留旧 `link set` 作为回退路径。

## 方案详情

### 现状分析
- 服务端已有稳定的单来源覆盖写入路径：`LinkSavedData.replaceLinksBySourceType(...)`。
- `link set` 已具备方向校验、写控校验、delta 事件发布与客户端快照同步逻辑。
- bench 端 `Build-LinkCommands` 已能识别 `broadcast_all`、`fan_in_first`、`banded` 规则，但仍按 source 逐条展开命令。
- 现有重压用例正好全部落在这三类规则内，适合优先改造成结构化批量接口。

### 技术方案
1. 新增 `/redstonelink bench link apply ...` 专用命令树，仅在 `benchmarkMode` 开启且具备 bench 权限时暴露。
2. 服务端新增结构化规则展开支撑，固定使用 `triggerSource -> core` 方向：
   - `broadcast_all`
   - `fan_in_first`
   - `banded`
3. 结构化命令一次性解析 source/target 批量序号，按规则展开为多组 `source -> targets`，再复用现有 `replaceLinksBySourceType`、写控、delta 和 snapshot 路径。
4. PowerShell bench 侧优先生成单条结构化命令；若服务端不支持或返回 bench/命令级失败，再自动回退到旧的逐条 `link set`。
5. 保留所有现有 case JSON 语义不变，仅替换建链传输方式。

### 影响范围
- 服务端命令注册：
  - `src/main/java/com/makomi/command/ModCommands.java`
  - 新增 `src/main/java/com/makomi/command/bench/*`
- 公共序号解析：
  - `src/main/java/com/makomi/util/SerialParseUtil.java`
- link 支撑复用：
  - `src/main/java/com/makomi/command/link/LinkCommandSupport.java`
- bench 脚本：
  - `tools/bench/lib/Bench.PlaceAndLink.ps1`
  - `tools/bench/lib/Bench.EntryPoint.ps1`
- 测试与说明：
  - `src/test/java/com/makomi/...`
  - `docs_dev/使用说明.md`

## 原子步骤清单

### 步骤 1：补服务端结构化批量建链入口
- **操作对象**：`src/main/java/com/makomi/command/bench/*`、`ModCommands`
- **具体动作**：新增 bench 命令注册器与 `bench link apply` 分支，并接入根命令树
- **预期结果**：服务端存在独立 bench/internal 风格入口，不污染普通 `link` 命令树
- **关键里程碑**：是

### 步骤 2：实现规则展开与批量写入
- **操作对象**：`BenchStructuredLinkApplySupport`、`SerialParseUtil`、`LinkCommandSupport`
- **具体动作**：实现有序批量序号解析、`broadcast_all/fan_in_first/banded` 规则展开、逐 source 覆盖写入以及 delta/snapshot 同步
- **预期结果**：单条结构化命令即可完成整批规则化建链
- **关键里程碑**：是

### 步骤 3：改 bench 脚本优先走结构化接口并保留回退
- **操作对象**：`tools/bench/lib/Bench.PlaceAndLink.ps1`、`tools/bench/lib/Bench.EntryPoint.ps1`
- **具体动作**：将建链计划从“命令字符串列表”升级为“结构化/经典双模计划”，执行时优先尝试结构化命令，失败再回退旧命令
- **预期结果**：`1->2048`、`1024->1`、`1024->1024 banded16`、mixed 多 sourceGroup 场景显著减少命令数
- **关键里程碑**：是

### 步骤 4：补测试与使用说明
- **操作对象**：`src/test/java/com/makomi/...`、`docs_dev/使用说明.md`
- **具体动作**：补规则展开测试、命令树解析契约测试，并更新使用说明中的行为描述
- **预期结果**：结构化批量建链具备可回归验证与文档说明
- **关键里程碑**：否

## 预期结果
- `1 -> 2048` 广播场景可由 1 条结构化命令完成建链。
- `1024 -> 1` 汇聚场景可由 1 条结构化命令完成建链。
- `1024 -> 1024 banded16` 可由 1 条结构化命令完成建链。
- mixed banded 场景按 sourceGroup 拆分后，通常可控制在 3 条以内。
- 语义仍严格保持 `triggerSource/core` 与 `triggerSource -> core` 单向写入，不引入旧术语回流。
