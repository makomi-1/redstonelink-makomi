# 快速连接工具第一阶段方案

生成时间：2026-03-30 08:50:08
文件名：2026-03-30_085008_快速连接工具第一阶段方案.md

## 任务背景

当前草稿希望新增一个“快速连接工具”，用于在游戏内快速把一组缓存的连接目标应用到方块节点上。第一阶段只要求“序号直连”可用，“频道模式”先做结构预留，不提前落业务写入。

本轮已确认两项关键口径：

1. 保留问题 1：接受补充建议，序号缓存必须显式记录缓存类型，即 `triggerSource/core`。
2. 保留问题 2：交互方式保持草稿原设计继续，不额外改成新的键位方案。

## 方案详情

### 现状分析

- 现有配对 GUI `[AbstractMultiPairingScreen](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/AbstractMultiPairingScreen.java)` 面向“某个来源节点”的即时配对，不适合直接复用为“工具缓存编辑器”。
- 现有网络与写入路径仍偏向命令字符串入口，适合已有配对场景，但不适合未来工具化交互、回执提示与模式扩展。
- 现有语义基线已经统一到 `triggerSource/core`，新工具必须严格遵守：
  - `triggerSource` 只能作为来源。
  - `core` 只能作为目标。

### 技术方案

第一阶段把快速连接工具定义为“连接模板刷子”，而不是“现场采集器”。

核心交互保持以下口径：

1. `潜行右键`：打开工具 GUI，编辑并持久化缓存。
2. `站立右键`：切换 `序号模式/频道模式`。
3. `左键命中方块`：把缓存作为覆盖式 `set` 应用到当前可配对节点。

实现分层如下：

- `QuickLinkToolItem`
  - 新工具物品，设置为不可堆叠。
  - 负责承接右键打开 GUI、右键切模式、左键应用入口。
- `QuickLinkToolData`
  - 管理工具 NBT。
  - 至少包含：
    - `mode = serial | channel`
    - `serial_cache_type = triggerSource | core`
    - `serial_cache_expression`
    - `channel_cache`（预留）
- `QuickLinkToolScreen`
  - 独立 GUI，不直接继承配对界面语义。
  - 外观可参考配对界面，但职责是编辑工具缓存。
  - 序号模式支持结构化输入：`N`、`A:B`、`/`。
  - 频道模式只做输入保存预留，不落真实连接逻辑。
- `QuickLinkApplyService`
  - 服务端统一解析当前命中方块节点与工具缓存。
  - 序号模式下执行覆盖式 `set`。
  - 失败时返回具体原因，供客户端屏幕中心提示。
- 客户端交互与渲染支持
  - 屏幕中心成功/失败提示。
  - 持工具时，对准“当前可应用对象”显示亮红描边。
  - 仅在工具缓存与命中对象语义匹配时描边。

### 保留问题处理

#### 保留问题 1：序号缓存类型

采用补充字段方案，不再只存一串序号。

原因：

- 同一批序号如果不区分 `triggerSource/core`，服务端无法判断这是“来源缓存”还是“目标缓存”。
- 后续频道模式、混合 GUI 提示、命中合法性校验都需要这个语义字段。

结论：

- 第一阶段必须新增 `serial_cache_type = triggerSource | core`。

#### 保留问题 2：交互方式

保持草稿原设计，不改交互主流程。

结论：

- `潜行右键打开 GUI`
- `站立右键切换模式`
- `左键应用缓存`

不额外引入新的模式切换键位，也不把工具改成“左键采集、右键应用”的采集器模型。

### 影响范围

- 服务端：
  - 新工具物品注册
  - 工具 NBT 数据结构
  - 连接应用服务
  - 必要的 C2S 请求与回执
- 客户端：
  - 工具 GUI
  - 屏幕中心提示
  - 命中高亮描边
  - 模式切换显示
- 资源层：
  - 若后续需要模式贴图映射，需要单独确认资源改动后再做

### 步骤 2：注册工具物品并接入基础交互
- **操作对象**：物品注册、`QuickLinkToolItem`
- **具体动作**：实现不可堆叠、潜行右键开 GUI、站立右键切模式、左键应用入口
- **预期结果**：工具具备完整交互壳层
- **关键里程碑**：是

- **操作对象**：单元测试、集成测试、客户端验证
- **具体动作**：补充工具数据、服务端应用和模式切换的关键测试，并执行全量回归
- **预期结果**：第一阶段实现可验证、可回归
- **关键里程碑**：是

## 预期结果

- 新增一个不可堆叠的快速连接工具。
- 第一阶段完整支持“序号模式”的缓存编辑与即时应用。
- “频道模式”只保留数据和界面扩展位，不提前写业务逻辑。
- 交互流程保持草稿原设计，不额外改键位。

## 语义对齐说明

- 命名统一使用 `triggerSource/core`。
- 写入方向保持 `triggerSource -> core`，不开放反向写入。
- `serial_cache_type` 与 `LinkNodeType.TRIGGER_SOURCE/CORE` 一一映射。
- 兼容层仅允许读旧写新；本工具新增字段全部直接使用新术语。
- 残余风险：
  - 若后续频道模式要真正落地，仍需补频道写入协议和合法性定义。
  - 若后续要做模式贴图变化，属于资源改动，需要单独确认。
