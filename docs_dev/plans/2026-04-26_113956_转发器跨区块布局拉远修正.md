# 转发器跨区块布局拉远修正

生成时间：2026-04-26 11:39:56
文件名：2026-04-26_113956_转发器跨区块布局拉远修正.md

## 任务背景

`x60/x61` 用于验证转发器跨区块生效，并保留“远端节点必须先离线”的前置断言。当前 dedicated bench 中，这两个用例都卡在远端节点离线前置断言，但游戏内人工实测可快速下线。结合当前用例坐标可见，远端节点与本地控制区只相隔几十格，属于同维度近距布局，容易被原版玩家加载半径、控制区附近活动块或 bench 自身布局串扰，导致“应离线节点”实际仍保持在线。

## 方案详情

### 现状分析

- `x60` 远端 `triggerSource` 位于 `256 64 978`，本地 `repeater/core/activator` 位于 `289~300 64 978~981`，距离不足以稳定表达“远端卸载”。
- `x61` 远端 `core` 位于 `320 64 998`，本地 `triggerSource/repeater/activator` 位于 `288~296 64 998~1001`，同样过近。
- `r07/r08` 复用 `x60/x61` 准备好的世界，若不一起迁移，重启复验会继续引用旧坐标。
- 当前问题属于测试布局与观测口径层，不是实现语义层；本轮不修改转发器、区块激活器、链接存储或命令实现。

### 技术方案

- 保留现有语义与断言：
  - 保留“远端节点必须先离线”的前置断言；
  - 保留“只验证跨区块生效，不验证精确延迟”的口径；
  - 保留 `triggerSource -> core` 方向与转发器中间层建模。
- 仅迁移远端节点：
  - `x60` 将远端 `triggerSource` 及其供能块迁移到 `x=1536` 一带；
  - `x61` 将远端 `core` 迁移到 `x=1536` 一带；
  - 本地 `repeater/core/activator` 区保持原位，减少连锁变更。
- 同步调整：
  - `benchForceLoadZones` 仅覆盖本地控制区和新的远端单节点区；
  - `arena.clearZones` 拆分为本地控制区与远端清理区；
  - `r07/r08` 的 `reuseExisting` 坐标、供能命令、delay 校验坐标同步迁移。
