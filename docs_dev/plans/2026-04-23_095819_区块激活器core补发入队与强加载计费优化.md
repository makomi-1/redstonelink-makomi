# 区块激活器core补发入队与强加载计费优化

生成时间：2026-04-23 09:58:19
文件名：2026-04-23_095819_区块激活器core补发入队与强加载计费优化.md

## 任务背景

当前区块激活器在新增 `force_load` 模式的 `core` 成员时，仍然走本地直接补 transient ticket 的即时拉起逻辑。这条路径虽然能立即生效，但没有复用跨区块 `sync` 补发的标准投影、排队、重试和强制加载限流服务。与此同时，现有 `tryForceLoad(...)` 对已持票 chunk 的重复命中仍按“每次调用”扣预算，导致同一 chunk 被重复续期时计费偏保守。

这轮要把 `core` 新增的即时生效语义收敛到“存在来源时，按真实 `triggerSource -> core` 补发进入跨区块队列”，并把强制加载计费从“按调用次数”优化为“按首次拉起的新 chunk 次数”。

## 方案详情

### 现状分析

- `ChunkActivatorImmediateEffectService` 当前对新增 `force_load + core` 走直接 transient ticket bootstrap。
- `InternalDispatchDeltaRuleSupport.publishTriggerSourceCurrentOrPersistedSyncReplay(...)` 已经可以按“当前真值优先、持久化 replay 快照兜底”发出标准 `SYNC_SIGNAL` delta。
- `InternalDispatchDeltaProjector` 在目标 `core` 未加载时，会将 `SYNC_SIGNAL` 自动转入 `CrossChunkDispatchService.queueSyncSignal(...)`，因此可以自然复用现有队列、重试和强制加载链路。
- `LinkSavedData` 已维护 `core -> triggerSource` 反向索引，可直接反查新 `core` 的来源集合。
- `CrossChunkDispatchTicketSupport.tryForceLoad(...)` 目前对已持票 chunk 的重复命中仍会重复扣除 `forceLoadCountThisTick / forceLoadCountBySource`。

### 技术方案

1. 调整区块激活器即时效果计划
   将新增 `force_load + core` 的计划项从“直接临时加载 chunk”改成“需要执行定向 replay 的新 core 集合”。

2. 改为 `core` 定向 replay 入队
   对每个新 `core`，反查已链接的 `triggerSource` 集合；逐个来源只向这个 `core` 定向补发当前/持久化 `sync` 真值。若目标未加载，则由现有 projector 自动进入跨区块队列并命中统一强制加载服务。

3. 优化强制加载计费
   在 `tryForceLoad(...)` 中先计算目标 `ForcedChunkKey`。若该 chunk 已在当前 `forcedChunksUntilTick` 中，仅续期，不再重复加 transient ticket，也不再重复扣预算；只有首次拉起新 chunk 时才消耗 `maxPerTick / maxPerSourcePerTick` 配额。

## 原子步骤清单

### 步骤 1：调整区块激活器即时效果计划
- **操作对象**：`ChunkActivatorImmediateEffectService`、`ChunkActivatorImmediateEffectServiceTest`
- **具体动作**：把 `forceLoadCores` 计划项改为 `replayCores` 或等价语义，并更新单测断言
- **预期结果**：新增 `force_load + core` 不再走 activator 本地直拉逻辑
- **关键里程碑**：是

### 步骤 2：接入 `core -> triggerSource` 定向 replay
- **操作对象**：`ChunkActivatorImmediateEffectService`
- **具体动作**：反查新 `core` 的已链接 `triggerSource`，逐个向该 `core` 执行单目标 `publishTriggerSourceCurrentOrPersistedSyncReplay(...)`
- **预期结果**：新 `core` 的即时生效进入标准 `source -> core` 投影与排队链路
- **关键里程碑**：是

### 步骤 3：优化强制加载计费
- **操作对象**：`CrossChunkDispatchTicketSupport`
- **具体动作**：让已持票 chunk 的重复命中只续期不重复扣费，首次新拉起 chunk 才消耗预算
- **预期结果**：减少同一 chunk 重复续期造成的过度限流消耗
- **关键里程碑**：是

### 步骤 4：补自动化测试
- **操作对象**：`ChunkActivatorImmediateEffectServiceTest`、`CrossChunkDispatchServiceTest`
- **具体动作**：覆盖“新 core 进入 replay 计划”“已持票 chunk 重复 try 不重复计费”
- **预期结果**：新设计与新计费口径有回归保护
- **关键里程碑**：是

### 步骤 5：执行回归验证
- **操作对象**：Gradle 测试任务
- **具体动作**：先跑定向测试，再跑 `.\gradlew.bat test testIntegration testClient testSlow --no-daemon`
- **预期结果**：确认本轮改动未破坏现有跨区块与区块激活器语义
- **关键里程碑**：是

## 预期结果

区块激活器新增 `force_load` 模式 `core` 后，不再用 activator 本地直拉 chunk，而是通过真实 `triggerSource -> core` 的 `sync` 补发进入跨区块队列，复用现有强制加载、重试与限流链路。同时，强制加载计费口径从“按调用次数”收敛到“按首次拉起的新 chunk 次数”，减少重复续期带来的预算浪费。
