# 跨区块提示完善

生成时间：2026-04-04 09:42:18
文件名：2026-04-04_094218_跨区块提示完善.md

## 任务背景

- 当前跨区块提示只对强加载接管场景给出明确反馈。
- 当目标跨区块且目标区块未加载、但未命中强加载或常驻规则时，玩家缺少“目标所在区块已卸载”的直接提示。
- 物品入口与方块入口的提示触发条件也不一致，导致部分 relay-only 场景在方块入口下完全静默。

## 方案详情

### 现状分析

- `LinkedTargetDispatchService` 已经在 `DispatchSummary` 中区分了 `forceLoadTargetSerials` 与 `relayTargetSerials`，但 `buildCrossChunkNotifyMessages(...)` 只在 `hasForceLoadHandled()` 时返回消息，且只输出强加载目标行。
- `TriggerSourceBlockEntity` 仍用 `hasForceLoadHandled()` 作为是否发送提示的门槛，而 `LinkerItem` / `SyncLinkerItem` 已经使用 `hasCrossChunkHandled()`。
- 语言资源中已有 `message.redstonelink.crosschunk.notify.relay_targets`，可以直接承接“目标区块已卸载”的文案更新。

### 技术方案

- 复用现有 `DispatchSummary`，不改跨区块派发逻辑，只改提示构建与触发条件。
- 将跨区块提示的总开关判定统一为 `hasCrossChunkHandled()`，保证 relay-only 场景也能进入提示链路。
- `buildCrossChunkNotifyMessages(...)` 的 header 改为统计 `crossChunkHandledCount()`，并在 `relayTargetSerials` 非空时补一行“目标所在区块已卸载，当前缓冲等待恢复”的提示。
- 同步更新中英文语言资源和单元测试，锁定新提示语义。

### 影响范围

- 服务端提示汇总：`src/main/java/com/makomi/data/LinkedTargetDispatchService.java`
- 方块入口提示触发：`src/main/java/com/makomi/block/entity/TriggerSourceBlockEntity.java`
- 用户可见文案：`src/main/resources/assets/redstonelink/lang/zh_cn.json`、`src/main/resources/assets/redstonelink/lang/en_us.json`
- 单元测试：`src/test/java/com/makomi/data/LinkedTargetDispatchServiceTest.java`

## 原子步骤清单

### 步骤 1：补齐 relay 场景提示
- **操作对象**：`LinkedTargetDispatchService`
- **具体动作**：将提示判定从 `hasForceLoadHandled()` 改为 `hasCrossChunkHandled()`，header 改为统计跨区块总接管量，并在 `relayTargetSerials` 非空时输出“目标区块已卸载”提示行。
- **预期结果**：非强加载/常驻的 unloaded 目标也能得到明确反馈。
- **关键里程碑**：是

### 步骤 2：统一方块入口提示门槛
- **操作对象**：`TriggerSourceBlockEntity`
- **具体动作**：将发送跨区块提示的条件改为 `dispatchSummary.hasCrossChunkHandled()`。
- **预期结果**：方块入口与物品入口口径一致，不再漏掉 relay-only 场景。
- **关键里程碑**：是

### 步骤 3：同步文案与测试
- **操作对象**：语言资源、`LinkedTargetDispatchServiceTest`
- **具体动作**：更新 `relay_targets` 文案，并新增测试覆盖 relay-only 提示与 header 统计逻辑。
- **预期结果**：用户可见提示和自动化回归都与新语义一致。
- **关键里程碑**：是

## 预期结果

- 当目标跨区块且未加载时：
  - 命中强加载/常驻规则的目标继续显示强加载提示；
  - 未命中强加载/常驻、只能进入缓冲的目标明确提示“目标所在区块已卸载”。
- 物品入口与方块入口的跨区块提示行为保持一致。
