# 事件信号覆盖与sync清理语义修复

生成时间：2026-04-12 12:46:00
文件名：2026-04-12_124600_事件信号覆盖与sync清理语义修复.md

## 任务背景
最新提交调整了 `core` 目标端的信号模型后，游戏内非压力回归主集合基本通过，但 `x23` mixed direct 全组合逐 tick 验证持续失败。进一步比对用户预期后确认，当前实现把 `pulse/toggle` 作为可并存的历史事件快照保留，并允许 `sync` 失效后回退到旧事件，这与本轮确认的新语义不一致。

本轮需要把目标端事件/同步语义收紧为：
- `pulse/toggle` 属于同一个事件域，事件间互相覆盖；
- 同 tick 仅保留更高优先级事件结果（`pulse > toggle`）；
- 同 tick 或更晚的 `sync` 会清理事件持久化；
- `sync` 失效时仅允许回退到仍存在的 `sync`，不再回露旧事件；
- `pulse` 到期后保留的是其自身回落结果，而不是更早的 `toggle`。

## 方案详情

### 现状分析
- 当前 `ActivatableTargetConcurrentBucketComponent` 显式保留 `pulse/toggle` 双事件快照，并通过 `pruneOlderFramesForIncoming` 禁止跨模式剪裁旧快照。
- 当前 `ActivatableTargetArbitrationComponent` 在重算 authority 时会同时从 `sync/pulse/toggle` 三类候选中选 winner，因此 `sync` 移除后会回退到旧事件。
- 现有内部测试也已固化了“pulse 结束后回退到旧 toggle”与“sync 结束后回退到旧 toggle”的旧语义，需要同步更新。
- `x23` bench 用例与逐 tick 模板依赖旧语义，因此在新实现调整后需一并校正。

### 技术方案
采用“最小收口”的方式修复，而不是重写整个目标端状态机：

1. 在并发组件内补事件域覆盖与同步清理能力。
   - 让更晚或同 tick 更高优先级事件进入时主动清掉被覆盖的旧事件快照。
   - 让同 tick 或更晚 `sync` 进入时主动清掉事件快照，避免后续回退到旧事件。

2. 收紧 delta/批处理入口对同 tick 低优先级事件的接受逻辑。
   - 同 tick 已有更高优先级 winner 时，低优先级事件不再作为 fallback 候选写入快照。
   - 批处理路径与单条 delta 路径保持同样规则，避免同 tick batch 与 direct 语义不一致。

3. 保持 pulse 到期后的派生输出为“回落结果本身”。
   - 即 pulse 窗口结束后直接清掉 pulse 真值，若没有更晚事件或有效 sync，则输出保持回落后的关闭态。
   - 不再通过旧 toggle 快照重新点亮。

4. 同步更新内部单测与 `x22/x23` 逐 tick 断言。
   - 删除或改写旧语义测试。
   - 为“事件互相覆盖”“sync 清理事件持久化”“pulse 到期不回露旧 toggle”补充保护测试。

## 原子步骤清单

### 步骤 1：收口事件域持久化
- **操作对象**：`ActivatableTargetConcurrentBucketComponent`
- **具体动作**：新增“事件互相覆盖”“sync 清理事件快照”的最小辅助逻辑，并在 pulse/toggle 记录路径复用
- **预期结果**：目标端不再同时长期保留可回退的旧 `pulse/toggle` 事件
- **关键里程碑**：是

### 步骤 2：统一 direct 与 batch 的接受规则
- **操作对象**：`ActivatableTargetDispatchSupport`
- **具体动作**：调整 activation/sync delta 的接受与提交流程，使同 tick 低优先级事件不落盘、同 tick 或更晚 sync 会清掉事件快照
- **预期结果**：single delta 与 batch 共享同一语义，`sync` 失效后不回退旧事件
- **关键里程碑**：是

### 步骤 3：更新仲裁与内部单测
- **操作对象**：`ActivatableTargetArbitrationComponent`、`ActivatableTargetBlockEntityInternalTest`
- **具体动作**：必要时收紧候选回退逻辑，并将旧语义测试改写为新语义保护测试
- **预期结果**：内部逻辑与单测统一到“事件互斥、sync 清理事件”模型
- **关键里程碑**：是

### 步骤 4：校正逐 tick 用例与模板
- **操作对象**：`Bench.FunctionalTrace.Expectations.ps1`、`x23` bench case
- **具体动作**：仅在实现修正后按新语义最小调整逐 tick 期望与必要的场景 reset
- **预期结果**：`x23` 断言与当前实现设计一致
- **关键里程碑**：否

### 步骤 5：回归与文档交付
- **操作对象**：bench/debug suite、`docs_dev/reviews`、必要时 `docs_dev/experiences`
- **具体动作**：复跑 `functional-mixed-combinations-direct-debug.json`，必要时补跑 `functional-mixed-direct-debug.json`，再补审查文档
- **预期结果**：确认回归结果并形成可追溯记录
- **关键里程碑**：是

## 预期结果
- 目标端事件语义改为单事件域覆盖模型，不再保留会被后续 `sync`/新事件回露的旧 `toggle/pulse`。
- `pulse` 到期后保持其自身回落结果，不再从旧 `toggle` 复活。
- `x23` 逐 tick 组合场景恢复与设计一致，`x22` 不被破坏。
