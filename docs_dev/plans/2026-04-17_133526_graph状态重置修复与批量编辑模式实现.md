# graph状态重置修复与批量编辑模式实现

生成时间：2026-04-17 13:35:26
文件名：2026-04-17_133526_graph状态重置修复与批量编辑模式实现.md

## 任务背景

当前网页 `graph` 页面存在两个直接影响可用性的问题：

- 编辑节点 alias 时，输入内容会被清空，并且当前选中节点会跳回到第一个节点
- 现有拓扑编辑只有“单个 triggerSource 的 replace 勾选列表”，无法满足 `n -> m` 的批量编辑需求

同时，现有服务端 graph 保存协议已经稳定在 `RenameNodeAlias` 与 `ReplaceTriggerSourceTargets` 两类结构化操作上，因此本轮优先在前端完成状态流修复和批量编辑模式实现，不扩大到服务端协议扩展。

## 方案详情

### 现状分析

- `App` 中的 `graphBundle` 每次渲染都会重新解析，导致 `GraphViewer` 接收到新的对象引用。
- `GraphViewer` 当前使用整个 `graphBundle` 对象作为重置 effect 的依赖，因此父组件轻微重渲染也会触发 draft 和选中态重置。
- 当前拓扑编辑 UI 仅支持单个 `triggerSource` 的 `replace`，且入口位于右侧详情面板，不能表达 `n -> m` 批量操作。
- 服务端当前只接受 `RenameNodeAlias` 与 `ReplaceTriggerSourceTargets`，但这已经足够承接前端的 `add/remove/replace` 批量编辑，因为前端可以把不同编辑模式统一折算为最终目标集合覆盖。

### 技术方案

1. 修复 graph 状态重置链路：
   - 在 `App` 中稳定 `graphBundle` 引用
   - 在 `GraphViewer` 中只在真正切换 graph 文件/快照时重置本地 draft 与默认选中节点
2. 实现新的拓扑编辑模式：
   - 工具栏新增 `view / add / remove / replace` 模式
   - 进入编辑模式后，点击 `triggerSource` 选择来源集合，点击 `core` 选择目标集合
   - 右侧面板展示批量编辑摘要、选择清单与“应用到草稿”按钮
3. 保持服务端协议不变：
   - `add/remove/replace` 最终都在前端转成每个 `triggerSource` 的 `ReplaceTriggerSourceTargets` 草稿操作
   - 仍然采用显式 `Save`
4. 更新节点视觉反馈：
   - 批量编辑中选中的 source/target 节点需要在图中有明显高亮
   - 保留单节点详情查看与 alias 编辑

### 影响范围

- `webapp/src/components/GraphViewer.tsx`
- `webapp/src/app.css`
- `docs_dev/reviews/**`
