# 信号模型边界收口

生成时间：2026-04-11 23:03:54
文件名：2026-04-11_230354_信号模型边界收口.md

## 任务背景

当前仓库已经把 `sync / toggle / pulse` 三类信号拆入统一目标端仲裁模型，但外围生命周期、持久化与跨区块接管边界仍未完全收口。结合本轮确认后的语义，目标是将信号模型明确为：

- `sync`：唯一的来源级持久信号，享有失效、补发、重算、过滤器运行期补偿等生命周期服务。
- `toggle / pulse`：事件信号，不享有来源级生命周期服务，但其事件结果仍可在目标端持久化，并在时间上覆盖较早的 `sync` 结果。
- `relay`：仅 `sync` 推荐开启；`toggle / pulse` 保留兼容能力，但默认与推荐都保持关闭。

本轮仅确认并固化实施方案，不直接修改业务实现。

## 方案详情

### 现状分析

- 目标端 `ActivatableTargetBlockEntity`、`ActivatableTargetArbitrationComponent`、`ActivatableTargetConcurrentBucketComponent` 已具备“按时间键覆盖、同时间固定仲裁”的基础能力。
- 当前 `sync` 已完整接入来源快照、目标上线 replay、来源 attach replay、过滤器变化补偿、来源失效与重算，语义上已经接近“唯一持久信号”。
- 当前 `toggle / pulse` 虽然在派发入口上是事件语义，但仍保留来源级并发桶、NBT 持久化和 `TRIGGER_SOURCE_INVALIDATION` 联动清理，这会把它们误提升为“带来源生命周期服务的长期贡献”。
- 跨区块队列仍支持 `toggle / pulse` relay，并保留实验性“无限等待”配置；这与“仅 `sync` 推荐开启 relay”存在设计张力，需要收口为“支持但不推荐”。

### 技术方案

本次收口不推翻现有仲裁骨架，而是收紧“哪类信号享有哪一层状态服务”：

1. 保留统一仲裁规则  
   `sync / pulse / toggle` 继续共享“时间上覆盖 + 同时间固定仲裁”的裁决模型，保持当前用户可感知的覆盖语义。

2. 将 `sync` 固定为来源级持久信号  
   `sync` 继续保留来源贡献表、来源失效、过滤器差分补偿、目标上线 replay、来源 attach replay、跨区块最新态 relay 等完整生命周期服务。

3. 将 `toggle / pulse` 收口为目标级事件结果  
   `toggle / pulse` 不再作为“来源长期贡献”参与失效、补发、过滤器补偿与 attach replay；它们只在目标端留下事件结果快照，用于重启后恢复当前结果态与后续仲裁比较。

4. 区分“持久化结果”与“生命周期服务”  
   `toggle / pulse` 仍可持久化，但持久化对象改为“目标本地事件结果快照”，而不是“来源桶长期存活”。这样既满足事件结果可延续，又不让其享有 `sync` 的来源级服务。

5. 收口 relay 推荐口径  
   配置与文档明确：`sync` 是唯一推荐开启 relay 的信号；`toggle / pulse` 的 relay 配置保留为兼容或实验能力，但默认关闭、不作为推荐模型。

## 原子步骤清单

### 步骤 1：收紧目标端状态分层
- **操作对象**：`ActivatableTargetBlockEntity`、`ActivatableTargetConcurrentBucketComponent`、`ActivatableTargetArbitrationComponent`
- **具体动作**：将 `sync` 保持为来源级并发贡献；将 `toggle / pulse` 改为目标本地事件结果快照参与仲裁，不再作为长期来源桶真值。
- **预期结果**：目标端结构上可区分“来源状态”与“事件结果”两层。
- **关键里程碑**：是

### 步骤 2：调整目标端持久化结构
- **操作对象**：`ActivatableTargetPersistenceHelper`、`ActivatableTargetBlockEntity`
- **具体动作**：保留 `sync` 来源级持久化；将 `toggle / pulse` 的持久化改为目标结果快照字段，并处理旧字段兼容读取。
- **预期结果**：读档后能恢复事件结果，但不再恢复 `toggle / pulse` 的来源级生命周期状态。
- **关键里程碑**：是

### 步骤 3：收紧来源失效与过滤器补偿边界
- **操作对象**：`ActivatableTargetDispatchSupport`、`InternalDispatchDeltaRuleSupport`、`LinkDispatchFilterService`、`LinkNodeLifecycleDispatchEvents`
- **具体动作**：让 `TRIGGER_SOURCE_INVALIDATION`、attach replay、target chunk load replay、过滤器运行期差分补偿仅作用于 `sync`。
- **预期结果**：`toggle / pulse` 不再享有节点生命周期服务与拦截导致的补发/失效。
- **关键里程碑**：是

### 步骤 4：收口跨区块 relay 推荐模型
- **操作对象**：`CrossChunkDispatchService`、`CrossChunkDispatchQueueSupport`、`CrossChunkDispatchRuntimeSupport`、配置模板
- **具体动作**：保留 `toggle / pulse` relay 兼容入口，但在默认配置、注释和说明中明确仅 `sync` 推荐开启 relay；必要时压缩实验性文案，避免误导。
- **预期结果**：默认配置与推荐模型和新语义一致。
- **关键里程碑**：否

### 步骤 5：补齐自动化测试基线
- **操作对象**：`tools/bench/**`、相关单元测试/集成测试
- **具体动作**：新增或改写用例，验证：
  - `sync` 仍具备 replay、失效、补发、过滤器补偿能力
  - `toggle / pulse` 可在时间上覆盖 `sync`
  - `toggle / pulse` 重进世界后恢复目标结果，但不因来源上下线或过滤器变化获得生命周期补偿
  - 默认推荐配置下仅 `sync` relay 为推荐路径
- **预期结果**：自动化证据与新设计一致。
- **关键里程碑**：是

### 步骤 6：同步文档与说明
- **操作对象**：`docs_dev/使用说明.md`、机制设计文档、必要公开文档
- **具体动作**：更新“信号模型”“relay 推荐口径”“重启恢复语义”“过滤器影响范围”等描述。
- **预期结果**：文档口径与实现一致，不再混淆“事件结果持久化”和“来源生命周期服务”。
- **关键里程碑**：否

## 预期结果

- `sync` 成为唯一的来源级持久信号。
- `toggle / pulse` 被明确为事件信号：可以覆盖旧结果、可以在目标端持久化结果，但不再享有来源级生命周期服务。
- 默认配置与推荐玩法明确为“仅 `sync` 推荐开启 relay”。
- 自动化测试、配置说明和机制文档与该模型保持一致。

## 风险与注意事项

- 若只移除 `toggle / pulse` 的失效补偿而不重构其持久化结构，重启后可能残留旧来源桶脏态。
- `toggle` 的“结果持久化”与“离线 relay 净奇偶”需严格区分，避免再次把 relay 语义误当生命周期语义。
- `pulse` 若继续跨重启保留到期信息，需要谨慎处理世界时间推进与过期判定，避免读档即过期或异常延长。
- 本轮残余风险：`toggle` 结果持久化字段的最小结构、旧 NBT 兼容策略和 bench 断言口径仍需在实施阶段细化；除此之外无。
