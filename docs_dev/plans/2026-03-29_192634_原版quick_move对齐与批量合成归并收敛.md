# 原版 quick_move 对齐与批量合成归并收敛

生成时间：2026-03-29 19:26:34
文件名：2026-03-29_192634_原版quick_move对齐与批量合成归并收敛.md

## 任务背景

当前第二层实现虽然已经切到“即时处理”，但还有两个明显偏差：

- `QUICK_MOVE` 的目标分区仍依赖前后态净增量推断，不是按原版菜单路由对齐；
- `shift` 点击结果槽的批量合成不会主动收敛，产物进入背包后仍会散开。

同时，本轮还有一条明确约束：

- mixin 尽量只负责“捕捉时机”，不在 mixin 内持有复杂上下文，也不在 mixin 内承载具体业务逻辑。

## 方案详情

### 现状分析

- 原版 `AbstractContainerMenu#doClick(...)` 在 `ClickType.QUICK_MOVE` 分支中，会循环调用菜单自己的 `quickMoveStack(...)`，因此结果槽的 `shift` 点击本身就是原版批量合成入口；
- 原版“优先分区”不由 `AbstractContainerMenu` 全局统一定义，而是由各菜单自己的 `quickMoveStack(...)` 和 `moveItemStackTo(...)` 范围/方向共同决定；
- 以 `CraftingMenu` 为例，结果槽 `0` 的 `quickMoveStack(...)` 会把产物路由到玩家背包区整段，并使用反向扫描；
- 当前第二层 service 仍通过“前后快照净增最多分区”去猜落点侧，属于启发式，不够稳定；
- 当前第二层只识别“已有有效序号”的物品，而批量合成新产物在进入背包当下通常还没有序号，因此会被直接跳过。

### 技术方案

- 保留 `AbstractContainerMenu` mixin，但把职责缩减为：
  - `HEAD` 通知本地 service“点击开始”；
  - `RETURN` 通知本地 service“点击结束”；
  - mixin 不再缓存 `clickedStack/carriedStack/snapshot` 等具体上下文；
- 在 `PairableItemAggregateMenuNormalizationService` 内维护本地点击上下文，并按点击类型分别处理：
  - `QUICK_MOVE`：
    - 按菜单类型和源槽语义解析“原版目标区”；
    - 第一批先覆盖 `CraftingMenu` 结果槽批量合成和“容器区 <-> 玩家背包区”双区菜单；
    - 对目标区内的新产物先补齐序号，再执行一次同类聚合归并；
  - `PICKUP_ALL`：
    - 保持现有“本地即时扫描并入”方向；
    - 所有参考栈选择和上下文恢复也下沉到 service 内。
- 对未知菜单保持保守策略：
  - 无法稳定识别原版目标区时，不做第二层归并，避免误整理到错误分区。

- `src/main/java/com/makomi/data/PairableItemAggregateMenuNormalizationService.java`
- `src/main/java/com/makomi/mixin/AbstractContainerMenuAggregateNormalizationTriggerMixin.java`

## 原子步骤清单

### 步骤 1：收缩 mixin 责任
- **操作对象**：`AbstractContainerMenuAggregateNormalizationTriggerMixin`
- **具体动作**：删除 mixin 中的点击前业务缓存字段，只保留时机转发
- **预期结果**：mixin 只负责捕捉时机，不负责承载业务上下文
- **关键里程碑**：是

### 步骤 2：下沉点击上下文与 quick move 目标策略
- **操作对象**：`PairableItemAggregateMenuNormalizationService`
- **具体动作**：在 service 内维护点击前后上下文，并按菜单类型解析原版目标区
- **预期结果**：`QUICK_MOVE` 不再依赖净增量猜测，而是按菜单路由归并
- **关键里程碑**：是

### 步骤 3：修复批量合成散开
- **操作对象**：`PairableItemAggregateMenuNormalizationService`
- **具体动作**：对结果槽 `shift` 点击返回后的目标区先补序号，再执行聚合归并
- **预期结果**：批量合成产物在一次点击结束后主动收敛
- **关键里程碑**：是

### 步骤 4：补回归测试
- **操作对象**：`PairableItemAggregateMenuNormalizationServiceTest`
- **具体动作**：覆盖结果槽目标区识别、双区菜单方向、未知菜单保守跳过等场景
- **预期结果**：行为边界具备自动化回归保护
- **关键里程碑**：否

## 预期结果

- `QUICK_MOVE` 的第二层归并与原版菜单路由更一致；
- `shift` 点击结果槽的批量合成结束后，目标区内产物会主动收敛，不再散开；
- mixin 只保留时机转发职责，业务逻辑集中到本地 service，便于维护和测试；
- 未知菜单在目标区不明时保守跳过，不引入错误归并。

## 语义对齐说明

- 命名校验：本方案不新增旧术语输出，仍保持 `triggerSource/core` 语义基线；
- 方向校验：本方案仅调整菜单聚合链路，不涉及 `triggerSource -> core` 写入方向；
- 文案校验：新增注释与文档不引入旧术语泄漏；
- 映射校验：不改变 `LinkNodeType.TRIGGER_SOURCE/CORE` 与 `triggerSource/core` 的映射；
- 兼容校验：不新增“写旧字段”逻辑，保持读旧写新边界不变；
- 残余风险：原版 `quickMoveStack(...)` 是菜单特化逻辑，本轮只先覆盖可稳定识别的菜单路由；未知菜单继续保守跳过。
