# 转发器实现

生成时间：2026-04-23 22:38:26
文件名：2026-04-23_223826_转发器实现.md

## 任务背景
需要为 RedstoneLink 新增“转发器”节点。该节点对外作为一个统一节点使用，但内部不能新增第三种图语义，仍需保持现有 `triggerSource/core` 双语义体系与方向隔离规则。用户已明确：
- 中文名固定为“转发器”
- 内部由两类现有语义构成
- 两侧共用同一序号
- 首版只实现 `1/2 tick` 固定延迟
- 不实现 `0 tick`
- 贴图已存在，仅按现有双层渲染方式接入

## 方案详情

### 现状分析
- 当前图语义只有 `triggerSource/core` 两类，命令、索引、跨区块、OCC、trace 都建立在该前提上。
- `PairableNodeBlockEntity` 默认只承载单一 `(type, serial)` 身份，无法直接表达“同一方块同时拥有 core 与 triggerSource 身份”。
- 序号分配由 `LinkSavedDataSerialSupport` 按两套独立计数器维护，不能天然获得“同号双身份”。
- 现有 pairing GUI 与网络通道已分别支持 `triggerSource` 与 `core`，可以复用，不必首版重写一整套双列表编辑器。

### 技术方案
- 新增“转发器”方块、物品、方块实体、语言与资源接入，但不新增新的 `LinkNodeType`。
- 新增同号双身份序号治理能力：
  - 为转发器分配一个同时对 `triggerSource/core` 都未占用、未退役的数字。
  - 放置、自愈重分配、退役、别名同步都以“双身份统一”处理。
- 新增转发器方块实体：
  - 输入侧按 `core` 身份接收现有派发与重算。
  - 输出侧按 `triggerSource` 身份注册到图中，并在延迟到期后将当前真值继续向下派发。
  - 输出侧补齐 sync replay 快照记录，保证跨区块 current truth 不在转发器层断掉。
- 新增转发器编辑页：
  - 统一显示转发器序号与别名。
  - 提供延迟模式切换。
  - 提供“输入侧配对”“输出侧配对”两个入口，复用现有 pairing screen。
- 展示侧统一补齐 tooltip、GUI 标题 token 与相关显示文案，保证对外只展示“转发器”概念。

## 原子步骤清单

### 步骤 1：补齐双身份序号与生命周期基础
- **操作对象**：`LinkSavedData`、`LinkSavedDataSerialSupport`、退役/别名相关服务
- **具体动作**：新增转发器同号序号分配、放置解析、自愈与双侧退役/别名镜像规则
- **预期结果**：转发器始终以一个序号对应一组 `core + triggerSource`
- **关键里程碑**：是

### 步骤 2：实现转发器运行态方块实体
- **操作对象**：新增转发器方块与方块实体
- **具体动作**：在单个方块实体中同时承载输入侧 `core` 与输出侧 `triggerSource` 身份，实现 `1/2 tick` 固定延迟与 sync replay
- **预期结果**：转发器可完成“接收 -> 延迟 -> 再派发”
- **关键里程碑**：是

### 步骤 3：接入注册与资源
- **操作对象**：注册表、语言文件、模型/方块状态/物品资源
- **具体动作**：注册转发器方块/物品/方块实体，接入现有贴图与双层渲染
- **预期结果**：转发器可正常获取、放置与渲染
- **关键里程碑**：否

### 步骤 4：接入编辑与展示链路
- **操作对象**：客户端 screen、网络 payload、tooltip/HUD/上下文 token
- **具体动作**：新增统一转发器编辑入口并复用现有 pairing 子页，补齐对外展示
- **预期结果**：玩家可配置延迟并分别编辑输入侧/输出侧配对
- **关键里程碑**：是

### 步骤 5：补充测试与验证
- **操作对象**：单元测试、集成测试、必要的游戏内验证
- **具体动作**：补充同号分配、双侧退役、延迟转发、展示链路测试，并执行自动化回归
- **预期结果**：功能正确且不破坏现有节点语义
- **关键里程碑**：是

## 预期结果
- 新增对外统一的“转发器”节点。
- 保持内部 `triggerSource/core` 语义不变，不引入第三节点类型。
- 支持 `1 tick / 2 tick` 固定延迟转发。
- 对外统一序号、别名和主要展示文案。
- 保持现有命令、跨区块、OCC、trace 语义体系可复用。
