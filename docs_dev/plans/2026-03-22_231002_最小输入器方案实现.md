# 最小输入器方案实现

生成时间：2026-03-22 23:10:02
文件名：2026-03-22_231002_最小输入器方案实现.md

## 任务背景

当前 bench、诊断和后续自动化测试已经具备“构场 + 建链 + 采样”能力，但输入驱动仍分裂为两套：

1. `sync triggerSource` 通过外部脚本控制红石方块输入
2. `pulse/toggle` 通过命令批量激活驱动

这会带来三类问题：

1. 驱动模型不统一，难以扩展多波形和多目标并发
2. bench 与后续模拟输入能力重复造轮子
3. 未来若要支持复杂拓扑、多路并发或状态联动，现有脚本层驱动难以复用

因此本轮实现一版最小输入器方案，先把“统一输入 job + 波形引擎 + 两类执行器”搭起来。

## 方案详情

### 现状分析

- `triggerSource` 侧已具备真实红石输入语义：
  - 普通信号触发器按边沿触发
  - `sync triggerSource` 按输入强度变化触发
- `core` 侧已具备 `sync/pulse/toggle` 三类并发语义桶与裁决逻辑
- bench 已有两种半成品驱动：
  - `sync_square_wave`
  - `activate_batch`
- 当前代码中还没有统一的“输入播放服务”，也没有运行时输入 job 管理层

### 技术方案

本轮只实现最小可用子集：

1. 只做内存态 job，不持久化
2. 波形只支持：
   - `square`
   - `custom_sequence`
3. 端点只支持：
   - `triggerSource` 输入
   - `core sync` 直输
4. `core pulse/toggle` 暂不做直输，留到下一阶段配合“模拟贡献者键”抽象

核心结构：

1. `InputPlaybackService`
   - 维护运行中 job
   - 服务端 tick 驱动
   - 提供 `start/stop/list/clear`
2. `InputWaveformSpec`
   - 统一定义每 tick 的功率样本
3. `InputJobSpec`
   - 定义目标端点、serial 集合、波形、总时长、相位等
4. 两类执行器
   - `triggerSource` 输入执行器
   - `core sync` 直输执行器

### 关键取舍

- 波形统一按 `0~15` 功率样本建模，而不是一开始就分裂成 `on/off` 与“事件模式”
- `triggerSource` 侧通过“真实红石输入”和“模拟输入”取 `max` 叠加
- `core sync` 直输暂时用服务内临时来源 serial 作为最小方案
- 不在本轮抽象 `core` 的通用模拟贡献者键，避免范围失控

### 影响范围

- `src/main/java/com/makomi/data/`：新增输入播放服务与波形模型
- `src/main/java/com/makomi/block/`、`src/main/java/com/makomi/block/entity/`：为发射器接入模拟输入层
- `src/main/java/com/makomi/command/`：新增 `/redstonelink input` 命令
- `src/main/resources/assets/redstonelink/lang/`：新增命令文案
- `docs_dev/使用说明.md`：新增最小输入器使用说明
- `src/test/java/com/makomi/`：新增最小测试

## 原子步骤清单

### 步骤 1：输入 job 与波形模型
- **操作对象**：`src/main/java/com/makomi/data/input/**`
- **具体动作**：新增端点枚举、波形类型、job 规格、运行态 lane 状态模型
- **预期结果**：形成统一输入描述层
- **关键里程碑**：是

### 步骤 2：输入播放服务
- **操作对象**：`src/main/java/com/makomi/data/input/InputPlaybackService.java`
- **具体动作**：实现运行时 job 管理、server tick 推进、start/stop/list/clear
- **预期结果**：服务端可持续播放输入 job
- **关键里程碑**：是

### 步骤 3：triggerSource 模拟输入叠层
- **操作对象**：`LinkSignalEmitterBlock` 相关方块实体与辅助逻辑
- **具体动作**：接入瞬时模拟输入功率，统一按 `max(real, simulated)` 计算输入
- **预期结果**：发射器侧支持波形输入
- **关键里程碑**：是

### 步骤 4：core sync 直输执行器
- **操作对象**：输入服务与 `ActivatableTargetBlockEntity` 调用侧
- **具体动作**：使用临时来源 serial 向 `core` 注入 `sync`，并在 job 结束时清理
- **预期结果**：支持多路 `core sync` 直输并发
- **关键里程碑**：是

### 步骤 5：命令入口
- **操作对象**：`src/main/java/com/makomi/command/ModCommands.java`
- **具体动作**：新增 `/redstonelink input start|stop|list|clear`
- **预期结果**：可直接启停输入 job
- **关键里程碑**：是

### 步骤 6：文案、说明与测试
- **操作对象**：语言文件、`docs_dev/使用说明.md`、测试目录
- **具体动作**：补充命令文案、使用说明和最小单元测试
- **预期结果**：形成可用闭环
- **关键里程碑**：否

## 预期结果

完成后，项目将具备一版最小可用输入器：

1. 可对 `triggerSource` 播放方波或自定义序列输入
2. 可对 `core` 直接播放 `sync` 强度序列
3. 支持多 job、多目标并发
4. 可被 bench、诊断命令和后续自动化测试直接复用

## 语义对齐说明

- 命名统一使用 `triggerSource/core`
- `triggerSource` 仍是来源语义，`core` 仍是目标语义
- `core sync` 直输内部仍建模为“模拟来源对目标贡献”，不改变方向约束
- 与 `LinkNodeType.TRIGGER_SOURCE/CORE` 保持一一对应
- 本轮不引入 `com.makomi.api.v1.*`
- 残余风险：`core sync` 临时来源 serial 仅为过渡方案，后续仍建议升级为真正的模拟贡献者键抽象
