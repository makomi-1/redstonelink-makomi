# 命令层 place、audit、node 基础命令拆分

生成时间：2026-03-24 21:31:59
文件名：2026-03-24_213159_命令层place_audit_node基础命令拆分.md

## 任务背景

前两轮已经完成 `input`、`node trace`、`link` 命令的拆分，但 `ModCommands` 仍然保留 `place`、`audit`、`node get/list/retire` 等大块实现，入口文件继续承担了过多命令注册和执行细节。当前目标是在不改变命令行为、不改变用户可见命令路径的前提下，继续收敛命令层组织结构，让 `ModCommands` 更接近纯根装配器。

## 方案详情

### 现状分析

- `ModCommands` 同时负责根命令注册、多个命令组的执行逻辑、专属枚举和内部记录类型，职责边界偏大。
- `node` 命令当前已经拆出 `trace`，但 `get/list/retire` 仍内联在根入口类中，命令组织不完整。
- `place` 和 `audit` 具有较强模块内聚性，其辅助方法并不适合继续堆叠到全局 `CommandTreeSupport`。
- 前两轮已经验证“命令注册器 + 模块内 support”模式可稳定复用，适合继续沿用。

### 技术方案

- 新增 `command/node/NodeCommandRegistry.java`，收拢 `node get/list/retire`，并统一组合 `ActivateCommandRegistry`、`NodeTraceCommandRegistry` 与 `RetireBatchCommandRegistry`。
- 新增 `command/place/PlaceCommandRegistry.java`，收拢 `place setblock/fill` 及其放置校验逻辑。
- 新增 `command/audit/AuditCommandRegistry.java`，收拢 `audit` 和 `audit summary [format]`。
- 全局共用逻辑继续保留在 `CommandTreeSupport`，但 `place`、`audit`、`node` 专属 helper、枚举和记录类型下沉到各自模块，避免新的公共 support 再次膨胀。
- `ModCommands` 仅保留根命令装配、少量仍未拆出的共用逻辑，以及与本轮无关的既有实现。

### 影响范围

- `src/main/java/com/makomi/command/ModCommands.java`
- `src/main/java/com/makomi/command/CommandTreeSupport.java`
- `src/main/java/com/makomi/command/node/NodeCommandRegistry.java`
- `src/main/java/com/makomi/command/place/PlaceCommandRegistry.java`
- `src/main/java/com/makomi/command/audit/AuditCommandRegistry.java`

## 原子步骤清单

### 步骤 1：梳理 node 基础命令依赖
- **操作对象**：`ModCommands` 中 `node get/list/retire` 相关方法
- **具体动作**：确认命令注册、执行方法、辅助枚举与格式化/校验依赖边界
- **预期结果**：得到可迁移到 `NodeCommandRegistry` 的完整实现闭包
- **关键里程碑**：是

### 步骤 2：抽离 node 基础命令注册器
- **操作对象**：`command/node`
- **具体动作**：新增 `NodeCommandRegistry` 并迁移 `node get/list/retire`，保留对既有 `activate/trace/retire batch` 子树的组合
- **预期结果**：`node` 相关命令结构在模块目录内聚合
- **关键里程碑**：是

### 步骤 3：抽离 place 命令注册器
- **操作对象**：`command/place`
- **具体动作**：新增 `PlaceCommandRegistry` 并迁移 `place setblock/fill` 及相关私有辅助实现
- **预期结果**：放置类命令独立，`ModCommands` 不再承载具体放置流程
- **关键里程碑**：否

### 步骤 4：抽离 audit 命令注册器
- **操作对象**：`command/audit`
- **具体动作**：新增 `AuditCommandRegistry` 并迁移审计汇总与格式解析逻辑
- **预期结果**：审计命令与数据输出逻辑独立聚合
- **关键里程碑**：否

### 步骤 5：收敛根入口
- **操作对象**：`ModCommands`
- **具体动作**：替换根命令装配为对新注册器的调用，删除已迁移的命令实现和局部类型
- **预期结果**：`ModCommands` 继续向纯入口收敛
- **关键里程碑**：是

### 步骤 6：执行回归验证
- **操作对象**：Gradle 测试任务
- **具体动作**：先跑 `CommandEntryContractTest`，再跑全标签测试任务
- **预期结果**：确认命令入口与全局回归未受拆分影响
- **关键里程碑**：是

## 预期结果

- `ModCommands` 的代码量与职责继续下降，命令层组织更清晰。
- `node`、`place`、`audit` 命令形成与 `input/link/trace` 一致的注册器结构。
- 命令路径、权限、反馈文案和行为保持兼容。
- 语义仍保持 `triggerSource -> core` 的既有方向约束，本轮不引入新的业务语义变化。
