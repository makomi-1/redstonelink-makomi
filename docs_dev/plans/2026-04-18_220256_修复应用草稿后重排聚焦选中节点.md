# 修复应用草稿后重排聚焦选中节点

生成时间：2026-04-18 22:02:56
文件名：2026-04-18_220256_修复应用草稿后重排聚焦选中节点.md

## 任务背景

当前 graph 可视化在“应用到草稿”后会触发结构重排，但画布不会跟随当前选中节点的新布局位置。上一轮为了避免整图自动跳回中心，把批量应用后的整图 `fitView` 关闭了，同时也丢掉了“重排后回到当前上下文节点”的能力。

本轮只修前端视口调度，不改 snapshot、draft 与服务端保存真值。

## 方案详情

### 现状分析

- `handleApplyBatchEdit()` 成功写入草稿后，会调用 `requestStructureLayoutRefresh({ fitViewport: false })`。
- `requestStructureLayoutRefresh()` 会先清空即时聚焦用的 `pendingFocusNodeKey`，导致重排完成后没有任何待执行的聚焦目标。
- 现有 `pendingFocusNodeKey` 适用于搜索、双击等立即聚焦，不适合结构重排后延迟到“新坐标落位之后”再执行。

### 技术方案

1. 为“结构重排后聚焦”补一条独立状态链路，不再复用即时聚焦状态。
2. 扩展 `requestStructureLayoutRefresh()`，允许同时携带“重排后聚焦节点 key”，并在需要时抑制整图自动 `fitView`。
3. `handleApplyBatchEdit()` 在草稿实际变更成功后，把当前 `selectedNodeKey` 作为重排后聚焦目标传入。
4. 重排完成、节点新位置生效后，再对该节点执行一次 `setCenter`；若该节点已不在当前画布中，则安全清空挂起状态。

### 影响范围

- `webapp/src/components/GraphViewer.tsx`
