# 扩展无线化红石原型

生成时间：2026-05-05 10:23:26
文件名：2026-05-05_102326_扩展无线化红石原型.md

## 任务背景

在现有“无线化转化器 + 无线化原版件”体系上，继续扩展原版红石分类中的常用原型。目标是让更多原版红石方块保留原版交互/受控表现，同时底层统一接入 `triggerSource/core` 语义。

## 方案详情

### 现状分析

- 当前项目已经具备三类可复用模板：
  - 同步 `triggerSource`：`WirelessStoneButtonBlock`、`WirelessStonePressurePlateBlock`、`WirelessSyncTriggerSourceBlockEntity`
  - 开关型 `core`：`WirelessOakDoorBlock`
  - 受控执行/受控外显 `core`：`WirelessPistonBlock`、`WirelessRedstoneLampBlock`、`WirelessDecorativeLightBlock`
- 无线化产物的注册、转化器配方、创造栏归类、HUD 上下文、掉落继承和 serial 语义都已有完整接线。
- 这轮不需要重新设计节点体系，只需按行为族继续扩展。

### 技术方案

按行为将本轮原型拆成三组：

1. 同步 `triggerSource`
- 补齐原版红石分类里尚未覆盖的按钮、压力板
- 统一保留原版触发特征，只把信号转接到已连接 `core`

2. 开关型 `core`
- 无线化橡木活板门
- 无线化铁活板门
- 无线化橡木栅栏门
- 无线化铁门
- 这些方块保留原版开关表现，屏蔽原版邻居红石输入，改由无线输入控制

3. 执行/输出型 `core`
- 无线化红石块：激活时持续对邻居输出，失活时停止输出
- 无线化发射器、投掷器、合成器、音符盒、TNT：无线输入到来时执行一次原版受红石触发后的动作

## 原子步骤清单

### 步骤 1：确定缺失的红石分类按钮与压力板
- **操作对象**：原版红石分类清单、现有无线化原型清单
- **具体动作**：列出尚未覆盖的按钮和压力板变种，只保留原版红石分类相关项
- **预期结果**：得到本轮 `triggerSource` 目标集合
- **关键里程碑**：是

### 步骤 2：补齐同步 triggerSource 原型
- **操作对象**：按钮/压力板方块类、方块实体、注册表、配方与资源
- **具体动作**：复用 `WirelessStoneButtonBlock` 与 `WirelessStonePressurePlateBlock` 模式新增缺失变种
- **预期结果**：原版红石分类按钮/压力板补齐为同步 `triggerSource`
- **关键里程碑**：否

### 步骤 3：补齐开关型 core 原型
- **操作对象**：活板门、栅栏门、铁门相关方块与方块实体
- **具体动作**：保留原版开关体验，屏蔽原版邻居红石输入，改为承接无线输入
- **预期结果**：门类/活板门类可被无线控制
- **关键里程碑**：是

### 步骤 4：补齐执行型与输出型 core 原型
- **操作对象**：红石块、发射器、投掷器、合成器、音符盒、TNT
- **具体动作**：把无线输入转接为原版受控表现；红石块实现持续邻居输出语义
- **预期结果**：执行件与输出件纳入无线化体系
- **关键里程碑**：是

### 步骤 5：补齐统一接线
- **操作对象**：`ModBlocks`、`ModItems`、`ModBlockEntities`、`ModItemGroups`、`LinkGuiDisplayContext`、`lang`、`loot`、`recipe`
- **具体动作**：接通注册、创造栏、远外显、掉落继承、无线化转化配方与模型复用
- **预期结果**：所有新增原型可正常产出、放置、配对和使用
- **关键里程碑**：否

### 步骤 6：回归验证
- **操作对象**：Gradle 编译与自动化测试
- **具体动作**：串行执行 `compileJava`、`compileClientJava`、`test testIntegration testClient testSlow`
- **预期结果**：验证新增原型未破坏既有无线化体系
- **关键里程碑**：是

## 预期结果

- 原版红石分类中常用的按钮、压力板、门类、执行件和输出件被纳入无线化体系
- 所有新增实现继续统一使用 `triggerSource/core`
- 无线化转化器能够产出对应原型，且物品放置后保持既有 serial、HUD、掉落与配对语义
