# 第二层归并即时处理与双击扫描实现

生成时间：2026-03-29 18:42:24
文件名：2026-03-29_184224_第二层归并即时处理与双击扫描实现.md

## 任务背景

当前第二层实现仍基于“原版点击命中后登记票据，服务器下一 tick 消费”的模型。该模型虽然避免了改写原版主流程，但实测仍有两个核心问题：

- `QUICK_MOVE` 归并侧判断不稳定，容易整理到点击源侧而不是落点侧；
- `PICKUP_ALL` 双击同类物品的命中信息不充分，仅靠票据和返回态难以稳定还原原版扫描语义。

本轮目标是在保留菜单层 mixin 的前提下，移除“下一 tick 票据消费”，改为点击返回后立即处理：

- `shift` 快移与 `shift` 点击结果槽：即时识别目标侧分区并归并；
- 双击同类物品：即时执行一段参考原版扫描顺序的聚合并入逻辑。

## 方案详情

### 现状分析

- 现有票据模型本质上是“延后猜测”，只能依赖前后态差分推断命中结果；
- `QUICK_MOVE` 的正确目标是“落点侧分区”，而不是点击源槽所在分区；
- `PICKUP_ALL` 属于菜单级多槽扫描，不是单槽动作，仅记录 `slotId + referenceStack` 仍然缺少足够上下文；
- 第一层点击 helper 已经有成熟的“有序前缀并入、64 上限、单件快照回填”语义，可复用到第二层即时实现中。

### 技术方案

- 保留 `AbstractContainerMenu` 的点击触发 mixin，但职责改为“缓存前态 + 返回后即时处理”，不再登记票据；
- `QUICK_MOVE`：
  - 在 `HEAD` 记录点击前槽位物品和参考物品对应的分区计数快照；
  - 在 `RETURN` 对比前后快照，寻找“非源分区中序号数量净增最多”的目标分区；
  - 仅对该目标分区执行同类物品稳定归并，避免全菜单或错误分区整理；
- `PICKUP_ALL`：
  - 在 `RETURN` 基于当前光标聚合栈，参考原版方向规则执行双轮槽位扫描；
  - 对命中的同类可配对物品执行即时并入光标，直到达到 `64` 个序号上限或无可并入槽位；
  - 不再使用“下一 tick”消费，不依赖额外票据状态。

## 原子步骤清单

### 步骤 1：补即时处理入口
- **操作对象**：`PairableItemAggregateMenuNormalizationService`
- **具体动作**：移除票据与 server tick 消费模型，新增快照捕获、目标侧即时归并、双击即时扫描入口
- **预期结果**：第二层逻辑不再依赖下一 tick，点击返回后可立即完成处理
- **关键里程碑**：是

### 步骤 2：重写菜单点击触发链路
- **操作对象**：`AbstractContainerMenuAggregateNormalizationTriggerMixin`
- **具体动作**：在点击前缓存 `clickedStack/carriedStack/QUICK_MOVE 快照`，在点击后分别调用即时归并和即时扫描
- **预期结果**：`QUICK_MOVE` 和 `PICKUP_ALL` 都能在正确时机触发第二层处理
- **关键里程碑**：是

### 步骤 3：补即时语义回归测试
- **操作对象**：`PairableItemAggregateMenuNormalizationServiceTest`
- **具体动作**：覆盖“只归并目标侧分区”“双击按方向扫描并即时并入光标”“非目标物品不处理”等场景
- **预期结果**：关键命中逻辑具备自动化回归保护
- **关键里程碑**：否

## 预期结果

- `shift` 快移与 `shift` 结果槽批量合成后，只整理真正落点侧；
- 双击同类物品不再靠票据猜测，而是立即按原版风格扫描并并入光标；
- 第二层仍不改写原版业务主流程，仅在命中后做局部补充；
- 不新增额外业务语义，不改变 `triggerSource/core` 命名、方向和持久化结构。

## 语义对齐说明

- 命名校验：本方案未新增旧术语输出，内部语义仍保持 `triggerSource/core` 基线；
- 方向校验：本方案仅处理物品菜单聚合，不涉及 `triggerSource -> core` 方向写入链路；
- 文案校验：新增文档与后续注释不引入旧术语泄漏；
- 映射校验：不改变 `LinkNodeType.TRIGGER_SOURCE/CORE` 与 `triggerSource/core` 的映射；
- 兼容校验：不新增兼容层写回逻辑，本轮仅调整第二层聚合命中方式；
- 残余风险：`PICKUP_ALL` 的原版细节很多，本方案只复用其扫描顺序与方向，不复刻全部内部判定；若遇到极少数特殊菜单，仍可能需要后续针对性补充。
