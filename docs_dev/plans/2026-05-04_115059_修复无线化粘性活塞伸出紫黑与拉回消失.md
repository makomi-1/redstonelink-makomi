# 修复无线化粘性活塞伸出紫黑与拉回消失

生成时间：2026-05-04 11:50:59
文件名：2026-05-04_115059_修复无线化粘性活塞伸出紫黑与拉回消失.md

## 任务背景

新增`无线化粘性活塞`后，用户在游戏内发现三类问题：

1. 粘性活塞伸出时整段占两格都显示为紫黑缺模型，回缩后恢复；
2. `无线化海晶灯`被推出时正常，但被拉回时会消失；
3. 可见`core`块被粘性活塞推出后也会消失且不恢复。

对现有实现与本地 1.21.1 原版资源对照后，前两类问题的主因已经明确：一是 sticky 资源模型引用名写错，二是回缩时对前方格子做了“拉回后又无条件删除”的顺序错误。

## 方案详情

### 现状分析

- `wireless_sticky_piston.json` 与 `wireless_piston_head.json` 当前引用了不存在的原版 sticky piston / sticky head 模型名，导致伸出态底座和头部都取不到模型。
- `WirelessPistonBlock.triggerEvent(...)` 在粘性回缩路径里：
  - 先尝试执行拉回；
  - 随后仍无条件 `removeBlock(frontPos, false)`；
  - 这会把刚拉回到前方格子的移动块直接删掉。
- 可见 `core` 的消失大概率与第二条是同一类“回缩尾部误删”问题，先去掉这个顺序 bug 再复测。

### 技术方案

1. 修正 sticky 相关 blockstate JSON 对原版模型的引用，保证 1.21.1 下模型路径真实存在。
2. 让 `tryPullBlockOnRetract(...)` 返回布尔值，表示本次回缩是否已经通过拉回消费了前方格子。
3. 只有当本次没有发生拉回时，才执行原有的 `removeBlock(frontPos, false)`。

### 影响范围

- `src/main/java/com/makomi/block/WirelessPistonBlock.java`
- `src/main/resources/assets/redstonelink/blockstates/wireless_sticky_piston.json`
- `src/main/resources/assets/redstonelink/blockstates/wireless_piston_head.json`

## 原子步骤清单

### 步骤 1：修正 sticky 资源模型引用
- **操作对象**：`wireless_sticky_piston.json`、`wireless_piston_head.json`
- **具体动作**：改成 1.21.1 原版真实存在的模型名
- **预期结果**：粘性活塞伸出时不再整段紫黑
- **关键里程碑**：是

### 步骤 2：修正粘性回缩误删顺序
- **操作对象**：`WirelessPistonBlock`
- **具体动作**：让拉回函数返回“是否已消费前方格子”，仅在未拉回时删除前方格
- **预期结果**：海晶灯与可见 core 被拉回时不再被回缩尾部删掉
- **关键里程碑**：是

### 步骤 3：构建与测试验证
- **操作对象**：Gradle 任务
- **具体动作**：串行执行 `compileJava`、`compileClientJava`、`test testIntegration testClient testSlow`
- **预期结果**：确认修复不引入编译或自动化回归
- **关键里程碑**：是

## 预期结果

完成后，`无线化粘性活塞`应当在伸出时正常显示，且被其拉回的无线海晶灯与已接入搬运协议的可见 core 不再在回缩末尾消失。
