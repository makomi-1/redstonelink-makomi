# 节点容器回收与创造放置策略第二轮

生成时间：2026-04-28 11:45:39
文件名：2026-04-28_114539_节点容器回收与创造放置策略第二轮.md

## 任务背景

在首期 `hide` 节点、智能眼镜幽灵渲染、定向面编辑工具落地后，第二轮不继续扩展可见节点的面编辑，而是收敛到“节点容器协作”。

本轮目标是把节点容器升级为：

- 统一放置入口
- 统一回收入口
- 创造模式下可切换的放置消耗策略控制器

这样可以把 `hide` 节点和可见节点统一纳入一套回收/再部署流程，为后续香草编辑工具与红石场发生器打底。

## 方案详情

### 现状分析

当前项目中已经具备以下基础能力：

- `SmartNodeContainerItem/Data/Menu/Screen` 已具备库存、当前放置类型与自动排序。
- 各节点方块已有掉落继承逻辑，会把序号、连接快照、别名或配置写回掉落物。
- 节点移除后会进入待退役队列，并依赖掉落物/玩家背包匹配取消退役。

因此第二轮不需要重写节点生命周期，而是要在“节点容器回收”上补一条受控保留路径，让节点在被容器接管时不进入误退役。

### 技术方案

#### 一、节点容器新增状态

在现有容器轻量快照上新增一个布尔状态：

- `creativeAutoConsumeEnabled`

语义：

- 生存模式：始终按正常消耗处理，不看此开关
- 创造模式 + 开：从容器中弹出真实节点并正常消耗
- 创造模式 + 关：放置时保留容器内节点库存，只生成一次临时放置副本

该状态写入 `SmartNodeContainerData`，并通过 `SmartNodeContainerMenu` 数据槽同步到客户端 GUI。

#### 二、节点容器回收流

回收入口限定为：

- 主手持有 `SmartNodeContainer`
- 潜行
- 对节点方块执行右键

支持对象：

- 可见 `core`
- 可见 `triggerSource`
- `hide core`
- `hide sync triggerSource`
- `repeater`

不在本轮支持范围的普通功能方块（过滤器、区块激活器）保持原样，不额外扩展。

#### 三、受控回收语义

回收时按以下顺序执行：

1. 基于方块 `BlockState + BlockEntity` 取真实掉落结果
2. 优先把可接受的掉落物并入节点容器
3. 若容器空间不足：
   - 生存模式：未并入部分生成掉落物
   - 创造模式：同样允许掉落
4. 若至少有一个结果被成功保留（进入容器或掉落实体）：
   - 移除方块
   - 取消该节点的待退役任务

关键点：

- 回收不直接“手搓一个新物品”，而是优先复用现有 `getDrops` 结果，这样能保留序号与配置继承逻辑。
- 回收不走“普通破坏 + 捡起”的异步链，而是走同步受控链，减少丢失或误退役。

#### 四、待退役协作

因为节点移除时现有逻辑会登记 `pending retire`，本轮需要补一条显式取消路径：

- 当受控回收确认“节点物品已被容器接管或已生成掉落物”后，取消对应 `type + serial` 的待退役记录。

这样可以避免“节点已经安全保留，但序号在宽限期结束后仍被退役”的错误。

#### 五、容器 GUI 调整

本轮在智能节点容器界面新增一个控制项：

- `创造自动消耗：开/关`

交互约束：

- 只有创造玩家打开容器时允许切换
- 生存玩家看见该状态但不允许修改，或直接显示为说明文本

不新增新的复杂 GUI 页签，仅在现有右侧面板补一个按钮。

### 影响范围

本轮预期涉及：

- `SmartNodeContainerData`
- `SmartNodeContainerItem`
- `SmartNodeContainerMenu`
- `SmartNodeContainerScreen`
- 待退役协作 helper
- 中英文文案
- `gradle.properties` 版本号更新为 `1.8.7-alpha`

本轮明确不涉及：

- 可见节点面编辑推广
- 香草编辑工具
- 红石场发生器
- 贴图改动
- `Mixin`

- **操作对象**：`SmartNodeContainerData`

- **关键里程碑**：是

## 预期结果

完成本轮后，应达到以下状态：

- 节点容器可对可见节点、隐藏节点和转发器执行 `Shift+右键` 受控回收
- 容器满时可回退为掉落物保留
- 创造模式可切换“放置是否自动消耗”
- 生存模式仍保持正常消耗与正常回收行为
- 不引入可见节点面编辑扩展

残余风险：

- 受控回收若未正确取消待退役，可能出现“物品保留成功但序号被退役”的竞态
- 容器回收若直接调用破坏链路，可能与现有 GUI 打开交互冲突，因此必须只在“主手节点容器 + 潜行”条件下拦截
