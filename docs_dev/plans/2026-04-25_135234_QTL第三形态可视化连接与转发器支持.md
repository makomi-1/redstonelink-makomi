# QTL第三形态可视化连接与转发器支持

生成时间：2026-04-25 13:52:34
文件名：2026-04-25_135234_QTL第三形态可视化连接与转发器支持.md

## 任务背景
- 快速连接工具当前只有 `serial/channel` 两种模式，无法满足“第三形态：可视化连接”的交互需求。
- 用户要求新增 `visualize` 第三模式，支持左键添加显示、右键移除显示、`Shift + B` 清空显示，并以穿墙连线形式展示对象之间的真实连接关系。
- 现有转发器在 QTL 的采集、频道模式预览和对象扫描链路中支持不完整，需要同步补齐，保证第三模式与既有两种模式对转发器的支持一致。
- 文档索引中已明确“可视化图扩展支持转发器，并做自隔离”，因此本轮实现需要沿用“转发器是 `triggerSource/core` 合成节点”的既有设计语义。

## 方案详情

### 现状分析
- `QuickLinkToolData.Mode` 只有 `SERIAL/CHANNEL`，模式循环、tooltip、GUI、物品模型状态都依赖该枚举。
- `QuickLinkNetworkClientHandlerSupport` 已有左键采集、右键应用的客户端命中解析和发包链，可复用为第三模式的添加/移除显示入口。
- `QuickLinkOutlineRenderer` 已有穿墙外框和频道预览请求缓存逻辑，适合扩展为“显示对象 + 连线”的统一渲染承载点。
- `NodeIdentitySnapshot` 已包含维度和坐标，服务端具备返回“对象位置 + 当前连接”的数据基础。
- 转发器当前在 `QuickLinkCollectService` 和 `QuickLinkOutlineRenderer` 的扫描逻辑中未被完整纳入，导致频道模式和预览模式不能按逻辑身份正确支持转发器。

### 技术方案
- 将 QTL 扩展为第三模式 `visualize`，模式循环改为 `serial -> channel -> visualize -> serial`。
- `visualize` 模式不写物品缓存，仅在客户端维护“显示对象列表”和颜色槽，避免污染现有 `serial/channel` 缓存语义。
- 新增 quick-link 可视化查询协议：客户端提交目标对象请求，服务端返回该对象的真实连接图快照，包含对象身份、位置、显示文本及可绘制边集合。
- 转发器在可视化中按聚合对象处理：分别查询其 `triggerSource` 身份的出边和 `core` 身份的入边，再在客户端合并成单个显示对象，并做自隔离，避免绘制内部自环。
- 现有 `serial/channel` 模式同步补齐转发器支持，使采集、频道预览、线框扫描都按当前缓存类型对应到转发器的 `triggerSource/core` 逻辑身份。
- `visualize` 模式下的潜行右键不再打开编辑器，改为通过按键与左/右键交互完成显示对象管理。

### 影响范围
- 数据与模式：`QuickLinkToolData`
- 客户端输入与提示：`RedstoneLinkClient`、`QuickLinkToolItem`
- quick-link 客户端交互与本地状态：`QuickLinkNetworkClientHandlerSupport`
- quick-link 网络编解码与注册：`QuickLinkNetwork*`
- 服务端查询与转发器兼容：`QuickLinkNetworkServerHandlerSupport`、`QuickLinkCollectService`
- 客户端渲染：`QuickLinkOutlineRenderer`
- GUI/头部/文案：`QuickLinkToolScreen`、`GuiHeaderContextSupport`、`lang`
- 测试与审查：相关测试类、`docs_dev/reviews/`

- **具体动作**：新增 `visualize` 模式，调整模式循环、按键提示、tooltip 与切换反馈，处理 `visualize` 模式下的特殊交互分支
- **预期结果**：QTL 可以稳定切换到第三模式，基础提示与物品状态一致
- **关键里程碑**：是

- **预期结果**：客户端可以获取穿墙连线渲染所需的稳定快照

## 预期结果
- 快速连接工具新增 `visualize` 第三模式。
- 玩家可以在游戏内把多个节点或转发器加入“显示对象列表”，并用不同颜色、穿墙连线直接看到它们的真实连接关系。
- 转发器在 `serial/channel/visualize` 三种 QTL 模式下都得到一致支持，并保持 `triggerSource/core` 语义、自隔离和方向约束不变。
