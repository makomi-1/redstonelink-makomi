# tooltip尾注统一与第三形态增量同步

生成时间：2026-04-26 17:11:02
文件名：2026-04-26_171102_tooltip尾注统一与第三形态增量同步.md

## 任务背景

当前若干物品的灰色补充说明行位置不统一，`SyncLinkerItem` 还缺少 `Ctrl + 滚轮调节信号强度` 提示；同时第三形态连线显示仍是一次性快照，本地显示对象在连接变化后不会自动刷新。用户要求统一灰色尾注显示规则，并把第三形态连线显示改成增量自动同步。

## 方案详情

### 现状分析

- `LinkerItem` 目前将灰色语义说明插在普通说明中间，导致尾注顺序不统一。
- `SyncLinkerItem`、`RepeaterBlockItem`、`SmartNodeContainerItem`、`ChunkActivatorBlockItem` 的灰色说明入口分散，样式和位置不一致。
- 第三形态可视化对象由客户端本地缓存持有，服务端只在“添加显示对象”时返回一次完整快照；后续连接变化不会触发刷新。
- `LinkSavedData` 已具备 `graphRevision / sourceRevision / coreRevision / runtimeNodeVersion`，可作为对象级增量同步的基线。

### 技术方案

- 在 `LinkerItem` 中收口灰色尾注入口，统一将灰色说明追加到 tooltip 最底部，并为子类提供可扩展的灰色尾注钩子。
- `SyncLinkerItem` 通过灰色尾注钩子补 `Ctrl + 滚轮调节信号强度`；`RepeaterBlockItem`、`SmartNodeContainerItem` 与 `ChunkActivatorBlockItem` 则将既有灰色说明整理到最低部。
- 扩展第三形态快照结构，为客户端缓存和首包快照补充 revision 基线；新增“批量增量刷新请求/响应”网络包，客户端按固定间隔上报当前显示对象基线，服务端仅返回变更对象与移除对象。
- 继续复用现有本地渲染与悬停 tooltip 逻辑，仅替换缓存更新方式，不改 `triggerSource -> core` 的业务写入语义。

### 影响范围

- 物品 tooltip：`LinkerItem`、`SyncLinkerItem`、`RepeaterBlockItem`、`SmartNodeContainerItem`、`ChunkActivatorBlockItem`
- 文案资源：`zh_cn.json`、`en_us.json`
- 第三形态可视化：`QuickLinkOutlineRenderer`、`QuickLinkVisualizationSnapshotService`
- 网络链路：`QuickLinkNetwork`、`QuickLinkNetworkRegistrationSupport`、`QuickLinkNetworkPayloadSupport`、`QuickLinkNetworkServerHandlerSupport`、`QuickLinkNetworkClientHandlerSupport`

## 原子步骤清单

### 步骤 1：统一 tooltip 灰色尾注入口
- **操作对象**：`LinkerItem` 及相关物品类、lang 文件
- **具体动作**：重排 tooltip 追加顺序，新增灰色尾注钩子，并补遥控器说明与既有灰色说明样式。
- **预期结果**：所有灰色补充说明位于 tooltip 最底部，且样式统一为灰色。
- **关键里程碑**：是

### 步骤 2：扩展第三形态快照基线
- **操作对象**：`QuickLinkVisualizationSnapshotService`、`QuickLinkNetwork`
- **具体动作**：给显示对象快照补 revision 基线字段，并定义增量同步请求/响应结构。
- **预期结果**：客户端和服务端可以围绕显示对象建立统一的版本比对基线。
- **关键里程碑**：是

### 步骤 3：实现客户端定时增量同步
- **操作对象**：`QuickLinkNetworkClientHandlerSupport`、`QuickLinkNetworkServerHandlerSupport`、`QuickLinkOutlineRenderer`
- **具体动作**：客户端定时上报当前显示对象基线，服务端仅返回变更对象和删除对象，客户端更新本地缓存。
- **预期结果**：第三形态显示对象会随连接变化自动刷新，不依赖重新手动添加。
- **关键里程碑**：是

### 步骤 4：回归验证与审查文档
- **操作对象**：Gradle 测试、`docs_dev/reviews/`
- **具体动作**：执行全标签自动化测试，校验文本编码与异常字符，并输出五段式审查文档。
- **预期结果**：改动具备自动化回归证据与可追溯审查记录。
- **关键里程碑**：是

## 预期结果

- 遥控器、转发器、智能节点容器及相关物品的灰色说明统一位于 tooltip 最底部。
- 第三形态可视化显示支持基于 revision 的对象级增量同步，连接变化后会自动刷新本地显示。
- 改动不引入 `com.makomi.api.v1.*` 依赖，不改变 `triggerSource/core` 语义边界。
