# directBatching配置语义同步方案

生成时间：2026-04-02 14:55:47
文件名：2026-04-02_145547_directBatching配置语义同步方案.md

## 任务背景
前一轮实现已将 loaded direct 链路的目标级批打包能力从 `sync` 扩展到 `toggle/pulse`，但配置键、内部字段和文档仍沿用 `directSyncBatching` 命名，形成“名称仅指 sync、实际行为覆盖 sync/toggle/pulse”的语义偏差。本轮目标是在不改变运行时行为边界的前提下，将配置项语义同步到当前实现，并按“读旧写新”保留兼容读取。

## 方案详情

### 现状分析
- 跨区块配置解析器当前仅读取 `crosschunk.directSyncBatching`。
- `RedstoneLinkCrossChunkConfig`、`RedstoneLinkConfig` 枚举与业务调用点均仍使用 `directSyncBatchingMode` / `CrossChunkDirectSyncBatchingMode` 命名。
- 默认模板与运行示例配置仍写出 `crosschunk.directSyncBatching=all_sync`。
- 使用说明虽然已解释其实际也控制 direct `toggle/pulse`，但主键名仍与真实语义不一致。

### 技术方案
采用“内部命名与外部配置同步收敛，兼容层只读旧键旧值”的最小方案：
- 将主配置键改为 `crosschunk.directBatching`。
- 将枚举与内部字段统一改名为 `CrossChunkDirectBatchingMode` / `directBatchingMode`。
- 将主值 `all_sync` 改为 `all_direct`，同时兼容解析旧值 `all_sync`。
- 解析时优先读取新键 `crosschunk.directBatching`，缺失时回退到旧键 `crosschunk.directSyncBatching`。
- 默认模板、运行示例配置和使用说明统一写新键新值。
- 业务行为保持不变：`off` / `queued_only` / `all_direct` 的实际路由逻辑不修改，仅调整命名与兼容读取。

### 影响范围
- 配置门面与枚举：`src/main/java/com/makomi/config/RedstoneLinkConfig.java`
- 跨区块配置模型与解析：`src/main/java/com/makomi/config/RedstoneLinkCrossChunkConfig.java`、`src/main/java/com/makomi/config/RedstoneLinkCrossChunkConfigParser.java`
- 默认配置模板与运行示例：`src/main/java/com/makomi/config/RedstoneLinkConfigTemplate.java`、`run/config/redstonelink-server.properties`
- 业务调用点：`src/main/java/com/makomi/data/InternalDispatchDeltaProjector.java`、`src/main/java/com/makomi/data/LinkedTargetDispatchService.java`
- 测试与文档：相关配置解析测试、行为测试、`docs_dev/使用说明.md`

## 原子步骤清单

### 步骤 1：重命名配置模型与枚举
- **操作对象**：`RedstoneLinkConfig.java`、`RedstoneLinkCrossChunkConfig.java`
- **具体动作**：将 `CrossChunkDirectSyncBatchingMode` 与 `directSyncBatchingMode` 统一改为 `CrossChunkDirectBatchingMode` 与 `directBatchingMode`
- **预期结果**：内部命名与当前行为一致
- **关键里程碑**：是

### 步骤 2：实现新键优先、旧键回退
- **操作对象**：`RedstoneLinkCrossChunkConfigParser.java`
- **具体动作**：优先读取 `crosschunk.directBatching`，兼容回退 `crosschunk.directSyncBatching`；同时兼容旧值 `all_sync`
- **预期结果**：旧配置文件继续可用，新配置输出统一为新语义
- **关键里程碑**：是

### 步骤 3：同步业务调用点与默认配置
- **操作对象**：业务调用点、配置模板、运行示例配置
- **具体动作**：将访问点、注释、默认键名和值全部切换到新命名
- **预期结果**：运行时行为不变，默认输出全部为新键新值
- **关键里程碑**：否

### 步骤 4：同步文档与测试
- **操作对象**：`docs_dev/使用说明.md`、相关单元测试
- **具体动作**：将主说明改为新键新值，并补兼容读取断言
- **预期结果**：用户文档与自动化测试同时覆盖新语义和兼容边界
- **关键里程碑**：是

## 预期结果
- 配置项主语义由 `crosschunk.directSyncBatching=all_sync` 统一迁移为 `crosschunk.directBatching=all_direct`。
- 旧键 `crosschunk.directSyncBatching` 与旧值 `all_sync` 继续可读，但不再作为默认写出。
- direct batching 对 `sync/toggle/pulse` 的真实控制范围与配置命名完全一致。
- 生命周期 replay 仍保持 `sync-only`，不改变现有边界。

## 语义对齐说明
- 命名统一收敛到 `directBatching`，避免继续输出只覆盖 `sync` 的旧语义。
- 仅影响 `triggerSource -> core` 的 loaded direct / ready-drain 批提交配置，不改变方向关系。
- 与 `LinkNodeType.TRIGGER_SOURCE/CORE` 的映射无变更。
- 兼容层严格执行“读旧写新”：读取旧键旧值，输出新键新值。
- 不引入 `com.makomi.api.v1.*` 依赖。
- 残余风险：历史 bench 文档和旧计划文档仍会保留旧键引用，但不影响当前运行配置。
