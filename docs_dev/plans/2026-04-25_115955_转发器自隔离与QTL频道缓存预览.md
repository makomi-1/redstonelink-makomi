# 转发器自隔离与 QTL 频道缓存预览

生成时间：2026-04-25 11:59:55
文件名：2026-04-25_115955_转发器自隔离与QTL频道缓存预览.md

## 任务背景
本轮需要继续收口转发器与快速连接工具（QTL）的边界语义，解决三个问题：

1. 转发器目前允许同号 `triggerSource -> core` 自连，导致内部形成自回灌。
2. QTL 处于频道缓存模式时，客户端还不能像序号缓存一样预览“同类型、同频道”的对象。
3. 需要确认转发器在实体身份与逻辑身份并存时，涉及实体变化后的承接是否与其它节点保持一致，并用回归测试锁住正确语义。

## 方案详情

### 现状分析
- 转发器当前使用统一序号承载 `triggerSource/core` 双身份，但链接索引层尚未阻止“同号自连”。
- 旧存档即使已经存在自连边，当前读取与运行时遍历仍会继续把它们当成真实连接参与派发、快照与展示。
- QTL 的频道缓存预览不能只靠客户端本地扫描完成，因为普通节点方块实体不持有通用频道真值，必须向服务端请求“当前缓存类型 + 当前频道”的成员序号列表。
- 转发器的双身份承接主链路目前设计上是完整的：实体层以 `core` 为物理身份，对外再补出同号 `triggerSource` 逻辑身份；生命周期、在线探针和放置/编辑链路都基于该双身份模型工作。

### 技术方案
1. 为转发器增加“图真值级自隔离”：
   - 写入层拒绝新增转发器同号自连。
   - 读取层过滤历史遗留自连，避免旧脏边继续参与派发、HUD、快照与导出。
   - 编解码层跳过该类非法边，让旧存档重载后自然完成清理。

2. 为 QTL 增加频道缓存预览查询：
   - 新增轻量 `C2S/S2C` 预览协议，由服务端返回“指定 `triggerSource/core` 类型 + 指定频道”的成员序号列表。
   - 客户端沿用现有序号缓存的扫描、颜色与外边框提取逻辑，只把“目标序号集合”改为服务端返回结果。
   - 缓存与节流继续遵循现有预览缓存策略，避免逐帧重复请求。

3. 对转发器“实体身份 vs 逻辑身份”补回归测试：
   - 明确锁住 `matchesNodeIdentity(...)` / `forEachNodeIdentity(...)` 的双身份契约。
   - 若实现过程中发现实体变化链路存在断点，再做最小修复；否则保持现有模型不扩散重构。

### 语义对齐说明
- 命名统一使用 `triggerSource/core`，不新增旧术语输出。
- 输入/输出方向保持 `triggerSource -> core` 单向合法性，自隔离也仅拦截该方向下的“同号非法边”。
- 与 `LinkNodeType.TRIGGER_SOURCE/CORE` 继续一一映射，不引入新的语义类型。
- 兼容层仅做“读旧写新”：旧存档里的非法自连会被读取层和保存层清掉，但不会改变其它合法连接行为。
- 残余风险：频道缓存预览引入新网络载荷后，需重点回归客户端缓存失效与跨维度切换场景。

## 预期结果
- 转发器不再接受或保留同号自连，旧存档中的该类脏边会被自动清理。
- QTL 频道缓存模式下可预览当前缓存类型对应的同频道对象，渲染方式与序号缓存一致。
- 转发器实体身份与逻辑身份的承接行为有明确测试保护，表现与其它节点保持一致。
