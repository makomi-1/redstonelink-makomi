# 快速连接工具输入防抖修复方案

生成时间：2026-03-30 16:19:33
文件名：2026-03-30_161933_快速连接工具输入防抖修复方案.md

## 任务背景

排查 quick-link 相关输入链路后确认：
- 中键清空曾受原版 `pick item` 消费顺序影响，已单独修复
- 左键采集与右键应用仍存在“同一次按下触发多次回调、多次发包”的风险

本轮目标是统一修复 quick-link 的左右键重复触发问题，并确认其它键位是否存在同类缺陷。

## 方案详情

### 现状分析

- `K` 键序号外显与 `B` 键 quick-link 模式切换都使用自定义 `KeyMapping`，当前不存在与原版同键竞争消费的问题。
- 左键采集走 `AttackBlockCallback`，右键应用走 `UseBlockCallback`，二者当前每次回调都会直接发包。
- 若同一次按下触发多次回调，服务端会连续处理多次 quick-link 请求，导致“首次成功、后续重复提示覆盖”的现象。

### 技术方案

- 在 quick-link 客户端交互层增加左右键各自的“本次按下已发送请求”状态。
- 注册客户端 tick 钩子：
  - 左键释放后复位采集状态
  - 右键释放后复位应用状态
- `AttackBlockCallback` / `UseBlockCallback` 在命中合法 quick-link 目标时：
  - 若本次按下尚未发送过，则发送请求并标记
  - 若本次按下已经发送过，则仅拦截，不再重复发包
- 其它键保持现状：
  - `K` 键不改
  - `B` 键不改
  - 中键清空维持现有上升沿检测实现

### 影响范围

- quick-link 客户端输入防抖
- 本轮方案文档

- **具体动作**：增加左右键请求锁和按键释放复位逻辑
- **预期结果**：一次左键/右键按下仅触发一次 quick-link 请求
- **关键里程碑**：是

- **操作对象**：Gradle 测试任务
- **具体动作**：执行 `.\gradlew.bat test testIntegration testClient testSlow --no-daemon`
- **预期结果**：确认输入防抖修复不破坏现有行为
- **关键里程碑**：是
