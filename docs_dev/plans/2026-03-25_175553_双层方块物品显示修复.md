# 双层方块物品显示修复

生成时间：2026-03-25 17:55:53
文件名：2026-03-25_175553_双层方块物品显示修复.md

## 任务背景
前一轮将 `core` 与发射器类 `triggerSource` 方块切为内外双层模型后，用户发现两个物品显示回归：
- 物品栏中显示为平面，而不是正常方块物品；
- 掉落模型尺寸几乎与完整方块相同，明显偏大。

本轮目标是在不改贴图内容、不改变世界双层渲染效果的前提下，修复 block item 的显示与掉落尺寸。

## 方案详情

### 现状分析
- 当前共享模板 `dual_layer_cube.json` 直接定义元素，但没有继承原版 block item 的显示变换基类。
- 对应 item model 继续直接 parent 到 block model，导致物品显示时丢失原版 block item 的标准 `display` 变换。
- 因此 GUI 与 ground 视图都退回到异常表现，出现平面化和掉落过大的问题。

### 技术方案
- 仅修共享模板 `dual_layer_cube.json`，为其补回 `minecraft:block/block` 父模型。
- 同时补 `gui_light: side`，使物品栏里的受光表现更接近普通方块物品。
- 保持现有 item model 不变，继续继承 block model，避免重复维护多份 item 资源。

### 影响范围
- `src/main/resources/assets/redstonelink/models/block/dual_layer_cube.json`
- 间接受影响：所有继承该模板的 `core` 与发射器物品显示
- 不涉及贴图、命令、网络、持久化与节点语义

## 原子步骤清单

### 步骤 1：修共享模板继承链
- **操作对象**：`dual_layer_cube.json`
- **具体动作**：补回 `minecraft:block/block` 父模型与 `gui_light` 配置。
- **预期结果**：物品栏与掉落显示重新获得标准 block item 变换。
- **关键里程碑**：是

### 步骤 2：校验 item 继承链
- **操作对象**：`models/item` 下对应 4 个 item model
- **具体动作**：确认继续复用 block model 即可，无需再拆 item 专用模型。
- **预期结果**：以最小改动完成修复。
- **关键里程碑**：否

### 步骤 3：回归验证
- **操作对象**：Gradle 自动化测试
- **具体动作**：执行全标签测试门禁，确认没有附带回归。
- **预期结果**：资源修复可用，现有功能不受影响。
- **关键里程碑**：是

- 物品栏恢复为正常方块物品观感。
- 掉落物恢复为正常 block item 大小。
