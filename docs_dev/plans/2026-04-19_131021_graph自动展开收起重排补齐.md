# graph自动展开收起重排补齐

生成时间：2026-04-19 13:10:21
文件名：2026-04-19_131021_graph自动展开收起重排补齐.md

## 任务背景

当前 graph 画布中，手动点击聚合块展开/收起时，会显式触发结构重排，因此展开成员节点后能够重新挤开并避免重叠。但对于搜索、清空搜索、孤立节点临时显示、编辑选区等“自动导致聚合块视觉展开/收起”的路径，画布虽然结构已经变化，却没有同步触发同等级别的重排，导致成员节点沿用旧坐标，出现未重新挤开的情况。用户要求补齐这些自动路径，同时明确不能改变现有“上下文自动聚焦优先于整图归位”的设计。

## 方案详情

### 现状分析

- `GraphViewer` 当前通过 `requestStructureLayoutRefresh(...)` 显式驱动手动展开/收起后的结构重排。
- 画布 `nodes/edges` 主更新 effect 在 `pendingStructureLayoutReset=false` 时会复用现有节点坐标，因此若结构变化没有置位该标记，即使 `canvasNodes/layoutEdges` 已变化，节点也不会重新布局。
- 聚合块的自动视觉展开/收起来自 `forcedVisibleNodeKeys` 变化；例如搜索命中、被选中、被临时拉回显示或进入编辑选区时，聚合成员会被自动提升到可见集合中。
- 搜索应用等路径当前只做 `focusNode(...)` 或状态切换，并未显式要求结构重排。

### 技术方案

本轮不为每个自动入口分别打补丁，而是在画布主更新链里统一检测“结构是否真的发生变化”：

1. 基于 `graphCanvasView.canvasNodes` 与 `graphCanvasView.layoutEdges` 构建稳定的结构签名。
2. 在主 `setNodes/setEdges` effect 中，若结构签名变化，则把本轮视为结构重排场景，重置节点坐标以重新执行自动布局。
3. 自动结构变化只触发“重排”，不触发 `fitView`；现有 `focusNode(...)`、`pendingAggregateFocusNodeKey`、`pendingPostLayoutFocusNodeKey` 等上下文聚焦链保持不变。
4. 手动展开/收起原有的显式 `requestStructureLayoutRefresh(...)` 逻辑继续保留；本轮是在此基础上补齐自动路径。

### 技术取舍

- 选择“统一结构签名检测”而不是逐个入口补 `requestStructureLayoutRefresh(...)`：
  - 优势：不会漏掉搜索之外的自动路径，后续新增自动展开来源也能自动覆盖。
  - 代价：需要维护一个额外的本地 `ref`，用于记录上一轮结构签名。
- 自动结构变化只重排、不整图归位：
  - 优势：严格满足“不改变现有上下文自动聚焦设计”的约束。
  - 代价：无上下文焦点的自动收起场景不会主动回到整图居中，但这是预期保守行为。

- **操作对象**：`webapp/src/components/GraphViewer.tsx`
- **具体动作**：新增基于 `graphCanvasView.canvasNodes/layoutEdges` 的稳定结构签名及上一次结构签名缓存
- **预期结果**：能够判断本轮更新是否属于真实结构变化，而不是仅高亮或选中态变化
- **关键里程碑**：是

### 步骤 2：把自动结构变化并入重排判定
- **操作对象**：`webapp/src/components/GraphViewer.tsx`
- **具体动作**：在主 `setNodes/setEdges` effect 中，将“结构签名变化”并入 `shouldResetPositions` 判定
- **预期结果**：搜索、清空搜索、临时显示、编辑选区等自动展开/收起都会重新布局并挤开

- **具体动作**：确保自动结构变化不触发新增 `fitView`，仍由既有上下文聚焦链控制视角移动
- **预期结果**：自动重排生效，但不改变当前上下文自动聚焦设计
- **关键里程碑**：是
