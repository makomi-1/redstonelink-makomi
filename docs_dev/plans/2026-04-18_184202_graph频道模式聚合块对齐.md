# graph频道模式聚合块对齐

生成时间：2026-04-18 18:42:02
文件名：2026-04-18_184202_graph频道模式聚合块对齐.md

## 任务背景

当前 graph 网页前端已经支持 `serial / channel` 两种显示模式，但频道模式目前只有 `channelHub` 两级虚拟连接，没有继续复用序号模式已有的两类聚合块。用户希望频道模式也支持 `triggerSource/core` 两类聚合块，且展开、收起、详情和渲染行为尽量与序号模式一致。

## 方案详情

### 现状分析

- `serial` 模式已经有完整的两段式聚合流程：先做 `core` 聚合，再做 `triggerSource` 聚合，并且包含替边、可见节点裁剪、展开布局和详情面板。
- `channel` 模式当前只生成 `triggerSource -> channelHub -> core` 两级可视化边，没有进入聚合阶段。
- 聚合详情当前默认把 `connectedNodeKeys` 当作真实节点处理；如果频道模式聚合块连接的是 `channelHub`，详情面板需要支持画布节点类型，而不是只支持真实节点。

### 技术方案

- 保持真实保存语义不变，本轮只扩展前端画布视图层。
- 在频道模式的 `channelHub` 投影视图之上，接入与序号模式一致的两段式聚合：
  - 按相同输入集合聚合 `core`
  - 再按相同输出集合聚合 `triggerSource`
- 聚合块在频道模式下允许把 `connectedNodeKeys` 指向 `channelHub`，同时继续维护关联到的真实 `triggerSource/core` 集合，用于搜索高亮和文案统计。
- 复用现有聚合块的展开/收起、包围框和布局链路，只补齐频道模式下的详情展示和图例说明。

### 影响范围

- `webapp/src/components/graphViewer/types.ts`
- `webapp/src/components/graphViewer/canvas.tsx`
- `webapp/src/components/GraphViewer.tsx`
- 视情况微调 `webapp/src/app.css`

## 原子步骤清单

### 步骤 1：扩展聚合数据模型
- **操作对象**：`webapp/src/components/graphViewer/types.ts`
- **具体动作**：补充聚合块在频道模式下所需的 connected/related 信息，使其能表达与 `channelHub` 的连接，同时继续保留真实 `triggerSource/core` 关联集合。
- **预期结果**：频道模式聚合块的数据结构可以完整描述成员、连接对象和搜索相关信息。
- **关键里程碑**：是

### 步骤 2：为频道模式接入两段式聚合
- **操作对象**：`webapp/src/components/graphViewer/canvas.tsx`
- **具体动作**：在 `channelHub` 投影视图生成后，按序号模式同样的顺序生成 `core aggregate` 和 `triggerSource aggregate`，并完成替边、可见节点裁剪、布局边补充。
- **预期结果**：频道模式画布中能渲染两类聚合块，并支持展开/收起。
- **关键里程碑**：是

### 步骤 3：补齐详情与图例
- **操作对象**：`webapp/src/components/GraphViewer.tsx`、`webapp/src/app.css`
- **具体动作**：让聚合块详情支持显示 `channelHub` 这类画布节点，并同步频道模式下的图例、统计和说明文案。
- **预期结果**：频道模式的聚合块在右侧详情和图例中解释完整，不再只支持真实节点。
- **关键里程碑**：否

### 步骤 4：验证与文档化
- **操作对象**：构建测试命令与 `docs_dev/reviews/`
- **具体动作**：执行 `npm.cmd run typecheck`、`.\gradlew.bat buildWebapp --no-daemon`、`.\gradlew.bat test testIntegration testClient testSlow --no-daemon`，完成后写审查文档。
- **预期结果**：本轮修改有完整验证证据和审查留痕。
- **关键里程碑**：是

## 预期结果

频道模式除了 `channelHub` 外，也能按与序号模式一致的规则显示 `triggerSource/core` 两类聚合块；点击聚合块后，展开、收起、聚焦、包围框和详情展示都能在频道模式下闭合，同时真实保存语义仍保持只处理 `triggerSource -> core`。
