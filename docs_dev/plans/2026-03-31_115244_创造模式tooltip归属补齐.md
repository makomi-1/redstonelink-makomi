# 创造模式 tooltip 归属补齐

生成时间：2026-03-31 11:52:44
文件名：2026-03-31_115244_创造模式tooltip归属补齐.md

## 任务背景
创造模式下，部分 RedstoneLink 物品在 tooltip 中原本应显示的蓝色归属行 `RedstoneLink` 会消失。  
对比发现，状态面板工具默认不会自动改写物品组件，因此通常不触发该问题；而可配对方块物品、遥控器等会在持有阶段写入运行时组件，导致原版创造标签匹配失败。

## 方案详情

### 现状分析
- 原版蓝色归属行来自创造模式 tooltip 逻辑，不是普通 tooltip 自带文本。
- 原版匹配创造标签时会按“物品类型 + 组件”精确判断。
- 本模组部分物品会在持有或交互后自动写入 `CUSTOM_DATA` / `CUSTOM_MODEL_DATA`，从而让原版不再认定它们属于 `RedstoneLink` 创造标签。
- 仅依赖原版创造界面补行会受其内部调用链影响；直接在本模组 tooltip 中定点补齐更稳。

### 技术方案
- 新增一个公共 tooltip 支持工具。
- 当满足以下条件时，直接在 tooltip 第 2 行补入蓝色 `RedstoneLink`：
  - 当前为创造模式 tooltip；
  - 当前物品栈与该物品默认实例的组件不一致；
  - 当前 tooltip 尚未包含同样的归属行。
- 将该工具复用到现有有自定义 tooltip 的本模组物品中，保证插入位置统一为“物品名之后、业务 tooltip 之前”。

### 影响范围
- `src/main/java/com/makomi/item/` 下 tooltip 相关物品类
- 新增一个 tooltip 公共支持工具类

## 原子步骤清单

### 步骤 1：新增创造模式归属补齐工具
- **操作对象**：`com.makomi.item` 公共工具类
- **具体动作**：封装“仅在创造模式且组件已偏离默认实例时插入蓝色 `RedstoneLink`”的统一逻辑
- **预期结果**：归属补齐条件集中管理，避免分散复制判断
- **关键里程碑**：是

### 步骤 2：接入现有自定义 tooltip 物品
- **操作对象**：`PairableBlockItem`、`LinkerItem`、`QuickLinkToolItem`、`StatePanelToolItem`
- **具体动作**：在各自 `appendHoverText(...)` 开头调用公共工具，保证归属行插在物品名后
- **预期结果**：创造模式下组件已变化的本模组物品恢复蓝色归属行
- **关键里程碑**：是

## 预期结果
创造模式下，因运行时组件变化而丢失原版蓝色归属行的 RedstoneLink 物品，会在与原版相同的位置恢复显示蓝色 `RedstoneLink`；未发生组件偏移的物品保持原样，不产生重复归属行。
