# bench批次A定义层与模板层整理

## 任务背景
当前 bench 工具链已经具备功能场景、性能场景、suite 编排与 datapack 公共函数，但定义层仍集中在少数大文件中：
- `tools/bench/functional-matrix.json`
- `tools/bench/matrix.json`
- `tools/bench/suites/first-mandatory.json`

同时，功能场景中的 phase 结构存在高频重复，后续继续扩展会反向推高 `run-bench.ps1` / `run-bench-suite.ps1` 的读取复杂度。

本批次仅处理“定义层与模板层整理”：
- 将 case 外置到独立文件；
- 引入 phase / drive 模板；
- 让 suite 更薄；
- 对执行脚本仅做新结构读取兼容，不拆执行引擎主逻辑。

## 方案详情

### 现状分析
- 功能场景共 10 个、性能场景共 5 个，仍以内嵌 `matrix.cases` 形式集中维护。
- 功能场景重复 phase 主要集中在 `trace_mount`、`trace_unmount`、`trace_read_tick_assert`、`wait_ticks`、`activate_batch`。
- 现有 `run-bench.ps1` 只识别 `matrix.cases`，`run-bench-suite.ps1` 通过 `matrixPath + caseId` 校验 case 是否存在。
- 因此若直接外置 case，必须同步补充读取层归一化逻辑，但不需要改执行流程主体。

### 技术方案
- 为功能与性能场景分别建立 `cases/` 目录。
- 将 `functional-matrix.json` 与 `matrix.json` 改为“索引 + defaults + templatePaths + casePaths”结构。
- 新增：
  - `tools/bench/templates/functional/phases.json`
  - `tools/bench/templates/performance/drive.json`
- case 文件使用 `template` 字段声明模板引用，脚本读取时展开为原有 phase/drive 结构。
- `run-bench.ps1` 与 `run-bench-suite.ps1` 只增加：
  - 读取 casePaths
  - 读取 templatePaths
  - 展开模板并归一化为旧的 `matrix.cases`
- `first-mandatory.json` 通过 `defaults` 收口公共 `benchAction` 与 `matrixPath`，减少重复。

### 影响范围
- `tools/bench/functional-matrix.json`
- `tools/bench/matrix.json`
- `tools/bench/suites/first-mandatory.json`
- `tools/bench/cases/**`
- `tools/bench/templates/**`
- `tools/bench/run-bench.ps1`
- `tools/bench/run-bench-suite.ps1`

## 原子步骤清单

### 步骤 1：落定义层目录
- **操作对象**：`tools/bench/cases/**`、`tools/bench/templates/**`
- **具体动作**：建立 functional/performance case 目录与模板目录。
- **预期结果**：定义层具备独立落点。
- **关键里程碑**：是

### 步骤 2：外置功能与性能 case
- **操作对象**：`functional-matrix.json`、`matrix.json`、`tools/bench/cases/**`
- **具体动作**：将原内嵌 case 改为外部 JSON 文件，并在 matrix 中保留索引与默认项。
- **预期结果**：matrix 文件不再承载完整 case 体。
- **关键里程碑**：是

### 步骤 3：引入模板层
- **操作对象**：`tools/bench/templates/functional/phases.json`、`tools/bench/templates/performance/drive.json`
- **具体动作**：提取高频模板并让 case 通过 `template` 字段复用。
- **预期结果**：功能 phase 与性能 step 明显去重。
- **关键里程碑**：是

### 步骤 4：收口 suite 定义
- **操作对象**：`tools/bench/suites/first-mandatory.json`
- **具体动作**：通过 `defaults` 减少公共字段重复。
- **预期结果**：suite 更薄、更稳定。
- **关键里程碑**：否

### 步骤 5：补脚本读取兼容
- **操作对象**：`tools/bench/run-bench.ps1`、`tools/bench/run-bench-suite.ps1`
- **具体动作**：读取新结构并展开模板，仍输出旧的 `matrix.cases` 供执行引擎使用。
- **预期结果**：执行逻辑保持不变，但可消费新定义层。
- **关键里程碑**：是

### 步骤 6：验证
- **操作对象**：bench 读取入口、Gradle 自动化测试
- **具体动作**：验证 List/PrintCase/suite case 解析与全标签测试门禁。
- **预期结果**：定义层整理后可正常读取与构建。
- **关键里程碑**：是

## 预期结果
- case 从大文件中拆出，按 functional/performance 分类独立维护。
- 常用 phase / drive 模板得到复用，降低定义层重复。
- suite 入口更薄，便于后续按 smoke / mandatory / regression / performance 扩展。
- `run-bench.ps1` / `run-bench-suite.ps1` 暂不大拆，但已具备消费新结构的能力，为后续批次奠定基础。
