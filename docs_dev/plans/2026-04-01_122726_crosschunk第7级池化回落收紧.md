## 任务背景

第 7 级首轮收紧已经完成 resident 与 force-load/ready drain 的容器复用，并通过现有 crosschunk stress 专项完成了 spark 对比。对比结果显示：

- `resident` 路径的 CPU 热点和 GC 抖动明显下降，但 health 快照中的堆占用没有同步下降。
- `queue release` 路径的额外堆占用主要体现为 Eden 抬升，不像明显的老年代保留。
- `force-load` 路径的 `old gen` 增量更明显，且 profiler 热点从 ready drain 前半段迁移到了 batch flush 与 HashMap 查找。

结合 spark profiler 与源码读取，当前更像是“池化后对象长期驻留”问题，而不是每 tick 的容器重建问题。因此本轮继续沿着 crosschunk 内部收紧，但优先改为“有限复用、可回落”的池化策略。

## 方案详情

### 现状分析

- `CoreDispatchBatchScheduler` 当前会把 `TargetBatchAccumulator` 回收到 `accumulatorPool`，但没有上限与缩容路径。
- `CoreDispatchBatchScheduler` 只有在 `pendingByTarget` 与 `accumulatorPool` 同时为空时才移除 `STATE_BY_SERVER`，这会让历史峰值池长期挂在服务端状态上。
- `CrossChunkDispatchRuntimeSupport.ChunkReadyDrainCache` 当前也会把 `LinkedHashMap` 分组容器和 `ReadyDrainTargetGroup` 回收到池中，同样缺少上限或回落策略。
- `DispatchState` 会跨 tick 持有 `readyDrainCache`、`targetLocatorCache`、scratch 集合与列表；如果对象池不主动回落，burst 之后的峰值容量会继续驻留。

### 技术方案

本轮不回退现有池化设计，而是在保持复用收益的前提下引入“有限池化”：

1. 为 `CoreDispatchBatchScheduler` 的 accumulator 池增加回收上限，并在状态空闲时允许释放整个 scheduler state。
2. 为 `ChunkReadyDrainCache` 的 target-group map 池和 group 池增加上限，只保留少量常态复用对象，超出部分直接丢弃。
3. 在 crosschunk 状态退出路径上补齐 runtime scratch/pool 清理，确保空闲状态不会保留无意义的大容量容器。
4. 通过现有自动化测试和既有 bench 专项继续验证，不改 dispatch 顺序、不改 resident/force-load 语义。

## 原子步骤清单

### 步骤 1：限制 scheduler accumulator 池
- **操作对象**：`CoreDispatchBatchScheduler`
- **具体动作**：为 `accumulatorPool` 引入池上限；在 recycle 时仅保留有限数量的 `TargetBatchAccumulator`；修正服务端状态空闲时的释放条件。
- **预期结果**：batch flush 相关池不会无限保留历史峰值容量。
- **关键里程碑**：是

### 步骤 2：限制 ready drain 容器池
- **操作对象**：`CrossChunkDispatchRuntimeSupport.ChunkReadyDrainCache`
- **具体动作**：为 `readyGroupMapPool` 与 `readyGroupPool` 引入池上限；回收时仅保留少量复用对象，超出部分直接释放引用。
- **预期结果**：force-load/ready drain burst 后，ready 分组容器可以回落。
- **关键里程碑**：是

### 步骤 3：补齐空闲状态清理
- **操作对象**：`CrossChunkDispatchService.DispatchState` 相关退出路径
- **具体动作**：在 crosschunk 状态退出或停服清理时，补齐 scratch/pool 清理，确保无残留大容量容器。
- **预期结果**：状态空闲时不再挂住历史峰值池。
- **关键里程碑**：否

### 步骤 4：测试与回归
- **操作对象**：相关单元测试与全量 Gradle 测试任务
- **具体动作**：补充或调整测试验证有限池化行为不影响语义；执行 `test testIntegration testClient testSlow` 回归。
- **预期结果**：功能语义保持不变，并具备回归证据。
- **关键里程碑**：是

- 尽量保持第 7 级首轮已经取得的 GC/MSPT 改善。
