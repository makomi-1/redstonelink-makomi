# 配对GUI样式抽象与主题化

生成时间：2026-04-10 23:44:37
文件名：2026-04-10_234437_配对GUI样式抽象与主题化.md

## 任务背景

当前配对 GUI 在视觉上存在三个连续问题：一是默认背景渲染链路带入了原版模糊/幕布效果，不适合当前自定义背景图；二是输入框和按钮仍使用原版默认皮肤，难以和新背景形成一致主题；三是这些视觉逻辑分散在 screen 内，不利于后续 core、triggerSource 以及其它 GUI 复用。用户要求在不改业务语义、不改配对数据流的前提下，把背景、输入框、按钮整理为统一的可覆写样式能力，并先在 core 配对界面上落地深蓝主题。

## 方案详情

### 现状分析

- `AbstractMultiPairingScreen` 原先负责直接创建输入框与按钮，但没有样式扩展点，具体 screen 只能复用原版组件外观。
- 配对 GUI 背景需要跟随实际内容区域而不是整屏铺满，否则会放大模糊观感，也不利于形成稳定的表单容器边界。
- 当前任务只涉及客户端 GUI 渲染层；`triggerSource/core` 的命名、方向和网络提交流程均不应变动。

### 技术方案

- 抽出 `GuiBackgroundRenderSupport`，统一承载背景预设、内容包围盒包裹和 nine-slice 绘制逻辑；背景按组件最小包围框加留白渲染，而不是覆盖整屏。
- 在 `AbstractMultiPairingScreen` 增加样式钩子：
  - `backgroundPreset()` 负责选择背景预设；
  - `inputBoxStyle()` 负责选择输入框皮肤；
  - `actionButtonStyle(ActionButtonKind kind)` 负责选择按钮皮肤。
- 新增 `StyledMultiLineEditBox`，只接管输入框背景与描边绘制，保留原版多行编辑、滚动和光标行为。
- 新增 `StyledButton`，继承原版 `Button`，只接管按钮绘制，保留点击、悬停、禁用和旁白语义；颜色按普通、悬停、禁用三态切换，并乘上控件自身 alpha。
- `CorePairingScreen` 先覆写输入框和按钮样式，使用深蓝主题；其余 screen 可暂时继续使用默认样式，后续按需覆写。

### 影响范围

- `src/client/java/com/makomi/client/screen/AbstractMultiPairingScreen.java`
- `src/client/java/com/makomi/client/screen/GuiBackgroundRenderSupport.java`
- `src/client/java/com/makomi/client/screen/StyledMultiLineEditBox.java`
- `src/client/java/com/makomi/client/screen/StyledButton.java`
- `src/client/java/com/makomi/client/screen/CorePairingScreen.java`

### 语义对齐说明

- 命名检查：本轮只改 GUI 样式层，不新增业务术语；`triggerSource/core` 现有命名保持不变。
- 方向检查：不触碰来源/目标写入路径，`sourceType()`、结构化 payload 和命令语义均不变。
- 文案检查：未引入旧术语输出，也未修改持久化键名或协议字段。
- 映射检查：`LinkNodeType.TRIGGER_SOURCE/CORE` 映射保持原状。
- 兼容层检查：无新增兼容层，也无“读旧写新”数据迁移需求。
- 残余风险：仅剩视觉观感层面的游戏内确认，无业务语义风险。

## 原子步骤清单

### 步骤 1：抽出背景绘制支持
- **操作对象**：`GuiBackgroundRenderSupport`、`AbstractMultiPairingScreen`
- **具体动作**：实现背景预设、区域包裹、包围盒合并和 nine-slice 绘制，并让配对界面背景改为按内容区域渲染。
- **预期结果**：配对 GUI 不再依赖整屏背景路径，背景容器能随内容自适应。
- **关键里程碑**：是

### 步骤 2：抽出输入框皮肤能力
- **操作对象**：`StyledMultiLineEditBox`、`AbstractMultiPairingScreen`
- **具体动作**：新增可覆写输入框样式记录，并由基类通过 `inputBoxStyle()` 选择是否启用自定义输入框皮肤。
- **预期结果**：输入框风格可以由具体 screen 覆写，不影响原有编辑行为。
- **关键里程碑**：是

### 步骤 3：抽出按钮皮肤能力
- **操作对象**：`StyledButton`、`AbstractMultiPairingScreen`
- **具体动作**：新增可覆写按钮样式记录，并让确认/清空按钮统一走 `createActionButton(...)` 接入样式钩子。
- **预期结果**：按钮外观可复用、可按界面定制，默认情况下仍可回退到原版按钮。
- **关键里程碑**：是

### 步骤 4：为 core 界面落地主题样式
- **操作对象**：`CorePairingScreen`
- **具体动作**：给 core 屏幕覆写背景预设、输入框皮肤与按钮皮肤，先行验证深蓝主题链路。
- **预期结果**：core 配对界面形成统一主题，triggerSource 可后续独立扩展。
- **关键里程碑**：是

### 步骤 5：执行本地编译验证
- **操作对象**：Gradle 客户端编译任务
- **具体动作**：运行 `.\gradlew.bat compileClientJava processResources --no-daemon`，确认新增渲染类与屏幕接线能通过编译。
- **预期结果**：客户端 GUI 改动在当前工作区可稳定编译。
- **关键里程碑**：是

## 预期结果

- 配对 GUI 背景改为围绕实际内容区域渲染，摆脱默认整屏模糊链路。
- 输入框和按钮都具备统一的、可覆写的样式接入方式。
- core 配对界面先落地深蓝主题，其它界面可复用同一套扩展骨架。
- 全程不修改配对业务语义，只影响客户端表现层。
