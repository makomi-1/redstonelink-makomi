# 跨模式迁回后孤立节点自动临时显示

生成时间：2026-04-20 12:10:13
文件名：2026-04-20_121013_跨模式迁回后孤立节点自动临时显示.md

## 任务背景

当前网页 graph 编辑器在“另一模式节点池”中把频道模式节点迁回序号模式后，如果这些节点在序号模式下尚无显式边，它们会进入孤立节点池而不会出现在主画布。虽然现有手动“揭示孤立节点”链路会把节点临时显示并聚焦，但跨模式迁回草稿后并没有复用这条链路，导致用户看到“应用到草稿后节点不在主画布里”，上下文聚焦也可能落空。

本次目标是在不改变现有上下文自动聚焦设计的前提下，让“本次跨模式迁回后新变成孤立节点”的节点自动进入临时显示集合，从而让现有聚焦链路自然生效。

## 方案详情

### 现状分析

- 序号主画布只展示 `connectionMode=serial` 且参与显式边或被强制可见的节点。
- 真正的孤立节点目前只在右侧孤立节点池展示，用户手动点选后才会写入 `pinnedIsolatedNodeKeys` 并触发 `focusNode(...)`。
- 跨模式迁回序号的入口 `handleApplyCrossModeDraft(...)` 会重排并请求聚焦，但不会自动把新孤立节点并入 `pinnedIsolatedNodeKeys`。

### 技术方案

1. 在前端新增一个小范围辅助逻辑：基于“应用后的草稿图”筛出本次跨模式迁回节点里、在序号模式下边数为 0 的节点。
2. 仅当当前处于 `serial` 视图且这些节点确实新变成孤立节点时，把它们合并进 `pinnedIsolatedNodeKeys`。
3. 不新增新的聚焦逻辑，继续沿用现有 `requestStructureLayoutRefresh({ focusNodeKey })`。节点一旦因 `pinnedIsolatedNodeKeys` 进入画布，现有聚焦即可自然命中。
4. 补前端测试，验证跨模式迁回后的新孤立节点会进入当前画布上下文，而不是只留在孤立节点池。

### 影响范围

- `webapp/src/components/GraphViewer.tsx`
- `webapp/src/components/GraphViewer.test.tsx`
- `docs_dev/reviews/`

- **操作对象**：`GraphViewer.tsx`
- **具体动作**：在 `handleApplyCrossModeDraft(...)` 附近增加基于应用后草稿图的孤立节点筛选逻辑。
- **预期结果**：可以精确拿到“本次迁回后新孤立”的节点集合。

- **操作对象**：`GraphViewer.tsx`
- **具体动作**：把上述节点并入 `pinnedIsolatedNodeKeys`，不改变手动揭示和现有聚焦逻辑。
- **预期结果**：这些节点在迁回后直接进入主画布上下文。
- **关键里程碑**：是

## 预期结果

- 频道模式节点迁回序号模式后，如果暂时缺乏显式边，也能被自动临时显示到主画布。
- 现有上下文聚焦设计保持不变，只是让它在节点实际可见后能够命中。
- 不影响手动孤立节点池揭示逻辑，不扩展到无关场景。
