# 移除频道前端归一化并保留多数类型聚焦

生成时间：2026-04-18 23:14:27
文件名：2026-04-18_231427_移除频道前端归一化并保留多数类型聚焦.md

## 任务背景

上一轮未提交改动同时包含两类修复：一类是批量应用草稿后，按当前选区里 `triggerSource/core` 哪类更多来决定重排后的自动聚焦；另一类是前端把 `channel > 0` 直接解释为频道成员，并据此影响搜索、频道详情绑定和序号/频道画布分桶。当前需求是手动移除第二类频道前端归一化逻辑，但保留第一类多数类型自动聚焦。

## 方案详情

### 现状分析

- `webapp/src/graphTypes.ts` 当前新增了 `connectionMode` 前端归一化与频道/序号辅助判定，导致 `channel > 0` 会直接影响视图归类。
- `webapp/src/components/GraphViewer.tsx` 当前搜索节点集和频道详情绑定也复用了这套归一化判定。
- `webapp/src/components/graphViewer/canvas.tsx` 当前序号/频道视图分桶同样复用了这套归一化判定。
- 多数类型自动聚焦相关状态、结构重排入口和重排后视口跟随，属于本轮要保留的修复。

### 技术方案

- 移除 `graphTypes.ts` 中的前端归一化逻辑，恢复 `connectionMode` 的原始解析口径。
- 将 `GraphViewer.tsx` 和 `canvas.tsx` 中与频道/序号分桶有关的判断恢复为显式 `connectionMode/channel` 条件。
- 保留 `batchEditFocusNodeKey`、`pendingPostLayoutFocusNodeKey`、`requestStructureLayoutRefresh({ focusNodeKey })` 等多数类型自动聚焦链路不动。

### 影响范围

- `webapp/src/graphTypes.ts`
- `webapp/src/components/GraphViewer.tsx`
- `webapp/src/components/graphViewer/canvas.tsx`
- `docs_dev/reviews/` 本轮审查文档
