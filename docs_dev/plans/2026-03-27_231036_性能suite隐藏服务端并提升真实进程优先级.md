# 性能suite隐藏服务端并提升真实进程优先级

生成时间：2026-03-27 23:10:36
文件名：2026-03-27_231036_性能suite隐藏服务端并提升真实进程优先级.md

## 任务背景
当前 bench 已支持在性能 suite 中自动拉起 dedicated server、外部客户端自动进服、自动聚焦与自动打开 `F3+2` tick 曲线。

实测发现，当 dedicated server 控制台窗口保持打开时，客户端观察到的 tick 曲线正常；一旦服务端窗口最小化，则会出现明显长红线，而重新展开窗口后红线又消失。这说明问题更接近同机运行时的 Windows 窗口/调度噪音，而不是 RedstoneLink 逻辑本身回退。

此外，现有 `mcserver/start.bat` 中通过 `wmic process where name="java.exe" CALL setpriority "high priority"` 试图提高优先级，但这条命令发生在新 server 进程启动前，通常不会稳定命中这一次 bench 启动出的真实 Java 进程。

## 方案详情

### 现状分析
- `tools/bench/lib/BenchSuite.Server.ps1` 当前只启动 `cmd.exe /c <start.bat>`，返回的是外层 wrapper 进程。
- 现有 suite summary 记录的 `serverPid` 也是 wrapper pid，而不是实际跑 dedicated server 的 Java 子进程。
- 性能/必跑包装脚本默认 `ServerWindowMode = "Minimized"`，这对同机观察仍可能触发窗口最小化相关噪音。

### 技术方案
- 在 `BenchSuite.Server.ps1` 内新增 dedicated server 子进程发现与优先级设置逻辑：
  - 先启动 wrapper `cmd.exe`
  - 短时间内探测其直接派生的 `java/javaw` 子进程
  - 若找到真实 Java 子进程，则对该真实进程设置优先级，并将其作为 suite 后续托管对象
  - 若未找到，则退回到 wrapper 进程本身，仍尝试设置优先级
- 新增可配置的 `ServerPriorityClass`，供 suite 脚本透传。
- 将性能 suite 与首批必跑包装脚本默认窗口模式从 `Minimized` 改为 `Hidden`，同时默认 `ServerPriorityClass = "High"`。
- 原始 `run-bench-suite.ps1` 继续保留 `ServerWindowMode = "Normal"` 默认，只新增可选优先级参数，避免影响通用用法。

### 影响范围
- `tools/bench/lib/BenchSuite.Server.ps1`
- `tools/bench/lib/BenchSuite.EntryPoint.ps1`
- `tools/bench/run-bench-suite.ps1`
- `tools/bench/run-performance-*.ps1`
- `tools/bench/run-first-mandatory-*.ps1`
- `tools/bench/run-performance-suite-common.ps1`
- `docs_dev/使用说明.md`

### 步骤 1：增强 dedicated server 启动托管
- **操作对象**：`tools/bench/lib/BenchSuite.Server.ps1`

- **预期结果**：suite 等待和记录的是更接近真实 dedicated server 的进程。

- **关键里程碑**：否

- **操作对象**：性能/必跑包装脚本与公共入口
- **具体动作**：默认 `ServerWindowMode = "Hidden"`、`ServerPriorityClass = "High"`。
- **预期结果**：同机观察时默认规避最小化窗口噪音。

## 预期结果
- 性能/必跑包装脚本默认不再显示最小化 server 控制台窗口，而是直接隐藏。
- dedicated server 启动后会对真实 Java 进程优先尝试设置高优先级，减少同机 bench 观察时的窗口调度噪音。
- 不改业务语义，不涉及 `triggerSource/core` 方向、存储或 API 依赖。
