# 发送接收过滤器

生成时间：2026-04-09 17:14:01
文件名：2026-04-09_171401_发送接收过滤器.md

## 任务背景

当前仓库已经具备 `triggerSource -> core` 的稳定派发链、节点生命周期桥接、客户端本地 Screen 与 payload 通信能力。  
本轮目标是在不引入 `com.makomi.api.v1.*`、不破坏 `triggerSource/core` 语义和方向约束的前提下，新增发送过滤器与接收过滤器两种方块：

1. 发送过滤器服务 `triggerSource`
2. 接收过滤器服务 `core`
3. 两者共享节点集过滤、信号过滤、邻居输入激活、范围外显、生命周期注册等公共能力
4. 作用域固定为以方块中心为中心、半径 `8`、边长 `17` 的立方域，并允许后续改为配置项

## 方案详情

### 现状分析

- 现有派发主链位于 `TriggerSourceBlockEntity -> LinkedTargetDispatchService -> ActivatableTargetBlockEntity`，过滤器适合接在派发阶段，而不是侵入 `LinkSavedData` 真值模型。
- 现有节点生命周期已由 `PairableNodeBlockEntity` 与 `LinkNodeLifecycleDispatchEvents` 收口，可复用其“上线/下线/加载后 attach”节奏维护过滤器运行时索引。
- 客户端已有本地 Screen、payload 编解码、结构化提交、描边与远外显渲染基线，可复用同类模式。
- 贴图已准备完成，本轮默认只接入已有贴图资源，不修改原始贴图文件。

### 技术方案

1. 新增过滤器抽象层：
   - `AbstractLinkFilterBlock`
   - `AbstractLinkFilterBlockEntity`
   - `LinkSendFilterBlock` / `LinkSendFilterBlockEntity`
   - `LinkReceiveFilterBlock` / `LinkReceiveFilterBlockEntity`
2. 过滤规则分三层：
   - 节点集模式：`白名单 / 过滤对象 / 关闭`
   - 信号阈值来源：`固定输入框 / 邻居最大输入`
   - 信号判定模式：`过滤上界 / 过滤下界 / 关闭`
3. 过滤器总生效前提：
   - 仅当过滤器方块自身接收到邻居非零输入时才参与计算
4. 信号有效阈值：
   - `固定输入框`：使用 GUI 配置的 `0~15`
   - `邻居最大输入`：直接使用过滤器方块自身当前采样到的邻居最大输入
5. 信号过滤比较口径：
   - 比较对象为本次无线派发强度，而不是被过滤节点自身的邻居输入
   - `SYNC_SIGNAL` 使用本次派发的真实强度
   - `ACTIVATION` 首版按 `15` 参与上下界比较，统一收口为“激活事件视作满强度派发”
6. 多过滤器合并规则：
   - 白名单取并集
   - 过滤对象取并集
   - 最终规则为“未命中过滤对象，且若存在白名单则必须命中白名单”
7. 运行时索引采用内存态注册表：
   - `dimension -> serviceType -> chunkKey -> filterRefs`
   - 配置真值写入方块实体 NBT
   - 区块级索引不写入 `SavedData`
8. 派发链接入策略：
   - 发送过滤器：对当前 `triggerSource` 做一次提前判定
   - 接收过滤器：对候选 `core` 集合做批量筛选，再进入 loaded/cross-chunk 派发
9. 客户端可视化：
   - 新增亮红色、可穿透方块透视的立方域线框外显
10. GUI 与网络：
   - 新增过滤器专用 payload 和 Screen，不复用命令字符串提交

### 影响范围

- 服务端方块/方块实体
- 运行时过滤索引与判定服务
- 现有派发主链
- 客户端 GUI、payload、反馈
- 客户端世界渲染
- 注册表、lang、models、blockstates、recipes
- 自动化测试与审查文档

## 原子步骤清单

### 步骤 1：新增过滤器基础类型
- **操作对象**：方块、方块实体、注册表
- **具体动作**：新增发送/接收过滤器方块与公共基类，补齐放置、破坏、掉落继承与右键开界面逻辑
- **预期结果**：两类过滤器可作为可放置节点类方块进入运行时
- **关键里程碑**：是

### 步骤 2：实现过滤配置与运行时索引
- **操作对象**：过滤器方块实体、运行时服务
- **具体动作**：实现 NBT 配置持久化、邻居输入激活态、覆盖区块集合、维度/区块级内存索引与版本号
- **预期结果**：过滤器在线集合与真实世界状态保持一致
- **关键里程碑**：是

### 步骤 3：实现过滤规则判定器
- **操作对象**：过滤规则与表达式解析模块
- **具体动作**：实现节点表达式、白名单/过滤对象、固定阈值/邻居最大输入、上界/下界过滤与并集合并逻辑
- **预期结果**：单过滤器与多过滤器组合行为稳定且可复用
- **关键里程碑**：是

### 步骤 4：把过滤接入派发主链
- **操作对象**：`TriggerSourceBlockEntity`、`LinkedTargetDispatchService`
- **具体动作**：在 source 入口执行发送过滤，在 target 集合分发前执行接收过滤
- **预期结果**：在不改变 `LinkSavedData` 真值模型的前提下完成过滤功能
- **关键里程碑**：是

### 步骤 5：新增 GUI 与网络协议
- **操作对象**：客户端 Screen、服务端 handler、payload
- **具体动作**：新增过滤器打开包、提交包、反馈包与对应界面；界面包含节点输入框、节点集模式、阈值来源、固定阈值、信号判定模式
- **预期结果**：玩家可直接配置过滤规则
- **关键里程碑**：是

### 步骤 6：新增范围外显
- **操作对象**：客户端渲染模块
- **具体动作**：实现亮红色、see-through 的边界线框渲染，并在远外显启用时显示作用域
- **预期结果**：远距离可视化过滤器实际作用域
- **关键里程碑**：否

### 步骤 7：补资源、测试与文档
- **操作对象**：lang、blockstates、models、recipes、测试、审查文档
- **具体动作**：接入已有贴图、补资源定义、增加布局/网络/规则测试，执行回归验证并生成审查文档
- **预期结果**：功能可加载、可配置、可回归验证
- **关键里程碑**：是

## 预期结果

- 新增发送过滤器与接收过滤器两种方块
- 在半径 `8`、边长 `17` 的立方域内对 `triggerSource/core` 进行区域过滤
- 支持节点集白名单/过滤对象
- 支持信号过滤的阈值来源切换：固定输入框或邻居最大输入
- 支持信号过滤的上界/下界模式
- 作用域可在远外显下以亮红色线框透视显示
- 整体实现继续遵守 `triggerSource/core` 语义与 `triggerSource -> core` 方向约束
