# 过滤器本地别名支持

生成时间：2026-04-15 16:37:30
文件名：2026-04-15_163730_过滤器本地别名支持.md

## 任务背景
过滤器需要补齐与节点一致风格的别名使用体验：可在 GUI 中编辑别名，并在近外显、远外显和物品 tooltip 中展示；但过滤器没有序号，不能直接复用当前基于 `(LinkNodeType, serial)` 的节点别名持久化模型。

## 方案详情

### 现状分析
- 节点别名当前由 `NodeAliasSavedData` 按 `(type, serial)` 维护，并同步到节点方块实体与单件物品缓存。
- 过滤器没有序号，当前只保存规则配置；GUI 打开包、保存包、方块实体 NBT、物品 NBT 都未承载过滤器别名。
- 过滤器已有近外显与范围盒远渲染，但没有文字型 far overlay；tooltip 也只展示规则配置。

### 技术方案
- 不把过滤器接入 `NodeAliasSavedData`，而是把别名作为过滤器自己的展示字段，独立保存在：
  - `AbstractLinkFilterBlockEntity`
  - `LinkFilterItemData`
  - `LinkFilterNetwork` 打开/保存 payload
- GUI 增加 alias 输入框；保存时与过滤规则一并提交，服务端统一做 normalize 与校验。
- 近外显在标题行优先展示“方块名 + 别名”；远外显新增过滤器文字渲染，优先显示别名，空别名回退过滤器标题；tooltip 新增别名行。
- 别名校验规则复用节点别名的字符/长度口径，但不引入“唯一性占用”和 alias->serial 解析逻辑。

## 语义对齐说明
- 内部术语仍保持 `triggerSource/core`；过滤器仅作为辅助设施，不引入旧术语输出。
- 过滤器别名不参与链路方向、OCC、过滤求值和持久化拓扑，只承担展示语义。
- 兼容层保持“规则配置照旧、别名为新增可选字段”，不会破坏旧存档的过滤规则读取。
- 残余风险：过滤器 far overlay 当前是把文字渲染合并进现有区域渲染器，若后续想拆分更复杂的样式，需要再抽公共 helper。
