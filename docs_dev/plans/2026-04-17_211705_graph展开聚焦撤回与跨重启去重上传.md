# graph展开聚焦撤回与跨重启去重上传

生成时间：2026-04-17 21:17:05
文件名：2026-04-17_211705_graph展开聚焦撤回与跨重启去重上传.md

## 任务背景

当前 graph 网页端已完成聚合块展开、侧栏页签和包围盒表意，但仍有三个待完善点：

1. 展开聚合块后只会触发全图重排，不会自动把视图聚焦到刚展开的操作块。
2. 网页端 graph 草稿仅支持持续编辑和保存，还缺少“最近一步本地草稿撤回”。
3. graph 导出目前只有进程内 `graphRevision` 复用，跨客户端/服务端重启后会重复上传同一结构图；同时导出内容夹带运行态信息，不适合直接做稳定去重依据。

本轮已确认的默认方向：

- 撤回先做“草稿级一级撤回”
- 跨重启去重优先做“规范化结构校验码”，不直接依赖版本号

## 方案详情

### 现状分析

- `webapp/src/components/GraphViewer.tsx` 当前通过 `pendingFocusNodeKey` 和全局 `fitView` 控制聚焦，但没有“展开后聚焦到 aggregate 局部块”的链路。
- `graphDraft.operations` 已经是当前本地修改的最小操作集合，适合实现单槽撤回。
- 服务端 `GraphSnapshotExportService` 当前只按 `graphRevision` 做内存缓存，跨重启失效；导出文件名又基于 tick 和 `snapshotId`，天然不稳定。
- graph 导出中的节点结构仍携带运行态字段（如 `online/active/inputPower/outputPower`），不利于“同结构图”跨重启稳定去重。
- 客户端收到 graph 导出后直接按文件名写入本地资产，若后续仅做“服务端复用已有文件名”而本地文件被清理，将出现复用命中但客户端缺文件的异常场景，因此需要补自愈逻辑。

### 技术方案

1. 前端展开聚焦：
   - 新增“待聚焦 aggregate 节点 key”状态。
   - 点击 aggregate 展开时，仅在“收起 -> 展开”边缘触发局部聚焦。
   - 等布局完成后，根据该 aggregate 及其展开 core 节点的边界执行局部 `fitView`，避免整图视口乱跳。

2. 草稿级一级撤回：
   - 新增一个“撤回前草稿快照”单槽。
   - 所有会修改 `graphDraft` 的本地操作（别名编辑、批量编辑）先保存旧草稿，再写新草稿。
   - 成功保存、切换图、重新加载 draft 后清空撤回槽。
   - UI 上新增“撤回一步草稿”按钮，仅作用于本地 draft，不回滚服务端真值。

3. graph 导出结构化去重：
   - 将 graph 导出收敛为稳定结构信息，去掉运行态波动字段及对应统计。
   - 引入“结构化规范文本 + 校验码”计算逻辑，输入只包含稳定语义：
     - 节点：`nodeKey/type/serial/alias/displayText/allocated/retired/connectionMode/channel/sourceRevision/coreRevision/capabilityFlags`
     - 边：`sourceNodeKey/targetNodeKey/kind/readable/editable`
   - 基于校验码生成稳定文件名后缀。

4. 跨重启持久化复用：
   - 在服务端新增 per-player graph 导出台账，持久化“最近一次成功导出的 checksum -> fileName”映射。
   - 再次导出同 checksum 时直接返回复用结果，不再分块传完整内容。
   - 网络请求增加“强制重传”开关；客户端命中复用但本地文件缺失时，自动重新请求一次强制重传。

- **关键里程碑**：是

- **操作对象**：`webapp/src/components/GraphViewer.tsx`

- **预期结果**：可以撤回最近一步本地草稿改动
- **关键里程碑**：是

- **预期结果**：graph export 成为稳定结构快照
- **关键里程碑**：否

## 预期结果

聚合块展开后视图会直接落到该块上；网页端可以本地撤回最近一步草稿；graph 导出改成稳定结构快照后，可通过结构校验码实现跨重启去重上传，并在客户端本地文件缺失时自动触发一次强制重传自愈。
