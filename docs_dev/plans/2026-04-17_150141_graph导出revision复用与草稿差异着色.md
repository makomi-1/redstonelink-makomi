# graph导出revision复用与草稿差异着色

生成时间：2026-04-17 15:01:41
文件名：2026-04-17_150141_graph导出revision复用与草稿差异着色.md

## 任务背景

当前网页 `graph` 页每次从游戏端打开时，服务端都会重新导出并上传完整 graph snapshot，即使 `graphRevision` 没有变化，也会重复构建、压缩并发送相同内容，造成不必要的数据传输。同时，网页端虽然已经支持本地草稿编辑，但图层里尚未把“基础图”和“草稿差异”明显区分开，用户很难直观看到哪些连线和节点处于草稿改动状态。

本轮只实现两项优化：

- graph 导出按 `graphRevision` 命中复用，revision 未变化时不重复上传
- 网页 graph 页增加草稿差异着色

不包含 graph 字段裁剪，该部分延后到频道模式扩展时再统一处理。

## 方案详情

### 现状分析

- `GraphSnapshotExportService` 当前每次都会重新构建 bundle、生成文件名并压缩字节。
- `StatePanelNetworkServerHandlerSupport.handleExportGraph` 总是调用 `sendGraphExport` 分块下发 graph 文件。
- 客户端 `applyGraphExportChunk` 在 `totalChunks <= 0` 时会直接返回，无法表达“直接打开本地已有 graph 文件”的语义。
- 网页 `GraphViewer` 当前只根据最终 `effectiveGraphBundle` 画图，没有单独标注 base/draft 差异。

### 技术方案

1. 服务端 graph 导出缓存：
   - 以“当前玩家 UUID + 当前 `graphRevision`”为 key 语义缓存最近一次导出的 graph 文件名与压缩字节
   - revision 未变化时，不重新导出 graph 内容，而是返回“复用已有本地 graph 文件”的轻量结果
2. 复用信号传输：
   - 继续复用现有 `StatePanelGraphExportChunkPayload`
   - 以 `totalChunks = 0` 表示“无需传输文件内容，客户端直接打开本地已有同名 graph 文件”
3. 客户端 graph 接包：
   - 新增 `zero-chunk graph export` 分支
   - 若本地已有对应 graph 文件，则直接打开；若文件不存在则静默失败并给出反馈
4. 前端草稿差异着色：
   - 节点：alias 改动节点、replace 操作涉及的来源节点与受影响目标节点使用草稿色强调
   - 边：草稿新增边用草稿色实线，草稿移除边用草稿色虚线保留对比

## 原子步骤清单

### 步骤 1：实现 revision 命中导出复用
- **操作对象**：`src/main/java/com/makomi/data/GraphSnapshotExportService.java`
- **具体动作**：为每个玩家缓存最近一次 graph 导出结果，`graphRevision` 未变化时返回复用结果
- **预期结果**：同 revision 下重复打开 graph 网页时不再重新导出压缩内容
- **关键里程碑**：是

### 步骤 2：实现客户端零分块 graph 复用打开
- **操作对象**：`src/main/java/com/makomi/network/StatePanelNetworkServerHandlerSupport.java`、`src/client/java/com/makomi/client/network/StatePanelNetworkClientHandlerSupport.java`
- **具体动作**：服务端发送 zero-chunk graph export 复用提示，客户端收到后直接打开已有本地 graph 资产
- **预期结果**：revision 未变化时打开网页仍可直达 graph 页，但不重复上传文件
- **关键里程碑**：是

### 步骤 3：实现草稿差异着色
- **操作对象**：`webapp/src/components/GraphViewer.tsx`
- **具体动作**：计算 base graph 与 effective graph 的边/节点差异，并为草稿差异使用独立颜色
- **预期结果**：用户能直观看到草稿新增、删除和受影响节点
- **关键里程碑**：是

### 步骤 4：验证与审查
- **操作对象**：Gradle / webapp 构建、`docs_dev/reviews/**`
- **具体动作**：执行构建与全标签回归，补写审查文档
- **预期结果**：形成完整验证证据与审查记录
- **关键里程碑**：是

## 预期结果

完成后，graph 网页入口在 `graphRevision` 未变化时会复用本地已有 graph 文件，减少重复上传；同时网页 graph 页会用单独颜色标出草稿差异，方便识别当前尚未保存的拓扑改动。
