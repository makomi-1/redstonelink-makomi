# 第二层物品堆叠菜单后处理归并方案

生成时间：2026-03-29 15:02:33
文件名：2026-03-29_150233_第二层物品堆叠菜单后处理归并方案.md

## 任务背景

第一层聚合栈已经支持物品级交互：左键并入、右键拆半、右键放一、tooltip 与数量角标。  
当前进入第二层，希望优先补齐更接近原版容器语义的“快捷整理”行为，但本轮明确要求尽量不使用 mixin。

本轮重点先解决：

- `shift` 快移后目标分区不会自动合并
- `shift` 批量合成产物进入库存后不会自动合并
- 普通容器/背包中的同类散栈希望自动折叠为聚合栈

## 方案详情

### 现状分析

- 现有入口集中在 `Item.overrideStackedOnOther(...)` 与 `Item.overrideOtherStackedOnMe(...)`，只能处理单次物品级点击。
- 原版的 `QUICK_MOVE`、`QUICK_CRAFT`、`PICKUP_ALL`、结果槽批量取出等流程位于 `AbstractContainerMenu.clicked/doClick/quickMoveStack`，已经超出物品级 hook 的覆盖范围。
- 因此，若坚持“第二层先尽量不用 mixin”，就不能精确改写双击归并、拖拽分发、结果槽连点批量合成这些菜单内部流程。
- 但可以在服务端每 tick 对玩家当前菜单做一次“后处理归并”，实现接近原版的自动折叠效果，尤其覆盖 `shift` 快移/`shift` 合成后的散栈场景。

### 技术方案

- 新增服务端 `PairableItemAggregateMenuNormalizationService`，注册到 `ServerTickEvents.END_SERVER_TICK`。
- 每 tick 遍历在线玩家当前 `containerMenu`，仅在 `carried` 为空时执行归并，避免与光标手持状态、拖拽中间态冲突。
- 归并只作用于带有效序号的聚合语义物品，和第一层点击 helper 保持同一判断口径。
- 槽位分区按以下规则隔离：
  - 先按 `Slot.container` 身份隔离，避免跨箱子/背包/输入槽容器误并
  - 再按 `Slot` 运行时具体类隔离，避免把副手/特殊槽位和普通存储槽混并
  - 仅处理 `slot.mayPlace(stack)` 为真的存储型槽位，跳过结果槽等只出不进的特殊槽位
- 在同一分区、同一物品类型内做一次稳定归并：
  - 汇总所有序号，统一做升序、去重
  - 以最早出现的非空槽位为目标槽位，按 `64` 上限依次回填
  - 多余槽位清空
  - 最终形成“左侧优先、顶部最小序号、最多 64 一个聚合栈”的稳定结果
- 归并后调用当前菜单 `broadcastChanges()`，把服务端结果同步回客户端。

- `src/main/java/com/makomi/RedstoneLink.java`
- `src/main/java/com/makomi/data/PairableItemAggregateMenuNormalizationService.java`

## 原子步骤清单

### 步骤 1：新增第二层菜单后处理服务
- **操作对象**：`PairableItemAggregateMenuNormalizationService`
- **具体动作**：注册 `END_SERVER_TICK`，遍历在线玩家菜单并筛选可归并槽位
- **预期结果**：建立无 mixin 的第二层统一入口
- **关键里程碑**：是

### 步骤 2：实现同分区自动聚合算法
- **操作对象**：服务类内部归并逻辑
- **具体动作**：按容器身份、槽位类、物品类型分组，统一收集序号并按 `64` 上限回填
- **预期结果**：`shift` 快移/`shift` 合成后的散栈可在下一 tick 自动折叠
- **关键里程碑**：是

### 步骤 3：接入主入口注册
- **操作对象**：`RedstoneLink`
- **具体动作**：在服务端初始化流程中注册第二层菜单后处理服务
- **预期结果**：第二层 A 版在运行期自动启用
- **关键里程碑**：否

### 步骤 4：补充回归测试
- **操作对象**：`PairableItemAggregateMenuNormalizationServiceTest`
- **具体动作**：覆盖同分区归并、64 上限、不跨容器、不跨槽位类、carried 非空跳过
- **预期结果**：第二层 A 版有自动化回归保护
- **关键里程碑**：否

## 预期结果

- 玩家执行 `shift` 快移后，同分区的同类可配对物品会自动聚合，不再长期留下多个单件散栈。
- `shift` 批量合成进入库存/容器的结果，也会在下一 tick 自动折叠成聚合栈。
- 整个第二层 A 版不依赖新的交互层 mixin，只做服务端菜单后处理。

## 暂不覆盖项

- 双击归并到光标
- 拖拽分发
- 结果槽“连点直接并入光标聚合栈”的原版即时手感

这些行为位于 `AbstractContainerMenu.doClick(...)` 内部的点击类型分支中；若后续要求完全贴原版语义，需再单独评估 mixin。

## 语义对齐说明

- 本方案不新增 `triggerSource/core` 之外的领域术语输出。
- 本方案不涉及方向写入，不改 `LinkNodeType` 与 `triggerSource/core` 的映射关系。
- 本方案不修改真实物品 `count`，只在服务端对聚合序号组做菜单后处理整理。
- 本轮仅补第二层“自动归并”，不变更配对 GUI、命令链路与存储语义。
- 残余风险：双击归并、拖拽分发、批量合成并入光标仍未覆盖；若后续要求完全贴原版，需要单独评估菜单层 mixin。
