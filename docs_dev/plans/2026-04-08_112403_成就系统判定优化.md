# 成就系统判定优化

生成时间：2026-04-08 11:24:03
文件名：2026-04-08_112403_成就系统判定优化.md

## 任务背景

当前成就系统统一通过 `RedstoneLinkAdvancementService` 发放，但创造模式与“已达成成就”的拦截点都偏后：

- 创造模式虽然最终不会发奖，但条件型成就仍会先做业务匹配，再在最终发奖阶段被拦下。
- 成就已经达成后，重复事件仍会再次进入匹配和发奖尝试，没有服务层统一短路。

本轮目标是在不改变成就语义的前提下，收紧无效判定路径。

## 方案详情

### 现状分析

- `awardIfEligible(...)` 目前只在最终发奖前检查 `isEligibleGameMode(player)`，没有显式的“已达成直接返回”。
- `awardComeFindMeInTheEndIfMatched(...)` 与 `awardConstellationIfThresholdReached(...)` 先做条件匹配，再调用最终发奖；因此创造模式与已达成成就仍会进入前置判定。
- 现有单测只覆盖“主世界到末地”与“首次跨 5 阈值”两个纯条件函数，没有覆盖前置短路语义。

### 技术方案

- 在 `RedstoneLinkAdvancementService` 内新增统一的“是否还需要处理该成就”前置 helper，统一封装：
  - 玩家与模式是否合法
  - 成就是否已存在
  - 玩家是否已经完成该成就
- 条件型成就入口在进入业务匹配前，先调用上述 helper：
  - 创造模式直接返回
  - 已达成直接返回
- 最终 `awardIfEligible(...)` 也复用该 helper，保证直接发奖型入口同样不会重复尝试。
- 在单测中补充纯判定 helper 覆盖，确保：
  - 创造模式不会继续处理成就
  - 已达成成就不会继续处理
  - 合法模式且未达成时仍允许进入后续流程
