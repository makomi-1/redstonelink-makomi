# 眼镜恢复原版护甲链并补tooltip与配方

生成时间：2026-04-26 16:27:31
文件名：2026-04-26_162731_眼镜恢复原版护甲链并补tooltip与配方.md

## 任务背景

用户确认智能眼镜当前不显示的根因在于后来新增的自定义 `ArmorRenderer` 抢走了原版护甲链路，希望恢复到 `de5cac7bd164d7eac1d4e5050e83615b82b54fcf` 那样的原版穿戴渲染。同时，用户要求补两条 tooltip、两个配方，并顺带给出“原版护甲渲染链是否支持 alpha”的本地调研结论。

## 方案详情

### 现状分析

- `SmartGlassesItem` 本身仍是标准 `ArmorItem + 自定义 ArmorMaterial.Layer` 方案，足以走原版护甲渲染链。
- 当前问题来自客户端额外注册的 `SmartGlassesArmorRenderer`，它替换了原版护甲层渲染路径。
- 转发器和智能节点容器 tooltip 分别由 `RepeaterBlockItem` 与 `SmartNodeContainerItem` 负责。
- 当前项目配方目录为 `src/main/resources/data/redstonelink/recipe/`，现有配方均使用 `minecraft:crafting_shaped`。
- 本地 1.21.1 映射显示原版 `HumanoidArmorLayer` 使用 `RenderType.armorCutoutNoCull(...)`，支持贴图透明像素 cutout，但不提供平滑 alpha 半透明 blending。

### 技术方案

1. 移除智能眼镜自定义护甲渲染注册，恢复原版护甲层渲染。
2. 删除已不再使用的 `SmartGlassesArmorRenderer`，避免保留失效实现。
3. 在转发器与智能节点容器物品 tooltip 中补充两条说明，并同步中英文文案。
4. 按项目当前 recipe 风格新增 `smart_glasses.json` 与 `smart_node_container.json`。

### 影响范围

- 客户端初始化：`RedstoneLinkClient`
- 客户端渲染：删除 `SmartGlassesArmorRenderer`
- 物品 tooltip：`RepeaterBlockItem`、`SmartNodeContainerItem`
- 本地化：`zh_cn.json`、`en_us.json`
- 配方：`src/main/resources/data/redstonelink/recipe/`
