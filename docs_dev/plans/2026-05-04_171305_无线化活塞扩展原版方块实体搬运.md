# 无线化活塞扩展原版方块实体搬运

生成时间：2026-05-04 17:13:05
文件名：2026-05-04_171305_无线化活塞扩展原版方块实体搬运.md

## 任务背景

当前工作区已具备“无线化活塞可搬运本 Mod 方块与节点”的基础能力，但原版带方块实体的高收益方块仍被原版活塞规则限制，无法进入无线化活塞搬运链。  
本次补文档对应的实际改动，目标是把首批边际效益最高的原版方块实体纳入支持范围：

- 漏斗
- 箱子 / 陷阱箱 / 木桶
- 熔炉 / 高炉 / 烟熏炉

本次只解决“可被无线化活塞推拉并保住自身状态”，不把这些原版方块无线化成节点。

## 方案详情

### 现状分析

- 原版 `PistonBaseBlock.isPushable(...)` 会直接拒绝大多数带 `BlockEntity` 的方块。
- 当前项目已经有一套 `WirelessPistonNodeMoveSupport`，可以为搬运中的方块实体记录 `NBT` 快照并在落地后恢复。
- 仅放开结构解析还不够，因为原版容器类方块在被替换成 `AIR` 或 `MOVING_PISTON` 时，可能在 `onRemove()` 中按“真实破坏”处理并吐出库存。

### 技术方案

本次实际采用三层最小扩展：

1. 结构解析放行  
   在 `WirelessPistonStructureResolver` 中显式把漏斗、箱子、陷阱箱、木桶、熔炉、高炉、烟熏炉视为“可由无线化活塞额外放宽”的原版方块实体方块。

2. 搬运前摘除源方块实体  
   在 `WirelessPistonBlock.moveBlocks(...)` 中，对上述原版方块在生成 `MOVING_PISTON` 前先执行 `removeBlockEntity(originalPos)`。  
   这样可避免原版容器在块状态被替换时误走“真实销毁/掉落库存”分支。

3. 落地后恢复与输出同步  
   `WirelessPistonNodeMoveSupport` 继续负责恢复完整 `NBT`，并在恢复后为这批原版方块补发一次比较器/邻居输出同步，确保库存类和熔炉类的红石读数及时刷新。

### 影响范围

- `src/main/java/com/makomi/block/WirelessPistonStructureResolver.java`
- `src/main/java/com/makomi/block/WirelessPistonNodeMoveSupport.java`
- `src/main/java/com/makomi/block/WirelessPistonBlock.java`

## 原子步骤清单

### 步骤 1：扩展结构解析白名单
- **操作对象**：`WirelessPistonStructureResolver`
- **具体动作**：新增原版方块实体识别方法，放行漏斗、箱子、陷阱箱、木桶、熔炉、高炉、烟熏炉
- **预期结果**：这批原版方块不再因 `hasBlockEntity` 规则被无线化活塞直接拒绝
- **关键里程碑**：是

### 步骤 2：在推动前摘除源 BlockEntity
- **操作对象**：`WirelessPistonBlock.moveBlocks(...)`
- **具体动作**：对首批支持的原版方块实体，在创建移动活塞方块前先移除源位置 `BlockEntity`
- **预期结果**：原版容器类方块在进入搬运流程时不再误触发掉物或清空库存
- **关键里程碑**：是

### 步骤 3：恢复后补发输出同步
- **操作对象**：`WirelessPistonNodeMoveSupport`
- **具体动作**：恢复 `NBT` 后，对首批支持的原版方块补发比较器与邻居更新
- **预期结果**：箱子、漏斗、熔炉系搬运后，红石读数和输出状态能及时收敛
- **关键里程碑**：是

### 步骤 4：回归验证
- **操作对象**：Gradle 构建与测试任务
- **具体动作**：执行 `compileJava`、`compileClientJava`、`test testIntegration testClient testSlow`
- **预期结果**：确认本次扩展没有破坏既有无线节点、无线化活塞和转化器逻辑
- **关键里程碑**：是

## 预期结果

- 无线化活塞可推动和拉回首批原版高收益方块实体。
- 搬运后保住库存、燃烧进度、配方进度和基本朝向语义。
- 比较器或邻居红石读取能在恢复后及时刷新。
- 现有 `triggerSource/core` 节点语义不受影响，因为本次改动只扩展“通用方块实体搬运层”，不新增节点类型或方向逻辑。
