# Graph 聚合锚点保留与结构切换重排

生成时间：2026-04-17 19:27:04
文件名：2026-04-17_192704_graph聚合锚点保留与结构切换重排.md

## 任务背景

当前 Graph 视图在核心聚合块交互上存在三个连锁问题：

- 聚合块展开后，蓝色聚合块本身会从画布消失，导致缺少可见的收起入口
- 展开或收起后，视口不会回到当前主拓扑区域，容易停在右侧空白区
- 聚合块展开后的核心节点排布会跑偏到左下，且可能与其他节点重合

本轮目标是在不改 `snapshot`、`draft`、服务端真值和真实保存方向的前提下，只修前端视图层的聚合交互与结构切换布局。

## 方案详情

### 现状分析

- 当前 `buildGraphCanvasView(...)` 在聚合块进入展开态后直接跳过 `collapsedAggregateNodes` 写入，导致聚合锚点从画布节点集合中消失。
- 当前节点刷新效果会优先复用旧坐标，这对普通状态变更有效，但对“展开/收起”这类结构性拓扑变化会保留错误位置。
- 当前只有初始装载和手动“重新布局”会主动执行 `fitView`，聚合切换本身不会触发视口归位。

### 技术方案

1. 保留聚合锚点：
   - 聚合块无论折叠态还是展开态，都继续作为可见锚点节点存在
   - 折叠态：隐藏真实 `triggerSource -> core` 边，保留 `triggerSource -> aggregate` 虚拟边
   - 展开态：恢复真实 `core` 与真实边，同时保留聚合锚点，并增加聚合锚点到其代表 `core` 的辅助边作为收起入口
2. 调整聚合与来源摘要的口径：
   - 展开中的聚合核心不再被后续单来源 `summary` 再次折叠
   - 保证聚合锚点不会被 `summary` 层误隐藏
3. 增加结构切换后的自动布局与视口聚焦：
   - 将聚合块和摘要节点的展开/收起视为“结构变更”
   - 结构变更后重新采用自动布局坐标，不继续复用旧位置
   - 布局完成后对当前锚点或主图执行一次自动聚焦，避免停在右侧空白区
