# 修复聚合块展开布局与收起状态

生成时间：2026-04-19 16:46:15
文件名：2026-04-19_164615_修复聚合块展开布局与收起状态.md

## 任务背景

当前图可视化编辑器存在两个前端表现问题：

1. 序号模式下，部分聚合块展开后仍沿用非整齐布局。
2. 有时在“应用到草稿 -> 清除选择 -> Save -> 重新布局”之后，新增部分仍然无法收起，除非重进页面。

本轮目标是在不改变现有上下文自动聚焦设计的前提下，最小粒度修复这两个问题。

## 方案详情

### 现状分析

- 序号模式的组件布局由 `webapp/src/components/graphViewer/canvas.tsx` 中的 `buildComponentLayout(...)` 控制。
- 当前仅在存在已展开聚合块时对 `core` lane 关闭 jitter，`triggerSource` lane 仍保留抖动，因此会出现“有些展开后整齐、有些仍然散开”的不一致。
- 聚合块是否视觉展开，当前会受到“成员节点是否被强制显示”影响；而 `selectedNodeKey` 又被纳入强制显示集合，所以保存与重排后，即使已清空批量选择，仍可能因为当前焦点保活导致聚合块持续展开。
- `expandedAggregateNodeKeys` 当前没有随画布聚合块集合变化做裁剪，结构变化后存在旧展开 key 残留风险。

### 技术方案

1. 调整序号模式下的 lane 布局策略，让展开聚合块时 `triggerSource/core` 两侧都走整齐布局。
2. 拆分“节点保活显示”和“聚合块自动展开”的来源集合，使 `selectedNodeKey` 继续参与上下文显示，但不再直接驱动聚合块视觉展开。
3. 在画布聚合块集合变化时，同步清理失效的 `expandedAggregateNodeKeys`，避免旧结构状态泄漏到新结构。

### 影响范围

- `webapp/src/components/graphViewer/canvas.tsx`
- `webapp/src/components/GraphViewer.tsx`
- `docs_dev/reviews/` 下新增审查文档

## 原子步骤清单

### 步骤 1：修正展开聚合块的整齐布局判定
- **操作对象**：`webapp/src/components/graphViewer/canvas.tsx`
- **具体动作**：统一序号模式下展开聚合块时的 lane 布局策略，关闭 `triggerSource/core` 两侧的 jitter。
- **预期结果**：所有展开聚合块都使用整齐布局。
- **关键里程碑**：是

### 步骤 2：拆分自动展开与节点保活显示
- **操作对象**：`webapp/src/components/GraphViewer.tsx`、`webapp/src/components/graphViewer/canvas.tsx`
- **具体动作**：新增仅用于聚合块自动展开的上下文可见集合，并使 `selectedNodeKey` 仅负责节点保活显示。
- **预期结果**：保存和重新布局后，新增部分不会因焦点残留而持续收不起。
- **关键里程碑**：是

### 步骤 3：回收失效展开态
- **操作对象**：`webapp/src/components/GraphViewer.tsx`
- **具体动作**：当当前画布聚合块集合发生变化时，裁剪掉已不存在的展开 key。
- **预期结果**：结构变化后不会保留无效展开态。
- **关键里程碑**：否

### 步骤 4：验证与审查记录
- **操作对象**：前端测试命令、`docs_dev/reviews/`
- **具体动作**：执行定向验证，并在完成后生成五段式审查文档。
- **预期结果**：形成可追溯的验证和审查结论。
- **关键里程碑**：是

## 预期结果

- 序号模式下，展开聚合块的成员排布稳定整齐。
- 应用草稿并保存后，若已清空批量选择，新增部分可正常重新收起，无需重进页面。
- 当前上下文自动聚焦设计保持不变。
