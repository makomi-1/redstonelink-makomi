# bench 启动期暂停菜单清理增强

生成时间：2026-03-27 22:08:34
文件名：2026-03-27_220834_bench启动期暂停菜单清理增强.md

## 任务背景

上一轮 bench 客户端自动化已经补了“启动期自动收起 `ESC/回到游戏` 菜单”的能力。  
但用户实测后仍然会在进入服务器后停留在 `ESC` 菜单，因此当前问题不太像“触发太早”，更可能是：

- 实际停留的 screen 不是 `PauseScreen` 单一类型
- 菜单是在进入世界后稍晚阶段才出现，超出了上一轮的清理窗口

本轮目标是增强启动期菜单清理策略，在不影响后续用户手动 `ESC` 的前提下，提高 bench 自动观察成功率，并补充日志证据。

## 方案详情

### 现状分析

- 当前逻辑只在 `client.player != null && client.level != null` 后执行，因此本质上已经是“进服后”时机
- 上一轮仅识别 `PauseScreen`
- 启动期清理窗口较短，可能无法覆盖自动 TP / 聚焦之后才出现的暂停菜单
- 当前没有记录“启动窗口内实际停住的 screen 类名”，后续复盘证据不足

### 技术方案

1. 放宽识别口径
   - 从仅识别 `PauseScreen`
   - 改为识别“任意 `isPauseScreen()==true` 且不是启动链路临时界面”的 screen

2. 拉长启动期清理窗口
   - 覆盖自动 TP、自动聚焦、tick chart 打开等后续动作
   - 仍保持有限时间，避免影响用户后续手动打开菜单

3. 记录启动窗口内实际 screen 类名
   - 仅在 screen 类型变化时写日志
   - 若后续仍有异常，可直接从日志看到真实界面类型与 pause 标志

4. 保留现有界面清理边界
   - 不把所有 screen 都强行清空
   - 只处理 pause-like screen 和 bench 启动链路临时界面

### 影响范围

- `src/client/java/com/makomi/client/bench/BenchClientAutomationController.java`
- `docs_dev/使用说明.md`
