# Graph 单来源核心聚合阈值下调

生成时间：2026-04-17 19:08:58
文件名：2026-04-17_190858_graph单来源核心聚合阈值下调.md

## 任务背景

上一轮已经引入“同输入核心聚合块”，当前规则要求同一聚合块至少有 2 个 `triggerSource` 和 2 个 `core`。用户希望进一步优化 1 对多场景，使单个 `triggerSource` 指向多个 `core` 时也能优先进入核心聚合块折叠逻辑，降低边和节点展开压力。

本轮仍然只改前端视图层，不改 `snapshot`、`draft`、服务端真值和真实保存方向。

## 方案详情

### 现状分析

- 当前 `GraphViewer` 使用 `SHARED_CORE_GROUP_MIN_SOURCE_COUNT = 2` 作为核心聚合块的来源数量门槛。
- 聚合逻辑发生在 `buildGraphCanvasView(...)` 前半段，优先于单来源高扇出 `summary` 折叠逻辑。
- 因此若把来源门槛降到 1，单来源多核心场景会自然转为优先使用聚合块，而不是继续走后续 `summary` 折叠。

### 技术方案

1. 将核心聚合块的来源门槛从 `2` 下调到 `1`。
2. 保持核心数量门槛 `SHARED_CORE_GROUP_MIN_CORE_COUNT = 2` 不变，避免单个 `core` 被不必要地虚拟化。
3. 保持现有交互边界不变：
   - 单来源聚合块仍通过点击聚合块本身展开或收起
   - 不额外新增 “点击 `triggerSource` 同时展开单来源聚合块” 的联动逻辑
