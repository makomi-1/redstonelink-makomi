# bench多来源资格筛选能力补齐

生成时间：2026-03-31 19:30:13
文件名：2026-03-31_193013_bench多来源资格筛选能力补齐.md

## 任务背景

上一轮已补齐生命周期重构后的单来源 functional 回归，但“目标上线时只筛入仍合格来源”的多来源场景仍缺少稳定覆盖。现状并不是 bench 无法摆出多来源，而是 functional 断言层缺少直接表达“多个来源集合”的能力，导致 `maxSources` 这类集合输出只能依赖脆弱正则手工拼接，最终只能收敛到单来源稳定用例。

本轮目标是在不修改运行时业务语义的前提下，补齐 bench 基础能力，并同时落地 1 组可跑通的多来源资格筛选 functional 用例。

## 方案详情

### 现状分析

- `tools/bench/lib/Bench.PlaceAndLink.ps1` 已支持多来源组放置与多条 link 规则编排，多来源布局不是主要阻塞点。
- `tools/bench/lib/Bench.FunctionalTrace.ps1` 当前主要按单个 `serialRef` / `source:<group>` 解析 serial 集合，缺少多引用合并入口。
- `redstonelink node get core ...` 的 `maxSources` 输出使用命令层稳定升序 CSV，而 bench 模板当前更偏向命令输入格式（如 slash/range/mixed），两者口径不一致。
- 因此 bench 需要补的是“集合引用 + 输出口径渲染”能力，而不是扩大编排系统或改运行时逻辑。

### 技术方案

采用最小能力补齐路线：

1. 在 functional serial 解析层增加“多 ref 合并”能力，使 phase / command template 可以直接引用多个来源集合。
2. 在 functional template 渲染层增加与 `node get` 输出一致的稳定 CSV 样式，专门用于 `maxSources` 等集合断言。
3. 基于新能力新增 1 条多来源资格筛选 functional 用例，验证“两个来源保留、一个来源失效、目标 reload 后仅重算保留来源”。
4. 将新 case 接入 functional matrix 与 regression suite，并补一段使用说明，保证后续可复用。

### 影响范围

- `tools/bench/functional-matrix.json`
- `tools/bench/suites/regression-lifecycle.json`
- `tools/bench/suites/regression-full.json`
