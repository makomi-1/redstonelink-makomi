# 配方生成

生成时间：2026-04-04 00:37:38

## 任务背景
`docs_dev/更新计划草稿与索引.md` 中“配方生成”条目标记出一个高优先级结构缺口：当前 18 个配方 JSON 全部放在 `data/redstonelink/recipe`（单数）路径下，而原版标准运行时路径应为 `data/<modid>/recipes`（复数）。同时，项目虽已声明 `fabric-datagen` 入口，但 `RedstoneLinkDataGenerator` 仍为空实现，仓库内没有 recipe provider 与对应自动化兜底。

用户要求“一步到位完成”，因此本次不仅要修复当前运行时目录风险，还要把 datagen 与测试补齐，避免后续再退回到手工散落维护。

## 方案详情

### 现状分析
1. 当前共有 18 个手写配方文件，全部位于 `src/main/resources/data/redstonelink/recipe/`。
2. 这些配方内容本身采用 1.21 风格 JSON（例如 `result.id`），主要风险不是格式，而是目录路径不符合标准。
3. `src/client/java/com/makomi/RedstoneLinkDataGenerator.java` 已作为 `fabric-datagen` 入口注册，但当前没有挂接任何 provider。
4. 仓库里没有 recipe 路径/存在性自动化测试，无法防止 `recipe` 单数目录再次出现。

### 技术方案
1. 将现有 18 个运行时配方资源从 `data/redstonelink/recipe` 迁移到标准 `data/redstonelink/recipes`。
2. 新增统一 recipe provider，用 `RecipeProvider` + `ShapedRecipeBuilder` / `ShapelessRecipeBuilder` 收口这 18 个配方的生成逻辑。
3. 在 `RedstoneLinkDataGenerator` 中注册该 provider，使 datagen 入口不再为空。
4. 增加资源布局测试：校验标准 `recipes` 目录完整存在、文件数量与名称符合预期，且旧 `recipe` 目录不再作为运行时目录保留。
5. 执行 `.\gradlew.bat test testIntegration testClient testSlow --no-daemon` 做回归验证。

### 影响范围
- 运行时配方资源：`src/main/resources/data/redstonelink/recipes/**`
- 旧目录迁移：`src/main/resources/data/redstonelink/recipe/**`
- datagen 入口与 provider：`src/client/java/com/makomi/**`
- 自动化测试：`src/test/java/com/makomi/**`
