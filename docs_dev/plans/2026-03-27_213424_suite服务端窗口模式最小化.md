# suite 服务端窗口模式最小化

生成时间：2026-03-27 21:34:24
文件名：2026-03-27_213424_suite服务端窗口模式最小化.md

## 任务背景

当前 bench suite 在启动 dedicated server 时，直接通过 `cmd.exe /c start.bat` 拉起服务端。  
这会导致服务端控制台窗口在每轮 case 启动时弹出并抢前台，遮挡外部客户端观察画面，影响 bench 自动观察与 F3+2 tick 曲线观测。

用户本轮要求的目标不是完全隐藏服务端，而是保留窗口存在感，但默认以“最小化”方式启动，减少对客户端前台焦点的干扰。

## 方案详情

### 现状分析

- `tools/bench/lib/BenchSuite.Server.ps1` 里的 `Start-DedicatedServerProcess` 当前没有窗口模式参数，固定按默认窗口样式启动
- `tools/bench/run-bench-suite.ps1` 与性能/必跑 suite 包装脚本也没有“窗口模式”透传能力
- 现有 dedicated server 生命周期、RCON ready/stop、PID 托管逻辑已经稳定，不应通过改 `start.bat` 破坏这层能力

### 技术方案

1. 在 suite 启动链路新增 `ServerWindowMode`
   - 可选值：`Normal` / `Minimized` / `Hidden`
   - 底层统一在 `Start-Process` 的 `-WindowStyle` 上生效

2. 保持底层 `run-bench-suite.ps1` 默认 `Normal`
   - 这样原始脚本行为兼容，调试时仍可直接看服务端窗口

3. 让常用包装脚本默认 `Minimized`
   - `run-performance-*.ps1`
   - `run-first-mandatory-*.ps1`
   - 满足 bench 观察场景的默认诉求

4. 在 suite summary 中写出 `serverWindowMode`
   - 方便后续分析结果时确认本轮窗口策略
