# bench 客户端聚焦改善

生成时间：2026-03-27 20:57:32
文件名：2026-03-27_205732_bench客户端聚焦改善.md

## 任务背景

当前 bench 外部客户端虽然已经支持自动启动、自动进服、自动 TP 和自动打开 `F3+2` tick 曲线，但宿主脚本只在“客户端刚启动后”做了一次窗口聚焦。  
这会导致以下实际问题：

- 启动阶段聚焦成功，不代表玩家真正进服后仍在前台
- 自动 TP 到观察点后，不代表客户端仍处于可直接观察状态
- suite/单 case 结果里只能看到一次 `focusResult`，无法判断后续阶段是否重新聚焦

本次要做的是把聚焦从“一次性动作”改成“多阶段动作”，并把结果写进 bench 输出，便于后续分析。

## 方案详情

### 现状分析

- `tools/bench/lib/Bench.Client.ps1` 当前仅有 `Focus-BenchClientWindow`，内部只尝试 `ShowWindowAsync + SetForegroundWindow`
- `Start-BenchClientAutomationSession` 只在客户端启动后调用一次聚焦
- `tools/bench/lib/Bench.EntryPoint.ps1` 的单 case/功能 case 在玩家 ready、观察 TP、正式 drive 前都没有再次聚焦
- `tools/bench/lib/BenchSuite.EntryPoint.ps1` 只把启动时的 `focusResult` 摘到 suite summary，没有完整事件链

### 技术方案

1. 在 `Bench.Client.ps1` 中增强聚焦能力：
   - 保留现有 `SetForegroundWindow`
   - 增加 `WScript.Shell.AppActivate` 作为回退手段
   - 统一返回结构化聚焦事件，包含 `stage/method/reason`

2. 在 bench client session 中新增聚焦事件集合：
   - `focusEvents`：记录所有阶段的聚焦尝试
   - `focusResult`：始终指向最近一次聚焦结果，兼容现有读取口径

3. 在 bench 主流程插入关键阶段重聚焦：
   - `launch_start`
   - `player_ready`
   - `observation_teleport`
   - `before_drive`（性能 case）

4. 在单 case 结果与 suite summary 中统一输出 bench client 聚焦摘要，便于核对实际是否完成了后续重聚焦。

### 影响范围

- `tools/bench/lib/Bench.Client.ps1`
- `tools/bench/lib/Bench.EntryPoint.ps1`
- `tools/bench/lib/BenchSuite.EntryPoint.ps1`
