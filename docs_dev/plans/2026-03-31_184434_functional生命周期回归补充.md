# functional 生命周期回归补充

## 任务背景

生命周期调度管线已完成重构，现有游戏内完整回归虽然通过，但 `tools/bench/cases/functional` 仍缺少几类与新分支直接对应的场景：

1. `triggerSource` context-detach 后的 attach replay 开关分支。
2. `target` reload 时对离线来源的 replay 资格过滤。
3. 真实物理移除与普通 context-detach 的外部行为差异。

本轮目标不是修改运行时代码，而是在 bench functional 层补齐最关键、可直接观测的新生命周期回归场景，并把它们接入主回归套件。

## 方案详情

### 现状分析

- 现有 [`f02`](D:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/f02/link_lifecycle_add_remove_set_clear.json) 主要覆盖链路命令生命周期，不直接断言 attach/detach 发布后的运行态结果。
- 现有 [`x07`](D:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x07/crosschunk_sync_reload_replay_enabled.json) / [`x08`](D:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x08/crosschunk_sync_reload_replay_disabled.json) 只覆盖“目标离线、来源状态变化、目标重载”的单来源 replay 分支。
- 生命周期重构后，`LinkNodeLifecycleDispatchEvents` 里新增或收敛的关键行为还没有被 functional case 直接覆盖：
  - 来源 attach replay 开关。
  - target attach replay 的来源资格过滤。
  - 物理移除路径对 replay 资格的影响。

### 技术方案

1. 复用现有 `command_assert + wait_ticks + forceload add/remove` 场景模板，新增 4 个 `X` 层 functional case。
2. 其中两项覆盖 `syncSourceAttachReplay.enabled` 的 enabled/disabled 对照：
   - 来源区块卸载触发 context-detach invalidation 后，重新加载来源区块。
   - 开启时目标应按当前高态恢复；关闭时应保持低态，直到来源再次出现真实输入变化。
3. 另两项覆盖 target reload 场景下对来源集合的过滤：
   - `context-detach` 来源被移出有效来源集合后，target reload 不应把它重新补回。
   - 真实物理移除的来源在 target reload 后同样不应被重新补回。
4. 每个多来源场景都直接断言 `node get core` 的 `active` 与 `maxSources`，避免只看“亮/灭”而忽略“重算对象集合”。
5. 更新 `functional-matrix`、`regression-lifecycle` 与 `regression-full`，让新增场景进入主回归入口。
