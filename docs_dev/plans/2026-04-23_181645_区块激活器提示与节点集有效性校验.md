# 区块激活器提示与节点集有效性校验

生成时间：2026-04-23 18:16:45
文件名：2026-04-23_181645_区块激活器提示与节点集有效性校验.md

## 任务背景

本轮需要补齐三类编辑体验与配置安全性问题：
- 区块激活器物品 tooltip 目前只显示模式名，没有直接解释 `force_load/resident` 的实际含义。
- 状态面板“状态”列表头目前没有 tooltip，用户无法直接理解 `on/off act/idle ret/live iN oN` 的字段意义。
- 过滤器与区块激活器保存节点集配置时，目前缺少“已分配且未退役”校验，可能允许无效 serial 混入配置。

本次改动不扩展到方案文档之外的界面说明，也不改动 API 依赖边界。

## 方案详情

### 现状分析

- `ChunkActivatorBlockItem.appendHoverText(...)` 已负责组装区块激活器物品 tooltip，可在现有模式行后追加模式说明。
- `StatePanelToolScreen` 已有表头绘制逻辑，但没有表头 hover tooltip 检测与渲染逻辑。
- `LinkFilterNetworkServerHandlerSupport.handleSaveFilter(...)` 与 `ChunkActivatorNetworkServerHandlerSupport.validateConfigState(...)` 仅做输入语法与数量校验，未校验 serial 是否已分配且未退役。
- 现有错误消息 `message.redstonelink.invalid_target_unallocated` / `message.redstonelink.invalid_target_retired` 已被项目其他链路使用，可直接复用。

### 技术方案

1. 在区块激活器 tooltip 中，按 `ChunkActivatorMode` 为 `force_load/resident` 追加模式说明文案。
2. 在状态面板界面中，为“状态”表头增加 hover 检测，并渲染多行 tooltip，解释各状态缩写。
3. 抽出网络侧 serial 活跃性校验支撑逻辑，供过滤器与区块激活器保存链路复用。
4. 在过滤器保存时，按 `filterKind.servicedNodeType()` 对 serial 目标执行“已分配且未退役”校验。
5. 在区块激活器保存时，分别对 `triggerSource/core` 两套节点集执行同口径校验。
6. 补充对应单元测试，最后跑全标签回归。

### 影响范围

- 客户端 tooltip 与界面渲染：
  - `src/main/java/com/makomi/item/ChunkActivatorBlockItem.java`

### 语义对齐说明

- 命名继续只使用 `triggerSource/core`，不新增旧术语输出。
- 输入/输出方向保持一致：过滤器按自身服务节点类型校验，区块激活器分别校验 `triggerSource/core` 节点集。
- 与 `LinkNodeType.TRIGGER_SOURCE/CORE` 的映射保持一一对应。
- 兼容层维持“读旧写新”，本次不新增 `com.makomi.api.v1.*` 依赖。
- 残余风险：无。
