# agents与skill补实现后审查文档规则

生成时间：2026-04-01 19:29:03
文件名：2026-04-01_192903_agents与skill补实现后审查文档规则.md

## 任务背景
当前项目内 `AGENTS.md` 与 `skills/docs-dev-docflow/SKILL.md` 已收口为“结果汇报默认直接输出关键实现信息，不强制附代码引用”，但还没有把“实现完成后自动生成结构化审查文档”纳入正式规则。用户本轮要求补齐该流程：每次实现完成后自动写入 `docs_dev/reviews` 审查文档，文档必须带具体代码引用行号，而对用户的结果汇报只保留简要总结。

## 方案详情

### 现状分析
- `AGENTS.md` 当前对“任务汇报/结果交付”的规则仍是默认直接口头汇报，不要求写 review 文档。
- `skills/docs-dev-docflow/SKILL.md` 的事件映射里也没有 `docs_dev/reviews`，审查仍停留在“提醒用户手动写 xlsx”。
- 项目当前缺少统一的实现后审查文档格式与落点。

### 技术方案
- 在 `AGENTS.md` 中新增“实现完成后自动生成 review 文档”的规则，目录固定为 `docs_dev/reviews`，命名规则与方案文档一致。
- 在 review 文档中固定要求四部分内容：
  1. 功能与语义、架构设计（关键方法和入口）
  2. 关键数据结构和算法性能分析
  3. 数据流或调用链
  4. 安全、性能、兼容性、扩展性风险分析与建议
- review 文档必须附具体代码引用行号。
- 结果汇报规则改为只做简要总结，不默认附代码或文件引用。
- 在 `skills/docs-dev-docflow/SKILL.md` 中同步事件映射、输出要求和 review 文档格式要求。

### 影响范围
- `AGENTS.md`
- `skills/docs-dev-docflow/SKILL.md`
- `docs_dev/reviews/` 文档流程

## 原子步骤清单

- **操作对象**：`AGENTS.md`
- **具体动作**：加入实现后 review 文档的自动工作流、命名规则、内容结构和结果汇报精简要求
- **预期结果**：主规则明确“先写 review，再简要汇报”
- **关键里程碑**：是

### 步骤 2：同步修改 docs-dev-docflow skill
- **操作对象**：`skills/docs-dev-docflow/SKILL.md`
- **具体动作**：把 `docs_dev/reviews` 纳入事件映射与输出要求
- **预期结果**：skill 与主规则保持一致
- **关键里程碑**：是

### 步骤 3：按新规则复读与校验
- **操作对象**：上述规则文件
- **具体动作**：重新读取关键段落，确认规则已切换成功
- **预期结果**：后续实现完成后的行为可直接按新规则执行
