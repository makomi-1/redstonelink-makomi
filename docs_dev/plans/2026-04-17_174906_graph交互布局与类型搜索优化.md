# Graph 交互布局与类型搜索优化

生成时间：2026-04-17 17:49:06
文件名：2026-04-17_174906_graph交互布局与类型搜索优化.md

## 任务背景

上一轮已经为网页 Graph 视图补上了孤立节点池化、高扇出摘要节点和聚合裁剪修复，但继续实测后又暴露出三个交互问题：

- 清空临时显示后仍有节点残留在主画布中
- 整体布局横向空间利用率不高，展开后仍然偏竖向堆叠
- 搜索没有类型筛选，重复序号场景下容易混淆 `triggerSource` 与 `core`

本轮目标是在不改 snapshot、draft、服务端真值和真实保存方向的前提下，继续优化前端视图层交互体验。

## 方案详情

### 现状分析

- `clear pinned` 现在只清空 `pinnedIsolatedNodeKeys`，但 `selectedNodeKey` 仍会进入 `forcedVisibleNodeKeys`，因此临时拉回的孤立节点可能因为“当前选中”继续留在主画布。
- 现有布局是“整个连通分量做全局双列，再按最大宽度换行”，高节点数组件会被拉成长条，展开后的目标节点也不会围绕各自来源节点局部展开。
- 搜索逻辑目前只有自由文本，没有 `triggerSource/core` 类型筛选；虽然内部 `nodeKey` 可区分类型，但 UI 没提供显式控制。

### 技术方案

1. 为 `清空临时显示` 增加“残留选中态回收”逻辑：仅当当前选中节点属于临时显示集合且清空后不再具备其他强制显示理由时，才同步清空该选中态。
2. 重构自动布局模型：从“按连通分量全局双列”改为“按 `triggerSource` 局部块横向铺排”，让每个来源节点与其当前可见目标/摘要节点形成独立布局单元，并为没有来源挂靠的节点保留 fallback 块。
3. 新增 `all / triggerSource / core` 搜索类型筛选：先按类型过滤，再执行现有文本匹配；搜索结果文案增加类型信息以解决重复序号歧义。
4. 同步调整前端样式，使新增筛选控件和新布局在桌面端、移动端都保持可读性与现有视觉风格一致。

## 预期结果

- `清空临时显示` 不再被选中态顶住而残留孤立节点。
