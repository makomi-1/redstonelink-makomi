# x21单次burst序列收紧

生成时间：2026-04-02 09:25:00
文件名：2026-04-02_092500_x21单次burst序列收紧.md

## 任务背景
`x21` 当前单次 burst 用 `15/15/15/0/0/0/0/0` 作为 8 tick 自定义序列。该序列适合验证整段波形是否整体右移，但对“同一 `core` 共享窗口导致窗口内部条目提前 flush”的检出能力偏弱。需要将其替换为逐 tick 更易区分的递减序列，以更严格地验证固定延迟语义。

## 方案详情

### 现状分析
- `x21` 的 `trace_sync_latency_collect_*` phase 已经会把模板展开成 8 tick 逐 tick期望序列，再交给服务端 `sync_latency` 做严格窗口匹配。
- 问题不在采集逻辑，而在当前 burst 序列平台过长，容易让“整段整体右移正确但窗口内部条目偷跑”的情况被掩盖。

### 技术方案
- 仅修改 `tools/bench/cases/functional/x21/sync_samechunk_latency_1024_to_1024_banded16_single_burst.json` 中 `start_sync_latency_single_burst.sequence`。
- 将 8 tick 序列改为 `15/14/13/12/11/10/9/0`。
- 保持 `tickCount=8`、source/core 延迟断言与窗口覆盖断言不变。

### 影响范围
- 直接影响：`x21` 单次 burst 功能用例。
- 间接影响：使用该 case 的同区块延迟专项套件结果会变得更严格。
- 不影响：服务端调度实现、trace 采集脚本、`triggerSource/core` 方向语义。
