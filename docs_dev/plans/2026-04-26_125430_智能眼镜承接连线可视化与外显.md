# 智能眼镜承接连线可视化与外显

生成时间：2026-04-26 12:54:30
文件名：2026-04-26_125430_智能眼镜承接连线可视化与外显.md

## 任务背景
当前 quick-link 连线可视化、第三形态 hover HUD 与部分客户端交互入口都依赖主手持有 `quick_link_tool`。用户要求将这部分“生效门槛”改为智能眼镜承接：连线可视化相关功能需满足“头部穿戴智能眼镜且主手为空”，远近外显只需“头部穿戴智能眼镜”。原有 `K`、`Shift+B`、左键添加显示对象、右键移除显示对象等交互语义保持不变。

## 方案详情

### 现状分析
- 客户端按键、方块描边、第三形态连线渲染、hover HUD 均散落着“主手必须是 `QuickLinkToolItem`”判定。
- 服务端 quick-link 可视化相关接包同样写死主手 QLT 验权。
- 远外显与近外显当前只看客户端显示配置，不看任何装备状态。
- 代码库中暂未发现现成的智能眼镜/头戴装备物品实现。

### 技术方案
- 新增一个最小可头戴的智能眼镜物品，注册模型、贴图与中英文本地化。
- 抽出共享判定工具，统一封装“是否穿戴智能眼镜”“是否主手为空”“是否允许连线可视化”“是否允许外显显示”。
- 客户端：
  - 保留原有按键和可视化语义；
  - 将连线可视化与 hover HUD 的生效条件从“主手 QLT”改为“戴眼镜 + 主手空”；
  - 将远/近外显的生效条件改为“戴眼镜”。
- 服务端：
  - quick-link visualize 相关请求改为依赖新判定；
  - 非 visualize 的 serial/channel/apply 主链路保持原状，避免扩散修改。

### 影响范围
- 物品注册与新物品类
- 客户端按键处理、quick-link 交互回调、可视化渲染、HUD 外显渲染
- 服务端 quick-link visualize 相关接包验权
- 资源：物品模型、语言，以及对原版头盔贴图的直接复用

## 原子步骤清单

### 步骤 1：新增智能眼镜物品
- **操作对象**：`ModItems`、新物品类、资源目录
- **具体动作**：补齐头戴智能眼镜的最小注册与资源链路
- **预期结果**：项目内存在可装备到头部的智能眼镜物品
- **关键里程碑**：是

### 步骤 2：收口统一判定
- **操作对象**：共享工具类
- **具体动作**：抽取智能眼镜穿戴、主手是否为空、连线可视化是否允许、外显是否允许等判定
- **预期结果**：客户端与服务端都能复用同一套条件
- **关键里程碑**：是

### 步骤 3：替换客户端入口
- **操作对象**：`RedstoneLinkClient`、`QuickLinkNetworkClientHandlerSupport`、`QuickLinkOutlineRenderer`、`LinkSerialHudOverlayRenderer`、far overlay 渲染器
- **具体动作**：把主手 QLT 依赖替换为智能眼镜条件，同时保持原按键语义
- **预期结果**：戴眼镜时外显生效，戴眼镜且主手空时可视化交互生效
- **关键里程碑**：是

### 步骤 4：替换服务端 visualize 验权
- **操作对象**：`QuickLinkNetworkServerHandlerSupport`
- **具体动作**：只调整 visualize 相关包处理的验权条件
- **预期结果**：客户端和服务端入口条件一致
- **关键里程碑**：是

### 步骤 5：验证与审查
- **操作对象**：测试命令与 `docs_dev/reviews/`
- **具体动作**：执行回归测试，补五段式审查文档
- **预期结果**：形成可追溯的实现与验证记录
- **关键里程碑**：是

## 预期结果
智能眼镜成为连线可视化与远近外显的统一承载入口：外显仅在戴眼镜时显示；连线可视化仅在戴眼镜且主手为空时允许交互；原有 quick-link 非 visualize 主链路保持不变。
