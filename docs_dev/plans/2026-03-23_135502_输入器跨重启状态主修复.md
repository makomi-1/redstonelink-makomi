# 输入器跨重启状态主修复

生成时间：2026-03-23 13:55:02
文件名：2026-03-23_135502_输入器跨重启状态主修复.md

## 任务背景

输入器当前是内存态 job，但运行过程中会把部分“运行时模拟状态”间接写进可持久化数据，导致跨重启后出现残留状态。

已确认本轮不做旧存档兼容清理，只做主修复，目标是阻断新污染并让 `triggerSource` 在区块加载时按当前真实输入无副作用重采样。

## 方案详情

### 现状分析

- `core sync direct` 的运行时模拟输入会进入 `runtimeSimulatedSyncConcurrentBuckets`，但落盘时又通过合并后的 SYNC 真值写回 `SyncSourceStrengths` / `SyncMaxSources`。
- `sync emitter` 的输入器驱动会走正常触发链，并把 replay 快照写进持久化 `SyncReplaySourceBlockEntity`。
- 普通 `triggerSource emitter` 的 `simulatedInputPower` 不持久化，但 `POWERED` 方块状态会被世界保存，区块重载后需要按当前真实输入重采样校正。

### 技术方案

1. `core`：
   - 新增“持久化专用 SYNC 视图”，仅从 `syncConcurrentBuckets` 计算。
   - `saveAdditional()` 写 `SyncSourceStrengths` / `SyncMaxSources` 时只使用该视图。

2. `sync emitter`：
   - 在 `SyncReplaySourceBlockEntity` 中新增运行时 replay 快照覆盖层，仅存于内存。
   - `replaySyncSnapshot()` 优先返回运行时覆盖层，NBT 读写仅处理持久化快照。
   - 输入器驱动 `sync emitter` 时只写运行时快照；模拟输入结束后再按当前真实输入静默回写持久化快照。

3. `triggerSource emitter`：
   - 在 `LinkSignalEmitterBlock` 中新增“无触发重采样”入口。
   - 新增 `TriggerSourceInputStateResyncService`，在 `CHUNK_LOAD` 时对已加载 `triggerSource emitter` 做静默重采样。
