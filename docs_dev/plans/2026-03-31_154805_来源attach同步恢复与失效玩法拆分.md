# 来源 attach 同步恢复与失效玩法拆分

生成时间：2026-03-31 15:48:05
文件名：2026-03-31_154805_来源attach同步恢复与失效玩法拆分.md

## 任务背景

节点生命周期调度主干已经从“全局区块活动扫描”迁移到“节点实例自发布 attach/detach + 预算化队列消费”。

当前剩余缺口主要有三点：

1. 来源节点重新 attach 后，还没有正式的恢复链。
2. replay 语义虽然底层更偏向 `sync`，但还没有单独作为一条明确玩法能力收口。
3. 失效玩法仍沿用“区块卸载失效 / 其它失效”的旧命名，尚未正式拆成 `hard invalidation` 与 `soft/context-detach invalidation` 两套配置语义。

本轮目标是在不改动生命周期调度主干的前提下，以最小范围补齐上述三点，并保持默认玩法偏向稳定、低干扰：

1. 默认仍推荐“方块放置着就是有效”，不因区块活动自动失效。
2. `source attach replay` 默认关闭。
3. `soft/context-detach invalidation` 默认关闭，保留为实验性玩法。
4. `hard invalidation` 默认开启，保持真实离线/解绑/删除等链路的已有稳定语义。

## 方案详情

### 现状分析

1. `LinkNodeLifecycleDispatchEvents` 已负责 attach/detach 预算化消费，但当前 `source attach` 只做在线登记与加载后自愈，不做恢复回放。
2. 当前 `target attach replay` 已存在，且只作用于“当前 attach 的目标自身”，不会全量回放所有目标。
3. 当前底层 replay helper 本身天然偏 `sync-only`：
   - `publishLinkAttached(...)` 最终产出的是 `SYNC_SIGNAL + UPSERT`
   - `publishLinkAttachedFromTargetChunkLoad(...)` 也只恢复 `sync`
4. 当前两类失效配置仍是旧语义：
   - `crosschunk.triggerSourceChunkUnloadInvalidation.enabled`
   - `crosschunk.triggerSourceInvalidation.enabled`
5. 旧命名虽然功能上可用，但无法直接表达“soft/context-detach”与“hard”两套玩法边界。

### 技术方案

#### 1. source attach replay 只实现 sync

在 `LinkNodeLifecycleDispatchEvents.consumeAttachTask(...)` 中，为来源节点新增一条可选恢复链：

1. 仅当节点类型允许作为 `triggerSource`
2. 且 `crosschunk.syncSourceAttachReplay.enabled=true`
3. 才对该来源当前已链接的 `core` 集合触发一次恢复

恢复实现直接复用现有 `InternalDispatchDeltaEvents.publishLinkAttached(...)`：

1. 不新增新的 delta 类型
2. 不扩展到 `toggle/pulse`
3. 仅沿用现有 `sync` 的强度解析与 `UPSERT` 语义

这样可保证本轮“只实现 sync 就行”，同时最大限度复用既有链路。

#### 2. hard / soft invalidation 正式拆分

配置层改为使用新的正式命名：

1. `crosschunk.triggerSourceHardInvalidation.enabled`
2. `crosschunk.triggerSourceContextDetachInvalidation.enabled`

语义定义：

1. `triggerSourceHardInvalidation`
   - 控制非 context-detach 的来源失效族
   - 包括真实离线、删除、解绑、退役等 `triggerSource invalidation`
   - 默认 `true`
2. `triggerSourceContextDetachInvalidation`
   - 控制来源仅因上下文脱附而触发的 soft invalidation
   - 默认 `false`

兼容策略采用“读旧写新”：

1. 新配置键优先
2. 若新键缺失，则回退读取旧键
3. 模板与新增文案只输出新键

#### 3. 生命周期 detach 管线只受 soft 开关控制

`LinkNodeLifecycleDispatchEvents.consumeDetachTask(...)` 仅负责普通上下文脱附语义。

因此该分支将只受 `triggerSourceContextDetachInvalidation.enabled` 控制：

1. 关闭时：来源 context-detach 只记录生命周期事实，不做失效
2. 开启时：才向目标发布 soft invalidation

这与真实删除/解绑等 hard invalidation 彻底分离。

## 原子步骤清单

### 步骤 1：补 source attach replay 配置
- **操作对象**：跨区块配置模型与默认模板
- **具体动作**：新增 `crosschunk.syncSourceAttachReplay.enabled`，默认关闭
- **预期结果**：来源 attach replay 成为独立能力开关
- **关键里程碑**：是

### 步骤 2：重命名并兼容失效配置
- **操作对象**：跨区块配置 parser / record / 模板
- **具体动作**：将 hard/soft invalidation 改用新命名，并保留旧键回退解析
- **预期结果**：配置语义正式对齐“hard / contextDetach”
- **关键里程碑**：是

### 步骤 3：接入 source attach sync 恢复
- **操作对象**：`LinkNodeLifecycleDispatchEvents`
- **具体动作**：在来源 attach 消费分支中，按新开关命中已链接目标并复用 `publishLinkAttached(...)`
- **预期结果**：来源重新 attach 时可恢复 `sync`
- **关键里程碑**：是

### 步骤 4：让 detach 只受 soft 开关控制
- **操作对象**：`LinkNodeLifecycleDispatchEvents` 与失效 helper
- **具体动作**：将 context-detach invalidation 的开关控制切换到新 soft 配置命名
- **预期结果**：默认玩法不再因 context-detach 自动失效
- **关键里程碑**：是

### 步骤 5：补回归测试
- **操作对象**：配置解析测试与 delta 规则测试
- **具体动作**：覆盖默认值、新键显式配置、旧键兼容回退，以及 hard/soft 两类失效开关
- **预期结果**：玩法边界具备可回归验证的契约
- **关键里程碑**：否

## 预期结果

1. 来源节点 attach 后可以按需执行一次 `sync-only replay`。
2. 默认玩法下，来源仅因区块活动脱附不会触发失效。
3. hard 与 soft invalidation 的配置边界清晰，且保持旧配置兼容。
4. 本轮不扩展 `toggle/pulse` 恢复语义，不改变 `triggerSource -> core` 方向模型。

## 语义对齐说明

1. 术语统一使用 `triggerSource/core`，与 `LinkNodeType.TRIGGER_SOURCE/CORE` 保持一一映射。
2. 恢复与失效方向保持 `triggerSource -> core`，不引入反向写入路径。
3. 配置兼容层遵循“读旧写新”，旧键仅保留读取兼容。
4. 本轮不引入 `com.makomi.api.v1.*` 依赖。
5. 残余风险：
   - `source attach replay` 本轮只恢复 `sync`，不覆盖 `toggle/pulse`。
   - 若目标当前不在线，恢复是否即时落地仍取决于现有投影/排队链路，不在本轮新增额外语义。
