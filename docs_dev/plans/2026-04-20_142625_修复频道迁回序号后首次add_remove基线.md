# 修复频道迁回序号后首次add_remove基线

生成时间：2026-04-20 14:26:25
文件名：2026-04-20_142625_修复频道迁回序号后首次add_remove基线.md

## 任务背景

网页图编辑器中，频道模式节点迁回序号模式后，第一次在序号模式执行 `add/remove` 时，前端仍把导出图里的旧当前目标集合当作基线，导致频道态旧目标被隐式并入 `ReplaceTriggerSourceTargets`，保存预检可能报“网页编辑当前只支持 serial 模式目标 core”。

## 方案详情

### 现状分析

- `webapp/src/components/graphViewer/draft.ts` 的 `applyBatchEditToDraft(...)` 会先调用 `resolveEffectiveTargetSerials(...)` 取当前目标集合，再折算 `add/remove/replace`。
- 当前“当前目标集合”的基线来自导出图 `edges`，而导出图的 `edges` 代表当前有效连接，不区分“频道态生效连接”和“显式 serial 边”。
- 对“base 为 channel，草稿里已把 triggerSource 切回 serial”的来源节点，第一次序号显式编辑应从空的显式 serial 边开始，而不是继承频道态旧目标。

### 技术方案

- 在 `draft.ts` 中新增 helper，识别“base 为 channel，草稿里有 `SetNodeChannel(triggerSource -> 0)`”的来源节点。
- 对上述来源节点：
  - `resolveEffectiveTargetSerials(...)` 在尚无显式 replace 时返回空集合；
  - `upsertReplaceTargetsDraft(...)` 的“是否与 base 相同”比较也改用空基线；
  - `applyDraftToGraph(...)` 在尚无显式 replace 时，不再沿用导出图中该来源节点的旧边，让草稿态可视图与显式 serial 语义一致。
- `replace` 模式保持不变，普通 serial 来源节点的 `add/remove` 逻辑保持不变。
