# 录制定时结束与默认空选集及节点列宽调整

生成时间：2026-04-16 20:44:45
文件名：2026-04-16_204445_录制定时结束与默认空选集及节点列宽调整.md

## 任务背景

当前状态面板录制 GUI 已支持录制参数配置、订阅子集选择、结束后导出和网页端查看，但仍有三个直接影响使用体验的细节：

1. 录制只能手动结束，缺少“按 tick 定时自动停止”的能力。
2. 录制 GUI 初次打开时默认会勾选全部订阅，不利于只录少量节点的场景。
3. recording 独立页面左侧 `Nodes` 列表占宽偏大，希望先收窄，并抽成可直接调整的常量。

本轮目标是在保持既有 recording 数据结构与网页主处理架构不变的前提下，为录制链路补定时结束能力，调整 GUI 默认选集行为，并把网页端节点列宽收束为可调常量。

## 方案详情

### 现状分析

- 录制开始请求当前只包含 `title / sampleEveryTicks / capacityPerNode / autoOpenWeb / selectedNodeKeys`，服务端 `ActiveSession` 也没有结束截止 tick，因此“定时结束”不能只做 GUI 计时，必须补到会话服务和网络载荷层。
- 当前录制 GUI 构造时会直接执行 `selectAllSubscriptions()`，这正是默认全选的来源；而活动录制会话的回填依赖 `applySessionSnapshot()`，两者可以分开处理。
- recording 网页左侧节点列宽目前硬编码在 CSS 的 `grid-template-columns` 中，没有单独常量，导致每次想微调都要改布局表达式本体。

### 技术方案

1. 在 `StatePanelRecordingSessionService` 的请求、快照和活动会话结构中新增 `durationTicks`，并增加基于服务端 `END_SERVER_TICK` 的到期自动结束处理。
2. 自动结束沿用现有“停止录制 -> 生成 recording bundle -> 分块回传客户端 -> 可选打开网页”的既有链路，不增加第二套导出逻辑。
3. 在录制 GUI 中新增“定时录制（tick）”输入框，正整数表示自动结束时长；空值或非正数视为不启用定时结束。
4. 录制 GUI 初次打开时默认不勾选任何节点，但如果当前存在活动录制会话，仍按服务端快照回填真实已选节点。
5. 将 recording 页面左侧 `Nodes` 列宽抽成 `:root` 下的 CSS 变量，并把默认值调窄。

### 技术取舍

- 定时录制单位按 `tick` 实现，与现有采样参数和 recording 数据时间体系一致，不额外引入秒级换算。
- 定时结束放在服务端 tick 处理中统一裁决，避免客户端关 GUI、掉线或网页关闭后行为不一致。
- GUI 默认空选集只影响“本地新打开录制界面”场景，不覆盖服务端已有活动会话的真实状态回填。
- `Nodes` 列宽用 CSS 变量表达，而不是再在 TS/JS 里引一层配置，保持离线网页静态样式修改的直接性。

### 语义对齐说明

- 本轮不调整 `triggerSource/core` 命名、方向约束、持久化键名和输出结构。
- 录制选集仍统一使用 `selectedNodeKeys`，内部语义保持不变。
- 不引入 `com.makomi.api.v1.*`。
- 兼容层无新增“写旧”行为。
- 残余风险：无。
