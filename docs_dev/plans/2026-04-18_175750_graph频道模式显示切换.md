# graph频道模式显示切换

生成时间：2026-04-18 17:57:50
文件名：2026-04-18_175750_graph频道模式显示切换.md

## 任务背景

当前 graph 网页前端已经完成 `serial` 拓扑图的查看、聚合块、搜索、局部编辑和布局优化，但频道模式仍没有独立可视化视图。  
用户要求本轮新增“频道模式显示（可切换）”，并明确以下约束：

- 频道模式天然支持聚合块渲染
- 频道模式需要一个中间虚拟点，形成频道两级连接
- 顶层显示模式先做“序号 / 频道”切换
- 为后续扩展可编辑与其它内容，序号、频道之内还要保留一层内套结构

同时，当前服务端 graph 保存仍只支持 `serial` 模式网页编辑，因此本轮必须限定为**前端显示层扩展**，不改真实保存语义。

## 方案详情

### 现状分析

- `GraphSnapshotBundle` 节点已包含 `connectionMode` 与 `channel` 字段，可为频道视图提供足够输入。
- `GraphViewer` 当前画布构建仍只围绕真实 `triggerSource -> core` 边展开。
- 当前 `GraphWriteService` 明确只接受 `serial` 模式保存请求，因此频道模式不能接入现有保存链路。
- 前端最近刚完成 `App.tsx` 与 `GraphViewer.tsx` 重文件拆分，现有 `graphViewer` 子模块已适合继续扩展显示模式。

### 技术方案

1. 在 `GraphViewer` 中引入新的显示层状态：
   - 外层：`serial / channel`
   - 内层：当前先只有 `topology`，但保留后续扩展位
2. 保持 `serial -> topology` 完全复用现有画布逻辑。
3. 为 `channel -> topology` 增加独立的前端派生视图：
   - 仅采集 `connectionMode === 'channel' && channel > 0` 的真实节点
   - 为每个频道生成一个虚拟 `channelHub`
   - 使用 `triggerSource -> channelHub -> core` 的两级连接模型
4. 频道视图中的 `channelHub` 作为前端聚合结构节点，不进入真实 `LinkNodeType` 与保存真值。
5. 频道模式暂时只读：
   - 保留搜索、详情、聚焦、布局
   - 关闭现有 serial 批量编辑入口
6. 扩展详情侧栏和图例，使其同时支持真实节点与 `channelHub` 说明。

### 影响范围

- `webapp/src/components/GraphViewer.tsx`
- `webapp/src/components/graphViewer/types.ts`
- `webapp/src/components/graphViewer/canvas.tsx`
- `webapp/src/components/graphViewer/search.ts`
- `webapp/src/app/GraphPage.tsx`
- `webapp/src/app.css`

### 语义对齐说明

- 命名统一使用 `triggerSource/core`
- 真实语义与真实保存仍只处理 `triggerSource -> core`
- 频道虚拟点仅属于网页显示层，不是新真值
- 与 `LinkNodeType.TRIGGER_SOURCE/CORE` 的映射不变
- 不引入 `com.makomi.api.v1.*`
- 残余风险：
  1. 频道视图第一版只读，不能直接承接现有 serial draft 差异编辑
  2. 搜索、孤立节点池、强制显示逻辑需要显式区分当前模式，否则可能把 serial 口径错误带入频道画布
