# 迁移到1.21.11 Fabric

生成时间：2026-04-27 09:48:23
文件名：2026-04-27_094823_迁移到1.21.11_Fabric.md

## 任务背景
当前工作区已经切到 `D:\OpenProjects\RedstoneLink\rl-fabric-1.21.11`，目标分支为 `migration/fabric-1.21.11`，但项目构建基线仍停留在 `Minecraft 1.21.1`。用户要求由我全权负责推进到 `1.21.11 Fabric`，并在落下整体方案后按步骤实施。

本轮方案的核心目标不是顺带重构业务，而是先把项目迁移到 `1.21.11` 可编译、可测试、可回归的稳定状态，再根据真实断点逐层修复。

## 方案详情

### 现状分析
- `gradle.properties` 当前仍是 `minecraft_version=1.21.1`、`loader_version=0.18.4`、`loom_version=1.15.4`、`fabric_api_version=0.116.9+1.21.1`。
- `src/main/resources/fabric.mod.json` 当前仍声明 `"minecraft": "~1.21.1"`。
- 构建脚本已具备 `main/client/test` 分源集与 `test`、`testIntegration`、`testClient`、`testSlow` 分层验证入口，适合采用“先版本基线、再分层收敛”的迁移方式。
- 项目存在客户端渲染、网络载荷、命令、数据存储、bench 脚本等多层代码；真正的迁移风险主要来自 `main/client/test` 编译断点，而不是版本号字符串本身。

### 官方版本基线
- 游戏版本：`1.21.11`，来自 Fabric 官方元数据 `https://meta.fabricmc.net/v2/versions/game`
- Loader 稳定版：`0.19.2`，来自 Fabric 官方元数据 `https://meta.fabricmc.net/v2/versions/loader` 与 `https://meta.fabricmc.net/v2/versions/loader/1.21.11`
- Fabric API 最新 `+1.21.11` 版本：`0.141.3+1.21.11`，来自 Fabric Maven 元数据 `https://maven.fabricmc.net/net/fabricmc/fabric-api/fabric-api/maven-metadata.xml`
- Loom 稳定线：当前稳定非 alpha 版本可取 `1.15.5`；`1.16.x` 仍带 alpha 标记，因此本轮优先采用稳定线，来源 `https://maven.fabricmc.net/net/fabricmc/fabric-loom/maven-metadata.xml`

### 技术方案
1. 先只更新构建与元数据入口，把项目从 `1.21.1` 升到 `1.21.11` 的可解析状态。
2. 运行快速编译任务，拿到真实迁移断点清单，按 `main -> client -> test` 的顺序收敛。
3. 每次只修一层的真实报错，不在迁移过程中顺带引入需求外设计。
4. 在主源码和客户端源码编译通过后，再跑全标签自动化测试，必要时再进入游戏内 dedicated/bench 回归。
5. 若出现测试失败或逐 tick 观测偏差，严格先按设计与语义约束复核，再判断是实现、测试模板还是观测口径问题。

### 技术取舍
- `Loom` 采用稳定的 `1.15.5`，而不是直接追 `1.16.1`，理由是本轮目标是优先降低构建层不确定性；如果后续 `1.15.5` 在 `1.21.11` 上存在明确阻断，再升级到 `1.16.x`。
- `Fabric API` 采用当前 `+1.21.11` 的最新版本 `0.141.3+1.21.11`，理由是它直接对应目标游戏版本，能够减少因继续使用 `1.21.1` API 造成的兼容噪音。
- `Lithium` 当前仅是可选本地运行时依赖，本轮不主动先改；只有在 `withLithium=true` 或客户端联调时确实阻断，才再单独校准它的版本。

### 影响范围
- 构建配置：`gradle.properties`、`build.gradle`、`settings.gradle`、`src/main/resources/fabric.mod.json`
- 主源码：`src/main/java/com/makomi/**`
- 客户端源码：`src/client/java/com/makomi/client/**`
- 测试：`src/test/**`
- 游戏内回归脚本与用例：`tools/bench/**`

### 预期与风险
- 预期结果：项目能在 `1.21.11 Fabric` 基线上完成依赖解析、源码编译、自动化测试，并在需要时完成基于当前工作区产物的游戏内回归。
- 主要风险：
  - Mojang/Fabric 小版本 API 变动集中暴露在客户端渲染与网络编解码处
  - 现有测试样本可能因为签名变更出现批量编译失败
  - dedicated/bench 若未同步当前构建产物，会造成回归结论失真
- 应对策略：
  - 先用快速编译缩小断点范围
  - 严格按 `main -> client -> test` 顺序修复
  - 涉及游戏内验证时遵守“先构建、再同步 server jar、再回归”

### 语义对齐说明
- 命名基线：本轮迁移只做 `1.21.11 Fabric` 适配，新增说明与实现仍统一使用 `triggerSource/core`
- 方向一致性：如迁移中触及来源/目标链路，继续保持 `triggerSource -> core` 的单向合法性校验，不允许反向写入
- `LinkNodeType` 映射：保持 `triggerSource=TRIGGER_SOURCE`、`core=CORE`
- 兼容策略：旧术语仅允许作为输入兼容读取，本轮不新增旧术语输出
- 残余风险：迁移过程中若某些旧测试模板仍残留旧术语，需要在测试层单独校准；当前仅记为关注项，未发现必须立即调整的设计冲突
