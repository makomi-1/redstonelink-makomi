# 自动化补测游戏内服务器基本权限

生成时间：2026-04-03 12:50:14
文件名：2026-04-03_125014_自动化补测游戏内服务器基本权限.md

## 任务背景
当前 bench/functional 自动化已经覆盖了基础命令运行态、策略管理命令、链路生命周期和部分边界命令，但“游戏内服务器基本权限”仍存在明显缺口：
- 缺少 dedicated server 自动化证据，证明低权限玩家会被读控/写控拒绝，高权限玩家会被放行。
- 缺少 dedicated server 自动化证据，证明命令限流会随权限等级分层，而不是只按同一玩家共享单桶。
- 现有 `policy_runtime_basic` 主要覆盖 `privacy current_links mask` 与 `write_control protected` 的管理命令增删改查，不覆盖权限差异本身。

本轮目标是在不引入 `com.makomi.api.v1.*` 依赖、不改变现有业务语义的前提下，补齐 dedicated server 下“读控、写控、限流”三个重要基础权限场景的专项自动化回归入口。

## 方案详情

### 现状分析
1. 现有功能 case 已具备 `command_assert` 编排能力，但当前用例几乎默认在同一执行主体下跑完整个 case，没有显式覆盖权限切换。
2. bench functional 层已经支持 `skipPlayerContext`，因此可以在单个 case 中混合“玩家上下文命令”和“控制台命令”，足以实现 `op/deop` 切换。
3. 读控语义已经稳定：`currentLinksPrivacy.viewPermissionLevel` 控制 `masked` 节点是否返回明文连接；命令读取和状态读取共用同一读控服务。
4. 写控语义已经稳定：`limited` 与 `protected` 权限不足统一反馈“没有足够权限”，`readonly` 单独反馈只读拒绝。
5. 命令限流语义已经稳定：按 `权限等级 + 主体身份 + 命令组` 分层分桶，权限变化后会切换到新的 tier/actor 桶。

### 技术方案
1. 新增 dedicated server functional case `C07`，覆盖基础读控与写控：
   - 先用控制台上下文配置 privacy mask 与 write_control protected 名单。
   - 给当前 bench 玩家打专用 tag，并通过控制台 `deop/op` 切换权限。
   - 在低权限下断言：
     - `link get` / `node get` 对 masked 节点返回空目标列表。
     - `link set` 在 limited 超量时被拒绝。
     - `link set` 命中 protected 时被拒绝。
   - 在高权限下断言同一读取与写入能够通过。
2. 新增 dedicated server functional case `C08`，覆盖权限感知限流：
   - 通过 suite 局部覆盖把 `OTHER` 组容量收紧到极小值。
   - 低权限玩家连续执行 `node list`，断言前几次通过、随后命中限流提示。
   - 提权后继续执行同命令，断言立即恢复通过，证明权限分层桶生效。
3. 新增专项 suite `server-basic-permission.json`：
   - 只挂载 `C07/C08` 两个权限专项 case。
   - 通过 `serverConfigOverrides` 固定本轮所需权限与限流配置，避免污染已有推荐回归入口。
4. 将 `C07/C08` 注册进 `functional-matrix.json`，使其可被单 case 与专项 suite 解析。

### 影响范围

## 原子步骤清单

### 步骤 1：新增 C07 权限读写专项 case
- **操作对象**：`tools/bench/cases/functional/c07/`
- **具体动作**：编排 masked 读控、limited/protected 写控、玩家 tag 与 `op/deop` 切换、读取/写入断言
- **预期结果**：低权限拒绝、高权限放行具备 dedicated server 自动化覆盖
- **关键里程碑**：是

### 步骤 2：新增 C08 权限限流专项 case
- **操作对象**：`tools/bench/cases/functional/c08/`
- **具体动作**：编排 `OTHER` 组小容量限流、低权限命中、高权限恢复通过的断言
- **预期结果**：权限感知限流具备 dedicated server 自动化覆盖
- **关键里程碑**：是

### 步骤 3：注册 matrix 与专项 suite
- **操作对象**：`tools/bench/functional-matrix.json`、`tools/bench/suites/server-basic-permission.json`
- **具体动作**：接入 `C07/C08` 并提供独立 dedicated server 权限专项 suite
- **预期结果**：权限专项可独立执行，不改变现有 suite 的前置条件
- **关键里程碑**：是

### 步骤 4：执行验证与审查归档
- **操作对象**：Gradle 全标签测试、专项 suite、`docs_dev/reviews/`
- **具体动作**：先执行 `.\gradlew.bat test testIntegration testClient testSlow --no-daemon`；若环境可用，再按“先构建当前工作区运行 jar，再同步 server jar”的规则执行 dedicated server 权限专项 suite；最后生成五段式审查文档
- **预期结果**：形成可追溯的实现、验证与审查闭环
- **关键里程碑**：是

## 预期结果
1. 游戏内服务器“读控/写控/限流”三类基础权限有 dedicated server 自动化证据。
2. 现有权限语义与文案保持不变，仅补充专项回归入口。
3. 权限专项与通用回归入口解耦，避免影响现有 suite 的执行前提。
4. 不新增 `com.makomi.api.v1.*` 依赖，不改变 `triggerSource/core` 语义。
