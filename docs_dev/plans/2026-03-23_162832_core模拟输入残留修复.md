# core模拟输入残留修复

生成时间：2026-03-23 16:28:32
文件名：2026-03-23_162832_core模拟输入残留修复.md

## 任务背景

在修复输入器跨重启状态主问题后，继续观察到 `core` 的模拟输入残留：

1. 停服/重进后，`core` 可能仍保持旧的激活外显
2. 该残留与 `triggerSource` 的加载期静默重采样不同，属于 `core` 目标端独立链路

## 方案详情

### 现状分析

- `InputPlaybackService` 当前只在 `SERVER_STOPPED` 移除内存态 `INPUT_STATES`，没有在停服前先执行 `clear(server)`
- 因此若停服瞬间仍有运行中 job，`cleanupCoreSyncLanes(...)` 可能没有机会先撤销 `core` 的运行态模拟 SYNC
- `core` 的 `ACTIVE` 方块状态由实体侧 `onActiveChanged(...)` 单独写回 blockstate
- `ActivatableTargetBlockEntity.loadAdditional(...)` 读档后会重建结构真值与派生缓存，但不会把 blockstate 再静默校正回当前派生态

### 技术方案

按最小修复处理两点：

1. 停服前清理输入器 job
   - 在 `SERVER_STOPPING` 先调用 `clear(server)`，确保 `core` 运行态模拟 SYNC 与 `triggerSource` 模拟输入在保存世界前被撤销

2. 读档后静默校正 `core` blockstate
   - `ActivatableTargetBlockEntity` 在 `loadAdditional(...)` 重建完派生态后，仅登记“待同步 blockstate”标记
   - 在 `onLoad()` 阶段执行一次无扇出的静默 blockstate 校正
   - 仅 `core` 子类实现该静默校正钩子，统一用 `UPDATE_CLIENTS` 同步可见态，不追加邻居扇出

- **预期结果**：不再把停服瞬间的模拟输入结果残留到 `core`/`triggerSource` 外显状态

- **预期结果**：结构真值重建后，`core` 的 `ACTIVE` 方块状态与当前派生态一致
