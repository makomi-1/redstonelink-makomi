# 频道预检性能优化

生成时间：2026-04-19 11:09:18
文件名：2026-04-19_110918_频道预检性能优化.md

## 任务背景

频道模式节点较多时，graph 保存预检会明显变慢，并最终在前端表现为 `Graph preview request timed out.`。现有分析表明，瓶颈主要不在前端，而在服务端频道批量预检阶段的重复目标集合推导。

## 方案详情

### 现状分析

- `GraphWriteService.preview()` 会直接复用正式保存的 `preparePlan()`。
- 频道操作会落到 `LinkChannelEditingService.prepareConfirmedBatchSetChannel()`。
- 当前每个受影响 `triggerSource` 都会重复：
  - 构造一次 overrides 索引
  - 在频道模式下扫描整批 overrides 以推导该频道的最终 core 成员
- 当频道成员和受影响 `triggerSource` 同时较多时，重复计算会显著放大。

### 技术方案

- 在 `LinkSavedDataChannelSupport` 中新增“批次级频道解析上下文”：
  - 只构建一次 overrides 索引
  - 对 `channel -> 最终 core 成员集合` 做惰性缓存
- 在 `LinkChannelEditingService.prepareConfirmedBatchSetChannel()` 中对整批 overrides 只初始化一次上下文，然后所有受影响 `triggerSource` 复用。
- 不改正式 apply 路径，不改 `triggerSource -> core` 真值语义，不改 draft/snapshot 协议。

### 影响范围

- `src/main/java/com/makomi/data/LinkSavedDataChannelSupport.java`
- `src/main/java/com/makomi/command/link/LinkChannelEditingService.java`
- 可能补充相关测试与审查文档

## 原子步骤清单

### 步骤 1：抽取频道批次上下文
- **操作对象**：`LinkSavedDataChannelSupport`
- **具体动作**：新增批次级 overrides 索引与频道 core 成员惰性缓存，并提供复用解析入口
- **预期结果**：频道最终目标集合的推导不再为每个 `triggerSource` 重建同一批数据
- **关键里程碑**：是

### 步骤 2：频道批量预检接入上下文复用
- **操作对象**：`LinkChannelEditingService`
- **具体动作**：在 `prepareConfirmedBatchSetChannel()` 中一次性构建上下文，并在受影响 `triggerSource` 遍历中复用
- **预期结果**：减少大频道场景下的重复扫描和重复 map 构建
- **关键里程碑**：是

### 步骤 3：构建验证与文档留痕
- **操作对象**：Gradle/Webapp 构建链路、`docs_dev/reviews/`
- **具体动作**：运行 `npm.cmd run typecheck`、`.\gradlew.bat buildWebapp --no-daemon`、`.\gradlew.bat test testIntegration testClient testSlow --no-daemon`，并生成审查文档
- **预期结果**：确认优化不改变现有语义，仅改善预检性能
- **关键里程碑**：是

## 预期结果

频道模式在节点较多时的保存预检明显提速，前端因 15 秒本地 RPC 超时而报 `Graph preview request timed out.` 的概率下降；同时保持 `triggerSource/core` 语义与真实保存行为不变。
