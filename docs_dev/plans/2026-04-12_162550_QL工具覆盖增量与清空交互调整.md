# QL工具覆盖增量与清空交互调整

生成时间：2026-04-12 16:25:50
文件名：2026-04-12_162550_QL工具覆盖增量与清空交互调整.md

## 任务背景

当前快速连接工具仍以“覆盖式应用 + 中键清空 + `B` 仅切模式”为主，其中 `core` 端 quick-link 仍采用“把缓存中的每个 `triggerSource` 覆写为只连接当前 `core`”的实现，不符合本轮确认的“双端独立一跳修改”语义。

用户已确认：
- 中键不再清空缓存，改为切换 quick-link 的应用编辑模式
- `潜行 + B` 改为隐式清空序号缓存与频道缓存
- `B` 单击保留模式切换，并允许切入 `channel`
- `channel` 仍只允许切换显示，不允许 collect/apply 真正使用
- quick-link 应用到 `triggerSource/core` 时，只修改命中端点的一跳拓扑关系
- 应用到过滤器时，同样支持覆盖、增量增加、增量删除三种模式

## 方案详情

### 现状分析

- `QuickLinkToolData` 当前只保存 `mode / serialCacheType / serialCacheExpression / channelCache`，没有“应用编辑模式”状态。
- 客户端 `RedstoneLinkClient` 里，中键固定调用 `handleQuickLinkClear(...)`；`B` 键尝试切到 `channel` 会被 `mode.channel_future` 直接拦截。
- `QuickLinkApplyService` 当前：
  - 对 `triggerSource` 命中是覆盖当前 `triggerSource` 的目标集合
  - 对 `core` 命中是把缓存中的每个 `triggerSource` 覆写成“仅连接当前 `core`”
  - 对过滤器命中只覆盖 `serialExpression`
- 命令层 `CoreLinkEditingService` 已具备“只围绕当前 `core` 的一跳来源集合做增删”的成熟逻辑，可复用到 quick-link。

### 技术方案

1. 为 quick-link 新增 `applyEditMode` 三态：
   - `replace`：覆盖
   - `append`：增量增加
   - `remove`：增量删除
2. 调整客户端按键职责：
   - 中键：循环切换 `applyEditMode`
   - `B`：站立时切换 `serial/channel`
   - `潜行 + B`：清空序号缓存与频道缓存，但保留当前模式、缓存类型与应用编辑模式
3. `channel` 模式改为“可切换但不可使用”：
   - GUI、tooltip、HUD 允许显示当前处于 `channel`
   - collect/apply 仍返回“未来扩展”提示
4. 重构 quick-link 应用服务：
   - 命中 `triggerSource`
     - `replace`：当前 `triggerSource` 的目标集合替换为缓存 `core`
     - `append`：只补当前 `triggerSource -> 缓存 core`
     - `remove`：只删当前 `triggerSource -> 缓存 core`
   - 命中 `core`
     - `replace`：当前 `core` 的来源集合替换为缓存 `triggerSource`
     - `append`：只补 `缓存 triggerSource -> 当前 core`
     - `remove`：只删 `缓存 triggerSource -> 当前 core`
   - 命中过滤器
     - `replace`：过滤器 `serialExpression` 替换为缓存集合
     - `append`：在过滤器现有集合基础上并入缓存集合
     - `remove`：从过滤器现有集合中移除缓存集合
5. 文案与公开说明同步更新：
   - 中英文语言文件
   - `docs/使用说明.md`
   - `docs/item_guide.html`
6. 补齐 quick-link 状态、节点应用、过滤器应用与按键交互的单测，并执行全标签回归。

### 技术取舍

- 不新增独立清空快捷键，按用户确认采用 `潜行 + B` 清空，从而避免双击时序判定的不稳定性。
- collect 规则保持现状，只改 apply 规则，控制本轮改动范围。
- `core` 端 quick-link 不再继续保留“逐 `triggerSource` 全量替换成单 `core`”的特化实现，改为按 `core` 视角的一跳关系做覆盖或增量修改，确保不影响一级邻居其它拓扑关系。

## 原子步骤清单

### 步骤 1：扩展 quick-link 缓存状态
- **操作对象**：`QuickLinkToolData`、相关测试
- **具体动作**：新增 `applyEditMode` 状态、默认值、序列化、循环切换与清空后保留逻辑
- **预期结果**：quick-link 物品可稳定保存覆盖/增量增加/增量删除模式
- **关键里程碑**：是

### 步骤 2：调整客户端按键职责
- **操作对象**：`RedstoneLinkClient`、tooltip/lang
- **具体动作**：中键改循环切换应用编辑模式；`潜行 + B` 改清空缓存；站立 `B` 允许切换到 `channel`
- **预期结果**：新交互入口可用，且不再依赖双击
- **关键里程碑**：是

- **操作对象**：`QuickLinkApplyService`、必要的共享 helper
- **具体动作**：按 `applyEditMode` 实现 `triggerSource/core` 两端的一跳覆盖/增量增加/增量删除
- **预期结果**：命中哪一端，就只修改该端与一级邻居的关系，不影响一级邻居其它边
- **关键里程碑**：是

### 步骤 4：扩展过滤器 quick-link 应用语义
- **操作对象**：`QuickLinkApplyService`、相关测试
- **具体动作**：把过滤器 `serialExpression` 从“只覆盖”扩展为覆盖/增量增加/增量删除
- **预期结果**：过滤器 quick-link 语义与节点 quick-link 一致
- **关键里程碑**：是

### 步骤 5：更新文档与验证

## 预期结果

- quick-link 支持三态应用编辑模式：覆盖、增量增加、增量删除
- 中键用于切换应用编辑模式，`潜行 + B` 用于清空缓存，`B` 单击用于切换 `serial/channel`
- `channel` 模式可切换显示，但 collect/apply 仍保持“未来扩展”限制
- quick-link 命中 `triggerSource/core` 时只修改命中端点的一跳关系；命中过滤器时同样支持覆盖或增量修改
- 新增设计、文案、注释继续统一使用 `triggerSource/core`，真实写入方向保持 `triggerSource -> core`
