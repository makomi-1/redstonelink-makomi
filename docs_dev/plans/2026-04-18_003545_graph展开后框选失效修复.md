# graph展开后框选失效修复

生成时间：2026-04-18 00:35:45
文件名：2026-04-18_003545_graph展开后框选失效修复.md

## 任务背景

graph 视图在存在已展开核心聚合块时，框选会出现整体失效：用户拖框后不是选不中，就是右侧批量编辑结果与实际选框不一致。结合前一轮“框选预览态 / 应用态分离”的实现，当前已确认根因是预览阶段把 ReactFlow 发出的真实 `select` 增量过滤掉了，转而依赖 `onSelectionChange` 推断最终选区；一旦画布里混入 `aggregate`、`aggregate-outline` 等非真实节点，这条推断链就会不稳定。

本轮目标是在不改 `triggerSource/core` 真值、不改 snapshot、draft 和服务端语义的前提下，恢复“存在展开块时也能稳定框选真实节点”的行为。

## 方案详情

### 现状分析

- 当前 `handleCanvasNodesChange` 在预览阶段会直接过滤全部 `select` 变更
- `pendingSelectionNodeKeysRef` 主要依赖 `onSelectionChange` 结果回填
- 展开后画布里会出现聚合块节点和包围盒节点，它们会干扰 `onSelectionChange` 的结果稳定性
- 最终导致框选结束时 `pendingSelectionNodeKeysRef` 为空或口径错误，从而表现为“只要有展开，所有节点都无法被框选”

### 技术方案

1. 保留“预览态 / 应用态分离”的总体结构，不回退前一轮设计
2. 调整 `handleCanvasNodesChange`：
   - 预览阶段不再简单丢弃全部 `select` 变更
   - 直接消费 ReactFlow 的 `NodeSelectionChange` 增量，维护 `pendingSelectionNodeKeysRef`
   - 仅接受真实 `triggerSource/core` 节点，对 `aggregate`、`aggregate-outline` 等非真实节点一律过滤
3. 弱化 `onSelectionChange` 在预览阶段的职责：
   - 预览期间不再把它作为最终候选选区的主数据源
   - 非预览场景仍保留已有即时同步行为，避免影响普通点击选中
4. 保持 `onSelectionEnd` 的一次性正式提交：
   - 框选结束后统一把最终真实节点集合写回画布 `selected`
   - 同步更新右侧批量编辑集合

### 影响范围

- `webapp/src/components/GraphViewer.tsx`
- `docs_dev/reviews/` 审查文档

### 语义对齐说明

- 命名仍只使用 `triggerSource/core`
- 真实保存语义仍只处理 `triggerSource -> core`
- 本轮仅修 ReactFlow 前端框选事件同步链，不改 snapshot、draft 和服务端真值
- 与 `LinkNodeType.TRIGGER_SOURCE/CORE` 的映射关系不变
- 兼容层仍然是“读旧写新”，本轮无新增兼容字段

### 步骤 1：修正预览阶段的节点选区增量来源
- **操作对象**：`webapp/src/components/GraphViewer.tsx`
- **具体动作**：在 `handleCanvasNodesChange` 中解析 `select` 增量，直接维护预览候选集合
- **预期结果**：展开块存在时，框选最终结果不再依赖不稳定的 `onSelectionChange`
- **关键里程碑**：是

- **操作对象**：`webapp/src/components/GraphViewer.tsx`
- **具体动作**：只把真实 `triggerSource/core` 节点纳入最终候选集合，保留普通点击和程序化清选的既有逻辑
- **预期结果**：聚合块与包围盒不会污染批量编辑选区
- **关键里程碑**：是

## 预期结果

即使画布中存在已展开的核心聚合块，用户仍可稳定框选真实 `triggerSource/core` 节点；框选范围、右侧批量编辑结果和画布最终选中态保持一致，聚合块与包围盒不再干扰选区提交。
