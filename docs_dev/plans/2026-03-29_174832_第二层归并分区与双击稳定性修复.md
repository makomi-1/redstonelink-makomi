# 第二层归并分区与双击稳定性修复

生成时间：2026-03-29 17:48:32
文件名：2026-03-29_174832_第二层归并分区与双击稳定性修复.md

## 任务背景

当前第二层归并已经切到“原版命中后打票据，服务器下一 tick 消费”的模式，但实测还有两个问题：

- 自动归并范围过宽，打开容器时会把容器区和玩家背包区一起归并；
- 双击同类物品的 `PICKUP_ALL` 命中不稳定，存在漏触发。

本轮目标是在不改写原版点击主流程的前提下，把第二层票据收窄到“命中分区”，并修正双击命中的参考栈来源。

## 方案详情

### 现状分析

- 现有票据模型只记录 `menu + item`，消费时会扫描该菜单内所有同物品分区，因此会出现“容器区和背包区一起被归并”。
- 现有 `PICKUP_ALL` 命中在 `RETURN` 后直接读取 `getCarried()`，该值依赖原版处理后的结果态，导致双击命中不稳定。
- 当前分区口径已经存在于消费器中：`Slot.container + Slot 运行时类`，可直接复用。

### 技术方案

- 将票据模型从“按物品”升级为“按命中分区 + 物品”：
  - `Container`
  - `Slot` 运行时类
  - `Item`
- `QUICK_MOVE`：
  - 在点击前缓存命中槽位物品；
  - 在点击后使用 `slotId` 对应槽位的分区 + 点击前物品登记票据。
- `PICKUP_ALL`：
  - 在 `HEAD` 同时缓存：
    - 点击前槽位物品
    - 点击前光标物品
  - 在 `RETURN` 时按稳定优先级选参考物品：
    - `carriedBefore`
    - `clickedStackBefore`
    - `getCarried()`
  - 仍使用 `slotId` 锁定分区，无法锁定时保守跳过，不做跨区推断。
- 消费器只归并命中票据对应的分区，不再按整菜单同物品全局处理。

### 影响范围

- `src/main/java/com/makomi/mixin/AbstractContainerMenuAggregateNormalizationTriggerMixin.java`
- `src/main/java/com/makomi/data/PairableItemAggregateMenuNormalizationService.java`
- `src/test/java/com/makomi/data/PairableItemAggregateMenuNormalizationServiceTest.java`

## 原子步骤清单

### 步骤 1：收窄第二层票据模型
- **操作对象**：`PairableItemAggregateMenuNormalizationService`
- **具体动作**：把票据从 `menu + item` 改为 `menu + 分区 + item`
- **预期结果**：自动归并只作用于命中那一侧，不跨容器区与玩家背包区
- **关键里程碑**：是

### 步骤 2：修正双击命中识别
- **操作对象**：`AbstractContainerMenuAggregateNormalizationTriggerMixin`
- **具体动作**：增加点击前光标栈缓存，`PICKUP_ALL` 改为稳定优先级参考栈选择
- **预期结果**：双击同类物品命中稳定，不再只依赖点击后 `getCarried()`
- **关键里程碑**：是

### 步骤 3：补回归测试
- **操作对象**：`PairableItemAggregateMenuNormalizationServiceTest`
- **具体动作**：新增“仅命中分区归并”与“双击参考栈稳定回退”覆盖
- **预期结果**：两个问题有自动化回归保护
- **关键里程碑**：否

## 预期结果

- 容器区与玩家背包区不再被一次票据同时归并；
- `shift` 快移只整理命中侧；
- 双击同类物品的第二层触发更稳定；
- 不改动 `triggerSource/core` 业务语义、配对命令链路和持久化结构。

## 语义对齐说明

- 本方案不新增旧术语输出，不改变 `triggerSource/core` 术语基线；
- 不涉及方向写入，不改变 `LinkNodeType` 与 `triggerSource/core` 的映射；
- 仅修正第二层票据粒度和命中稳定性；
- 残余风险：极少数特殊菜单若 `slotId` 无法稳定定位，将采用保守跳过策略，不做跨区归并。
