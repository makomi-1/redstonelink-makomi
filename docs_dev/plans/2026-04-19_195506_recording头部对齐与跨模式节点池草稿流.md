# recording头部对齐与跨模式节点池草稿流

生成时间：2026-04-19 19:55:06

## 任务背景

当前 graph 页面已经具备较完整的左侧工具栏和右侧详情/批量编辑结构，但 recording 页面头部仍保留旧布局；同时 graph 编辑器虽然已经支持序号与频道两种模式的网页草稿编辑，却缺少“将另一模式节点迁入当前模式”的独立入口。用户要求：

- recording 页面头部与 graph 页面保持一致，把 `已连接` 与 `Dedicated Recording Viewer` 放到右侧顶部。
- graph 右侧新增“另一模式节点池”页签，用于从另一模式选择多个节点，点击“应用到草稿”后统一迁入当前模式。
- 两种模式都统一为“先应用到草稿，再继续当前模式编辑”；始终都是草稿态，只有 `Save` 才改后端真值，且同样可撤回。

## 方案详情

### 现状分析

- `webapp/src/app/RecordingPage.tsx` 仍使用旧的头部结构：桥接状态单独一行，`Dedicated Recording Viewer` 位于左侧标题正文。
- `webapp/src/components/graphViewer/types.ts` 的右侧页签类型只有 `details / isolated / batch`，没有跨模式入口。
- `webapp/src/components/GraphViewer.tsx` 已具备频道批量编辑选择态 `selectedEditChannelNodeKeys`，以及序号模式来源/目标选择态；`graphDraft` 已支持 `SetNodeChannel` 与 `ReplaceTriggerSourceTargets`。
- `webapp/src/components/graphViewer/draft.ts` 已能将 `SetNodeChannel(channel>0)` 折算为切入频道，将 `SetNodeChannel(channel=0)` 折算为回到 serial，但跨模式节点的 UI 分桶、选择与应用时机还没有实现。

### 技术方案

- 复用 graph 页现有头部布局样式，让 recording 页也使用“左标题说明 + 右状态/分析器标识”的结构。
- 为右侧页签新增 `crossMode`，名称显示为“另一模式节点池”。
- 在 `GraphViewer` 中新增独立的跨模式选择态：
  - 序号模式下，候选节点来自 `connectionMode=channel && channel>0` 的节点。
  - 频道模式下，候选节点来自 `connectionMode=serial` 的节点。
  - 这些选择态在切换显示模式时自动清空，未应用前不写入 `graphDraft`。
- 点击“应用到草稿”时才统一折算为跨模式草稿操作：
  - 序号模式：对选中的频道节点写 `SetNodeChannel(channel=0)`，把它们迁回 serial。
  - 频道模式：对选中的序号节点写 `SetNodeChannel(channel=当前目标频道号)`，把它们迁入当前频道。
- 应用后立即把这些节点并入当前模式的后续编辑上下文：
  - 序号模式：按类型分别并入当前来源/目标选区，但只在“已应用后”才允许继续改边。
  - 频道模式：并入当前频道编辑选区。
- 文案中明确说明：
  - 两种模式都必须先“应用到草稿”后，才能继续当前模式编辑。
  - 序号模式下，迁回 serial 只是回到显式边模式，不会自动生成真实边；后续仍需使用当前序号模式的 add/remove/replace 去编辑。
