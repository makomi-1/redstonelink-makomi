# c06命令边界bench配置修正

生成时间：2026-03-29 23:49:54
文件名：2026-03-29_234954_c06命令边界bench配置修正.md

## 任务背景
`c06_command_boundary` 在核心/完整回归套件中失败，但失败点并非业务实现异常，而是 bench 期望与当前服务器配置不一致。

当前 `crosschunk whitelist set` 的服务端默认批量上限为 `1024`，而 `c06` 用例中的“too many”阶段只提交了 `1:3`，不会触发超限失败。

## 方案详情

### 现状分析
- `tools/bench/cases/functional/c06/command_boundary_matrix.json` 中的超限断言复用 `{{targets:range}}`，当前只会生成 3 个序号。
- `tools/bench/suites/functional-phase2.json` 已经通过 `serverConfigOverrides.server.command.crosschunk.whitelist.maxSetSerials=2` 修正了同一问题。
- `tools/bench/suites/regression-core.json` 与 `tools/bench/suites/regression-full.json` 尚未同步该 override，因此仍会按默认上限 1024 运行，导致断言过时。

### 技术方案
仅修改 bench suite 配置，不改业务代码：
- 为 `regression-core.json` 中的 `c06_command_boundary` 增加局部 server config override；
- 为 `regression-full.json` 中的 `c06_command_boundary` 增加相同 override；
- 保持 case 文件与服务端业务实现不变。

### 影响范围
- `tools/bench/suites/regression-core.json`
- `tools/bench/suites/regression-full.json`
- 新增方案文档
