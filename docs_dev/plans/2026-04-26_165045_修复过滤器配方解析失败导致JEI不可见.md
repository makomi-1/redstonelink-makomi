# 修复过滤器配方解析失败导致JEI不可见

生成时间：2026-04-26 16:50:45
文件名：2026-04-26_165045_修复过滤器配方解析失败导致JEI不可见.md

## 任务背景

用户反馈在 JEI 中看不到发送过滤器和接收过滤器的配方，而其他模组物品配方可正常显示。快速核对后发现这两个配方文件存在，但运行日志中有 `Parsing error loading recipe`，说明问题不在 JEI，而在 Minecraft 启动时未成功加载这两个 recipe。

## 方案详情

### 现状分析

- `src/main/resources/data/redstonelink/recipe/link_send_filter.json`
- `src/main/resources/data/redstonelink/recipe/link_receive_filter.json`

这两份运行时配方使用了字符串式 ingredient 写法，而项目中其他已正常加载的配方使用的是标准对象式 ingredient 写法。运行日志已明确报出：

- `Parsing error loading recipe redstonelink:link_send_filter`
- `Parsing error loading recipe redstonelink:link_receive_filter`

另外，datagen 源 `RedstoneLinkRecipeProvider` 里对这两个过滤器仍沿用旧的通用模板，和当前运行时资源内容已经漂移。如果只修资源文件，不修 datagen，后续重新生成资源时仍可能把修复覆盖掉。

### 技术方案

1. 保留当前过滤器配方设计语义不变，只把运行时 JSON 改为 Minecraft 可解析的标准 ingredient 结构。
2. 在 `RedstoneLinkRecipeProvider` 中为发送过滤器和接收过滤器补独立生成方法，使 datagen 产物与运行时资源重新一致。
3. 跑全量自动化测试，确认本次修复不会影响其他配方、资源布局和客户端/服务端回归。

### 影响范围

- `src/main/resources/data/redstonelink/recipe/link_send_filter.json`
- `src/main/resources/data/redstonelink/recipe/link_receive_filter.json`
- `src/client/java/com/makomi/datagen/RedstoneLinkRecipeProvider.java`
- `docs_dev/reviews/`
- 视实现阻塞情况决定是否补 `docs_dev/experiences/`

## 原子步骤清单

### 步骤 1：修正运行时过滤器配方格式
- **操作对象**：两个过滤器 recipe JSON
- **具体动作**：把 `key` 中的字符串式 ingredient 改为对象式 `{"item": "..."}`，保留现有配方材料与布局不变。
- **预期结果**：Minecraft 可成功解析这两个过滤器配方。
- **关键里程碑**：是

### 步骤 2：同步修正 datagen 配方源
- **操作对象**：`RedstoneLinkRecipeProvider`
- **具体动作**：把两个过滤器从通用基础模板中拆出，改为独立 recipe 生成逻辑，与运行时资源保持一致。
- **预期结果**：后续 datagen 不会再把过滤器配方写回错误或漂移状态。
- **关键里程碑**：是

### 步骤 3：执行自动化回归并补文档
- **操作对象**：Gradle 测试、审查文档、必要经验文档
- **具体动作**：运行 `.\gradlew.bat test testIntegration testClient testSlow --no-daemon`，随后补审查文档；若本轮形成了可复用的排障经验，再写经验文档。
- **预期结果**：修复结果可验证、可追溯。
- **关键里程碑**：否

## 预期结果

发送过滤器和接收过滤器的配方会重新被 Minecraft 成功加载，因此能在 JEI 中正常显示；同时 datagen 源与运行时资源恢复一致，避免同类问题再次出现。
