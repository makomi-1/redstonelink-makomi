# 输入器命令参数类型迭代0与1

生成时间：2026-03-23 13:05:54
文件名：2026-03-23_130554_输入器命令参数类型迭代0与1.md

## 任务背景

当前输入器命令仍使用 `StringArgumentType.string()` 读取 `serials` 与 `sequence`，虽然能保留后续参数树，但缺少面向领域的输入边界约束，也无法为后续批量序号命令统一复用。

这轮只实现已确认的“迭代 0 + 1”：

1. 新增最小自定义 token 参数类型基础设施。
2. 先迁移 `/redstonelink input start ...` 的 `serials` 与 `sequence`。
3. 业务解析继续复用现有 `SerialParseUtil` 与 `InputWaveformSpec`，不扩展到其他命令。

## 方案详情

### 现状分析

- [ModCommands.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/ModCommands.java#L1500) 的输入器分支目前仍以 `StringArgumentType.string()` 读取 `serials` 和 `sequence`。
- [SerialParseUtil.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/util/SerialParseUtil.java#L23) 已具备批量序号语义解析能力。
- [InputWaveformSpec.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/input/InputWaveformSpec.java#L116) 已具备自定义波形文本解析能力。
- 工程内尚无现成自定义命令参数类型注册范式，需要补最小注册入口，确保服务端与客户端命令树同步安全。

### 技术方案

1. 新增 `CommandTokenReadUtil`，统一实现“从当前游标读取到下一个空格为止”的 token 读取逻辑。
2. 新增两个参数类型：
   - `SerialBatchArgumentType`
   - `SignalSequenceArgumentType`
3. 新增 `ModCommandArgumentTypes.register()`，在 [RedstoneLink.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/RedstoneLink.java#L25) 初始化时先注册参数类型，再注册命令。
4. 将输入器 `square/custom` 分支的 `serials` 与 `sequence` 改为新参数类型，执行层仍复用既有业务解析。
5. 新增参数类型与命令链路测试，重点验证：
   - 合法字符接受
   - 非法字符拒绝
   - 空格终止后仍可继续解析后续参数
