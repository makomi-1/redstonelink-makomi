# bench路径配置抽取

生成时间：2026-04-09 11:47:51
文件名：2026-04-09_114751_bench路径配置抽取.md

## 任务背景

当前 bench 游戏内测试编排存在两类重复的绝对路径硬编码：

- 多个 PowerShell 入口脚本把 `ServerRoot`、`TemplateWorldPath`、`PrismLauncherPath`、`PrismRootDir` 直接写成默认值。
- 多个 suite JSON 条目把 reload 专用模板世界 `templateWorldPath` 直接写成绝对路径。

这导致环境迁移成本高，也让 suite 与脚本对同一类本地路径各自维护，容易偏移。

## 方案详情

### 现状分析

- `run-bench-suite.ps1`、`run-regression-suite-common.ps1`、`run-performance-suite-common.ps1` 与各个 thin wrapper 都在参数默认值中持有绝对路径。
- `BenchSuite.Config.ps1` 已支持 `{{param:...}}` 参数化，但 `templateWorldPath` 尚未走这套展开逻辑。
- `regression-full.json`、`regression-lifecycle.json`、`functional-phase2.json` 中的 reload 模板路径仍为绝对路径。

### 技术方案

- 新增 `tools/bench/bench.path-config.json`，集中声明 bench 本地路径：
  - `serverRoot`
  - `templateWorld`
  - `reloadTemplateWorld`
  - `prismLauncher`
  - `prismRootDir`
- 新增 `tools/bench/lib/Bench.PathConfig.ps1`，负责读取与校验该配置，并提供默认值解析函数。
- 脚本层移除绝对路径参数默认值，改为在未传入时从 `bench.path-config.json` 补默认。
- suite 解析层把 bench 路径配置注入参数，并让 `templateWorldPath` 先做参数展开再解路径，这样 suite 可以使用 `{{param:reloadTemplateWorld}}`。
- 将现有 reload suite 条目改为引用配置参数，而不是继续写死绝对路径。

### 影响范围

- `tools/bench/bench.path-config.json`
- `tools/bench/lib/Bench.PathConfig.ps1`
- `tools/bench/run-bench-suite.ps1`
- `tools/bench/run-regression-suite-common.ps1`
- `tools/bench/run-performance-suite-common.ps1`
- 相关 thin wrapper 脚本
- `tools/bench/lib/BenchSuite.Config.ps1`
- `tools/bench/suites/regression-full.json`
- `tools/bench/suites/regression-lifecycle.json`
- `tools/bench/suites/functional-phase2.json`
- `docs_dev/plans/`
- `docs_dev/reviews/`

- **操作对象**：`tools/bench/bench.path-config.json`、`tools/bench/lib/Bench.PathConfig.ps1`

- **预期结果**：bench 编排可从单一配置源读取路径。
- **关键里程碑**：是
