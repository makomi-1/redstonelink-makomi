# 频道模式派发中间收口优化

生成时间：2026-04-15 22:18:40
文件名：2026-04-15_221840_频道模式派发中间收口优化.md

## 任务背景

当前频道模式在配置层已经维护频道成员索引，并在模式切换时把频道关系展开为普通 `triggerSource -> core` 边。  
但运行时派发仍然直接基于普通边展开后的目标集逐个处理，只在目标端按 `core` 做批调度，没有形成“同频道来源先收口、再统一扇出”的运行时中间层。

本次只优化**频道模式下**的运行时派发路径，不改频道展开落库设计，不改序号模式。

## 方案详情

### 现状分析

- 配置层已存在频道成员索引与频道目标推导：[LinkSavedDataChannelSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataChannelSupport.java)。
- 频道切换时，上层编辑服务会计算受影响的 `triggerSource`，并把频道关系改写为普通边：[LinkChannelEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkChannelEditingService.java)。
- 运行时派发仍在 `LinkedTargetDispatchService` 内按 `targetSerials` 逐目标遍历，没有频道级中间收口：[LinkedTargetDispatchService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkedTargetDispatchService.java)。
- 当前已存在的批处理是“目标级 `core` batch”，不是“频道级 batch”：[CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java)。

### 技术方案

1. 新增运行时 `ChannelDispatchScheduler`
   - 仅用于频道模式派发的内存态中间收口。
   - 以 `server + dueTick + sourceChannel + dispatchKind + graphRevision` 作为分桶边界。
   - 统一在 `END_SERVER_TICK` flush，`window=0` 时补 late-arrival flush。

2. 在 `LinkedTargetDispatchService` 增加频道模式 fast path
   - 当来源节点当前连接模式为 `CHANNEL` 时，不再直接按普通边展开后的 `targetSerials` 逐个派发。
   - 改为读取来源频道值并提交给 `ChannelDispatchScheduler`。
   - 序号模式保持现状，不受影响。

3. `ChannelDispatchScheduler` flush 逻辑
   - flush 时按频道一次性解析当前 `core` 频道成员集。
   - 针对每个 `core`：
     - 做 receive 过滤判断；
     - 已加载目标进入现有 `CoreDispatchBatchScheduler` 或 direct apply；
     - 未加载目标进入现有 `CrossChunkDispatchService.queue*Batch(...)`。
   - 保持现有 `core` 真值、批窗口和跨区块队列语义不变。

4. 正确性保护
   - 第一版使用 `LinkSavedData.graphRevision()` 作为拓扑切分键，避免拓扑变化前后的频道事件错误混桶。
   - 不新增持久化字段，不引入频道级 revision。

- bench / 单测回归用例

### 语义对齐说明

- 命名统一使用 `triggerSource/core`。
- 方向保持 `triggerSource -> core`。
- 本次不改频道配置落库设计，只改频道模式运行时派发路径。
- 兼容层保持“读旧写新”原则不变，本方案不涉及 API。
- 残余风险：若 `graphRevision` 切分过于保守，可能降低同窗口合批率，但不会破坏语义正确性。

## 预期结果

频道模式下的运行时派发从“先按边展开、再按 core 收口”改为“先按 channel 收口、再按 core 扇出”，从而减少同频道多来源同窗口派发时的重复目标解析、重复过滤判定和重复分桶成本，同时保持现有频道配置、普通边生命周期和目标端真值语义不变。
