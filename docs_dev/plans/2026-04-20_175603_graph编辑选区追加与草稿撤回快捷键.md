# graph编辑选区追加与草稿撤回快捷键

生成时间：2026-04-20 17:56:03
文件名：2026-04-20_175603_graph编辑选区追加与草稿撤回快捷键.md

## 任务背景

当前网页 graph 编辑器在编辑模式下的点击选区和框选选区仍然表现为覆盖式更新，用户期望改成追加式选区。同时，现有草稿撤回只有按钮入口，用户希望增加 `Ctrl+Z` 快捷键支持，用于撤回最近一次本地草稿应用。

## 方案详情

### 现状分析

- `GraphViewer.tsx` 当前通过 ReactFlow 的 `onSelectionChange` 和框选预览链路，把画布选区收口到业务选区状态。
- 业务选区的最终写回函数 `applyBatchSelectionFromNodeKeys(...)` 会直接用本轮选区覆盖 `selectedEditSourceSerials / selectedEditTargetSerials / selectedEditChannelNodeKeys`。
- 框选预览阶段会把 `selected=false` 节点从待确认集合里删除，因此即使 ReactFlow 自身启用了多选键，最终业务态仍会被覆盖。
- 草稿撤回当前仅由“撤回草稿”按钮触发 `handleUndoDraft()`，没有键盘快捷键。

### 技术方案

- 在 `GraphViewer.tsx` 中新增统一的“追加到业务选区”辅助函数，按当前显示模式分别维护：
  - `serial` 模式下的来源/目标序号集合
  - `channel` 模式下的节点键集合
- 将现有 `applyBatchSelectionFromNodeKeys(...)` 从“覆盖写回”改成“追加写回”，并复用到：
  - 普通点击后的选区同步
  - `Ctrl/Shift` 点击后的选区同步
  - 框选结束后的选区同步
- 调整框选预览逻辑，使其以“起始业务选区 + 本次新增框选结果”为基础，不再把旧业务选区删除。
- 为 `GraphViewer` 增加窗口级 `keydown` 监听：
  - 仅在 `Ctrl+Z` / `Meta+Z`
  - 且不在输入框、文本域、可编辑元素中时触发
  - 调用既有 `handleUndoDraft()`
- 更新右侧批量编辑区域文案，明确说明“点击或框选会持续追加，清空选择用于重置”。
- 在 `GraphViewer.test.tsx` 中补充：
  - `Ctrl+Z` 撤回测试
  - 追加式选区相关测试入口或最小验证覆盖

### 影响范围

- `webapp/src/components/GraphViewer.tsx`
- `webapp/src/components/GraphViewer.test.tsx`
- 可能涉及少量提示文案

## 预期结果

网页 graph 编辑器在编辑模式下将统一表现为追加式选区：点击、框选、`Ctrl/Shift` 多选都不会冲掉已有选区；本地草稿撤回支持 `Ctrl+Z`，且不会干扰输入框内的原生文本撤销行为。本次改动仅作用于前端交互层，不改变 `triggerSource/core` 语义与现有保存协议。
