# 智能眼镜连线显示操作增加站立条件

生成时间：2026-04-27 08:25:45
文件名：2026-04-27_082545_智能眼镜连线显示操作增加站立条件.md

## 任务背景
当前智能眼镜已经承接 quick-link visualize 的连线显示与操作入口，但用户要求进一步收紧“连线显示操作”的执行门槛：添加或移除显示对象时，除了佩戴智能眼镜且主手为空，还必须处于站立状态。与此同时，需要避免误伤现有 `Shift+B` 清空显示对象列表的交互。

## 方案详情

### 现状分析
- `SmartGlassesAccessSupport` 已拆分“显示权限”和“操作权限”：
  - 显示：只要求佩戴智能眼镜。
  - 操作：要求佩戴智能眼镜且主手为空。
- `QuickLinkNetworkClientHandlerSupport` 的 visualize 左键添加、右键移除共用同一个“可操作”门槛。
- 服务端 `QuickLinkNetworkServerHandlerSupport` 对“添加显示对象”请求也复用了当前的统一操作判定。
- 现有 tooltip 只说明“佩戴且主手为空”，尚未体现“站立”要求。

### 技术方案
- 不直接修改现有 `canOperateQuickLinkVisualization(...)`，避免把潜行 `Shift+B` 清空入口一起禁用。
- 在 `SmartGlassesAccessSupport` 新增更细粒度的“允许修改显示对象”判定：
  - 佩戴智能眼镜；
  - 主手为空；
  - 当前非潜行，即站立状态。
- 客户端 visualize 左键添加、右键移除改为使用该新判定。
- 服务端“添加显示对象”请求的验权同步改为使用该新判定，避免客户端绕过门槛发包。
- 中英文 tooltip 同步改写为“站立添加/移除，Shift+B 清空”。
- 补最小自动化测试覆盖该门槛逻辑。

### 影响范围
- 智能眼镜交互门槛判定：`SmartGlassesAccessSupport`
- quick-link visualize 客户端交互：`QuickLinkNetworkClientHandlerSupport`
- quick-link visualize 服务端验权：`QuickLinkNetworkServerHandlerSupport`
- 中英文文案：`zh_cn.json`、`en_us.json`
- 判定回归测试：`src/test/java/**`

## 原子步骤清单

### 步骤 1：新增站立修改门槛判定
- **操作对象**：`SmartGlassesAccessSupport`
- **具体动作**：新增“允许修改显示对象”的细粒度方法，并补齐中文注释
- **预期结果**：可单独表达“站立 + 戴眼镜 + 主手空”的 visualize 修改门槛
- **关键里程碑**：是

### 步骤 2：调整客户端 visualize 添加/移除入口
- **操作对象**：`QuickLinkNetworkClientHandlerSupport`
- **具体动作**：让左键添加、右键移除使用新的站立判定，保留 `Shift+B` 清空语义
- **预期结果**：只有站立时才能添加或移除显示对象
- **关键里程碑**：是

### 步骤 3：同步服务端添加显示对象验权
- **操作对象**：`QuickLinkNetworkServerHandlerSupport`
- **具体动作**：把 visualize 添加请求的服务端权限校验切换到新判定
- **预期结果**：客户端与服务端门槛一致
- **关键里程碑**：否

### 步骤 4：同步中英文 tooltip
- **操作对象**：`zh_cn.json`、`en_us.json`
- **具体动作**：更新智能眼镜与 visualize 文案，明确“站立添加/移除，Shift+B 清空”
- **预期结果**：交互规则对用户可见且与实现一致
- **关键里程碑**：否

### 步骤 5：补最小判定测试
- **操作对象**：`src/test/java/**`
- **具体动作**：补充站立/潜行/显示权限分离的门槛测试
- **预期结果**：该门槛后续变更有自动化保护
- **关键里程碑**：是

## 预期结果
智能眼镜连线显示的“添加/移除显示对象”操作将被收紧为“站立 + 佩戴眼镜 + 主手为空”才能执行；纯显示权限仍只要求佩戴眼镜；`Shift+B` 清空显示对象列表继续可用；相关 tooltip 与自动化测试同步更新。
