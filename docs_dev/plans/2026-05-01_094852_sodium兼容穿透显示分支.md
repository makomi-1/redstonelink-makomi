# Sodium兼容穿透显示分支

## 任务背景

当前客户端渲染兼容分支只在检测到 `Iris` 时才启用，因此单独加载 `Sodium` 的环境仍会继续走普通渲染路径，导致穿透显示相关的箭头、连线和描边问题没有被兼容修正。需要在不影响 vanilla 路径的前提下，把这部分兼容范围扩展到 `Sodium-only` 环境。

## 方案详情

### 现状分析

- 当前兼容判定入口集中在 `IrisRenderCompatSupport.shouldUseCompatibilityBranch()`。
- 该入口目前只检查 `FabricLoader.isModLoaded("iris")`。
- quick-link 描边/预览/连线与定向箭头的兼容路径都统一依赖这一判断。
- 因此只要没有加载 `Iris`，即使加载了 `Sodium`，也不会进入兼容分支。

### 技术方案

1. 保留现有兼容渲染实现，不改算法、不改线段构造方式。
2. 仅扩展兼容判定条件：
   - 只要加载了 `iris` 或 `sodium`，就启用兼容分支。
3. 同步修正 `IrisRenderCompatSupport` 的类注释和方法注释，使其准确描述当前职责。
4. 跑全量自动化测试回归，确认这次判断扩展不会影响其他客户端或服务端逻辑。

### 影响范围

- `IrisRenderCompatSupport`
- 所有依赖 `shouldUseCompatibilityBranch()` 的客户端渲染入口（不改调用代码，只改变命中结果）

## 原子步骤清单

### 步骤 1：扩展兼容判定
- **操作对象**：`src/client/java/com/makomi/client/render/IrisRenderCompatSupport.java`
- **具体动作**：把兼容判定从 `iris` 扩展为 `iris || sodium`，并同步修正文档注释
- **预期结果**：单独加载 `Sodium` 时也会命中当前穿透显示兼容分支
- **关键里程碑**：是

### 步骤 2：执行全量回归
- **操作对象**：Gradle 测试任务
- **具体动作**：执行 `.\gradlew.bat compileJava compileClientJava test testIntegration testClient testSlow --no-daemon`
- **预期结果**：兼容判定扩展不引入编译或测试回归
- **关键里程碑**：是

## 预期结果

完成后，`Sodium-only` 环境会和 `Iris` 环境一样进入现有兼容渲染分支，从而让穿透显示相关的箭头、连线和描边也获得相同的兼容修正；未加载 `Sodium/Iris` 的普通环境保持不变。
