# suite支持功能case新档隔离批跑

生成时间：2026-03-23 20:34:18

## 任务背景

当前 `tools/bench/run-bench-suite.ps1` 已支持“每 case 一个新档”的 dedicated server 编排流程，但它只会调用 `run-bench.ps1 -Action RunCase`，因此只能批跑性能矩阵，不能对功能矩阵执行同样的新档隔离批跑。

本轮目标是在不复制 suite 逻辑、不新增第二套脚本的前提下，让 suite 同时支持：

1. 性能 case：`RunCase`
2. 功能 case：`RunFunctionalCase`

并保持每个 case 仍走：

复制模板世界 -> 切 `level-name` -> 启服 -> 跑单 case -> 停服 -> 进入下一个 case

## 方案详情

### 现状分析

- `run-bench-suite.ps1` 当前通过 `CaseIds + MatrixPath` 解析待跑 case。
- suite 在调用子脚本时将 `Action` 硬编码为 `RunCase`。
- suite 结果摘要当前偏向性能结果，主要读取 `spark` 相关字段；而功能结果的关键字段是 `passed/checks/failedChecks`。
- 功能 case 已有独立矩阵 `tools/bench/functional-matrix.json`，并已有 `RunFunctionalCase` 能落统一 JSON 结果。

### 技术方案

1. 为 suite 新增显式参数 `-BenchAction`
   - 可选值：`RunCase`、`RunFunctionalCase`
   - 默认保持 `RunCase`

2. 透传子动作到 `run-bench.ps1`
   - 把 suite 中原先写死的 `Action = "RunCase"` 改为 `Action = $BenchAction`
   - 其他参数继续复用现有逻辑

3. 泛化结果摘要
   - 保留通用字段：
     - `caseId`
     - `resultPath`
   - 性能模式继续补充：
     - `profilerUrl`
     - `healthUrl`
   - 功能模式新增：
     - `passed`
     - `checksCount`
     - `failedChecksCount`

4. 更新使用说明
   - 增加功能 suite 批跑示例
   - 明确：
     - `-BenchAction RunFunctionalCase`
     - `-MatrixPath ./tools/bench/functional-matrix.json`
   - 说明功能 suite 不依赖 spark

### 影响范围

- `tools/bench/run-bench-suite.ps1`
- `docs_dev/使用说明.md`
