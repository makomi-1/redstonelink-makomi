# 远近外显面向与IO快照调整

生成时间：2026-03-24 11:59:45
文件名：2026-03-24_115945_远近外显面向与IO快照调整.md

## 任务背景

本次调整聚焦客户端远外显与近外显两条显示链路：
- 远外显渲染器当前命名过窄，实际已复用于多类节点。
- 核心粉（含透明变种）在游戏实测中，侧面远外显未与顶/底面保持一致，`FACE_OFFSET` 表现存在分裂。
- 按钮、拉杆需要统一改为面向显示。
- 近外显需要在现有快照体系基础上补充最终 IO 信息，避免客户端本地临时推导。

## 方案详情

### 现状分析

- [`src/client/java/com/makomi/client/render/LinkCoreShortCodeRenderer.java`](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/LinkCoreShortCodeRenderer.java) 当前同时承担 core、triggerSource 多类节点的远外显渲染，类名已不准确。
- 远外显当前通过 `SUPPORT_FACE` 和 `FACE + FACING` 推导朝外法线，但顶/底/侧面仍共用一条简化渲染路径，导致侧面表现与顶底面不一致。
- [`src/client/java/com/makomi/client/render/LinkSerialHudOverlayRenderer.java`](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/LinkSerialHudOverlayRenderer.java) 已有“当前连接”懒加载缓存机制，可复用同样模式承载运行态快照。
- [`src/main/java/com/makomi/data/NodeSnapshotQueryService.java`](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/NodeSnapshotQueryService.java) 与 [`src/main/java/com/makomi/data/NodeRuntimeSnapshot.java`](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/NodeRuntimeSnapshot.java) 已提供稳定运行态读模型，可直接服务 HUD。

### 技术方案

1. 将远外显渲染器重命名为更通用的 `LinkNodeFarOverlayRenderer`，仅修正命名与注册引用，不扩大职责。
2. 在远外显渲染器中拆分“贴附节点外法线解析”和“文本板朝向/位移应用”两个步骤，统一使用同一外法线驱动按钮、拉杆、核心粉的面向与位移计算，并将贴面位移统一收敛到半格。
3. 参考“当前连接”网络通路，在 [`src/main/java/com/makomi/network/PairingNetwork.java`](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetwork.java) 新增运行态快照请求/回包，实现近外显按需拉取最终 IO 数据。
4. 在 HUD 中复用运行态快照缓存，增加最终输入/输出文本行，并保持 `triggerSource/core` 语义输出。

### 影响范围

- 客户端渲染：远外显类名、远外显矩阵逻辑、近外显文本内容
- 客户端入口：渲染器注册与新增快照接收
- 网络层：运行态快照请求/回包 payload
- 服务端读模型：复用现有运行态查询服务
- 本地化文案：新增近外显 IO 行中英文键值
