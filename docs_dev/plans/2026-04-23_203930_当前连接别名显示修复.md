# 当前连接别名显示修复

## 任务背景

GUI tooltip 与近外显 HUD 的“当前连接”只显示 `#序号`，没有显示目标节点别名；物品 tooltip 可以正常显示别名。此前提交 `bba1b97aa6f0536befaf5f38ee9a822cfdce6387` 已接入展示文本链路，但运行结果失败，需修复实际丢失点。

## 方案详情

### 现状分析

服务端 `NodeSnapshotQueryService.queryLinks(...)` 在隐私过滤阶段会生成 `visibleTargetDisplayTexts`，但随后 `withRevisions(...)` 重建 `NodeLinksSnapshot` 时只传入可见目标列表与 revision，未保留展示文本，导致 GUI 打开包与 HUD 当前连接回包最终退化为默认 `#序号`。物品 tooltip 走 `buildItemSnapshotLinks(...)`，未经过该覆盖点，因此不受影响。

### 技术方案

修复 `withRevisions(...)`，在补充 `graphRevision/sourceRevision/coreRevision` 时继续传入 `normalizedSnapshot.visibleTargetDisplayTexts()`。补充定向单元测试，锁定“补 revision 不丢展示文本”的契约。

### 影响范围

- 服务端当前连接快照查询链路。
- pairing GUI 打开包中的当前连接展示文本。
- 近外显 HUD 当前连接快照回包中的展示文本。
- 不改变连接方向、隐私过滤、网络协议字段、物品 tooltip 逻辑。

## 原子步骤清单

### 步骤 1：保留展示文本
- **操作对象**：`NodeSnapshotQueryService.withRevisions(...)`
- **具体动作**：重建 `NodeLinksSnapshot` 时传入原快照中的 `visibleTargetDisplayTexts`
- **预期结果**：补 revision 不再覆盖别名展示文本
- **关键里程碑**：是

### 步骤 2：补充回归测试
- **操作对象**：`NodeSnapshotQueryServiceTest`
- **具体动作**：添加覆盖 `withRevisions(...)` 的定向测试
- **预期结果**：展示文本在 revision 补全后仍为 `别名(#序号)`
- **关键里程碑**：是

### 步骤 3：执行验证
- **操作对象**：Gradle 测试任务
- **具体动作**：先跑定向测试，再按项目规则跑全标签回归
- **预期结果**：相关测试通过且无全局回归失败
- **关键里程碑**：是

## 预期结果

GUI tooltip 与近外显 HUD 的“当前连接”会和物品 tooltip 一样显示 `别名(#序号)`；没有别名时仍回退到 `#序号`。

## 语义对齐说明

本次修复只保留既有 `triggerSource/core` 当前连接展示文本，不改变 `LinkNodeType.TRIGGER_SOURCE/CORE` 映射，不新增旧术语输出，不引入 `com.makomi.api.v1.*` 依赖。残余风险：已打开 GUI 若目标别名在界面打开后被外部修改，仍可能依赖重新打开或后续刷新机制更新。
