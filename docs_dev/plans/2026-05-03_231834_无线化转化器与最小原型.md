# 无线化转化器与最小原型

生成时间：2026-05-03 23:18:34
文件名：2026-05-03_231834_无线化转化器与最小原型.md

## 任务背景

本轮目标是在当前工作区内新增一套“无线化原版件”的最小可用闭环。
用户要求新增一个不承载节点身份的“无线化转化器”，用于把原版红石/发光方块转成携带节点身份的无线化方块。
本轮最小原型包含：
- 无线化转化器
- 无线化拉杆
- 无线化石按钮
- 无线化石压力板
- 无线化活塞
- 无线化红石灯

这些无线化方块必须统一使用 `triggerSource/core` 语义：
- 拉杆、石按钮、石压力板属于 `triggerSource`
- 活塞、红石灯属于 `core`
- 方向固定为 `triggerSource -> core`

同时保留原版信号特征：
- `triggerSource` 只转接原版信号，不再给邻居提供红石输出
- `core` 只响应连接信号并执行原版受电表现，不再依赖原版邻居红石输入

## 方案详情

### 现状分析

当前仓库已经具备完整的节点身份、序号持久化、配对与跨区块联动基础设施：
- `PairableBlockItem` + `LinkItemData` 已支持“物品序号 -> 放置继承 -> 掉落回写”
- `TriggerSourceBlockEntity` / `SyncReplaySourceBlockEntity` 已支持 triggerSource 派发与 sync 回放
- `ActivatableTargetBlockEntity` 已支持 core 的 toggle/pulse/sync 三类接收语义
- `LinkNodeLifecycleDispatchEvents` 已负责加载后 blockstate 与输入状态自愈

缺口主要在三处：
1. 当前没有“原版行为外壳 + 节点身份”的无线化原型方块
2. 当前没有专用转化器，也没有只对专用机器生效的炉式转换链路
3. 现有 `link_sync_lever` 等成品不完全符合“无线化原版件”的命名和行为边界，需新建而非复用

### 技术方案

#### 1. 无线化 triggerSource/core 公共基类

新增两组公共基类：
- 无线化 triggerSource 基类：
  - 负责 serial 放置/掉落/卸载继承
  - 屏蔽原版对邻居的红石输出
  - 将原版自身状态变化通过 `forwardLinkedSignal(...)` 转接给已连接 `core`
- 无线化 core 基类：
  - 负责 serial 放置/掉落/卸载继承
  - 屏蔽原版从邻居读取红石输入
  - 在 `ActivatableTargetBlockEntity` 激活态变化时执行原版受电表现

这样可把“节点语义”与“原版表现”解耦，后续扩展更多无线化原版件时复用成本最低。

#### 2. 无线化转化器

采用“专用 recipe type + 炉式容器”的方案：
- 方块层继承 `AbstractFurnaceBlock`
- 方块实体继承 `AbstractFurnaceBlockEntity`
- 菜单层继承 `AbstractFurnaceMenu`
- 客户端屏幕复用炉子界面纹理
- 自定义 `RecipeType` 与 `RecipeSerializer`

这样能同时满足：
- 漏斗/燃料/输出槽/进度条全部复用原版炉逻辑
- 普通熔炉不能越权产出无线化方块
- 转化器燃料可单独限制为 `redstone_link_component`

#### 3. 最小原型方块

##### triggerSource 侧
- 无线化拉杆
  - 继承 `LeverBlock`
  - 保留原版开关手感和 `POWERED` 外显
  - 切换后把当前 `0/15` 强度同步转发到连接目标
- 无线化石按钮
  - 继承 `ButtonBlock`
  - 保留原版脉冲时长与按下/释放特征
  - 按下时转发 `15`，释放时转发 `0`
- 无线化石压力板
  - 继承 `PressurePlateBlock`
  - 保留原版受压触发与释放逻辑
  - 通过覆写 `entityInside/tick` 后比对状态变化，转发 `15/0`

三者统一走同步 triggerSource 语义，只转接原版波形，不向邻居输出红石。

##### core 侧
- 无线化红石灯
  - 继承 `RedstoneLampBlock`
  - 忽略原版邻居红石输入
  - 由 `core` 激活态直接控制 `LIT`
- 无线化活塞
  - 继承 `PistonBaseBlock`
  - 忽略原版 `neighborChanged/onPlace` 自动伸缩
  - 在 `core` 激活态变化时复用原版活塞移动逻辑
  - 由于原版 `triggerEvent` 会再次校验邻居红石，需在子类内复制并改写对应判断为“读取当前无线化核心激活态”

#### 4. 资源与命名

统一命名为“无线化的 + 原名称”，注册名使用英文风格：
- `wireless_converter`
- `wireless_lever`
- `wireless_stone_button`
- `wireless_stone_pressure_plate`
- `wireless_piston`
- `wireless_redstone_lamp`

显示名称：

- 无线化的拉杆
- 无线化的石按钮
- 无线化的石压力板
- 无线化的活塞
- 无线化的红石灯

贴图与模型全部优先复用原版资源，不修改 `textures/**`。

## 预期结果

完成后，项目中将新增一个可通过漏斗输入输出的“无线化转化器”，并形成以下最小闭环：
- 原版拉杆、石按钮、石压力板可被转化为无线化 triggerSource
- 原版活塞、红石灯可被转化为无线化 core
- 无线化 triggerSource 不再直接向邻居输出红石，而是将原版信号特征同步转接给已连接的 core
- 无线化 core 不再依赖邻居红石输入，而是用连接信号驱动原版表现

## 语义对齐说明

- 命名是否仅使用 `triggerSource/core`：是
- 输入/输出结构是否保持方向一致：是，固定为 `triggerSource -> core`
- 文案与注释是否无旧术语泄漏：新增部分要求是；与历史类交互处仅保留兼容语境
- 与 `LinkNodeType` 映射是否一一对应：是，`triggerSource=TRIGGER_SOURCE`，`core=CORE`
- 兼容层是否仅“读旧写新”：是
- 残余风险：
  - 无线化活塞需复制部分原版 `triggerEvent` 逻辑，后续版本升级时要同步核对原版实现差异
  - 专用 recipe type 接入若遗漏客户端菜单/配方书边界，可能需要一轮编译修正
