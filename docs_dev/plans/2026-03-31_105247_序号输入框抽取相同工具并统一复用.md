# 序号输入框抽取相同工具并统一复用

生成时间：2026-03-31 10:52:47
文件名：2026-03-31_105247_序号输入框抽取相同工具并统一复用.md

## 任务背景

当前客户端存在三套与序号输入相关的 GUI：

- 配对界面：`AbstractMultiPairingScreen`
- 快速连接工具：`QuickLinkToolScreen`
- 状态面板：`StatePanelToolScreen`

三者都涉及序号文本输入、非法 token 提示、窗口变化后的控件重建，以及不同程度的布局适配。

本次方案目标是一次性解决以下问题：

- 明确 GUI 打开后的布局变化属于纯客户端行为，不引入额外服务端响应链路
- 抽取三处重复的序号输入语法工具，统一规范化与校验行为
- 为配对界面与快速连接工具补齐响应式布局能力
- 为三类 GUI 统一补齐本地草稿恢复，避免窗口变化导致未提交输入丢失
- 保持现有 `AbstractMultiPairingScreen` 的 pairing 领域边界，不抽成覆盖全部 GUI 的总基类

## 方案详情

### 现状分析

1. `QuickLink` 与 `StatePanel` 首次打开 GUI 时依赖服务端下发初始 payload，但布局变化本身不需要服务端参与。
2. 三处 GUI 都存在序号输入语法处理，但实现路径不统一：
   - 配对界面自行做多行折叠、token 校验
   - `QuickLink` 直接调用 `SerialParseUtil`
   - `StatePanel` 也直接调用 `SerialParseUtil`
3. `StatePanel` 已具备较完整的纯客户端响应式布局与输入回填能力。
4. `QuickLink` 与配对界面仍以固定几何为主，缺少统一的本地草稿恢复。
5. 现有 `AbstractMultiPairingScreen` 已是合理的领域基类，但不适合作为所有序号类 GUI 的总基类。

### 技术方案

本次采用“通用 support + 保留领域基类”的组合式方案：

1. 新增 `SerialInputSyntaxSupport`
   - 统一处理序号文本规范化
   - 统一处理多行折叠为 `/`
   - 统一处理非法 token 收集与提示参数
   - 统一处理目标列表回显文本生成入口

2. 新增 `CenteredFormLayoutSupport`
   - 为居中表单型 GUI 提供纯函数布局计算
   - 让配对界面与 `QuickLink` 具备与 `StatePanel` 一致的窄屏收敛思路
   - 支持窗口变化时只依赖客户端尺寸重算，不触发服务端 reopen/resync

3. 保留 `StatePanelToolScreen` 的独立布局模型
   - 不把列表面板、列布局、按钮矩阵并入通用基类
   - 仅复用输入语法 support 和草稿恢复思路

4. 为三处 GUI 增加本地草稿恢复
   - `AbstractMultiPairingScreen`：恢复当前多行输入
   - `QuickLinkToolScreen`：恢复当前输入和缓存类型按钮状态
   - `StatePanelToolScreen`：保留现有输入恢复并整理为统一模式

5. 补齐客户端测试
   - 新增输入语法 support 测试
   - 新增 `QuickLink` / pairing 布局测试
   - 保留并扩展 `StatePanel` 布局测试作为回归门禁

### 影响范围

- `src/client/java/com/makomi/client/screen/QuickLinkToolScreen.java`
- `src/client/java/com/makomi/client/screen/StatePanelToolScreen.java`
- 新增客户端 support 类
- `src/test/java/com/makomi/client/screen/**`

## 原子步骤清单

### 步骤 1：抽取序号输入语法 support
- **操作对象**：client screen support 层、三类 GUI
- **具体动作**：提取输入规范化、非法 token 收集、回显文本辅助逻辑
- **预期结果**：三类 GUI 的序号输入行为统一
- **关键里程碑**：是

### 步骤 2：抽取居中表单响应式布局 support
- **操作对象**：`AbstractMultiPairingScreen`、`QuickLinkToolScreen`
- **具体动作**：将固定几何换为纯函数布局解析，支持窄屏收敛与居中布局
- **预期结果**：配对界面与 `QuickLink` 在窗口变化时布局稳定
- **关键里程碑**：是

### 步骤 3：补齐本地草稿恢复
- **操作对象**：三类 GUI
- **具体动作**：在客户端 screen 生命周期内保存并回填未提交输入
- **预期结果**：窗口变化或 `init` 重建后不丢本地编辑内容
- **关键里程碑**：是

### 步骤 4：补齐客户端测试
- **操作对象**：client screen test
- **具体动作**：新增语法 support 测试与布局测试
- **预期结果**：输入规则与响应式布局具备回归门禁
- **关键里程碑**：否

## 预期结果

- GUI 布局变化完全由客户端本地处理，不需要额外服务端 reopen/resync
- 三类 GUI 的序号输入规则统一，后续维护只改一处
- 配对界面与快速连接工具具备稳定的响应式布局能力
- 三类 GUI 的未提交本地草稿在窗口变化后可恢复
- 保持 `AbstractMultiPairingScreen` 的 pairing 专属职责，不引入臃肿总基类
