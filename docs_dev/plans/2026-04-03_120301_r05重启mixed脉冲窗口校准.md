# r05重启mixed脉冲窗口校准

生成时间：2026-04-03 12:03:01
文件名：2026-04-03_120301_r05重启mixed脉冲窗口校准.md

## 任务背景
`r05` 改成按实现设计断言 `sync -> pulse -> toggle -> none` 后，实跑 dedicated suite 表明：`x25` 准备阶段通过，但 `r05` 在移除 `sync` 后立即观测到的是 `toggle`，而不是 `pulse`。结果 JSON 显示 `pulse` 在 verify 阶段前已经过期，说明当前 suite 的 `server.pulseDurationTicks=40` 仍不足以跨过 prepare -> restart -> verify 的整段时间。

## 方案详情

### 现状分析
- 运行时实现允许 `core` 持久化 `pulse/toggle` 并发桶；若 `pulse` 尚未过期，重启后应继续参与仲裁。
- 当前 restart suite 已尝试用更长 `pulseDurationTicks` 保留 `pulse` 观测窗口，但 40 tick 只够覆盖短暂重启，不够覆盖当前 dedicated suite 的整段编排开销。
- `r05` 当前 `pulseExpiryWaitTicks=45` 是围绕旧的 `pulseDurationTicks` 设置的；若只拉长 `pulseDurationTicks` 而不同步拉长到期等待，后续 `toggle` 断言会重新落在 `pulse` 仍未过期的区间。

### 技术方案
- 将 `restart-mixed-replay` suite 中的 `server.pulseDurationTicks` 进一步提高到能够覆盖当前 restart 编排窗口的保守值。
- 同步拉长 `r05` 的 `pulseExpiryWaitTicks`，保证：
  - 移除 `sync` 后仍能观测到 `pulse`
  - 中段检查仍处于 `pulse` 窗口内
  - 到期检查时已稳定回落到 `toggle`
- 不改运行时实现，不改 `r05` 的稳态断言结构，只调整场景参数。

### 影响范围
- `tools/bench/suites/restart-mixed-replay.json`
- `tools/bench/cases/functional/r05/restart_mixed_replay_redstone_verify.json`

- **预期结果**：verify 阶段移除 `sync` 后，`pulse` 仍有剩余有效期可观测
