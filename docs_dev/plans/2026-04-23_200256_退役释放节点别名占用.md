# 退役释放节点别名占用

生成时间：2026-04-23 20:02:56
文件名：2026-04-23_200256_退役释放节点别名占用.md

## 任务背景

节点退役后，`type + serial` 会进入退役集合并清理连接、跨区块白名单、当前连接隐私与写保护，但节点别名仍保留在 `NodeAliasSavedData` 中，导致原别名继续占用，后续无法分配给其它节点。

## 方案详情

### 现状分析

- 退役统一入口为 `LinkRetireCoordinator.retireAndSyncWhitelist(...)`，所有命令退役、创造破坏、物品销毁与待退役补偿最终都会走该入口。
- `NodeAliasSavedData` 已提供 `remove(type, serial)`，可同时删除正向别名与反向别名索引。
- 当前缺口是退役统一入口未调用该删除能力。

### 技术方案

- 在 `LinkRetireCoordinator.retireAndSyncWhitelist(...)` 中补充别名清理。
- 仅当 `NodeAliasSavedData.remove(...)` 确实移除别名时，调用 `NodeAliasServerSupport.syncDisplaysAfterAliasChanged(...)` 刷新在线节点与玩家物品展示缓存。
- 补充单元测试覆盖“退役后别名反查为空、同名别名可被其它节点重新占用”。

### 影响范围

- `src/main/java/com/makomi/data/LinkRetireCoordinator.java`
- `src/test/java/com/makomi/data/LinkRetireCoordinatorTest.java`

## 预期结果

节点退役会自动释放同 `type + serial` 的别名占用；后续其它节点可立即复用同名别名，不改变已有 `triggerSource/core` 方向语义、别名校验规则和退役序号治理规则。

## 语义对齐说明

- 命名保持 `triggerSource/core`，不新增旧术语输出。
- 输入/输出结构不变，只补退役副作用。
- 与 `LinkNodeType.TRIGGER_SOURCE/CORE` 映射保持一一对应。
- 不新增 `com.makomi.api.v1.*` 依赖。
- 兼容边界无变化；退役序号仍不可复用，释放的是别名占用。
