# triggerSource加载期静默重采样回归修复

生成时间：2026-03-23 15:29:24
文件名：2026-03-23_152924_triggerSource加载期静默重采样回归修复.md

## 任务背景

在“输入器跨重启状态主修复”之后，测试中出现新的加载回归：

1. 新地图挂载输入器后退出重进，客户端加载卡在 100%
2. 旧存档即使没有用过输入器，也可能在重进时卡在 100%

已确认这是刚刚改动引入的回归，而不是单纯的旧存档兼容问题。

## 方案详情

### 现状分析

- 当前 `TriggerSourceInputStateResyncService` 直接在 `ServerChunkEvents.CHUNK_LOAD` 回调里遍历区块内所有 `triggerSource emitter`
- 遍历后立即调用 `resyncPoweredStateFromCurrentInputsWithoutTrigger(...)`
- 该静默重采样内部仍可能执行 `level.setBlock(..., Block.UPDATE_ALL)`，从而在区块加载关键路径内触发邻居更新和额外状态传播
- 由于该服务对所有 emitter 生效，而不是只对曾被输入器驱动过的节点生效，所以旧存档同样会命中这条路径

### 技术方案

将 `triggerSource` 静默重采样从“直接在 `CHUNK_LOAD` 内执行”改成“两段式”：

1. `CHUNK_LOAD` 时只记录待处理区块任务，不直接修改世界状态
2. 在下一次服务端 tick 再消费队列，并对仍在线的区块做静默重采样

补充保护：

1. 使用服务器级内存队列，按 `server + dimension + chunkPos` 去重
2. 在 `SERVER_STOPPING/SERVER_STOPPED` 清理队列，避免停服边界残留
3. 若区块在消费时已不在线，则直接跳过

### 影响范围

- `src/main/java/com/makomi/data/TriggerSourceInputStateResyncService.java`
- 若需要配套注册钩子，则涉及 `src/main/java/com/makomi/RedstoneLink.java`
- 回归验证会覆盖现有输入器相关测试与全标签测试

## 原子步骤清单

### 步骤 1：改造加载期重采样服务
- **操作对象**：`TriggerSourceInputStateResyncService`
- **具体动作**：将 `CHUNK_LOAD` 直接重采样改为“入队后下一 tick 消费”
- **预期结果**：避免在区块加载关键路径中直接 `setBlock`
- **关键里程碑**：是

### 步骤 2：补充生命周期清理
- **操作对象**：`TriggerSourceInputStateResyncService`
- **具体动作**：增加停服阶段的队列清理与消费时在线校验
- **预期结果**：避免跨阶段残留任务或无效重采样
- **关键里程碑**：否

- **操作对象**：Gradle 测试任务

- **关键里程碑**：是
