# P26双侧最小覆盖过滤压测

生成时间：2026-04-11 13:45:00
文件名：2026-04-11_134500_P26双侧最小覆盖过滤压测.md

## 任务背景
基于现有 `sync 1024 -> 1024` 重压基线，新增一个同时覆盖 `triggerSource/core` 双侧过滤器的正式压测用例。用户要求过滤器采用节点集过滤，使用最少过滤器完成空间覆盖；`send/core` 节点集相位差为 `0`，同类过滤器节点集保持一致，并最终跑通带外部客户端自动启动、自动进服、自动传送观察位的实际验证。

## 方案详情

### 现状分析
- 现有正式重压基线是 `P18`，负责 `1024 -> 1024` 的 `banded16` 规则化映射。
- 过滤器半径为 `8`，单个过滤器的有效覆盖范围是以过滤器方块为中心的 `17x17x17` 立方体。
- 当前 `RunCase` 会在性能 case 中先启动 `spark` 再执行 `drive.steps`，若把过滤器搭建写进 `drive.steps`，会把过滤器布置成本混入性能测量窗口，无法公平对比原始 `P18`。
- bench 已具备稳定的 `command_assert`/`wait_ticks` phase 执行器，可以直接复用于性能 case 的驱动前初始化。

### 技术方案
- 为 `RunCase` 增加一个可选的 `setupPhases` 执行阶段，执行时机放在放置/建链完成后、观察位传送与 `spark` 前。
- 复用现有功能 phase 执行器，避免引入新的 bench 配置语法。
- 新增 `P26` 用例，沿用 `P18` 的节点布局、建链方式与驱动模板。
- 在 `P26` 中新增 `8` 个过滤器：
  - `4` 个 send 过滤器覆盖 `triggerSource` 区域
  - `4` 个 receive 过滤器覆盖 `core` 区域
- 所有过滤器统一使用奇数序号节点集 `1/3/5/.../1023`，并通过 case 参数复用同一份表达式，实现 `send/core` 相位差 `0` 与同类过滤器一致。
- 过滤器方块放到节点平面上方两格，避免覆盖原有节点块；利用半径覆盖平面节点。
