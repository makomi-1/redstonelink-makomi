# 加载期校正异步化与非阻塞优化

生成时间：2026-03-23 16:46:47
文件名：2026-03-23_164647_加载期校正异步化与非阻塞优化.md

## 任务背景

前一轮为修复 `core` 模拟输入残留，在 `ActivatableTargetBlockEntity.clearRemoved()` 中加入了读档后静默 blockstate 校正。

实测发现这再次把 `setBlock(...)` 放回了地图加载关键路径，导致进图阶段出现阻塞式卡顿。

同时，现有 `TriggerSourceInputStateResyncService` 还存在两个可继续优化的点：

1. 仅延迟 1 tick 不代表区块一定已经稳定
2. `CHUNK_LOAD` 时对所有区块无差别入队，存在额外开销

## 方案详情

### 现状分析

- `ActivatableTargetBlockEntity.clearRemoved()` 当前会直接调用 `syncLoadedBlockStateIfNeeded()`
- `core` 子类中的该同步最终仍会执行 `level.setBlock(...)`
- 这类写世界动作即使是 `UPDATE_CLIENTS`，仍不应放在方块实体重新附着的加载关键路径里
- `TriggerSourceInputStateResyncService` 当前是“区块先入队，下一 tick 用 `getChunkNow` 消费”
- 当前 triggerSource 队列没有在入队阶段做预筛选，也没有在 chunk 暂时不可得时做非阻塞重试

### 技术方案

本轮做三点最小修复：

1. 撤掉 `clearRemoved()` 内的直接 blockstate 校正
   - `ActivatableTargetBlockEntity` 仅保留“是否存在待校正 drift”的运行态标记
   - 不再在方块实体生命周期回调里直接写世界

2. 新增 `core` 专用异步校正服务
   - 在 `CHUNK_LOAD` 时仅扫描并筛出“确实需要校正”的 `core`
   - 入队的是具体 block 位置，而不是整个区块
   - 在 `END_SERVER_TICK` 用 `getChunkNow(...)` 非阻塞获取 chunk
   - 若 chunk 暂时不可得，则按有限次数重试，不阻塞主线程

3. 优化 `TriggerSourceInputStateResyncService`
   - `CHUNK_LOAD` 时先预筛选，只有区块内实际存在可重采样 emitter 才入队
   - 消费阶段对 `getChunkNow(...) == null` 的任务做有限重试，而不是直接丢弃或阻塞等待

## 原子步骤清单

### 步骤 1：撤掉加载关键路径里的直接改块
- **操作对象**：`ActivatableTargetBlockEntity`
- **具体动作**：删除 `clearRemoved()` 内的同步改块，仅保留待校正标记与查询/消费入口
- **预期结果**：不再在方块实体重新附着时直接 `setBlock(...)`
- **关键里程碑**：是

### 步骤 2：实现 `core` 异步校正服务
- **操作对象**：新增服务类 + `RedstoneLink` 注册
- **具体动作**：按 block 位置入队、非阻塞消费、有限重试、仅处理 drift 的 `core`
- **预期结果**：`core` 外显校正在加载后异步完成，不阻塞主线程
- **关键里程碑**：是

### 步骤 3：优化 triggerSource 队列
- **操作对象**：`TriggerSourceInputStateResyncService`
- **具体动作**：补预筛选、有限重试与非阻塞消费
- **预期结果**：降低无效入队与“1 tick 未稳定就消费”的风险
- **关键里程碑**：否

### 步骤 4：补测试并回归
- **操作对象**：相关测试与 Gradle 任务
- **具体动作**：更新内部测试并执行定向测试、全标签回归
- **预期结果**：确认功能修复且未引入新的行为回归
- **关键里程碑**：是

## 预期结果

- 地图加载阶段不再因 `core` 读档校正而直接写世界导致阻塞
- `core` 与 `triggerSource` 的加载后校正都改为真正的异步、非阻塞消费
- `triggerSource/core` 术语、方向约束与 `LinkNodeType` 映射保持不变
