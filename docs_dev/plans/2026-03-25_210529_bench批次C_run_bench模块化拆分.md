## 任务背景

bench 批次 A 已完成 `case/template` 定义层整理，批次 B 已完成 datapack 公共函数与 suite 分层。当前剩余的主要体量问题集中在 [run-bench.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/run-bench.ps1)，该文件仍同时承担：

- matrix / template / case 解析
- RCON 收发
- 世界准备与 datapack 安装
- 放置节点与建链
- functional trace 断言
- spark 启停与活动采集
- 结果汇总与主入口调度

本轮目标是完成批次 C，把单 case 执行引擎收口为“主脚本壳 + lib 模块”结构，保持外部 CLI 与现有 bench 用法不变。

## 方案详情

### 现状分析

- `tools/bench/run-bench.ps1` 已超过 3000 行，单文件承担多类职责，继续扩展会直接拖累：
  - case 加法成本
  - debug 定位效率
  - suite 层复用与后续拆分
- 当前入口参数、执行动作与结果路径已经被：
  - `run-bench-suite.ps1`
  - `run-first-mandatory-suite.ps1`
  - `docs_dev/使用说明.md`
  共同依赖，因此本轮不改外部命令形态，只改内部组织。

### 技术方案

1. 新建 `tools/bench/lib/`，按职责拆出模块脚本并通过 dot-source 载入：
- `Bench.Matrix.ps1`
- `Bench.Rcon.ps1`
- `Bench.World.ps1`
- `Bench.PlaceAndLink.ps1`
- `Bench.FunctionalTrace.ps1`
- `Bench.PerfSpark.ps1`
- `Bench.Results.ps1`

2. 保留 `tools/bench/run-bench.ps1` 作为轻量入口壳，只负责：
- 参数定义
- 全局运行期变量
- 依赖模块载入
- `switch ($Action)` 主分发

3. 函数迁移遵循“职责成组迁出，不改行为语义”：
- matrix/template/case/defaults/serial 格式相关进入 `Bench.Matrix.ps1`
- socket / RCON / 响应解析进入 `Bench.Rcon.ps1`
- 世界准备、区块、时间推进、datapack 安装进入 `Bench.World.ps1`
- 放置、建链、serial 提取进入 `Bench.PlaceAndLink.ps1`
- functional phase、trace mount/read/latest、断言进入 `Bench.FunctionalTrace.ps1`
- spark activity 轮询、性能采集进入 `Bench.PerfSpark.ps1`
- 结果对象、summary、JSON 输出进入 `Bench.Results.ps1`

4. 主入口兼容要求：
- `-Action`
- `-CaseId`
- `-MatrixPath`
- `-SavePath`
- `-RconHost/-RconPort/-RconPassword`
- `-AsPlayer`
- `-SparkActivityPath`
- `-SparkActivityTimeoutMs`
- `-SparkActivityPollIntervalMs`
- `-SkipSpark`
- `-DryRun`
  均保持不变。

### 影响范围

- `tools/bench/run-bench.ps1`
- `tools/bench/lib/*.ps1`

### 语义对齐说明

- 命名是否仅使用 `triggerSource/core`：本轮不新增业务语义字段，命令与脚本仍沿用 bench 现有 case 定义；不引入旧术语新输出。
- 输入/输出结构是否保持方向一致：本轮仅重组脚本职责，不改变 `triggerSource -> core` 的业务方向。
- 文案与注释是否无旧术语泄漏：仅补充脚本职责注释，不新增对外业务文案。
- 与 `LinkNodeType` 映射是否一一对应：无业务映射改动。
- 兼容层是否仅“读旧写新”：本轮不涉及持久化兼容设计。
- 残余风险：若函数迁移时遗漏共享全局变量，可能导致运行期脚本找不到状态；通过 `List`、`PrintCase`、`smoke suite` 与 Gradle 测试兜底。
