# 首批必跑收敛修复

生成时间：2026-03-24 16:20:52
文件名：2026-03-24_162052_首批必跑收敛修复.md

## 任务背景
首批必跑 suite 在对齐服务器 mod 版本后仍稳定剩余 4 个失败项：
- `F02 link_lifecycle_add_remove_set_clear`
- `F04 input_activate_trace_command_alignment`
- `X04 restart_persist_toggle_prepare`
- `R02 restart_persist_toggle_verify`

现有失败已经可以收敛为三类问题：
1. `link add/remove` 仍只接受玩家命令源；
2. `trace_read_tick_assert` 在 pulse/tick window 场景下可能因 read limit 偏小裁掉关键窗口；
3. bench case 执行前没有统一确保 arena 区块已加载。

## 方案详情

### 现状分析
- `ModCommands` 中 `link add/remove` 仍直接检查 `source.getPlayer()`，与 `link set` 的 benchmark mode 兼容策略不一致。
- `tools/bench/run-bench.ps1` 的 `trace_read_tick_assert` 只按给定 limit 读一次；当读取时刻偏晚，旧样本窗口可能已经被滚出返回结果。
- `tools/bench/run-bench.ps1` 在构场与 serial 回读前没有统一 `forceload`，因此某些稍远 arena 会直接报 `That position is not loaded`。

### 技术方案
- 命令侧：
  - 让 `link add/remove` 复用 `allowPlayerSourceOrBenchmarkMode`；
  - 将单目标链路更新逻辑改为基于 `source.getLevel()` 工作；
  - 仅在存在玩家源时执行背包内链接快照同步。
- bench 执行侧：
  - 基于 case arena 统一执行 `forceload add`，保证构场、回读 serial、复用世界等步骤都在已加载区块内执行；
  - 为 `trace_read_tick_assert` 增加“检测窗口可能被截断时自动扩大 read limit 并重读”的逻辑。

### 影响范围
- `src/main/java/com/makomi/command/ModCommands.java`
- `tools/bench/run-bench.ps1`
- 如行为说明发生变化，再补 `docs_dev/使用说明.md`

## 原子步骤清单

### 步骤 1：修复 link add/remove 的 benchmark mode 兼容
- **操作对象**：`src/main/java/com/makomi/command/ModCommands.java`
- **具体动作**：将 `executeLinkAddWithTypeArg`、`executeLinkRemoveWithTypeArg` 改为允许 benchmark mode；让底层更新逻辑兼容空玩家。
- **预期结果**：`F02` 不再因 “This command can only be used by a player.” 失败。
- **关键里程碑**：是

### 步骤 2：增加 bench arena forceload
- **操作对象**：`tools/bench/run-bench.ps1`
- **具体动作**：新增 arena 区块范围解析与 `forceload` 辅助函数，并在 `RunCase`、`RunFunctionalCase` 中执行。
- **预期结果**：`X04/R02` 不再因未加载区块导致 serial 回读失败。
- **关键里程碑**：是

### 步骤 3：增强 trace_read_tick_assert 的补读能力
- **操作对象**：`tools/bench/run-bench.ps1`
- **具体动作**：在 tick window 断言前检查是否存在“起始窗口被裁掉”的特征，必要时自动扩大 `node trace read` 的 limit 到 mount capacity 以内并重读。
- **预期结果**：`F02/F04` 的 pulse/tick window 断言可覆盖真实关键窗口。
- **关键里程碑**：是

### 步骤 4：验证首批必跑
- **操作对象**：工作区构建产物、bench suite 结果目录
- **具体动作**：构建最新 mod，更新到 bench 服务器，重跑首批必跑 suite，并检查结果 JSON 与汇总。
- **预期结果**：4 个剩余失败项全部收敛。
- **关键里程碑**：是

## 预期结果
首批必跑 suite 全量通过，且 bench 在无人值守 benchmark mode 下不再依赖人工记忆额外的玩家上下文或临时扩大 trace limit。
