# 删除废弃api实现

生成时间：2026-03-26 12:34:58
文件名：2026-03-26_123458_删除废弃api实现.md

## 任务背景
当前仓库中的 `src/main/java/com/makomi/api/v1` 设计上已计划废弃，但代码与构建入口仍保留。静态扫描显示主业务链路已经切换到内部实现路径，`LinkerItem` 不再依赖 `RedstoneLinkApi`，现存 API 主要承担对外包装与旧语义映射职责。目标是在不引入额外设计变更的前提下，删除这套废弃 API 实现，并清理对应的构建残留。

## 方案详情

### 现状分析
- `com.makomi.api.v1.*` 当前未被主工程其余源码直接引用，主要为包内自引用。
- 旧 API 暴露 `BUTTON/CORE` 术语，与当前项目强制语义基线 `triggerSource/core` 不一致。
- `build.gradle` 仍保留 `testApiLegacy` 任务，但测试源码中已无 `api-legacy` 标签，现状更接近空壳验证入口。
- 删除该目录属于公开兼容层退役，不影响当前仓库内部主链路，但会移除外部依赖入口。

### 技术方案
- 直接删除 `src/main/java/com/makomi/api/v1/**` 目录下的废弃 API 源码，避免继续保留旧术语与对外桥接层。
- 同步删除 `build.gradle` 中仅服务于该兼容层的 `testApiLegacy` 任务，避免保留无实际价值的构建入口。
- 不改动其他业务代码、命令、配置、资源与语义主链路，确保范围最小。

### 影响范围
- `src/main/java/com/makomi/api/v1/**`
- `build.gradle`
- `.github/workflows/build.yml`
- `docs_dev/使用说明.md`
