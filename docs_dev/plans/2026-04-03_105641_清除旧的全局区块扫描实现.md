# 清除旧的全局区块扫描实现

生成时间：2026-04-03 10:56:41
文件名：2026-04-03_105641_清除旧的全局区块扫描实现.md

## 任务背景
节点生命周期调度主干已经迁移到 `LinkNodeLifecycleDispatchEvents` 的节点命中式 attach/detach 消费模型，但仓库中仍残留两份基于 `ServerChunkEvents.CHUNK_LOAD` 扫描区块方块实体的旧实现：`CoreBlockStateResyncService` 与 `TriggerSourceInputStateResyncService`。当前主入口未注册它们，属于死代码残留，需要清除并做对应生命周期游戏内回归。

## 方案详情

### 现状分析
- 现行生效路径：`RedstoneLink` 仅注册 `LinkNodeLifecycleDispatchEvents`，没有注册旧扫描服务。
- 旧实现特征：在 `CHUNK_LOAD` 回调中扫描整块方块实体，再做 `core`/`triggerSource` 加载校正。
- 风险面：保留旧实现会干扰阅读和后续维护，但删除它们不应改变当前运行语义。

### 技术方案
1. 删除未注册、未引用的旧扫描服务：
   - `src/main/java/com/makomi/data/CoreBlockStateResyncService.java`
   - `src/main/java/com/makomi/data/TriggerSourceInputStateResyncService.java`
2. 不修改现行 `LinkNodeLifecycleDispatchEvents` 生命周期主链。
3. 先跑 Gradle 全标签自动化，再按“先构建、再同步 server jar”的规则跑生命周期 dedicated server 回归。

### 影响范围
- `src/main/java/com/makomi/data/CoreBlockStateResyncService.java`
- `src/main/java/com/makomi/data/TriggerSourceInputStateResyncService.java`
- `docs_dev/reviews/` 审查文档

### 步骤 1：删除旧扫描实现
- **操作对象**：`CoreBlockStateResyncService`、`TriggerSourceInputStateResyncService`
- **具体动作**：删除两份遗留 `CHUNK_LOAD` 扫描服务
- **预期结果**：仓库不再保留旧的全局区块扫描实现
- **关键里程碑**：是

### 步骤 2：执行静态回归
- **操作对象**：Gradle 测试任务
- **具体动作**：运行 `.\gradlew.bat test testIntegration testClient testSlow --no-daemon`
- **预期结果**：确认删除后编译和自动化测试通过
- **关键里程碑**：是

- **操作对象**：bench dedicated server 生命周期回归
- **具体动作**：先构建并同步 server jar，再跑 `regression-lifecycle` 套件中与 reload replay / source attach replay 相关 case
- **预期结果**：确认现行节点命中式生命周期主链在游戏内仍正常
- **关键里程碑**：是
