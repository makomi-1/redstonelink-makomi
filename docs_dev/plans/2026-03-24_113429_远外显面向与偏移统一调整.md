# 远外显面向与偏移统一调整

生成时间：2026-03-24 11:34:29
文件名：2026-03-24_113429_远外显面向与偏移统一调整.md

## 任务背景

当前远外显文本框统一由客户端 `LinkCoreShortCodeRenderer` 渲染。

现状存在两类问题：

- 核心粉与透明核心粉虽然已按面法线显示，但法线位移过大，当前为 `0.80` 方块，导致文本框离薄层模型过远。
- 连接按钮与连接拉杆仍走“顶面上方固定显示”路径，没有按附着面法线显示。

本次需求要求：

- 核心粉（含透明变种）远外显文本框改为更贴面的位移
- 连接按钮与连接拉杆改为面向显示
- 上述几类统一改为 `1/2` 方块的法线位移

## 方案详情

### 现状分析

- 渲染入口集中在 `src/client/java/com/makomi/client/render/LinkCoreShortCodeRenderer.java`
- 当前仅 `LinkRedstoneDustCoreBlock.SUPPORT_FACE` 分支按面显示，其他节点统一顶显
- 核心粉当前偏移量为 `0.80D`
- 透明核心粉继承 `LinkRedstoneDustCoreBlock`，只需改渲染器的粉类分支即可同步覆盖
- `ButtonBlock` / `LeverBlock` 都继承 `FaceAttachedHorizontalDirectionalBlock`
- 经本地映射代码核实，`FaceAttachedHorizontalDirectionalBlock.getConnectedDirection(...)` 的语义为：
  - `FLOOR -> DOWN`
  - `CEILING -> UP`
  - `WALL -> FACING`
  即该方向表示“从方块指向支撑面”的方向，因此文本外法线应使用其反向

### 技术方案

在 `LinkCoreShortCodeRenderer` 内收口为统一的“外法线解析”逻辑：

1. 若方块状态带有 `LinkRedstoneDustCoreBlock.SUPPORT_FACE`，继续按核心粉语义解析外法线
2. 若方块状态带有 `FaceAttachedHorizontalDirectionalBlock.FACE/FACING`，按按钮/拉杆语义解析外法线
3. 若都不满足，则保持原有完整方块顶显逻辑

统一常量调整：

- 面向位移 `FACE_OFFSET` 调整为 `0.50D`
- 完整方块顶显高度 `BLOCK_TOP_TEXT_Y` 保持不变

### 影响范围

- `src/client/java/com/makomi/client/render/LinkCoreShortCodeRenderer.java`
- 方案文档

### 技术取舍

- 只改客户端渲染器，不改方块、方块实体、协议或贴图资源
- 不扩展到其他未点名节点，避免无关渲染行为变化
- 使用统一 helper 解析外法线，避免未来再为按钮、拉杆、薄层核心分别写分支
