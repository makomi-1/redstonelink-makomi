# 物品堆叠容器语义适配方案

生成时间：2026-03-29 10:10:40
文件名：2026-03-29_101040_物品堆叠容器语义适配方案.md

## 任务背景

当前可配对物品固定为 `stacksTo(1)`，玩家在原版物品栏中只能逐个搬运同类节点物品。  
本次不改配对 GUI、不改现有 `sendSetLinksCommand` 链路，也不引入原版真实 `count` 堆叠；只在现有单件语义之上补一层“有序序号聚合栈”。  
第一层聚合交互已落地后，遗留问题集中在“聚合数量角标”。无 mixin 的 HUD/Screen 外围补绘在实机中仍出现图层落后和快捷物品栏缺失，因此需要把显示接回原版槽位渲染链。

## 方案详情

### 现状分析

- 现有核心假设仍是“一栈一号”，典型入口集中在 `LinkItemData.getSerial/setSerial`、放置取号、tooltip 展示与退役匹配。
- 原版真实堆叠不能直接复用，因为一个 `count` 栈无法表达多序号有序集合，也会冲掉现有单序号出入口。
- Minecraft 1.21.1 已为物品提供背包点击扩展点：`overrideStackedOnOther` 与 `overrideOtherStackedOnMe`；这足够覆盖第一层“物品级”聚合操作。
- 原版数量角标并不是在整帧末尾统一补画，而是在各自槽位/浮动物品渲染内部直接调用 `GuiGraphics.renderItemDecorations(...)`。
- 现有 `HudRenderCallback + ScreenEvents.afterRender` 外围补绘虽然可近似显示，但无法稳定复用原版的图层、深度和快捷物品栏渲染时机，实机仍会出现“数字压在贴图后面”和“底部快捷栏不显示”。

### 技术方案

- 保留原版真实栈为 `stacksTo(1)`，不改变现有单序号存储与服务端命令链路。
- 在 `LinkItemData` 上新增聚合序号组字段，统一维护“升序、去重、顶部最小序号”。
- 聚合序号组上限固定为 `64`，以常量约束合并与并入行为；超出上限的部分保留在来源栈。
- 聚合数量角标改为“最小客户端渲染 mixin”方案：
  - 在 `Gui.renderSlot(...)` 中拦截热键栏/副手槽角标绘制前的 `renderItemDecorations(...)`
  - 在 `AbstractContainerScreen.renderSlot(...)` 中拦截普通槽位角标绘制
  - 在 `AbstractContainerScreen.renderFloatingItem(...)` 中拦截鼠标手持浮动物品角标绘制
- 注入时不改原版真实栈，也不直接重绘文字；只把传给原版 `renderItemDecorations(...)` 的 `ItemStack` 替换成一个“显示用 count 副本”，让原版继续使用自己的层级、偏移和深度处理。
- 第一层仅实现物品级交互：
  - 左键同类物品合并为聚合栈
  - 右键空手点聚合栈按有序中点拆半
  - 手持聚合栈右键空槽时放出顶部一个序号
  - 手持聚合栈右键同类槽位时只并入顶部一个序号
  - 聚合态禁止右键打开配对/触发逻辑
  - tooltip 显示聚合数量与有序序号表达式
  - 客户端在热键栏与容器槽位右下角补绘聚合数量角标，但不改原版真实 `count`
- 第一层明确不做：
  - 双击归并
  - `shift` 快移
  - 快速拖拽分发
  - 批量合成并入
  - 创造模式复制聚合

## 原子步骤清单

### 步骤 1：定义聚合序号组数据模型
- **操作对象**：`LinkItemData`
- **具体动作**：新增聚合序号组读写、顶序号移除、右键拆半、按序号匹配等基础能力
- **预期结果**：单件与聚合件共用一套序号访问 API，原有单序号读取继续可用
- **关键里程碑**：是

### 步骤 2：接入物品级背包点击重载
- **操作对象**：`PairableBlockItem`、`LinkerItem`、聚合点击 helper
- **具体动作**：复用原版 `overrideStackedOnOther` / `overrideOtherStackedOnMe` 完成左键合并、右键拆半、右键放一
- **预期结果**：不依赖 mixin 即可获得第一层聚合交互
- **关键里程碑**：是

### 步骤 3：补齐原有出入口适配
- **操作对象**：`PairableBlockItem`、`LinkNodeRetireMatchSupport`
- **具体动作**：聚合态禁止右键打开 GUI；方块放置仅消耗顶部一个序号并保留余项；待退役匹配支持“聚合栈包含某序号”
- **预期结果**：聚合栈不会直接冲坏现有单序号放置与保留判定
- **关键里程碑**：是

### 步骤 4：将角标显示接回原版渲染链
- **操作对象**：client mixin/render support
- **具体动作**：移除外围补绘方案，改为在原版 `renderItemDecorations(...)` 调用前注入“显示用 count 副本”
- **预期结果**：容器槽位、快捷物品栏和浮动物品统一复用原版角标渲染时机
- **关键里程碑**：是

### 步骤 5：补齐展示与测试
- **操作对象**：tooltip/test
- **具体动作**：保留已有聚合数量/序号展示，并补充 mixin 方案回归验证
- **预期结果**：玩家可读，聚合显示与上限语义有自动化覆盖
- **关键里程碑**：否

## 预期结果

- 玩家可在普通物品栏中把同类可配对物品聚合成一格，并按有序规则拆分与放出。
- 聚合栈最多承载 `64` 个有序序号，容器与热键栏中会显示对应数量角标。
- 数量角标通过原版 `renderItemDecorations(...)` 链路绘制，显示层级与普通物品数量字一致，并覆盖容器内底部快捷物品栏与浮动物品。
- 原有单序号放置、配对和服务端命令链路保持不变，只在入口/出口处做聚合适配。
- 第一层完成后，是否继续补双击归并、`shift` 快移、批量合成，再单独评估。

## 语义对齐说明

- 本方案不新增 `triggerSource/core` 之外的领域术语输出；现有 `LinkNodeType.TRIGGER_SOURCE/CORE` 映射不变。
- 本方案不修改连接方向判定，也不改变 `link set` 输入输出结构。
- 兼容边界维持“读旧写新”中的“旧逻辑仍可读单序号，新逻辑额外可读聚合序号组”。
- 本轮新增的 `64` 上限与数量角标仅作用于聚合层，不影响 `triggerSource/core` 语义与原版真实物品栈计数。
- 客户端渲染 mixin 仅替换角标显示用物品栈，不新增任何 `triggerSource/core` 方向写入路径。
- 残余风险：聚合掉落物若直接进入“实体销毁退役”路径，当前第一层仍以顶部序号为主；后续如要覆盖整栈销毁退役，需要继续扩展事件模型。
