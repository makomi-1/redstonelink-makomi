## 任务背景

第一阶段已完成单节点读模型家族的基础收口：

- `NodeIdentitySnapshot` 统一承载身份字段
- `NodeLinksSnapshot` 统一承载当前连接可见视图
- `NodeRuntimeSnapshot` 统一承载运行态字段
- `NodeSnapshotQueryService` 已用于 `node get` / `link get`

但 current-links 的其他主要消费点仍未完全收口，仍存在以下分散路径：

- `PairingNetwork` 直接读取 raw targets 后调用旧 `List<Long>` 包装
- 物品/NBT 写回点直接调用旧 `Set<Long>` 包装
- `CurrentLinksPrivacyService` 仍暴露旧式包装方法，导致外层继续绕过统一读模型入口

本阶段目标是继续完成 current-links 读取侧的收口，但不改变协议语义、持久化结构与方向语义。

## 方案详情

### 现状分析

- `CurrentLinksPrivacyService` 仍保留 `resolveVisibleCurrentLinksSnapshot(...)` 与 `resolveItemSnapshotTargets(...)`
- `PairingNetwork` 的配对 GUI 打开与近外显查询仍直接消费旧 `List<Long>` 视图
- `ModCommands`、`LinkerItem`、多个方块掉落路径仍直接消费旧 `Set<Long>` 物品快照包装
- `NodeLinksSnapshot` 当前仅提供 `visibleTargets()` 与 `visibleTargetCount()`，缺少物品写回所需的稳定 `Set` 视图
- `NodeSnapshotQueryService` 尚缺少专门的 links-only 查询入口

### 技术方案

本阶段采用“查询服务收口 + 读模型便捷出口补齐”的方式推进：

1. 保留 `CurrentLinksPrivacyService` 作为底层可见性与脱敏规则层
2. 在 `NodeSnapshotQueryService` 中补充 links-only 查询入口，统一读取 `LinkSavedData` 与组装 `NodeLinksSnapshot`
3. 在 `NodeLinksSnapshot` 中补充消费侧便捷出口，避免各调用点重复从 `List<Long>` 手动转 `Set<Long>`
4. 将 `PairingNetwork`、物品 NBT 写回点、命令侧物品同步路径统一改为消费 `NodeLinksSnapshot`
5. 在主调用点迁移完成后，删除旧的 `List<Long>` / `Set<Long>` 包装方法

### 技术取舍

- 不修改网络 payload：继续向客户端发送 `List<Long>`，降低回归风险
- 不修改持久化结构：`LinkSavedData` 仍是真实连接数据来源
- 不把 `NodeLinksSnapshot` 下沉到 wire 层：它保持服务端读模型职责
- 不引入 `com.makomi.api.v1.*`：继续走内部实现路径

## 原子步骤清单

### 步骤 1：补齐 links 读模型便捷出口
- **操作对象**：`NodeLinksSnapshot`
- **具体动作**：新增稳定的 `visibleTargetSet()` 等便捷方法，并补充中文方法注释
- **预期结果**：消费侧不再各自实现 `List -> Set` 转换
- **关键里程碑**：是

### 步骤 2：补齐 links-only 查询服务
- **操作对象**：`NodeSnapshotQueryService`
- **具体动作**：新增按玩家视角、命令/系统视角、物品快照视角查询 `NodeLinksSnapshot` 的入口
- **预期结果**：外层不再手动读取 raw targets 并重复组装 links 视图
- **关键里程碑**：是

### 步骤 3：迁移配对网络消费路径
- **操作对象**：`PairingNetwork`
- **具体动作**：将 GUI 打开与近外显 current-links 查询统一改为使用 `NodeLinksSnapshot`
- **预期结果**：网络消费路径收口到统一读模型
- **关键里程碑**：是

### 步骤 4：迁移物品/NBT 写回路径
- **操作对象**：`ModCommands`、`LinkerItem`、相关方块类
- **具体动作**：将物品链接快照写回统一改为使用 `NodeLinksSnapshot.visibleTargetSet()`
- **预期结果**：item/drop/命令同步路径统一使用同一份 links 读模型
- **关键里程碑**：是

### 步骤 5：清理兼容包装与补测试
- **操作对象**：`CurrentLinksPrivacyService`、相关测试
- **具体动作**：删除不再使用的旧包装方法，补充 links 读模型与网络分支的定向测试
- **预期结果**：第二阶段收口完成且具备回归保障
- **关键里程碑**：是

## 预期结果

- current-links 的主要服务端消费入口统一收口到 `NodeLinksSnapshot`
- `PairingNetwork`、物品 NBT 写回点、命令侧同步逻辑不再直接依赖旧包装
- 后续第三阶段若继续整合近外显/GUI 读模型，可直接复用本阶段形成的稳定边界

## 语义对齐说明

- 命名统一使用 `triggerSource/core`
- 输入/输出结构不改变方向语义，仍保持 `triggerSource -> core`
- 与 `LinkNodeType.TRIGGER_SOURCE/CORE` 映射保持一一对应
- 本阶段仅重构内部读取层，不改协议语义、不改持久化键、不引入 API 依赖
- 残余风险：无语义层残余风险；仅需在实现时保留既有 `PairingNetwork` 空指针契约测试
