# 剩余写入口收口与bench命名修正

生成时间：2026-04-03 20:29:11
文件名：2026-04-03_202911_剩余写入口收口与bench命名修正.md

## 任务背景
在已完成 `P1` 快照隔离与 `P2` 主线程边界保护后，当前并发治理分析里“第一阶段”的真实剩余缺口，已经不是再从零搭一套新事务服务，而是把仍然绕过共享写入闭环的路径继续收口。

仓库现状是：
1. `LinkSetExecutionService` 已承接 `link set` 与配对网络的覆盖写入闭环；
2. `link add/remove/clear` 仍直接改 `LinkSavedData`；
3. `QuickLinkApplyService` 与 bench 结构化批量建链仍各自复制 `replace + delta + snapshot`；
4. `BenchStructuredLinkApplySupport` 命名已经落后于当前“映射规则展开 + 批量覆盖写入”职责。

## 方案详情

### 现状分析
- 共享写入闭环已存在，适合作为当前阶段统一收口点，不必再并行引入第二套 `LinkGraphMutationService`。
- 单条命令、quick-link、bench 三类路径的核心差异主要在“输入解析/反馈口径/调用场景”，而不在真实写入动作本身。
- 当前 `sourceRevision/graphRevision` 仍不存在；本轮只完成“剩余写入口收口”，不扩展到存档结构与冲突回执协议。

### 技术方案
1. 增强 `LinkSetExecutionService`：
   - 抽出“按结构化目标集合执行覆盖写入”的共享入口；
   - 让调用方可复用同一套 replace、delta、节点快照与物品快照同步闭环；
   - 保留调用方自定义反馈能力，避免把所有入口硬绑定为 `link set` 文案。
2. 收口 `link add/remove/clear`：
   - 改成先算 `nextTargets`，再走共享执行入口；
   - 维持原命令反馈文案与行为，不改变用户可见语义。
3. 收口 `QuickLinkApplyService`：
   - 保留 quick-link 自身解析与失败映射；
   - 真正写入改为复用共享执行入口，不再自维护副作用闭环。
4. bench 类重命名并收口：
   - 将 `BenchStructuredLinkApplySupport` 重命名为 `BenchLinkMappingApplySupport`；
   - 批量建链的真实写入阶段复用共享执行入口；
   - 同步命令注册、测试和相关文档引用。

### 影响范围
- `src/main/java/com/makomi/command/link/LinkSetExecutionService.java`
- `src/main/java/com/makomi/command/link/LinkCommandRegistry.java`
- `src/main/java/com/makomi/data/QuickLinkApplyService.java`
- `src/main/java/com/makomi/command/bench/BenchStructuredLinkApplySupport.java`（重命名）
- `src/main/java/com/makomi/command/bench/BenchLinkCommandRegistry.java`
- 对应 bench / quick-link / link command 测试
- 审查文档与必要的计划/命名引用

## 原子步骤清单

### 步骤 1：增强共享写入闭环
- **操作对象**：`LinkSetExecutionService`
- **具体动作**：抽出可复用的结构化覆盖写入执行入口，统一 replace、delta、快照同步
- **预期结果**：后续命令、quick-link、bench 可共用同一真实写入闭环
- **关键里程碑**：是

### 步骤 2：迁移单条命令写路径
- **操作对象**：`LinkCommandRegistry`
- **具体动作**：将 add/remove/clear 逻辑改为“计算 nextTargets -> 调共享执行入口”
- **预期结果**：普通 `link` 命令不再直接维护副作用闭环
- **关键里程碑**：是

### 步骤 3：迁移 quick-link 写路径
- **操作对象**：`QuickLinkApplyService`
- **具体动作**：保留 quick-link 专属校验与提示，但真实写入走共享执行入口
- **预期结果**：quick-link 与命令/网络使用同一套写入闭环
- **关键里程碑**：是

### 步骤 4：重命名并迁移 bench 写路径
- **操作对象**：bench apply support、bench registry、bench tests
- **具体动作**：重命名类并让执行阶段复用共享写入闭环
- **预期结果**：bench 命名与职责对齐，且不再复制写入副作用逻辑
- **关键里程碑**：是

### 步骤 5：测试与审查文档
- **操作对象**：相关测试与 `docs_dev/reviews/`
- **具体动作**：补/改测试，执行 `.\gradlew.bat test testIntegration testClient testSlow --no-daemon`，再生成审查文档
- **预期结果**：本轮收口具备自动化回归保护和可追溯审查记录
- **关键里程碑**：是

## 预期结果
- 现有链接写入路径进一步收口到共享闭环，减少重复的 replace/delta/snapshot 实现。
- `BenchStructuredLinkApplySupport` 更名为符合职责的 `BenchLinkMappingApplySupport`。
- 语义继续保持 `triggerSource -> core` 单向写入，不新增旧术语输出，不引入 `com.makomi.api.v1.*`。
- `sourceRevision/graphRevision` 仍未落地，作为下一阶段独立工作保留。
