# link命令拆分

生成时间：2026-03-24 20:45:28
文件名：2026-03-24_204528_link命令拆分.md

## 任务背景

在 `input` 与 `node trace` 已完成拆分后，`ModCommands` 中剩余最大的命令块是 `link`。  
当前 `link` 同时混合了命令树注册、`write_control` 子树、链路增量/覆盖写入、写控制判定、客户端快照同步等职责，已经不再适合作为统一入口类的一部分继续膨胀。

本轮目标是在不改变现有命令语义与权限行为的前提下，将 `link` 全量迁出 `ModCommands`，形成独立的命令注册器与模块内 support。

## 方案详情

### 现状分析

- `ModCommands` 当前仍内联承载 `/redstonelink link` 根树及其执行逻辑。
- `write_control protected` 与 `link add/remove/set/get` 在同一类中实现，职责边界不清晰。
- `link set`、写控制判定、目标序列号解析、物品/节点快照同步属于 link 模块内部共享逻辑，但当前散落在入口类中。
- `CurrentLinksPrivacyCommandRegistry` 已经是独立模块，说明 `link` 根树本身具备继续拆分的条件。

### 技术方案

1. 新增 `command/link/LinkCommandRegistry`
   - 承载 `/redstonelink link` 根树
   - 负责 `add/remove/set/get`
   - 组合 `CurrentLinksPrivacyCommandRegistry` 与新的 `LinkWriteControlCommandRegistry`
2. 新增 `command/link/LinkWriteControlCommandRegistry`
   - 只负责 `write_control protected add/remove/list/set confirm`
3. 新增 `command/link/LinkCommandSupport`
   - 负责 link 模块内部共享命令层辅助
   - 包括目标序列号解析、写控制判定、受控名单激活校验、物品快照同步、节点快照同步
4. 将 `allowPlayerSourceOrBenchmarkMode` 提升到 `CommandTreeSupport`
   - 供 `link` 与后续 `place` 等命令共用
5. 回收 `ModCommands` 中旧 `link` 实现
   - 仅保留 `.then(LinkCommandRegistry.createRoot())`

### 影响范围

- `src/main/java/com/makomi/command/ModCommands.java`
- `src/main/java/com/makomi/command/CommandTreeSupport.java`
- `src/main/java/com/makomi/command/link/LinkCommandRegistry.java`
- `src/main/java/com/makomi/command/link/LinkWriteControlCommandRegistry.java`
- `src/main/java/com/makomi/command/link/LinkCommandSupport.java`

## 原子步骤清单

### 步骤 1：创建 link 命令注册器
- **操作对象**：`command/link/LinkCommandRegistry.java`
- **具体动作**：迁移 `/redstonelink link` 根树和 `add/remove/set/get` 执行逻辑
- **预期结果**：`link` 主命令拥有独立注册器
- **关键里程碑**：是

### 步骤 2：创建 write_control 子注册器
- **操作对象**：`command/link/LinkWriteControlCommandRegistry.java`
- **具体动作**：迁移 `write_control protected` 全部注册与执行逻辑
- **预期结果**：`write_control` 从入口类中剥离
- **关键里程碑**：是

### 步骤 3：抽取 link 模块共享 support
- **操作对象**：`command/link/LinkCommandSupport.java`
- **具体动作**：迁移 link 专属辅助方法与解析结果结构
- **预期结果**：link 内部共享逻辑集中，避免污染全局 support
- **关键里程碑**：是

### 步骤 4：补充全局通用命令上下文校验
- **操作对象**：`CommandTreeSupport.java`
- **具体动作**：加入 `allowPlayerSourceOrBenchmarkMode`
- **预期结果**：`link` 与后续命令可统一复用玩家/RCON 场景校验
- **关键里程碑**：否

### 步骤 5：瘦身 ModCommands
- **操作对象**：`ModCommands.java`
- **具体动作**：改为装配 `LinkCommandRegistry`，删除旧 `link` 实现与遗留 helper
- **预期结果**：入口类继续向“根装配器”收敛
- **关键里程碑**：是

### 步骤 6：执行回归验证
- **操作对象**：Gradle 测试任务
- **具体动作**：运行 `CommandEntryContractTest` 与全标签自动化测试
- **预期结果**：确认拆分前后命令行为一致
- **关键里程碑**：是

## 预期结果

- `ModCommands` 进一步减重，职责集中到根装配。
- `link` 命令层形成与 `input`、`node trace` 一致的模块结构。
- 用户可见命令、权限、确认分支与反馈文案保持不变。
- 为后续继续拆 `place`、`audit` 提供一致的结构模板。
