# bench逐tick对比二期

生成时间：2026-03-23 22:28:31
文件名：2026-03-23_222831_bench逐tick对比二期.md

## 任务背景

- 第一阶段已经补齐 `RunFunctionalCase`、功能矩阵和基于 `trace read` 的周期窗口断言，能够稳定覆盖 `sync/pulse/toggle` 的主要场景。
- 当前仍缺少“按服务端 tick 逐点证明”的正式断言链路，尤其是：
  - `trace mount` 挂载即写基线快照，需要明确裁剪规则；
  - `trace read` 为单序号、最新优先输出，需要在 bench 侧完成正序化与对齐；
  - `pulse/toggle` 仍主要依赖 `trace latest` 的稳态快照，不能直接证明窗口内每个 tick 的演化。

## 方案详情

### 现状分析

- `NodeStateTraceService.mount(...)` 会在挂载时立即记录一条当前快照，见 `src/main/java/com/makomi/data/NodeStateTraceService.java`。
- `NodeStateTraceService.readSamples(...)` 返回最近样本，顺序为最新优先；bench 现有 `trace_read_cycle_assert` 已做正序化后窗口旋转匹配。
- `tools/bench/run-bench.ps1` 目前没有 phase 级上下文表，无法把“挂载 tick”“驱动命令起止 tick”传递给后续断言 phase。
- `tools/bench/functional-matrix.json` 中 `sync` 已迁到周期窗口断言，但 `pulse/toggle` 仍使用 `trace_latest_assert`。

### 技术方案

1. 为功能 phase 增加上下文元数据
   - `trace_mount` 记录 `mountTick`
   - `input_start_square` / `input_start_custom` / `activate_batch` 记录 `commandStartTick` 与 `commandEndTick`
   - 后续断言 phase 通过 `mountRef`、`anchorRef` 引用这些上下文

2. 新增严格逐 tick 断言 phase：`trace_read_tick_assert`
   - 先对 `trace read` 结果做时间正序化
   - 裁掉挂载基线和锚点之前的样本
   - 只在有限锚点窗口内查找连续 `N` tick 的候选窗口
   - 对候选窗口逐 tick 比较期望字段并输出 mismatch 明细

3. 明确三类规则
   - 挂载窗口规则：逐 tick 断言要求先 `trace_mount`，且 `every=1`
   - 基线样本裁剪规则：裁掉 `tick < max(mountTick + 1, anchorTickMin)` 的样本
   - `n tick` 对齐规则：默认仅允许 `alignmentSlackTicks=1` 的有限偏移，不做任意周期旋转

4. 为 `sync/pulse/toggle` 提供模板化期望生成
   - `sync`：从输入器参数推导每 tick `active/input/output/resolvedStrength`
   - `pulse`：按 `server.pulseDurationTicks` 推导高电平持续窗口再回落
   - `toggle`：按事件后稳态保持推导连续窗口

5. 迁移功能矩阵
   - 先把现有 `sync` case 切到 `trace_read_tick_assert`
   - 再把 `pulse/toggle` 从 `trace_latest_assert` 迁到逐 tick 断言

### 影响范围

- `tools/bench/functional-matrix.json`
