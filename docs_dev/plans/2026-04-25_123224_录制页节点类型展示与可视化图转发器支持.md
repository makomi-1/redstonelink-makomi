# 录制页节点类型展示与可视化图转发器支持

生成时间：2026-04-25 12:32:24
文件名：2026-04-25_123224_录制页节点类型展示与可视化图转发器支持.md

## 任务背景

`docs_dev/更新计划草稿与索引.md` 中新增两项前后关联需求：

1. 录制页面图例和 tooltip 添加节点类型；
2. 可视化图扩展支持转发器，将其作为 `triggerSource/core` 双身份组合节点展示，并支持展开后分别编辑两端连接，同时保持自隔离。

当前项目中录制 bundle 已经携带节点 `type`，graph bundle 也已具备 `capabilityFlags` 可扩展能力，因此本次优先采用“最小协议扩展 + 视图组合”的实现路径。

## 方案详情

### 现状分析

- 录制页左侧节点列表已经显示 `type #serial · traceKind`，但图例选中摘要与图表 tooltip 仍只展示 `displayText`。
- graph 当前逻辑节点仍只有 `triggerSource/core`，画布节点只有 `actual/aggregate/channelHub`，不存在转发器专用组合节点。
- graph 保存协议只支持别名、`triggerSource -> core` 覆盖和频道设置，因此转发器展开后的编辑需要复用既有草稿操作，而不是新增独立保存协议。
- 转发器后端语义仍是统一序号双身份，且已有同号 `triggerSource -> core` 自连拒绝保护，因此前端只需补足组合视图与交互隔离。

### 技术方案

1. 录制页补一个统一的“带类型节点标题”格式函数，并把它接入选中摘要与 tooltip。
2. graph 导出层在 `capabilityFlags` 中为转发器两端节点补 `repeater` 标记，避免前端只能靠“同序号双节点”猜测。
3. web graph serial 视图新增 `repeater` 画布节点语义，只对带 repeater 标记的同序号双身份做组合：
   - 收起态显示一个转发器组合块；
   - 展开态显示该组合块与其 `triggerSource/core` 两个真实成员；
   - 两端连接边仍复用现有真实边与布局逻辑。
4. `GraphViewer` 详情与批量编辑接入 repeater：
   - 组合块显示转发器摘要；
   - 真实成员仍沿用既有别名编辑与批量编辑；
   - 从组合块或其成员派生编辑选区时，执行自隔离过滤，禁止同号 `triggerSource -> core` 自连。
5. 补充前后端测试并执行回归，同时生成审查文档。

## 预期结果

- 录制页面图例、tooltip、选中摘要的节点信息展示统一为带类型格式；
- 可视化图 serial 视图新增转发器组合节点，支持展开浏览双身份；
