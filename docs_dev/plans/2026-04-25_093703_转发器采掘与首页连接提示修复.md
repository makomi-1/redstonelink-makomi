# 转发器采掘与首页连接提示修复

生成时间：2026-04-25 09:37:03
文件名：2026-04-25_093703_转发器采掘与首页连接提示修复.md

## 任务背景
- 用户反馈转发器在生存模式下表现得像基岩一样难以挖掘，体验异常。
- 用户要求在转发器首页 GUI 的“当前连接”区域补充悬停 tooltip，并区分 `triggerSource` 输入侧与 `core` 输出侧。
- 本轮只做最小粒度修复，不扩展到其他方块或其他 GUI。

## 方案详情

### 现状分析
- 转发器方块注册位于 `ModBlocks`，当前属性直接复制 `Blocks.OBSERVER`。
- 资源标签 `src/main/resources/data/minecraft/tags/block/mineable/pickaxe.json` 已收录多个同类功能块，但遗漏了 `redstonelink:link_repeater`。
- 转发器首页 GUI `RepeaterEditorScreen` 已渲染输入/输出摘要，但没有悬停区域判定，也没有 tooltip 生成逻辑。

### 技术方案
- 在 `mineable/pickaxe` 标签中补入转发器，使其与现有观察者系功能块保持一致的采掘分类。
- 在 `RepeaterEditorScreen` 中为输入侧与输出侧摘要增加悬停区域判断，并基于完整展示文本列表生成 tooltip。
- 补充资源契约测试与 GUI tooltip 测试，防止后续回归。

### 影响范围
- 资源标签：转发器采掘分类
- 客户端 GUI：转发器首页当前连接的悬停提示
- 自动化测试：资源与客户端屏幕逻辑

### 语义对齐说明
- 命名统一使用 `triggerSource/core`。
- 输入/输出结构保持 `triggerSource -> core` 方向一致。
- 新增文案与注释不使用旧术语。
- 与 `LinkNodeType.TRIGGER_SOURCE/CORE` 映射保持一致。
- 兼容层保持“读旧写新”，本轮无额外兼容字段变更。
- 残余风险：若采掘体感异常还涉及更深层破坏判定，本轮仅先修复最明确的标签遗漏。

## 原子步骤清单

- **操作对象**：`src/main/resources/data/minecraft/tags/block/mineable/pickaxe.json`
- **具体动作**：加入 `redstonelink:link_repeater`
- **预期结果**：转发器具备正常 pickaxe 采掘分类
- **关键里程碑**：是

### 步骤 2：实现首页当前连接 tooltip
- **操作对象**：`src/client/java/com/makomi/client/screen/RepeaterEditorScreen.java`
- **具体动作**：补充输入侧与输出侧摘要的悬停区域、tooltip 构建方法与渲染逻辑
- **预期结果**：首页 GUI 可分别展示 `triggerSource` 输入侧与 `core` 输出侧的完整连接 tooltip
- **关键里程碑**：是

### 步骤 3：补充自动化测试
- **操作对象**：`src/test/java/com/makomi/block/*`、`src/test/java/com/makomi/client/screen/*`

- **预期结果**：关键行为具备回归保护
- **关键里程碑**：否

## 预期结果
- 生存模式下转发器不再出现明显异常的采掘分类问题。
- 转发器首页 GUI 的输入侧与输出侧“当前连接”区域均支持悬停 tooltip。
