# 补充节点集运行期变更触发sync失效与补发测试

## 任务背景
当前过滤器运行期测试已经覆盖 send / receive 两侧在固定阈值、邻居最大输入、物理范围与部分节点集静态分流下的行为，但还缺少“节点集在运行期变化后，既有 `sync` 贡献如何失效或补发”的 dedicated functional 证据。用户本轮明确要求先补这部分测试，不处理 quick-link 与过滤器 GUI 交互。

## 方案详情

### 现状分析
- 过滤器配置变化统一经 `AbstractLinkFilterBlockEntity.applySnapshot(...)` 进入 `LinkDispatchFilterService.refreshFilterWithCurrentNeighborSignal(...)`。
- 该链路会对变更前后的过滤器条目做 `before/after` 对比，并在 `sync` 可恢复快照存在时发布失效或补发。
- 当前已有 `x28` 只证明了 receive `blocklist` 的静态命中/未命中分流，没有证明运行期 `nodeSetMode` 与 `serialExpression` 切换时的重算。
- 过滤器 functional case 继续受“`data merge block` 后需补邻居刷新”这一 bench 口径约束影响。

### 技术方案
- 新增两条 dedicated functional case：
  - send 侧：验证 `disabled -> blocklist -> serialExpression 切换 -> disabled` 过程中，命中来源的既有 `sync` 失效与补发。
  - receive 侧：验证同构的目标侧行为。
- 每条 case 都保持 `sync` 高态持续存在，避免把一次性脉冲误当作补发。
- 每次 `serialExpression` / `nodeSetMode` 变更后，都补一次真实邻居变化，确保运行态过滤真值及时刷新。
- 将新 case 接入 `functional-matrix.json` 与 `regression-core.json`，然后只定向跑通新增用例。

### 影响范围
- `tools/bench/cases/functional/` 新增 send / receive 节点集运行期专项 case。
- `tools/bench/functional-matrix.json`
- `tools/bench/suites/regression-core.json`
- `docs_dev/reviews/` 审查文档
- 如出现新的明确阻塞点，再补 `docs_dev/experiences/`
