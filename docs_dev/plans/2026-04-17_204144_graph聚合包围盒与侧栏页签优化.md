# graph聚合包围盒与侧栏页签优化

生成时间：2026-04-17 20:41:44

## 任务背景

当前 graph 视图已经完成“移除 summary、保留 aggregate 作为主要折叠层”的前端视图优化，但仍存在几个明显的可读性问题：

1. 聚合块展开后，只能看到散开的 core 节点，缺少“这仍是一组”的包围表意。
2. 右侧功能区沿纵向堆叠，孤立节点池、批量编辑和节点详情会把侧栏越挤越长，影响主图阅读。
3. 连线仍显示 `kind` 文本，用户视角下会把它读成额外的 serial/语义噪音。
4. 节点卡片内部重复显示类型标识，信息密度偏高。

本轮继续只改前端视图层与样式，不改 `snapshot`、`draft`、服务端真值和 `triggerSource -> core` 的真实保存语义。

## 方案详情

### 现状分析

- `webapp/src/components/GraphViewer.tsx` 目前负责节点/边生成、自动布局、右侧详情与编辑侧栏的全部渲染逻辑。
- 节点卡片中的类型眉标由 `buildNodeLabel` / `buildAggregateNodeLabel` 构建。
- 实际边标签目前直接沿用 `edge.kind`。
- 右侧区域当前是一个单列长侧栏，孤立节点池、批量编辑、节点详情依次堆叠。
- 核心聚合块展开后已只展开 `core` 节点，但没有补充视觉分组边界。

### 技术方案

1. 为已展开的聚合块派生“包围盒节点”：
   - 基于当前自动布局后的节点位置，计算聚合块本体及其展开 core 节点的包围范围。
   - 包围盒只作为前端 overlay 表意层，不参与真实拓扑、保存和搜索语义。
   - 包围盒应不可交互、不可拖拽，并位于真实节点层之下。

2. 将右侧功能区改为页签面板：
   - 提供 `详情`、`孤立节点池`、`批量编辑` 三个页签。
   - 默认显示详情；切入非 `view` 模式时自动切到批量编辑页签。
   - 主体仍保持双栏布局，但右栏只显示一个活动面板，减少纵向堆叠。

3. 精简节点与连线文本：
   - 节点卡片内部移除类型眉标，仅保留标题和状态信息。
   - 实际边与聚合边均不再显示文本标签。
   - 在画布外补一组固定图例，说明 `triggerSource / core / aggregate / expanded aggregate area` 的视觉语义。

4. 样式收口：
   - 新增包围盒、图例、页签和压缩侧栏的样式。
   - 保持桌面端更紧凑，同时在窄屏下退回单列，不破坏现有响应式行为。

### 影响范围

- `webapp/src/components/GraphViewer.tsx`
- `webapp/src/app.css`
- `docs_dev/reviews/`（本轮完成后新增审查文档）
