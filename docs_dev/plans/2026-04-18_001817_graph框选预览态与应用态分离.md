# graph框选预览态与应用态分离

## 任务背景

graph 视图当前框选时，未最终落入选框的节点也会出现选中态波动。根因是 ReactFlow 在拖框过程中持续发出选区变化，而前端立即把这些“预览选区”写进右侧批量编辑集合和节点高亮逻辑。目标是在不改 `triggerSource/core` 真值、snapshot、draft 和服务端语义的前提下，将框选预览态和最终应用态分离。

## 方案详情

### 现状分析

- `onSelectionChange` 在拖框过程中持续触发
- 当前实现会立刻把拖框中的实时选区写入 `selectedEditSourceSerials / selectedEditTargetSerials`
- 节点样式又会立刻用这两个集合渲染“已选来源/目标”高亮
- 结果是拖框经过但未最终选中的节点也会短暂亮起，形成闪烁和波动

### 技术方案

1. 通过 ReactFlow 的 `onSelectionStart / onSelectionEnd` 标记当前是否处于框选预览阶段
2. 框选预览阶段中：
   - `onSelectionChange` 只缓存当前最终候选节点，不立即写入批量编辑集合
   - `onNodesChange` 中的 `select` 变更先不写回受控节点状态，避免节点选中态一路抖动
3. 框选结束时：
   - 一次性提交最终节点集合到 `selectedEditSourceSerials / selectedEditTargetSerials`
   - 同步把最终节点集合写入画布节点 `selected`
4. 非框选场景下（如点击单节点、程序化清空）继续保持即时同步

- **操作对象**：`webapp/src/components/GraphViewer.tsx`

- **预期结果**：拖框过程中未最终选中的节点不再持续闪烁

## 预期结果

拖框过程中只保留选框矩形本身作为预览，右侧批量选择结果和业务高亮只在框选结束后更新；未最终框中的节点不再出现“已选来源/目标”波动。
