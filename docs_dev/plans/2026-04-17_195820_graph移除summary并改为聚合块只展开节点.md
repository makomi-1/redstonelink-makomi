# Graph 移除 summary 并改为聚合块只展开节点

生成时间：2026-04-17 19:58:20
文件名：2026-04-17_195820_graph移除summary并改为聚合块只展开节点.md

## 任务背景

当前 Graph 视图中的 `summary` 本质上是按来源节点的“剩余目标数量”做压缩，不是按结构语义做聚合。用户明确指出这会造成显示失真，因此希望尽可能移除 `summary`，让主画布只保留具有结构语义的核心聚合块。

同时，当前核心聚合块展开后仍会带出大量边，用户希望改成“块展开、边不展开”：展开时只看到更多 `core` 节点，仍维持少量的 `triggerSource -> aggregate` 外层边。

本轮仍然只改前端视图层，不改 `snapshot`、`draft`、服务端真值和真实保存方向。

## 方案详情

### 现状分析

- 当前 `summary` 以来源节点的高扇出阈值作为触发条件，会把一批来源集合并不一致的 `core` 打包成摘要节点，语义不准确。
- 当前核心聚合块展开后仍会恢复真实 `triggerSource -> core` 边，导致边数量重新膨胀。
- 当前布局依赖画布边的连通关系；如果展开后完全不显示任何块内关系，需要额外保留仅用于布局的内部关系，否则展开出来的 `core` 会被当作孤立节点分散排布。

### 技术方案

1. 移除 `summary` 主链路：
   - 删除 `summary` 节点类型、样式、边样式和点击交互
   - 删除 `summary` 统计项和 `triggerSource` 侧的摘要展开状态
   - 主画布不再使用 `summary` 作为视图压缩手段
2. 核心聚合块成为唯一折叠层：
   - 折叠态继续只显示 `triggerSource -> aggregate`
   - 展开态显示真实 `core` 节点，但继续隐藏真实 `triggerSource -> core`
   - 不新增可见的 `aggregate -> core` 边，避免边再次膨胀
3. 为保持布局稳定，引入仅用于布局的内部连接：
   - 聚合块展开时，为自动布局阶段提供 `aggregate -> core` 的内部布局边
   - 这些内部边只参与布局计算，不进入实际画布渲染
