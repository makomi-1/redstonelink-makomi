# 转发器quicklink图写入修正与缓存方框加粗

生成时间：2026-04-24 23:09:36
文件名：2026-04-24_230936_转发器quicklink图写入修正与缓存方框加粗.md

## 任务背景
用户反馈两处问题：

1. QTL 缓存对象的穿墙方框过细，不够醒目。
2. 对转发器应用 quick-link 后，HUD 提示“核心已应用”，但重新打开转发器配置时对应侧仍为空，说明“应用成功提示”和“实际配置读取结果”不一致。

本轮目标是在不扩展额外设计的前提下，完成最小修复，并继续保持 `triggerSource/core` 语义一致。

## 方案详情

### 现状分析
- `QuickLinkOutlineRenderer` 已使用自定义 `RenderType` 绘制缓存对象穿墙轮廓，但线宽仍为默认线宽。
- 转发器编辑器和方块实体的快照读取统一走 `RepeaterGraphSnapshotSupport.resolve(...)`，输入/输出表达式来自 `LinkSavedData` 当前图真值，而不是本地方块实体缓存。
- 当前 `QuickLinkApplyService.applyToRepeaterFromCache(...)` 只改本地 `RepeaterConfigSnapshot`，没有写真实图关系，因此会出现“提示成功，但重新打开编辑器为空”的错位。

### 技术方案
- 对缓存对象穿墙方框：
  - 仅调整 `QuickLinkOutlineRenderer` 里的预览 `RenderType` 线宽状态。
  - 不改普通命中白框替换逻辑，也不影响其它 HUD / 远外显。
- 对转发器 quick-link：
  - 保留“缓存类型决定写入哪一侧”的用户语义。
  - 但实际写入不再只改本地 `RepeaterConfigSnapshot`，而是映射到真实图写入：
    - `triggerSource` 缓存映射到 `core` 目标语义，更新输入侧图关系
    - `core` 缓存映射到 `triggerSource` 目标语义，更新输出侧图关系
  - 写入后继续保留转发器专用成功提示文案。

### 影响范围
- `src/main/java/com/makomi/data/QuickLinkApplyService.java`
- `src/client/java/com/makomi/client/render/QuickLinkOutlineRenderer.java`
- `src/test/java/com/makomi/data/QuickLinkApplyServiceTest.java`

- **预期结果**：QTL 缓存对象外显更醒目
- **关键里程碑**：否

- **预期结果**：应用后重新打开转发器配置，输入/输出侧能看到真实非空配置
- **关键里程碑**：是
