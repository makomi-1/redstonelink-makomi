# 修复区块激活器回归用例漂移

生成时间：2026-04-22 18:05:44
文件名：2026-04-22_180544_修复区块激活器回归用例漂移.md

## 任务背景
当前 dedicated bench 回归中，区块激活器相关用例与跨区块 reload replay 用例已经出现测试模板漂移：
- `x44/x45/x46` 仍按旧的 `serialExpression/mode` 写区块激活器方块实体配置，无法正确命中当前多服务对象配置模型；
- `x08` 仍试图验证已删除的 `syncTargetChunkLoadReplay.enabled` 关闭语义，继续保留会产生无效失败。

本轮目标是在不改业务实现的前提下，最小化修复 bench 回归入口与模板，使其重新对齐当前设计语义。

## 方案详情

### 现状分析
- 区块激活器方块实体当前持久化与读取逻辑已切换为 `activeType`、`triggerSourceSerialExpression`、`triggerSourceMode`、`coreSerialExpression`、`coreMode` 五个 canonical 字段，旧字段仅保留兼容读取。
- `x49` 已经使用新字段写法，能够作为 `triggerSource/core` 新语义下的模板对照。
- `x08` 与多个 suite 入口仍使用 `crosschunk.syncTargetChunkLoadReplay.enabled`，但该配置入口已删除，继续覆写不会改变运行时行为。

### 技术方案
- 将 `x44/x45/x46` 的 `data merge block` 命令统一改为当前 canonical NBT 写法，只配置 `triggerSource` 侧：
  - `activeType:"triggerSource"`
  - `triggerSourceSerialExpression`
  - `triggerSourceMode`
  - `coreSerialExpression:""`
  - `coreMode:"force_load"`
- 将 `x08_reload_replay_disabled` 从活跃 bench 回归入口中移除，避免继续对不存在的“关闭 replay”语义做断言。
- 本轮不扩散处理其他 suite 中残留的 `syncTargetChunkLoadReplay.enabled`，仅把当前已确认误报路径先止血；其余项作为残余风险在汇报中说明。
