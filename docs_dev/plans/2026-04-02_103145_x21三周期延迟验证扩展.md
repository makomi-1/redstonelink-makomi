# x21三周期延迟验证扩展

生成时间：2026-04-02 10:31:45
文件名：2026-04-02_103145_x21三周期延迟验证扩展.md

## 任务背景
当前 `x21` 同区块 sync 延迟专项只对单个 8 tick burst 周期做服务端逐 tick 匹配。为提高固定延迟语义的验证强度，需要把该服务端验证窗口扩展到连续 3 个周期，并分别对 `dispatchBatchWindowTicks=0/1/2` 单独运行验证。

## 方案详情

### 现状分析
- `x21` case 当前使用 `15/14/13/12/11/10/9/0` 作为单周期 8 tick burst。
- `trace_sync_latency_collect_*` phase 通过 `tickCount` 指定服务端逐 tick 匹配窗口长度。
- `functional-samechunk-latency-debug.json` 已经提供了 `window=0/1/2` 三个独立 suite entry，可直接复用。

### 技术方案
- 将 `x21` case 中 burst 序列重复 3 次，形成 24 tick 连续验证窗口。
- 同步把 `start_sync_latency_single_burst.totalTicks` 和两个 trace phase 的 `tickCount` 从 `8` 调整为 `24`。
- 继续使用现有 debug suite，但每次只挑一个 `entryId` 跑单 entry，使 `window=0/1/2` 各自独立出结果。

### 影响范围
- 直接影响：`tools/bench/cases/functional/x21/sync_samechunk_latency_1024_to_1024_banded16_single_burst.json`
- 验证影响：`tools/bench/suites/functional-samechunk-latency-debug.json` 的三个 entry 将在新样本上分别执行
- 不影响：调度实现、trace 脚本、`triggerSource/core` 语义、其它 bench case

## 原子步骤清单

### 步骤 1：扩展 x21 burst 样本到 3 个周期
- **操作对象**：`tools/bench/cases/functional/x21/sync_samechunk_latency_1024_to_1024_banded16_single_burst.json`
- **具体动作**：把 `sequence` 扩成 24 tick，`totalTicks/tickCount` 从 `8` 改为 `24`
- **预期结果**：服务端逐 tick 匹配窗口覆盖连续 3 个完整周期
- **关键里程碑**：是

### 步骤 2：分别运行三组窗口验证
- **操作对象**：`tools/bench/suites/functional-samechunk-latency-debug.json`
- **具体动作**：按 `entryId` 分别运行 `window=0/1/2` 的单 entry suite
- **预期结果**：获得三组独立功能结果 JSON 与 suite summary
- **关键里程碑**：是

### 步骤 3：汇总结果并形成审查记录
- **操作对象**：`run/profiles/bench-suite-results/`、`docs_dev/reviews/`
- **具体动作**：解析三组结果中的 matched ratio、delay ticks 与 coverage，并写审查文档
- **预期结果**：形成可追溯验证结论
- **关键里程碑**：否

## 预期结果
- `x21` 从单周期验证升级为 3 周期连续验证。
- `window=0/1/2` 都能独立产出结果，便于确认固定延迟在更长窗口下是否仍严格生效。
- 不改变现有调度和运行时语义，仅收紧测试强度。
