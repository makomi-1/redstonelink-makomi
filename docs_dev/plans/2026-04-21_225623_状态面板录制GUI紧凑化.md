# 状态面板录制GUI紧凑化

生成时间：2026-04-21 22:56:23
文件名：2026-04-21_225623_状态面板录制GUI紧凑化.md

## 任务背景
录制 GUI 目前延续了旧版较松散的纵向排布方式，标题、摘要、参数输入、录制控制、订阅选择和状态信息之间存在较多留白。  
更关键的是，`StatePanelRecordingScreen.resolveLayout(...)` 在屏幕高度不足时会收缩 `panelHeight`，但内部控件坐标仍使用固定常量，导致底部控件与状态文本可能落到可视区之外。  
本次目标是在不压缩主输入字段宽度预留的前提下，对录制 GUI 做与状态面板/过滤器类似的紧凑化处理。

## 方案详情

### 现状分析
- 录制界面主文件为 `src/client/java/com/makomi/client/screen/StatePanelRecordingScreen.java`。
- 当前布局通过大量 `panelTop + 常量偏移` 直接给出坐标，视觉上松散，且 `PANEL_HEIGHT` 与内部内容高度耦合不清晰。
- 录制参数输入框、自动打开网页按钮、录制控制按钮和订阅选择列表均依赖同一套布局结果，适合统一重算。
- 现有仓库已经为状态面板与过滤器编辑器补了布局回归测试，录制界面尚缺少对应测试。

### 技术方案
- 将录制界面布局改为“紧凑版顺序布局”：
  - 保留左侧标签列宽与右侧字段宽度，确保标题、采样间隔、容量、时长等输入框的长度预留不缩水。
  - 压缩标题区、摘要区、参数区、按钮区与选择区之间的纵向间距。
  - 统一用真实内容高度作为面板高度基线，避免“面板高度缩了、内部坐标没缩”的假收敛。
- 保持原有 5 行订阅按钮与滚动交互，不新增动态行数逻辑，避免超出本轮最小改动范围。
- 新增录制界面布局测试，覆盖：
  - 窄屏宽度收敛；
  - 字段宽度预留保持；
  - 中等高度视口下状态区仍位于可视范围内；
  - 选择区行和状态区的纵向顺序关系正确。

### 影响范围
