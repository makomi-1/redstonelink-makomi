# 补sync游戏内覆盖与重算回归

生成时间：2026-04-24 14:35:40
文件名：2026-04-24_143540_补sync游戏内覆盖与重算回归.md

## 任务背景

当前 `sync` 跨 tick 覆盖语义已经在内部单测和 dedicated 回归的 mixed/replay 场景中得到部分验证，但仍缺两条纯 `sync` 游戏内 functional 用例：
- 更晚 tick 的较低强度 `sync` 覆盖更早 tick 的较高强度 `sync`
- 同 tick 多个 `sync` 并发时，较高强度 `sync` 失效后应重算回同 tick 仍有效的较低强度 `sync`

本轮目标是补齐这两条 dedicated functional 回归，并基于当前工作区重新构建、同步 server jar 后跑通。

## 方案详情

### 现状分析

- 现有 `X20/X21` 主要覆盖同区块 `sync` 延迟与自定义强度序列，但没有直接断言“later low sync 覆盖 earlier high sync”。
- 现有 `X38` 覆盖普通边 add/remove 导致 `sync` 失效与补发，但没有覆盖“同 tick 双 `sync` 并发时移除高强度后回落到低强度”。
- bench 模板已具备 `input_start_custom_triggerSource`、`input_start_custom_batch_triggerSource`、`link_command`、`trace_latest_assert_core`、`command_assert`，足以表达这两条语义，无需新增 bench 引擎能力。

### 技术方案

- 新增 `X55` dedicated functional case：
  - 使用两个 `sync_emitter` fan-in 到同一个 `core`
  - 先让来源 A 以强度 `15` 在较早 tick 生效
  - 再让来源 B 以强度 `7` 在更晚 tick 生效
  - 断言目标最终保持 `effectiveMode=sync`、`resolvedStrength=7`，并通过 `node get core` 校验 `maxSources` 指向 later source
- 新增 `X56` dedicated functional case：
  - 使用两个 `sync_emitter` 在同 tick 同时写入 `15` 与 `7`
  - 先断言目标取同 tick 的高强度 `15`
  - 再移除高强度来源与 target 的普通边，只让低强度来源仍保留同 tick bucket
  - 断言目标回落到 `effectiveMode=sync`、`resolvedStrength=7`，并校验 `maxSources` 指向 surviving low source
- 将两个 case 注册到 `functional-matrix.json`
- 新增一个小型 suite，统一设置 `crosschunk.directSyncBatching=all_sync` 与 `crosschunk.dispatch.batchWindowTicks=0`，用于 dedicated 定向回归
- 按项目规则先构建并同步 server jar，再执行新 suite，汇总 dedicated 结果

### 影响范围

- `tools/bench/cases/functional/x56/sync_same_tick_high_removed_recompute_to_low.json`
- `tools/bench/functional-matrix.json`
