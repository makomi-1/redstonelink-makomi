# 过滤器 scope 矩阵低电平夹具修正

生成时间：2026-04-11 22:11:47
文件名：2026-04-11_221147_过滤器scope矩阵低电平夹具修正.md

## 任务背景

`send_filter_runtime_scope_nodeset_matrix` 与 `receive_filter_runtime_scope_nodeset_matrix` 在 bench functional 中稳定失败。失败点都集中在 `neighbor_max_input + upper_bound` 的“非零低态 7 应失效”断言。

进一步验证后确认，当前测试并未真正构造出非零低态：`setblock ... redstone_wire[power=7]` 只在放置瞬间带有该状态，随后会被 vanilla 红石系统按真实供电网络重算回 `power=0`。因此当前 case 实际测到的是“邻居输入归零”而不是“邻居输入降到 7”。

本次改动仅修正 bench 测试夹具，不调整过滤器实现语义。

## 方案详情

### 现状分析

- `x27/x28` 的高态邻居都使用过滤器相邻位置的 `minecraft:redstone_block`，该部分行为稳定。
- 低态阶段直接把相邻方块替换为 `minecraft:redstone_wire[power=7]`，该状态缺少真实供电来源，落地后会退回 `power=0`。
- 用例目标是验证 `neighbor_max_input` 对真实世界邻居信号的采样，而不是验证手写 blockstate 是否被持久保留。

### 技术方案

- 在 `x27/x28` 中保留原有高态 `redstone_block` 阶段。
- 将低态阶段改为“比较器输出 7”夹具：
  - 过滤器相邻方块改为 `minecraft:comparator[facing=north,mode=compare]`
  - 比较器后方补 `minecraft:composter[level=7]`
  - 在比较器与堆肥桶下方补支撑石块，保证夹具可稳定放置
- 该夹具使用 vanilla 真实红石规则产生固定非零低态，能被 `getBestNeighborSignal` 正常读取，且改动范围只落在 case 本身，不影响 triggerSource/core 主体布局。

### 影响范围

- `tools/bench/cases/functional/x27/send_filter_runtime_scope_nodeset_matrix.json`
- `tools/bench/cases/functional/x28/receive_filter_runtime_scope_nodeset_matrix.json`
- 文档化输出：
  - `docs_dev/reviews/` 审查文档

### 语义对齐说明

- 命名仅涉及既有 case 名称，不新增旧术语输出，内部语义仍使用 `triggerSource/core`
- 输入输出方向未变，仍是 `triggerSource -> core`
- 本次仅修测试夹具，不变更 `LinkNodeType.TRIGGER_SOURCE/CORE` 映射
- 兼容层无新增写旧逻辑，属于“修测试模板，不修实现”
- 残余风险：比较器夹具依赖 vanilla 方块状态更新，需在回归中再次确认 dedicated server 下的 tick 时序稳定

- **操作对象**：`x27/x28` bench case

- **预期结果**：明确最小修改范围
- **关键里程碑**：是

### 步骤 2：替换低电平夹具
- **操作对象**：`x27/x28` bench case
- **具体动作**：把裸 `redstone_wire[power=7]` 改为 `comparator + composter[level=7]` 真实红石夹具，并补充必要支撑块
- **预期结果**：低态阶段稳定提供非零 7 邻居输入
- **关键里程碑**：是

### 步骤 3：回归验证

`x27/x28` 的“非零低态 7”阶段改为真实可稳定存在的红石夹具后，bench functional 将实际验证 `neighbor_max_input` 的非零低态收紧语义，而不再被 `redstone_wire[power=7]` 自回落为 `0` 的 vanilla 行为误伤。
