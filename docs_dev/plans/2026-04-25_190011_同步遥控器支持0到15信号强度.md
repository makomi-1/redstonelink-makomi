# 同步遥控器支持0到15信号强度

生成时间：2026-04-25 19:00:11
文件名：2026-04-25_190011_同步遥控器支持0到15信号强度.md

## 任务背景

用户要求调整同步遥控器的现有交互语义，使其不再局限于 `0/15` 二态，而是支持游戏内可调的 `0~15` 红石信号强度。调整方式需同时覆盖 GUI 修改与手持 `Ctrl + 鼠标滚轮` 快捷修改，并在修改时即时反馈当前强度。与此同时，站立右键主交互要改为“发送一次当前设定强度的同步信号”，不能再在使用时隐式切换强度。

## 方案详情

### 现状分析

- 同步遥控器主交互当前在站立右键时会把缓存强度在 `0/15` 间切换，再派发到已连接 `core`。
- 物品数据层对同步遥控器强度做了二态归一，所有正值都会折叠为 `15`。
- 现有 triggerSource 配对界面已经支持 `REDSTONELINK_SYNC_LINKER` 显示上下文，可复用现有 pairing GUI 而不必新开完整独立界面。
- 现有 `PairingNetwork` 仅覆盖配对、别名与近外显快照，不包含同步遥控器强度保存协议。
- 客户端已有 action bar 即时提示与键位/网络同步范式，可复用于手持快捷调节反馈。

### 技术方案

1. 调整 `LinkItemData` 中同步遥控器强度持久化语义，将二态归一改为 `0~15` clamp。
2. 修改 `SyncLinkerItem` 主动作逻辑，移除右键翻转行为，改为读取当前缓存强度并单次派发。
3. 在现有 pairing GUI 基础上增加可选扩展控制行，仅在同步遥控器上下文显示强度减小、当前值与强度增大控件。
4. 为同步遥控器新增最小 C2S 保存 payload，并在服务端校验当前主手物品与序号后回写真实物品状态。
5. 在客户端注册手持同步遥控器的 `Ctrl + 鼠标滚轮` 快捷调节入口，同步保存并用 action bar 展示当前强度。
6. 更新相关 tooltip、GUI 文案与测试，保证实现、提示和验证口径一致。

### 影响范围

- 同步遥控器物品主逻辑与 tooltip
- 物品 NBT/镜像模型状态工具
- triggerSource pairing GUI 抽象与同步遥控器上下文分支
- `PairingNetwork` 的 payload、注册与服务端处理
- 客户端入口中的输入监听与即时提示
- 中英文语言文件与单元测试

## 原子步骤清单

### 步骤 1：调整同步遥控器强度持久化语义
- **操作对象**：`LinkItemData`
- **具体动作**：将同步遥控器信号强度归一逻辑从二态改为 `0~15` clamp，并保持现有二态贴图镜像规则
- **预期结果**：同步遥控器物品可稳定保存任意 `0~15` 强度
- **关键里程碑**：是

### 步骤 2：改造同步遥控器站立右键主动作
- **操作对象**：`SyncLinkerItem`
- **具体动作**：移除使用时的 `0/15` 翻转逻辑，改为发送当前已设定强度；同步更新主动作 tooltip 文案
- **预期结果**：站立右键只负责发送一次当前强度的同步信号
- **关键里程碑**：是

### 步骤 3：为同步遥控器扩展 pairing GUI 强度控制
- **操作对象**：`AbstractMultiPairingScreen`、`TriggerSourcePairingScreen`
- **具体动作**：增加可选控制行扩展点，并在同步遥控器上下文显示强度调节控件
- **预期结果**：用户可在游戏内 GUI 中直接查看并修改同步遥控器当前强度
- **关键里程碑**：是

### 步骤 4：补充同步遥控器强度保存网络协议
- **操作对象**：`PairingNetwork`、`PairingNetworkRegistrationSupport`、`PairingNetworkServerHandlerSupport`
- **具体动作**：新增保存同步遥控器强度的 payload、注册和服务端处理逻辑
- **预期结果**：GUI 调节与快捷调节都通过服务端真值保存
- **关键里程碑**：是

### 步骤 5：实现手持 Ctrl+鼠标滚轮快捷调节

- **预期结果**：用户可手持同步遥控器快速调整 `0~15` 强度
- **关键里程碑**：是
