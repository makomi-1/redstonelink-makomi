# 状态面板与过滤器GUI紧凑化

生成时间：2026-04-21 22:35:04
文件名：2026-04-21_223504_状态面板与过滤器GUI紧凑化.md

## 任务背景

当前 `StatePanelToolScreen` 与 `LinkFilterEditorScreen` 已具备完整功能，但界面存在明显的“空间利用偏松”问题：

- 状态面板把订阅输入、类型切换、三颗主按钮、表头与列表分成多层竖排，横向也为状态列留出了较长原始文案，整体显得过宽过高。
- 过滤器编辑器虽然面板本身不宽，但将 alias、目标模式、节点集、阈值来源、阈值输入、信号模式等全部拆成独立纵向段，导致界面偏长。

本轮目标是把这两个 GUI 做紧凑化处理，但不能破坏原有字段长度预留：alias、序号表达式、频道等主输入区仍需保持原有宽度与可编辑空间，不能为了缩界面去压缩字段输入体验。

## 方案详情

### 现状分析

- 状态面板当前主界面固定面板宽度 `548`，输入框与类型切换按钮都占满整行，三颗主按钮再单独占一行；列表状态列直接显示 `online / active / retired / in= / out=` 长串文案，是当前最主要的宽度压力。
- 状态面板已有列宽最小值保护与布局测试，因此不应直接粗暴压缩 `serial` 列或输入框宽度，而应优先通过布局合并和状态表达收敛来减小面板感知体积。
- 过滤器编辑器当前 preferred width 仅 `320`，主要问题不是面板太宽，而是纵向组块过多；同时 alias、serial、channel 三类输入框都直接使用 `panelWidth()`，这些正是本轮“字段长度预留”需要保留的区域。
- 过滤器已有布局测试与共享输入区点击命中逻辑，任何组块压缩都必须同步维护 `resolveLayout(...)`、背景包围盒和输入点击判定。

### 技术方案

1. 状态面板紧凑化：
   - 保留订阅输入框整行宽度不变。
   - 将“订阅类型切换 + 订阅/刷新/录制”压缩到同一行，减少一整行高度。
   - 收窄默认面板宽度，并通过更紧凑的状态文案缩减状态列压力。
   - 保持 `serial` 列与输入框的字段显示空间，不改输入长度校验语义。

2. 过滤器编辑器紧凑化：
   - 保留 alias、serial、channel 主输入区整行宽度。
   - 将 `target mode + node set`、`threshold source + signal mode` 这两组改为左右并排的双列区块。
   - 将 `fixed threshold` 与动作区整体上移，减少纯标签堆叠带来的纵向长度。
   - 保持 serial/channel 共享输入区点击命中逻辑与背景包围盒一致。

3. 测试与回归：
   - 更新现有 `StatePanelToolScreenLayoutTest` 与 `LinkFilterEditorScreenLayoutTest` 预期。
   - 视需要新增更能体现“紧凑后仍不破坏关键宽度/顺序”的断言。

### 影响范围

- `src/client/java/com/makomi/client/screen/StatePanelToolScreen.java`
- `src/client/java/com/makomi/client/screen/LinkFilterEditorScreen.java`
- 相关布局测试：
  - `src/test/java/com/makomi/client/screen/StatePanelToolScreenLayoutTest.java`
  - `src/test/java/com/makomi/client/screen/LinkFilterEditorScreenLayoutTest.java`

### 技术取舍

- 本轮不改字段最大长度、协议与服务端校验，只调整 GUI 布局与显示文案密度，风险最小。
- 对状态面板，优先压缩状态文案与按钮排布，而不是压缩输入区和 `serial` 识别区，避免破坏字段长度预留。
- 对过滤器，优先压缩纵向层级而不是横向输入框宽度，避免 alias/serial/channel 的主编辑空间退化。

## 原子步骤清单

### 步骤 1：改状态面板布局与状态表达
- **操作对象**：`StatePanelToolScreen.java`
- **具体动作**：合并类型切换与主按钮区，收紧默认宽度与纵向间距，并把状态文案改为更紧凑的短格式
- **预期结果**：状态面板更紧凑，但订阅输入框和主要字段显示空间不缩水
- **关键里程碑**：是

### 步骤 2：改过滤器编辑器纵向分组
- **操作对象**：`LinkFilterEditorScreen.java`
- **具体动作**：将若干按钮组选项改成双列区块，压缩标签与控件的纵向层级，保留 alias/serial/channel 输入区整行宽度
- **预期结果**：过滤器 GUI 更短更集中，但主输入区长度预留不变
- **关键里程碑**：是

### 步骤 3：同步布局测试
- **操作对象**：`StatePanelToolScreenLayoutTest.java`、`LinkFilterEditorScreenLayoutTest.java`
- **具体动作**：更新紧凑化后布局断言，必要时补字段宽度/顺序相关回归
- **预期结果**：布局变化可稳定回归
- **关键里程碑**：是

### 步骤 4：执行验证并产出审查文档
- **操作对象**：测试任务、`docs_dev/reviews/`
- **具体动作**：运行全标签自动化测试，并写入五段式审查文档
- **预期结果**：交付包含验证证据与风险审查
- **关键里程碑**：是

## 预期结果

完成后，状态面板和过滤器编辑器都会比当前更紧凑、更少空耗层级；同时 alias、serial expression、channel 等主输入字段仍维持原有长度预留和编辑空间，不会因为界面压缩而影响输入体验。

残余风险：
- 英文文案较长，紧凑化后更依赖按钮/标签排布是否合理，需要测试覆盖英文场景的最小布局稳定性。
- 状态文案压缩后信息密度更高，需保证仍能区分 `online/active/retired` 与功率读数。
