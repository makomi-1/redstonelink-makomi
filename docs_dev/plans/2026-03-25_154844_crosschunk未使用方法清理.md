# crosschunk未使用方法清理

生成时间：2026-03-25 15:48:44
文件名：2026-03-25_154844_crosschunk未使用方法清理.md

## 任务背景
crosschunk 派发簇在完成 `QueueSupport / RuntimeSupport / TicketSupport / CodecSupport / StateSupport` 拆分后，
主类中残留了多组仅做单层委托的私有方法。
这些方法已无实际调用方，继续保留会放大阅读噪声，并干扰后续数据层与派发层维护。

## 方案详情

### 现状分析
- `CrossChunkDispatchQueueSavedData` 中存在少量未使用的私有包装方法，真实实现已下沉到 `CrossChunkDispatchQueueStateSupport` 与 `CrossChunkDispatchQueueCodecSupport`。
- `CrossChunkDispatchService` 中存在一组较大的未使用私有 facade，真实实现已下沉到 `CrossChunkDispatchQueueSupport`、`CrossChunkDispatchRuntimeSupport` 与 `CrossChunkDispatchTicketSupport`。
- 这些方法均为 `private`，不承担外部契约，也不直接参与测试反射入口，适合直接删除。

### 技术方案
- 仅删除确认无调用方的私有方法，不调整仍作为主流程入口使用的包装方法。
- 清理后同步修正可能产生的未使用 import 或格式噪声。
- 保持 `triggerSource/core` 语义、`LinkNodeType.TRIGGER_SOURCE/CORE` 映射和现有公开 API 不变。

### 影响范围
- `src/main/java/com/makomi/data/CrossChunkDispatchQueueSavedData.java`
- `src/main/java/com/makomi/data/CrossChunkDispatchService.java`

## 原子步骤清单

### 步骤 1：清理 QueueSavedData 遗留私有包装
- **操作对象**：`CrossChunkDispatchQueueSavedData.java`
- **具体动作**：删除已无调用方的 `isValidPendingEntryInput`、`allocateNextVersion`、`parseDispatchKey`、`normalizeLegacyActivationKey`
- **预期结果**：主类只保留仍参与 `load/save/upsert` 主流程的私有委托与公开契约
- **关键里程碑**：是

### 步骤 2：清理 DispatchService 遗留私有 facade
- **操作对象**：`CrossChunkDispatchService.java`
- **具体动作**：删除已无调用方、真实逻辑已下沉到 support helper 的私有 facade
- **预期结果**：`CrossChunkDispatchService` 聚焦公开入口与仍需要的服务编排逻辑
- **关键里程碑**：是

### 步骤 3：回归验证
- **操作对象**：Gradle 测试任务
- **具体动作**：先跑 crosschunk 定向测试，再跑全标签自动化回归
- **预期结果**：确认未使用方法清理不影响 crosschunk 行为与整体构建
- **关键里程碑**：是

## 预期结果
- crosschunk 派发簇主类中的死代码明显减少。
- helper 分层关系更清晰，后续继续拆分或维护时不再被历史 facade 干扰。
- 功能行为保持不变，仅提升代码组织质量与可读性。
