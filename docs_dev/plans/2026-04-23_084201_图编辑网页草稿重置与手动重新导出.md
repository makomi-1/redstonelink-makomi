# 图编辑网页草稿重置与手动重新导出

生成时间：2026-04-23 08:42:01
文件名：2026-04-23_084201_图编辑网页草稿重置与手动重新导出.md

## 任务背景

当前 graph 编辑网页会自动持久化本地草稿，但只在草稿操作数组变空时才隐式删除对应 draft 文件。实际使用中会出现“草稿残留且用户难以清理”的情况。另外，游戏里的 graph 发生变化后，网页端不会自动重新导出最新 graph；现有“刷新索引”只刷新文件列表，不会强制重读当前同名 graph 文件内容，需要补一个明确的“重新导出最新 graph”入口。

## 方案详情

### 现状分析

- graph 草稿在页面加载时按 `draftFileName` 自动读取，本地状态变化后再 debounce 持久化。
- 当前没有用户侧显式“强制清空草稿”的入口。
- graph 保存成功时只有在 `refreshRequired=true` 的链路下才会主动刷新最新 graph。
- 单独打开 graph 页面不会自动重新导出 graph；手动“刷新索引”也不会在同名文件下重读当前 graph 内容。

### 技术方案

- 在 graph 编辑页新增“重置草稿”按钮。
  - 若当前没有未保存草稿，则直接重置本地状态并显式删除当前草稿文件。
  - 若当前有未保存草稿，则先弹确认框，再清空草稿、撤销历史、预检状态与相关提示。
- 在 graph 编辑页新增“重新导出最新 graph”按钮。
  - 复用已有 `/api/graph/refresh` 接口。
  - 若当前存在未保存草稿，则先提示用户继续会丢弃草稿；确认后先清空当前草稿，再刷新最新 graph。
  - 刷新成功后沿用现有 `onGraphEntryReloaded` 让父层替换当前 graph 条目与页面上下文。
- 草稿层补一个显式删除 helper，避免只能靠自动 debounce 间接删除。

### 影响范围

- `webapp/src/components/GraphViewer.tsx`
- `webapp/src/components/graphViewer/draft.ts`
- `webapp/src/components/GraphViewer.test.tsx`
- 可能涉及 `webapp/src/app/storageApi.ts` 的现有 refresh 调用复用，但不新增新的后端接口

## 预期结果

graph 编辑网页将新增两个明确入口：

- “重置草稿”：用于强制清掉残留草稿并恢复到当前基线图。
- “重新导出最新 graph”：用于在游戏里的 graph 已变化后，把网页端重新同步到最新 graph。

这样可以把“本地草稿清理”和“网页基线刷新”两个问题从隐式机制改成显式可操作入口，减少卡死在旧草稿或旧 graph 上的情况。
