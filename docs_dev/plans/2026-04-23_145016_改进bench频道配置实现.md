# 改进bench频道配置实现

生成时间：2026-04-23 14:50:16
文件名：2026-04-23_145016_改进bench频道配置实现.md

## 任务背景

当前 bench 频道配置主要通过 `occ_channel_partition` phase 循环发送单节点 OCC 频道提交命令完成。大规模场景下会产生大量 RCON 往返、重复的 OCC 校验与单节点 prepare/apply，导致频道配置阶段明显偏慢。

用户要求把该能力改进为更适合 bench 的实现，并在完成后跑一个对应的游戏内测试验证。

## 方案详情

### 现状分析

- bench OCC 命令层当前只暴露单节点频道提交入口，`triggerSource/core` 都是 `serial + channel + expectedRevision` 的单条写入。
- `tools/bench/lib/Bench.FunctionalTrace.Phases.ps1` 中的 `occ_channel_partition` 仍按 serial 循环拼命令并逐条发出。
- 服务层已经存在批量频道 prepare/apply 能力：`LinkChannelEditingService.prepareConfirmedBatchSetChannel(...)` 与 `applyPreparedBatchSetChannel(...)`，且底层已有 `ChannelOverride` 批量目标推导缓存。
- 因此瓶颈主要在“bench 没接入批量入口”，而不是频道模型本身不支持批量。

### 技术方案

1. 为 bench OCC 增加批量频道提交入口，允许一次提交一批 `triggerSource/core` 的 `serials + channelBase/partitionSize` 批量覆盖描述。
2. bench 命令层内部直接组装 `ChannelOverride` 列表，复用 `LinkChannelEditingService.prepareConfirmedBatchSetChannel(...)` / `applyPreparedBatchSetChannel(...)`，避免逐节点单独 OCC 往返。
3. 保持术语与方向语义一致：
   - 命令与实现统一使用 `triggerSource/core`
   - `triggerSource` 只作为来源，`core` 只作为目标
   - 兼容层如需保留旧 bench phase，仅作为内部桥接，不新增旧术语对外输出
4. 更新 `occ_channel_partition` phase，使其优先走新的批量命令，而不是逐条 `submit`
5. 不批量改所有频道 case；只保留命令层与 `occ_channel_partition` phase 的必要适配，并选取已有频道性能/功能 case 做定向验证，确认“新批量路径生效、旧单节点频道路径不回归”。

### 影响范围

- `src/main/java/com/makomi/command/bench/BenchOccCommandRegistry.java`
- `src/test/java/com/makomi/command/bench/BenchOccCommandRegistryTest.java`
- `tools/bench/lib/Bench.FunctionalTrace.Phases.ps1`
- 定向验证目标：`tools/bench/cases/performance/p27/...` 与 `tools/bench/cases/functional/x39/...`

## 原子步骤清单

### 步骤 1：补 bench 批量频道提交入口
- **操作对象**：bench OCC 命令层 / 提交适配层
- **具体动作**：新增面向 `triggerSource/core` 的批量频道提交命令，并桥接到现有批量频道服务
- **预期结果**：bench 可一次提交一批频道覆盖，而非逐 serial 单发
- **关键里程碑**：是

### 步骤 2：改造 `occ_channel_partition` phase
- **操作对象**：`tools/bench/lib/Bench.FunctionalTrace.Phases.ps1`
- **具体动作**：把频道分区 phase 改成优先调用新的批量 bench 命令
- **预期结果**：频道 partition 不再生成大量单节点 RCON 命令
- **关键里程碑**：是

### 步骤 3：验证批量频道写入口径
- **操作对象**：单测与频道场景定向游戏内测试
- **具体动作**：先跑 `BenchOccCommandRegistryTest`，再跑 `p27` 验证 `occ_channel_partition` 新批量路径，最后跑 `x39` 验证旧单节点频道命令路径未回归
- **预期结果**：能同时证明“批量频道配置已生效”和“旧频道功能路径仍保持兼容”
- **关键里程碑**：是

## 预期结果

- bench 频道配置阶段明显减少命令往返与重复 prepare/apply 开销。
- `triggerSource/core` 语义与现有频道模式行为保持一致。
- 定向验证覆盖 `p27 + x39`，作为本轮交付证据。
