# x23同窗口混合全组合逐tick全窗口验证

生成时间：2026-04-02 22:23:09

## 任务背景

当前 `x22` 已经收敛为单一参数化 case，并完成 `dispatchBatchWindowTicks=0/1/2` 的 mixed 分段验证。接下来需要补一个新的 `x23` 专项，用于验证“同窗口内三类信号叠加后的非空子集全组合”在 `all_direct + batchWindowTicks=0/1/2` 下的逐 tick 行为是否稳定。

本轮用户已明确：
- 组合口径只覆盖 `S/P/T` 的非空子集全组合，不做排列覆盖。
- source 波形仍沿用 mixed 现有三类特征，高值分别为 `sync=15`、`pulse=14`、`toggle=13`，低值统一为 `0`。
- 目标仍是 `triggerSource -> core` 单向 bench 验证，不修改运行时实现。

## 方案详情

### 现状分析

- `x22` 已提供可复用的单 core、三 source、source 逐 tick 参考相位、target relative 对齐与窗口参数化骨架。
- `Bench.FunctionalTrace.ps1` 已支持 mixed `sync/pulse/toggle` 三类目标期望模板，但尚未覆盖组合段 `SP/ST/PT/SPT`。
- bench 已支持同一 phase 解析 `serialRefs`，但 `input_start_custom_triggerSource` 对不同 source 仍只能使用单一 `sequence`，因此组合段需要使用多个启动 phase 在同一窗口内连续下发。
- 运行时仲裁规则已明确为 `SYNC > PULSE > TOGGLE`；更晚 `sync/pulse` 会清理更早帧，`pulse` 回落后可按保留的 toggle 候选回退。

### 技术方案

- 新增 `x23` 参数化 case，继续复用 `dispatchBatchWindowTicks` 参数。
- case 内按 7 个组合段组织：
  - `S`
  - `P`
  - `T`
  - `SP`
  - `ST`
  - `PT`
  - `SPT`
- 每个组合段内：
  - 对参与的 source 逐个执行 `input_start_custom_triggerSource`
  - 对参与 source 各自执行 source 逐 tick 断言
  - 对 target 使用 relative 模板断言，并按组合选择 `S/P/T/SP/ST/PT/SPT` 对应模板
- 在 `Bench.FunctionalTrace.ps1` 中新增组合模板构造函数，统一由 `windowTicks` 生成前导零偏移，避免在 case JSON 内重复手写窗口差异。
- 新增 `x23` debug suite，像 `x22` 一样覆盖 `window=0/1/2`。
- 将 `x23` case 路径加入 `tools/bench/functional-matrix.json`，便于 suite 直接解析。
