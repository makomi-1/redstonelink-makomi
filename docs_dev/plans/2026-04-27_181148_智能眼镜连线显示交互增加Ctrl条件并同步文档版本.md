# 智能眼镜连线显示交互增加Ctrl条件并同步文档版本

生成时间：2026-04-27 18:11:48
文件名：2026-04-27_181148_智能眼镜连线显示交互增加Ctrl条件并同步文档版本.md

## 任务背景
当前智能眼镜承接的 `visualize` 连线显示交互，已经把“显示本身”和“显示对象增删操作”拆成不同门槛：
- 显示只要求佩戴智能眼镜；
- 左键添加、右键移除要求佩戴智能眼镜、主手为空且处于站立状态；
- `Shift+B` 清空显示对象保持走广义操作门槛。

本轮需要在现有“站立 + 主手空”基础上，为智能眼镜连线显示的添加/移除交互再增加“按住 `Ctrl`”条件，并同步更新 Tooltip、非 `README.md` 文档、图鉴、使用说明，同时把版本号提升到 `1.8.2`。

## 方案详情

### 现状分析
- `SmartGlassesAccessSupport` 已集中承接智能眼镜显示、广义操作、显示对象修改三类门槛判定，适合作为本轮唯一语义收口点。
- 客户端 `QuickLinkNetworkClientHandlerSupport` 负责本地左键添加、右键移除入口判定；服务端 `QuickLinkNetworkServerHandlerSupport` 负责“添加显示对象”的 C2S 请求校验。
- 当前 `RequestQuickLinkVisualizeSnapshotPayload` 只携带命中对象身份，不携带 `Ctrl` 状态；如果仅改客户端判定，协议层会与服务端认知脱节。
- 当前仓库已有 `Screen.hasControlDown()` 的使用先例，可复用该客户端按键判定方式。

### 技术方案
- 在 `SmartGlassesAccessSupport` 中把“修改显示对象”门槛调整为：佩戴智能眼镜、主手为空、站立、并显式要求 `Ctrl`。
- 客户端在 visualize add/remove 判断时统一复用新门槛；其中添加请求在构建 C2S 包时附带 `Ctrl` 标记。
- 服务端对 visualize 添加请求复用同一语义，但 `Ctrl` 只能校验请求中携带的布尔值，不能像潜行那样从 `ServerPlayer` 独立感知；考虑到这里只影响观察类对象增删，不涉及拓扑真值写入，该残余风险可接受。
- 同步更新测试、Tooltip、图鉴、使用说明、机制文档与版本号，确保实现与说明一致。

### 影响范围
- 客户端交互入口与输入判定
- quick-link visualize 的 C2S 请求协议与服务端校验
- 智能眼镜/快速连接工具 Tooltip
- `docs/usage_guide_cn.md`、`docs/usage_guide_en.md`
- `docs/item_guide.html`
- `docs/mechanism_design_cn.md`、`docs/mechanism_design_en.md`
- `gradle.properties`
