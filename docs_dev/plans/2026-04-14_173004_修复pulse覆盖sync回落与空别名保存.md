# 修复pulse覆盖sync回落与空别名保存

生成时间：2026-04-14 17:30:04
文件名：2026-04-14_173004_修复pulse覆盖sync回落与空别名保存.md

## 任务背景
当前配对与目标仲裁存在两个问题：
1. `core` 目标端在更晚的 `pulse` 覆盖更早的 `sync` 后，脉冲回落时会重新回露旧 `sync` 真值，不符合“最新总是最有效”的语义。
2. pairing GUI 允许提交空别名，但服务端仍按“非法空别名”拒绝保存，导致无法通过 GUI 清空别名并回到仅显示序号。

本次修复需保持内部术语统一使用 `triggerSource/core`，并继续遵守 `triggerSource -> core` 的方向约束。

## 方案详情

### 现状分析
- `sync` 路径已支持在更晚事件到来时清理更早事件域，但 `pulse/toggle` 只会清理部分旧真值，导致旧 `sync` 在回落后重新成为 authority 候选。
- 同 tick 内已有稳定优先级规则 `SYNC > PULSE > TOGGLE`，该规则需要保留；新增修复只针对“跨 tick 的 later event 淘汰 earlier truth”。
- pairing GUI 的空 alias 已能通过客户端 payload 归一化为 `""`，但服务端保存入口统一调用 `upsert`，空值被校验层判为 `empty`，没有进入现有的别名删除路径。

### 技术方案
- 为 `core` 目标端补充跨 tick 的旧真值清理规则：当更晚的 `pulse/toggle` 生效时，清理更早的 `sync` 真值，避免脉冲结束或 toggle 后续变化时回露旧 `sync`。
- 保持同 tick 内仍按现有优先级仲裁，不因 later `toggle` 降级覆盖同 tick `sync`。
- 对 loaded direct batching 与 delayed event 场景，继续以事件自带 `eventMeta.timeKey` 判断“早/晚”，不按实际到达 tick 直接清理，以兼容批窗口内合法迟到。
- 在 pairing GUI 服务端别名保存入口中，将空 alias 解释为“删除当前别名”，复用 `remove` 与 alias state 回填逻辑，避免改动客户端协议。
