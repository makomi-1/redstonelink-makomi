# bench性能窗口与客户端自动化补强

生成时间：2026-03-27 13:38:19

## 任务背景

当前 bench 已支持 dedicated server 单 case 与 suite 自动化，也已具备外部客户端自动启动、自动进服与掉线重连能力。

但现阶段仍存在三类问题：

1. 性能 case 运行时长不统一，尚未实现“总 80 秒、前 20 秒预热、只统计后 60 秒”的采样窗口。
2. 带玩家自动化在 dedicated server 重启后等待偏长，默认自动进服与 ready 轮询节奏偏保守。
3. 外部客户端启动后缺少前台焦点控制，也无法在进服后自动打开 `F3+2` tick 曲线，不利于观察与拟真对照。

本次改动目标是在不引入额外复杂框架的前提下，把 bench 性能窗口、客户端自动化与观察体验一次补齐。

## 方案详情

### 现状分析

- 现有 performance case 的 `totalTicks` 仍以 `200/240/300` 为主，未统一到长时压测窗口。
- 现有 spark 采集是“驱动开始前启动、驱动结束后停止”，没有 warmup 与 measure 分段。
- 现有外部客户端自动化只负责写配置、启动进程、自动连接与重连，不负责切换前台窗口。
- 客户端侧已经具备 bench 自动连接控制器，适合作为“进服成功后的自动动作”挂点。

### 技术方案

1. 为 performance bench 引入统一的性能采样窗口：
   - matrix defaults 增加 `performanceWindow.warmupTicks` 与 `performanceWindow.measureTicks`
   - performance case 的 `drive.totalTicks` 统一为 `1600 tick`
   - spark 在 warmup 结束后启动，只覆盖后续 measure 窗口
2. 调整 bench 自动客户端默认节奏：
   - `BenchClientInitialConnectDelayMs` 默认值改为更激进的低延迟
   - `BenchClientReconnectIntervalMs` 默认值缩短
   - `PlayerReadyPollIntervalMs` 默认值缩短
3. 在 PowerShell bench 启动链里新增“尽力切前台”的真实客户端窗口聚焦：
   - 基于已识别的 tracked game process 轮询主窗口句柄
   - 失败仅记录，不中断 bench
4. 在客户端 bench 自动化控制器里新增“进服后自动动作”：
   - 读取 bench 配置中的可选开关
   - 进服成功后幂等打开 debug overlay
   - 幂等打开 `F3+2` 对应的 fps/tick chart
   - 避免 reconnect 时再次 toggle 导致图表被关掉

- bench 性能采样只覆盖后 `1200 tick = 60 秒`
