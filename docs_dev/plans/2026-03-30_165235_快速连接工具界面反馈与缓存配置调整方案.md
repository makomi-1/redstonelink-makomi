# 快速连接工具界面反馈与缓存配置调整方案

生成时间：2026-03-30 16:52:35
文件名：2026-03-30_165235_快速连接工具界面反馈与缓存配置调整方案.md

## 任务背景

快速连接工具已经具备基础交互能力，但当前 GUI 按钮位置仍依赖固定坐标，运行时反馈仍显示在屏幕中心，且序号缓存长度错误复用了配对输入配置。为保持界面布局稳定、反馈位置统一，并让 quick-link 与 pairing 的配置边界清晰，需要做一次小范围整理。

## 方案详情

### 现状分析

- `QuickLinkToolScreen` 里输入框、缓存类型按钮、保存按钮、清空按钮与状态提示的 Y 坐标仍是硬编码。
- 配对 GUI 已有基于输入框高度计算按钮行和状态提示位置的实现，可直接借鉴布局思路。
- quick-link 反馈当前通过独立 HUD overlay 在屏幕中心渲染，与 `B` 键模式切换的 action bar 位置不一致。
- quick-link 序号缓存输入长度当前复用了 pairing 配置，后续调优会互相影响。

### 技术方案

1. 在 `QuickLinkToolScreen` 内补齐布局辅助方法，统一由输入框高度推导三个按钮与状态提示位置。
2. 将 quick-link 运行时反馈统一切到 action bar，停用现有中心 HUD overlay 注册链路。
3. 为 quick-link 新增独立客户端配置 `client.quickLinkSerialCacheMaxLength`，默认值 `1024`，并让 quick-link GUI 读取该配置。
4. 同步中英文案与使用说明，确保当前行为和配置描述一致。

### 影响范围

- 客户端 quick-link GUI 布局
- quick-link 客户端反馈显示链路
- 客户端显示配置解析、默认值与模板生成
- 中英文本地化文案
- 使用说明文档

## 原子步骤清单

### 步骤 1：重构 quick-link GUI 布局
- **操作对象**：`QuickLinkToolScreen`
- **具体动作**：新增输入框、缓存类型按钮、操作按钮行、状态提示的布局计算方法；改为根据输入框高度自动定位。
- **预期结果**：三个按钮与状态提示位置不再依赖写死坐标。
- **关键里程碑**：是

### 步骤 2：统一 quick-link 反馈位置
- **操作对象**：`QuickLinkNetworkClientHandlerSupport`、`RedstoneLinkClient`、`QuickLinkFeedbackOverlayRenderer`
- **具体动作**：将 quick-link 网络反馈改为 action bar 显示；停用中心 HUD overlay 注册与依赖。
- **预期结果**：采集、应用、清空与模式限制提示统一出现在 action bar。
- **关键里程碑**：是

### 步骤 3：拆分 quick-link 序号缓存长度配置
- **操作对象**：客户端配置相关类与 `QuickLinkToolScreen`
- **具体动作**：新增 `quickLinkSerialCacheMaxLength` 配置字段、默认值、模板与解析逻辑，并让 quick-link 输入框使用该值。
- **预期结果**：quick-link 序号缓存长度独立可配，默认 1024。
- **关键里程碑**：是

### 步骤 4：同步文案与说明
- **操作对象**：`zh_cn.json`、`en_us.json`、`docs_dev/使用说明.md`
- **具体动作**：补齐本轮涉及的提示和配置说明，保留现有英文基线。
- **预期结果**：中英文案和使用说明与新行为保持一致。
- **关键里程碑**：否

### 步骤 5：补验证并执行回归
- **操作对象**：客户端配置测试、Gradle 测试任务
- **具体动作**：补最小配置解析/默认值测试，执行 `.\gradlew.bat test testIntegration testClient testSlow --no-daemon`。
- **预期结果**：本轮改动具备回归证据。
- **关键里程碑**：是

## 预期结果

- 快速连接工具 GUI 的三个按钮会根据输入框高度自动布局。
- quick-link 外部反馈统一使用 action bar，与 `B` 键模式提示位置一致。
- quick-link 序号缓存长度拥有独立客户端配置，默认值为 `1024`。
- 中英文文案与使用说明同步更新，当前行为可直接对照理解。
