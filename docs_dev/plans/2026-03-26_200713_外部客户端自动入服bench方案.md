# 外部客户端自动入服 bench 方案

生成时间：2026-03-26 20:07:13
文件名：2026-03-26_200713_外部客户端自动入服bench方案.md

## 任务背景

当前 bench 已支持 `AsPlayer` 玩家上下文等待与初始化，但单 case 与 suite 仍要求手动启动客户端并进服。  
考虑到开发环境 `runClient` 自带较大运行噪音，且不利于长期稳定的 bench 版本控制，本次改造目标调整为：

1. 由 bench 自动启动一个外部客户端实例，而不是开发环境客户端。
2. 外部客户端实例自动进入 dedicated server，并在 suite 重启服务端后自动重连。
3. 服务端与外部客户端统一同步同一份本地构建 jar，避免版本漂移。

## 方案详情

### 现状分析

1. 单 case bench 已有玩家就绪等待与初始化逻辑，可复用为“客户端已入服”的最终校验。
2. suite 已有 dedicated server 启停、RCON 探活和 mod jar 同步能力，适合作为外部客户端生命周期的挂载点。
3. 仓库已有客户端入口 `RedstoneLinkClient`，但尚无 bench 专用自动入服/重连能力。
4. 现有 bench 服务端样例已使用 `online-mode=false`，与本地外部 bench 客户端方案兼容。

### 技术方案

采用“两层协作”方案：

1. **模组客户端层**  
   新增 bench 自动入服控制器，从客户端实例 `config` 目录读取 bench 配置文件；当配置启用时，客户端启动后自动连接指定服务器，并在断线后按固定间隔自动重连。

2. **PowerShell 编排层**  
   bench / suite 脚本新增外部客户端参数，负责：
   - 构建并同步最新 mod jar 到客户端 `mods` 目录
   - 写入客户端 bench 配置文件
   - 启动/停止外部客户端进程
   - 与现有 `AsPlayer` / `PlayerReady` 流程对接

### 影响范围

1. `src/client/java/com/makomi/**`
2. `tools/bench/run-bench.ps1`
3. `tools/bench/run-bench-suite.ps1`
4. `tools/bench/lib/Bench.EntryPoint.ps1`
5. `tools/bench/lib/BenchSuite.EntryPoint.ps1`
6. `tools/bench/lib/BenchSuite.ModSync.ps1`
7. 新增 `tools/bench/lib/Bench.Client.ps1`
8. `docs_dev/使用说明.md`

## 原子步骤清单

### 步骤 1：补客户端 bench 自动入服模块
- **操作对象**：`src/client/java/com/makomi/client/bench/**`、`RedstoneLinkClient`
- **具体动作**：
  - 新增 bench 配置读取类
  - 新增自动连接/重连状态机
  - 在客户端初始化时注册 tick 驱动
- **预期结果**：外部客户端在启用 bench 配置后可自动入服并在掉线后自动重连
- **关键里程碑**：是

### 步骤 2：补 PowerShell 外部客户端管理模块
- **操作对象**：新增 `tools/bench/lib/Bench.Client.ps1`
- **具体动作**：
  - 封装客户端 bench 配置写入
  - 封装客户端进程启动、存活检查与停止
  - 封装客户端与 `AsPlayer` 一致性校验
- **预期结果**：单 case 与 suite 共享同一套外部客户端生命周期管理逻辑
- **关键里程碑**：是

### 步骤 3：扩展 mod jar 同步为服务端/客户端共用
- **操作对象**：`tools/bench/lib/BenchSuite.ModSync.ps1`
- **具体动作**：
  - 将现有“同步服务端 mod jar”能力抽象为“同步到指定 mods 目录”
  - 供外部客户端 `mods` 目录复用
- **预期结果**：服务端与客户端可使用同一份本地构建 jar
- **关键里程碑**：否

### 步骤 4：给单 case bench 接入外部客户端自动启动
- **操作对象**：`run-bench.ps1`、`Bench.EntryPoint.ps1`
- **具体动作**：
  - 增加外部客户端相关参数
  - 在进入玩家上下文等待前按需启动客户端
  - 在单 case 结束后按配置停止客户端
- **预期结果**：单 case 可一条命令完成“启动客户端 -> 自动入服 -> bench 执行”
- **关键里程碑**：是

### 步骤 5：给 suite 接入外部客户端自动启动与重连
- **操作对象**：`run-bench-suite.ps1`、`BenchSuite.EntryPoint.ps1`
- **具体动作**：
  - 增加外部客户端相关参数
  - suite 外层启动客户端一次
  - 每轮 case 复用同一客户端，依赖客户端自动重连跨过服务端重启
  - suite 结束统一关闭客户端
- **预期结果**：suite 无需人工反复进服
- **关键里程碑**：是

### 步骤 6：补使用说明与验证
- **操作对象**：`docs_dev/使用说明.md`
- **具体动作**：
  - 补单 case / suite 的外部客户端自动化命令示例
  - 明确客户端目录、mods 同步、配置文件与限制条件
- **预期结果**：用户可直接照文档运行
- **关键里程碑**：否

## 预期结果

1. 新增一个面向外部客户端实例的 bench 自动入服能力。
2. 单 case 可自动拉起客户端并进入 dedicated server。
3. suite 可在 dedicated server 每轮重启时依赖客户端自动重连，真正做到无人值守。
4. 服务端与客户端使用同一份本地构建 jar，实现 bench 运行版本一致性。
