# 区块激活器破坏失效验证

生成时间：2026-04-22 10:55:51
文件名：2026-04-22_105551_区块激活器破坏失效验证.md

## 任务背景

现有 dedicated 回归已经覆盖：

- `x44`：区块激活器激活态下对 `force_load` 的贡献
- `x45`：区块激活器重新加载后失活，对 `resident` 贡献的撤销

但还缺少“区块激活器被真实物理破坏后，其持久化节点集贡献立即失效”的 dedicated 验证，需要补齐。

## 方案详情

### 现状分析

- 区块激活器的“失活”与“物理破坏”是两条不同生命周期：
  - 失活走 `refreshPlacedActivatorState -> upsert(active=false)`
  - 物理破坏走 `onRemove -> markPhysicalRemovalInProgress -> setRemoved -> removePlacedActivatorState`
- 已有 `x45` 能验证 resident 激活态持有和失活撤销，但不能证明物理破坏时 persisted activator 条目被删除。
- bench 对 unload/reload 敏感用例仍需关闭 `autoLoadCaseChunks`，否则会被 runner 默认 `forceload add` 污染。

### 技术方案

采用最小实现：

1. 新增一条 `resident` 物理破坏 dedicated case
   - 仍使用 1 个区块激活器作用于 3 个 `triggerSource`
   - 先验证激活态下 resident 持有来源在线
   - 再重新加载激活器自身 chunk，让激活器重新附着
   - 随后物理破坏区块激活器，再移除 self forceload
   - 最终断言 3 个 `triggerSource` 变为 `online=false`

2. 不额外新增 `force_load` 物理破坏 case
   - 物理破坏的关键语义是“持久化条目删除”
   - resident 对 `triggerSource online` 的观测更直接、更稳定
   - 先覆盖这条核心生命周期，避免一次性扩面过大

3. 接入 functional matrix 与 lifecycle/full suite
   - 让该用例能单跑，也能随现有 dedicated 生命周期回归一起跑
