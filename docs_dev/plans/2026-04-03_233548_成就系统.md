# 成就系统

生成时间：2026-04-03 23:35:48
文件名：2026-04-03_233548_成就系统.md

## 任务背景
用户要求实现 `docs_dev/更新计划草稿与索引.md` 中“成就系统”条目，范围包括 4 个成就：
1. 根节点“无线时代”：第一次合成红石连接原件，万物互联的第一步
2. 分支“喂，来末地找我”：第一次进行主世界对末地的成功激活，超越维度
3. 分支“运筹帷幄”：第一次在状态面板订阅节点，决胜千里
4. 分支“星罗棋布”：第一次存在 `>=1` 对 `>=5` 连接，首个分布式控制枢纽

已确认标题采用“条件前面是标题，条件后面是描述”的口径；同时用户要求这些成就仅在生存/极限语义下达成，并把 `C:\Users\15166\Desktop\icons\a_*.png` 接入为对应成就图标。

## 方案详情

### 现状分析
当前仓库尚未存在 `advancement` 资源目录，也没有现成的自定义成就触发器注册。
现有服务端代码已经具备 4 个成就所需的稳定业务落点：
1. `redstone_link_component` 已注册为普通物品，可通过 `Item#onCraftedBy(...)` 精确捕获首次合成成功。
2. `LinkedTargetDispatchService.dispatchActivation(...)` 统一承接激活派发，适合收口“主世界对末地的成功激活”。
3. `StatePanelNetworkServerHandlerSupport.handleSubscribe(...)` 中 `StatePanelToolData.writeSubscriptions(...)` 后可以判断“本次是否新增订阅”。
4. `LinkSetExecutionService.applyPreparedReplace(...)` 是 command / pairing / quick-link / bench 共用的真实写入闭环，适合收口“首次达到 >=5 连接”。

成就图标不能直接在 advancement JSON 中引用任意 png；Minecraft 成就显示图标本质上是物品栈渲染，因此本次需要新增 4 个隐藏图标物品，并给这些物品配置模型与贴图，再在 advancement JSON 中引用。

### 技术方案
1. 新增统一的成就发放服务，集中封装成就 ID、玩家资格门禁与手动发奖逻辑。成就条件固定且一次性，不使用自定义 criterion trigger，而采用 `minecraft:impossible` + 服务端 `PlayerAdvancements.award(...)` 手动发放，减少协议与注册复杂度。
2. 把 `REDSTONE_LINK_COMPONENT` 改为自定义物品，在 `onCraftedBy(...)` 中发放根节点“无线时代”。
3. 扩展 `LinkedTargetDispatchService.DispatchSummary`，补充本次真正处理成功的目标序号快照；然后在具有 `ServerPlayer` 上下文的成功激活入口中，严格按“来源维度=主世界，且本次真正成功处理的目标中存在末地 core”发放“喂，来末地找我”。
4. 在状态面板订阅成功且本次确有新增订阅时发放“运筹帷幄”。
5. 在统一 replace 写入闭环中比较写入前后目标数量；当某个 `triggerSource` 首次从 `<5` 变为 `>=5` 时发放“星罗棋布”，从而覆盖 triggerSource/core 双视角写入。
6. 新增 4 个隐藏图标物品、对应模型与贴图资源，并编写 4 个 advancement JSON，形成完整成就树。
7. 补单测与集成测试覆盖关键发奖条件后，执行 `.\gradlew.bat test testIntegration testClient testSlow --no-daemon` 回归。
