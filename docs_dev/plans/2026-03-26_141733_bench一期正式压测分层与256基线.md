# bench一期正式压测分层与256基线

生成时间：2026-03-26 14:17:33
文件名：2026-03-26_141733_bench一期正式压测分层与256基线.md

## 任务背景
当前游戏内自动化测试已经具备 bench 单 case 执行、suite 编排、功能场景与轻量性能场景，但现有性能 case 规模偏轻，无法满足“正式压测至少从 256 起步，后续再扩到 512/1024”的目标。同时，命令/功能补测也需要从现有 `first-mandatory` 中拆出更清晰的独立入口，避免“轻量验证、功能回归、正式压测”混在一起。

## 方案详情

### 现状分析
- `tools/bench/lib/Bench.PlaceAndLink.ps1` 当前仅支持 `broadcast_all / fan_in_first / round_robin / zip` 几种 link 映射模式，无法自然表达 `256 x 256` 起步的规则化多对多连接。
- 现有 `tools/bench/matrix.json` 中的性能场景仅覆盖 `1->64 / 64->1 / 16->16 / 1->256 / 64->64`，更适合轻量回归，不适合作为正式压测门槛。
- 现有 suite 结构缺少“lite 与 baseline 分层”，`nightly-full.json` 仍直接引用当前轻量性能项。
- functional phase 当前没有“通用命令执行 + 中途重新取号/重新摆放”的能力，因此本轮不强行落地 `retire/reallocate`、`feedback loop` 等新功能 case，而先完成分层和 256 正式基线底座。

### 技术方案
- 在 `Bench.PlaceAndLink.ps1` 中新增适用于高规模多对多场景的规则化映射模式，首批支持“带宽式连续窗口”映射，用于表达每个 `triggerSource` 连接到固定数量的连续 `core`。
- 新增正式性能矩阵文件与 256 基线 case 文件，使“lite 性能场景”和“baseline-256 正式性能场景”分离。
- 新增 suite：
  - `performance-lite.json`：承接现有轻量性能 case。
  - `performance-baseline-256.json`：承接新的 256 正式性能 case。
  - `command-basic.json`：独立承接现有稳定功能/命令回归 case，作为后续扩充真正命令专项 case 的入口。
- 更新 `docs_dev/使用说明.md`，明确新的 suite/matrix 使用方式与分层定位。

### 影响范围
- `tools/bench/lib/Bench.PlaceAndLink.ps1`
- `tools/bench/matrix.json`
- `tools/bench/suites/*.json`
- `tools/bench/cases/performance/**`
- `docs_dev/使用说明.md`

## 原子步骤清单

### 步骤 1：扩展高规模建链映射模式
- **操作对象**：`tools/bench/lib/Bench.PlaceAndLink.ps1`
- **具体动作**：新增适用于正式压测的规则化多对多映射，至少支持 `banded16` 语义所需的参数读取与目标窗口计算。
- **预期结果**：case 定义可以自然表达 `256 x 256` 级别的多对多建链，不必手写海量 link。
- **关键里程碑**：是

### 步骤 2：新增 256 正式性能矩阵与 case
- **操作对象**：`tools/bench/` 下新的 matrix/case 文件
- **具体动作**：新增正式性能 matrix 和首批 256 场景，至少覆盖 `sync` 与 `mixed` 两类运行态压力。
- **预期结果**：bench 具备“lite 与正式 baseline”两套独立性能入口。
- **关键里程碑**：是

### 步骤 3：重组 suite 分层
- **操作对象**：`tools/bench/suites/*.json`
- **具体动作**：新增 `performance-lite.json`、`performance-baseline-256.json`、`command-basic.json`，并调整 `nightly-full.json` 的性能项引用，避免继续混用旧轻量性能 case 作为正式基线。
- **预期结果**：suite 结构清晰区分脚本烟雾、命令功能回归与正式性能压测。
- **关键里程碑**：是

### 步骤 4：补充使用说明
- **操作对象**：`docs_dev/使用说明.md`
- **具体动作**：补充新的 suite/matrix 执行命令与层级说明，明确旧性能项仅作 lite 验证。
- **预期结果**：后续执行与汇报时不会再混淆“轻量性能”和“正式压测”。
- **关键里程碑**：否

### 步骤 5：验证 bench 与主工程
- **操作对象**：bench 入口、suite 解析、Gradle 自动化测试
- **具体动作**：验证 `List/PrintCase`、suite/matrix 解析结果，并执行项目要求的全标签自动化测试门禁。
- **预期结果**：确认第一期改动未破坏 bench 主流程与主工程。
- **关键里程碑**：是

## 预期结果
第一期完成后，项目将具备清晰的 bench 分层：
- `performance-lite` 继续负责脚本/环境级轻量验证；
- `command-basic` 负责独立的游戏内命令/功能回归入口；
- `performance-baseline-256` 成为新的正式压测起点；
- 后续 `512/1024`、`mutation` 与 `feedback loop` 可在此基础上继续扩展，而无需回头返工底层映射与 suite 结构。
