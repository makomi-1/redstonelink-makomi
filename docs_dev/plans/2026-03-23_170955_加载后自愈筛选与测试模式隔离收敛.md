# 加载后自愈筛选与测试模式隔离收敛

生成时间：2026-03-23 17:09:55
文件名：2026-03-23_170955_加载后自愈筛选与测试模式隔离收敛.md

## 任务背景

当前 `triggerSource/core` 的加载后自愈已改成异步、非阻塞消费，但还存在三个待收敛点：

1. `triggerSource` 侧“有效 emitter”仍是区块级粗筛，入队范围偏宽。
2. 一部分测试/诊断能力与正常运行时能力还未完全隔离。
3. 有限重试仍是硬编码，且超过预算时缺少明确日志。

本轮目标是在不回退既有非阻塞方案的前提下，把这三点收敛为更清晰、可控、开销更低的一版。

## 方案详情

### 现状分析

- `TriggerSourceInputStateResyncService` 当前只要区块内存在 `LinkTriggerSourceBlockEntity + LinkSignalEmitterBlock` 就会入队，属于“候选粗筛”。
- `CoreBlockStateResyncService` 已具备节点级 `pendingLoadBlockStateSync` 标记，只消费确实待校正的 `core`。
- `InputPlaybackService`、`NodeStateTraceService` 目前仍在主入口无条件注册。
- `triggerSource/core` 两条自愈链路的最大重试次数都写死为 `40`，最终放弃时没有单独日志。

### 技术方案

1. 为 `LinkTriggerSourceBlockEntity` 增加节点级 `pendingLoadInputStateResync` 标记。
2. 在 `LinkTriggerSourceBlockEntity` 读档时重置纯运行态字段，并按当前方块/持久快照信息判断是否需要加载后重采样。
3. 在 `LinkSyncEmitterBlockEntity` 读档后补充同步发射器特有的“最近输入强度/重放快照”判据，避免只靠 `POWERED` 粗判。
4. 将 `TriggerSourceInputStateResyncService` 的入队与消费都收敛到“仅处理带 pending 标记的 emitter”。
5. 将 `core/triggerSource` 加载后自愈拆为独立运行时开关，默认开启，不与测试模式绑定。
6. 将输入器与 trace 这类测试/诊断能力挂到现有 `server.command.benchmarkMode.enabled`，关闭时不注册对应服务，命令树也不开放。
7. 将加载后自愈的最大重试次数抽成配置，并在超过预算后记录一次明确告警日志。

## 原子步骤清单

### 步骤 1：补 triggerSource 节点级待校正标记
- **操作对象**：`LinkTriggerSourceBlockEntity`、`LinkSyncEmitterBlockEntity`
- **具体动作**：增加 `pendingLoadInputStateResync` 读档判据与访问接口；同步发射器补充基于持久快照的判据
- **预期结果**：`triggerSource` 从“区块级粗筛”收敛为“节点级真筛”
- **关键里程碑**：是

### 步骤 2：收敛 triggerSource 自愈服务
- **操作对象**：`TriggerSourceInputStateResyncService`
- **具体动作**：只对带 pending 标记的 emitter 入队、消费并清理标记
- **预期结果**：无关 emitter 不再进入加载后静默重采样
- **关键里程碑**：是

### 步骤 3：补运行时配置开关
- **操作对象**：`RedstoneLinkConfig`、`RedstoneLink`
- **具体动作**：新增 `core/triggerSource` 自愈开关与共享重试预算；按 benchmarkMode 挂载测试/诊断服务
- **预期结果**：正常使用与测试能力的额外开销分层隔离
- **关键里程碑**：是

### 步骤 4：补最终放弃日志
- **操作对象**：`TriggerSourceInputStateResyncService`、`CoreBlockStateResyncService`
- **具体动作**：使用配置化预算；超过预算后输出一次明确日志
- **预期结果**：有限重试的边界可观测、可调
- **关键里程碑**：否

### 步骤 5：更新说明并回归验证
- **操作对象**：`docs_dev/使用说明.md`、Gradle 测试任务
- **具体动作**：补充新配置说明并执行定向/全量测试
- **预期结果**：文档与行为一致，确认无回归
- **关键里程碑**：是

## 预期结果

- `triggerSource` 加载后自愈从“存在 emitter 即入队”收敛为“存在待校正节点才入队”。
- 输入器与 trace 的额外运行时开销可通过测试模式统一隔离。
- `core/triggerSource` 自愈能力保留为正常运行时自愈，不会因为测试模式关闭而丢失。
- 有限重试不再是写死常量，最终放弃时也有日志可追踪。

## 语义对齐说明

- 本轮新增命名仅使用 `triggerSource/core`，无旧术语新增泄漏。
- 输入/输出方向未变化，仍保持 `triggerSource -> core`。
- 与 `LinkNodeType.TRIGGER_SOURCE/CORE` 映射保持一一对应。
- 不引入 `com.makomi.api.v1.*` 依赖。
- 不涉及持久化键“读旧写新”迁移；新增状态仅为运行态或内部配置项。
- 残余风险：`benchmarkMode` 关闭后，输入器与 trace 命令树会被隐藏，这属于有意收敛而非兼容缺陷。
