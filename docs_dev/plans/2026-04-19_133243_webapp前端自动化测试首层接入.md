# webapp前端自动化测试首层接入

生成时间：2026-04-19 13:32:43
文件名：2026-04-19_133243_webapp前端自动化测试首层接入.md

## 任务背景

当前网页前端已经承载 graph 草稿、搜索、聚合、编辑与保存等较复杂逻辑，但 `webapp` 目录还没有建立自动化测试体系。为了先补齐成本最低、收益最高的一层回归保护，本轮先接入前端测试基础设施，并覆盖两类测试：

1. 纯逻辑单测
2. React 组件测试

本轮只在 `webapp` 内实现，不接入 Gradle，不改服务端接口与真实保存语义。

## 方案详情

### 现状分析

- `webapp/package.json` 目前没有测试依赖与测试脚本。
- `webapp/vite.config.ts` 当前只有构建配置，没有 Vitest 测试配置。
- `webapp/tsconfig.json` 当前未包含测试环境类型。
- 目标模块中已经存在一批可直接测试的纯函数，包括：
  - `webapp/src/graphTypes.ts`
  - `webapp/src/app/storageApi.ts`
  - `webapp/src/components/graphViewer/draft.ts`
  - `webapp/src/components/graphViewer/search.ts`
  - `webapp/src/components/graphViewer/canvas.tsx` 中的纯构建函数
- 目标组件包括：
  - `webapp/src/App.tsx`
  - `webapp/src/app/GraphPage.tsx`
  - `webapp/src/components/GraphViewer.tsx`

### 技术方案

本轮采用 `Vitest + jsdom + @testing-library/react + @testing-library/user-event` 作为测试基建，并补一个统一的测试 setup 文件，集中处理 `ResizeObserver`、`matchMedia`、`requestAnimationFrame` 等浏览器能力 mock。

接口层模拟先使用 `mock fetch`，不引入 `MSW`。这样能以更小改动先打通页面测试与交互测试，后续若测试范围继续扩大，再考虑引入更完整的接口模拟层。

纯逻辑测试优先覆盖成功路径、失败路径与关键边界；组件测试优先覆盖页面加载、错误处理、基础用户交互，不把第一轮范围扩展到所有复杂画布几何细节。

### 影响范围

- `webapp/package.json`
- `webapp/vite.config.ts`
- `webapp/tsconfig.json`
- 新增测试 setup 与测试文件
- 可能补充少量仅为测试稳定性服务的前端辅助导出或测试工具文件

## 原子步骤清单

### 步骤 1：接入前端测试基建
- **操作对象**：`webapp/package.json`、`webapp/vite.config.ts`、`webapp/tsconfig.json`、测试 setup 文件
- **具体动作**：新增 Vitest 与 Testing Library 依赖、测试脚本、Vitest 配置与 jsdom 基础 mock
- **预期结果**：`webapp` 可运行单测和组件测试
- **关键里程碑**：是

### 步骤 2：补纯逻辑单测
- **操作对象**：`webapp/src/graphTypes.test.ts`、`webapp/src/app/storageApi.test.ts`、`webapp/src/components/graphViewer/draft.test.ts`、`webapp/src/components/graphViewer/search.test.ts`、`webapp/src/components/graphViewer/canvas.test.ts`
- **具体动作**：为解析、请求、草稿折算、搜索匹配、画布构建等纯函数补充测试
- **预期结果**：关键纯逻辑具备基础回归覆盖
- **关键里程碑**：是

### 步骤 3：补组件测试
- **操作对象**：`webapp/src/App.test.tsx`、`webapp/src/app/GraphPage.test.tsx`、`webapp/src/components/GraphViewer.test.tsx`
- **具体动作**：模拟 `/api/**` 请求和基础浏览器环境，验证加载、错误处理与关键交互
- **预期结果**：页面级关键流程具备基础回归覆盖
- **关键里程碑**：是

### 步骤 4：执行验证并收束
- **操作对象**：`webapp` 测试命令、必要的类型检查与实现修正
- **具体动作**：运行测试，修复失败点，确认首轮测试体系可以稳定执行
- **预期结果**：形成可复用的前端自动化测试基础
- **关键里程碑**：是

## 预期结果

- `webapp` 具备可直接运行的单测和组件测试能力。
- graph 草稿、搜索、画布构建等高频易回归逻辑有了自动保护。
- App / GraphPage / GraphViewer 至少具备一层可持续扩展的页面测试骨架。
- 本轮不改真实保存语义，仍保持 `triggerSource -> core` 真值路径不变。
