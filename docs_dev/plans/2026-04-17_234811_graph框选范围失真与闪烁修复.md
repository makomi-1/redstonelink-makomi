# graph框选范围失真与闪烁修复

生成时间：2026-04-17 23:48:11
文件名：2026-04-17_234811_graph框选范围失真与闪烁修复.md

## 任务背景

graph 视图已接入 ReactFlow 框选作为批量编辑选择入口，但当前存在一组同链路问题：实际只框到部分节点时，右侧统计和画布高亮会被放大；框选过程中主画布会闪烁、不稳定。目标是在不改 `triggerSource/core` 真值、snapshot、draft 和服务端语义的前提下，修复框选命中和状态同步。

## 方案详情

### 现状分析

- 现有框选使用 `SelectionMode.Partial`，选框擦到节点也会命中，口径偏宽
- 批量选择结果会进入 `forcedVisibleNodeKeys`，拖框过程中主画布可见节点集和聚合展开态会跟着变化
- 节点 `selected` 又被外部批量选择集合强控，ReactFlow 内部选区与业务选择状态相互拉扯

### 技术方案

本轮将框选链路收敛为单向数据流：

1. 把框选命中口径切到 `SelectionMode.Full`
2. 解除批量选择结果对主画布可见性和“保活理由”的反向驱动
3. 不再用外部批量选择集合直接驱动 ReactFlow 节点 `selected`，重建节点时保留当前画布真实选中态

这样可以把“选框命中”“业务选择”“主画布拓扑可见性”三层解耦，避免拖框时画布结构变化反过来污染选区结果。

### 影响范围

- `webapp/src/components/GraphViewer.tsx`
- `docs_dev/reviews/` 审查文档

## 原子步骤清单

### 步骤 1：收紧框选命中口径
- **操作对象**：`webapp/src/components/GraphViewer.tsx`
- **具体动作**：将 ReactFlow 的 `selectionMode` 从 `Partial` 调整为 `Full`
- **预期结果**：只有完全落入选框的节点才被选中
- **关键里程碑**：是

### 步骤 2：解除批量选择对主画布可见性的反向驱动
- **操作对象**：`webapp/src/components/GraphViewer.tsx`
- **具体动作**：将批量选择集合从 `forcedVisibleNodeKeys` 及相关“保活理由”中移除
- **预期结果**：拖框时主画布可见节点集不再跟着变化，闪烁收敛
- **关键里程碑**：是

### 步骤 3：解除节点 selected 的外部强控
- **操作对象**：`webapp/src/components/GraphViewer.tsx`
- **具体动作**：不再用批量选择集合直接回写节点 `selected`，节点重建时保留当前 ReactFlow 真实选中态
- **预期结果**：ReactFlow 内部选区与右侧批量选择结果保持一致，不再互相放大
- **关键里程碑**：是

### 步骤 4：回归验证
- **操作对象**：`webapp` 与 Gradle 构建测试链路
- **具体动作**：执行 `npm.cmd run typecheck`、`.\gradlew.bat buildWebapp --no-daemon`、`.\gradlew.bat test testIntegration testClient testSlow --no-daemon`
- **预期结果**：确认修复未引入新的前端或集成回归
- **关键里程碑**：是

## 预期结果

框选结果严格贴近实际选框范围，右侧统计与画布高亮不再被放大；拖框过程中主画布不再因拓扑可见节点变化而闪烁或不稳定。
