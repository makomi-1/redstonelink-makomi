# P4 serial模式显式保存编辑第一版

生成时间：2026-04-17 11:34:38
文件名：2026-04-17_113438_P4_serial模式显式保存编辑第一版.md

## 任务背景

现有整体方案文档已定义 `P4` 为“serial 模式显式保存编辑”。当前仓库已经完成：

- `P3` serial 模式只读可视化网络分析器
- graph 快照导出、客户端本地落盘与独立网页查看页
- 节点别名持久化能力
- `triggerSource -> core` 正向覆盖写入能力
- OCC 冲突判定与现有写控能力

但网页端仍然只能只读分析，尚未具备“本地草稿 + 主动保存”的编辑闭环。因此本轮以最小可交付范围推进 `P4`，先让 graph 页面支持显式保存编辑第一版，不提前进入自由拖线、频道模式编辑或独立编辑器物品入口。

## 方案详情

### 现状分析

- 服务端已有 `NodeAliasSavedData`，可直接承接节点别名保存。
- 服务端已有 `LinkSetExecutionService`、`LinkOccSupport`，可直接承接 `triggerSource -> core` 正向覆盖写入与 OCC 冲突判定。
- 客户端已有 `LocalWebAppBridgeService` 与 `LocalWebAssetRepository`，可以继续作为网页和游戏之间的本地离线桥接层。
- 网页端 `graph` 页目前已经具备图展示、节点详情、文件加载等基础，但没有草稿模型、保存 RPC、冲突提示与未保存提醒。

### 技术方案

1. 定义 `GraphDraft` 与 `GraphWriteIntent` 的最小结构：
   - 草稿仅保存在客户端本地，不进入服务端真值层
   - 写入意图只使用结构化操作，不做整图覆盖
2. 新增 graph save 网络与 bridge 链路：
   - 网页通过本地 HTTP RPC 提交保存请求
   - 客户端转发 C2S graph save payload
   - 服务端执行后回传保存结果
3. 服务端复用现有真值能力：
   - 别名编辑复用 `NodeAliasSavedData`
   - 拓扑编辑复用 `LinkSetExecutionService`
   - 冲突判定复用 `LinkOccSupport`
4. 网页端 graph 页面升级为“编辑器第一版”：
   - 节点别名编辑
   - 单个 `triggerSource` 的目标集合编辑
   - `Save` 按钮
   - `clean / dirty / saving / conflict` 状态机
   - 页面关闭前未保存提醒

### 技术取舍

- 第一版只做 `serial` 模式，不做 `channel` 模式编辑。
- 第一版只做“结构化保存”，不做自由拉线，避免将复杂图交互和真值写回耦合到一起。
- 第一版先支持单个 `triggerSource` 的目标集合编辑，而不直接进入多来源 `n -> m` 批量编辑 UI，优先保证写入语义和冲突处理闭环稳定。
- 草稿、布局、筛选状态继续只写客户端本地文件，不写入 `LinkSavedData`、状态面板物品 NBT 或其他服务端持久化真值。

## 预期结果

完成后，玩家可在独立 `graph` 页面中加载 graph 文件、查看 serial 拓扑，并对节点 alias 与单个 `triggerSource` 的目标集合进行本地编辑；只有点击 `Save` 后，结构化写入意图才会经由本地 bridge 和网络链路进入服务端真值层。保存成功后清理 dirty，冲突时保留本地草稿并提示刷新。当前阶段不包含 `channel` 模式编辑、自由拉线、多来源 `n -> m` 批量编辑 UI，也不接入状态面板入口。
