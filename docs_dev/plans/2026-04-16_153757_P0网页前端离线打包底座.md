# P0 网页前端离线打包底座

生成时间：2026-04-16 15:37:57
文件名：2026-04-16_153757_P0网页前端离线打包底座.md

## 任务背景

本轮按已确认的整体方案从 `P0` 起步，实现“网页前端工程 + 离线打包 + 客户端本地桥接”的最小可运行闭环。

当前阶段不接入录制结果、拓扑快照、保存 RPC，也不提前改录制 GUI 语义；目标仅是把后续网页主处理能力所需的底座先搭起来。

## 方案详情

### 现状分析

- 仓库当前没有独立前端工程，也没有 `package.json`、`vite.config.*`、`tsconfig*.json` 等网页构建入口。
- 现有资源打包仍以 `src/main/resources/**` 为核心，`build.gradle` 仅处理 Fabric 资源展开，尚未接入前端静态资源构建。
- 客户端当前有独立命令根 `/rlclient`，适合作为 `P0` 的最小网页入口，避免过早侵入状态面板录制 GUI。
- 代码库中尚无现成 `localhost`/HTTP/browser bridge，因此需要新增客户端本地桥接服务。

### 技术方案

#### 1. 前端工程目录

在仓库根目录新增 `webapp/`，采用：

- `React`
- `TypeScript`
- `Vite`

首版仅提供一个首页：

- 展示 `RedstoneLink Web Tools`
- 调用本地 `/api/ping`
- 显示当前离线桥接状态和 `P0` 说明

当前不引入录制页、图编辑页与 `React Flow` 业务代码，避免提前铺开未使用依赖。

#### 2. 构建与打包集成

Gradle 中新增 `npmInstallWebapp` 与 `buildWebapp` 任务：

- `npmInstallWebapp`
  - 在 `webapp/` 内执行安装
- `buildWebapp`
  - 调用 `npm run build`
  - 将产物输出到 `build/generated/redstonelink-webapp`

再由 `processResources`：

- 依赖 `buildWebapp`
- 将 `build/generated/redstonelink-webapp/**` 打进 `assets/redstonelink/webapp/**`

这样可以保证：

- 运行时网页资源不污染源码目录
- 最终 Jar 内具备完整离线网页资源
- `runClient/build` 走同一条资源打包链路

#### 3. 客户端本地桥接最小壳

新增客户端 `web` 包，提供一个单例桥接服务：

- 监听 `127.0.0.1` 随机端口
- 仅暴露本地 HTTP
- 从 classpath/Jar 提供 `assets/redstonelink/webapp/**`
- 提供最小数据接口 `GET /api/ping`

`/api/ping` 返回内容只用于验链，不承载业务数据，建议包括：

- `status`
- `modId`
- `bridgeVersion`
- `startedAtEpochMillis`
- `mode=offline-embedded`

#### 4. 游戏内最小入口

在现有客户端命令根 `/rlclient` 下增加：

- `/rlclient web open`

行为：

- 若本地桥未启动，则先启动
- 打开系统浏览器到本地首页
- 反馈打开结果或失败原因

当前不改状态面板录制按钮，也不新增服务端协议，避免与 `P2` 录制 GUI 任务耦合。

#### 5. 语义与边界

- 本轮不新增任何 `triggerSource/core` 写路径。
- 不引入 `com.makomi.api.v1.*` 依赖。
- 本轮网页只读且只做桥接验链，不产生世界真值修改。
- 录制结果、图快照、草稿持久化目录设计保留到 `P1/P2/P3` 再接入。

### 影响范围

- `build.gradle`
- `.gitignore`
- 新增 `webapp/**`
- 新增客户端 `web` 本地桥接类
- `RedstoneLinkClient.java`

## 预期结果

完成后，项目将具备一个可离线打包进 Mod 的网页前端底座：

- 仓库内存在独立 `webapp/` 工程
- Gradle 能自动构建并打包网页资源
- 客户端可启动本地桥接服务并打开系统浏览器
- 网页首页能够通过 `/api/ping` 验证桥接链路

这一步只解决“网页能否成为后续主处理容器”的基础问题，不提前承诺录制或图编辑业务闭环。
