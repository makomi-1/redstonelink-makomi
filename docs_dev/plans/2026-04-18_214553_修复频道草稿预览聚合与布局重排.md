# 修复频道草稿预览聚合与布局重排

生成时间：2026-04-18 21:45:53
文件名：2026-04-18_214553_修复频道草稿预览聚合与布局重排.md

## 任务背景

当前 graph 可视化在批量“应用到草稿”后存在两类问题：

1. 频道模式下，草稿变更节点会被强制显示，但所属聚合块仍保持折叠，导致成员节点直接出现在主画布中却没有上下文连线，视觉上像重复或自发展开。
2. 所有模式下，批量应用草稿后仍尽量复用旧坐标，结构已经变化但位置未同步重排，导致预览区域错位、挤压或跑到无关区域。

本轮只修前端视图层与草稿预览行为，不改 snapshot、draft 持久化格式和服务端真值语义。

## 方案详情

### 现状分析

- `GraphViewer.tsx` 会把 `draftDiff.changedNodeKeys` 直接并入 `forcedVisibleNodeKeys`，草稿变更节点会被强制显示。
- `canvas.tsx` 的频道模式会为 channel hub 两侧生成核心聚合块和 triggerSource 聚合块，并隐藏对应真实边。
- 频道模式当前没有像序号模式那样，根据被强制显示的成员节点自动把所属聚合块切到展开态。
- `handleApplyBatchEdit()` 在成功写入草稿后没有触发布局结构刷新，因此 React Flow 会保留旧位置映射。

### 技术方案

1. 对齐频道模式与序号模式的聚合语义：
   - 频道核心聚合块若命中被强制显示的 core 成员，则自动视为展开。
   - 频道 triggerSource 聚合块若命中被强制显示的 triggerSource 成员，则自动视为展开。
   - 保持 `triggerSource/core` 术语与方向不变，仅修画布层可见性口径。
2. 批量应用草稿后，统一触发一次结构布局重排：
   - 仅在 `applyLocalDraftChange(nextDraft)` 成功时触发。
   - 使用结构刷新而非继续复用旧坐标，避免预览残留旧拓扑位置。
   - 本次批量应用后不做整图自动 `fitView`，避免把编辑上下文跳到全局中心。

### 影响范围

- `webapp/src/components/GraphViewer.tsx`
- `webapp/src/components/graphViewer/canvas.tsx`

## 原子步骤清单

### 步骤 1：修正频道聚合块展开口径
- **操作对象**：`webapp/src/components/graphViewer/canvas.tsx`
- **具体动作**：让频道模式生成聚合块时也根据 `forcedVisibleNodeKeys` 判断是否自动展开，避免草稿变更成员在折叠聚合下被单独显露。
- **预期结果**：频道模式草稿预览不再出现“成员节点裸露、无上下文、看似重复”的情况。
- **关键里程碑**：是

### 步骤 2：批量草稿应用后触发结构重排
- **操作对象**：`webapp/src/components/GraphViewer.tsx`
- **具体动作**：在批量应用到草稿成功后请求结构布局刷新，并关闭本次整图自动归位。
- **预期结果**：所有模式下草稿预览生成后不再沿用旧拓扑坐标，局部预览更稳定。
- **关键里程碑**：是

### 步骤 3：回归验证与审查文档
- **操作对象**：前端构建与测试脚本、`docs_dev/reviews/`
- **具体动作**：执行类型检查、webapp 构建、Gradle 全量测试，并输出审查文档。
- **预期结果**：确认改动未破坏现有 graph 视图与草稿保存链路。
- **关键里程碑**：是

- 所有模式应用到草稿后，预览节点位置会按新结构重新排布，不再明显复用旧布局。
