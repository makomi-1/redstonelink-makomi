## 任务背景
当前 dedicated bench 中，`x48_chunk_activator_resident_core` 仍未跑通。已有代码分析显示 resident/core 贡献的生效与撤销链路在实现上闭合，因此需要先核对 bench 用例自身是否存在观测或预加载口径问题。同时需要给出“跨区块命令是否支持直接查看/修改区块激活器节点集”的结论。

## 方案详情

### 现状分析
- `x48` 使用显式 `benchForceLoadZones` 维持场地初始化与驱动所需区块加载。
- 用例中的占位 source 放在 `256 64 722`，会把显式预加载区扩到额外的 `z=45` chunk。
- 用例后续只执行了 `forceload remove 256 718 256 718` 与 `forceload remove 272 718 272 718`，释放范围仅覆盖 `z=44`，与预加载范围不完全对齐。
- 因此需要先修 bench 用例口径，避免把预加载残留误判成 resident 撤销失败。

### 技术方案
- 保持 resident/core 业务实现不变，只最小修改 `x48` 用例：
  - 将占位 source 调整到与目标 core 同一 chunk。
  - 同步收窄 `benchForceLoadZones`，确保显式预加载范围与后续释放范围一致。
- 之后复用现有 build-sync dedicated 脚本重跑 `x47/x48`，确认：
  - `x47` 继续通过；
  - `x48` 在 dedicated 下通过“保持在线”和“撤销后离线”两段断言。
