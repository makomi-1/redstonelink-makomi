# 修复活塞回拉核心邻居输出与转化器GUI提示

生成时间：2026-05-04 12:16:30
文件名：2026-05-04_121630_修复活塞回拉核心邻居输出与转化器GUI提示.md

## 任务背景

当前无线化活塞已经可以推拉可见 `core`，但在把 `core` 拉回原位后，只恢复了节点序号与方块外显，没有把原版应有的邻居输出同步补发，导致周围红石网络不能立即按恢复后的输出状态收敛。  
同时，无线化转化器 GUI 仍缺少槽位 tooltip，而同类问题此前已经在智能节点容器界面中通过“在 render 末尾统一自行解析悬停槽位”的方式解决。

## 方案详情

### 现状分析

- 无线化活塞搬运恢复链位于 `WirelessPistonNodeMoveSupport`，当前恢复完成后只会：
  - 重新载入节点快照；
  - 取消待退役；
  - 对 `ActivatableTargetBlockEntity` 调用 `consumePendingLoadBlockStateSync()`，仅同步 blockstate/原版表现。
- 可见 `core` 的正常邻居输出补发逻辑不在 `consumePendingLoadBlockStateSync()`，而是在 `LinkCoreBlockEntity.onActiveChanged()` 中，通过 `NeighborFanoutUtil.notifyCenterAndSixNeighbors(...)` 触发。
- 因为活塞恢复时没有经过 `onActiveChanged()` 这条路径，所以回拉后的可见 `core` 缺少一次邻居输出重放。
- `WirelessConverterScreen` 当前只有背景绘制，没有像 `SmartNodeContainerScreen` 那样覆写 `render()` / `renderTooltip()` 并手动补槽位 tooltip。

### 技术方案

1. 在无线节点活塞恢复链中，为“可见 `core`”补一层恢复后的邻居输出重放：
   - 仍保留现有 `consumePendingLoadBlockStateSync()` 负责恢复方块外显；
   - 在其后识别当前恢复目标是否属于可见 `core` 方块实体；
   - 复用已有 `NeighborFanoutUtil.notifyCenterAndSixNeighbors(...)`，按当前解析输出强度补发一次邻居更新；
   - 保持最小范围，只先覆盖已经接入活塞搬运协议的可见 `core`。
2. 为无线化转化器 GUI 复用智能节点容器的 tooltip 修法：
   - 在 `WirelessConverterScreen.render()` 末尾统一绘制悬停槽位 tooltip；
   - 覆写空的 `renderTooltip()`，避免继续依赖父类内部 `hoveredSlot`；
   - 本地重新解析当前鼠标命中的槽位，仅在未拖拽物品且槽位有物品时绘制 tooltip。

### 影响范围

- 服务端活塞恢复链：`WirelessPistonNodeMoveSupport`
- 可见 `core` 邻居更新：复用既有 `NeighborFanoutUtil`
- 客户端 GUI：`WirelessConverterScreen`
