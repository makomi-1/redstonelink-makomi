# 快速连接工具中键触发修复方案

生成时间：2026-03-30 15:17:08
文件名：2026-03-30_151708_快速连接工具中键触发修复方案.md

## 任务背景

调试中发现：主手手持快速连接工具时，鼠标中键并未进入 `handleQuickLinkClear(client)` 断点，导致“中键清空缓存”功能实际上没有触发。

## 方案详情

### 现状分析

- 当前实现依赖 `client.options.keyPickItem.consumeClick()`。
- `keyPickItem` 属于原版绑定，原版主循环本身会消费该点击。
- 因此到了客户端 `END_CLIENT_TICK` 时，quick-link 侧再调用 `consumeClick()` 可能已经拿不到点击计数。

### 技术方案

- 不再依赖 `consumeClick()` 读取中键。
- 改为基于 `client.options.keyPickItem.isDown()` 做上升沿检测：
  - 当前 tick 为按下
  - 上一 tick 为未按下
  - 仅在该时刻触发一次 quick-link 清空
- 继续保留原有限制：主手持快速连接工具、GUI 未打开、只清空缓存不切模式。

### 影响范围

- 客户端 quick-link 输入轮询
- 本轮方案文档

## 原子步骤清单

### 步骤 1：替换中键触发判定
- **操作对象**：`src/client/java/com/makomi/RedstoneLinkClient.java`
- **具体动作**：增加中键上一帧状态缓存，并用 `isDown()` 上升沿替代 `consumeClick()`
- **预期结果**：中键清空可稳定进入处理方法
- **关键里程碑**：是

### 步骤 2：执行全量回归
- **操作对象**：Gradle 测试任务
- **具体动作**：执行 `.\gradlew.bat test testIntegration testClient testSlow --no-daemon`
- **预期结果**：确认修复未破坏现有 quick-link 行为
- **关键里程碑**：是

## 预期结果

- 中键按下时可稳定触发 quick-link 缓存清空
- 长按中键只触发一次，松开后再次按下才会再次清空
- 其余 quick-link 交互语义不变
