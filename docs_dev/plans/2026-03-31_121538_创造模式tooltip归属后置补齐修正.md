# 创造模式 tooltip 归属后置补齐修正

生成时间：2026-03-31 12:15:38
文件名：2026-03-31_121538_创造模式tooltip归属后置补齐修正.md

## 任务背景
上一版创造模式 tooltip 归属补齐实现挂在物品 `appendHoverText(...)` 阶段。  
实际观察表明，带序号物品在“刚取出时”能短暂显示归属，但序号分配完成后蓝色归属又消失，说明真正漏掉归属的是创造模式界面的后置处理阶段，而不是物品自身基础 tooltip 阶段。

## 方案详情

### 现状分析
- 原版创造模式在 `CreativeModeInventoryScreen.getTooltipFromContainerItem(...)` 中，会在拿到物品 tooltip 结果后，再按创造标签归属补一行蓝色标签名。
- 带序号物品在持有阶段会写入运行时组件，导致原版后置阶段按“物品类型 + 组件”匹配创造标签时失败。
- 上一版仅在 `appendHoverText(...)` 里补齐，时机过早，无法稳定覆盖创造界面最终结果。

### 技术方案
- 保留现有公共 tooltip 归属支持工具。
- 新增客户端 mixin，注入 `CreativeModeInventoryScreen.getTooltipFromContainerItem(...)` 的 `RETURN`。
- 仅当满足以下条件时，对返回 tooltip 做后置补齐：
  - 当前物品属于 `redstonelink` 命名空间；
  - 当前物品栈组件已偏离默认实例；
  - 当前 tooltip 尚未包含蓝色 `RedstoneLink` 归属行。
- 插入位置仍保持在 tooltip 第 2 行，与原版归属字段位置一致。

### 影响范围
- `src/client/java/com/makomi/client/mixin/**`
- `src/main/resources/redstonelink.client.mixins.json`
- `src/main/java/com/makomi/item/CreativeTooltipOriginSupport.java`

- **具体动作**：补充“是否本模组物品 / 是否组件偏离默认实例 / 是否已存在归属行 / 直接补行”公共方法，供 item 与 screen 层复用
- **预期结果**：创造模式归属判断逻辑集中，避免重复实现
- **关键里程碑**：是

- **操作对象**：`CreativeModeInventoryScreen` client mixin 与 client mixin 配置
- **具体动作**：在 `getTooltipFromContainerItem(...)` 返回后，对缺失归属的带组件偏移物品追加蓝色 `RedstoneLink`
- **预期结果**：带序号物品在序号分配后仍能稳定显示归属行
- **关键里程碑**：是
