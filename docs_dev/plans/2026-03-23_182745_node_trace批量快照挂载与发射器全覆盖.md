## 任务背景

当前 `node trace` 首版只支持单节点 `latest/mount/read/unmount`，并且 `triggerSource` 只覆盖在线 `sync` 来源。现计划扩展为：

1. 支持批量即时快照
2. 支持批量挂载
3. 支持批量卸载
4. 实现发射器全覆盖，至少覆盖 `pulse/toggle/sync emitter`
5. 本轮不做 `read` 批量化

## 方案详情

### 现状分析

- `ModCommands` 中 `node trace` 相关命令仍按单个 `serial` 构建。
- `NodeStateTraceService` 已按 `type + serial` 维护独立挂载状态，命令层可以直接循环复用，不必额外引入批量 service API。
- `NodeRuntimeProbe` 当前仅支持 `CORE` 与 `SYNC_TRIGGER_SOURCE`。
- 普通发射器输入强度语义已在 `LinkSignalEmitterBlock.resolveInputSignalStrength(...)` 中统一定义。

### 技术方案

1. 扩展 `NodeRuntimeProbe.TraceNodeKind`
   - 新增 `PULSE_TRIGGER_SOURCE`
   - 新增 `TOGGLE_TRIGGER_SOURCE`
   - 保留 `SYNC_TRIGGER_SOURCE`

2. 扩展 `NodeRuntimeProbe.resolveCurrent(...)`
   - `core` 仍直接返回 `CORE`
   - 在线 `LinkPulseEmitterBlockEntity` 返回 `PULSE_TRIGGER_SOURCE`
   - 在线 `LinkToggleEmitterBlockEntity` 返回 `TOGGLE_TRIGGER_SOURCE`
   - 在线 `LinkSyncEmitterBlockEntity` 返回 `SYNC_TRIGGER_SOURCE`
   - 其他 `triggerSource` 暂不支持

3. 扩展 `NodeRuntimeSnapshot`
   - 保持统一 DTO
   - 新增通用发射器字段：
     - `visiblePowered`
     - `runtimeInputPower`
   - 保证 `pulse/toggle/sync emitter` 都能在同一输出结构中表达

4. 命令层新增批量分支
   - 复用 `SerialBatchArgumentType`
   - 新增：
     - `/redstonelink node trace latest <type> <serials>`
     - `/redstonelink node trace mount <type> <serials> [every] [capacity]`
     - `/redstonelink node trace unmount <type> <serials>`
   - 保留现有单节点分支

5. `read` 本轮保持单节点
   - 避免命令输出量爆炸
   - 后续若需要批量历史，建议单独做 `dump/export` 类命令
