# 转发器退役匹配与快照显示修复

生成时间：2026-04-25 11:10:37
文件名：2026-04-25_111037_转发器退役匹配与快照显示修复.md

## 任务背景
本轮需要一并修复转发器在正常挖掘、掉落、拾取、再放置过程中的误退役问题，以及由此引发的物品 tooltip、编辑器和放置后连接关系显示不一致问题。

在现有实现中，转发器会共用同一个统一序号来承载 `triggerSource/core` 双身份，但待退役匹配链对掉落物仅按单一身份识别，导致正常掉落时仍可能保留另一侧待退役任务，最终把图真值错误退役。同时，转发器物品把“连接关系摘要”和“自身配置”混在同一份快照中，旧号失效后序号会重新分配，但旧连接摘要仍残留在物品缓存里，造成 tooltip 仍显示旧连接而编辑器/放置按图真值为空。

除根因修复外，本轮还要补齐以下用户可见行为：

- 转发器物品 tooltip 改成和其它节点一致的“序号 + 别名合并显示”
- QTL 采集转发器时按当前缓存类型采对应身份：`triggerSource/core`
- 转发器近外显 HUD 新增一行：`跨区块身份（t/c）：<triggerSource身份>/<core身份>`

## 方案详情

### 现状分析
- 转发器掉落物当前仍以统一物品形态存在，但待退役匹配层没有显式处理“双身份共用一个物品”的例外情况。
- 转发器物品快照中，`delay` 属于物品自身配置，而输入/输出连接关系本质上应以服务端图真值为准；这两个维度当前没有明确拆开。
- 转发器 tooltip、QTL 采集和近外显 HUD 分散在不同模块，需要统一按 `triggerSource/core` 双身份语义收口。

### 技术方案
1. 在待退役匹配层为转发器增加双身份识别逻辑：
   - 当物品为转发器且序号匹配时，允许它同时命中同号 `triggerSource/core` 两种待退役键。
   - 保持转发器统一物品模型不变，不修改普通节点与通用 `PairableItem` 的现有语义。

2. 拆分转发器物品快照的权威边界：
   - 连接关系按服务端图真值解析，不再直接相信物品上残留的旧输入/输出摘要。
   - `delay` 等自身配置继续保存于物品缓存，保证物品可脱离世界独立携带这些设置。
   - 当旧序号失效并重分配新序号时，清理不再适用的旧连接展示缓存。

3. 调整转发器物品 tooltip 与相关显示：
   - 统一改成“序号 + 别名合并显示”。
   - 输入/输出摘要继续显示，但数据源改为图真值。

4. 扩展 QTL 与近外显：
   - QTL 采集转发器时，按当前缓存类型采 `triggerSource/core` 对应身份。
   - 近外显 HUD 新增双身份跨区块状态行，并保持现有亮绿色转发器主题。

5. 为上述行为补测试并完成回归验证。

## 原子步骤清单

### 步骤 1：修复转发器待退役匹配
- **操作对象**：`LinkNodeRetireMatchSupport` 及相关退役入口
- **具体动作**：为转发器物品增加同号 `triggerSource/core` 双身份匹配能力
- **预期结果**：正常掉落或背包持有转发器时，两侧待退役都能被正确取消
- **关键里程碑**：是

### 步骤 2：拆分转发器物品缓存权威
- **操作对象**：`RepeaterItemData`、`RepeaterGraphSnapshotSupport`、`RepeaterBlockItem`
- **具体动作**：把连接关系改为按图真值读取，保留 `delay` 等自身配置走物品缓存；必要时清理旧连接展示缓存
- **预期结果**：tooltip、编辑器、放置后三处对连接关系显示一致
- **关键里程碑**：是

### 步骤 3：统一 tooltip 显示
- **操作对象**：`RepeaterBlockItem`
- **具体动作**：改成和其它节点一致的“序号 + 别名合并显示”
- **预期结果**：转发器物品 tooltip 与其它节点风格统一
- **关键里程碑**：否

### 步骤 4：扩展 QTL 采集与近外显 HUD
- **操作对象**：QTL 采集逻辑、转发器近外显数据/渲染逻辑
- **具体动作**：按缓存类型采 `triggerSource/core` 对应身份；新增 `跨区块身份（t/c）` 行
- **预期结果**：QTL 与近外显都能体现转发器双身份语义
- **关键里程碑**：是

### 步骤 5：补测试与回归
- **操作对象**：`src/test/java/**`
- **具体动作**：补待退役匹配、物品快照显示、QTL/HUD 相关测试并执行回归
- **预期结果**：关键回归点可复现并被自动化锁住
- **关键里程碑**：是

## 预期结果
- 转发器正常挖掘、掉落、拾取、再放置不会误退役图真值。
- 转发器物品在序号变化时不会再残留旧连接摘要，tooltip、编辑器和放置后的连接视图保持一致。
- 转发器物品 tooltip 改为“序号 + 别名合并显示”。
- QTL 采集转发器时能按当前缓存类型采对应身份。
- 转发器近外显 HUD 能同时显示 `triggerSource/core` 两侧跨区块身份。
