# 第二层归并改为操作命中打票据

生成时间：2026-03-29 16:30:38
文件名：2026-03-29_163038_第二层归并改为操作命中打票据.md

## 任务背景

当前第二层实现采用“菜单默认后处理扫描，再通过手动布局保持抑制”的方式执行自动归并。  
该语义与当前需求不一致：用户明确要求第二层只在命中特定原版操作后，才由服务器在下一 tick 消费一次归并。

本轮明确收敛后的触发源只有三类：

- `shift` 快速移动
- 双击同类物品
- `shift` 点击结果槽，对应原版批量合成命中

手动拆分、右键放一、普通手动整理不应触发第二层归并。

## 方案详情

### 现状分析

- 现有第二层服务 `PairableItemAggregateMenuNormalizationService` 仍会在 `END_SERVER_TICK` 默认扫描当前菜单。
- 这导致第二层即使没有命中特定原版操作，也可能介入菜单整理，语义过宽。
- 目标操作都位于原版 `AbstractContainerMenu.clicked(...)` / `doClick(...)` / `quickMoveStack(...)` 体系内，无法仅靠第一层物品级 hook 精确识别。
- 工程当前已经启用了客户端 mixin 配置，可复用同一 mixin 机制新增最小范围的通用菜单注入。

### 技术方案

- 新增通用 mixin 配置 `redstonelink.mixins.json`，用于服务端/通用逻辑注入。
- 在 `AbstractContainerMenu.clicked(...)` 的 `RETURN` 位置注入最小 mixin，只负责“命中识别 + 打一次归并票据”。
- 票据触发规则收敛为：
  - `ClickType.QUICK_MOVE` 且目标槽不是结果槽：记为 `shift` 快移命中
  - `ClickType.QUICK_MOVE` 且目标槽是结果槽：记为批量合成命中
  - `ClickType.PICKUP_ALL`：记为双击同类命中
  - 其他点击类型：不打票据
- 票据按“菜单 + 分区 + 物品类型”维度登记，分区仍保持：
  - `Slot.container`
  - `Slot` 运行时类
  - `Item`
- `PairableItemAggregateMenuNormalizationService` 改为“票据消费器”：
  - `END_SERVER_TICK` 只消费当 tick 已打的票据
  - 对被命中的分区执行一次归并
  - 消费后立即移除票据
- 删除当前“默认自动归并 + 手动布局保持”相关逻辑，避免与新语义冲突。

## 原子步骤清单

### 步骤 1：新增通用 mixin 配置
- **操作对象**：`fabric.mod.json`、`redstonelink.mixins.json`
- **具体动作**：为菜单层触发注入增加 common/server mixin 入口
- **预期结果**：工程可加载第二层触发 mixin
- **关键里程碑**：是

### 步骤 2：实现菜单命中打票
- **操作对象**：`AbstractContainerMenu` mixin
- **具体动作**：在 `clicked(...)` 返回后识别 `QUICK_MOVE`、结果槽 `QUICK_MOVE`、`PICKUP_ALL`
- **预期结果**：只有指定原版操作才会登记归并票据
- **关键里程碑**：是

### 步骤 3：将第二层服务改为票据消费器
- **操作对象**：`PairableItemAggregateMenuNormalizationService`
- **具体动作**：移除默认自动扫描与手动布局保持，改为消费一次性归并票据
- **预期结果**：第二层只在命中后下一 tick 执行一次归并
- **关键里程碑**：是

### 步骤 4：补回归测试并验证
- **操作对象**：`PairableItemAggregateMenuNormalizationServiceTest`
- **具体动作**：覆盖“不打票不归并 / 打票后归并 / 票据只消费一次”
- **预期结果**：新语义有自动化回归保护
- **关键里程碑**：否

## 预期结果

- 第二层不再默认自动归并。
- 只有 `shift` 快移、双击同类、`shift` 点击结果槽三类原版命中后，服务器下一 tick 才会执行一次归并。
- 手动拆分、右键放一、普通手动整理不会触发第二层归并。

## 语义对齐说明

- 本方案不新增 `triggerSource/core` 之外的领域术语输出。
- 本方案不涉及方向写入，不改变 `LinkNodeType` 与 `triggerSource/core` 映射。
- 本方案只调整第二层触发机制，不改变命令链路、配对 GUI 和持久化结构。
- 残余风险：第二层触发识别依赖菜单层 mixin，但会严格限制在 `AbstractContainerMenu.clicked(...)` 的返回后做最小打票，不主动改写原版点击分支。
