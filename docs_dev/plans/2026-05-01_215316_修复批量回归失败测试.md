# 修复批量回归失败测试

生成时间：2026-05-01 21:53:16
文件名：2026-05-01_215316_修复批量回归失败测试.md

## 任务背景
- 26.1 迁移后，本地构建出现 61 个测试失败，集中表现为两类：
- 一类是 `*ItemDataTest`、`SmartGlassesAccessSupportTest` 等在 `new ItemStack(...)` 时触发空指针，本质是 26.1 下物品 holder 默认组件尚未绑定。
- 另一类是 `GraphWriteServiceTest`、`CrossChunkDispatchServiceTest`、`LinkCommandSupportTest` 等服务端夹具测试在反射写字段时触发 `NoSuchFieldException`，本质是 26.1/Yarn 字段名变化。
- 另外，在 Java 25 工具链下，JaCoCo 0.8.12 会在测试通过后卡死在 `jacocoTestReport`，导致构建仍失败。

## 方案详情

### 现状分析
- 现有测试大量直接使用 `Bootstrap.bootStrap()`，但没有补齐 26.1 新增的物品默认组件绑定步骤。
- 多个测试把 `ServerChunkCache.dataStorage` 等字段名写死，无法兼容 26.1 中的 `savedDataStorage`。
- 少数测试通过反射篡改 `ItemStack.item` 来伪造 `PairableItem` / `SmartGlassesItem`，这在 26.1 下不再稳定，因为 `ItemStack` 内部持有的是 holder 视图。
- 构建脚本固定使用 `jacoco` 0.8.12，而项目测试工具链已切到 Java 25。

### 技术方案
- 在 `TestMinecraftSupport` 中统一补齐测试引导：
- 使用 `VanillaRegistries.createLookup()` 构造带完整 tag 视图的 `HolderLookup.Provider`。
- 在 `bootstrapMinecraft()` 后自动执行内建物品默认组件重绑定。
- 在 `withWritableBlockRegistries(...)` 中支持测试期临时注册物品/方块后再次重绑组件。
- 提供 `setFieldByCandidates(...)`，让测试夹具按候选字段名兼容 26.1 字段漂移。
- 将失败测试的 `@BeforeAll` 统一接入 `TestMinecraftSupport.bootstrapMinecraft()`。
- 将 `SmartGlassesAccessSupportTest`、`LinkCommandSupportTest` 中基于反射篡改 `ItemStack.item` 的写法，替换为真实注册的模组物品栈。
- 将服务端测试夹具里对 `ServerChunkCache` 的字段写入统一改为 `"savedDataStorage", "dataStorage"` 候选写法。
- 将 `jacoco` 升级到支持 Java 25 的版本，恢复测试后续报表生成。

### 影响范围
- 测试基础设施：`src/test/java/com/makomi/testsupport/TestMinecraftSupport.java`
- 测试夹具：`LinkCommandSupportTest`、`SmartGlassesAccessSupportTest`、`GraphWriteServiceTest`、`CrossChunkDispatchServiceTest`、`InternalDispatchDeltaEventsTest`、`LinkChannelEditingServiceTest`、`LinkRetireCoordinatorTest`、`RepeaterItemDataTest`、`SmartNodeContainerRetireSupportTest`
- 测试引导：`LinkItemDataTest`、`QuickLinkToolDataTest`、`LinkFilterItemDataTest`、`ChunkActivatorItemDataTest`、`StatePanelToolDataTest` 等
- 构建配置：`build.gradle`
