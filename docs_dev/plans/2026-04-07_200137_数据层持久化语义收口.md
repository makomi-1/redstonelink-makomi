# 数据层持久化语义收口

生成时间：2026-04-07 20:01:37
文件名：2026-04-07_200137_数据层持久化语义收口.md

## 任务背景

当前仓库虽然对外语义已基本统一为 `triggerSource/core`，但数据层与持久化层仍残留旧 `button*` 字段、旧持久化键，以及“`core` 也能直接作为底层写入 sourceType”的实现路径。  
用户本轮明确要求：不保留历史兼容，一步到位清理数据层 / 持久化层语义；同时保留 `link set/add/remove core ...` 这类高层双视角编辑入口，以便继续提供操作便利性。

## 方案详情

### 现状分析

- `LinkSavedData`、`LinkSavedDataCodecSupport`、`LinkSavedDataSerialSupport`、`LinkSavedDataQuerySupport` 仍使用 `buttonNodes/buttonToCores/nextButtonSerial` 等旧命名。
- `LinkSavedDataLinkIndexSupport` 与相关 facade 仍允许 `CORE` 作为 `sourceType` 直接进入底层写入逻辑，这与项目强制语义“真实写入仅允许 `triggerSource -> core`”冲突。
- `core` 视角配对、OCC、quick-link 与部分读模型确实需要保留，但它们应属于“高层编辑/观察视角”，而不是底层双向真值模型。
- bench / functional 主路径当前并不依赖 `link set core ...` 直接写到数据层，因此可把 `core` 入口上移为服务层转换。

### 技术方案

1. 统一数据层与持久化层命名：
   - `nextButtonSerial -> nextTriggerSourceSerial`
   - `buttonNodes -> triggerSourceNodes`
   - `buttonToCores -> triggerSourceToCores`
   - `coreToButtons -> coreToTriggerSources`
   - `allocatedButtonSerials -> allocatedTriggerSourceSerials`
   - `retiredButtonSerials -> retiredTriggerSourceSerials`
2. `LinkSavedData` 持久化 schema 只保留新键名：
   - 不再读取或写回旧 `button*` / `nextButtonSerial` 键。
   - 节点 `type` 字段继续统一使用 `triggerSource/core`。
3. 拆分底层写入与读视图：
   - 底层只保留 `triggerSource -> core` 正向写入 API。
   - 新增“按节点类型读取关联节点集合”的只读 API，供 `core` 视角查询、near overlay、OCC 快照、生命周期逻辑复用。
4. 保留高层双视角编辑入口，但不再让 `core` 成为底层真实来源：
   - `link set/add/remove core ...`
   - `core pairing`
   - `pairing/quick-link OCC`
   上述入口统一先转成“以 `core` 为观察中心的编辑请求”，再在服务层拆解成多个 `triggerSource -> core` 正向写入计划。
5. 收紧语义工具：
   - `resolveTargetTypeForSource(...)` 只接受 `TRIGGER_SOURCE -> CORE`。
   - 若需要“按节点类型拿对侧节点类型”，新增独立读视图 helper，不再复用写语义 helper。
