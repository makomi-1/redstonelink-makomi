# 过滤器补充频道模式

生成时间：2026-04-15 17:30:47
文件名：2026-04-15_173047_过滤器补充频道模式.md

## 任务背景

当前过滤器只支持基于序号表达式的节点集合过滤，运行时求值、持久化、GUI、物品 NBT、网络 payload 与 quick-link 入口都围绕 `serialExpression` 工作。现需为过滤器补充频道模式，使过滤器在“序号 / 频道”之间二选一，并在运行时由 `triggerSource/core` 根据自身当前连接模式选择匹配的过滤器。

## 方案详情

### 现状分析

- 过滤器配置快照只包含 `serialExpression`、节点集合模式和信号规则。
- 运行时求值器只接收 `serial`，无法按节点当前频道进行白名单/拦截名单判断。
- 节点当前是 `serial` 还是 `channel` 模式，已有 `LinkSavedDataChannelSupport` 可查询。
- quick-link 对过滤器的频道模式仍显式报“不支持”。

### 技术方案

- 新增过滤目标模式枚举，定义 `SERIAL / CHANNEL` 两种过滤目标模式。
- 扩展 `LinkFilterConfigSnapshot`，新增 `targetMode` 与 `channel`，并在归一化阶段保证“序号与频道只能保存一个”：
  - `SERIAL` 模式下清空频道值
  - `CHANNEL` 模式下清空序号表达式
- 扩展过滤器持久化、物品 NBT、网络 payload、GUI 与 tooltip，使过滤器能完整编辑、保存和展示频道模式。
- 将 `LinkDispatchFilterService` 的过滤求值入口改为模式感知：
  - 先根据服务节点类型查询该节点当前是 `serial` 还是 `channel` 模式
  - 再只对对应模式的过滤器做匹配
  - `serial` 模式匹配序号，`channel` 模式匹配频道
- 保持现有邻居输入总开关、信号阈值和 send/receive/replay 过滤补发协调逻辑不变，只替换其内部求值依据。
- 放开 quick-link 对过滤器的频道模式应用门禁，使其在频道缓存模式下可直接写入过滤器频道值。

## 预期结果

过滤器支持频道模式后，`triggerSource/core` 在运行时会依据自身当前连接模式选择相同模式的过滤器进行白名单/拦截名单求值；序号与频道配置保持互斥，现有邻居输入总开关和信号规则继续自然生效，quick-link 也可直接写入频道过滤配置。
