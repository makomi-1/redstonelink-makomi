# graph画布移动缩放时隐藏包围框

生成时间：2026-04-18 01:05:17

## 任务背景

上一轮已经把聚合包围框从节点拖拽与选中组拖拽的热路径中移除，但当前画布在平移和缩放时，包围框仍然保持显示并参与渲染。用户希望继续把这两类视口交互也纳入同一套包围框挂起机制，进一步降低移动和缩放时的卡顿。

本轮目标是在不改 `triggerSource/core` 真值、不改 snapshot、draft 和服务端语义的前提下，仅从前端 graph 视图层补齐视口交互期间的包围框隐藏策略。

## 方案详情

### 现状分析

- 当前 `GraphViewer` 已存在统一的包围框挂起/恢复函数
- 节点拖拽和选中组拖拽已接入该机制
- 画布平移和缩放尚未接入，因此视口变化期间包围框仍会参与渲染
- ReactFlow 已提供 `onMoveStart / onMoveEnd`，可直接复用现有挂起深度计数

### 技术方案

1. 直接把 `onMoveStart` 绑定到 `suspendAggregateOutlineRendering`
2. 把 `onMoveEnd` 绑定到 `resumeAggregateOutlineRendering`
3. 继续复用现有的挂起深度计数，统一处理节点拖拽、组选拖拽、画布平移和画布缩放的事件重叠

### 影响范围

- `webapp/src/components/GraphViewer.tsx`
- `docs_dev/reviews/` 审查文档

### 语义对齐说明

- 命名仍只使用 `triggerSource/core`
- 真实保存语义仍然只处理 `triggerSource -> core`
- 本轮仅修前端 graph 视图层的包围框显示时机，不改 snapshot、draft 和服务端真值
- 与 `LinkNodeType.TRIGGER_SOURCE/CORE` 映射保持不变
- 本轮无新增兼容字段，兼容层仍是“读旧写新”

当用户平移或缩放 graph 画布时，聚合包围框会像节点拖拽时一样临时隐藏；交互结束后再恢复显示，从而进一步减少视口移动与缩放过程中的渲染负担。
