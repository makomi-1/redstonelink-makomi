## 任务背景
上一轮已经完成数据层 / 持久化层的 `triggerSource/core` 语义收口，但文案、注释和资源 key 仍残留少量旧 `button` 术语，例如 `button_pairing`、`button_source_only`、`audit.button_*`，以及把 `triggerSource` 写成“按钮节点”的中文注释。这些残留会继续误导维护与排查，因此需要继续完成命名层收口，并重新执行完整游戏内回归。

## 方案详情

### 现状分析
- 玩家可见文本大多已改成 `triggerSource/core`，但内部 lang key 仍残留 `button_*`。
- `TriggerSourcePairingScreen`、`ActivateCommandRegistry`、`AuditCommandRegistry` 仍引用旧 key。
- `LinkButtonBlock`、`LinkSignalEmitterBlock`、`LinkSyncLeverBlock`、`LinkerItem` 等注释中仍有“按钮节点 / 按钮配对界面”表述。
- 真实方块/物品/模型资源名如 `link_push_button`、`link_toggle_button` 属于具体物体命名，不属于本轮语义残留，不纳入修改范围。

### 技术方案
- 直接把旧资源 key 改名为 `trigger_source_*` / `trigger_source_pairing.*`，不保留旧 key 兼容。
- 同步更新所有 Java / Client 代码引用，确保运行时翻译命中新的 key。
- 只修正误导性注释，保留真实按钮/拉杆/发射器的具体方块含义描述。
- 完成后先跑全标签自动化测试，再跑 `run-regression-full-suite-build-sync.ps1` 做完整游戏内回归。
