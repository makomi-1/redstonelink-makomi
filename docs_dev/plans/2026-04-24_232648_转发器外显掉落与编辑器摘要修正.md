# 转发器外显掉落与编辑器摘要修正

生成时间：2026-04-24 23:26:48
文件名：2026-04-24_232648_转发器外显掉落与编辑器摘要修正.md

## 任务背景
用户反馈当前转发器仍存在四类问题：

1. quick-link 缓存对象穿墙方框在方块相连时，内部接缝边线仍有残留。
2. 转发器近外显无法稳定显示已连接的 `core`，说明客户端摘要没有持续跟随图真值。
3. 转发器被挖掘后无法正常掉落。
4. 转发器编辑器“当前连接”摘要仍显示纯序号，没有沿用别名展示文本。

本轮目标是在不扩展额外交互设计的前提下，完成上述四项最小修复，并继续保持 `triggerSource/core` 语义一致。

## 方案详情

### 现状分析
- `QuickLinkOutlineRenderer` 当前把同色缓存对象合并成 `VoxelShape` 后直接调用 `LevelRenderer.renderVoxelShape(...)`。这种做法可以消掉部分内部体素，但仍会保留部分共面拼接边，因此“只保留最外层方框”不彻底。
- 转发器近外显走的是 `LinkSerialHudOverlayRenderer.renderRepeaterOverlay(...) -> LinkSerialHudOverlayTextSupport.buildNearOverlayLines(LinkRepeaterBlockEntity, Font)`，直接读取客户端方块实体里的 `configSnapshot/inputDisplayTexts/outputDisplayTexts`，并不走 near-overlay 网络快照；而当前图改动后只同步了在线物品，没有统一刷新已放置转发器方块实体，所以摘要会漂。
- 转发器编辑器打开包 `RepeaterNetwork.OpenRepeaterEditorPayload` 只传 `RepeaterConfigSnapshot` 与统一别名，`RepeaterEditorScreen` 只能直接显示 `input/outputSerialExpression`，因此摘要天然是纯序号。
- 转发器掉落问题需要同时核对 `LinkRepeaterBlock` 的破坏链和资源侧配置；当前方块虽然实现了 `getDrops(...)`，但缺少显式自掉落保障与回归验证，存在实际破坏路径未命中的风险。

### 技术方案
1. quick-link 预览由“合并体素形状再画线框”改为“按外露面求二维边界，再回写成三维线段渲染”，确保相连面的内部边不再绘制，只保留外轮廓。
2. 为转发器补一个统一的“图真值同步展示”入口：图关系变化后同时刷新在线转发器物品缓存与已加载转发器方块实体，从根上修复近外显/客户端摘要漂移。
3. 扩展转发器编辑器打开 payload，显式携带输入侧和输出侧的展示文本列表；客户端编辑器用展示文本优先构建摘要，缺失时再回退序号表达式。
4. 收紧转发器掉落路径：为方块破坏补显式自掉落保障，并补针对 `getDrops(...)` / 客户端摘要 / quick-link 线框边界逻辑的回归测试。

### 影响范围
- 客户端渲染：`QuickLinkOutlineRenderer`、`RepeaterEditorScreen`
- 服务端图同步：`RepeaterGraphSnapshotSupport`、`PairingOccSubmissionSupport`、`QuickLinkApplyService`
- 网络载荷：`RepeaterNetwork`、`RepeaterNetworkPayloadSupport`、`RepeaterNetworkClientHandlerSupport`
- 方块行为：`LinkRepeaterBlock`
- 测试：转发器网络/方块掉落/quick-link 相关测试

### 语义对齐说明
- 命名继续仅使用 `triggerSource/core`，不新增旧术语输出。
- 转发器输入侧继续表达“哪些 `triggerSource` 指向当前转发器”，输出侧继续表达“当前转发器指向哪些 `core`”，不改变方向语义。
- 编辑器与近外显只修复展示载荷与同步时机，不修改已有 `LinkNodeType.TRIGGER_SOURCE/CORE` 映射。
- 兼容层继续保持“读旧写新”；本轮不引入 `com.makomi.api.v1.*` 依赖。

## 原子步骤清单

### 步骤 1：重写 quick-link 缓存方框边界提取
- **操作对象**：`QuickLinkOutlineRenderer`
- **具体动作**：把缓存对象预览从 `VoxelShape` 合并改成按颜色分组的外露面边界线段生成，并仅绘制真正的最外层边。
- **预期结果**：相连缓存对象之间不再出现内部接缝边线。
- **关键里程碑**：是

### 步骤 2：补转发器图真值展示同步
- **操作对象**：`RepeaterGraphSnapshotSupport`、`PairingOccSubmissionSupport`、`QuickLinkApplyService`
- **具体动作**：新增统一同步入口，在涉及转发器统一序号的图改动后，同时刷新在线物品和已加载转发器方块实体客户端数据。
- **预期结果**：转发器近外显与客户端展示稳定跟随真实图关系，能够显示已连接 `core`。
- **关键里程碑**：是

### 步骤 3：扩展转发器编辑器打开载荷并改摘要展示
- **操作对象**：`RepeaterNetwork`、`RepeaterNetworkPayloadSupport`、`RepeaterNetworkClientHandlerSupport`、`RepeaterEditorScreen`
- **具体动作**：给打开编辑器的 payload 增加输入/输出展示文本列表，客户端优先按别名展示文本构建“当前连接”摘要。
- **预期结果**：转发器 GUI 当前连接摘要不再是纯序号。
- **关键里程碑**：是

### 步骤 4：修正掉落链并补回归测试
- **操作对象**：`LinkRepeaterBlock` 与相关测试
- **具体动作**：核准转发器破坏掉落路径，补显式自掉落保障与最小测试覆盖。
- **预期结果**：转发器可正常挖掘掉落，且本轮四项问题都有对应回归验证。
- **关键里程碑**：是

## 预期结果
- quick-link 缓存方框只显示最外层边界，内部拼接边不再残留。
- 转发器近外显能够稳定显示输入/输出连接摘要，包括已连接的 `core`。
- 转发器被挖掘后可正常掉落带配置的物品。
- 转发器编辑器中的当前连接摘要优先显示别名文本。
