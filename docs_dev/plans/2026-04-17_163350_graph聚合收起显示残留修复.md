# Graph 聚合收起显示残留修复

生成时间：2026-04-17 16:33:50
文件名：2026-04-17_163350_graph聚合收起显示残留修复.md

## 任务背景

上一轮已经为网页 Graph 视图加入了：

- 孤立节点池化
- 高扇出摘要节点
- 强制展开优先级

但实测发现“聚合/收起”并没有真正反映到画布显示，尤其是被收起的目标节点仍然留在主画布里，导致用户感知上等于“没有收起”。

本轮目标是修复这一点，保证视图裁剪确实影响 ReactFlow 中的实际可见节点与边。

## 方案详情

### 现状分析

- 现有实现先按原始 graph 的 incident edge 计算节点可见性，再删除一部分需要摘要替换的目标节点或目标边。
- 这种顺序有风险：如果某个节点在“原始图”里可见，但在“视图裁剪后”应该只通过摘要节点表达，它仍可能残留在画布里。
- 因此问题不一定出在交互入口，而更可能出在“可见节点集合的生成时机”。

### 技术方案

1. 先确定哪些真实边会被摘要节点替代，形成 `hiddenEdgeKeys`。
2. 基于“替代后的真实可见边”重新计算 `visibleActualNodeKeys`，而不是沿用原始图的 incident edge 判定。
3. 摘要节点继续作为纯前端虚拟节点参与布局和渲染。
4. 孤立节点池仍按原始真实图的 incident edge 判定，不改变其语义。

- **操作对象**：`webapp/src/components/GraphViewer.tsx`
- **具体动作**：先生成要被摘要隐藏的边，再根据可见边重算可见节点集合
- **预期结果**：被摘要替换掉的节点不会继续残留在主画布
- **关键里程碑**：是

- **操作对象**：`webapp/src/components/GraphViewer.tsx`
- **具体动作**：同步修正摘要文案并跑前端构建、项目测试
- **预期结果**：聚合显示与内部逻辑保持一致
- **关键里程碑**：是

## 预期结果

- 高扇出收起会真实减少主画布中的可见节点/边。
- 主画布显示结果与右侧孤立节点池、摘要统计保持一致。
- 不改 `triggerSource -> core` 的真实保存语义，只修复前端视图层裁剪行为。
