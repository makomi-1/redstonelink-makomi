# 修复转发器重进存档加载阻塞

生成时间：2026-04-24 20:55:02
文件名：2026-04-24_205502_修复转发器重进存档加载阻塞.md

## 任务背景

当前工作区路径为 `D:\OpenProjects\RedstoneLink\rl-release-no-mixin`。

用户反馈：放置了转发器的存档在重进时线程被阻塞。静态分析后发现，阻塞高概率不是 attach replay 查询，而是转发器在 `clearRemoved()` 加载附着阶段直接调用 `level.setBlock(...)` 校正 `ACTIVE` 外显，把项目已规避过的“加载关键路径直接改块”问题重新引了回来。

## 方案详情

### 现状分析

- `LinkRepeaterBlockEntity.clearRemoved()` 当前会在 `super.clearRemoved()` 后立刻调用 `syncRepeaterActiveBlockState(dispatchedOutputPower > 0)`
- `syncRepeaterActiveBlockState(...)` 内部直接执行 `level.setBlock(..., Block.UPDATE_CLIENTS)`
- 项目已有加载期优化经验明确要求：方块实体重新附着的关键路径禁止直接 `setBlock(...)`，应改为挂起后由非阻塞生命周期队列消费
- `core` 现有已经有成熟路径：`loadAdditional()` 记录 `pendingLoadBlockStateSync`，随后由 `LinkNodeLifecycleDispatchEvents.consumeAttachTask()` 在 `getChunkNow(...)` 校验通过后调用 `consumePendingLoadBlockStateSync()`
- 转发器目前没有复用这条路径，因为它把 `syncBlockStateFromDerivedState()` 设成空实现、`shouldQueueLoadBlockStateSync()` 固定返回 `false`

### 技术方案

1. 移除转发器在 `clearRemoved()` 里的直接 blockstate 校正
2. 让转发器复用现有加载后挂起式校正链路：
   - `syncBlockStateFromDerivedState(...)` 改为按“已派发输出态”同步 `ACTIVE`
   - `shouldQueueLoadBlockStateSync(...)` 改为按“当前 blockstate 是否等于已派发输出态”决定是否挂起
3. 保持转发器特殊语义不变：
   - 可见 `ACTIVE` 仍由 `dispatchedOutputPower > 0` 驱动，而不是输入侧即时真值
   - 延迟调度、replay 快照持久化、`triggerSource/core` 双身份与方向约束不变
4. 补两条单测：
   - 读档时若 blockstate 与已派发输出态不一致，应登记 `pendingLoadBlockStateSync`
   - 若 blockstate 已与已派发输出态一致，则不应登记挂起校正

## 原子步骤清单

### 步骤 1：撤掉转发器加载期直接改块
- **操作对象**：`LinkRepeaterBlockEntity`
- **具体动作**：删除 `clearRemoved()` 内的直接 `syncRepeaterActiveBlockState(...)`
- **预期结果**：重进存档时不再在方块实体附着链路直接 `setBlock(...)`
- **关键里程碑**：是

### 步骤 2：接回挂起式 load-resync 语义
- **操作对象**：`LinkRepeaterBlockEntity`
- **具体动作**：实现转发器自己的 `syncBlockStateFromDerivedState(...)` 与 `shouldQueueLoadBlockStateSync(...)`
- **预期结果**：转发器外显仍以已派发输出态为准，但校正时机切到非阻塞生命周期消费链
- **关键里程碑**：是

- **具体动作**：新增针对转发器已派发输出态外显的 load-resync 单测
- **预期结果**：后续若有人把转发器重新改回加载期直接改块，测试可及时报警
- **关键里程碑**：是

### 步骤 4：执行编译与全量回归
- **操作对象**：Gradle 任务与审查文档

- **关键里程碑**：是

## 预期结果

- 带转发器的存档重进时，不再因转发器加载附着阶段直接写世界而阻塞
- 转发器 `ACTIVE` 外显仍以“已派发输出态”驱动，语义保持不变
- 语义对齐说明：
  - 命名继续只使用 `triggerSource/core`
  - 不改变 `triggerSource -> core` 方向约束
  - 不引入 `com.makomi.api.v1.*` 依赖
  - 兼容层无新增“写旧读新”问题
- 残余风险：若 `runtime.coreLoadResyncEnabled` 被人为关闭，转发器和 core 一样都会放弃加载后 blockstate 漂移校正；本轮不扩该配置语义，风险可接受
