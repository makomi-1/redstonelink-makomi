## 任务背景
用户需要一个临时 bench 场景，用于把 `x22` mixed 逐 tick 验证中的 `pulse` 子阶段单独抽离出来，固定在 `crosschunk.dispatch.batchWindowTicks=2` 下复现问题，方便后续通过场景复现和断点调试继续缩小问题范围。

## 方案详情

### 现状分析
- 现有 `x22/x23/x24` 为 mixed 场景，按 `sync -> pulse -> toggle` 三个子阶段顺序验证。
- 最新复跑结果显示：同步最新 jar 后，`window=0/1` 已通过，`window=2` 仅 `pulse` 目标端断言失败。
- 当前需要一个最小复现场景，避免 `sync/toggle` 干扰。

### 技术方案
- 新增独立 functional case，仅保留单个 `pulse triggerSource`、单个 `core` 与同样的多周期输入波形 `14/0/0/0/0/14/0/0`。
- 目标端断言继续复用现有 `mixed_direct_pulse_relative` 模板，但固定 `windowTicks=2`，保证与 `x22` 的 pulse 子阶段对齐。
- 不改现有 `functional-matrix.json`，改为新增独立 matrix 与 suite，减少对现有回归入口的影响。

### 影响范围
- `tools/bench/cases/functional/x26/`
- `tools/bench/functional-pulse-window2-matrix.json`
- `tools/bench/suites/functional-pulse-window2-debug.json`
