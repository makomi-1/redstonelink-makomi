# P1 客户端本地缓存与 Bridge 数据通道

生成时间：2026-04-16 16:28:48
文件名：2026-04-16_162848_P1客户端本地缓存与Bridge数据通道.md

## 任务背景

`P0` 已完成网页前端离线打包底座，当前需要继续对照既有整体方案中的 `P1`，把客户端本地缓存目录和本地 Bridge 数据通道真正接起来。

本轮目标不是录制会话、图快照导出或保存回写，而是先把“客户端本地文件 / 客户端内存 -> 本地 HTTP -> 网页读取”这条链路做成稳定底座。

## 方案详情

### 现状分析

- 当前本地 Bridge 只提供静态网页资源和 `/api/ping`，还没有任何本地资产目录和业务数据接口。
- 前端首页仍是 `P0` 静态说明页，不能展示或读取本地资产。
- 既有整体方案已经约定本地网页资产根目录应为 `gameDir/redstonelink/web/**`，并约定四类资产：
  - `recordings/`
  - `graphs/`
  - `drafts/`
  - `layouts/`
- 现有代码库中已有客户端本地文件写入经验，可复用“目录初始化 + UTF-8 写入 + 小文件原子替换”的思路。

### 技术方案

#### 1. 本地资产仓

新增客户端本地资产仓服务，根目录固定解析为：

- `gameDir/redstonelink/web/`

四类子目录：

- `recordings/`
- `graphs/`
- `drafts/`
- `layouts/`

目录规则：

- `recordings`、`graphs` 使用 `.json.gz`
- `drafts`、`layouts` 使用 `.json`

`P1` 阶段自动补一组占位示例资产，确保网页端在没有真实录制/图快照导出能力前，也能验证目录扫描和内容读取链路。

#### 2. 本地 Bridge 数据接口

在现有 Bridge 上新增两类只读接口：

- `GET /api/storage/index`
  - 返回本地根目录、刷新时间、四类目录摘要、每类若干资产条目
- `GET /api/storage/entry?kind=...&name=...`
  - 返回指定资产的元信息与文本内容预览

当前仍只支持 `GET/HEAD`，不做写接口，不做自动同步。

#### 3. 网页端预览页

把首页从 `P0` 说明页升级为 `P1` 资产预览页：

- 保留本地 Bridge 状态
- 增加本地资产目录概览
- 支持点击条目后读取单资产文本内容
- 明确标注当前是 `P1` 只读缓存预览，不代表真实录制/图编辑页面

#### 4. 示例资产边界

`P1` 自动生成的示例资产必须明确属于客户端本地缓存，不得进入世界真值：

- 不写服务端数据
- 不写 `NBT`
- 不新增 `triggerSource -> core` 真值写路径
- 仅作为 `P1` 数据通道验链资产

### 影响范围

- 新增客户端本地资产仓类
- 调整 `LocalWebAppBridgeService`
- 调整 `webapp/src/**`
- 新增客户端只读单测
- 新增 `P1` 方案与审查文档

### 语义对齐说明

- 本轮不新增旧术语输出，后续真实业务仍按 `triggerSource/core` 语义演进。
- 本轮不引入 `com.makomi.api.v1.*`。
- 本轮仅新增客户端本地缓存和只读数据接口，不新增真实拓扑写入路径。
- 本地示例资产不属于真实录制结果、真实图快照或真实保存草稿，只是 `P1` 验链数据。
- 残余风险：
  1. `P1` 示例资产与后续 `P2/P3` 真实 DTO 需要严格衔接，避免示例结构被误认为最终契约。
  2. `recordings/graphs` 当前先按 `.json.gz` 约定，后续真实导出时需保证字段演进兼容。

- **关键里程碑**：是
