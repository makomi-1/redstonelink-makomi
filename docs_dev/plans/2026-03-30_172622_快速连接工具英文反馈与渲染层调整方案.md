# 快速连接工具英文反馈与渲染层调整方案

生成时间：2026-03-30 17:26:22
文件名：2026-03-30_172622_快速连接工具英文反馈与渲染层调整方案.md

## 任务背景

当前 quick-link 英文反馈与中文口径仍有偏差；连接同步拉杆和连接脉冲按钮仍使用半透明渲染层；quick-link 在“将一批 triggerSource 应用到 core”时还使用硬编码缓存数量上限，未与现有 `set_links` 数量规则统一。需要做一次小范围一致性整理。

## 方案详情

### 现状分析

- `en_us.json` 中 `message.redstonelink.quick_link.*` 部分文案比中文更偏解释性，和当前中文提示不完全一致。
- `LINK_SYNC_LEVER` 与 `LINK_PUSH_BUTTON` 当前在客户端注册为 `RenderType.translucent()`，相关 block model 也写死为 `minecraft:translucent`。
- `QuickLinkApplyService` 在 `triggerSource 缓存 -> core` 路径中仍使用硬编码 `4096` 作为缓存数量上限，而现有 `link set` 已统一使用 `server.maxTargetsPerSetLinks`。

### 技术方案

1. 仅同步 quick-link 英文反馈键，使其与当前中文文案语义一致。
2. 将连接同步拉杆和连接脉冲按钮的世界渲染层与相关 model `render_type` 一并切到 `cutout`，不修改任何贴图资源。
3. 将 quick-link 应用到 core 时的缓存数量上限统一改为 `RedstoneLinkConfig.general().maxTargetsPerSetLinks()`。
4. 补最小测试与使用说明，确保规则可追溯。

### 影响范围

- quick-link 中英文提示文案
- 同步拉杆、连接脉冲按钮的客户端渲染层与模型声明
- quick-link 服务端应用数量限制
- quick-link 相关测试与使用说明

## 原子步骤清单

### 步骤 1：同步 quick-link 英文反馈
- **操作对象**：`src/main/resources/assets/redstonelink/lang/en_us.json`
- **具体动作**：对齐 `message.redstonelink.quick_link.*` 到当前中文含义。
- **预期结果**：英文反馈和中文口径一致。
- **关键里程碑**：是

### 步骤 2：调整同步拉杆与连接脉冲按钮渲染层
- **操作对象**：`RedstoneLinkClient`、相关 block/item model
- **具体动作**：将 `LINK_SYNC_LEVER`、`LINK_PUSH_BUTTON` 改为 `cutout` 渲染，并同步修改对应模型 `render_type`。
- **预期结果**：放置态与物品栏渲染不再使用半透明混合。
- **关键里程碑**：是

### 步骤 3：统一 quick-link apply 数量上限
- **操作对象**：`QuickLinkApplyService`
- **具体动作**：移除硬编码 `4096`，改为复用 `server.maxTargetsPerSetLinks`。
- **预期结果**：quick-link apply 与 `link set` 数量规则一致。
- **关键里程碑**：是

### 步骤 4：补测试与说明
- **操作对象**：测试代码、`docs_dev/使用说明.md`
- **具体动作**：补最小测试并更新 quick-link 使用说明中关于应用数量上限的描述。
- **预期结果**：本轮规则调整有回归证据和文档说明。
- **关键里程碑**：否

## 预期结果

- quick-link 英文反馈不会再和中文口径分叉。
- 连接同步拉杆与连接脉冲按钮在世界与物品栏中都不再以半透明方式渲染。
- quick-link 将 triggerSource 缓存应用到 core 时，会和现有 `set_links` 一样受 `server.maxTargetsPerSetLinks` 约束。
