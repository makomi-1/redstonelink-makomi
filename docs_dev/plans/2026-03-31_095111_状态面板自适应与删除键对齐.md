# 状态面板自适应与删除键对齐

生成时间：2026-03-31 09:51:11
文件名：2026-03-31_095111_状态面板自适应与删除键对齐.md

## 任务背景
- 当前状态面板工具界面在窗口大小变化、全屏切换和不同分辨率下缺少统一布局收敛层。
- 删除按钮依赖初始化时的固定列坐标，存在与实时列表绘制位置脱节的风险。
- 本次目标是以最小粒度修复状态面板布局自适应与删除键对齐问题，不扩散到其他 GUI。

## 方案详情

### 现状分析
- `StatePanelToolScreen` 目前使用固定 `PANEL_WIDTH`、固定列宽与固定按钮宽度，缺少按当前屏幕尺寸收敛的布局计算。
- 控件在 `init()` 中按当时坐标创建，后续仅局部更新 `Y` 坐标，`clean all` 与删除按钮没有统一按最新布局刷新完整位置。
- 列文本绘制与按钮位置并未完全共用同一份几何结果，窄屏下容易出现状态文本与删除按钮挤压、漂移或观感错位。

### 技术方案
1. 在 `StatePanelToolScreen` 内新增统一布局解析层：
   - 依据当前 `Screen` 的 `width/height` 解析面板宽度、面板左上角、按钮宽度、表头与列表列边界。
   - 保留当前默认视觉宽度作为上限，但允许在窄屏场景下自动收敛。
2. 所有可交互控件改为消费同一份布局结果：
   - 输入框、类型切换按钮、三枚主操作按钮、`clean all`、删除按钮统一按布局结果同步 `X/Y/width`。
   - 删除按钮不再依赖静态右边界常量，而是依赖实时操作列位置。
3. 列文本渲染改为基于实时列宽裁剪：
   - 类型列、序号列、状态列全部按当前布局宽度截断文本，避免与操作列重叠。
4. 增加纯几何 client 测试：
   - 覆盖默认屏幕与窄屏场景下的面板宽度收敛、删除按钮对齐和状态列剩余宽度约束。

### 影响范围
- `src/client/java/com/makomi/client/screen/StatePanelToolScreen.java`
- `src/test/java/com/makomi/client/screen/` 下新增或补充状态面板布局测试

## 原子步骤清单

### 步骤 1：提取状态面板布局计算
- **操作对象**：`StatePanelToolScreen`
- **具体动作**：新增内部布局结果对象与统一计算方法，收口面板宽度、列宽、按钮坐标与列表区域几何
- **预期结果**：布局几何由单一入口控制，便于后续统一渲染与同步
- **关键里程碑**：是

### 步骤 2：统一控件坐标刷新
- **操作对象**：`StatePanelToolScreen`
- **具体动作**：让输入框、操作按钮、`clean all` 与删除按钮全部按布局结果同步位置和尺寸
- **预期结果**：窗口变化或 GUI 尺寸变化时控件仍能保持对齐
- **关键里程碑**：是

### 步骤 3：按实时列宽收敛文本绘制
- **操作对象**：`StatePanelToolScreen`
- **具体动作**：为类型列、序号列、状态列引入按宽度裁剪的渲染逻辑
- **预期结果**：删除按钮与文本列不再相互压住
- **关键里程碑**：是

### 步骤 4：补充 client 布局回归测试
- **操作对象**：状态面板 client 测试
- **具体动作**：新增纯几何布局测试，校验默认与窄屏下的关键坐标关系
- **预期结果**：后续修改布局时可自动发现删除键对齐回归
- **关键里程碑**：否

## 预期结果
- 状态面板在窗口化、全屏和不同分辨率下都能保持居中与不越界。
- 删除按钮固定贴合最右操作列，不再随布局变化出现漂移。
- 列渲染在窄屏场景下仍保持可读，不与操作按钮重叠。

## 语义对齐说明
- 命名基线：本次仅调整 GUI 布局，不新增业务语义字段，未引入旧术语外泄。
- 方向一致性：不修改任何 `triggerSource -> core` 业务写入路径，方向约束不受影响。
- 映射关系：`LinkNodeType.TRIGGER_SOURCE/CORE` 现有映射保持不变。
- 兼容边界：本次无兼容层写入改动。
- 残余风险：极端矮屏下列表仍保持 8 行常量，只做位置收敛，不做动态行数压缩。
