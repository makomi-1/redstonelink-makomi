# 修复客户端退出时滚轮回调重复释放崩溃

生成时间：2026-04-26 16:38:46
文件名：2026-04-26_163846_修复客户端退出时滚轮回调重复释放崩溃.md

## 任务背景

用户在正常退出开发环境客户端后，`runClient` 以 JVM native 崩溃结束。`run/hs_err_pid22736.log` 显示崩溃发生在 `Window.close()` 调用 `glfwFreeCallbacks()` 期间，堆栈落在 `Callback.free()` 与 `DeleteGlobalRef()`，说明退出阶段存在 GLFW 回调重复释放风险。

## 方案详情

### 现状分析

- 客户端会在 `ensureSyncLinkerScrollHookInstalled(...)` 中通过 `GLFW.glfwSetScrollCallback(...)` 安装同步遥控器滚轮回调。
- 客户端停止时，`registerClientLifecycleHooks()` 里的 `CLIENT_STOPPING` 回调会手动执行 `syncLinkerScrollCallback.free()`。
- 原生日志显示关闭窗口时还会进入 `Window.close() -> glfwFreeCallbacks()`，因此当前回调对象很可能被手动释放一次、关窗时再次释放一次。

### 技术方案

采用最小修复路径：

1. 保留同步遥控器滚轮回调的安装和运行时逻辑不变。
2. 在客户端停止阶段不再手动 `free()` 当前滚轮回调，只清空 Java 侧引用和窗口句柄记录。
3. 让窗口关闭阶段统一执行 GLFW callbacks 释放，避免与我们自己的生命周期钩子重复释放同一 native 资源。

### 影响范围

- `src/client/java/com/makomi/RedstoneLinkClient.java`
