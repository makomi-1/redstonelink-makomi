# 批量选区多数类型聚焦与频道新增成员聚合修复

生成时间：2026-04-18 22:36:28
文件名：2026-04-18_223628_批量选区多数类型聚焦与频道新增成员聚合修复.md

## 任务背景

当前 graph 前端还剩两个相关问题：

1. “应用到草稿”后的自动聚焦仍然只跟随单个 `selectedNodeKey`，没有按当前批量选区里 `triggerSource/core` 哪一类节点更多来决定上下文。
2. 频道模式下，已有聚合块仍能显示，但新增进入频道的那部分成员有时没有并进聚合块，现象更像是新增成员在前端重建时没有稳定进入同一个频道分桶。

本轮仍只修前端图视图与状态调度，不改真实保存语义与 `triggerSource -> core` 真值边界。

## 方案详情

### 现状分析

- `handleApplyBatchEdit()` 当前把 `selectedNodeKey` 直接作为结构重排后的聚焦对象，无法表达“按选区多数类型决定上下文”。
- 序号模式与频道模式的批量选区已经分别收口为：
  - 序号模式：`selectedEditSourceSerials / selectedEditTargetSerials`
  - 频道模式：`selectedEditChannelNodeKeys`
- 频道聚合视图当前按 `connectionMode === "channel" && channel > 0` 过滤成员。如果新增成员的模式字段与频道号回传不完全同步，就可能拿到了频道号但没被并进频道分桶。

### 技术方案

1. 新增批量选区代表节点解析：
   - 序号模式比较选中的 `triggerSource/core` 数量。
   - 频道模式也比较选中的 `triggerSource/core` 数量。
   - 选中数量更多的一类，作为重排后聚焦的上下文类型；同类内优先复用当前 `selectedNodeKey`，否则取稳定顺序下的首个节点。
2. 对前端节点模式做更稳的归一化：
   - 只要节点 `channel > 0`，就把它视作频道成员。
   - 序号视图只吃非频道成员；频道视图与频道聚合分桶统一吃频道成员。
   - 这样即便新增成员回传时存在短暂的 `connectionMode/channel` 不一致，也不会掉出频道聚合块。

### 影响范围

- `webapp/src/graphTypes.ts`
- `webapp/src/components/GraphViewer.tsx`
- `webapp/src/components/graphViewer/canvas.tsx`

## 原子步骤清单

### 步骤 1：补模式归一化 helper
- **操作对象**：`webapp/src/graphTypes.ts`
- **具体动作**：新增节点连接模式归一化与“频道成员/序号成员”判定 helper，并用于快照与保存回包解析。
- **预期结果**：前端基线里的节点模式口径稳定，不再因回包字段轻微不一致掉出频道分桶。
- **关键里程碑**：是

### 步骤 2：改应用草稿后的聚焦对象选择
- **操作对象**：`webapp/src/components/GraphViewer.tsx`
- **具体动作**：基于批量选区计算“哪类节点更多”的代表节点，并将其作为重排后的 `focusNodeKey`。
- **预期结果**：应用草稿后自动聚焦更符合批量操作上下文。
- **关键里程碑**：是

### 步骤 3：统一频道/序号视图的成员过滤
- **操作对象**：`webapp/src/components/GraphViewer.tsx`、`webapp/src/components/graphViewer/canvas.tsx`
- **具体动作**：把搜索节点集合、序号视图节点集合、频道视图节点集合都切到同一套模式判定 helper。
- **预期结果**：新增频道成员不会在视图重建时被错误排除。
- **关键里程碑**：是
