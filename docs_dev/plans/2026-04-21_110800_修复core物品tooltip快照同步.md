# 修复core物品tooltip快照同步

生成时间：2026-04-21 11:08:00
文件名：2026-04-21_110800_修复core物品tooltip快照同步.md

## 任务背景
当前项目的拓扑真值始终以 `triggerSource -> core` 方向写入，运行态与上线后的节点读取均正常。但用户确认：当连接关系发生变化后，背包中 `core` 物品 tooltip 依赖的 `rl_links` 快照不会自动同步刷新。问题不局限于某一个 GUI 视角，而是所有会改动 `core` 成员集合的入口都会漏掉这类物品快照回写。

## 方案详情

### 现状分析
- 统一拓扑写入最终会落到 `LinkSetExecutionService` 的后置同步逻辑。
- 当前后置同步会刷新在线节点客户端显示，并刷新真实写入来源物品的链接快照。
- 由于真实写入方向固定为 `triggerSource -> core`，现有物品快照刷新天然更偏向 `triggerSource`，受影响的 `core` 物品没有进入统一回写链。
- 批量 `core` 编辑又复用了批量同步收集器，因此若只在单个入口补丁，后续仍会产生入口不一致的问题。

### 技术方案
- 保持真实拓扑写入方向不变，继续只允许 `triggerSource -> core` 正向写入。
- 在 `LinkCommandSupport` 中扩展现有“玩家物品链接快照刷新”能力，使其既能刷新真实来源物品，也能刷新受影响 `core` 物品。
- 将受影响 `core` 序号纳入 `LinkSetExecutionService` 的统一后置同步与批量同步收集器，避免单条写入和批量写入行为分叉。
- 保持所有读写命名、注释与对外语义统一使用 `triggerSource/core`，不引入旧术语与反向写入路径。

### 影响范围
- `src/main/java/com/makomi/command/link/LinkCommandSupport.java`
- `src/main/java/com/makomi/command/link/LinkSetExecutionService.java`
- 可能涉及对应测试文件，用于补回归验证
- `docs_dev/reviews/` 审查文档

## 原子步骤清单

### 步骤 1：确认统一后置同步扩展点
- **操作对象**：`LinkSetExecutionService`、`LinkCommandSupport`
- **具体动作**：梳理单条写入和批量写入如何登记节点同步与物品快照同步，明确最小改动入口
- **预期结果**：确定一处统一扩展点即可覆盖所有改拓扑入口
- **关键里程碑**：是

### 步骤 2：补齐受影响core物品快照刷新
- **操作对象**：`LinkCommandSupport`
- **具体动作**：扩展玩家物品链接快照刷新逻辑，使其支持按节点类型与序号刷新 `core` 单件物品的 `rl_links` 缓存
- **预期结果**：背包中的 `core` 物品 tooltip 可读取到最新连接快照
- **关键里程碑**：是

### 步骤 3：接入统一写入闭环
- **操作对象**：`LinkSetExecutionService` 及其批量同步收集器
- **具体动作**：让单条写入、批量 `core` 编辑与其它复用入口都自动登记受影响 `core` 物品刷新
- **预期结果**：两个视角及复用入口行为一致，不再依赖入口补丁
- **关键里程碑**：是

### 步骤 4：补回归验证与审查文档
- **操作对象**：相关测试、`docs_dev/reviews/`
- **具体动作**：补最小测试并执行验证，最后生成五段式审查文档
- **预期结果**：形成可追溯验证证据与实现审查记录
- **关键里程碑**：否

## 预期结果
任意入口修改 `triggerSource -> core` 拓扑后，受影响 `core` 物品的 tooltip 快照都会自动刷新；语义方向仍严格保持 `triggerSource -> core`，不新增任何反向写入或旧术语输出。
