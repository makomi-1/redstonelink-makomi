# 网页偏好本地持久化

生成时间：2026-04-20 17:15:09
文件名：2026-04-20_171509_网页偏好本地持久化.md

## 任务背景

网页前端已经支持中英文切换和主题切换，但当前持久化仅依赖浏览器 `localStorage`。由于本地 bridge 每次启动时绑定随机端口，网页 origin 会在游戏重启后变化，导致浏览器把新的网页视为另一个站点，之前的 `localStorage` 无法恢复。用户要求选择“方案 2”，即把网页偏好移出浏览器 origin 范围，通过客户端本地持久化与 bridge 接口同步。

## 方案详情

### 现状分析

- 本地网页 bridge 当前使用随机端口启动，因此每次游戏重启后 base URL 会变化。
- 前端 `App.tsx` 当前在初始化时读取 `localStorage`，语言和主题切换时也直接写回 `localStorage`。
- bridge 现有接口已经覆盖 ping、storage、graph save/preview/draft，但没有网页偏好接口。
- 现有客户端网页模块已具备本地落盘能力与 UTF-8 文本处理能力，适合新增一个独立的网页偏好存储。

### 技术方案

- 在 `src/client/java/com/makomi/client/web/` 下新增独立的 `LocalWebPreferencesStore`，负责：
  - 从客户端本地文件读取网页偏好
  - 写入网页偏好
  - 对非法值安全回退到默认值
- 在 bridge 中新增：
  - `GET /api/preferences`：返回当前偏好
  - `POST /api/preferences`：接收并保存偏好
- 在 `LocalWebJsonSupport` 中新增网页偏好 JSON 的构建与最小解析支持，保持 bridge 内部不引入额外 JSON 依赖。
- 前端新增 preferences API 封装，`App.tsx` 改为：
  - 启动后异步读取 `/api/preferences`
  - 用户切换语言或主题时写回 `/api/preferences`
  - 默认值仅作为接口失败时的兜底，不再依赖 `localStorage` 做最终真值

### 影响范围

- 客户端本地网页 bridge 模块
- 前端应用入口与偏好读取/写回逻辑
- 前端测试用例

## 原子步骤清单

### 步骤 1：新增客户端网页偏好存储
- **操作对象**：`src/client/java/com/makomi/client/web/`
- **具体动作**：新增本地偏好存储类，定义语言和主题字段、默认值、读取与原子写入逻辑
- **预期结果**：客户端具备稳定的网页偏好真值来源
- **关键里程碑**：是

### 步骤 2：扩展 bridge 偏好接口
- **操作对象**：`LocalWebAppBridgeService.java`、`LocalWebJsonSupport.java`
- **具体动作**：新增 `/api/preferences` 的 GET/POST 接口以及对应 JSON 构建和解析
- **预期结果**：前端可通过 bridge 读取和保存偏好
- **关键里程碑**：是

### 步骤 3：前端接入偏好接口
- **操作对象**：`webapp/src/App.tsx`、`webapp/src/app/*.ts`
- **具体动作**：新增 preferences 请求封装，改造初始化与切换时的偏好读写逻辑
- **预期结果**：网页主题和语言跨游戏重启保持稳定
- **关键里程碑**：是

### 步骤 4：补测试并执行回归
- **操作对象**：`webapp/src/**/*.test.*`、构建与测试命令
- **具体动作**：更新前端单测，覆盖 preferences 加载与保存路径，并执行前端与 Gradle 回归
- **预期结果**：新链路有自动化验证，且不破坏现有功能
- **关键里程碑**：是

## 预期结果

网页语言和主题不再依赖随机 origin 下的 `localStorage`。即使游戏重启、bridge 端口变化，前端仍会通过客户端本地偏好文件恢复上次选择。整个实现不改变 `triggerSource/core` 语义，也不扩展 graph、recording 或其他业务协议。
