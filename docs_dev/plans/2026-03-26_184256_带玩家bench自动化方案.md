# 带玩家 bench 自动化方案

生成时间：2026-03-26 18:42:56
文件名：2026-03-26_184256_带玩家bench自动化方案.md

## 任务背景
当前 bench 已支持通过 `-AsPlayer` 借用玩家上下文执行 `place/link set/input start` 等命令，但自动化能力仍停留在“命令包装”层：

1. `run-bench.ps1` 只会直接连接现成 RCON，不会等待目标玩家上线。
2. `run-bench-suite.ps1` 只会等待 dedicated server 的 RCON 就绪，再把 `-AsPlayer` 原样透传给单 case bench。
3. 真实“带玩家”压测场景下，服务端启动完成并不等于玩家已经进入世界、到达目标维度或完成测试前初始化。

本次目标是在不改动现有 case/matrix 结构的前提下，为单 case 与 suite 补齐“等待玩家就绪 + 可选玩家初始化命令”的自动化能力。

## 方案详情

### 现状分析
1. 现有玩家上下文仅由 `Wrap-WithPlayerContext` 拼接 `execute as <player> at <player> run ...` 完成。
2. 若 `-AsPlayer` 提供但玩家未上线，bench 命令会在运行时失败，而不是先等待或给出明确就绪检查。
3. suite 能做启停服，但不能保证玩家上线、打 tag、切模式、传送等前置动作已完成。
4. 该问题适合在 bench 公共脚本层解决，而不应散落到各个 case、suite 或外部临时脚本中。

### 技术方案
采用“单 case bench 增强，suite 透传复用”的方案：

1. 在 `run-bench.ps1` / `run-bench-suite.ps1` 增加玩家自动化参数。
2. 在 `Bench.Rcon.ps1` 中新增玩家就绪等待与初始化命令执行能力。
3. 在 `Bench.EntryPoint.ps1` 的 `RunCase` / `RunFunctionalCase` 中，在 `reload` 与 `PrepareFunctions` 之后、正式放置节点之前调用玩家就绪流程。
4. suite 不重复实现玩家等待逻辑，只把参数透传给单 case bench，避免两套行为分叉。

### 影响范围
1. `tools/bench/run-bench.ps1`
2. `tools/bench/run-bench-suite.ps1`
3. `tools/bench/lib/Bench.Rcon.ps1`
4. `tools/bench/lib/Bench.EntryPoint.ps1`
5. `tools/bench/lib/BenchSuite.EntryPoint.ps1`
6. `docs_dev/使用说明.md`

## 原子步骤清单

### 步骤 1：补充入口参数
- **操作对象**：`run-bench.ps1`、`run-bench-suite.ps1`
- **具体动作**：新增玩家等待超时、轮询间隔、就绪探针命令、玩家初始化命令等参数，并写入全局状态或透传给单 case bench。
- **预期结果**：命令行可直接声明“等待哪个玩家/选择器”、“等待多久”、“就绪后要执行哪些玩家初始化命令”。
- **关键里程碑**：是

### 步骤 2：实现玩家就绪等待与初始化
- **操作对象**：`Bench.Rcon.ps1`
- **具体动作**：新增通用函数，轮询玩家选择器是否可用，并在玩家就绪后按玩家上下文依次执行初始化命令。
- **预期结果**：bench 可稳定等待玩家进入世界并完成测试前准备。
- **关键里程碑**：是

### 步骤 3：接入单 case 执行流
- **操作对象**：`Bench.EntryPoint.ps1`
- **具体动作**：在 `RunCase` / `RunFunctionalCase` 的准备阶段接入玩家等待与初始化调用。
- **预期结果**：所有带 `-AsPlayer` 的单 case bench 都自动获得该能力。
- **关键里程碑**：是

### 步骤 4：让 suite 复用单 case 能力
- **操作对象**：`BenchSuite.EntryPoint.ps1`
- **具体动作**：把新增玩家自动化参数从 suite 透传到 `run-bench.ps1`。
- **预期结果**：suite 启停服后可继续等待玩家上线并初始化，再执行 case。
- **关键里程碑**：否

### 步骤 5：补充使用说明与验证
- **操作对象**：`docs_dev/使用说明.md`
- **具体动作**：新增带玩家自动化命令说明、参数解释与推荐用法；随后执行 PowerShell 语法检查与基础 bench 命令验证。
- **预期结果**：用户可直接按文档使用；脚本语法与基础入口保持正常。
- **关键里程碑**：是

## 预期结果
1. 单 case bench 可在 `-AsPlayer` 场景下自动等待玩家上下文就绪，而不是直接失败。
2. suite 可在“启服 -> 等 RCON -> 等玩家 -> 初始化玩家 -> 跑 case”的链路上复用同一套逻辑。
3. 用户可以通过选择器、等待参数与初始化命令实现更稳定的“带玩家”压测自动化。
