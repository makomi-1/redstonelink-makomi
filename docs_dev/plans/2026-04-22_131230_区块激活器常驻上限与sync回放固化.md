# 区块激活器常驻上限与sync回放固化

生成时间：2026-04-22 13:12:30
文件名：2026-04-22_131230_区块激活器常驻上限与sync回放固化.md

## 任务背景
本轮需要把近期确认的三项跨区块/区块激活器调整一起落地：
1. 新增 resident 常驻总上限配置，默认 128，最高支持 256。
2. 区块激活器近外显/远外显文本颜色切换为激活器主题色。
3. 目标区块加载时的 sync 回放不再允许关闭，改为硬编码启用，仅保留即时尝试策略配置。

## 方案详情

### 现状分析
- 现有 `RedstoneLinkCrossChunkConfig` 仍暴露 `syncTargetChunkLoadReplay.enabled`，生命周期派发会据此直接跳过回放。
- resident 当前没有总上限配置，也没有对“手动 resident + 激活态区块激活器 resident 并集”做统一计数。
- 区块激活器外显颜色仍按 `activeType` 走普通节点色，没有使用其 GUI 背景主题色。

### 技术方案
- 在跨区块配置中新增 `crosschunk.resident.maxEntries`，并把配置解析、默认快照、模板、测试一起补齐。
- 在 `CrossChunkEffectiveWhitelistService` 中增加“有效 resident 去重计数”与“预估写入后 resident 总量”能力，统一按 `role + type + serial` 去重。
- 在跨区块命令 resident 写入口与区块激活器服务端保存入口增加上限校验，超限时返回明确错误文案。
- 移除 `syncTargetChunkLoadReplay.enabled` 配置及其判断分支，`CHUNK_LOAD` 的 sync 回放改为始终启用。
- 在客户端外显公共渲染工具中补区块激活器主题色常量，并替换近外显/远外显调用点。

### 影响范围
- 配置：`src/main/java/com/makomi/config/**`
- 跨区块 resident 统计与命令：`src/main/java/com/makomi/data/**`、`src/main/java/com/makomi/command/crosschunk/**`
- 区块激活器服务端保存：`src/main/java/com/makomi/network/**`
- 客户端外显：`src/client/java/com/makomi/client/render/**`
- 文案与说明：`src/main/resources/assets/redstonelink/lang/**`、`docs/usage_guide_*.md`
- 测试：`src/test/java/com/makomi/config/**`、`src/test/java/com/makomi/data/**`

## 原子步骤清单

### 步骤 1：调整跨区块配置结构
- **操作对象**：`RedstoneLinkCrossChunkConfig`、解析器、默认快照、模板
- **具体动作**：新增 resident 总上限字段；删除 `syncTargetChunkLoadReplay.enabled` 解析与模板项；保留 `immediateAttemptFirst`
- **预期结果**：配置快照与模板只保留仍然有效的键，resident 上限可配置
- **关键里程碑**：是

### 步骤 2：补 resident 有效去重计数
- **操作对象**：`CrossChunkEffectiveWhitelistService`
- **具体动作**：新增当前有效 resident 去重计数与“命令/区块激活器写入后”的预估计数 helper
- **预期结果**：resident 总量判断统一覆盖手动 resident 与激活态区块激活器 resident
- **关键里程碑**：是

### 步骤 3：接入写入口校验
- **操作对象**：`CrossChunkCommandRegistry`、`ChunkActivatorNetworkServerHandlerSupport`
- **具体动作**：resident add/set 与区块激活器保存前调用预估计数 helper，超限时返回失败文案
- **预期结果**：超出配置上限的 resident 写入会被阻止，且用户能看到明确原因
- **关键里程碑**：是

### 步骤 4：调整区块激活器外显与 sync 回放逻辑
- **操作对象**：客户端 overlay 渲染、`LinkNodeLifecycleDispatchEvents`
- **具体动作**：区块激活器近外显/远外显改用主题色；移除 sync 回放开关分支
- **预期结果**：外显颜色与 GUI 主题一致，target chunk load replay 始终可用
- **关键里程碑**：否

### 步骤 5：补测试与说明
- **操作对象**：配置测试、resident 统计测试、使用文档
- **具体动作**：更新解析断言，新增 resident 去重计数测试，同步 usage guide 说明
- **预期结果**：行为可回归验证，文档不再暴露失效配置键
- **关键里程碑**：是

## 预期结果
- 服务端支持配置 resident 有效总上限，默认 128，最大 256。
- resident 计数口径基于最终生效的唯一节点集合，不会被手动 resident 与区块激活器重复配置绕过。
- 区块激活器近远外显颜色与其 GUI 主题一致。
- 目标区块加载时的 sync 回放改为固定启用。

## 语义对齐说明
- 命名统一继续使用 `triggerSource/core`，无新增旧术语输出。
- 输入/输出方向保持 `triggerSource -> core`，本轮不引入反向写入。
- 与 `LinkNodeType.TRIGGER_SOURCE/CORE` 的映射保持一一对应。
- 兼容层仅保留“读旧写新”的既有处理，本轮无新增旧键写回。
- 残余风险：若存在历史离线配置或运行时激活路径未经过本轮新增写入口，仍需通过回归验证确认 resident 上限拦截覆盖面。
