# Graph 孤立节点池化与高扇出摘要节点

生成时间：2026-04-17 15:55:42
文件名：2026-04-17_155542_graph孤立节点池化与高扇出摘要节点.md

## 任务背景

上一轮已把 Graph 视图改成“连通分量分块布局”，但两个可读性问题仍然突出：

- 完全无连接的节点一多，会稀释主画布对真实拓扑的表达价值。
- 某些 `triggerSource` 挂了大量简单 `core` 叶子目标时，虽然结构语义不复杂，但图上会被大量边和叶子节点挤满。

你已经确认本轮要一次性解决三件事：

- 孤立节点池化
- 高扇出摘要节点
- 强制展开优先级与交互联动

并且这些都只允许发生在网页前端视图层，不得改变 `triggerSource -> core` 的真实保存语义。

## 方案详情

### 现状分析

- 当前 `GraphViewer` 会直接把 `effectiveGraphBundle.nodes` 全量送入布局和 ReactFlow，因此“孤立节点”和“高扇出叶子节点”都会无差别占据画布空间。
- 现有搜索、草稿差异、批量编辑选择、节点详情选择都已经有稳定状态源，可作为“强制显示优先级”的直接输入。
- 现有布局函数已经支持基于“节点列表 + 边列表”做整图排布，因此可以在进入布局前先做一层前端视图裁剪。

### 技术方案

1. 在 `GraphViewer` 中新增“画布视图模型”层，用于从真实 `effectiveGraphBundle` 派生：
   - 主画布节点
   - 主画布边
   - 摘要节点
   - 孤立节点池
2. 孤立节点处理规则：
   - 默认不进入主画布
   - 进入右侧“孤立节点池”列表
   - 用户点击后加入本地临时显示集合，并可聚焦到画布
3. 高扇出摘要规则：
   - 只聚合某个 `triggerSource` 下“仅有这一条 incident edge 的 `core` 叶子节点”
   - 默认保留前 `N` 个叶子目标，其余收为一个摘要节点，如 `+12 leaf cores`
   - 点击来源节点或摘要节点可展开/收起该局部
4. 强制显示优先级：
   - 当前选中节点
   - 搜索命中节点
   - 草稿差异节点
   - 批量编辑已选节点
   - 手动加入画布的孤立节点
   以上节点一律不受聚合/池化影响
5. 所有摘要节点、孤立节点池、展开状态和临时显示状态都只存在于前端视图层，不写回 graph snapshot、draft 或服务端真值。

## 预期结果

- 主画布更聚焦于真正的拓扑结构。
- 大量孤立节点不会继续挤占主图空间，但仍能在侧栏检索和拉回。

- 搜索、草稿差异、编辑选择和详情查看仍可强制看到真实节点。
