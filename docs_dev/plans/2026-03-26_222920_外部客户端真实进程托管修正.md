# 外部客户端真实进程托管修正

生成时间：2026-03-26 22:29:20
文件名：2026-03-26_222920_外部客户端真实进程托管修正.md

## 任务背景

当前 bench 已支持外部客户端自动启动、自动入服与断线重连，但在 Prism Launcher 这类启动器场景下，bench 只托管了外层启动器进程。启动器在拉起真正的 Minecraft `java/javaw` 进程后会快速退出，导致 bench 误判“客户端启动失败”，并且在收尾阶段也无法可靠关闭真实客户端进程。

本次任务目标是在不改变现有 bench 命令接口的前提下，修正单 case 与 suite 的客户端进程托管逻辑，使其能够兼容“启动器进程快速退出、真实游戏进程独立运行”的模式。

## 方案详情

### 现状分析

- `tools/bench/lib/Bench.Client.ps1` 当前通过 `cmd.exe /c <command>` 启动外部客户端，并直接把返回的进程对象视为“客户端进程”。
- 该实现适合直接启动长生命周期游戏进程的命令，不适合 Prism 这类先启动启动器、再分叉真实 Minecraft 进程的命令。
- `tools/bench/lib/Bench.EntryPoint.ps1` 与 `tools/bench/lib/BenchSuite.EntryPoint.ps1` 已把 bench 客户端会话当作统一对象使用，因此最合适的修正点是 `Bench.Client.ps1` 内部，而不是在单 case / suite 外围再增加额外包装脚本。

### 技术方案

在 `Bench.Client.ps1` 内增加“真实客户端进程识别与托管”能力：

1. 启动前记录现有 `java/javaw` 进程快照。
2. 执行外部客户端启动命令，得到启动器进程对象。
3. 若外层进程持续存活，则沿用现有模式。
4. 若外层进程快速退出，则进入“启动器模式”：
   - 轮询新出现的 `java/javaw` 进程；
   - 依据命令行中是否包含 bench 客户端实例根目录或工作目录判断其是否属于当前 bench 客户端；
   - 若识别到真实客户端进程，则切换为托管该进程。
5. 停止时优先关闭真实客户端进程；若外层启动器进程仍在，再补充清理启动器进程。

### 影响范围

- `tools/bench/lib/Bench.Client.ps1`
- `tools/bench/lib/BenchSuite.EntryPoint.ps1`
- `docs_dev/使用说明.md`
