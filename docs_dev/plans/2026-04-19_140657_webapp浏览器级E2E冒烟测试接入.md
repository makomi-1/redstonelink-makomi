# webapp浏览器级E2E冒烟测试接入

生成时间：2026-04-19 14:06:57
文件名：2026-04-19_140657_webapp浏览器级E2E冒烟测试接入.md

## 任务背景

`webapp` 已完成前两层自动化测试：

1. 纯逻辑单测
2. React 组件测试

为了继续补足真实浏览器环境下的页面交互回归，本轮接入第三层浏览器级 E2E 测试，使用 `Playwright` 先建立一组小规模但高价值的冒烟用例。

本轮重点是“真实浏览器 + mock /api/**”，不接真实 Minecraft bridge，不改后端或保存真值语义。

## 方案详情

### 现状分析

- `webapp/package.json` 当前没有 `Playwright` 依赖和 E2E 脚本。
- 现有前端测试已经使用 `Vitest + jsdom`，适合逻辑和组件层，但不能覆盖真实浏览器中的路由、真实 DOM 事件、网络拦截和部分复杂交互。
- `App.tsx` 已经承载首页、recording、graph 三类页面路由切换。
- `GraphViewer.tsx` 已经包含搜索输入态/应用态分离、保存预检提示、序号/频道模式切换等稳定的可见交互锚点，适合做首批 E2E 冒烟。

### 技术方案

本轮在 `webapp` 内接入 `Playwright`，只先跑 `Chromium`。通过 Playwright 的 `page.route('**/api/**')` 在浏览器层统一 mock `/api/**`，覆盖：

- `./api/ping`
- `./api/storage/index`
- `./api/storage/entry`
- `./api/graph/draft`
- `./api/graph/preview`
- `./api/graph/save`

Playwright 通过 `webServer` 启动本地 `vite` 开发服务，直接对真实页面执行自动化操作。首批只建立少量冒烟场景，不追求一次性全覆盖。

### 影响范围

- `webapp/package.json`
- `webapp/package-lock.json`
- `.gitignore`
- `webapp/playwright.config.ts`
- `webapp/e2e/**`
- 可能补充少量测试专用工具文件

## 原子步骤清单

### 步骤 1：接入 Playwright 基建
- **操作对象**：`webapp/package.json`、`webapp/package-lock.json`、`webapp/playwright.config.ts`、`.gitignore`
- **具体动作**：新增 Playwright 依赖、E2E 运行脚本、浏览器配置与 E2E 产物忽略规则
- **预期结果**：`webapp` 可直接运行浏览器级 E2E 测试
- **关键里程碑**：是

### 步骤 2：建立统一的浏览器侧 API mock
- **操作对象**：`webapp/e2e/**`
- **具体动作**：集中封装 `/api/**` route mock，提供 graph/recording/home 场景所需的基础返回数据与错误分支控制
- **预期结果**：E2E 测试不依赖真实 Minecraft bridge
- **关键里程碑**：是

### 步骤 3：编写首批冒烟用例
- **操作对象**：`webapp/e2e/**/*.spec.ts`
- **具体动作**：补页面路由、搜索和应用、save/preview 错误提示、关键视图切换，以及一个稳定的真实鼠标交互用例
- **预期结果**：第三层具备最小但有效的真实浏览器回归能力
- **关键里程碑**：是

### 步骤 4：执行验证并收束
- **操作对象**：E2E 命令、现有前端测试与仓库回归命令
- **具体动作**：运行 `typecheck`、`vitest`、`playwright`，最后运行根目录 `.\gradlew.bat test testIntegration testClient testSlow --no-daemon`
- **预期结果**：确认第三层接入未破坏现有前端与仓库链路
- **关键里程碑**：是

## 预期结果

- `webapp` 新增 Playwright 浏览器级 E2E 冒烟能力。
- 路由、搜索应用、保存错误提示、显示模式切换等高价值页面流程有了真实浏览器环境下的自动回归。
- 本轮不改 `triggerSource -> core` 真值语义，不触碰 snapshot、draft 与服务端真实保存逻辑。
