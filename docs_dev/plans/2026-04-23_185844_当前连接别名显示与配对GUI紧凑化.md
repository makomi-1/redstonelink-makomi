# 当前连接别名显示与配对GUI紧凑化

生成时间：2026-04-23 18:58:44
文件名：2026-04-23_185844_当前连接别名显示与配对GUI紧凑化.md

## 任务背景

当前 triggerSource/core 配对 GUI 的“当前连接”字段展示过短，且 GUI、GUI tooltip、近外显 HUD、物品 tooltip 中的当前连接仍以纯序号结构展示。目标是统一改为节点别名展示口径：有别名时显示 `别名(#序号)`，无别名时显示 `#序号`；同时紧凑化核心与触发器配对 GUI，但不改变外层预留空间。

## 方案详情

### 现状分析

- 配对 GUI 当前只接收目标序号列表，无法在客户端还原目标别名。
- 近外显 HUD 当前连接快照只下发目标序号，缓存值也只保存序号。
- 物品 tooltip 依赖 `LinkItemData` 中的 `rl_links` 序号数组，缺少目标展示文本快照。
- 当前配对 GUI 面板宽高预留已固定，展示过短应通过内部布局与文本组织优化解决，不应扩大面板。

### 技术方案

- 在当前连接读模型中补充目标展示文本列表，并从服务端查询时按 `NodeAliasDisplayUtil.formatDisplayText` 生成。
- 扩展配对 GUI 打开 payload 与近外显当前连接 payload，使客户端可获得目标展示文本。
- 为物品 NBT 增加目标展示文本缓存字段，并在现有连接快照同步链路中一起刷新。
- 新增通用展示文本列表截断工具，供物品 tooltip、GUI、HUD 复用，避免显示口径分叉。
- 配对 GUI 保持现有面板预留宽高，仅压缩内部 Y 间距，并将当前连接内容按可用宽度显示更多信息。

### 影响范围

- `NodeLinksSnapshot` 与 `NodeSnapshotQueryService` 的当前连接读模型。
- `PairingNetwork`、`PairingNetworkPayloadSupport`、客户端接包与近外显缓存。
- `LinkItemData`、`PairableBlockItem`、`LinkerItem`、`TooltipTextTruncateUtil`。
- `AbstractMultiPairingScreen`、`TriggerSourcePairingScreen`、`CorePairingScreen`。
- payload、NBT、HUD 文案与配对布局相关测试。

### 语义对齐说明

- 命名继续使用 `triggerSource/core`，不新增旧术语输出。
- 本次只扩展展示快照，不改变 `triggerSource -> core` 写入方向。
- `LinkNodeType.TRIGGER_SOURCE/CORE` 映射保持一一对应。
- 兼容层采用读旧写新：缺少展示文本时回退到 `#序号`。
- 残余风险：旧物品栈在下一次同步前只能显示纯序号，但不会产生错误。

## 原子步骤清单

### 步骤 1：扩展当前连接读模型
- **操作对象**：`NodeLinksSnapshot`、`NodeSnapshotQueryService`
- **具体动作**：为当前连接目标增加展示文本列表，并在服务端查询时按对侧节点类型解析别名。
- **预期结果**：服务端当前连接快照同时具备目标序号和目标显示文本。
- **关键里程碑**：是

### 步骤 2：扩展网络 payload 与客户端缓存
- **操作对象**：`PairingNetwork`、`PairingNetworkPayloadSupport`、客户端接包、近外显 snapshot cache
- **具体动作**：在配对 GUI 打开包与近外显当前连接回包中编码/解码目标展示文本。
- **预期结果**：GUI 与 HUD 可直接使用服务端真值展示别名。
- **关键里程碑**：是

### 步骤 3：扩展物品 NBT 当前连接快照
- **操作对象**：`LinkItemData` 与物品 tooltip 入口
- **具体动作**：写入/读取目标展示文本快照，旧栈缺字段时按序号回退。
- **预期结果**：物品 tooltip 的当前连接显示与 GUI/HUD 口径一致。
- **关键里程碑**：是

### 步骤 4：统一当前连接显示格式
- **操作对象**：GUI、HUD、tooltip 文本构造工具
- **具体动作**：将当前连接文本构造改为展示文本列表截断，保留空值 `-` 与 `(+n)` 省略提示。
- **预期结果**：相关展示统一为 `别名(#序号)` 或 `#序号`。
- **关键里程碑**：是

### 步骤 5：紧凑化配对 GUI
- **操作对象**：`AbstractMultiPairingScreen`
- **具体动作**：不修改外层预留宽高，只压缩内部间距与当前连接行展示策略。
- **预期结果**：核心和触发器 GUI 更紧凑，当前连接可用显示空间更充分。
- **关键里程碑**：是

### 步骤 6：补充并运行测试
- **操作对象**：payload、NBT、HUD、layout 相关测试
- **具体动作**：补充回归断言并执行定向测试，再按需要执行更大范围测试。
- **预期结果**：关键链路与兼容路径有自动化覆盖。
- **关键里程碑**：是

## 预期结果

- GUI、GUI tooltip、近外显 HUD、物品 tooltip 的当前连接统一展示别名与序号。
- 没有别名的目标直接显示 `#序号`，旧数据兼容。
- 配对 GUI 更紧凑，但不改变面板预留空间。
