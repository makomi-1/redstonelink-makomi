# graph与曲线页布局说明精简及宽度扩展

生成时间：2026-04-19 19:09:49
文件名：2026-04-19_190949_graph与曲线页布局说明精简及宽度扩展.md

## 任务背景

当前网页前端已经完成 graph 编辑器左侧工具栏布局，但仍存在说明文案混杂、右侧详情冗余、节点列表重复显示类型、graph/recording 页面宽度不一致，以及 graph / recording 页面底部仍显示原始 JSON 等问题。用户要求继续收紧展示信息并扩大主要交互区域。

## 方案详情

### 现状分析

- `webapp/src/components/GraphViewer.tsx` 中，左侧提示文案把固定交互说明与随模式变化的说明混在同一段里；右侧详情仍显示 `Current Target Cores` 和 `Capability Flags` 等冗余块；节点池和批量编辑列表直接使用 `displayText`，会重复把类型一起显示出来。
- `webapp/src/app/GraphPage.tsx` 中，`Dedicated Graph Analyzer` 与连接状态未与页面标题形成你要求的右上对齐关系；同时页面底部仍保留原始 JSON 展示。
- `webapp/src/app/RecordingPage.tsx` 中，录制曲线页面仍保留原始 JSON，并继续使用默认录制页宽度，没有和 graph 页面宽度对齐。
- `webapp/src/app.css` 中，graph 页面已单独加宽，但右栏偏窄；recording 页面仍是默认宽度，曲线卡片也没有利用更宽的页面空间。

### 技术方案

- 仅做前端展示层改造，不改变 graph / recording 的数据结构、保存接口和草稿语义。
- graph 页面头部改为“左标题说明 + 右桥接状态/分析器标识”的紧凑布局。
- `GraphViewer` 的提示文案拆成“动态说明”和“固定交互说明”，其中固定说明沉到左栏底部。
- 删除右侧详情中无价值的 `Current Target Cores` 与 `Capability Flags` 区块。
- 在 `GraphViewer` 局部引入紧凑节点标签格式化，只影响节点池和批量编辑列表，统一显示为 `#序号 (别名)` / `#序号`。
- 继续放宽 graph 页面，并加宽右侧详情栏；同时把 recording 页面宽度与 graph 页面拉齐，并让曲线图区吃到新增宽度。
- 去掉 graph 与 recording 页面底部的原始 JSON 区块。
- 同步调整前端测试断言，再执行前端与 Gradle 全量回归。
