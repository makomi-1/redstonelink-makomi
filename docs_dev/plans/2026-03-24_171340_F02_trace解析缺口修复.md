# F02 trace解析缺口修复

生成时间：2026-03-24 17:13:40
文件名：2026-03-24_171340_F02_trace解析缺口修复.md

## 任务背景
首批必跑 suite 在二次收敛后仅剩 `F02 link_lifecycle_add_remove_set_clear` 未通过。

最新结果显示：
- `link add/get/remove/set/clear` 命令本身全部成功；
- 失败仅剩 `tick_window` 断言；
- 原始 `node trace read` 响应文本中实际包含缺失 tick，但 bench 结果中的 `samples` 丢失了该条记录。

因此本轮问题已收敛为：bench 对 `NodeTrace` 响应的解析不够稳健，无法处理 RCON 返回中被换行打断的 sample 前缀与字段文本。

## 方案详情

### 现状分析
- `tools/bench/run-bench.ps1` 的 `Split-NodeTraceEntries` 依赖精确前缀 `"[RedstoneLink/NodeTrace]"` 做切分。
- 实际 RCON 响应可能在前缀内部或字段内部插入换行，导致：
  - 一个 sample 无法被切分成独立 entry；
  - `Parse-NodeTraceSamples` 最终漏掉某个 tick。
- 该问题已经在 `F02` 中复现，并可由结果文件中的原始 `response` 与解析后的 `samples` 对比确认。

### 技术方案
- 为 `NodeTrace` 响应增加统一规范化步骤：
  - 先处理全角标点；
  - 再移除 `CR/LF`，把被打断的前缀和字段重新拼回连续文本。
- `Split-NodeTraceEntries` 与 `Parse-NodeTraceSamples` 统一复用该规范化文本，避免同一条 sample 因换行破碎而被遗漏。

### 影响范围
- `tools/bench/run-bench.ps1`
