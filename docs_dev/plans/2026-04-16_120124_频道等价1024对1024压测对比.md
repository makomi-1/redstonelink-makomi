# 频道等价1024对1024压测对比

生成时间：2026-04-16 12:01:24
文件名：2026-04-16_120124_频道等价1024对1024压测对比.md

## 任务背景

用户要求补一个频道模式下的性能压测，并与现有序号模式进行同口径对比。  
最初候选口径包括 `1 -> 1024`、`1024 -> 1`、`1024 -> 1024` 与“单频道全连接”放缩方案；经核对现有 `P18` 的 `banded16` 拓扑后确认：

- `fanout=16`
- `stride=16`
- `wrap=true`

因此窗口是循环复用而非重叠，`P18` 实际可被精确拆成 `64` 个互不重叠的 `16 triggerSource + 16 core` 频道块，不需要退化成 `1024-1-1024` 或单频道全连接放缩证明。

本轮目标是在**保持默认 `crosschunk.directBatching=all_direct` 与 `crosschunk.dispatch.batchWindowTicks=0`** 的前提下，新增一个与 `P18` 边集完全等价的频道版 `1024 -> 1024 sync` 压测，并分别对序号版/频道版各执行 `3` 次，最后汇总均值。

## 方案详情

### 现状分析

- 现有正式重压基线 `P18` 是 `1024 -> 1024 sync` 的 `banded16` 规则化多对多映射。
- 纯性能 case 已支持 `setupPhases`，且这些 phase 运行在 spark 采集开始之前，因此频道配置与边展开可以放在性能窗口外完成。
- 现有 bench OCC 频道提交通道只支持**单节点** `triggerSource/core` 提交，不适合直接在 case JSON 中硬编码 2048 条配置命令。
- bench phase 解析器已经支持通过 `serialRef/sourceGroup/targets` 获取稳定的“按布局排序后的 serial 顺序”，因此可以新增一个 setup phase，在脚本层按固定分块自动映射频道号。

### 技术方案

1. 在 `tools/bench/lib/Bench.FunctionalTrace.Phases.ps1` 新增一个 setup phase：
   - 输入 `type`、`serialRef`、`partitionSize`、`channelBase` 等参数；
   - 按 bench 现有 serial 顺序，把第 `0..15` 个节点映射到频道 `1`，第 `16..31` 个映射到频道 `2`，以此类推；
   - 依次执行 `redstonelink bench occ pairing submit ... channel ... expectedRevision=0`；
   - 因为性能 case 使用 fresh world，节点初始 revision 为 `0`，可直接用固定 `expectedRevision=0`，避免额外 snapshot 开销。

2. 新增频道版 performance case：
   - 复用 `P18` 的 arena、`1024` 个 `triggerSource`、`1024` 个 `core` 与相同的 `sync_square_wave` 驱动窗口；
   - 不再预建普通 serial links；
   - 在 `setupPhases` 中分别对 `core` 与 `triggerSource` 执行一次“按 16 分块映射 64 频道”的批量频道配置；
   - setup 结束后等待少量 tick，让频道模式同步出的 ordinary links 和相关运行态完成收敛。

3. 新增专项对比 suite：
   - 包含现有序号版 `P18` 与新增频道版 case；
   - 不覆写 `directBatching`，保持默认 `all_direct`；
   - 仅显式固定 `crosschunk.dispatch.batchWindowTicks=0`，确保结果口径一致。

4. 构建与验证：
   - 先构建当前工作区 jar，再同步 dedicated server jar；
   - 运行对比 suite 共 `3` 轮；
   - 依据 `docs/使用说明.md` 的 spark 章节，从 spark 原始 JSON 摘要中提取主指标并统计均值。

### 影响范围

- `tools/bench/lib/Bench.FunctionalTrace.Phases.ps1`
- `tools/bench/cases/performance/` 新增频道版 `1024 -> 1024 sync` case
- `tools/bench/matrix-performance-heavy.json`
- `tools/bench/suites/` 新增频道/序号对比 suite
- `docs_dev/reviews/` 新增本轮审查文档

### 语义对齐说明

- 命名统一使用 `triggerSource/core`。
- 方向保持 `triggerSource -> core`。
- 频道版压测通过频道配置同步 ordinary links，但性能目标是比较频道模式运行时派发与序号模式在**等价边集**下的表现，不引入新的业务语义。
- 本轮不新增 `com.makomi.api.v1.*` 依赖。
- 残余风险：性能结果仍会受 JVM 暖机、GC 与 spark 采样波动影响，因此结论以三轮均值为准。

## 预期结果

得到一个与 `P18` 边集完全等价的频道版 `1024 -> 1024 sync` 正式重压 case；在默认 `all_direct + batchWindowTicks=0` 口径下，对序号模式与频道模式分别执行三轮 dedicated 压测，并输出 spark 主指标均值对比，进而判断频道收口优化在等价高压拓扑下是否带来可观察的性能收益。
