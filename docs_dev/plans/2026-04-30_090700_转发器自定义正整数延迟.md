# 转发器自定义正整数延迟

生成时间：2026-04-30 09:07:00
文件名：2026-04-30_090700_转发器自定义正整数延迟.md

## 任务背景

草稿新增要求：转发器支持自定义延迟，允许输入任意 `>0` 的 tick；`2 tick` 以上需要标为实验性，并明确提示“延迟期间若有新输入，会重新计算延迟并丢掉之前的输入”。当前实现仍停留在 `1/2 tick` 两档枚举，编辑器与展示层也没有自定义输入能力，需要统一扩展。

## 方案详情

### 现状分析

- 运行时调度本身已支持“新输入覆盖旧 pending”：
  - `onActiveChanged(...)` -> `armDelayedDispatch(...)`
  - 新的 `pendingDispatchTick/pendingDispatchPower` 会直接覆盖旧值
- 限制点主要在数据模型与 UI：
  - `RepeaterDelay` 只支持 `ONE_TICK/TWO_TICKS`
  - 编辑器只有两个延迟按钮
  - payload、物品 NBT、tooltip、HUD 和单测都只认 `1/2 tick`

### 技术方案

- 将 `RepeaterDelay` 从枚举重构为“正整数 tick 值对象”：
  - 支持任意 `>0` 的延迟值
  - 保留 `ONE_TICK/TWO_TICKS` 常量，减少既有调用面改动
  - 继续兼容旧 token：`1tick/2tick`
  - 新值统一按规范 token 持久化：`Ntick`
- 将转发器编辑器从“按钮切换”改成“数字输入框”：
  - 只接受正整数
  - tooltip 提示规则、实验性说明和“新输入覆盖旧 pending”语义
- 展示层统一支持自定义 tick：
  - 物品 tooltip
  - HUD 文本
  - 编辑器显示
- 运行时主链保持最小改动，继续复用现有延迟调度语义。

## 原子步骤清单

- **操作对象**：`RepeaterDelay`、`RepeaterConfigSnapshot`
- **具体动作**：把延迟从枚举改成支持任意正整数的值对象，并保留 `1/2 tick` 常量与旧 token 兼容解析
- **预期结果**：转发器配置可持久化任意 `>0` 的延迟值
- **关键里程碑**：是

- **预期结果**：玩家可输入任意正整数 tick，并收到实验性提示
- **关键里程碑**：是

- **操作对象**：tooltip/HUD/lang/payload/NBT 相关调用点

- **预期结果**：旧数据可读，新数据统一写成新规范
- **关键里程碑**：是

### 步骤 4：补最小回归并执行全量测试

- **关键里程碑**：是

## 预期结果

- 转发器支持任意 `>0` 的自定义输入延迟。
- `2 tick` 以上在编辑器 tooltip 中被标注为实验性。
- 延迟期间新输入覆盖旧 pending 的语义保持不变。
- 非转发器链路与 `triggerSource -> core` 方向语义不受影响。
