# graph包围框拖拽卡顿与框选后消失修复

生成时间：2026-04-18 00:53:45
文件名：2026-04-18_005345_graph包围框拖拽卡顿与框选后消失修复.md

## 任务背景

graph 视图在核心聚合块展开后会绘制包围框。当前已确认两个相关问题：

1. 展开后拖拽会明显变卡，且当包围框意外消失后卡顿会明显缓解
2. 在框选完成后，展开块的包围框会一起消失

这说明包围框既进入了拖拽热路径，又错误地跟随选中态变化参与了重建。目标是在不改 `triggerSource/core` 真值、不改 snapshot、draft 和服务端语义的前提下，仅从前端 graph 视图层优化包围框的渲染策略。

## 方案详情

### 现状分析

- 包围框当前作为 `aggregateOutline` ReactFlow 节点渲染
- 包围框节点直接由 `buildAggregateOutlineFlowNodes(graphCanvasView.aggregateNodes, nodes)` 现算，依赖实时 `nodes`
- `nodes` 会在选中态、拖拽态和结构重排时频繁变化，因此包围框会被反复重算和重挂载
- 包围框样式包含大面积渐变和阴影，在拖拽时会放大重绘成本

### 技术方案

1. 把包围框节点从 `displayNodes` 的实时现算链路中拆出，改为单独维护一份包围框节点状态
2. 只在“聚合结构变化”或“节点位置变化”后同步包围框；纯选中态变化不再触发包围框重建
3. 在节点拖拽和选中组拖拽期间临时隐藏包围框，拖拽结束后再按最终位置恢复
4. 轻量化包围框样式，去掉高成本阴影，仅保留轻边框和浅背景

### 影响范围

- `webapp/src/components/GraphViewer.tsx`
- `webapp/src/app.css`
- `docs_dev/reviews/` 审查文档
- `docs_dev/experiences/` 经验文档

### 语义对齐说明

- 命名仍只使用 `triggerSource/core`
- 真实保存语义仍然只处理 `triggerSource -> core`
- 本轮仅修前端 graph 视图层的包围框渲染与交互性能，不改 snapshot、draft 和服务端真值
- 与 `LinkNodeType.TRIGGER_SOURCE/CORE` 映射关系不变
- 本轮无新增兼容字段，兼容层仍然是“读旧写新”
