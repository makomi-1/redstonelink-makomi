# 网页前端重文件重构

生成时间：2026-04-18 17:19:06
文件名：2026-04-18_171906_网页前端重文件重构.md

## 任务背景

当前 `webapp` 前端中存在明显过重的文件，尤其是 `GraphViewer.tsx` 与 `App.tsx`，已经同时承担大量数据类型、纯算法、页面状态、网络访问和 JSX 结构，继续叠加功能会显著提高维护成本与回归风险。

本轮目标不是新增业务能力，而是在不改变现有 `triggerSource/core` 语义和 graph/draft/save 业务含义的前提下，先完成一次低风险的结构重构，把重文件拆成更清晰的模块边界。

## 方案详情

### 现状分析

- `webapp/src/components/GraphViewer.tsx` 超过 3000 行，同时包含常量、内部类型、搜索逻辑、聚合构建、布局算法、draft 变换、React 状态和完整页面 JSX。
- `webapp/src/App.tsx` 超过 800 行，同时包含 URL 解析、本地网页桥探测、存储索引拉取、entry 加载和三个页面的顶层装配。
- `webapp/src/app.css` 也较大，但当前优先级低于 TSX 结构重构，因为样式迁移和组件拆分同时进行会放大回归面。

### 技术方案

1. 抽离 `App.tsx` 的纯逻辑模块：
   - 提取 app 级类型
   - 提取 URL location 解析与构建
   - 提取格式化工具
   - 提取 storage / bridge 的读取函数
   - 让 `App.tsx` 只保留顶层状态和页面装配

2. 抽离 `GraphViewer.tsx` 的纯逻辑模块：
   - 提取 graph viewer 常量与内部类型
   - 提取搜索与样式计算
   - 提取聚合视图构建
   - 提取自动布局算法
   - 提取 draft 变换、diff、保存调用
   - 让 `GraphViewer.tsx` 主要承担状态协调和事件分发

3. 若主组件体积仍明显过大，再继续拆 graph UI 结构：
   - toolbar
   - canvas panel
   - sidebar / isolated pool / batch editor

4. 本轮不主动大迁移 `app.css`：
   - 仅在拆分过程中必要时保留现有样式引用
   - 避免结构重构和样式重排同时发生

### 影响范围

- `webapp/src/App.tsx`
- `webapp/src/components/GraphViewer.tsx`
- 新增 `webapp/src/app/**` 模块
- 新增 `webapp/src/components/graphViewer/**` 模块
