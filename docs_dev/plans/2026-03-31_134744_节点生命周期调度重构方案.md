# 节点生命周期调度重构方案

生成时间：2026-03-31 13:47:44
文件名：2026-03-31_134744_节点生命周期调度重构方案.md

## 任务背景

当前与区块活动相关的补发、失效与读档校正，主路径仍依赖全局 `CHUNK_LOAD/CHUNK_UNLOAD` 挂钩后扫描区块内方块实体。  
这条路径存在两个核心问题：

1. 区块活动与业务重算绑定过深，容易把整区块扫描带入主线程热路径。
2. 以区块扫描驱动上线/下线语义时，跨重启恢复与补偿成本偏高，也容易与真实方块移除语义缠绕。

本次确认后的重构目标，是把主路径改为“节点/方块实体自感知生命周期事件发布”，由节点命中式触发调度，而不是依赖全局区块活动扫描。  
此前讨论过的 `sync` 来源区块活动重算、补发与重算独立开关、输入器跨重启清理等内容仍保留为后续约束，但当前第一优先级是生命周期调度管线本身。

## 方案详情

### 现状分析

1. 当前全局区块活动扫描入口集中在区块生命周期服务，核心位置包括：
   - `LinkNodeLifecycleDispatchEvents`
   - `CoreBlockStateResyncService`
   - `TriggerSourceInputStateResyncService`
2. 当前项目中的真实节点移除，实际由各节点方块的 `onRemove(...) -> unregisterNode(true)` 驱动，而不是直接依赖 `setRemoved()`。
3. 底层时序确认结果如下：
   - 真实换块时，`onRemove(...)` 早于 `setRemoved()`。
   - `onRemove(...)` 执行期间旧方块实体仍可访问。
   - 区块批量清理/上下文脱附可以直接命中 `setRemoved()`，不会走 `onRemove(...)`。
   - 新放置路径中，方块实体的附着/`clearRemoved()` 早于项目当前的 `setPlacedBy(...) -> setLinkData(serial)`。
   - 读档恢复路径中，`serial` 一般会先由 NBT 读入，再进入附着流程。

### 技术方案

第一阶段方案不再以“全局区块活动扫描”作为生命周期主线，而改为“节点自感知 + 预算化后处理队列”的调度模型。

#### 1. 生命周期语义拆分

将节点相关状态拆成三层：

1. 物理存在态：方块是否被真实替换、挖掘或破坏。
2. 上下文附着态：方块实体当前是否仍挂在区块/世界上下文中。
3. 就绪发布态：节点是否已满足发布 online 的最小条件，例如 `level` 已就绪且 `serial > 0`。

这样可以避免把“真实移除”“区块卸载”“刚创建但未分配 serial”这三类情况混成一个生命周期事件。

#### 2. 事件来源改造

1. `onRemove(...)`
   - 仅作为“物理移除预标记”入口。
   - 在旧方块实体仍可访问时打瞬时标记，例如 `physicalRemovalInProgress`。
   - 真实移除仍沿用现有 `unregisterNode(true)` 与退役兜底链路。
2. `clearRemoved()`
   - 仅表示“上下文已附着”。
   - 不无条件立即发布 online。
   - 只记录“待发布附着事件”。
3. `setRemoved()`
   - 仅表示“上下文已脱附”。
   - 若命中 `physicalRemovalInProgress`，则视为物理移除后的后继脱附，不重复发布普通 offline/context-detach。
   - 若未命中该标记，则视为区块/上下文脱附，可进入普通 offline/context-detach 流程。

#### 3. 风险 1 处理策略

风险 1：如何区分“真实方块移除”和“区块/上下文脱附”，避免重复发布或误退役。

处理策略：

1. 以 `onRemove(...)` 作为真实物理移除的唯一前置信号。
2. 在节点实例内保留瞬时物理移除标记。
3. `setRemoved()` 只处理上下文语义，不直接承担退役判定。
4. 节点实例增加 attach/detach 幂等位，避免重复发布生命周期事件。
5. 退役语义继续沿用现有掉落物检测与待确认退役机制，不并入普通生命周期主链。

#### 4. 风险 2 处理策略

风险 2：附着事件可能早于 `serial` 分配，导致 online 发布过早。

触发边界：

1. 新放置路径中，`clearRemoved()` 可能早于 `setPlacedBy(...) -> setLinkData(serial)`。
2. 读档恢复通常不受该边界影响，因为 `serial` 一般会先由 NBT 载入。

处理策略：

1. `clearRemoved()` 只记录“已附着、待发布”。
2. 真正发布 online 的前置条件至少为：
   - `level != null`
   - `serial > 0`
   - 当前不处于 `physicalRemovalInProgress`
3. 在 `setLinkData(...)` 中补一次“就绪后冲刷待发布附着事件”。
4. 若节点始终未获得有效 `serial`，则不发布 online。

#### 5. 生命周期调度管线

生命周期钩子本身保持轻量，不直接在钩子里执行补发、失效重算或区块扫描。

统一改为：

1. 节点实例命中 attach/detach 后，只向生命周期管理器发布轻量事件。
2. 生命周期管理器负责：
   - 幂等去重
   - 注册表维护
   - 将后处理任务投递到预算化队列
3. 预算化队列在 tick 中消费：
   - 按节点预算
   - 按 target 预算
   - 按 chunk 预算
4. 消费阶段按 `targetChunk -> targetSerial` 聚合受影响对象。
5. 重算后仅在结果确实变化时才应用，避免无差别重写世界状态。

#### 6. 与实验性玩法的关系

以下内容不作为第一阶段主链的一部分，但保留为第二层约束：

1. `sync` 来源的区块活动重算作为实验性玩法，默认关闭。
2. 补发与重算保持独立开关，不强耦合。
3. 输入器跨重启清理纳入实验性玩法，默认关闭，并明确说明输入器是内存态测试/调试工具。
4. 动态处理窗口可后续配置化，默认可从 `0 tick` 起步。

### 影响范围

第一阶段预计涉及以下模块：

1. 节点方块实体基类 `PairableNodeBlockEntity`
2. 各节点方块的 `onRemove(...)` 路径
3. 生命周期管理与预算化队列
4. 现有全局区块生命周期扫描入口的迁移或裁撤
5. 与生命周期相关的补发/失效重算衔接层

## 原子步骤清单

### 步骤 1：收敛生命周期语义
- **操作对象**：生命周期设计与节点状态边界
- **具体动作**：明确物理存在态、上下文附着态、就绪发布态三层语义，并把真实移除与上下文脱附拆开
- **预期结果**：后续实现不再把 `onRemove(...)`、`clearRemoved()`、`setRemoved()` 混为同一语义
- **关键里程碑**：是

### 步骤 2：为节点实体补充瞬时生命周期状态
- **操作对象**：`PairableNodeBlockEntity`
- **具体动作**：增加物理移除标记、待发布附着标记、attach/detach 幂等状态与“就绪后冲刷”入口
- **预期结果**：节点实例能够自描述当前生命周期状态，并在正确时机发布事件
- **关键里程碑**：是

### 步骤 3：调整真实移除与上下文脱附入口
- **操作对象**：各节点 block 的 `onRemove(...)` 与 block entity 的附着/脱附钩子
- **具体动作**：在 `onRemove(...)` 提前打物理移除标记；在 `clearRemoved()` / `setRemoved()` 中仅处理上下文语义与待发布逻辑
- **预期结果**：真实移除与区块脱附可以稳定区分，风险 1 可控
- **关键里程碑**：是

### 步骤 4：接入生命周期管理器与预算化队列
- **操作对象**：生命周期调度服务
- **具体动作**：实现轻量事件收口、幂等去重、预算化入队与 tick 消费
- **预期结果**：生命周期钩子不再直接执行重路径业务逻辑
- **关键里程碑**：是

### 步骤 5：按目标聚合补发与重算
- **操作对象**：补发/失效重算处理链
- **具体动作**：消费生命周期事件时按目标区块与目标序号聚合，并在结果变化时再应用
- **预期结果**：减少重复计算与无效写入，控制主线程成本
- **关键里程碑**：否

### 步骤 6：迁移现有全局区块活动扫描主路径
- **操作对象**：`LinkNodeLifecycleDispatchEvents`、`CoreBlockStateResyncService`、`TriggerSourceInputStateResyncService`
- **具体动作**：将主路径从全局区块活动扫描迁移到节点命中式生命周期调度，仅保留实验性或补偿性用途
- **预期结果**：区块活动不再成为默认业务重算入口
- **关键里程碑**：是

### 步骤 7：补充配置、说明与验证
- **操作对象**：配置结构、测试与使用说明
- **具体动作**：为实验性开关与默认语义补充配置解析、回归测试和必要说明
- **预期结果**：默认行为与实验性玩法边界清晰，可回归验证
- **关键里程碑**：否

## 预期结果

1. 生命周期主路径从“全局区块活动扫描”切换为“节点自感知事件发布”。
2. `onRemove(...)` 与 `setRemoved()` 的语义边界清晰，不再混淆真实移除与上下文脱附。
3. 新放置节点不会因为 `serial` 尚未分配而过早发布 online。
4. 补发与重算进入预算化队列，并按目标聚合执行，降低主线程阻塞风险。
5. 实验性玩法与默认稳定语义解耦，后续可独立启用和验证。

## 语义对齐说明

1. 本方案内部术语统一使用 `triggerSource/core`，与 `LinkNodeType.TRIGGER_SOURCE/CORE` 保持一一映射。
2. 方向语义保持 `triggerSource -> core`，本方案未引入任何反向写入路径。
3. 兼容层仍按“读旧写新”原则处理，旧术语仅允许保留在输入别名解析层。
4. 本方案不引入 `com.makomi.api.v1.*` 依赖。
5. 当前残余风险：
   - 活塞迁移是否归类为物理移除，仍需后续专项收口。
   - 若节点实例级幂等位设计不完整，仍可能出现重复 attach/detach 发布。
