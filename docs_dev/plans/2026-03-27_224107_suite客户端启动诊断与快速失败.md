# suite客户端启动诊断与快速失败

生成时间：2026-03-27 22:41:07
文件名：2026-03-27_224107_suite客户端启动诊断与快速失败.md

## 任务背景
在将 suite 外部客户端启动时机后移到 dedicated server ready 之后，实际跑例时又观察到一种新现象：服务端已经 ready 很久，但外部客户端没有出现。由于用户手动停服后 summary 只留下 RCON 断连错误，而 `benchClient` 为 `null`，现有结果不足以快速判断是“未请求自动客户端”“未进入启动分支”“启动抛错”还是“启动后未被记录”。

## 方案详情

### 现状分析
- `tools/bench/lib/BenchSuite.EntryPoint.ps1` 目前只有在成功拿到 `$benchClientSession` 后才会写入 `suiteSummary.benchClient`。
- 若本轮没有进入启动分支，或启动前就停在其它阶段，summary 中只能看到 `benchClient = null`，无法判断请求态与尝试态。
- 当前 suite 也没有把“正在等 RCON ready / 正在尝试启动 bench client / 已进入等玩家就绪”这些关键节点直接打到 host 日志。

### 技术方案
- 为 suite summary 增加四个顶层诊断字段：
  - `benchClientRequested`
  - `benchClientStartAttempted`
  - `benchClientStartSucceeded`
  - `benchClientStartError`
- 在关键节点增加显式日志：
  - suite 启动时打印是否请求自动客户端
  - 每个 entry 打印等待 RCON ready
  - RCON ready 后打印是否开始启动外部客户端
  - 客户端会话建立后打印 tracked pid/kind
  - 调用单 case 前打印即将进入 bench 的玩家就绪等待
- 若已请求 `AutoStartBenchClient`，但 `Start-BenchClientAutomationSession` 返回空会话，则直接抛出明确异常并终止当前 case，不再继续等待玩家就绪。

### 影响范围
- `tools/bench/lib/BenchSuite.EntryPoint.ps1`
- `docs_dev/使用说明.md`

- **预期结果**：summary 不再只有 `benchClient = null` 这种黑盒状态。
- **关键里程碑**：是

## 预期结果
- 当服务器 ready 但客户端未出现时，可直接从控制台日志和 `summary.json` 判断：
  - 是否请求了自动客户端
  - 是否真正尝试过启动
  - 启动是否成功
  - 若失败，失败原因是什么
- 避免继续进入长时间“等待玩家就绪”的黑盒阶段。
