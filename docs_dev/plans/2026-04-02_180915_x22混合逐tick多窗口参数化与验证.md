# x22混合逐tick多窗口参数化与验证

生成时间：2026-04-02 18:09:15
文件名：2026-04-02_180915_x22混合逐tick多窗口参数化与验证.md

## 任务背景

当前 `x22` 仅稳定覆盖 `all_direct + batchWindowTicks=0` 的 mixed 逐 tick 断言，`x23/x24` 仍为独立静态 case，且沿用“整段 target 序列统一锚到 sync start”的旧模型。实测表明 mixed 用例中后续 `pulse/toggle` 的 `jobStartTick` 会相对首个 `sync` 锚点产生漂移，因此需要参考 `x21` 的参数化方式，将 mixed 逐 tick 用例收敛为单一参数化 case，并分别验证 `window=0/1/2`。

## 方案详情

### 现状分析

- `x21` 已支持 `parameters.dispatchBatchWindowTicks`，并由 suite entry 覆盖参数值。
- `x22` 已改为分段锚定，能稳定通过 `window=0`。
- `x23/x24` 仍是旧式静态断言，不适合直接作为多窗口统一基线。
- bench 参数替换链路已支持功能 case 内的 `{{param:...}}`，但 mixed 三段目标期望序列仍需要脚本模板辅助生成。

### 技术方案

- 在 `Bench.FunctionalTrace.ps1` 中补充 mixed 目标段的参数化期望模板，按 `dispatchBatchWindowTicks=0/1/2` 生成 `sync/pulse/toggle` 三段逐 tick 期望。
- 将 `x22` 收敛为唯一 mixed 参数化 case，默认参数为 `0`，并保留分段锚定结构。
- `functional-mixed-direct-debug.json` 中三个 entry 统一指向参数化后的 `x22`，分别覆盖 `dispatchBatchWindowTicks=0/1/2` 与服务端配置 `crosschunk.dispatch.batchWindowTicks=0/1/2`。
- 从 `functional-matrix.json` 中移除 `x23/x24` 独立 case 引用，统一保留 `x22` 参数化入口。
- 分别运行三次并分析结果，区分“实现偏差”与“断言锚点/参数模型偏差”。

### 影响范围

- `tools/bench/lib/Bench.FunctionalTrace.ps1`
- `tools/bench/cases/functional/x22/mixed_samechunk_direct_window0_tick_assert.json`
- `tools/bench/suites/functional-mixed-direct-debug.json`
- `tools/bench/functional-matrix.json`
