# 频道模式落地与普通links同步

生成时间：2026-04-15 10:57:49
文件名：2026-04-15_105749_频道模式落地与普通links同步.md

## 任务背景
当前项目已经有稳定的普通 `triggerSource -> core` links 真值、生命周期调度、delta 补发/失效、OCC 与 quick-link 闭环；但频道模式仍停留在设计阶段，quick-link 的 `channel` 也只是缓存占位，pairing GUI 仍只能编辑 serial links。

本次实现采用已确认方案：
- 节点身份仍然只保留 `serial`
- 每个节点连接配置只保留一种模式：`SERIAL` 或 `CHANNEL`
- 切换模式时清空旧模式配置
- `channel` 为非零正 `long`
- 频道与序号完全隔离
- 频道服务或模式切换只负责把普通 links 改到正确真值，其它生命周期、读模型、dispatch、privacy、OCC 与快照同步自然复用现有逻辑

## 方案详情

### 现状分析
- 当前真正生效的连接真值是 `LinkSavedData` 中的普通 `triggerSource -> core` 双向索引，所有读侧与生命周期服务都直接消费这套 ordinary links。
- `PairableNodeBlockEntity` 只持久化 `serial`，没有节点连接模式与频道配置。
- pairing GUI 的打开/提交 payload 只有 serial links 视角，没有模式或频道字段。
- quick-link 已有 `channel` 模式 UI 与缓存字段，但服务端 collect/apply 仍直接报 `channel_future`。
- `LinkSetExecutionService`、`CoreLinkEditingService`、pairing、quick-link、bench 这些写入口仍默认所有节点都在 serial 语义下工作，没有“serial/channel 隔离”校验。

### 技术方案
- 在 `LinkSavedData` 中新增节点频道配置真值与频道桶索引：
  - 每类节点维护“当前是否处于 channel 模式”的持久化映射
  - 维护 `channel -> triggerSource set` 与 `channel -> core set`
  - ordinary links 继续作为唯一生效边真值
- 新增频道同步服务：
  - `triggerSource` 切到频道模式时，仅重算该来源自己的 ordinary links
  - `core` 切到频道模式或频道值变化时，重算所有受影响的 `triggerSource`
  - 频道服务内部仍通过现有 `PreparedReplaceOperation -> applyPreparedReplace(...)` 闭环改边，确保 delta、快照同步与 revision 自然生效
- serial 写入口接入模式隔离：
  - 以 serial 方式写入时，目标对端若处于 channel 模式则拒绝写入
  - 对当前被编辑节点，serial 写入视为切回 serial 模式，并清理其频道配置
- pairing GUI 接入模式切换与频道输入：
  - 打开 payload 下发当前模式与频道值
  - 提交 payload 上送模式、serial 表达式或频道值
  - 客户端切换模式时立即清空旧输入，符合“切换即清空旧模式配置”
- quick-link 接入真实频道 collect/apply：
  - `channel` 模式采集节点频道值
  - `channel` 模式应用到节点时改频道配置并通过频道服务同步 ordinary links
  - 过滤器仍只支持 serial 形态

### 语义对齐说明
- 命名统一继续使用 `triggerSource/core`，不新增旧术语输出
- 所有真实边仍然只写 `triggerSource -> core` 正向
- 新增模式只影响“如何生成 ordinary links”，不改变现有 dispatch/read 模型
- 兼容层保持“读旧写新”：旧存档无频道配置时默认视为 serial 模式
- 残余风险：`core` 切换频道模式后会把仍指向它的 serial links 剪掉，这属于本次“模式隔离且切换清空旧配置”的既定语义

## 原子步骤清单

### 步骤 1：扩展 LinkSavedData 的频道配置与桶索引
- **操作对象**：`LinkSavedData`、`LinkSavedDataCodecSupport`、新增频道 helper
- **具体动作**：新增节点频道配置、频道成员桶与持久化读写；提供查询、登记、移除与受影响来源收集能力
- **预期结果**：世界级数据层可以稳定保存并读取频道模式真值
- **关键里程碑**：是

### 步骤 2：实现频道服务对 ordinary links 的同步闭环
- **操作对象**：新增频道同步服务，必要时补充 `LinkSavedData` 辅助方法
- **具体动作**：在节点切换到频道模式、频道值变化、退出频道模式、退役时，收集受影响 `triggerSource` 并通过现有 replace 执行器改 ordinary links
- **预期结果**：频道配置变化只靠“改边”即可驱动现有生命周期服务自然生效
- **关键里程碑**：是

### 步骤 3：让 serial 写入口感知模式隔离
- **操作对象**：`LinkSetExecutionService`、`CoreLinkEditingService`、pairing/quick-link/bench 相关入口
- **具体动作**：serial 写入时拒绝 channel 模式对端，并在当前编辑节点被 serial 写入时清掉其频道配置
- **预期结果**：serial 与 channel 不再混写，旧服务仍只消费 ordinary links
- **关键里程碑**：是

### 步骤 4：接入 pairing GUI 的模式切换与频道提交
- **操作对象**：`PairingNetwork*`、`AbstractMultiPairingScreen`、`TriggerSourcePairingScreen`、`CorePairingScreen`
- **具体动作**：扩展打开/提交 payload，客户端增加模式切换按钮和频道输入，服务端按模式分流到 serial 或频道服务
- **预期结果**：GUI 可直接切换 serial/channel 并保存真实频道配置
- **关键里程碑**：是

### 步骤 5：接入 quick-link 的频道 collect/apply
- **操作对象**：`QuickLinkToolData`、`QuickLinkCollectService`、`QuickLinkApplyService`、`QuickLinkNetworkServerHandlerSupport`
- **具体动作**：移除 `channel_future` 占位，改为真实采集节点频道并将频道配置应用到节点
- **预期结果**：quick-link 的两种模式都可真实工作
- **关键里程碑**：否

### 步骤 6：补充测试与审查文档
- **操作对象**：`src/test/**`、`docs_dev/reviews/`
- **具体动作**：补充 `LinkSavedData`、pairing payload、quick-link 与模式隔离回归测试，执行全标签自动化测试，生成五段式审查文档
- **预期结果**：新语义有可追溯的验证与审查记录
- **关键里程碑**：是

## 预期结果
- 节点可在 `SERIAL` 与 `CHANNEL` 两种连接模式间切换，且切换时旧模式配置被清空。
- `channel` 变更只通过 ordinary links 真值更新来驱动现有 lifecycle/delta/read 服务，无需额外改读侧。
- pairing GUI 与 quick-link 都能真实编辑和应用频道配置。
- serial/channel 隔离被收口到真实写入口，不再出现两种模式混写同一节点的状态。
