# 命令参数解析完全覆盖

生成时间：2026-03-24 09:56:37
文件名：2026-03-24_095637_命令参数解析完全覆盖.md

## 任务背景
当前命令层已经完成了输入器与 `node trace` 的结构化参数接入，但仍存在一批旧入口继续使用 `greedyString() + 尾缀手拆`。这导致命令提示、参数边界、测试契约和后续快照整合都要同时兼容新旧两套解析路径。本轮目标是在不改业务语义与持久化结构的前提下，把残留命令全部迁移到 Brigadier 显式节点和已有参数类型上。

## 方案详情

### 现状分析
- 批量序号参数类型已存在：`SerialBatchArgumentType`
- 输入序列参数类型已存在：`SignalSequenceArgumentType`
- 旧解析残留主要集中在以下命令：
  - `node activate`
  - `link set`
  - `link write_control protected set`
  - `link privacy current_links mask set`
  - `node retire batch`
  - `crosschunk whitelist set`
- 旧兼容逻辑集中在 `CommandSuffixParser`，当前测试也仍围绕“后缀剥离”而不是“命令树契约”。

### 技术方案
采用“小参数类型 + 显式 literal 节点”的最小改造路径，不引入新的重型抽象层：

1. 批量序号统一改用 `SerialBatchArgumentType`
2. `toggle` / `pulse` / `confirm` / `resident` 统一改为 Brigadier 显式节点
3. 业务解析继续复用 `SerialParseUtil` 等现有逻辑
4. 所有使用点迁完后删除 `CommandSuffixParser`
5. 将测试从“尾缀解析测试”迁移为“命令树契约测试”

### 影响范围
- 命令注册层：
  - `src/main/java/com/makomi/command/activate/ActivateCommandRegistry.java`
  - `src/main/java/com/makomi/command/ModCommands.java`
  - `src/main/java/com/makomi/command/privacy/CurrentLinksPrivacyCommandRegistry.java`
  - `src/main/java/com/makomi/command/retire/RetireBatchCommandRegistry.java`
  - `src/main/java/com/makomi/command/crosschunk/CrossChunkCommandRegistry.java`
  - `src/main/java/com/makomi/command/CommandSuffixParser.java`
- 测试：
  - `src/test/java/com/makomi/command/CommandEntryContractTest.java`
- 文档：
  - `docs_dev/使用说明.md`

## 原子步骤清单

### 步骤 1：迁移 activate 命令
- **操作对象**：`ActivateCommandRegistry`
- **具体动作**：
  - 将 `source_serials` 从 `greedyString()` 改为 `SerialBatchArgumentType`
  - 将 `toggle/pulse` 从尾缀解析改为显式 literal
  - 保留无模式时默认 `toggle`
  - 删除 `parseSerialsAndMode(...)`
- **预期结果**：`activate triggerSource 1:10`、`activate triggerSource 1/3/4 pulse` 由命令树直接解析
- **关键里程碑**：是

### 步骤 2：迁移 confirm-only 命令
- **操作对象**：`ModCommands`、`CurrentLinksPrivacyCommandRegistry`、`RetireBatchCommandRegistry`
- **具体动作**：
  - `link set`、`write_control protected set`、`privacy current_links mask set`、`node retire batch` 改用 `SerialBatchArgumentType`
  - 将 `confirm` 改为显式节点
  - 执行函数改为显式接收 `confirmed`
- **预期结果**：确认语义不变，但不再从字符串尾部剥离
- **关键里程碑**：是

### 步骤 3：迁移 resident + confirm 命令
- **操作对象**：`CrossChunkCommandRegistry`
- **具体动作**：
  - 将 `serials` 改用 `SerialBatchArgumentType`
  - 展开 `<serials>`、`<serials> confirm`、`<serials> resident`、`<serials> resident confirm`
  - 执行函数改为显式接收 `resident` 和 `confirmed`
- **预期结果**：`crosschunk whitelist set` 完全脱离尾缀解析器
- **关键里程碑**：是

### 步骤 4：清理旧解析器
- **操作对象**：`CommandSuffixParser` 及各命令类
- **具体动作**：
  - 删除不再使用的 `parseConfirmSuffix(...)` / `parseSerialsAndMode(...)`
  - 删除 `CommandSuffixParser`
- **预期结果**：命令层只保留结构化参数和显式节点
- **关键里程碑**：否

### 步骤 5：迁移测试与说明
- **操作对象**：`CommandEntryContractTest`、`docs_dev/使用说明.md`
- **具体动作**：
  - 将原“后缀剥离测试”改为“命令树契约测试”
  - 更新命令示例为标准小写与标准顺序
- **预期结果**：测试、文档、实际命令入口一致
- **关键里程碑**：否

### 步骤 6：验证回归
- **操作对象**：Gradle 测试任务
- **具体动作**：
  - 先跑命令相关定向测试
  - 再跑 `.\gradlew.bat test testIntegration testClient testSlow testApiLegacy --no-daemon`
- **预期结果**：确认迁移未破坏现有功能
- **关键里程碑**：是

## 预期结果
- 命令入口统一为结构化参数解析
- 命令提示与报错回到 Brigadier 标准行为
- 后续快照整合和测试脚本可以基于稳定命令树继续推进
- 仅收敛命令输入兼容性，不改业务存储和运行语义
