# 补充过滤器运行期四类覆盖并跑通新增用例

生成时间：2026-04-10 17:08:02

## 任务背景

现有过滤器运行期游戏内测试已经覆盖 send / receive 两侧在固定阈值与邻居最大输入阈值下的基础失效与补发语义，但仍缺少四类关键设计覆盖：
- 邻居输入降到非零低态时的失效与恢复补发
- `lower_bound` 模式下的运行期失效与补发
- 节点集白名单命中与未命中的分流行为
- 过滤器物理作用半径正方体范围内外的分流行为

本轮目标是在不新增业务实现和不扩展 bench 内部命令的前提下，补齐上述四类覆盖，并仅跑通新增用例。

## 方案详情

### 现状分析

- 现有 `x24` / `x26` 已验证 send / receive 过滤器在运行期对 `sync` 信号的基础失效与补发。
- 当前邻居输入变化仅覆盖从高值掉到 `0` 的场景，未覆盖“非零但不足以放行”的中间态。
- 当前 `signalMode` 仅覆盖 `upper_bound`。
- 当前节点集配置为 `serialExpression:\"\"` 与 `nodeSetMode:\"disabled\"`，没有验证命中节点与未命中节点分流。
- “作用范围”经确认按物理正方体半径解释，实际对应 `PlacedLinkFilterSavedData.FilterEntry.covers(BlockPos)` 的覆盖判定。

### 技术方案

- 继续沿用现有 functional case 模板，新增 send / receive 两条补充 case，不修改业务代码与 bench 内部命令。
- 每条新增 case 内同时覆盖四类设计：
  - `neighbor_max_input` 下高值降到非零低态，再恢复
  - `lower_bound`
  - 节点集 whitelist 命中 / 未命中对照
  - 物理范围内 / 范围外对照
- 通过 `command_assert`、邻居方块切换、多个目标点位和逐步断言完成覆盖。
- 将新增 case 接入 functional matrix，但本轮验证仅执行新增用例。

### 影响范围

- `tools/bench/cases/functional/` 下新增过滤器 functional case
- `tools/bench/functional-matrix.json` 接入新增 case
- 如需便于 targeted 执行，可能调整相关 suite 清单
