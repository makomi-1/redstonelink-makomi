# 命令层 input 与 node trace 拆分

生成时间：2026-03-24 19:43:17
文件名：2026-03-24_194317_命令层input与node_trace拆分.md

## 任务背景

在代码组织优化主线已确认后，本轮从命令层开始落第一刀，优先拆分 `ModCommands` 中耦合度高、且与 bench/运行态观测直接相关的两个命令域：

- `/redstonelink input`
- `/redstonelink node trace`

这两个命令域同时覆盖参数树注册、批量参数校验、运行态读取、反馈输出与限流判定，是当前 `ModCommands` 高行数的重要来源。先拆这两块，可以在不触及 `link/place/audit` 等更大面积写路径的前提下，验证“根装配器 + 子注册器 + 最小共享 support”的组织方式是否稳定。

## 方案详情

### 现状分析

- `ModCommands` 同时承担根命令注册和 `input/node trace` 的全部执行细节，单文件已接近 2700 行。
- `command` 包已经存在 `activate/crosschunk/privacy/retire/semantic` 子包，命令层具备继续拆分的组织基础。
- `input` 与 `node trace` 共享少量命令层工具能力，例如：
  - 类型解析
  - 可选整型参数读取
  - 序列号格式化
  - 其他命令权限判定
- 现有命令契约、反馈文案、权限与 `triggerSource/core` 语义已经稳定，本轮不能改变外部行为。

### 技术方案

采用“根文件瘦身、共享能力最小下沉”的保守拆分方式：

1. 新增 `command.input.InputCommandRegistry`，接管 `/redstonelink input` 的命令树与执行逻辑。
2. 新增 `command.node.NodeTraceCommandRegistry`，接管 `/redstonelink node trace` 的命令树与执行逻辑。
3. `ModCommands` 保留根树装配职责，并把少量可复用命令层 helper 收敛为包级静态方法，供子注册器复用。
4. 不引入新的业务抽象层，不改变现有持久化、权限配置、trace/input 服务调用路径。

### 影响范围

- `src/main/java/com/makomi/command/ModCommands.java`
- `src/main/java/com/makomi/command/input/`
- `src/main/java/com/makomi/command/node/`
- 相关命令契约测试
