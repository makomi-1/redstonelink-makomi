# 修复新存档近外显刷新失效

生成时间：2026-04-08 16:54:33
文件名：2026-04-08_165433_修复新存档近外显刷新失效.md

## 任务背景
客户端单端新存档中，近距离文本外显的“当前连接”和“最终 I/O”刷新会在进入新世界后失效；同一轮排查中发现 `run/saves/New World (12)` 已在运行一段时间后恢复，而 `run/saves/New World (13)` 仍处于未恢复状态。现需基于现有近外显请求链路定位根因并做最小粒度修复。

## 方案详情

### 现状分析
- 近外显文本由客户端 `LinkSerialHudOverlayRenderer` 命中节点后懒请求两类服务端快照：当前连接/跨区块身份、最终 I/O。
- 服务端 `PairingNetworkServerHandlerSupport` 对两类请求都使用静态 `UUID -> lastTick` 节流表，并按 `gameTime` 判断是否处于最小 tick 间隔窗口。
- 单端切换到新存档时，集成服重启后新世界 `gameTime` 从 0 重新开始，但静态节流表不会自动清空，导致 `nowTick < lastTick` 时仍被误判为处于节流窗口内。
- 该问题会使新存档近外显长时间收不到服务端回包，直到新世界 tick 追平旧记录后才“自行恢复”。

### 技术方案
- 仅修改近外显服务端节流逻辑，不改动配对语义、存档结构和客户端文案/渲染路径。
- 在 `PairingNetworkServerHandlerSupport` 的通用近外显节流逻辑中显式处理 tick 回绕/世界重开场景：
  - 若发现当前 `nowTick` 小于历史 `lastTick`，直接视为旧世界残留状态，不再按节流窗口拒绝本次请求。
  - 若发现全局清理节拍 `lastThrottleCleanupTick` 也发生回绕，则一并清空旧节流表，避免新世界长期继承旧状态。
- 补充纯逻辑回归测试，覆盖“tick 回绕不应继续被节流”的边界。

### 影响范围
