# Graph 可视化连通分量分块布局

生成时间：2026-04-17 15:21:38
文件名：2026-04-17_152138_graph可视化连通分量分块布局.md

## 任务背景

当前网页 Graph 视图仍采用“全局两列”自动布局：所有 `triggerSource` 固定在左列，所有 `core` 固定在右列。  
这会导致：

- 多个互不相连的拓扑块也被硬挤在同一对列里，画布横向空间浪费明显。
- 图越来越高、越来越密时，阅读和定位都会变差。
- 后续批量编辑模式虽然已经能工作，但视觉上仍缺少“按局部网络分块”的可读性。

本轮目标是在不引入自由拉线、不过度复杂化交互的前提下，把自动布局切换为“按连通分量分块 + 组件内 `triggerSource/core` 分层 + 多块自动铺排”。

## 方案详情

### 现状分析

- 当前布局逻辑集中在 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx) 的 `buildAutoLayoutNodes(...)`，只按节点类型分别累加纵向索引。
- 节点重建逻辑在 `useEffect` 中通过 `buildAutoLayoutNodes([node], ...)` 对单节点做回退位置，这种写法默认“节点位置与全图无关”，不适用于依赖整体拓扑的布局算法。
- 当前 `handleAutoLayout()` 也直接调用旧的全局两列布局，因此即使手动重排，也无法按拓扑块重新整理。

### 技术方案

1. 新增“整体位置计算”层，而不是在生成 ReactFlow 节点时顺带决定位置。
2. 先基于 `GraphSnapshotBundle.edges` 把图按无向连通关系拆成多个 connected components。
3. 每个 component 内部保持简单规则：
   - `triggerSource` 单独成层
   - `core` 单独成层
   - 两层在局部块内左右分开
   - 节点顺序按 `serial` 和 `nodeKey` 做稳定排序
4. component 级布局完成后，再把多个块按固定最大行宽做流式铺排，充分利用横向空间。
5. 节点样式、草稿差异着色、搜索高亮、编辑选中等逻辑继续复用，布局改动只影响坐标生成。
6. 节点刷新时继续保留用户拖拽过的位置；只有首次装载和点击“自动布局”时，才完整应用新布局。
