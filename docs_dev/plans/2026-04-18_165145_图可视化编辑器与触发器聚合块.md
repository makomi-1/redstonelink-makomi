# 图可视化编辑器与触发器聚合块

生成时间：2026-04-18 16:51:45
文件名：2026-04-18_165145_图可视化编辑器与触发器聚合块.md

## 任务背景

当前基线已经回退到 `f7c175b16e131cf4f847d335d0469e3b26725f02`，需要在该基线上重新实现两个能力：
1. 新增 `graph visual editor` 物品，右键时去重导出当前 graph 并自动打开图网络页面。
2. 扩展 `triggerSource` 聚合块，使其在输出对象完全一致时具备与现有核心聚合块一致的渲染与展开机制。

本轮只处理前端可视化与导出入口，不改变 `triggerSource -> core` 的真实保存语义，不引入 `com.makomi.api.v1.*` 依赖。

## 方案详情

### 现状分析

- 现有命令 `/rlclient web graph` 已走通完整链路：服务端 `GraphSnapshotExportService` 负责 graph 去重导出，客户端 `StatePanelNetworkClientHandlerSupport` 负责接收分块、写入本地资产并自动打开网页。
- `graph_visual_editor.png` 贴图已存在，因此本轮无需修改贴图资源本体，只需补齐新物品注册、模型、配方和文案。
- `webapp/src/components/GraphViewer.tsx` 当前仅支持 `core` 聚合块，聚合节点结构、标签、布局和边样式都写死成了单一角色。

### 技术方案

1. 把状态面板 graph 导出的服务端发送逻辑抽为公共能力，统一承载“复用已有 graph 文件 / 分块发送 / 自动打开网页”的行为，供现有状态面板导出和新物品复用。
2. 新增 `GraphVisualEditorItem`，在主手右键时于服务端调用现有 graph 去重导出服务并通过公共发送器把结果推到客户端；客户端继续复用原有 graph 资产写入与自动打开逻辑。
3. 补齐 `ModItems`、`ModItemGroups`、物品模型、配方和中英文文案，使新物品可合成、可显示、可使用。
4. 将前端聚合节点改造成双角色结构，增加聚合角色字段，使同一套聚合渲染逻辑同时支持 `core` 聚合与 `triggerSource` 聚合。
5. 新增 `triggerSource` 聚合分组逻辑：多个 `triggerSource` 指向的 `core` 集合完全一致时，折叠显示为同一个聚合块；展开后保留聚合块本体，仅展开成员节点，不恢复全部真实边。

### 影响范围

- 服务端 graph 导出发送链路
- 新物品注册、配方、模型、lang 文案
- 前端 `GraphViewer` 聚合块视图构建与渲染
