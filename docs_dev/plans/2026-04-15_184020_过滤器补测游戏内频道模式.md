# 过滤器补测游戏内频道模式

生成时间：2026-04-15 18:40:20
文件名：2026-04-15_184020_过滤器补测游戏内频道模式.md

## 任务背景

当前过滤器已经补齐频道模式实现，并且 Java 自动化测试已覆盖持久化、payload、quick-link、规则求值与 replay 目标模式选择。

但 `tools/bench` 现有 dedicated functional 用例仍集中在 `serial/nodeSet` 路径，尚未覆盖频道模式在真实游戏内的关键链路，尤其是：

- `send filter` / `receive filter` 在频道模式下的阻断与放行
- 已激活 `sync` 链路在频道过滤运行期变更后的失效与补发
- 邻居输入为 `0` 时作为总开关关闭、恢复后重新生效

本轮目标是在不改业务语义、不重复补整套信号矩阵的前提下，补齐 dedicated functional 频道过滤关键链路，并基于当前工作区构建产物完成一次真实游戏内回归。

## 方案详情

### 现状分析

1. 现有过滤器功能 case 已有：
   - `x32/x33`：`send/receive` 节点集运行期 `sync` 失效与补发
   - `x34/x35`：`send/receive` 节点集邻居输入 `0` 总开关
   - `x27/x28`：节点集范围、阈值与非零低态矩阵
2. 仓库内不存在频道过滤 functional case，`tools/bench/functional-matrix.json` 也尚未挂接相关用例。
3. 信号阈值、物理范围与邻居非零低态的运行时骨架已经由 `x27/x28` 证明；频道模式与序号模式的主要差异集中在“过滤目标如何匹配”，因此本轮优先补“目标匹配维度切换”最关键的 dedicated functional 证据。

### 技术方案

1. 复用 `x32/x33/x34/x35` 的场景骨架，新增 4 个频道模式 functional case：
   - `send_filter_runtime_channel_reconcile`
   - `receive_filter_runtime_channel_reconcile`
   - `send_filter_runtime_channel_zero_master_switch`
   - `receive_filter_runtime_channel_zero_master_switch`
2. 用 `data merge block` 直接写入过滤器 `targetMode:"channel"` 与 `channel:<long>`，并通过节点命令把 `triggerSource/core` 切到频道模式，避免 GUI 依赖，保证 dedicated server 可稳定跑。
3. 断言重点放在：
   - 匹配频道时阻断/放行是否正确
   - 频道值运行期切换后，既有 `sync` 是否正确失效/补发
   - 邻居输入掉到 `0` 是否关闭过滤器，恢复后是否重新生效
4. 将新增 case 挂入 `functional-matrix.json`，并新增一个只包含这 4 个 case 的专项 suite，便于单独构建、同步、复跑。
5. 按项目规则先构建当前工作区运行 jar，再同步 dedicated server mod jar，最后执行专项 suite 实跑并分析结果。
