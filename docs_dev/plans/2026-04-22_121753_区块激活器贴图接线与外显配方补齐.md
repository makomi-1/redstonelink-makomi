# 区块激活器贴图接线与外显配方补齐

生成时间：2026-04-22 12:17:53
文件名：2026-04-22_121753_区块激活器贴图接线与外显配方补齐.md

## 任务背景

区块激活器的方块贴图与 GUI 背景资源已经就位，但当前模型与界面仍未真正接线，游戏内也缺少区块激活器的远外显别名与近外显信息。同时，区块激活器当前配方仍沿用旧模板，不符合“中心连接原件、外围一圈 8 个土方块”的新要求。

## 方案详情

### 现状分析

- 资源文件 `chunk_activator.png`、`chunk_activator_bright.png`、`chunk_activator_background.png` 已存在，但区块激活器模型仍引用 `link_sync_emitter*` 外层贴图，GUI 也仍复用 `triggerSource/core` 配对背景。
- 区块激活器当前没有客户端方块实体远外显渲染注册，也没有近外显 HUD 文案入口。
- 区块激活器已有 `displayAlias`、`activeType`、`activeConfig`、`active()` 等客户端可读状态，足以支撑外显补齐。
- datagen 与运行时 recipe json 仍是旧的“基础材质 + 连接原件”模板配方。

### 技术方案

1. 接通区块激活器资源：
   - 方块模型外层改为 `chunk_activator/chunk_activator_bright`。
   - 内层统一改为和其它双层节点一致的 `component_core_block`。
   - GUI 背景新增区块激活器专用预设，并让编辑界面固定使用该背景图。
2. 补齐区块激活器外显：
   - 远外显新增专用 renderer，优先显示别名，空别名回退区块激活器标题。
   - 近外显新增区块激活器文案组装，展示标题/别名、激活状态、服务对象、激活模式、节点集。
   - 远外显颜色继续沿用 `activeType` 对应的 `triggerSource/core` 语义色，确保世界内一眼可区分作用类型。
3. 调整配方：
   - datagen 新增区块激活器专用配方构建方法。
   - 运行时 recipe json 同步改为中心 `redstone_link_component`、外围 8 个 `dirt`。

### 影响范围

- `src/client/java/com/makomi/client/screen/` 区块激活器背景预设与编辑界面
- `src/client/java/com/makomi/client/render/` 区块激活器远外显与近外显文案
- `src/client/java/com/makomi/RedstoneLinkClient.java` 区块激活器 renderer 注册
- `src/main/resources/assets/redstonelink/models/block/` 区块激活器方块模型
- `src/main/resources/assets/redstonelink/lang/` 外显文案
- `src/client/java/com/makomi/datagen/` 与 `src/main/resources/data/redstonelink/recipe/` 区块激活器配方

- 命名是否仅使用 `triggerSource/core`：是，新增外显文案中的服务对象仍统一输出 `triggerSource/core`。
- 输入/输出结构是否保持方向一致：是，本轮仅补显示与配方，不改动 `triggerSource -> source`、`core -> target` 的既有方向约束。
- 文案与注释是否无旧术语泄漏：目标如此实施；实现时不新增 `button/source/target` 等旧术语。
