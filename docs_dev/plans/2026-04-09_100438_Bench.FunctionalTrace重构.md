# Bench.FunctionalTrace 重构

生成时间：2026-04-09 10:04:38
文件名：2026-04-09_100438_Bench.FunctionalTrace重构.md

## 任务背景

`tools/bench/lib/Bench.FunctionalTrace.ps1` 中的 `Invoke-FunctionalPhases` 已经承担了 phase 分发、命令执行、DryRun 分支、检查项登记、phase 上下文读写等多项职责，函数体过长且维护成本高。本次目标是在不改变现有 bench 行为语义和结果结构的前提下，对该脚本进行结构性重构，提升可读性、可维护性和后续扩展效率。

## 方案详情

### 现状分析

- `Invoke-FunctionalPhases` 通过超长 `switch` 处理多个 phase，存在明显的单一职责违背。
- `trace_mount`、`trace_unmount`、`input_start_*` 等命令型 phase 共享大量重复流程，包括 serial 解析、命令组装、DryRun 处理和结果写回。
- `command_assert`、`trace_read_tick_assert`、`trace_sync_latency_collect` 等高复杂度 phase 既包含命令执行，又包含大量校验和统计逻辑，阅读和调试成本高。
- 现有 `Add-FunctionalPhaseResult` / `Resolve-FunctionalPhaseResult` 已经提供了稳定的 phase 上下文边界，适合作为拆分后的统一接入点。

### 技术方案

- 保持 phase 配置格式、RCON 命令文本、DryRun 行为、phaseResult 字段和 check 字段结构不变，只进行函数级结构拆分。
- 新增轻量 phase 执行上下文，将 `Connection`、serial map、`phaseContext`、`checks`、`failedChecks` 收口，减少共享状态在大函数中的散落访问。
- 提取统一的检查项登记辅助函数，避免不同 phase handler 重复维护成功/失败 check 集合。
- 将 `Invoke-FunctionalPhases` 改为薄入口，只负责遍历 phase、按 kind 分发、写回 phaseResult 和最终汇总。
- 按 phase 职责拆分 handler，优先把命令型和断言/采集型 phase 分组抽离，保持每个函数职责单一。

### 影响范围

- `tools/bench/lib/Bench.FunctionalTrace.ps1`
- `docs_dev/plans/`
- `docs_dev/reviews/`

## 原子步骤清单

### 步骤 1：整理共享执行上下文
- **操作对象**：`tools/bench/lib/Bench.FunctionalTrace.ps1`
- **具体动作**：新增 phase 执行上下文与统一 check 登记 helper，统一共享状态访问方式。
- **预期结果**：后续 handler 提取时不再反复传递和拼装同类共享参数。
- **关键里程碑**：是

### 步骤 2：提取基础命令型 phase handler
- **操作对象**：`tools/bench/lib/Bench.FunctionalTrace.ps1`
- **具体动作**：拆出 `trace_mount`、`trace_unmount`、`input_start_square`、`input_start_custom`、`input_start_custom_batch`、`input_clear`、`link_command`、`activate_batch`、`wait_ticks` 等处理函数。
- **预期结果**：大函数中的重复命令执行流程按职责收口。
- **关键里程碑**：是

### 步骤 3：提取高复杂度断言与采集 handler
- **操作对象**：`tools/bench/lib/Bench.FunctionalTrace.ps1`
- **具体动作**：拆出 `command_assert`、`trace_latest_assert`、`trace_read_cycle_assert`、`trace_read_tick_assert`、`trace_sync_latency_collect` 等处理函数。
- **预期结果**：复杂校验逻辑独立封装，便于单点维护和回归排查。
- **关键里程碑**：是

### 步骤 4：收敛主分发入口
- **操作对象**：`tools/bench/lib/Bench.FunctionalTrace.ps1`
- **具体动作**：将 `Invoke-FunctionalPhases` 保留为遍历、分发和汇总入口，移除超长 `switch` 的主体逻辑。
- **预期结果**：主流程清晰，后续新增 phase 时只需扩展对应 handler。
- **关键里程碑**：是

### 步骤 5：执行验证与审查文档化
- **操作对象**：脚本本体、`docs_dev/reviews/`
- **具体动作**：执行脚本级 smoke 校验与仓库要求的自动化回归，完成后生成五段式审查文档。
- **预期结果**：确认结构重构未破坏 bench 行为，并保留可追溯审查记录。
- **关键里程碑**：是

- bench 脚本现有行为、配置格式、返回结果字段和 DryRun 语义保持兼容。
