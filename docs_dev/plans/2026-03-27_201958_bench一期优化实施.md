# bench 一期优化实施

生成时间：2026-03-27 20:19:58

## 任务背景
bench 最新一轮 heavy 压测暴露出三个一期问题：
1. suite 模式下 `-CaseIds` 形参未真正过滤 `entries`，导致定向运行仍会跑全集。
2. bench 建链默认把 target serial 展开成长 slash list，RCON 文本冗长，不利于后续重压场景。
3. 结果文件缺少放置、建链、驱动等阶段耗时，导致“序号回读慢”与“建链慢”容易混淆。

本期只处理低风险、高收益的 bench 脚本层改动，不引入新的 Java 批量建链接口。

## 方案详情

### 现状分析
- suite 入口在 `tools/bench/lib/BenchSuite.Config.ps1` 中解析 `SuitePath` 与 `RequestedCaseIds`，但仅 CLI matrix 模式会按 `RequestedCaseIds` 过滤，suite 模式直接全量展开 `entries`。
- bench 建链在 `tools/bench/lib/Bench.PlaceAndLink.ps1` 的 `Build-LinkCommands` 中统一生成 `redstonelink link set triggerSource ...`，默认 target serial 格式为 `slash_list`。
- 单 case 结果在 `tools/bench/lib/Bench.EntryPoint.ps1` 中写出，目前保留了 serialResolution、linkOperations、drive 等结果，但没有阶段耗时。

### 技术方案
1. 在 suite 解析阶段增加 `RequestedCaseIds` 对 `entryId` / `caseId` 的双匹配过滤，并对未命中的请求直接报错。
2. 在建链命令生成阶段加入“自动选择更短的 serial 表达式”逻辑：
   - 规则显式声明 `targetSerialFormat` 时保持原行为；
   - 未声明时，优先在 `range` 与 `slash_list` 之间选择更短文本，确保连续 serial 自动收敛为 `a:b`。
3. 在单 case 执行阶段新增轻量级耗时埋点：
   - 放置阶段：总耗时、target 放置耗时、source 分组放置耗时；
   - 建链阶段：命令数、总耗时、平均每条耗时；
   - 驱动阶段：开始时相对耗时、总耗时、性能窗口耗时。

### 影响范围
- `tools/bench/lib/BenchSuite.Config.ps1`
- `tools/bench/lib/Bench.PlaceAndLink.ps1`
- `tools/bench/lib/Bench.EntryPoint.ps1`
