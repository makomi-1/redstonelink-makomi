# suite客户端延后至服务端ready后启动

生成时间：2026-03-27 22:24:58
文件名：2026-03-27_222458_suite客户端延后至服务端ready后启动.md

## 任务背景
当前性能 suite 已支持 dedicated server 自动启动、外部 Prism 客户端自动启动、自动进服、自动传送与自动打开 F3+2 tick 曲线。

实际运行中发现，外部客户端在 suite 入口阶段就被提前拉起，而 dedicated server 此时仍未完成启动。由于 Prism 启动命令带有 `--server`，客户端会先发起一轮或多轮连接，导致启动初期出现 `Connection refused`、连接页与断线页切换等抖动，干扰观察，并放大“像是卡在 ESC/菜单”的误判。

## 方案详情

### 现状分析
- `tools/bench/lib/BenchSuite.EntryPoint.ps1` 会在 suite 主循环前调用 `Start-BenchClientAutomationSession`。
- 但每个 entry 的 dedicated server 是在循环内按 case 启动，并通过 `Wait-RconReady` 等待 ready。
- 因此客户端启动时点早于服务端 ready 时点。
- 现有 bench 客户端模组已经具备自动连接、重连、启动界面清理、F3+2 曲线开启等能力，不需要额外改业务链路。

### 技术方案
- 将 suite 中外部客户端自动启动时机从“进入主循环前”后移到“当前 entry 的 dedicated server 已通过 `Wait-RconReady`”之后。
- 客户端会话仍然只在 suite 生命周期内启动一次；第一例启动后，后续 entry 继续复用这一个外部客户端进程。
- 保持现有 `focusEvents`、`benchClient` summary、退出回收逻辑不变，只调整其赋值时机。

### 影响范围
- `tools/bench/lib/BenchSuite.EntryPoint.ps1`
- `docs_dev/使用说明.md`

## 原子步骤清单

### 步骤 1：调整 suite 客户端启动时机
- **操作对象**：`tools/bench/lib/BenchSuite.EntryPoint.ps1`
- **具体动作**：移除 suite 入口前置启动；在每个 entry 的 `Wait-RconReady` 之后判断 `$benchClientSession` 是否为空，若为空则启动外部客户端。
- **预期结果**：客户端首次连接只会发生在 dedicated server ready 之后。
- **关键里程碑**：是

### 步骤 2：保持 summary 与会话信息完整
- **操作对象**：`tools/bench/lib/BenchSuite.EntryPoint.ps1`
- **具体动作**：在延后启动后同步更新 `$suiteSummary.benchClient`，保证 summary 仍能记录 bench client 启动结果。
- **预期结果**：suite 结果文件结构不退化。
- **关键里程碑**：否

### 步骤 3：补充使用说明
- **操作对象**：`docs_dev/使用说明.md`
- **具体动作**：补充 suite 外部客户端启动顺序说明，明确“服务端 ready 后再启动客户端”。
- **预期结果**：用户可正确理解新时序。
- **关键里程碑**：否

## 预期结果
- suite 首次拉起外部客户端时，不再出现因服务端尚未 ready 导致的启动期连续拒连。
- bench 客户端仍保留自动进服、自动传送、自动打开 F3+2 tick 曲线、窗口聚焦等既有能力。
- 不涉及 `triggerSource/core` 业务语义、方向约束、持久化结构与 API 依赖变更。
