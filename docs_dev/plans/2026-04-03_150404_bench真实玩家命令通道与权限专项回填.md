# bench真实玩家命令通道与权限专项回填

生成时间：2026-04-03 15:04:04
文件名：2026-04-03_150404_bench真实玩家命令通道与权限专项回填.md

## 任务背景

当前服务器基本权限专项已经补齐 `C07/C08` 测试资产，并完成 `DryRun`、全标签自动化测试，以及 dedicated server + Prism 客户端的首次真实跑测。

真实跑测暴露出两类偏差：

1. `C07` 在场景准备阶段失败，`data get block ... Serial` 通过 `RCON -> execute as <player>` 链路返回空响应，导致 bench 无法解析序号。
2. `C08` 已进入功能断言，但低权限第三次 `node list` 未稳定命中限流，更像是“命令源/回包口径不是真实玩家原生命令”的测试偏差。

结合网络端重构文档、现有 bench 实现和 dedicated server 对照样本，当前判断是：

- 生产权限/限流实现仍以 `CommandSourceStack` 为准，设计基线未变。
- 问题更集中在 bench 仍用 `RCON + execute as/at` 模拟玩家，导致“命令源语义”和“回包采集口径”都不够稳定。
- 因此本轮优先修复测试执行链，而不是直接改权限/限流生产实现。

## 方案详情

### 现状分析

当前 bench 的玩家上下文命令执行方式是：

1. PowerShell 侧通过 `Wrap-WithPlayerContext` 把命令包成 `execute as <AsPlayer> at <AsPlayer> run ...`
2. 再统一走 `Invoke-RconCommand`
3. 依赖 RCON 文本回包做 serial 解析、命令断言和限流观测

这条链路的问题在于：

- 当命令内部实际把反馈发回“玩家源”而不是“控制台源”时，RCON 侧会收到空响应或不稳定响应。
- 即使 `execute as` 把实体上下文切到玩家，根命令源仍不是“玩家自己在客户端发起的命令”，会影响权限语义和回包分发。

### 技术方案

本轮采用“bench 专用最小真实玩家命令桥”：

1. 新增 `BenchCommandNetwork`，提供最小 `C2S/S2C` payload。
2. 客户端 bench 自动化控制器在配置启用时，轮询客户端实例 `config` 目录下的 request 文件。
3. 客户端收到 request 后，通过 `C2S` 把命令发给服务端。
4. 服务端使用 `player.createCommandSourceStack()` 作为根命令源执行命令，并用自定义 `CommandSource` 捕获系统消息/成功消息/失败消息与回调结果。
5. 服务端把结构化结果通过 `S2C` 回给客户端。
6. 客户端把结果写回 response 文件。
7. PowerShell 侧在 `Invoke-RconCommand` / `Invoke-RconCommandWithTickWindow` 内部识别“当前是玩家上下文命令”时，自动改走该玩家命令桥；非玩家上下文命令继续走原有 RCON。

这样可以做到：

- 玩家权限语义来自真实 `ServerPlayer` 的 `CommandSourceStack`
- 现有 bench case/phase 配置尽量不改
- `skipPlayerContext=true` 的控制台命令仍保留 RCON 路径
- dedicated server + Prism 的真实客户端链路能够稳定回收输出文本

### 影响范围

- 服务端网络模块：新增 bench 命令桥网络通道与服务端 handler
- 客户端自动化模块：新增 request/response 文件桥与 S2C 回包处理
- bench PowerShell：新增玩家命令桥请求写入/轮询读取，并接入现有命令执行入口
- 权限专项 case：尽量不改语义断言，仅在必要时补齐对真实玩家通道的使用

### 技术取舍

选择“文件桥 + 最小 C2S/S2C 命令执行通道”，不选择“客户端直接发聊天命令并从聊天栏抓文本”的原因：

- 文件桥更容易和现有 PowerShell bench 对接，脚本阻塞/轮询模型更直接。
- 结构化回包可同时携带 `output/resultCode/tickWindow/errorDetail`，比聊天抓取更稳定。
- 仍然保留真实玩家命令源，不会再把权限专项测成 RCON/控制台语义。

### 设计依据与修复层次

- 设计依据：生产权限与限流判断基于 `CommandSourceStack`，真实玩家命令应由 `player.createCommandSourceStack()` 执行。
- 当前实测与设计差异：bench 真实跑测仍通过 RCON 包装玩家上下文，导致回包与命令源语义偏离设计。
- 本轮最终修复层次：优先修“测试执行链/观测口径”，不直接按当前实测结果修改权限或限流生产逻辑。

### 语义对齐说明

- 命名校验：本轮新增设计不引入 `button/source/target` 新术语，涉及节点类型时继续使用 `triggerSource/core`。
- 方向校验：本轮只补命令执行通道，不改任何 `triggerSource -> core` 方向语义。
- 文案与注释校验：新增代码与文档统一使用 `triggerSource/core`，不新增旧术语输出。
- `LinkNodeType` 映射校验：仅复用现有映射，无新增映射分支。
- 兼容层校验：本轮主要是测试链路兼容，业务存储与对外字段不变。
- 残余风险：无新增语义风险；主要风险在 dedicated server + Prism 实机链路是否存在客户端文件桥时序问题。
