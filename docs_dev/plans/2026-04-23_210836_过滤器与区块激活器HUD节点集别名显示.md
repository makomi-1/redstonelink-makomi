# 过滤器与区块激活器HUD节点集别名显示

生成时间：2026-04-23 21:08:36
文件名：2026-04-23_210836_过滤器与区块激活器HUD节点集别名显示.md

## 任务背景

节点自身 HUD 当前连接别名显示已修复，但过滤器和区块激活器近外显 HUD 的节点集仍只显示 `#序号`。此前提交已实现节点当前连接展示文本链路，但过滤器和区块激活器不是走节点连接快照，而是直接从本地方块实体配置解析 `serialExpression`，因此没有别名数据。

## 方案详情

### 现状分析

过滤器 HUD 使用 `LinkFilterConfigSnapshot.serialExpression()` 解析序号，再调用仅带序号的文本构造路径；区块激活器 HUD 同样按当前 `activeConfig().serialExpression()` 解析序号。两者都没有从服务端同步节点别名展示文本，因此 `NodeAliasDisplayUtil.normalizeDisplayTexts(..., List.of())` 会统一兜底成 `#序号`。

### 技术方案

在过滤器和区块激活器方块实体的客户端同步 tag 中携带节点集展示文本。服务端按配置节点类型解析 `别名(#序号)`；客户端加载 update tag 后缓存 displayTexts；HUD 文案构造优先使用 displayTexts，缺失或不匹配时继续回退 `#序号`。别名变更时扩展 `NodeAliasServerSupport.syncDisplaysAfterAliasChanged(...)`，刷新已加载且引用该节点的过滤器和区块激活器方块实体。

### 影响范围

- 过滤器方块实体客户端同步字段。
- 区块激活器方块实体客户端同步字段。
- 近外显 HUD 节点集文本构造。
- 节点别名变更后的已加载显示刷新。
- 不改变过滤器规则、区块激活器强加载/常驻语义，不改网络协议，不改贴图资源。

## 原子步骤清单

### 步骤 1：过滤器同步节点集展示文本
- **操作对象**：`AbstractLinkFilterBlockEntity`
- **具体动作**：增加只用于客户端外显的节点集展示文本缓存；服务端 update tag 写入别名展示文本，客户端 loadAdditional 读取
- **预期结果**：过滤器近外显序号模式可获取 `别名(#序号)` 列表
- **关键里程碑**：是

### 步骤 2：区块激活器同步两套展示文本
- **操作对象**：`LinkChunkActivatorBlockEntity`
- **具体动作**：分别缓存 triggerSource/core 节点集展示文本，并随 update tag 同步到客户端
- **预期结果**：区块激活器 HUD 按当前 activeType 显示对应节点集别名
- **关键里程碑**：是

### 步骤 3：HUD 消费展示文本
- **操作对象**：`LinkSerialHudOverlayTextSupport`
- **具体动作**：过滤器/区块激活器 HUD 节点集文本优先使用方块实体缓存的 displayTexts，缺失时回退序号
- **预期结果**：HUD 节点集显示 `别名(#序号)`，无别名显示 `#序号`
- **关键里程碑**：是

### 步骤 4：别名变更刷新已加载方块实体
- **操作对象**：`NodeAliasServerSupport`
- **具体动作**：别名变更后扫描已加载过滤器/区块激活器条目，引用命中时触发方块实体同步
- **预期结果**：已加载过滤器/区块激活器在别名变更后可收到新展示文本
- **关键里程碑**：是

### 步骤 5：补充测试与验证
- **操作对象**：相关单元测试与 Gradle 任务
- **具体动作**：补充 displayTexts 归一与 HUD 文本构造测试，执行定向测试和全标签回归
- **预期结果**：修复点可回归验证，现有测试不退化
- **关键里程碑**：是

## 预期结果

过滤器和区块激活器近外显 HUD 的节点集会显示节点别名，例如 `中控A(#3)/#7`；旧存档、未同步或无别名时仍稳定显示 `#序号`。

## 语义对齐说明

本次只补充 `triggerSource/core` 节点集展示文本同步与 HUD 消费，不改变来源到目标方向、不改变 `LinkNodeType.TRIGGER_SOURCE/CORE` 映射、不新增旧术语输出、不引入 `com.makomi.api.v1.*` 依赖。残余风险：未加载区块内的过滤器/区块激活器不会在别名变更瞬间发包，但下次加载或服务端同步时会重新生成展示文本。
