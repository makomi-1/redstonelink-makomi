# 远外显摄像头朝向与IO轮询修正

生成时间：2026-03-24 12:33:14
文件名：2026-03-24_123314_远外显摄像头朝向与IO轮询修正.md

## 任务背景

上一轮已为近外显补充最终 IO 信息，并调整了贴附类节点的远外显面向逻辑。实测后发现两类问题仍未达标：
- 近外显最终 IO 更新不够及时，当前缓存策略导致状态变化后需要等待较长时间才能反映到 HUD。
- 核心粉、按钮、拉杆的远外显文本框应与其他节点一致，统一面向摄像头；当前贴附类节点仍按面法线旋转，导致侧面与顶底面的位移观感不一致，按钮/拉杆侧面尤为明显。

## 方案详情

### 现状分析

- [`src/client/java/com/makomi/client/render/LinkSerialHudOverlayRenderer.java`](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/LinkSerialHudOverlayRenderer.java) 当前对最终 IO 采用“缓存未过期就不再请求”的策略，`RUNTIME_HUD_CACHE_TTL_MILLIS=1500ms` 明显压低了更新频率。
- [`src/client/java/com/makomi/client/render/LinkNodeFarOverlayRenderer.java`](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/LinkNodeFarOverlayRenderer.java) 当前贴附类节点通过外法线锚点定位后，又进一步按外法线旋转文本板，导致侧面和顶/底面的 `FACE_OFFSET` 视觉表现不一致。
- 用户希望贴附类节点的远外显像其他节点一样始终面向摄像头，同时保留面向位移语义。

### 技术方案

1. 保留最终 IO 快照缓存与请求节流，但将请求策略改为“命中目标节点期间按节流周期主动轮询”，不再等待缓存 TTL 过期后才再次发起请求。
2. 缩短最终 IO 缓存 TTL，使 HUD 在停止收到新快照后更快丢弃过期数据，降低“旧值残留”的窗口。
3. 将贴附类节点的远外显变换改为“按外法线锚点位移 + 统一公告牌朝向摄像头”，不再让文本板本身沿面法线旋转。
4. 将 `FACE_OFFSET` 与注释重新对齐到半格语义，使核心粉、按钮、拉杆在侧面和顶/底面使用同一世界坐标位移规则。

### 影响范围

- 客户端远外显渲染器
- 近外显最终 IO 缓存与请求节流逻辑
- 无新增服务端协议字段；沿用既有运行态快照链路
