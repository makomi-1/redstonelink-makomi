# 26.1同步1.21.11迁移整体方案

生成时间：2026-05-01 17:51:11
文件名：2026-05-01_175111_26.1同步1.21.11迁移整体方案.md

## 任务背景

当前分支 `migration/fabric-26.1` 已完成 `26.1` 基础编译迁移，但相对 `migration/fabric-1.21.11` 仍缺少 9 个迁移提交，对应 5 组能力缺口：

1. 外显穿透渲染与 Iris/Sodium 兼容分支
2. hide 扩展节点、容器临时选取与对应客户端幽灵渲染
3. 转发器正整数延迟
4. 智能眼镜显示配置补齐
5. GUI 输入框主题与标题描边收敛

本轮目标不是重新设计 `26.1` 功能，而是严格以 `1.21.11` 已落地结果为迁移对象，基于 `26.1` 已变化的客户端渲染、GUI 与 Fabric 接口差异完成等价迁移，并按批次逐步提交。

## 方案详情

### 现状分析

- `26.1` 当前分支已打通 `compileJava`、`compileClientJava`、`compileTestJava`，且 `runClient` 已通过 Java 25 toolchain 固化，具备逐步迁移与逐步 smoke 的验证条件。
- `1.21.11` 相对当前分支的差异主要集中在客户端与资源层，主服务端框架改动较少，因此实施顺序应先补齐客户端基础设施，再补业务功能。
- `26.1` 当前 GUI 头部与输入框已切到 `GuiGraphicsExtractor` 抽取渲染链路，不能直接照搬 `1.21.11` 后续提交里基于 `GuiGraphics` 的实现；需要按 `26.1` 机制接口改写，但行为与视觉结果仍以迁移对象为准。
- `1.21.11` 的标题描边在缓存中可确认存在 `Font.drawInBatch8xOutline` / `drawStringWithBackdrop` 一类接口；但若 `26.1` 当前 GUI 抽取链无法稳定调用，优先保留当前稳定可见的四向描边 fallback，禁止为“强上新接口”造成标题消失。

### 技术方案

按依赖顺序拆成 5 个可提交批次：

1. **渲染基础设施批次**
   - 迁移穿透线段/面层公共渲染支持。
   - 迁移 quick-link / 定向箭头在 `26.1` 下的穿透外显与 Iris 兼容分支。
   - 收敛当前节点描边、preview 线框、第三形态连线的共用绘制路径。
   - 该批次不触碰业务语义，只解决“能否按 1.21.11 方式显示”。
2. **hide 扩展与容器批次**
   - 迁移 hide 系列扩展方块、方块实体、注册表、容器临时选取逻辑、客户端幽灵渲染。
   - 同步对应语言、blockstate、model、recipe 与贴图资源；贴图缺口按 `1.21.11` 对应文件直接复制对齐。
   - 该批次是资源改动集中面，执行时记录目标贴图清单、目的、方式与回退点。
3. **转发器延迟批次**
   - 迁移 `RepeaterDelay` 的正整数 tick 语义。
   - 同步编辑界面、物品提示与测试断言。
4. **智能眼镜配置批次**
   - 迁移智能眼镜方向箭头显示开关、客户端配置模板与解析器。
   - 保持 hide 节点在眼镜下的可见性规则与 `1.21.11` 一致。
5. **GUI 主题与标题批次**
   - 迁移多行输入框主题壳、无阴影 hint/计数器与标题描边收敛。
   - 优先在 `26.1` 可用接口上恢复描边；若直接接 `drawInBatch8xOutline` 无法接入当前抽取链，则保留稳定四向描边 fallback，确保标题始终可见。

### 技术取舍

- **迁移策略**：优先按 `1.21.11` 已有提交边界分批，而不是重新混排业务主题。这样能最大限度复用迁移对象的实现意图、验证口径与后续 commit 语义。
- **26.1 接口适配策略**：只在 `26.1` 明确变化的接口处做最小改写，例如 world render 事件、GUI 抽取绘制链、渲染层注册、客户端 key/hud 注册等；不主动扩展新设计。
- **资源策略**：若 `26.1` 缺少 `1.21.11` 对应贴图资源，直接复制对齐，不额外重绘、不改风格，保证迁移对象一致性。
- **标题描边策略**：优先尝试接入目标版本可用接口，但以“标题绝不消失”为第一约束；稳定性高于接口新旧。

### 预期结果与风险

- 预期最终 `migration/fabric-26.1` 的功能表现与 `migration/fabric-1.21.11` 对齐。
- 每个批次都具备独立提交点，并通过“该部分编译 + `runClient` 启动冒烟”验收。
- 主要风险：
  - `26.1` GUI 抽取链与 `1.21.11` GUI 直绘链存在接口断层，标题描边与多行输入框皮肤需要按当前机制改写。
  - Iris/Sodium 兼容分支可能受当前 26.1 渲染状态对象差异影响，需要以运行时 smoke 为准校正。
  - hide 扩展批次包含资源与注册表大面改动，若遗漏资源入口会在启动期而不是编译期暴露。

## 原子步骤清单

### 步骤 1：迁移渲染基础设施
- **操作对象**：`src/client/java/com/makomi/client/render/**`、`RedstoneLinkClient.java`
- **具体动作**：同步穿透几何渲染、quick-link/定向箭头兼容分支、必要注册入口
- **预期结果**：外显渲染主链与 Iris/Sodium 兼容链在 `26.1` 下可编译并完成客户端启动 smoke
- **关键里程碑**：是

### 步骤 2：迁移 hide 扩展与容器联动
- **操作对象**：hide 方块/方块实体/注册表/容器逻辑/资源文件
- **具体动作**：同步 hide 扩展节点、容器临时选取、客户端幽灵渲染、语言/模型/配方/贴图
- **预期结果**：hide 扩展功能与资源入口在 `26.1` 下完整可加载
- **关键里程碑**：是

### 步骤 3：迁移转发器正整数延迟
- **操作对象**：`RepeaterDelay`、`RepeaterEditorScreen`、相关 HUD/测试
- **具体动作**：同步正整数 tick 语义、编辑界面行为与测试
- **预期结果**：转发器延迟行为与 `1.21.11` 一致
- **关键里程碑**：是

### 步骤 4：迁移智能眼镜显示配置
- **操作对象**：客户端显示配置、解析器、眼镜渲染开关
- **具体动作**：补齐方向箭头配置、模板、文案与可见性规则
- **预期结果**：智能眼镜显示配置与 `1.21.11` 对齐
- **关键里程碑**：否

### 步骤 5：迁移 GUI 主题与标题显示
- **操作对象**：标题渲染支持、输入框组件、相关 screen
- **具体动作**：恢复多行输入框主题壳、无阴影提示、标题描边收敛
- **预期结果**：GUI 标题稳定可见，输入框主题与别名提示表现与迁移对象一致
- **关键里程碑**：是

## 验证策略

- 每批次先执行工作区双校验，再进行写操作。
- 每批次至少执行：
  - 对应最小编译任务（通常为 `compileJava`、`compileClientJava`、必要时 `compileTestJava`）
  - `.\gradlew.bat --no-daemon runClient` 启动冒烟
- `runClient` 冒烟以客户端进入初始化完成态、无启动期崩溃/资源缺失错误为通过标准；验证完成后主动结束进程，避免残留后台客户端。

## 语义对齐说明

- 命名检查：本轮新增/迁移实现继续统一内部术语 `triggerSource/core`，与既有 `LinkNodeType.TRIGGER_SOURCE/CORE` 映射保持一一对应。
- 方向检查：迁移仅同步既有功能，不改变 `triggerSource -> core` 单向写入约束。
- 文案检查：新引入文案与配置键保持 `triggerSource/core`，旧术语仅允许作为兼容输入别名存在。
- 兼容边界检查：坚持“读旧写新”，不恢复 `com.makomi.api.v1.*` 依赖。
- 残余风险：GUI 与渲染层为 `26.1` 接口差异集中区，需要以逐批 smoke 结果继续收敛；除此之外无新增语义风险。
