# bench graph无玩家上下文阻塞

## 阻塞点

- dedicated bench suite 在 `server.command.benchmarkMode.enabled=true` 的无人值守场景下，`bench graph export/preview/save` 仍回 `reason=no_player`。
- 首轮尝试还误用了 `-AsPlayer BenchBot`，结果 suite 先卡在玩家上下文等待，掩盖了真正的代码问题。

## 解决方法

- 先按文档口径确认 benchmark mode 已开启，dedicated functional case 不再传 `-AsPlayer`，把环境噪音拿掉。
- 然后把 `bench graph` 相关链路改成 source-aware：
  - `BenchGraphCommandRegistry` 直接把 `CommandSourceStack` 传给 graph export / preview / save。
  - `GraphSnapshotExportService` 抽象 `ViewerContext`，为系统命令源生成合成 dedupe actor，保留 export force/reuse 语义。
  - `GraphWriteService` 新增 `CommandSourceStack` 重载，权限、限流、OCC 统一按命令源执行，保留玩家路径兼容。

## 复用建议

- 以后 dedicated bench 若已开启 `server.command.benchmarkMode.enabled=true`，优先走“无 `-AsPlayer`”路径，避免把玩家在线状态误当成业务回归失败。
- 新增 bench/internal 命令时，若设计目标包含 RCON/控制台无人值守执行，入口一开始就不要把玩家实体当成唯一身份源。
