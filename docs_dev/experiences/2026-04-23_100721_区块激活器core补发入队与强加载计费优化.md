# 区块激活器core补发入队与强加载计费优化

## 阻塞点

为 `tryForceLoad(...)` 新增“已持票 chunk 重复命中不重复扣费”测试时，直接调用真实 `addRegionTicket(...)` 会在最小 `ServerLevel` 测试夹具里触发 `ServerChunkCache.distanceManager == null` 的空指针，导致测试焦点从“计费口径”偏移到 Minecraft 区块系统初始化细节。

## 解决方法

- 不再让该测试走“首次真实加票”分支。
- 改为预先向 `DispatchState.forcedChunksUntilTick` 写入同一 `ForcedChunkKey`，并同步预置 `forceLoadCountThisTick / forceLoadCountBySource`。
- 然后仅验证再次命中同一 chunk 时：
  - 只续期 `forcedChunksUntilTick`
  - 不重复增加 `forceLoadCountThisTick`
  - 不重复扩张 `forceLoadCountBySource`

## 经验结论

涉及 Minecraft 区块票据的单测，如果目标只是验证“调度状态机/计费口径”，优先隔离到状态层，不要把测试耦合到完整 `ServerChunkCache` 和 `DistanceManager` 初始化；否则很容易被底层世界夹具噪声干扰。
