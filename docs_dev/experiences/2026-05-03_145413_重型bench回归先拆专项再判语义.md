# 重型bench回归先拆专项再判语义

生成时间：2026-05-03 14:54:13
文件名：2026-05-03_145413_重型bench回归先拆专项再判语义.md

## 阻塞点

一次性把 samechunk latency、mixed direct、mixed combinations 放进同一批 dedicated functional 回归时，`x20~x23` 很容易在 bench 玩家命令桥或玩家上下文阶段提前超时，表象上会混出三类错误：`Timed out waiting for bench player command bridge response within 5000ms`、`Timed out waiting for player context`、以及同场景残留导致的 `That position is not loaded`。这会让“工具链阻塞”和“真实语义失败”混在一起，难以直接判断改动是否回归。

## 解决方法

先复用仓库里现成的专项 suite，把回归拆成更小的 dedicated 批次分别跑：

1. 先跑与本次改动最直接相关、规模较小的 `functional-mixed-direct-debug.json`，确认 `x22` 能形成有效通过结论。
2. 再单独跑 `functional-mixed-combinations-direct-debug.json` 和 `functional-samechunk-latency-debug.json`，把 `x23` 与 `x20/x21` 的失败归因为“独立场景问题”或“bench 链路超时”，不要与本次实现主结论混算。
3. 读取 suite `summary.json` 判定结果时，优先看 `status/passed/resultMissing/error`，避免只凭控制台零散日志下结论。

这次拆跑后，`x22` 三个窗口全部通过，而 `x23` 与 `x20/x21` 的问题被成功隔离成后续独立处理项，没有再污染本次性能原型的回归验收结论。
