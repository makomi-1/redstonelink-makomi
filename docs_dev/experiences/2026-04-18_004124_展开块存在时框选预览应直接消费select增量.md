# 展开块存在时框选预览应直接消费select增量

生成时间：2026-04-18 00:41:24

## 阻塞点
- ReactFlow 画布里一旦混入聚合块和聚合包围盒，`onSelectionChange` 返回的节点集合就不再适合作为框选预览态的唯一真源；如果预览阶段又把 `NodeSelectionChange` 的 `select` 增量全部过滤掉，就会出现“框到一部分却全选”或“只要有展开就完全框选失败”。

## 解决方法
- 预览阶段不要再依赖 `onSelectionChange` 猜最终选区，改为直接消费 `handleCanvasNodesChange` 收到的 `select` 增量。
- 在框选开始时先快照当前正式选区，再基于后续 `select true/false` 增量维护候选集合。
- 预览候选集合只保留真实 `triggerSource/core` 节点，聚合块和包围盒一律在入口过滤。

## 复用建议
- 命中 ReactFlow 或类似图编辑器的“框选预览态 / 应用态分离”场景时，优先确认哪条事件链提供的是增量真源，哪条只是派生视图结果。
- 如果画布里存在辅助节点、包围盒、锚点等非业务节点，不要让它们参与业务选区的最终提交；应在事件入口就统一过滤。
