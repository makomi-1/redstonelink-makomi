# GraphViewer详情分支联合类型收窄

## 阻塞点

`GraphViewer.tsx` 的详情面板原本先把 `selectedCanvasNode` 抽成 `selectedNode`，再用 `channelHub / aggregate / else` 三段式 JSX 分支渲染。最后一段只是兜底 `else` 时，TypeScript 不会把 `selectedNode` 推断成非空，导致 `typecheck` 在详情字段上集中报 `possibly null`。

## 解决方法

- 不要在“联合类型兜底分支”里继续依赖前面拆出来的 nullable 变量。
- 把最后一段详情渲染改成显式 `selectedCanvasNode.kind === "actual"` 分支，并在分支内部直接使用 `selectedCanvasNode.graphNode`。
- 这种写法能让 TS 利用判别式联合完成收窄，后续新增新的 `kind` 时也更容易定位遗漏分支。

## 复用建议

- 只要 React 组件里存在 `kind` 判别式联合，优先写成显式分支，不要把“最后一个 else”当成某个固定子类型。
- JSX 层如果字段较多，宁可在分支内部直接访问 `xxx.graphNode`，也不要过早拆成跨分支复用的 nullable 临时变量。
