# 慢测性能基线抖动复核

## 阻塞点
- 执行全量回归命令 `.\gradlew.bat test testIntegration testClient testSlow --no-daemon` 时，`LinkSavedDataPerformanceSlowTest` 首次失败。
- 失败表现为加载耗时阈值超线：`load cost 51ms exceeds limit 40ms`。

## 处置方法
- 先读取失败 XML，确认失败点仅为 `testSlow` 的性能基线断言，而非功能断言。
- 再单独重跑 `.\gradlew.bat testSlow --tests com.makomi.data.LinkSavedDataPerformanceSlowTest --no-daemon`，确认该慢测可通过。
- 最后重新执行完整命令，确认 `test / testIntegration / testClient / testSlow` 全部通过。

## 经验结论
- 对慢测性能阈值失败，先区分“功能回归”与“环境抖动”。
- 若失败集中在毫秒级性能阈值，且本轮改动未触及对应核心路径，应优先单测复核，再回到全量套件重跑确认。
- 最终交付时应同时保留“首次失败原因”和“复跑通过结论”，避免把一次性抖动误判为功能问题。
