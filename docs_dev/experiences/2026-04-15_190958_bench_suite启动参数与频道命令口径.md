# bench suite 启动参数与频道命令口径

生成时间：2026-04-15 19:09:58

## 阻塞点

- dedicated `run-bench-suite.ps1` 虽然能自动构建并同步 mod jar，但如果未显式传 `-ServerStartCommand`，会在进入首个 case 前直接抛出 `ServerStartCommand is required`，导致这类失败看起来像“suite 配置坏了”，实际是启动参数缺失。
- 频道 OCC case 如果把命令写成 `submit core <serial> channel <id>` 或 `submit triggerSource <serial> channel <id>`，会在 dedicated 实跑时被 Brigadier 直接拒绝；真实语法要求先写对端类型字面量，再进入 `channel` 分支。

## 根因

- `run-bench-suite.ps1` 入口没有为外部 dedicated server 提供隐式默认启动命令，必须由调用方明确给出前台阻塞型启动脚本。
- `BenchOccCommandRegistry` 的频道命令树挂在 `triggerSource -> core -> channel` 和 `core -> triggerSource -> channel` 分支上，case 若只凭“看起来像 pairing submit”的直觉写命令，会漏掉中间字面量层级。

## 解决方法

- dedicated suite 固定按以下口径执行：
  `powershell -ExecutionPolicy Bypass -File .\tools\bench\run-bench-suite.ps1 -ServerStartCommand '.\start.bat' ...`
- 新增频道 OCC case 前，先对照命令树确认命令模板：
  - `redstonelink bench occ pairing submit triggerSource <serial> core channel <channel> expectedSourceRevision=<rev>`
  - `redstonelink bench occ pairing submit core <serial> triggerSource channel <channel> expectedCoreRevision=<rev>`

## 可复用检查清单

- dedicated suite 首跑前先确认是否已经传入 `-ServerStartCommand`。
- bench 新命令上线后，先用 dedicated case 实跑一次，不只看 `PrintCase`。
- 若 dedicated 结果里出现 `Incorrect argument for command`，优先回查 `BenchOccCommandRegistry` 的字面量层级，而不是先怀疑业务实现。
