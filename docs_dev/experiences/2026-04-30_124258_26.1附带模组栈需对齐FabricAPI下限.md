# 26.1附带模组栈需对齐FabricAPI下限

生成时间：2026-04-30 12:42:58
文件名：2026-04-30_124258_26.1附带模组栈需对齐FabricAPI下限.md

## 阻塞背景

主模组本体已经能在 26.1 纯净客户端成功启动，但启用本地附带模组栈后，运行链路先后卡在依赖挂载方式和运行期版本约束上。

## 阻塞点与解决

- 阻塞点：
  当前这套 26.1 构建脚本里没有可直接调用的 `modRuntimeOnly` / `modLocalRuntime` 扩展方法；即使版本号本身正确，Gradle 也会在脚本求值阶段失败。
- 解决方法：
  由于 Lithium / JEI / Sodium / Iris 都已经是 26.1 原生版本，不需要再做旧版 remap，所以直接改为受开关控制的 `runtimeOnly` 即可。

- 阻塞点：
  `Sodium 0.8.9+mc26.1.1` 明确声明会拒绝 `fabric-api < 0.145.1`，而原项目基线是 `0.145.0+26.1`，导致 Fabric Loader 在启动早期直接判定模组不兼容。
- 解决方法：
  将 `fabric_api_version` 提升到 `0.145.1+26.1`，保持 `minecraft_version=26.1` 不变，再组合 `Lithium 0.24.2 / JEI 29.5.0.27 / Sodium 0.8.9 / Iris 1.10.9` 即可闭合当前附带模组运行矩阵。

## 后续建议

- 后续同步附带模组版本时，不要只看单个模组是否支持当前 Minecraft 版本，还要同时检查它对 `fabric-api`、渲染器或前置模组的下限约束。
- 如果附带模组已经是 26.1 原生构建，优先先验证 `runtimeOnly` 是否足够；只有确实需要 remap 的旧版模组，才继续找 Loom 的专用 mod runtime 配置。
