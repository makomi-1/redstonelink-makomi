# hide资源与26.1幽灵渲染适配

## 阻塞点

在 26.1 迁移 hide 扩展时，客户端存在两个串联阻塞：

1. 旧版 hide 幽灵渲染实现依赖的方块模型接口在 26.1 已变化，直接沿用会导致 `compileClientJava` 失败。
2. hide 物品模型改为引用 `block/*_hide.png` 后，目标分支缺少对应贴图资源，`runClient` 进入资源加载时会把 hide 物品全部渲染成紫黑缺失纹理。

## 定位方式

1. 先通过 `compileClientJava` 收敛到幽灵渲染失败点，确认 26.1 不能再走旧版 `getBlockRenderer()` 直取模型的路径。
2. 对照当前分支已稳定运行的 26.1 方块渲染代码，确认应切换到 `BlockStateModelSet + ModelBlockRenderer + QuadInstance` 的模型提交链。
3. 再通过 `runClient` 日志确认失败已经从“代码编译”切换成“资源缺失”，并锁定缺失的是 `hide_*` 物品最终引用到的 `textures/block/*_hide.png`。

## 解决方法

- 幽灵渲染部分新增 26.1 专用支撑层，统一由 `HideGhostRenderSupport` 负责取 block state model、收集 model parts，并把 vanilla 算好的顶点色仅压缩 alpha 后提交。
- 过滤器和区块激活器的 hide 渲染器不再各自维护普通状态映射，而是统一调用 `HideNodeSupport.resolveGhostDisplayState(...)`，减少 26.1 与 1.21.11 差异扩散。
- 资源部分直接从迁移对象分支补齐缺失的 `textures/block/*_hide.png` 与必要 item 贴图，使 item model 与 block model 的纹理引用重新闭合。

## 复用提醒

- 后续凡是迁移 1.21.11 的 hide/block-model 客户端渲染，优先复用现有 26.1 `HideGhostRenderSupport`，不要直接复制旧版 block renderer API。
- 遇到“编译已过但客户端物品紫黑”的场景，先检查最终 item model 是否改成引用 `block/` 贴图，再核对对应 `textures/block/*.png` 是否已经同步到目标分支。
