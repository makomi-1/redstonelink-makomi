# sync语义改造断口修复

## 阻塞点
- 给 `RedstoneLinkCrossChunkConfig` 新增 record 字段后，显式构造点没有同步补齐，首先在 `RedstoneLinkServerConfigSnapshot` 默认快照处编译失败，随后还会波及测试夹具。
- `sync` 默认语义从“最新帧覆盖”切到“跨 tick 共存”后，旧自动化测试里混有两类陈旧断言：一类仍假设 `pulse/toggle` 会覆盖或回露，另一类仍假设默认只保留最新 `sync` 帧。

## 解决方法
- 新增 record 字段后，先全局检索 `new RedstoneLinkCrossChunkConfig(`，逐个补齐构造参数，并把默认快照同步到 parser/template 的默认值，避免运行时默认口径分叉。
- 对测试做“两层拆分”：
  - 默认路径统一按 `syncCrossTickOverride=false` 验证跨 tick 共存和跨类型硬压制。
  - 旧覆盖语义只保留在显式 `crosschunk.syncCrossTickOverride=true` 的测试块里验证。
- 源码契约测试不要继续绑死旧实现细节；这次把扇出去重契约改成“保留 `TimeKey` 记录，但不再把它作为重复激发条件”。

## 复用建议
- 以后只要给 record/配置快照新增字段，先做一次“构造点全检”，再跑编译；这比等编译器逐个报错更快，也更不容易漏掉测试夹具。
- 当语义切换同时影响“默认行为”和“兼容开关”时，优先把测试拆成“默认语义测试 + 开关语义测试”，不要在同一批断言里混写两套预期。
