# 共享输入区隐藏控件吞点击

生成时间：2026-04-15 20:56:07

## 阻塞点

- 过滤器 GUI 的 `serialInputBox` 和 `channelInputBox` 共用同一块坐标区域，切到 `channel` 模式后界面看起来只剩频道输入框，但鼠标点击仍被隐藏的多行序号框吞掉，导致频道输入框无法聚焦。

## 根因

- 仅设置 `visible/active=false` 并不能保证原版 `MultiLineEditBox` 完全退出点击链。
- 当多个控件共享同一区域时，如果继续依赖 `Screen` 默认按注册顺序分发点击，先注册的隐藏控件仍可能抢先返回 `true`。

## 解决方法

- 不修改通用控件实现，直接在具体 GUI 的 `mouseClicked` 中为共享输入区增加显式路由：
  - 先根据当前模式和坐标解析“本次点击应该归谁”
  - 再把点击和焦点交给当前可见输入框
  - 同时在模式切换时清理隐藏控件残留焦点

## 可复用检查清单

- 只要界面里存在“多个输入控件共用同一区域，靠模式切换显示”的设计，就不要只依赖 `visible/active`。
- 遇到“看得见但点不到”的 GUI 问题，优先检查隐藏控件是否仍在默认点击分发链上。
- 最小回归测试可直接锁“坐标 + 当前模式 -> 应路由到哪种输入框”，不一定非要做完整 GUI 自动点击。
