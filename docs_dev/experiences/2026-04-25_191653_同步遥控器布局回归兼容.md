# 同步遥控器布局回归兼容

## 阻塞点

为同步遥控器在 pairing GUI 中增加附加控制行后，`AbstractMultiPairingScreen` 的静态 `resolveLayout(..., LayoutDensity.COMPACT)` 默认行为被我一并改成了“仍保留模式按钮语义”，导致全量回归中的 `AbstractMultiPairingScreenLayoutTest.resolveLayoutShouldCompactRepeaterContext()` 失败。

## 解决方法

- 不直接改写旧静态重载的默认语义。
- 新增一个显式接收 `showModeButton/showSupplementalButtonRow` 的布局重载，只让实例态真实界面走这条新路径。
- 保留旧静态重载对 `COMPACT` 的兼容语义：`COMPACT` 仍默认视为“不显示模式按钮”，从而维持原有测试与转发器紧凑布局行为不变。

## 复用建议

- 给现有 GUI 基类新增布局能力时，优先“加新重载承载新语义”，不要直接篡改被测试或被其它上下文隐式依赖的旧重载默认值。
- 做完这类布局抽象扩展后，除了定向测试，还要尽早跑一次对应标签的全量 UI 回归，避免兼容性问题拖到最后一起爆出。
