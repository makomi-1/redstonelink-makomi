# 物品tooltip契约测试避免直接实例化经验

## 阻塞点

为遥控器 tooltip 新增 Java 契约测试时，最初直接在测试里实例化 `LinkerItem` / `SyncLinkerItem`，结果触发了物品初始化相关的静态依赖，导致测试在真正断言前就失败。

## 解决方法

- 不把“tooltip 文案键测试”写成物品实例测试，而是像现有区块激活器 tooltip 测试一样，抽一个静态 helper，只验证返回的翻译键。
- 业务代码侧把遥控器跨区块 tooltip 文案收口到 `LinkerItem.crossChunkCapabilityTooltip()`，实例方法 `buildCrossChunkCapabilityTooltip()` 只做转发。
- 测试侧只校验 helper 返回的 `TranslatableContents` key，避免把无关的物品初始化链路带进来。

## 适用场景

- 仅想验证 tooltip 文案 key / 组件类型 / 映射关系；
- 被测逻辑本身不依赖真实世界、注册表或物品运行态；
- 直接实例化 Minecraft 物品/方块对象会额外触发静态初始化副作用时。

## 经验结论

对这类“文案契约”测试，优先抽静态 helper 再测 helper；不要为了断言一个翻译键，去承受整条物品实例初始化链路的耦合成本。
