# 内部辅助方法扩签后的漏改调用点

## 阻塞点

在为 `LinkSetExecutionService.prepareConfirmedReplaceResolvedTargets(...)` 增加“同请求允许的频道目标集合”参数后，`GraphWriteService` 与 `LinkChannelEditingService` 已同步通过，但仍遗漏了 `CoreLinkEditingService` 的直调点，导致 `compileJava` 失败。

## 解决方法

1. 不只搜索 public 入口，还要全局搜索内部 helper 的所有直接调用点。
2. 对扩签方法统一补默认参数（本次为 `Set.of()`），保证原有调用语义不变。
3. 先跑一次定向 `gradlew test --tests ...`，用编译器把漏改调用点快速打出来，再回到实现层补齐。

## 后续复用建议

- 以后只要修改 `command/link` 下的共享 helper 签名，先执行一次：
  - `rg -n "方法名\\(" src/main/java -S`
- 对“旧语义保持不变”的调用点，优先传显式默认值，而不是在各调用方重写分支逻辑。
