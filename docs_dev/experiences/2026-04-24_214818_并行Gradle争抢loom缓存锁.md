# 并行Gradle争抢loom缓存锁

生成时间：2026-04-24 21:48:18
文件名：2026-04-24_214818_并行Gradle争抢loom缓存锁.md

## 阻塞点

- 在同一工作区并行启动多个会触发 Fabric Loom 参与解析/编译的 Gradle 任务时，任务会争抢 Loom 缓存锁。
- 这次表现为一边跑 `compileJava/compileClientJava`，另一边同时跑测试任务后，编译任务报出大量“包不存在 / 类不存在 / 符号找不到”的表象错误，但根因并不是源码真的被改坏。

## 解决方法

- 停掉并行的 Gradle 任务后，改为串行执行：先单独跑目标测试或编译任务，再继续下一个任务。
- 如果已经出现这类大面积缺类报错，不要立刻按报错去改源码，先用单独一条 Gradle 命令重跑确认；本轮串行重跑后，定向测试和全量测试都恢复正常。

## 适用范围

- 适用于当前这类 Fabric Loom / Gradle 工作区，尤其是 `compileJava`、`compileClientJava`、`test`、`testIntegration`、`testClient`、`testSlow` 等可能共同触发依赖解析与编译缓存访问的任务组合。

## 注意事项

- 同一工作区内不要并行跑多个会触发 Loom 缓存访问的 Gradle 命令。
- 如果只是想缩短验证时间，优先选择“减少任务集合”而不是“并行启动多个 Gradle 进程”。
- 看到大面积基础类缺失报错时，先排除工具链锁竞争，再判断是否真的需要修改代码。
