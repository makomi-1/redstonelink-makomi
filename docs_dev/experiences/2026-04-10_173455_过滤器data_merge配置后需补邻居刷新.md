# 过滤器 data merge 配置后需补邻居刷新

## 阻塞点

过滤器 functional case 中，直接使用 `data merge block` 修改 `serialExpression`、`nodeSetMode`、`signalThresholdSource` 或 `signalMode` 后，真实 dedicated 跑测会出现“命令执行成功，但运行态过滤效果没有立即变化”的假失败。

## 解决方法

在每次关键过滤器配置切换后，补一组真实邻居变化，例如：
- 先把邻位改成 `minecraft:air`
- 再恢复为 `minecraft:redstone_block`
- 最后补 `wait_ticks`

这样可以稳定触发过滤器运行态重采样与持久化真值刷新，再进行输入注入和 trace 断言。

## 适用场景

- `fixed_input` 与 `neighbor_max_input` 之间切换
- `upper_bound` / `lower_bound` 之间切换
- 节点集 `serialExpression` / `nodeSetMode` 切换
