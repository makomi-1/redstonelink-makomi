# 单测环境最小转发器夹具构造

生成时间：2026-04-24 21:15:00
文件名：2026-04-24_211500_单测环境最小转发器夹具构造.md

## 阻塞点
- 纯 `stable-core` 单测里直接调用 `ModBlocks.register()` 会在 `MappedRegistry.createIntrusiveHolder(...)` 抛出 `This registry can't create intrusive holders`，因为内建注册表已冻结。
- 即便绕过了方块构造，若继续借用 `BlockEntityType.BEACON` 之类的原版类型，`BlockEntity.validateBlockState(...)` 仍会因为测试块不属于该类型的合法方块集合而失败。

## 解决方法
- 不走真实模组注册，而是在测试内短暂打开 `BuiltInRegistries.BLOCK` 与 `BuiltInRegistries.BLOCK_ENTITY_TYPE` 的写窗口，构造最小 `LinkRepeaterBlock` 和匹配的最小 `BlockEntityType`。
- 写窗口必须是 `try-with-resources` 形式，并在关闭时按逆序恢复 `frozen` 与 `unregisteredIntrusiveHolders`，避免污染同 JVM 里的其他测试。
- 这样可以保留真实 `LinkRepeaterBlock.ACTIVE`/`instanceof LinkRepeaterBlock` 行为，避免把行为测试退化成纯源码正则。

## 适用范围
- 适用于需要验证“自定义 blockstate/自定义 block entity type 语义”，但又不想引入完整模组注册流程的纯 JUnit/Fabric Loom 单测。

## 注意事项
- 该手法只适合测试源集，禁止带入运行时代码。
- 如果后续测试开启并行执行，需评估是否把这类注册表写窗口测试串行化，避免多个用例同时修改同一全局注册表状态。
