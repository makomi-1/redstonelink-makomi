# Fabric护甲渲染签名差异处理

## 阻塞点
- 新增智能眼镜半透明穿戴渲染时，按常见示例使用了 `ItemRenderer.getArmorFoilBuffer(vertexConsumers, renderType, false, stack.hasFoil())` 四参数写法。
- 当前项目对应的 1.21.1 / Fabric API 版本实际只提供三参数签名，导致 `compileClientJava` 直接失败。

## 解决方法
- 先用本地编译快速收敛错误，再按当前映射版本改成三参数调用：
  - `ItemRenderer.getArmorFoilBuffer(vertexConsumers, RenderType.entityTranslucent(texture), stack.hasFoil())`
- 修正后重新执行 `compileJava compileClientJava --no-daemon`，确认渲染器签名已经和当前环境对齐，再继续跑全量测试。

## 复用建议
- 以后在本项目新增 Fabric 客户端渲染入口时，不要直接照搬别处示例里的方法签名，先用本地依赖或一次快速编译确认当前 API 版本的真实参数列表。
- 尤其是 `ArmorRenderer`、`ItemRenderer`、`RenderType` 这类跨版本变化较频繁的客户端 API，优先采用“先最小编译验证，再扩展功能”的方式推进。
