# 单测避免直接触发 ModItems 静态初始化

## 阻塞点
- 新增容器销毁递归退役单测时，最初直接用 `new ItemStack(ModItems.LINK_REDSTONE_CORE)`、`ModItems.LINK_REPEATER` 造测试数据，结果在纯数据层单测里提前触发 `ModItems` 静态初始化，抛出 `This registry can't create intrusive holders`。

## 解决方法
- 不把这类单测绑到物品注册表生命周期上，而是把待测逻辑继续下沉一层。
- 这次做法是给 `SmartNodeContainerRetireSupport` 增加包级可见的 `retireTargets(...)`，让测试直接构造 `RetireTarget` 列表，只验证“递归退役语义”，不再依赖 `ItemStack + ModItems` 的完整注册环境。

## 复用提示
- 如果测试目标是“算法/状态机/保存数据副作用”，优先抽出更低层、无注册表副作用的可测入口。
- 只有测试目标本身就是“注册表映射/物品分类”时，才考虑给测试补 `RegistryWriteWindow` 之类的注册表写窗口。
