# 客户端渲染测试Bootstrap前置

## 阻塞点

- `QuickLinkOutlineRendererTest` 在直接引用 `QuickLinkOutlineRenderer` 时，类静态初始化会提前触发 `RenderType -> Items/Blocks -> BuiltInRegistries` 链路。
- 如果测试类没有先执行 `SharedConstants.tryDetectVersion()` 与 `Bootstrap.bootStrap()`，就会报 `Not bootstrapped (called from registry ResourceKey[minecraft:root / minecraft:game_event])`，表现为业务测试在类初始化阶段直接失败。

## 解决方法

- 参考仓库中其他 MC 侧单测的统一做法，在测试类 `@BeforeAll` 中补：
  - `SharedConstants.tryDetectVersion();`
  - `Bootstrap.bootStrap();`
- 这样可以在进入客户端渲染或物品/方块相关静态路径前完成注册表初始化，避免把环境问题误判成实现回归。

## 适用场景

- 直接触发 `RenderType`、`Items`、`Blocks`、方块属性、客户端渲染器静态字段初始化的 JVM 单测。
- 新增客户端渲染类测试、物品/方块静态常量测试、依赖注册表默认值的工具类测试。

## 复用提醒

- 后续新增类似测试时，优先先查仓库已有测试是否都做了 bootstrap 前置，再决定是否继续排查业务代码。
- 这条经验适合后续沉淀进 `docs_dev/经验总结.md`，并在涉及客户端渲染/注册表的测试模板里固化。
