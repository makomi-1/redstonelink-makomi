# 26.1键位映射API从keybinding迁到keymapping

生成时间：2026-04-30 12:03:05
文件名：2026-04-30_120305_26.1键位映射API从keybinding迁到keymapping.md

## 阻塞背景

客户端迁移进入 `compileClientJava` 阶段后，旧版 `1.21.11` 的键位辅助类和包路径已经不再适配 26.1，导致客户端入口剩余报错长期集中在键位注册链上。

## 阻塞点与解决

- 阻塞点：
  `1.21.11` 侧沿用的是 `keybinding` 命名与对应 helper；迁到 26.1 后，客户端源码侧已切到 `keymapping` 命名，单靠旧包路径或凭感觉替换，很容易误判为“只能直接调用 `fabric.impl`”。
- 解决方法：
  先确认 26.1 的公开模块与类名已经变为 `fabric-key-mapping-api-v1` 和 `net.fabricmc.fabric.api.client.keymapping.v1.KeyMappingHelper`，再在 `build.gradle` 显式补齐该 client-only 子模块依赖，并把键位注册切到 `KeyMappingHelper.registerKeyMapping(...)`。

## 后续建议

- 遇到 Fabric API rename 时，先核对模块名、包名和公开 helper 是否一起改名，不要直接把内部 `impl` 类当作正式迁移结果。
- 26.1 之后如果再新增客户端键位能力，优先复用当前 `KeyMappingHelper` 方案和显式子模块依赖，避免重复踩同一类编译坑。
