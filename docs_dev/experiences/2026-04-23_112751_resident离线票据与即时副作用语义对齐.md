# resident离线票据与即时副作用语义对齐

生成时间：2026-04-23 11:27:51
文件名：2026-04-23_112751_resident离线票据与即时副作用语义对齐.md

## 阻塞点

- dedicated `x52/x54` 一开始表现不一致：`x52` 会看到目标被拉起，但来源仍离线；`x54` 则连目标区块都没被 resident 拉起，导致很难直接判断是实现缺陷还是测试口径问题。

## 根因

- 区块激活器即时副作用计划把所有 `triggerSource` 新增成员都放进了 `replayTriggerSources`，把 `triggerSource/resident` 误实现成了“resident + replay”。
- resident 常态同步又按 runtime-ready 过滤离线节点，导致 bootstrap 的 resident 票据可能在真正拉起区块前被下一轮 diff 移除。

## 解决方法

- 把 `triggerSource` replay 收敛到 `force_load`，resident 只负责 resident bootstrap。
- 把 resident 期望票据改为按持久化节点登记位置汇总，允许离线节点先被拉起。
- dedicated 断言按设计拆层：`x52` 只验来源区块被拉起并保持，`x54` 先验目标区块在线，再验 core 后续重算恢复高态。

## 复用建议

- 以后遇到“resident 场景节点始终 offline”时，优先检查 resident desired ticket 是否错误依赖 runtime-ready。
- 以后遇到“resident 看起来顺带补发”时，优先检查 immediate effect plan 是否把 resident 与 replay 混在一起。
- 这类问题优先按“resident 负责加载、补发/重算负责后续状态恢复”的分层去排查，能更快区分实现缺陷与测试口径错误。
