# PowerShell 无 BOM 注释兼容性

生成时间：2026-04-09 10:44:38
文件名：2026-04-09_104438_PowerShell无BOM注释兼容性.md

## 阻塞点

在重构 `tools/bench/lib/Bench.FunctionalTrace.ps1` 的过程中，脚本通过 `Get-Content -Encoding UTF8` 与 `scriptblock` 方式都能正常读取，但直接在 Windows PowerShell 5.1 下点载 `.ps1` 文件时出现连续 `Unexpected token '}'` 解析错误，导致新增 handler 无法被真实 bench 入口加载。

## 原因定位

- 文件采用 UTF-8（无 BOM）。
- 新增了多条非 ASCII 注释。
- Windows PowerShell 5.1 直接解析文件时，对无 BOM 脚本中的非 ASCII 注释兼容性不稳定；同一份文本经 `ReadAllText` 再转 `ScriptBlock` 时可通过，但直接点载文件会失败。
- 通过“移除非 ASCII 注释后再点载”的对比验证，可稳定复现并消除问题。

## 解决方法

1. 保留 UTF-8（无 BOM）约束不变。
2. 将脚本中的新增非 ASCII 注释改为 ASCII 注释，避免文件级解析歧义。
3. 对同文件中相关的旧非 ASCII 注释一并改写，确保 dedicated bench 入口实际点载通过。
4. 使用 `powershell -NoProfile -Command ". <script>; Get-Command ..."` 做真实点载 smoke，而不是只依赖 `Get-Content` / `ScriptBlock` 侧验证。

## 复用建议

- 对需要被 Windows PowerShell 5.1 直接 `.` 载入的 `.ps1` 文件，优先使用 ASCII 注释。
- 若项目要求 UTF-8（无 BOM），验证阶段必须补一次“真实文件点载” smoke，不能只看内存脚本块解析结果。
- 以后若再次出现“文件直载报错、内存解析正常”的反常现象，优先排查无 BOM + 非 ASCII 注释组合。
