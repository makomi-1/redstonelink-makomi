# bench预加载区残留导致resident断言失真

## 阻塞点
- dedicated bench 中，`x48_chunk_activator_resident_core` 前半段“resident 保活”通过，但后半段“失活撤销后离线”一直失败。
- 业务实现分析未发现 resident/core 撤销链路缺口，说明阻塞点更可能在 bench 用例口径。

## 解决方法
- 对比用例坐标与 `tools/bench/lib/Bench.World.ps1` 的 `Ensure-CaseChunksLoaded` 逻辑后发现：
  - `benchForceLoadZones` 会完整转成 `forceload add`。
  - `x48` 的占位 source 放在 `z=722`，把显式预加载区扩到了额外一排 chunk。
  - 用例 phases 只移除了 `z=44` 的 chunk，没有覆盖这排额外预加载。
- 处理方式：
  - 不改 resident/core 实现。
  - 把占位 source 收回同一 chunk，并同步缩小 `benchForceLoadZones`。
  - 重新跑 dedicated build-sync，确认 `x48` 通过。

## 复用建议
- 以后写 `autoLoadCaseChunks=false` 的 bench case 时，必须先检查：
  - 显式 `benchForceLoadZones` 是否跨入了额外 chunk；
  - 用例中的 `forceload remove` 是否完整覆盖这些显式预加载 chunk。
- 如果断言是“应离线”，优先先排查 bench 预加载残留，再怀疑业务实现。
