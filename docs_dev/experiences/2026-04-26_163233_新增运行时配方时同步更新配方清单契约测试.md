# 新增运行时配方时同步更新配方清单契约测试

## 阻塞点

新增 `smart_glasses.json` 与 `smart_node_container.json` 后，全量回归在 `RecipeResourceLayoutTest` 失败。失败原因不是配方 JSON 本身格式错误，而是运行时配方清单契约仍停留在旧集合，未登记这两个新文件。

## 解决方法

1. 先读取 `src/test/java/com/makomi/RecipeResourceLayoutTest.java`，确认它校验的是 `src/main/resources/data/redstonelink/recipe/` 下的完整 JSON 文件名集合。
2. 不改测试目录语义，也不迁移既有 recipe/ 结构，只把本次新增的运行时配方文件名同步补入 `EXPECTED_RECIPE_FILES`。
3. 重新执行全量回归，确认失败点消失。

## 复用建议

- 以后只要新增运行时配方文件，都应同步检查 `RecipeResourceLayoutTest` 的 `EXPECTED_RECIPE_FILES`。
- 若未来真的要迁移到其他目录，应先统一更新运行时资源布局设计，再整体调整该契约测试，而不是只改单个新配方路径。
