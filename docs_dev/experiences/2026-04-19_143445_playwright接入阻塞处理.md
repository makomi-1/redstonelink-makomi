# playwright接入阻塞处理

## 阻塞点 1：浏览器下载锁残留

第一次执行 `playwright install chromium` 被中途打断后，`C:\Users\15166\AppData\Local\ms-playwright\__dirlock` 残留，后续安装即使切换代理也会直接失败。

### 解决方法

1. 先检查是否还有 `playwright install chromium` 相关 `node` 进程在运行。
2. 只终止这些明确属于 Playwright 浏览器安装的进程。
3. 核对锁目录绝对路径后，只删除 `__dirlock` 目录本身。
4. 重新带代理环境变量执行安装。

### 复用建议

- 浏览器安装被用户中断后，不要立刻重复执行安装命令。
- 先检查残留安装进程和 `__dirlock`，否则会误判成代理或网络问题。

## 阻塞点 2：Vitest 默认排除规则被覆盖

为了让 Vitest 排除 `e2e/**`，如果直接写死 `exclude: ['e2e/**']`，会把 Vitest 默认的 `node_modules` 排除规则一起覆盖掉，导致依赖包自带测试被扫进来。

### 解决方法

1. 从 `vitest/config` 引入 `configDefaults`。
2. 用 `exclude: [...configDefaults.exclude, 'e2e/**']` 在默认排除规则基础上追加目录。

### 复用建议

- 以后修改 Vitest `exclude/include` 时，优先采用“在默认规则上追加”的方式。
- 对测试框架默认配置不了解时，先读当前配置语义，再改，避免小改动把测试发现范围放大。
