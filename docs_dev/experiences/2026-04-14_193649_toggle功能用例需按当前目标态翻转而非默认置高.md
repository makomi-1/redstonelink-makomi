# toggle 功能用例需按当前目标态翻转而非默认置高

## 阻塞点

在补 `restart replay` 时间键专项时，初版 prepare case 预期“较晚 toggle 后目标保持高态”，导致 dedicated functional 断言失败。

## 现象

- 较早 `sync` 已把目标拉到 `active=true / effectiveMode=sync / resolvedStrength=15`
- 更晚 `toggle` 触发后，目标实际变成 `active=false / effectiveMode=toggle / resolvedStrength=0`
- 这不是 replay 实现错误，而是 `toggle` 在当前模型里按“翻转当前目标结果态”工作

## 解决方法

1. 不再把 mixed 场景里的 `toggle` 默认理解成“置高”
2. 设计用例时先看 toggle 发生前的目标结果态，再推导 toggle 后应为高还是低
3. 将专项断言改为“更晚 toggle 把当前高态翻成低态，重启后旧 sync replay 不能把它重新点亮”

## 复用建议

- 凡是 `toggle` 与 `sync/pulse` 混合的 functional case，都先显式写出“toggle 前基准态”
- 若目的是验证“later event 覆盖 earlier sync”，优先让 later `toggle` 翻成低态；这样断言更敏感，能直接抓到旧 sync 被错误当成新事件重放的情况
