# 补丁上下文漂移时先重读最新文件再拆小补丁

生成时间：2026-04-16 20:56:58

## 阻塞点
- 在已有较多未提交改动的前提下，针对 `StatePanelRecordingScreen.java` 一次性落大补丁，容易因为局部布局代码已经变化而出现上下文不匹配，导致补丁直接失败。

## 解决方法
- 先重新读取目标文件的最新内容，不依赖旧缓存。
- 把“字段新增 / `init()` 表单新增 / `startRecording()` 参数补齐 / `PanelLayout` 调整”拆成几个连续的小块补丁，而不是一次跨多个远距离区域硬贴。
- 落盘后立即做只读复查，重点检查 record 构造参数顺序和布局字段数量是否仍一一对应。

## 复用建议
- 命中 GUI 布局类、长 JSON、长 CSS 这类高漂移文件时，优先按“小补丁 + 复查 + 再补”的节奏推进。
- 如果文件同时被前几轮改过，先用行号复核新增字段和构造参数，再继续下一轮实现，能明显降低补丁失败和隐藏编译错误。
