# IrisSodium兼容渲染分支

## 阻塞点

原工作区 `1.21.1` 的 `Iris` 兼容直绘线段实现，依赖的是旧版世界渲染入口和直接线段提交方式；迁到 `1.21.11` 后，这套方法对应的接口和渲染时机已经变了，不能直接照搬。

## 现象

- 旧实现依赖的世界事件阶段与当前 `world` 包下事件名不一致。
- 旧实现假设可以继续直接把线段写到兼容分支专用渲染目标里，但当前版本更稳定的公共能力其实已经是现成的穿透四边形管线。
- 如果硬搬旧实现，要么编译不过，要么容易再次遇到兼容模组下的位移、遮挡或线段显示异常。

## 解决方法

把“兼容模组分支”的实现语义保留下来，但把“具体提交方式”替换成当前版本可用的方法：

1. 判定层继续保留为“检测到 `iris` 或 `sodium` 时启用兼容分支”。
2. 业务渲染层统一先沉淀为世界空间线段。
3. 兼容分支不再直接提交线段，而是把每条线段展开成面向相机的细长四边形。
4. 最终复用当前 `1.21.11` 已经稳定的穿透四边形公共管线提交。

## 复用建议

以后再从旧工作区迁客户端渲染兼容逻辑时，优先同步“判定条件、显示语义、调用链位置”，不要直接复制旧版底层提交代码。先确认当前版本已经存在的公共渲染支撑，再把旧逻辑适配到新的公共支撑上。这样通常比继续维持多套旧底层渲染实现更稳。
