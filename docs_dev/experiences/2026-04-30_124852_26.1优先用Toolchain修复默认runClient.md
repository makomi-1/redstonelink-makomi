# 26.1优先用Toolchain修复默认runClient

生成时间：2026-04-30 12:48:52
文件名：2026-04-30_124852_26.1优先用Toolchain修复默认runClient.md

## 阻塞背景

迁移分支已经能在显式传入 `-Dorg.gradle.java.home=C:\Program Files\Java\jdk-25` 时启动客户端，但用户直接执行 `.\gradlew.bat --no-daemon runClient` 仍会失败。

## 阻塞点与解决

- 阻塞点：
  Gradle wrapper 本身是从当前环境的 `JAVA_HOME=C:\Program Files\Java\jdk-21` 起步的，`compileJava` 会在任务初始化阶段直接命中“`不支持发行版本 25`”。
- 解决方法：
  不去要求调用方追加命令行参数，也不把绝对路径硬写进公共 `gradle.properties`，而是直接在项目里声明 Java 25 toolchain，并把 `JavaExec` / `Test` 任务统一绑定到同一个 `java25Launcher`。

## 后续建议

- 对 26.1 这种明确要求 Java 25 的迁移分支，优先让项目自身通过 toolchain 保证 JVM 版本，而不是依赖调用者记忆额外参数。
- 只有在目标机器根本没有可探测的 JDK 25 时，才退回到显式 `org.gradle.java.home` 或环境变量方案。
