# 空搜索命中集合参与强制显示前先归零

生成时间：2026-04-17 16:55:31

## 阻塞点
- 当视图层把“搜索命中集合”直接并入“强制显示集合”时，如果空查询默认返回全量命中，就会把整张图都误标成强制显示，导致收起、临时显示清空等局部可见性逻辑全部失效。

## 解决方法
- 在匹配函数层明确规定：空串和纯空白查询一律返回“不命中”，不要沿用字符串包含函数对空串的默认真值。
- 在调用层再加一层 `hasSearch` 守卫，无真实搜索时直接返回空命中集合，避免后续派生链路继续做无意义遍历和状态放大。
- 如果一个集合同时汇总“搜索命中 / 编辑选择 / 草稿差异 / 手动拉回”等多种来源，排查问题时要逐项验证各来源在空态下是否真的归零，不能只看最终合并结果。

## 复用建议
- 命中 `query -> matchedSet -> forcedVisibleSet -> canvasView` 这类链路时，优先先确认“空查询语义”是否被显式定义，再排查裁剪和布局逻辑。
- 对复用型派生集合，尽量在“匹配函数”和“调用入口”两层同时防守，能明显降低默认值泄漏到视图层的概率。
