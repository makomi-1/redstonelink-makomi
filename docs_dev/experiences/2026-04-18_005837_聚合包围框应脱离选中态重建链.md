# 聚合包围框应脱离选中态重建链

生成时间：2026-04-18 00:58:37

## 阻塞点
- 聚合包围框如果直接依赖实时 `nodes` 集合现算，就会跟随选中态、拖拽态等所有节点变化一起进入重建链。结果是：框选完成后包围框容易意外消失，拖拽时还会把大面积装饰节点持续带进热路径，明显放大卡顿。

## 解决方法
- 把包围框节点单独维护成独立状态，不再在 `displayNodes` 中每次都直接用实时 `nodes` 现算。
- 只在“聚合结构变化”或“节点位置变化”后同步包围框；纯选中态变化只更新真实节点，不触碰包围框节点。
- 节点拖拽和选中组拖拽期间临时隐藏包围框，结束后再按最终位置恢复，避免装饰层持续进入拖拽热路径。

## 复用建议
- 命中 ReactFlow、拓扑图或白板类界面时，凡是“包围盒 / 分组底板 / 高亮块”这类装饰节点，都应优先脱离业务节点的高频状态链。
- 如果一个装饰节点只表达布局或分组关系，就尽量只订阅“结构变化”和“位置变化”，不要跟随 `selected`、hover、批量编辑状态一起更新。
