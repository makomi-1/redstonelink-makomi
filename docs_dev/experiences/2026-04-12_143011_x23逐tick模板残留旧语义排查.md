# 阻塞点

这轮事件信号回归里，`functional-mixed-combinations-direct-debug` 的 x23 在实现已按设计收口后仍然失败，阻塞点不是代码继续回归，而是逐 tick 模板还保留了旧的 `pulse` 回落语义。

# 现象

- 首次失败只剩 `combo_pt_target_ticks` 和 `combo_spt_target_ticks` 两条断言，对应的 case 定义都在 x23 组合逐 tick 校验里。[mixed_samechunk_direct_combinations_tick_assert.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x23/mixed_samechunk_direct_combinations_tick_assert.json#L471) [mixed_samechunk_direct_combinations_tick_assert.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x23/mixed_samechunk_direct_combinations_tick_assert.json#L550)
- 实际观测表明 later `toggle` 会立刻对当前亮态取反，并不会在 `pulse` 回落后恢复旧 `toggle`；但模板函数还在期待“第二段 pulse 结束后继续亮”。[Bench.FunctionalTrace.Expectations.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.Expectations.ps1#L349) [Bench.FunctionalTrace.Expectations.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.Expectations.ps1#L374)

# 原因

- 这次失败属于“观测模板残留旧语义”，不是“实现与设计不符”。实现侧已经明确采用“事件同域互相覆盖、`pulse` 高于同 tick `toggle`、更晚 `toggle` 直接翻当前目标状态、同 tick 或更晚 `sync` 清事件持久化”的规则。
- x23 的 `PT` / `SPT` expectation builder 没跟随新语义同步，仍把旧的 `toggle fallback` 当成回落候选，于是游戏内逐 tick 断言和内部实现设计产生了错位。

# 解决方法

- 先用内部单测和实现代码确认语义，再去改 bench 模板，而不是根据实测去反向塑造实现。
- 把 `Build-MixedDirectPulseToggleRelativeTraceExpectations` 和 `Build-MixedDirectSyncPulseToggleRelativeTraceExpectations` 的尾样本改成新语义：later `toggle` 只保留对“当前结果态”的翻转，不再回露旧 `toggle`。[Bench.FunctionalTrace.Expectations.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.Expectations.ps1#L349) [Bench.FunctionalTrace.Expectations.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.Expectations.ps1#L374)

# 复用建议

- 游戏内自动化测试失败时，先把问题归类到“实现缺陷 / 模板错误 / 观测口径偏差”三层之一，再决定修哪里，避免直接拿实测波形去定义新语义。
- 凡是组合逐 tick 模板依赖相对序列推导的 case，改信号模型后都应优先复查 expectation builder，而不是只盯 case JSON；因为多个断言点可能共享同一个模板函数。
