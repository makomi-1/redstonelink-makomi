# 单测中注册表侵入式持有器导致物品构造失败

## 阻塞点
- 在纯 JUnit 环境里直接引用 `ModItems.SMART_GLASSES`，会触发 `ModItems` 静态初始化。
- 当前物品注册路径会在类加载阶段构造新的 `Item`，但测试环境下对应注册表并未处于允许创建 intrusive holder 的阶段，因此抛出：
  - `IllegalStateException: This registry can't create intrusive holders`

## 解决方法
- 不在这类轻量单测里直接依赖 `ModItems` 单例物品。
- 将“是否是智能眼镜”的识别从“注册表单例相等”改为“`instanceof SmartGlassesItem` 类型判定”。
- 测试侧复用 `Items.STONE` 作为基础 `ItemStack`，再通过 `Unsafe.allocateInstance(SmartGlassesItem.class)` + 反射替换 `ItemStack.item` 字段，构造最小可用替身。
- 若后续只需要验证“物品类型门槛”而不需要完整注册链，优先沿用该模式，避免把测试耦合到模组物品注册生命周期。
