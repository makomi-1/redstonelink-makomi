# 客户端炉界面映射差异处理

生成时间：2026-05-04 00:16:28
文件名：2026-05-04_001628_客户端炉界面映射差异处理.md

## 阻塞点

在给无线化转化器补客户端界面时，最初尝试直接复用 `AbstractFurnaceScreen` 的 recipe-book 参数构造方式，但当前工作区的编译映射与本地 `javap` 反查出来的类名并不完全一致，导致 `SearchRecipeBookCategory / RecipeBookCategories / RecipeBookComponent.TabInfo` 的导入与编译结果不稳定，`compileClientJava` 首轮失败。

相关落点：
- 失败入口最初在 [WirelessConverterScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/WirelessConverterScreen.java#L17)
- 最终稳定接线点在 [RedstoneLinkClient.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/RedstoneLinkClient.java#L186)

## 解决方法

先不把问题继续放大到 recipe-book 分类映射层，而是把转化器 screen 降级成“纯炉式容器界面”：
- 直接继承 `AbstractContainerScreen`，复用原版炉贴图绘制背景。[WirelessConverterScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/WirelessConverterScreen.java#L17)
- 菜单层继续保留 `AbstractFurnaceMenu`，并覆写 `isFuel` 把燃料缩窄到连接原件，确保功能语义不丢。[WirelessConverterMenu.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/menu/WirelessConverterMenu.java#L16) [WirelessConverterMenu.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/menu/WirelessConverterMenu.java#L34)

这样处理后：
- 服务端配方、漏斗、燃烧、菜单逻辑全部可用；
- 客户端少了 recipe-book 辅助，但不影响无线化转化器的核心使用闭环；
- 编译与测试恢复稳定。

## 复用建议

- 遇到“本地反查类名”和“当前编译映射实际可见类名”不一致时，优先先保功能闭环，再决定是否继续追 recipe-book、分类页、特效层等外围增强。
- 对炉式机器这类功能，screen 可以先走最小静态容器界面，后续再按版本稳定性补 recipe-book。
- 这条经验建议后续整理进 `docs_dev/经验总结.md`，作为“客户端映射差异的降级处理策略”。
