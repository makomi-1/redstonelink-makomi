# 26.1 渲染管线片段适配

## 阻塞点

在 26.1 客户端渲染迁移中，新增穿墙几何管线时直接把 `RenderPipelines.LINES` / `RenderPipelines.DEBUG_QUADS` 作为 `RenderPipeline.builder(...)` 的入参，`compileClientJava` 报错提示 builder 仅接收 `Snippet[]`，不能接收现成 `RenderPipeline`。

## 定位方式

1. 先通过 `compileClientJava` 收敛到精确报错，确认失败点位于新建的穿墙渲染支撑类。
2. 再用本机 `javap` 读取 26.1 本地缓存类签名，确认 `RenderPipeline.builder` 的真实签名为 `builder(Snippet...)`。
3. 同步检查 `RenderPipelines` 可用片段常量，确认 26.1 仍暴露 `LINES_SNIPPET` 与 `DEBUG_FILLED_SNIPPET` 可直接复用。

## 解决方法

- 线段穿墙管线改为基于 `RenderPipelines.LINES_SNIPPET` 构建。
- 面层穿墙管线改为基于 `RenderPipelines.DEBUG_FILLED_SNIPPET` 构建，并保留 `withCull(false)` 与 `DepthStencilState(CompareOp.ALWAYS_PASS, false)`。
- 这样既保留了 1.21.11 的“穿墙可见”语义，也与 26.1 当前客户端渲染底座完全对齐。

- [SeeThroughWorldGeometryRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/render/SeeThroughWorldGeometryRenderSupport.java#L47)

## 复用提醒

- 后续凡是从 1.21.11 同步自定义 `RenderPipeline` 时，先核对目标版本是“传 `Snippet` 组装”还是“直接复用现成 pipeline”。
- 只要新分支首次接入自定义渲染管线，优先先跑一次 `compileClientJava`，再决定是否需要继续深挖 `javap`/本地 jar 签名。
