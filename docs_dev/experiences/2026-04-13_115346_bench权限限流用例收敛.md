# bench权限限流用例收敛

## 阻塞点
- 直接按 `functional-matrix.json` 用 `CaseIds` 单跑 `C08` 时，不会带上 `server-basic-permission` suite 中的 `serverConfigOverrides`，结果就是服务端实际仍处于 `server.command.rateLimit.enabled=false` 的默认环境，限流断言天然不会成立。[server-basic-permission.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/suites/server-basic-permission.json#L27) [BenchSuite.EntryPoint.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/BenchSuite.EntryPoint.ps1#L175) [BenchSuite.EntryPoint.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/BenchSuite.EntryPoint.ps1#L223)
- `node alias set` 这类命令虽然业务上已经 `sendFailure + return 0`，但 bench 的 failure heuristic 没有覆盖对应文案时，`command_assert.expectFailureResponse=true` 仍会报 `expected_failure_missing`，看起来像实现没拒绝，实际上是 bench 识别漏了。[Bench.Rcon.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.Rcon.ps1#L119) [Bench.FunctionalTrace.Common.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.Common.ps1#L463)

## 解决方法
- 权限/限流类 functional case 优先通过 suite entry 跑，不要直接拿 matrix case id 代替；如果确实要单跑，就必须显式补齐 suite 里的 `serverConfigOverrides`，否则结论不可信。[server-basic-permission.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/suites/server-basic-permission.json#L27)
- 给 bench failure classifier 补充命令失败文案模式时，要同时更新 `Test-BenchResponseLooksLikeFailure` 和 `Test-FunctionalCommandAssertHardFailure` 两处，否则 drive 路径和 functional trace 路径会出现判定不一致。[Bench.Rcon.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.Rcon.ps1#L119) [Bench.FunctionalTrace.Common.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.Common.ps1#L463)
