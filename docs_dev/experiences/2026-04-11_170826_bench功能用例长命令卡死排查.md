# bench功能用例长命令卡死排查

生成时间：2026-04-11 17:08:26
文件名：2026-04-11_170826_bench功能用例长命令卡死排查.md

## 阻塞点

- `1024 -> 1024` 的 dedicated functional case 首次长时间卡住，经排查发现 bench 结构化连线并未支持 `zip`，导致脚本回退成 1024 条经典 `link set` 命令，前置建链阶段就被明显拉长。
- 在补齐 `zip` 之后，用例仍会在第一批 `setblock` 之后卡住；进一步定位发现问题已从建链转移到超长 `data merge block {serialExpression:...}` 命令，表现为 dedicated server 侧 RCON client 直接断开，suite 外层迟迟不收口。

## 解决方法

- bench 侧需要同时补齐 Java 命令注册、映射应用和 PowerShell 结构化下发三处 `zip` 支持，确保 `zip` 真正走结构化单命令路径，而不是脚本层静默回退。
- 对“验证过滤器拦截是否生效”的 functional case，不要继续复用超长枚举串；优先改成更短但语义可验证的节点集表达，例如本轮采用的连续对称区间 `1:4/29:32/993:996/1021:1024`。把“拦截语义验证”和“输入长度/RCON 极限压力”拆成两类 case，避免一个问题修完后另一个问题还在掩盖根因。
