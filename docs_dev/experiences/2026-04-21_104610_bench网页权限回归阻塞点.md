# bench 网页权限回归阻塞点

## 阻塞点 1：bench 摘要型拒绝响应不等于 functional runner 里的“失败响应”

- 现象：
  - `g02_graph_web_permission_gate_basic` 中，低权限 graph export/preview/save 已经返回 `outcome=rejected reason=permission_denied`，但 case 仍被判失败。
- 原因：
  - `bench graph` 返回的是稳定摘要文本，runner 会把它当作普通命令响应；`expectFailureResponse=true` 适合原版命令报错口径，不适合这种“业务拒绝但协议仍返回稳定 summary”的 bench 输出。
- 处理：
  - 去掉 `g02/g03` 里这类步骤的 `expectFailureResponse=true`，只保留 `expectedPrefix + expectedRegexes` 去断言 `outcome/reason`。
- 落地位置：
  - [graph_web_permission_gate_basic.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/g02/graph_web_permission_gate_basic.json#L79)
  - [recording_web_permission_gate_basic.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/g03/recording_web_permission_gate_basic.json#L47)

## 阻塞点 2：recording bench start 默认空选区会被服务端按“未选择节点”拒绝

- 现象：
  - `g03_recording_web_permission_gate_basic` 在高权限下已经成功准备状态面板订阅，但 `bench recording start` 仍返回 `reason=no_selection`。
- 原因：
  - `StatePanelRecordingSessionService.start` 依赖 `selectedNodeKeys` 过滤订阅；bench 入口最初传的是空列表，等价于“显式没选任何节点”，而不是“选中全部订阅”。
- 处理：
  - 在 `BenchRecordingCommandRegistry` 中，从当前主手状态面板读取订阅并折算出 `selectedNodeKeys`，让 automated bench 语义对齐到“准备完订阅后默认录制全部订阅”。
- 落地位置：
  - [BenchRecordingCommandRegistry.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/bench/BenchRecordingCommandRegistry.java#L112)
  - [BenchRecordingCommandRegistry.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/bench/BenchRecordingCommandRegistry.java#L188)
  - [StatePanelRecordingSessionService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/StatePanelRecordingSessionService.java#L115)

## 可复用结论

- 以后新增 bench 命令时，如果返回的是“机器可读 summary”，functional case 优先断言 `outcome/reason`，不要先假定它必须表现成原版命令失败包。
- 以后给 GUI / web 功能补 dedicated server 自动化时，要先核对“前端默认态”在 bench 命令里是否被显式补齐；尤其是选区、草稿、默认勾选项这类隐式上下文。
