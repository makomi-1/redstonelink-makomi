# 补充过滤器运行期四类覆盖并跑通新增用例

## 1. 功能与语义、架构设计

本轮新增了两条过滤器运行期 functional case：send 侧 `x27` 聚焦物理范围、`neighbor_max_input` 非零低态与 `fixed_input lower_bound` 重配置；receive 侧 `x28` 在此基础上补入节点集 blocklist 覆盖，并通过 matrix / suite 接入 targeted 回归入口。关键入口分别见 [x27](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x27/send_filter_runtime_scope_nodeset_matrix.json#L2)、[x28](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x28/receive_filter_runtime_scope_nodeset_matrix.json#L2)、[functional-matrix.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/functional-matrix.json#L57) 与 [regression-core.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/suites/regression-core.json#L72)。

语义上，`x27` 用“范围内高强度被挡、范围外同强度放行”验证 send 过滤器正方体半径裁剪，并用 `neighbor_max_input` 的 `15 -> 非零低态 -> 15` 验证运行期失效/补发；`x28` 通过 core 串号 blocklist 验证 receive 节点集只影响命中目标，同时复用相同的范围与失效/补发断言。相关相位可见 [x27](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x27/send_filter_runtime_scope_nodeset_matrix.json#L91)、[x27](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x27/send_filter_runtime_scope_nodeset_matrix.json#L227)、[x28](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x28/receive_filter_runtime_scope_nodeset_matrix.json#L69)、[x28](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x28/receive_filter_runtime_scope_nodeset_matrix.json#L153)。

## 2. 关键数据结构和算法性能分析

两条新 case 都继续复用 bench 现有 phase 模板和 `command_assert + input_start_custom + trace_latest_assert` 组合，没有新增 bench 内部命令，也没有引入新的解析层分支，因此运行时复杂度基本仍由单 case 相位数线性决定。send / receive 两条 case 的相位长度分别集中在 [x27](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x27/send_filter_runtime_scope_nodeset_matrix.json#L62) 和 [x28](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x28/receive_filter_runtime_scope_nodeset_matrix.json#L31)。

为避免 `data merge block` 改配置后运行态真值未刷新，本轮把“配置切换后补一次真实邻居变化”固定为测试模板动作，这一策略在常数成本内换取了可重复性，避免把不稳定口径压到业务实现上。对应刷新相位见 [x27](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x27/send_filter_runtime_scope_nodeset_matrix.json#L101)、[x27](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x27/send_filter_runtime_scope_nodeset_matrix.json#L238)、[x28](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x28/receive_filter_runtime_scope_nodeset_matrix.json#L79)、[x28](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x28/receive_filter_runtime_scope_nodeset_matrix.json#L252)。

## 3. 数据流或调用链

测试调用链保持为：bench 通过 matrix 解析 case，suite 通过 entryId 选中矩阵 case，再由 functional phase 顺序执行世界搭建、过滤器配置、输入注入与 trace 断言。入口注册见 [functional-matrix.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/functional-matrix.json#L57) 与 [regression-core.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/suites/regression-core.json#L72)。

每个 case 内部的数据流则是：放置过滤器和邻居支撑块，先用 `data merge block` 写配置，再通过邻居掉电/复电触发持久化真值刷新，随后用 `input start triggerSource custom` 注入固定强度，最后用 trace 读取 core 最新样本做逐点断言。send 侧完整链可见 [x27](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x27/send_filter_runtime_scope_nodeset_matrix.json#L68)、[x27](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x27/send_filter_runtime_scope_nodeset_matrix.json#L119)、[x27](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x27/send_filter_runtime_scope_nodeset_matrix.json#L270)；receive 侧对应链路见 [x28](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x28/receive_filter_runtime_scope_nodeset_matrix.json#L33)、[x28](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x28/receive_filter_runtime_scope_nodeset_matrix.json#L97)、[x28](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x28/receive_filter_runtime_scope_nodeset_matrix.json#L178)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

安全与兼容性方面，本轮只改 bench 测试资产，没有新增业务实现、没有改存档结构、没有引入 `com.makomi.api.v1.*` 依赖，语义仍维持 `triggerSource/core` 单向派发基线。接线层变化仅体现在 [functional-matrix.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/functional-matrix.json#L57) 与 [regression-core.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/suites/regression-core.json#L72)。

残余风险主要有两个。第一，`neighbor_max_input` 的“非零低态”当前仍依赖 `redstone_wire[power=n]` 的场景搭建，后续若世界更新口径变化，可能需要改为更稳定的小线路供电。第二，`data merge block` 配置切换后的刷新依赖测试中显式补一次邻居变化，若未来 bench 新 case 复用过滤器模板但遗漏这一动作，仍可能出现“配置已写入但 SavedData 未刷新”的假失败。可参考 [x27](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x27/send_filter_runtime_scope_nodeset_matrix.json#L102) 和 [x28](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x28/receive_filter_runtime_scope_nodeset_matrix.json#L80) 的刷新写法复用。

## 5. 并发冲突审查

本轮没有改多线程业务代码，也没有引入新的共享状态写入点；主要并发边界仍在 dedicated suite 逐 case 启停服务端和世界隔离上。新增 case 通过独立 world 名和 suite entry 顺序执行，避免同一世界内并发改同一过滤器块或 trace 挂载。相关串行入口见 [regression-core.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/suites/regression-core.json#L72)。

风险等级评估为低。需要注意的并发型问题不是线程竞争，而是“同一 case 内配置切换与观测时序竞争”，本轮已通过 `wait_ticks` 和邻居刷新相位显式拉开。send / receive 两条 case 中的相位隔离分别见 [x27](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x27/send_filter_runtime_scope_nodeset_matrix.json#L233) 与 [x28](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x28/receive_filter_runtime_scope_nodeset_matrix.json#L247)。
