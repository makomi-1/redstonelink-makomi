# graph包围框拖拽卡顿与框选后消失修复

## 1. 功能与语义、架构设计（关键方法和入口）

本轮修复只作用于 graph 前端视图层，不改 `triggerSource/core` 真值、snapshot、draft 和服务端保存语义。核心设计是把展开块包围框从 `displayNodes` 的实时现算链路拆出来，单独维护 `aggregateOutlineNodes` 状态；同时在节点拖拽和选中组拖拽期间临时隐藏包围框，结束后再按最终位置恢复。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L218) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1588) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1722) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2091) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2734)

这样做把包围框的职责重新限定为“表达展开块边界”，而不是跟随所有节点 UI 状态一起重建。对应地，框选完成后真实节点的选中态仍然可以更新，但包围框不会因为纯选中态变化而被误删；拖拽热路径中也不再持续重绘这个大面积装饰层。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1839) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2098)

## 2. 关键数据结构和算法性能分析

新增的数据结构很轻：一份 `aggregateOutlineNodes` 状态缓存当前包围框节点，一份 `aggregateOutlineSuspended` 布尔状态控制拖拽期间是否显示，再加一个 `aggregateOutlineSuspendDepthRef` 处理节点拖拽和选中组拖拽事件可能的重叠。这些状态都只服务于前端装饰层，不影响 graph 真值。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1588) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1595)

性能上，`sameAggregateOutlineFlowNodes` 只比较包围框节点的 `id / position / width / height`，让包围框在纯选中态变化时不再重复提交到 ReactFlow。拖拽期间直接暂停包围框渲染，再配合更轻的 CSS 样式，避免了大面积渐变与阴影在拖拽时持续参与重绘。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L218) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1843) [app.css](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L944)

## 3. 数据流或调用链

修复后的链路是：graph 结构与位置更新后，通过 `buildAggregateOutlineFlowNodes` 计算包围框节点；`useEffect` 仅在未挂起包围框渲染时同步到 `aggregateOutlineNodes`；`displayNodes` 再根据 `aggregateOutlineSuspended` 决定是否把包围框并入 ReactFlow 的节点列表。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L166) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1722) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1839)

交互层面，`onNodeDragStart/onNodeDragStop` 和 `onSelectionDragStart/onSelectionDragStop` 分别接入包围框挂起/恢复逻辑。这样无论是单节点拖拽还是选中组拖拽，包围框都会先退出热路径，拖拽结束后再按最终位置恢复。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2091) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2736)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

安全和语义层面，本轮没有新增 API 依赖，没有改持久化结构，没有改 `triggerSource -> core` 真实保存边界，符合项目当前语义约束。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2112)

兼容性风险主要在 ReactFlow 事件时序：当前实现假定 `onNodeDragStart/Stop` 与 `onSelectionDragStart/Stop` 会成对触发，因此用深度计数防止重叠事件提前恢复。若后续升级 ReactFlow，应优先复核拖拽开始/结束事件是否仍成对触发。样式层面，本轮把包围框简化为轻边框和浅背景，视觉稍微保守，但能明显降低重绘压力，属于刻意的性能取舍。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2091) [app.css](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L944)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

前端仍运行在 React 单线程事件循环，没有引入新的跨线程共享状态。本轮主要解决的是“真实节点选中态更新”和“装饰层包围框重建”之间的读改写覆盖：过去两者耦合在同一个 `nodes` 更新链里，导致框选后包围框可能消失；现在改为真实节点和装饰层分别维护，各自按不同触发条件更新，风险等级从中降到低。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1586) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1839) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2098)

后续如果继续增加“装饰层标签”“聚合块标题背景板”这类附属节点，建议延续当前做法：装饰层单独缓存、只订阅结构和位置变化、必要时在高频交互期间临时挂起，避免再次把展示层节点耦合回业务节点的热路径。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1722) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1839)
