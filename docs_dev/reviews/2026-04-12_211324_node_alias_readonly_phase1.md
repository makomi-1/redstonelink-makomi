## 2. 关键数据结构和算法性能分析
- 别名持久化继续使用两组双向 `HashMap` 维护 `(type, serial) -> alias` 与 `(type, alias) -> serial`，平均查询/更新复杂度保持 O(1)，不会把别名读取引入到现有拓扑索引热点中；见 [NodeAliasSavedData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/NodeAliasSavedData.java#L40)、[NodeAliasSavedData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/NodeAliasSavedData.java#L41)、[NodeAliasSavedData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/NodeAliasSavedData.java#L143)。
- 反查别名时采用“按类型桶直接命中 + 跨类型最多两次追加”的方式，而不是遍历全部节点，因此 `resolveAllByAlias` 的额外成本固定且很小；见 [NodeAliasSavedData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/NodeAliasSavedData.java#L100)。
- GUI 网络层只增加一个短字符串字段 `displayText` / `sourceDisplayText`，编码仍是线性扫描，不会改变 payload 的数量级；见 [PairingNetworkPayloadSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkPayloadSupport.java#L39)、[PairingNetworkPayloadSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkPayloadSupport.java#L71)、[StatePanelNetworkPayloadSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/StatePanelNetworkPayloadSupport.java#L25)、[StatePanelNetworkPayloadSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/StatePanelNetworkPayloadSupport.java#L88)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议
- 别名唯一性当前仍是“同类型内唯一”，因此同名 alias 可以同时落在 `triggerSource` 和 `core` 两侧；这符合当前 `resolve <alias>` 的多命中设计，但如果未来需要全局唯一，必须升级索引规则和冲突反馈；见 [NodeAliasSavedData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/NodeAliasSavedData.java#L40)、[NodeAliasSavedData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/NodeAliasSavedData.java#L100)、[NodeAliasSavedData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/NodeAliasSavedData.java#L143)。
- 状态面板对不可读节点只回退显示 `#序号`，不外显 alias，这与“别名受读控制约束”保持一致；若后续希望连序号也隐藏，需要单独改订阅展示语义，而不是直接改 alias 层；见 [StatePanelNetwork.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/StatePanelNetwork.java#L275)、[StatePanelNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/StatePanelNetworkServerHandlerSupport.java#L275)、[StatePanelNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/StatePanelNetworkServerHandlerSupport.java#L401)。
- 物品 tooltip 现已覆盖在线玩家背包同步和主要节点掉落物生成，但仍未主动遍历箱子、漏斗、离线玩家等非在线库存容器；若以后要求“所有物品栈 alias 实时一致”，建议单独设计容器级刷新策略，避免把别名同步做成全局扫描热点；见 [NodeAliasServerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/NodeAliasServerSupport.java#L74)、[LinkButtonBlock.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/LinkButtonBlock.java#L92)、[LinkCoreBlock.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/LinkCoreBlock.java#L104)。
- 配对 GUI 与状态面板都只改了“节点自身序号字段”，当前连接列表、目标列表仍保持纯序号。这个范围控制是刻意的；若后续要扩到列表展示，需要先定义“列表里 alias 冲突、排序、截断”的稳定规则；见 [AbstractMultiPairingScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/AbstractMultiPairingScreen.java#L253)、[StatePanelToolScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/StatePanelToolScreen.java#L424)。

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）
- `NodeAliasSavedData` 使用普通 `HashMap`，没有额外锁；在当前 Fabric 服务端主线程命令/保存模型下风险较低，但不适合未来直接搬到异步任务里使用；见 [NodeAliasSavedData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/NodeAliasSavedData.java#L40)、[NodeAliasSavedData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/NodeAliasSavedData.java#L143)。
- 在线物品 alias 同步会遍历在线玩家背包并触发 `broadcastChanges()`，当前发生在 alias 命令写入后、服务端主线程内，属于可接受的短临界区；若未来别名批量改名，应考虑合并广播，避免对同一玩家反复触发菜单刷新；见 [NodeAliasServerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/NodeAliasServerSupport.java#L74)、[NodeAliasServerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/NodeAliasServerSupport.java#L86)。
- 客户端侧新增 payload 仍使用 record + `List.copyOf(...)` 冻结消息体，避免网络线程与渲染线程共享可变集合；这使得本轮扩展 display text 后没有额外引入可变共享状态；见 [PairingNetwork.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetwork.java#L196)、[PairingNetwork.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetwork.java#L242)、[StatePanelNetwork.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/StatePanelNetwork.java#L54)、[StatePanelNetwork.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/StatePanelNetwork.java#L191)。
- 综上，本轮并发风险等级评估为“低”。建议继续保持“别名写入仅服务端命令入口、客户端只读展示”的边界，不要把 alias 解析下沉到异步批处理或客户端本地写逻辑中。
