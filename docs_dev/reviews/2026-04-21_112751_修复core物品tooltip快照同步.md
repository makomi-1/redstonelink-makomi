## 1. 功能与语义、架构设计（关键方法和入口）

- 本次修复没有改拓扑真值写入层，而是补在“写入后的统一快照同步层”：单条写入路径在 `registerPostWriteSync(...)` 中，除了继续同步在线节点与真实来源 `triggerSource` 物品外，新增了对受影响 `core` 物品快照的刷新，避免背包 tooltip 继续显示旧链接集合。[LinkSetExecutionService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkSetExecutionService.java#L519)
- 玩家物品快照同步入口统一收敛到 `syncPlayerItemLinkSnapshots(...)`，它会扫描主背包、副手、盔甲栏和当前拖拽物品，并只在实际发生变更时广播一次容器更新，减少重复广播导致的界面抖动。[LinkCommandSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkCommandSupport.java#L154)
- 批量写入路径通过 `BatchLinkSnapshotSyncCollector.collectPreparedReplace(...)` 同时登记真实来源 `triggerSource` 与受影响 `core` 的物品快照刷新请求，再在 `flush()` 中按 `(player, nodeType)` 分组批量执行，保证批量替换场景与单条写入场景语义一致。[LinkCommandSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkCommandSupport.java#L328) [LinkCommandSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkCommandSupport.java#L412)
- 语义对齐结果：内部命名与文案继续使用 `triggerSource/core`，写入方向仍是 `triggerSource -> core`，这次仅补“受影响 core 物品快照”的回写，不引入反向拓扑写入，残余语义风险为无。[LinkSetExecutionService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkSetExecutionService.java#L536)

## 2. 关键数据结构和算法性能分析

- 受影响序号先经 `normalizePositiveSerials(...)` 做“正数过滤 + 去重”，避免空值、重复值和非法序号把后续背包扫描放大；该步骤时间复杂度为 `O(k)`，`k` 为待同步序号数。[LinkCommandSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkCommandSupport.java#L275)
- 背包刷新主体为 `syncPlayerInventoryLinkSnapshots(...)` 和 `syncItemListLinkSnapshots(...)`，本质是对有限槽位做线性扫描，复杂度约为 `O(n)`，`n` 为玩家当前四段容器总槽位数；由于扫描范围固定且只在写后触发，开销稳定可控。[LinkCommandSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkCommandSupport.java#L194) [LinkCommandSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkCommandSupport.java#L218)
- `matchesNodeItem(...)` 额外限制“单序号物品 + 指定节点类型 + 命中序号集合”，因此不会误刷聚合栈，也不会把其他普通物品卷入回写；这是本次修复能保持最小影响面的关键过滤器。[LinkCommandSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkCommandSupport.java#L254)
- 批量 collector 在 `flush()` 前使用 `Set` 去重请求、`LinkedHashMap` 归并 `(player, nodeType)`，从“每个序号一次广播”收敛到“每个玩家每种类型一次广播”，避免批量替换下广播次数随目标数量线性膨胀。[LinkCommandSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkCommandSupport.java#L398) [LinkCommandSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkCommandSupport.java#L418)

## 3. 数据流或调用链

- 单条写入调用链：`registerPostWriteSync(...)` -> `syncAffectedNodeLinkSnapshots(...)` -> `syncAffectedPlayerItemLinkSnapshots(...)` -> `syncPlayerItemLinkSnapshots(...)` -> `syncPlayerInventoryLinkSnapshots(...)` -> `syncItemListLinkSnapshots(...)` / `syncSingleItemLinkSnapshot(...)` -> `LinkItemData.syncCurrentLinksSnapshotIfSingle(...)`。这条链补上了此前缺失的 `core` 物品快照刷新分支。[LinkSetExecutionService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkSetExecutionService.java#L519) [LinkCommandSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkCommandSupport.java#L172) [LinkCommandSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkCommandSupport.java#L237)
- 批量写入调用链：`collectPreparedReplace(...)` 先累计“在线节点同步请求 + 玩家物品快照请求”，随后 `flush()` 分别处理在线节点同步与按组归并后的玩家物品刷新；因此批量路径与单条路径最终汇聚到同一套玩家背包刷新逻辑，不再出现“在线节点同步了、背包 core tooltip 没同步”的视角差异。[LinkCommandSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkCommandSupport.java#L328) [LinkCommandSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkCommandSupport.java#L412)
- 回归验证数据流由两个测试覆盖：一个直接验证命中 `core` 序号时 tooltip 快照会刷新，另一个验证 collector 会同时登记 `triggerSource` 与受影响 `core` 序号，确保单路径和批路径都落在本次修复面内。[LinkCommandSupportTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/command/link/LinkCommandSupportTest.java#L53) [LinkCommandSupportTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/command/link/LinkCommandSupportTest.java#L86)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全性：本次改动只发生在服务端命令写后同步与服务端玩家背包遍历，不新增网络入口、权限放宽或外部 API 依赖，符合当前“业务实现层不依赖 `com.makomi.api.v1.*`”约束。[LinkSetExecutionService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkSetExecutionService.java#L519)
- 兼容性：`matchesNodeItem(...)` 目前明确跳过聚合序号物品，因此本次修复覆盖的是“单件 core 物品 tooltip 快照”；若未来需要让聚合栈也展示实时拓扑快照，需要单独设计聚合态展示规则，不能直接复用当前单件逻辑。[LinkCommandSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkCommandSupport.java#L262)
- 性能：玩家背包刷新仍是命中后即时扫描，若未来要支持一次命令影响超大玩家集合，建议再往上增加“玩家范围裁剪”或更细粒度槽位索引；在当前“单玩家命令提交后同步自己物品”的语境下，现有复杂度足够低。[LinkCommandSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkCommandSupport.java#L194)
- 测试兼容性：Minecraft 1.21 测试环境下直接 `new Item(...)` / `new Block(...)` 会撞上 intrusive holder 限制，因此测试夹具改为“复用 `Items.STONE` 栈底座 + 反射替换 `item` 视图”的方式，保证回归测试能稳定覆盖物品快照语义而不依赖注册表生命周期；后续同类测试可以复用这一手法。[LinkCommandSupportTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/command/link/LinkCommandSupportTest.java#L150) [LinkCommandSupportTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/command/link/LinkCommandSupportTest.java#L159) [LinkCommandSupportTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/command/link/LinkCommandSupportTest.java#L186)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- 共享状态：新增逻辑没有引入新的静态可变状态，`BatchLinkSnapshotSyncCollector` 的 `nodeSnapshotSyncRequests` / `playerItemSnapshotSyncRequests` 都是实例级、请求期集合，flush 后立即清空；当前共享状态风险等级为低。[LinkCommandSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkCommandSupport.java#L321) [LinkCommandSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkCommandSupport.java#L412)
- 读改写覆盖：`syncSingleItemLinkSnapshot(...)` 先读取旧 `linkedSerials`，再调用 `LinkItemData.syncCurrentLinksSnapshotIfSingle(...)` 回写最新快照，最后以新旧集合比较决定是否广播；这能避免“无变化也广播”，同时不会覆盖非命中物品的数据。[LinkCommandSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkCommandSupport.java#L237)
- 线程边界：当前调用源来自命令写入后的服务端逻辑，默认在主线程内执行；`HashSet` / `LinkedHashMap` 本身不具备并发保护，但在当前同步调用模型下没有并发访问证据。若未来要把 collector flush 下沉到异步任务，必须先改为线程隔离或并发容器。风险等级：低，建议仅在未来异步化时复审。[LinkSetExecutionService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkSetExecutionService.java#L519) [LinkCommandSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkCommandSupport.java#L418)
