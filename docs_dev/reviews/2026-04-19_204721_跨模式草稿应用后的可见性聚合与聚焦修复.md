## 1. 功能与语义、架构设计

- 本轮在 `GraphViewer` 中把“存量编辑上下文”和“当前编辑态生效选区”拆开，避免查看态继续被编辑选区强制撑开，入口在 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L315) 与 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L412)。
- 通过 `resolveContextFocusNodeKey` 统一“哪一类节点选得更多就优先聚焦哪一类”的规则，跨模式应用、切入编辑态和批量编辑都复用同一口径，见 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L139)。
- ReactFlow 受控选区增加“可见节点同步”层，只有编辑态的业务选区才会回写到画布 `selected` 状态，避免空选区事件反向清空业务选区，见 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L837) 与 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1482)。
- 切入编辑态时会主动触发一次结构重排和上下文聚焦，跨模式应用后也改为复用统一焦点决策，而不是直接使用临时选区首节点，见 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1772) 与 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1973)。

## 2. 关键数据结构和算法性能分析

- `sameStringArray` 用于稳定比较画布选区，避免只因数组引用变化造成重复同步，见 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L128)。
- `storedEditContextNodes` 与 `activeEditSourceNodeKeys/activeEditTargetNodeKeys` 采用派生缓存，避免在每次渲染时重复从大图节点集合做散乱判断，见 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L412) 与 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L428)。
- `desiredCanvasSelectionNodeKeys` 先按当前可见节点做过滤，再与当前 ReactFlow 选区比对后决定是否回写，避免“隐藏节点永远选不中”引起的死循环式状态更新，见 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L837)。
- `applyCanvasSelectedNodeKeys` 改为仅在实际选中态发生变化时返回新数组，降低无意义 `setNodes` 造成的额外渲染，见 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1482)。

## 3. 数据流或调用链

- 跨模式应用调用链为：选择另一模式节点 -> 生成草稿变更 -> 写入业务编辑上下文 -> 结构重排 -> 统一焦点聚焦，关键入口见 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1973)。
- 编辑模式切换调用链为：切换 `editMode` -> 如果进入编辑态则保留业务上下文并触发结构重排 -> 画布可见节点同步出受控选区，见 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1772) 与 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1087)。
- 查看态与编辑态的聚合差异由 `aggregateAutoExpandNodeKeys` 决定：查看态不再自动吃入残留编辑选区，编辑态才会把选区纳入可见/展开上下文，见 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L506)。
- 前端回归测试分别覆盖了“序号模式切入编辑态后节点不消失”和“频道查看态重新聚合”两条链路，见 [GraphViewer.test.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.test.tsx#L326) 与 [GraphViewer.test.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.test.tsx#L359)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全性：本轮只改前端状态同步与显示逻辑，没有新增后端写接口，也未改变 `triggerSource -> core` 方向语义；后端保存协议无变化。
- 性能：新增的选区同步 effect 只对当前可见节点执行比较与回写，复杂度与画布可见节点数线性相关，可接受；如果后续画布节点量显著增长，可以考虑把“可见选区节点键”进一步缓存到专用 hook 中。
- 兼容性：频道与序号两种模式继续复用同一套草稿与保存口径，没有引入新的连接模式分支；残余风险是后续若再加入新的显示模式，需要同步接入 `storedEditContextNodes` 和焦点决策函数。
- 扩展性：`resolveContextFocusNodeKey` 已被抽成独立函数，后续搜索、孤立节点池或更多编辑入口若需要统一聚焦规则，可直接复用，避免再次分叉。

## 5. 并发冲突审查

- 共享状态集中在 `graphDraft`、`selectedEditSourceSerials`、`selectedEditTargetSerials`、`selectedEditChannelNodeKeys` 与 `nodes`，都位于同一个 React 组件内部，没有跨线程共享，见 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L226) 与 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L244)。
- 最大的读改写覆盖风险来自 ReactFlow 选区回流覆盖业务选区；本轮通过“仅编辑态同步”“可见节点过滤”“无变化不回写”三层约束来压制该冲突，见 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L837)、[GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1087) 与 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1482)。
- 结构重排与聚焦之间的竞争由既有 `pendingStructureLayoutReset / pendingPostLayoutFocusNodeKey` 串行化处理，本轮只改焦点来源，没有新增并发入口，风险等级评估为“低”。
- 建议后续若继续扩展复杂编辑流，可以把“业务选区”“画布选区”“聚焦请求”收敛到统一 reducer，进一步减少状态分散带来的覆盖风险。
