## 1. 功能与语义、架构设计

- `RecordingPage` 复用 graph 页头部结构，把连接状态与分析器标识统一放到右上区域，避免录制页和图页在视觉层级上继续分叉，入口在 [RecordingPage.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app/RecordingPage.tsx#L40) 与 [RecordingPage.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app/RecordingPage.tsx#L50)。
- `GraphViewer` 新增 `crossMode` 侧栏页签，并把“另一模式节点池”纳入既有草稿流，而不是直接写后端；核心状态和候选集构建位于 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L219) 与 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L371)。
- 跨模式应用统一复用现有 `applyChannelEditToDraft` 草稿折算路径，没有新增后端接口；序号模式迁回 `serial` 仅恢复显式边编辑语义，频道模式则迁入当前频道号，入口在 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1888)。
- 侧栏类型定义扩展为 `"crossMode"`，保持详情、孤立节点池、批量编辑并列结构，避免在 `GraphViewer` 内继续堆叠条件分支，定义见 [types.ts](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/types.ts#L46)。

## 2. 关键数据结构和算法性能分析

- 跨模式节点池的候选集按当前显示模式从 `effectiveGraphBundle.nodes` 单次过滤并缓存，避免在渲染阶段多次扫描整图，位置见 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L371)。
- `mergeUniqueSortedNumbers` 与 `mergeUniqueSortedStrings` 统一负责跨模式应用后的去重和稳定排序，保证 UI 选区与草稿上下文可重复、可比较，位置见 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L104) 与 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L116)。
- `handleApplyCrossModeDraft` 只在点击“应用到草稿”时做一次折算，避免选择过程频繁重建草稿、触发布局与预检，减少了大图场景下的无效计算，见 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1888)。
- 当前复杂度仍主要受 `effectiveGraphBundle.nodes` 规模影响，候选池过滤和去重都是线性或线性对数级，对现有前端数据规模可接受；未引入额外的嵌套图遍历。

## 3. 数据流或调用链

- 图页数据流为：`graphBundle` 输入 -> `graphDraft` 叠加为 `effectiveGraphBundle` -> 生成跨模式候选节点池 -> 用户选择另一模式节点 -> `handleApplyCrossModeDraft` 写入本地草稿 -> 保存按钮继续走既有预检/保存链路，关键节点见 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L279)、[GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L371)、[GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1888)。
- 显示模式切换时会清空跨模式临时选择，防止旧模式残留选择污染新模式编辑上下文，见 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1671)。
- 录制页数据流保持不变，仅头部容器结构切换为 graph 页统一样式类；录制 bundle 仍直接传入 `RecordingViewer`，见 [RecordingPage.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app/RecordingPage.tsx#L40) 与 [RecordingPage.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app/RecordingPage.tsx#L128)。
- 回归测试覆盖了跨模式应用和录制页头部展示，分别见 [GraphViewer.test.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.test.tsx#L294) 与 [RecordingPage.test.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app/RecordingPage.test.tsx#L64)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全性：本轮未新增后端写接口，仍复用现有预检与保存流程，风险主要集中在前端草稿态误导；已通过明确提示“应用到草稿后再继续编辑”降低误用风险，见 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1922) 与 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1929)。
- 性能：候选池仍基于整图节点扫描；若未来节点量继续增长，可以考虑把 `serial/channel` 模式候选分桶缓存到 `graphBundle` 衍生层，但当前没有必要提前做。
- 兼容性：序号模式和频道模式都复用了既有 `channel` 折算逻辑，没有改写保存协议；残余风险是后续若新增第三种连接模式，需要同步补齐 `crossModeCandidateNodes` 的过滤口径。
- 扩展性：`GraphSidebarPanel` 已显式扩展为并列标签，后续若继续增加编辑池或分析面板，可沿同一结构扩展，不需要重写整个侧栏布局。

## 5. 并发冲突审查

- 共享状态主要是 `graphDraft`、`selectedCrossModeNodeKeys`、`selectedEditSourceSerials`、`selectedEditTargetSerials` 与 `selectedEditChannelNodeKeys`，它们都限定在 `GraphViewer` 组件内部，未跨线程共享，入口见 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L156) 与 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L219)。
- 读改写覆盖风险集中在“切模式”和“应用跨模式草稿”两条路径；当前通过切模式时清空临时选择、应用时统一一次性合并去重，降低了交错点击导致的局部覆盖概率，见 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1671) 与 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1888)。
- React 前端仍存在同一事件循环内的异步状态批处理，但本轮没有引入额外的并发副作用或外部订阅；风险等级评估为“低”。
- 建议后续若继续扩展跨模式编辑，再把“跨模式临时选择态”抽成独立 reducer，统一处理切模式、清空、应用、撤回四类动作，避免状态分散后出现遗漏。
