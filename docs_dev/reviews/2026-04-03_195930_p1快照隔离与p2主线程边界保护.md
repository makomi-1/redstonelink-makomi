## 1. 功能与语义、架构设计

- P1 将“按来源查询目标集合”的对外契约收敛为稳定快照，避免事件链继续持有内部可变 `Set` 视图；外部统一经由 `[LinkSavedData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedData.java#L285)` 暴露快照语义，内部无拷贝遍历仍保留在 `[LinkSavedDataLinkIndexSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataLinkIndexSupport.java#L184)`。
- 生命周期链路的三处消费入口已全部改为读取快照，再把结果传给内部 delta 事件，避免 attach/detach/replay 期间被后续写操作回写同一个集合实例，见 `[LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L241)`、[LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L259)、[LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L287)。
- P2 新增统一主线程 guard，把“必须在服务端主线程访问全局状态”的隐含约定显式化；guard 本体位于 `[ServerThreadGuard.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/ServerThreadGuard.java#L5)`，CrossChunk 关键入口接入见 `[CrossChunkDispatchService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CrossChunkDispatchService.java#L498)`、[CrossChunkDispatchService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CrossChunkDispatchService.java#L523)、[CrossChunkDispatchService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CrossChunkDispatchService.java#L617)、[CrossChunkDispatchService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CrossChunkDispatchService.java#L627)，Core scheduler 关键入口接入见 `[CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L112)`、[CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L155)、[CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L190)、[CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L210)、[CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L237)。
- 语义对齐：本轮仅处理 `triggerSource/core` 既有内部链路与线程边界，未新增旧术语输出，也未引入 `com.makomi.api.v1.*` 依赖；`LinkNodeType.TRIGGER_SOURCE/CORE` 映射保持不变，残余风险：无。

## 2. 关键数据结构和算法性能分析

- 链接索引底层仍维持 `buttonToCores/coreToButtons` 的双向 `HashMap<Long, Set<Long>>`，查询快照路径通过 `[LinkSavedDataLinkIndexSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataLinkIndexSupport.java#L175)` 委托到 `Set.copyOf(...)`，单次成本为 O(n)，但只落在对外查询与事件边界，避免把可变集合长时间暴露到后续链路。
- 热路径若只需内部遍历，仍可走 `[LinkSavedDataLinkIndexSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataLinkIndexSupport.java#L187)` 的无拷贝遍历；因此本轮没有把所有读取都强制变为全量复制，只在外泄边界做快照，属于定点止血而非全面重构。
- `ServerThreadGuard.requireServerThread(...)` 只做 `server == null` 和同线程探针两次 O(1) 判断，见 `[ServerThreadGuard.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/ServerThreadGuard.java#L23)`；对 CrossChunk 与 Core scheduler 的吞吐影响可以忽略，相比状态污染代价更低。
- 全局状态容器的数据结构未变化，仍沿用 `IdentityHashMap<MinecraftServer, ...>`；本轮只增加入口边界，不改变 resident/retry/batch 桶结构与调度算法，因此不引入新的状态放大风险，见 `[CrossChunkDispatchService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CrossChunkDispatchService.java#L627)` 与 `[CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L237)`。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全/一致性：主线程 guard 现在能在越界线程第一时间抛出异常，避免静默写坏 `STATE_BY_SERVER` 或 scheduler 桶状态，见 `[ServerThreadGuard.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/ServerThreadGuard.java#L23)`、[CrossChunkDispatchServiceTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/data/CrossChunkDispatchServiceTest.java#L60)、[CoreDispatchBatchSchedulerTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/data/CoreDispatchBatchSchedulerTest.java#L92)。建议未来若新增异步入口，统一先 `server.execute(...)` 回主线程，再触达这些服务。
- 性能：快照复制带来额外分配，但仅发生在事件链外泄边界；保留 `[LinkSavedDataLinkIndexSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataLinkIndexSupport.java#L187)` 的无拷贝遍历后，热路径仍可避免不必要复制，当前代价可接受。
- 兼容性：`server == null` 仍被 guard 放行，确保大量反射/纯单测不被误伤，见 `[ServerThreadGuard.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/ServerThreadGuard.java#L24)`；同时测试夹具通过覆写 probe 精准模拟越线程，不需要真实启动服务端，见 `[TestMinecraftServerFactory.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/data/TestMinecraftServerFactory.java#L14)`。
- 扩展性：本轮只给 CrossChunk 与 Core scheduler 加入口 guard，未把所有全局状态容器统一抽象成“线程边界基类/模板”；若后续类似状态容器增多，可考虑把 `ServerThreadGuard` 升级为更通用的 `server-thread` 约束组件，减少重复手写入口保护。当前残余风险：低。

## 5. 并发冲突审查

- 共享状态：`CrossChunkDispatchService.STATE_BY_SERVER` 与 `CoreDispatchBatchScheduler.STATE_BY_SERVER/LAST_COMPLETED_END_TICK_BY_SERVER` 是本轮主要共享状态；关键入口已在访问前先过 `[ServerThreadGuard.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/ServerThreadGuard.java#L23)`，对应接入点见 `[CrossChunkDispatchService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CrossChunkDispatchService.java#L498)`、[CrossChunkDispatchService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CrossChunkDispatchService.java#L627)、[CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L125)、[CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L238)。风险等级：由中降为低。
- 读改写覆盖：链接索引底层仍是普通 `HashSet`，但生命周期事件链已不再持有内部集合引用，读侧快照与写侧索引变更解耦，见 `[LinkSavedData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedData.java#L285)` 与 `[LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L241)`。风险等级：低。
- 重入/线程边界：Core scheduler 既有的 apply-phase 重入防护未被破坏，本轮只是把非主线程路径提前拦截，不改变原有 drain/flush 机制；关键 flush 入口见 `[CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L237)`。风险等级：低。
- 建议：若未来把 `LinkSavedData` 写入口开放给异步任务，仍需进一步统一“写入口回主线程”策略；本轮只解决了集合视图外泄与两类全局状态容器的显式线程边界，未把整个存档写模型事务化。当前残余风险：低，且范围已明确。
