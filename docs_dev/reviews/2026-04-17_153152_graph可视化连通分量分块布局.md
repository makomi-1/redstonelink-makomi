# Graph 可视化连通分量分块布局

## 1. 功能与语义、架构设计（关键方法和入口）

- 本轮把 Graph 自动布局从“全局两列”改为“连通分量分块 + 组件内 `triggerSource/core` 双层布局 + 多块流式铺排”。核心入口分别是连通分量拆分 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L210)、组件内布局 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L263) 和整图铺排 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L312)。
- 节点渲染与位置来源已解耦，`buildGraphFlowNodes(...)` 只负责把位置映射和样式状态组装成 ReactFlow 节点，避免再出现“单节点 fallback 无法感知全图拓扑”的问题 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L348)。
- 初次装载与手动“自动布局”都会走新的整体布局映射，分别位于初始化 effect [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L995) 和按钮处理函数 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1122)。

## 2. 关键数据结构和算法性能分析

- 新增的核心中间结构是 `Map<string, XYPosition>`，由 `autoLayoutPositions` 记忆化生成，供节点初始化、刷新和重排复用 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L873)。
- 算法分三层：先建无向邻接表，再做 BFS/连通分量拆分，最后按块排序与流式铺排；整体复杂度近似为 `O(V + E + V log V)`，其中排序主要来自稳定输出顺序 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L193) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L210) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L312)。
- 组件内布局没有引入 force layout 或迭代优化器，只使用固定列距、固定纵向间距与短列居中，因此性能稳定、结果可预测，也符合“简单好用优先”的目标 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L270)。

## 3. 数据流或调用链

- 现有图数据仍先由 `baseGraphBundle + graphDraft` 合成出 `effectiveGraphBundle`，再生成草稿差异 `draftDiff`，这个主链未变 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L865) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L869)。
- 在此基础上新增 `effectiveGraphBundle -> autoLayoutPositions -> buildGraphFlowNodes(...) -> ReactFlow nodes` 的布局链路，使位置计算完全依赖有效拓扑而不是局部节点 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L873) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1016)。
- 节点刷新时会先读取当前画布已有位置，再只把新样式和新节点替换进去，从而保留用户手动拖拽过的坐标；边集仍由 `buildEdges(...)` 按基线图与草稿差异生成 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L386) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1017)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 语义上没有改动写入协议、草稿结构和保存接口，仍然只围绕 `triggerSource -> core` 方向组织视图与编辑，因此不触碰服务端兼容边界 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L593) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1153)。
- 现布局对“多连通分量”场景收益最大；若未来出现“单个超大连通分量”且节点数继续提升，画布仍可能表现为单个高块，这时建议再补“组件内分组折叠”或“集合编辑侧栏”，而不是直接转向自由拉线 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L263)。
- 初始化 effect 保持只在首载和快照切换时重排，避免草稿变化时把用户当前视角和拖拽结果重置；这是本轮需要特别守住的兼容点 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L995)。

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- 共享状态主要是 `nodes`、`edges`、`graphDraft` 和 `selectedNodeKey`，都在 React 单线程事件循环内更新，没有新增跨线程共享对象，线程边界风险为低 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L851)。
- 节点刷新采用 `setNodes((currentNodes) => ...)` 函数式更新，先读取当前已有位置再合成新节点，降低了“布局状态被后续样式刷新覆盖”的读改写冲突风险 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1016)。
- 仍需注意的重入点是：如果未来把布局计算改成异步 worker 或远端请求，必须保证 `effectiveGraphBundle` 与 `autoLayoutPositions` 的版本一致；目前二者都在同一渲染周期内由 `useMemo` 同步生成，风险等级低，无额外修复项 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L865) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L873)。
