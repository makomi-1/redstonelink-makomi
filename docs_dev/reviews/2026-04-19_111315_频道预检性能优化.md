## 1. 功能与语义、架构设计（关键方法和入口）

- 本轮把频道批量预检从“每个 `triggerSource` 重建整批 override 解析环境”改成“整批只构建一次解析上下文，再复用到所有来源”，入口仍然保持在频道 prepare 阶段，没有改真实 apply 路径，也没有改 `triggerSource -> core` 真值语义。[LinkChannelEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkChannelEditingService.java#L70) [LinkChannelEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkChannelEditingService.java#L98)
- `LinkSavedDataChannelSupport` 新增批次级上下文构造与复用入口，把 overrides 索引和“频道最终 core 成员集合”缓存都收口到同一个 helper 里，保持推导逻辑仍然集中在数据查询层，不把性能细节散到上层服务里。[LinkSavedDataChannelSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataChannelSupport.java#L177) [LinkSavedDataChannelSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataChannelSupport.java#L204) [LinkSavedDataChannelSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataChannelSupport.java#L362)
- 单节点 override 推导与原有批量推导入口也改成走共享上下文版本，避免未来再次出现“单点入口优化了，批量入口没优化”或相反的漂移。[LinkSavedDataChannelSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataChannelSupport.java#L122) [LinkSavedDataChannelSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataChannelSupport.java#L154)

## 2. 关键数据结构和算法性能分析

- `BatchTargetResolutionContext` 是本轮核心数据结构，内部保存：
  - `overridesByNodeKey`
  - 只影响频道成员修正的 `coreOverrides`
  - `cachedChannelCoreTargetsByChannel`
  这样频道模式下多个 `triggerSource` 共用同一频道时，频道 core 成员只需要推导一次。[LinkSavedDataChannelSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataChannelSupport.java#L362)
- 优化前，`resolveDesiredTargetsForTriggerSourceWithOverrides()` 每次都要重建 overrides 索引，而且 `collectEffectiveChannelCores()` 每次都扫描整批 overrides；优化后，索引构建降为每批一次，同一频道的 core 成员推导降为每频道一次。[LinkSavedDataChannelSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataChannelSupport.java#L154) [LinkSavedDataChannelSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataChannelSupport.java#L177) [LinkSavedDataChannelSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataChannelSupport.java#L293)
- 算法复杂度从接近“受影响 `triggerSource` 数量 × overrides 数量”收敛为“每批一次 overrides 索引 + 每个来源一次轻量查询 + 每个频道一次成员修正”，对大频道预检更友好。[LinkChannelEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkChannelEditingService.java#L98) [LinkSavedDataChannelSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataChannelSupport.java#L293)

## 3. 数据流或调用链

- graph 保存预检仍从 `GraphWriteService.preview()` 进入，再走 `preparePlan()`，其中频道操作仍由 `LinkChannelEditingService.prepareConfirmedBatchSetChannel()` 负责，说明这次只优化中间推导层，没有改协议或写回链路。[GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L154) [GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L208)
- 在频道 prepare 中，整批 normalized overrides 先构造一次 `BatchTargetResolutionContext`，随后每个受影响 `triggerSource` 都通过 `resolveDesiredTargetsForTriggerSourceWithContext()` 取最终目标集合，再继续走既有的 `prepareConfirmedReplaceResolvedTargets()` 校验链路。[LinkChannelEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkChannelEditingService.java#L98) [LinkChannelEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkChannelEditingService.java#L107) [LinkSavedDataChannelSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataChannelSupport.java#L204)
- 对于频道模式来源，`collectEffectiveChannelCores()` 会先查频道缓存，未命中时再基于真值桶索引和 `coreOverrides` 计算一次，并把结果回填缓存，后续同频道来源直接命中缓存返回。[LinkSavedDataChannelSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataChannelSupport.java#L293) [LinkSavedDataChannelSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataChannelSupport.java#L384)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 兼容性：当前缓存只存在于 prepare / preview 过程中，不落盘、不改 saved data，因此不会影响跨重启行为，也不会污染正式保存后的真值状态。风险等级：低。[LinkSavedDataChannelSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataChannelSupport.java#L357)
- 性能：这次主要消除了重复推导，但没有引入真实世界大频道基准或 profiler 数据，因此“是否足以把所有超时都压到 15 秒以内”还没有量化证据。风险等级：中。建议下一步用一个大频道存档复测，必要时再决定是否给 preview 单独放宽超时或做请求合并。[LinkChannelEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkChannelEditingService.java#L70)
- 扩展性：上下文目前只缓存 core 频道成员结果；如果后续还要进一步优化来源集合解析，可以继续把“受影响频道 -> triggerSource 成员集合”也纳入同一批次上下文，而不需要再改上层调用链。风险等级：低。[LinkSavedDataChannelSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataChannelSupport.java#L177)
- 安全性：没有引入新的外部接口或权限变化，仍沿用原来的 channel/replace 校验与写控判定。风险等级：低。[LinkChannelEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkChannelEditingService.java#L111)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- 共享状态：`BatchTargetResolutionContext` 是单次 prepare 内部对象，只在当前线程中构建和使用，不会跨请求共享，因此不会引入新的跨线程竞争。风险等级：低。[LinkSavedDataChannelSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataChannelSupport.java#L362)
- 读改写覆盖：本轮只读 `LinkSavedData` 现状并推导目标集合，真正写回仍发生在原有 apply 阶段，因此不会扩大读改写覆盖面。风险等级：低。[LinkChannelEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkChannelEditingService.java#L135) [LinkChannelEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkChannelEditingService.java#L157)
- 重入/线程边界：graph preview 仍可能在服务端主线程排队执行，本轮减少的是单次 prepare 的计算量，不是改变网络排队模型。风险等级：中。建议若后续仍观察到排队型卡顿，再补 preview 去重/淘汰机制，而不是继续在主线程堆更多长任务。[GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L154) [LinkChannelEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkChannelEditingService.java#L70)
