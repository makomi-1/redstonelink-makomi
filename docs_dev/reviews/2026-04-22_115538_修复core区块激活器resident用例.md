# 修复core区块激活器resident用例

## 1. 功能与语义、架构设计（关键方法和入口）
- 本轮没有修改 resident/core 的业务实现，而是修正 `x48` bench 用例的显式预加载范围，使它与释放阶段的 `forceload remove` 覆盖范围一致，入口位于 [chunk_activator_resident_three_cores.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x48/chunk_activator_resident_three_cores.json#L7) 与 [chunk_activator_resident_three_cores.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x48/chunk_activator_resident_three_cores.json#L36)。
- 用例仍保留原有语义链路：先验证 resident 保活，再验证失活撤销后的离线结果，关键断言位于 [chunk_activator_resident_three_cores.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x48/chunk_activator_resident_three_cores.json#L73) 与 [chunk_activator_resident_three_cores.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x48/chunk_activator_resident_three_cores.json#L144)。
- 设计依据来自 bench 预加载执行入口：`benchForceLoadZones` 会被统一转成 `forceload add`，实现位于 [Bench.World.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.World.ps1#L332) 与 [Bench.World.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.World.ps1#L349)。

## 2. 关键数据结构和算法性能分析
- 关键数据结构仍是用例 JSON 中的 `benchForceLoadZones`、`targets`、`sources` 三段配置；本轮只把 source 与显式预加载区收敛到同一 chunk，见 [chunk_activator_resident_three_cores.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x48/chunk_activator_resident_three_cores.json#L7) 与 [chunk_activator_resident_three_cores.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x48/chunk_activator_resident_three_cores.json#L43)。
- `Get-CaseBenchForceLoadZones` 与 `Ensure-CaseChunksLoaded` 的复杂度没有变化，仍然是按 zone 线性展开并逐条发出 `forceload add`，见 [Bench.World.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.World.ps1#L332) 与 [Bench.World.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.World.ps1#L372)。
- 性能层面的实际收益是把 `x48` 的显式预加载从跨两排 chunk 收敛为单排 chunk，减少了无关 chunk 常驻时间与对离线断言的噪音。

## 3. 数据流或调用链
- 用例配置中的 `benchForceLoadZones` 先由 [chunk_activator_resident_three_cores.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x48/chunk_activator_resident_three_cores.json#L7) 提供。
- bench 执行时，`Get-CaseBenchForceLoadZones` 读取这些 zone，并由 `Ensure-CaseChunksLoaded` 发出真实 `forceload add` 命令，见 [Bench.World.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.World.ps1#L332) 与 [Bench.World.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.World.ps1#L378)。
- 随后用例 phases 里的 `forceload remove`、`node get core` 断言依次验证“resident 保持在线”和“撤销后离线”，对应 [chunk_activator_resident_three_cores.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x48/chunk_activator_resident_three_cores.json#L75) 与 [chunk_activator_resident_three_cores.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x48/chunk_activator_resident_three_cores.json#L146)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议
- 安全性风险低：本轮只改测试用例坐标，不涉及游戏内持久化数据、命令权限或运行态业务逻辑，见 [chunk_activator_resident_three_cores.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x48/chunk_activator_resident_three_cores.json#L7)。
- 兼容性风险低：未改 resident/core 实现，也未改变 `triggerSource/core` 术语与方向语义；本轮属于纯 bench 口径修正。
- 扩展性建议：后续新增同类用例时，应先核对显式 `benchForceLoadZones` 与释放 phases 是否一一覆盖，避免再次出现“预加载范围大于释放范围”的假失败，参考 [Bench.World.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.World.ps1#L358)。

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）
- 本轮改动对象是静态 JSON 用例文件，本身不存在 Java 共享状态并发读写问题；bench 运行阶段按顺序消费 phases，风险等级低，见 [chunk_activator_resident_three_cores.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x48/chunk_activator_resident_three_cores.json#L49)。
- 真实风险在“配置与执行口径不一致”：当 `benchForceLoadZones` 与释放命令不同步时，会造成读侧断言看到残留加载状态，这是一类“配置级读改写覆盖”问题，关键路径见 [Bench.World.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.World.ps1#L349) 与 [chunk_activator_resident_three_cores.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x48/chunk_activator_resident_three_cores.json#L134)。
- 建议：后续 resident/force-load bench case 在评审时把“显式预加载区”和“释放区”做成固定核对项，避免并发无关但结果上类似共享状态污染的误判。
