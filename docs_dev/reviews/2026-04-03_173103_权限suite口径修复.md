## 1. 功能与语义、架构设计（关键方法和入口）

- 本轮修复聚焦 bench 测试口径，而非业务权限实现。RCON 侧失败判定入口 `Test-BenchResponseLooksLikeFailure` 现在补齐了中文“没有足够权限”“操作过于频繁”以及更具体的中文退役失败句式，保证 dedicated server 回包能先被统一归类为失败响应。[Bench.Rcon.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.Rcon.ps1#L119)
- 功能 case 的二次兜底判定仍由 `Test-FunctionalCommandAssertHardFailure` 负责，但本轮把会误伤正常 `node get` 输出的宽模式收紧成具体失败句式，避免把 `maxSources=-` 与 `已退役=false` 这类正常字段错判为失败。[Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L457)
- `C07` 用例的目标断言改为只在 `target_list/目标列表` 字段上做命中/拒绝检查，同时补充 `target_list=-` 的显式断言，使“masked 读控”和“unmasked 放行”都直接绑定到目标列表语义，而不再误吃到 `源序号=1` 这类合法字段。[server_permission_read_write_basic.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/c07/server_permission_read_write_basic.json#L60)

## 2. 关键数据结构和算法性能分析

- 两层失败判定都仍然是“顺序扫描固定模式数组并短路返回”的实现，时间复杂度维持在 O(P)，其中 P 仅为少量正则项；本轮只增加了少数中文模式，不会改变 bench 执行链的量级。[Bench.Rcon.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.Rcon.ps1#L119) [Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L468)
- `Test-NodeTraceReadRateLimited` 仍然是单次正则匹配，只是从英文扩成中英双语，不引入额外采样、回放或 trace 展开成本。[Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L1226)
- `C07` 的 JSON 断言从“全响应裸数字匹配”改成“限定到目标列表字段”，虽然正则略长，但依然只针对单条响应文本做常数次匹配，成本远低于 dedicated server / client 的真实跑测耗时。[server_permission_read_write_basic.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/c07/server_permission_read_write_basic.json#L63)

## 3. 数据流或调用链

- dedicated server 或客户端直发命令返回后，单 case 驱动会先在命令检查阶段把 `response` 归一化，再调用 `Test-FunctionalCommandAssertHardFailure` / `Test-BenchResponseLooksLikeFailure` 判定是否属于失败响应；若通过，再继续跑 `expectedRegexes` / `rejectRegexes`。这也是本轮误判发生和修复的主链路。[Bench.PlaceAndLink.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.PlaceAndLink.ps1#L1063) [Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L2430)
- 在 `C07` 中，权限语义本身来自 dedicated server 的真实回包，case JSON 只负责解释这些回包。本轮通过把 `rejectRegexes/expectedRegexes` 收口到 `target_list` 字段，明确了“读控是否 masked”“提权后是否 unmasked”应由目标列表字段负责，而不是由任意数字片段决定。[server_permission_read_write_basic.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/c07/server_permission_read_write_basic.json#L68)
- 限流专项 `C08` 没改 case 文件，但因为 `responseLooksLikeFailure` 已能识别中文“操作过于频繁”，所以 dedicated server 的真实中文限流回包现在会沿相同调用链正确落入 `expectFailureResponse=true` 的通过分支。[Bench.Rcon.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.Rcon.ps1#L139) [Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L2440)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全性方面，本轮没有放宽任何权限校验，只是让 bench 正确认出“没有足够权限”和“操作过于频繁”的失败语义，因此不会改变服务端对低权限玩家的实际授权边界。[Bench.Rcon.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.Rcon.ps1#L125)
- 兼容性风险主要在文案层：当前失败判定依赖回包文案模式，若后续中英文提示词再次调整，bench 可能重新出现“expected_failure_missing / failure_response”误判。建议后续把失败口径进一步收敛到更稳定的错误码、结构化前缀或统一消息词典。[Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L468)
- 扩展性风险在 case 模板层：`C07` 现在显式依赖 `target_list/目标列表` 字段名，如果未来命令输出结构改名，需要同步更新 case 模板；但这比继续使用“全响应裸数字”更符合设计语义，也更不容易掩盖真实错误。[server_permission_read_write_basic.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/c07/server_permission_read_write_basic.json#L63)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- 本轮改动只涉及两个 PowerShell 判定函数里的只读模式数组，以及一个功能 case JSON；没有新增共享可变状态、锁、异步回调或跨线程资源访问，运行时仍是 bench 现有的串行命令判定流程，风险等级为低。[Bench.Rcon.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.Rcon.ps1#L119) [Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L2430)
- 现有的玩家直发桥接共享状态并未在本轮触碰，因此不存在新增的 request/response 文件竞争；本轮只是让桥接返回的文本在后续断言阶段被更准确地解释。[Bench.PlaceAndLink.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.PlaceAndLink.ps1#L1073)
- 建议后续如果继续扩充失败文案模式，统一只在单一函数维护词典并补一组纯脚本单测，避免不同脚本各自维护相近但不一致的模式集合，引入新的口径分叉。[Bench.Rcon.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.Rcon.ps1#L119) [Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L468)
