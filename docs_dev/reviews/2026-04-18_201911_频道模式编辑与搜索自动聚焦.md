# 频道模式编辑与搜索自动聚焦

## 1. 功能与语义、架构设计

- 前端把频道模式从只读切为可编辑视图，核心入口在 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L211) 与 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L542)，其中编辑能力扩展到全部 `topology` 内容模式，频道模式只保留 `view/replace` 两种交互。
- 频道编辑没有复用序号模式的 `triggerSource -> core` 批量边语义，而是新增独立的 `SetNodeChannel` 协议操作；前端协议定义位于 [graphTypes.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/graphTypes.ts#L74) 和 [graphTypes.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/graphTypes.ts#L149)，服务端解析与返回体扩展位于 [GraphWriteJsonSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteJsonSupport.java#L29) 和 [GraphWriteJsonSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteJsonSupport.java#L419)。
- 服务端保存链路在原有 alias / serial replace 之外，新增频道覆盖校验和应用分支；主入口与计划聚合位于 [GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L104) 和 [GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L729)。
- 语义上仍保持 `triggerSource/core` 命名和真实连接方向仅为 `triggerSource -> core`；频道编辑只是通过频道配置推导普通边，不引入反向写入，具体落点在 [LinkChannelEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkChannelEditingService.java#L29)。

## 2. 关键数据结构和算法性能分析

- 前端草稿层新增 `SetNodeChannel` 后，`applyChannelEditToDraft` 只按节点 key 去重并覆写同节点操作，避免单次批量编辑生成重复频道操作；见 [draft.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.ts#L266)。
- `applyDraftToGraph` 采用“两阶段预演”：先合成 alias / replace / channel 覆盖后的节点状态，再基于显式 serial 边和有效频道成员重建最终 `triggerSource -> core` 边集合；这样保存前预览和保存后本地基线保持一致，关键逻辑在 [draft.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.ts#L294)。
- 该重建算法的复杂度主要是节点扫描加边扫描，整体接近 `O(N + E)`；频道成员通过 `Map<channel, coreSerials[]>` 聚合，避免按 source 重复全表查 core，见 [draft.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.ts#L356)。
- 搜索样式层取消非匹配节点降透明度，直接把节点和边保持原透明度，减少每次搜索应用后的视觉状态分叉和额外重绘扰动，变更点在 [canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L234) 和 [canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L285)。

## 3. 数据流或调用链

- 频道模式下的批量编辑数据流为：选择节点与输入频道号 -> `handleApplyBatchEdit` -> `applyChannelEditToDraft` -> `persistDraft` -> `submitGraphSave`，对应实现位于 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1405)、[draft.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.ts#L266) 与 [draft.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.ts#L564)。
- 服务端保存调用链为：`GraphWriteJsonSupport.parseRequest` 解析 `SetNodeChannel` -> `GraphWriteService.validateChannelOperations` 做 OCC 与写控校验 -> `LinkChannelEditingService.prepareConfirmedSetChannel/applyPreparedSetChannel` 真正落地频道配置和普通边，关键节点在 [GraphWriteJsonSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteJsonSupport.java#L64)、[GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L390)、[LinkChannelEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkChannelEditingService.java#L29) 与 [LinkChannelEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkChannelEditingService.java#L131)。
- 搜索交互数据流为：输入态搜索条件 -> `handleApplySearch` 计算首个命中 -> 同步写入 applied state 并 `focusNode` -> `pendingFocusNodeKey` 驱动画布居中；入口与聚焦过程在 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1192) 和 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L869)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全与写控：频道编辑复用了现有写控与限流入口，没有绕开现有命令权限和 `LINK_RW` 限额；对应实现位于 [GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L514)。
- OCC 兼容：频道编辑按节点类型分别校验 `sourceRevision/coreRevision`，可避免频道视图直接覆盖过期节点状态；实现位于 [GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L406)。
- 扩展性：`UpdatedNodeState` 已扩展 `connectionMode/channel`，为后续频道模式编辑后的即时刷新和更多模式切换留出了协议空间，见 [GraphWriteJsonSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteJsonSupport.java#L419) 与 [draft.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.ts#L494)。
- 残余风险：当前服务端在同一次保存里把 serial replace 与 channel set 作为并列批次处理，没有显式保留用户原始操作顺序；如果未来允许在同一草稿里对同一批节点混用两类高层编辑，可能需要进一步定义优先级或显式禁用冲突组合。相关聚合点在 [GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L145) 与 [GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L217)。

## 5. 并发冲突审查

- 共享状态：前端主要共享状态是 `graphDraft`、选择集合和聚焦 key；草稿修改统一经 `applyLocalDraftChange` / `setGraphDraft` 收口，避免多个 UI 分支直接拼操作数组，见 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1170)。
- 读改写覆盖：服务端频道保存对节点 revision 做了 OCC 校验，冲突时直接返回结构化 `updatedNodes` 给前端，降低旧草稿覆盖新真值的风险，见 [GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L423)。
- 重入/线程边界：`LinkChannelEditingService` 仍运行在服务端同步命令线程语义下，内部最终调用 `LinkSetExecutionService` 和 `LinkSavedDataChannelSupport` 处理真值更新，没有新增异步线程写入点；实现位于 [LinkChannelEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkChannelEditingService.java#L131)。
- 风险等级：中低。当前最大风险不是线程安全，而是“混合编辑操作的语义顺序”与“频道配置变更但真实边不变时的外部感知口径”；建议后续若继续扩展频道编辑，补一组覆盖“混合操作草稿”的集成测试。
