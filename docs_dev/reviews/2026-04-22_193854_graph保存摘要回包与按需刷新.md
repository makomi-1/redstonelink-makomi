## 1. 功能与语义、架构设计（关键方法和入口）

本轮把 `graph_write_result` 的成功回包从“按受影响节点展开的 `updatedNodes`”收缩成最小摘要，只保留 `changedNodeCount` 与 `refreshRequired`，从源头切断“保存影响面越大，成功回包越大”的线性膨胀路径。协议入口在 [GraphWriteJsonSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteJsonSupport.java#L86) 和 [GraphWriteJsonSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteJsonSupport.java#L180)，实际保存服务在 [GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L66) 按别名/频道/拓扑三类操作汇总 `changedNodeKeys` 并判定是否必须刷新最新 graph。

客户端网页侧不再依赖成功回包里的节点 revision 补丁，而是在保存成功后按需调用新的 `/api/graph/refresh`。bridge 入口在 [LocalWebAppBridgeService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/web/LocalWebAppBridgeService.java#L182) 和 [LocalWebAppBridgeService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/web/LocalWebAppBridgeService.java#L344)，等待协调器在 [LocalWebGraphRefreshRpc.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/web/LocalWebGraphRefreshRpc.java#L37)。前端保存分支在 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2246) 根据 `refreshRequired` 选择“本地落定新基线”或“刷新最新 graph 后再同步父层状态”，父层索引与当前文件同步在 [App.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/App.tsx#L46) 和 [App.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/App.tsx#L341)。

## 2. 关键数据结构和算法性能分析

性能上的关键变化是把成功路径的返回成本从“序列化所有受影响节点对象”降成“去重计数 + 刷新标记”。`GraphWriteService` 现在使用 `LinkedHashSet<String>` 统计变化节点键，复杂度仍然与受影响节点数线性相关，但内存和网络输出从大对象列表收敛成常量级摘要，关键位置在 [GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L66) 和 [GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L125)。

图刷新链路复用了既有 graph export 分块传输，只新增 `requestId` 做请求关联，而不是另起一套全量拉取协议。导出请求/分块结构扩展点在 [StatePanelNetwork.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/StatePanelNetwork.java#L263) 和 [StatePanelNetwork.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/StatePanelNetwork.java#L566)，编解码在 [StatePanelNetworkPayloadSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/StatePanelNetworkPayloadSupport.java#L329) 与 [StatePanelNetworkPayloadSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/StatePanelNetworkPayloadSupport.java#L367)。网页端索引更新则只做单条 `StorageEntrySummary` upsert，避免保存后再全量重拉索引，见 [storageApi.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app/storageApi.ts#L17) 和 [App.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/App.tsx#L46)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

安全与稳定性上，本轮没有扩大单包字符串上限，而是直接减少成功回包内容，因此对 `graph_write_result` 的编码风险是实质性消除；兼容层上，冲突/拒绝/预检仍保留 `updatedNodes` 和 `preview`，只有 `applied` 改为摘要，兼容消费逻辑集中在 [graphTypes.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/graphTypes.ts#L98) 与 [BenchGraphCommandRegistry.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/bench/BenchGraphCommandRegistry.java#L297)，其中 bench 已做 `changedNodeCount -> updatedNodeCount` 的向后兼容映射，避免现有 functional 输出格式抖动。

残余风险主要有两点。第一，保存成功但自动刷新失败时，前端会退回到“本地应用草稿结果 + 明确提示需手动重载最新 graph”的降级路径，位置在 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2324)；这能避免用户重复提交同一草稿，但后续继续编辑仍应以重新加载真实 graph 为准。第二，当前刷新仍复用整份 graph export，而不是真正的节点级 patch 拉取；这已经解决单包爆炸问题，但如果未来 graph 文件本身继续明显增大，可以继续在现有 `requestId` 关联基础上往“按需 patch”扩展，而无需再改保存协议主干。

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

服务端保存链路仍在原有主线程/命令线程边界内完成，没有新增共享可变全局状态；新增的等待态只出现在客户端本地 bridge 层，`LocalWebGraphRefreshRpc` 使用 `ConcurrentHashMap<String, CompletableFuture<String>>` 管理按 `requestId` 关联的等待请求，见 [LocalWebGraphRefreshRpc.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/web/LocalWebGraphRefreshRpc.java#L25) 和 [LocalWebGraphRefreshRpc.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/web/LocalWebGraphRefreshRpc.java#L76)。网络回包完成与失败都在客户端线程明确收口，见 [StatePanelNetworkClientHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/network/StatePanelNetworkClientHandlerSupport.java#L160) 与 [StatePanelNetworkClientHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/network/StatePanelNetworkClientHandlerSupport.java#L212)。

前端 React 层的共享状态风险较低，主要是“保存刷新后父子状态同步可能把当前视图重置”。本轮通过在 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L317) 持有待同步的保存消息与显示模式，并在 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L982) 消费，避免 `onGraphEntryReloaded` 后把保存反馈和当前模式立即清空。综合判断：并发冲突风险等级为“低到中”，当前实现已经把网络等待、UI 重入和索引覆盖的主要冲突面收口；后续若继续引入 patch 拉取，再补一层“同一页面仅允许一个 refresh 中请求在途”的前端互斥即可。
