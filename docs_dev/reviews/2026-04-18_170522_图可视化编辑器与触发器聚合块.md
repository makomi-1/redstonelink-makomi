## 2. 关键数据结构和算法性能分析

- 前端聚合节点结构从单一 `core` 聚合扩展为带 `aggregateRole` 的双角色结构，并补充 `memberNodeKeys/connectedNodeKeys` 等通用字段，降低后续扩展时的分支复制量，定义见 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L78)。
- 新增 `buildSourceTargetsByNodeKey`，将 `triggerSource` 的输出 `core` 集合作为分组签名来源；同时保留原有 `buildTargetSourcesByNodeKey` 以支持 `core` 聚合，入口见 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L486)。
- `buildGraphCanvasView` 现按“先构造核心聚合、再按避让策略构造触发器聚合、最后统一回推可见节点/边”的顺序组织，时间复杂度仍主要受节点和边线性扫描影响，核心实现见 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L507)、[GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L551)、[GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L617)、[GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L706)。
- 为避免同一批真实边被 `core` 聚合和 `triggerSource` 聚合同时替代，本轮采用“核心聚合优先，触发器聚合避让已被核心聚合覆盖的 core 节点”策略，相关判定点在 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L593)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全与语义：本轮未新增任何 `com.makomi.api.v1.*` 依赖，也未改变真实写入方向；graph 导出仍然只读，不触碰 `triggerSource -> core` 真值，相关导出入口见 [GraphExportNetworkSupport.java](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/GraphExportNetworkSupport.java#L22)。
- 性能：前端聚合仍是以节点/边的批量扫描和分组签名为主，没有引入明显高阶复杂度；但大图下 `buildGraphCanvasView` 的多次 `map/filter/forEach` 仍需观察，关键段在 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L507)。
- 兼容性：`triggerSource` 聚合目前有意识避让已被核心聚合覆盖的 `core` 节点，降低双重聚合错位风险，但代价是部分重叠场景不会再继续做来源侧聚合；若后续需要更高压缩率，可再演进为真正的分层聚合图，当前判断在 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L593)。
- 扩展性：公共 graph 导出发送器已经把“导出 + 分块 + 自动打开网页”收束为独立能力，后续如果还要给其它物品或命令复用，只需接入 [GraphExportNetworkSupport.java](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/GraphExportNetworkSupport.java#L22)。

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- 共享状态：新增服务端公共导出支持类本身不持有可变共享状态，只有常量分块大小，代码位于 [GraphExportNetworkSupport.java](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/GraphExportNetworkSupport.java#L13)；实际去重缓存仍复用既有 `GraphSnapshotExportService`。
- 读改写覆盖：新物品仅触发导出，不写回 graph 真值，也不覆盖状态面板物品内部数据；因此不存在新的世界状态读改写覆盖路径，物品入口见 [GraphVisualEditorItem.java](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/item/GraphVisualEditorItem.java#L70)。
- 线程边界：服务端导出和网络发送仍在既有服务端处理线程内执行，前端聚合计算仍在浏览器主线程内同步完成；没有引入新的异步共享容器或跨线程回调。
- 风险等级：低。当前主要剩余风险不是并发，而是前端双角色聚合在极端重叠拓扑下的可视表达是否足够直观，建议后续结合实际存档继续人工观察 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L617) 到 [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L738) 的聚合边替代效果。
