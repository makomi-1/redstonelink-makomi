## 1. 功能与语义、架构设计

- 本次改动把 graph 前端编辑选区从“覆盖式回流”改成“统一追加式收口”，核心入口是对选区命中的真实节点做追加的 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1664)；点击节点时也会直接复用这条追加链路，见 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1983) 和 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2020)。
- 框选预览阶段不再把 `selected=false` 当作业务层删除信号，而是只吸收新增命中节点，从而避免框选结束后用本轮结果覆盖旧选区，见 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1555)。
- 草稿撤回仍复用既有 `handleUndoDraft()`，但现在额外接入了窗口级 `Ctrl+Z / Meta+Z` 快捷键；同时显式排除了输入框、文本域和可编辑元素，避免和文本编辑撤销冲突，见 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L127)、[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1793)、[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1813)。
- 批量编辑面板的提示文案同步改成“点击或框选会持续追加，清空选择用于重置”，避免 UI 文案继续误导用户必须依赖 `Ctrl/Shift`，见 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2946)、[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L3018)、[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L3045)。

## 2. 关键数据结构和算法性能分析

- 追加式选区仍然基于现有三类状态容器：`selectedEditSourceSerials`、`selectedEditTargetSerials`、`selectedEditChannelNodeKeys`，只是写入策略从“替换整组数组”改成“合并去重排序”，核心算法在 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L98) 和 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L108)。
- `appendBatchSelectionFromNodeKeys(...)` 的复杂度主要取决于当前选区大小和本轮命中节点数，单次为 `O(n log n)` 级别，其中排序成本来自稳定顺序去重；以现有网页图编辑规模来看可接受，见 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1664)。
- `Ctrl+Z` 快捷键不会引入新的撤回数据结构，仍然消费现有 `undoDraftHistory` 栈尾快照，因此没有额外状态膨胀风险，见 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1793)。

## 3. 数据流或调用链

- 普通点击链路：ReactFlow 节点点击进入 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2056)，由 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1983) 判断节点类型与编辑状态后，直接调用 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2020) 追加进业务选区。
- 选区回流链路：ReactFlow 的 `onSelectionChange` 回传当前选区后，不再覆盖业务数组，而是统一走 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2627) -> [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1664) 追加收口。
- 框选链路：`onSelectionStart`/`onNodesChange(select)`/`onSelectionEnd` 期间由 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1555) 收集新增节点，结束后在 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1745) 同时更新受控高亮与业务选区。
- 撤回链路：窗口 `keydown` 命中 `Ctrl+Z` 后由 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1813) 过滤输入态和空历史，再调用 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1829) 进入 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1793) 的既有草稿撤回逻辑。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 兼容性：本次交互语义明显变化，旧行为下用户可能通过“重新框选”来替换选区；现在这一路径变成持续追加，重置手段改为“清空选择”。对应提示文案已同步更新，但若后续用户仍需要“替换式框选”，建议再引入显式模式切换，而不是重新依赖隐式修饰键，参考 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2946)。
- 性能：追加式回流会让 `onSelectionChange` 的重复回调更频繁落到去重合并逻辑，但由于内部先做了相等性短路，重复命中不会持续触发状态震荡，见 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1671) 和 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1698)。
- 安全性：`Ctrl+Z` 监听仅绑定前端窗口，不涉及后端接口或持久化协议扩面；输入态拦截减少了误伤文本编辑的风险，见 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L127)。
- 扩展性：当前快捷键只绑定撤回，后续若要补 `Redo` 或更多画布快捷键，建议继续沿用“窗口监听 + 输入态屏蔽 + 现有命令处理函数”的组织方式，以保持行为一致性。

## 5. 并发冲突审查

- 共享状态主要集中在 React 组件内部的选区状态、草稿状态和撤回历史，没有跨线程共享可变对象；浏览器事件与 ReactFlow 回调最终都串行落在同一个组件状态机中，见 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1664) 和 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1793)。
- 可能的读改写覆盖点在于“点击 / 选区回流 / 框选结束”三路同时更新业务选区；本次通过统一追加收口，把不同来源的更新变成幂等合并，降低了覆盖风险，见 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1664) 和 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1745)。
