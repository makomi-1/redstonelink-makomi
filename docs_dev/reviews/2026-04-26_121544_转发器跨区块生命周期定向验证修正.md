## 2. 关键数据结构和算法性能分析

- 这轮改动只涉及 bench case JSON 和 suite 断言口径，没有引入新的运行时代码路径或额外算法复杂度；运行期仍是单节点 `triggerSource -> repeater -> core` 的 O(1) 查询、断言和 setblock 驱动。[repeater_crosschunk_target_effect_activator_assert.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x61/repeater_crosschunk_target_effect_activator_assert.json#L47) [repeater_crosschunk_target_restart_verify.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/r08/repeater_crosschunk_target_restart_verify.json#L48)

## 3. 数据流或调用链

- target-side prepare 数据流为：本地 `sync triggerSource` 建链到本地 `repeater core`，再由 `repeater triggerSource` 指向远端 `core`；在 target 卸载后，activator 拉起远端目标，再由本地 input 拉高验证最终 `core` 生效。[repeater_crosschunk_target_effect_activator_assert.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x61/repeater_crosschunk_target_effect_activator_assert.json#L81) [repeater_crosschunk_target_effect_activator_assert.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x61/repeater_crosschunk_target_effect_activator_assert.json#L186)
- target-side restart 复用同一世界，先通过 `benchForceLoadZones` 读取远端 Serial，随后校验高态恢复、链接关系和 delay 配置，再在本地 input 断电后断言远端 target 失活。[repeater_crosschunk_target_restart_verify.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/r08/repeater_crosschunk_target_restart_verify.json#L11) [repeater_crosschunk_target_restart_verify.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/r08/repeater_crosschunk_target_restart_verify.json#L79) [repeater_crosschunk_target_restart_verify.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/r08/repeater_crosschunk_target_restart_verify.json#L146)
- source-side prepare 当前链路虽然也完成了 `triggerSource -> repeater -> core` 建链和远端 source 卸载，但在 activator 之前本地 target 已经维持高态，因此后续无法把“activator 恢复”与“本地锁存高态”区分开。[repeater_crosschunk_source_effect_activator_assert.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x60/repeater_crosschunk_source_effect_activator_assert.json#L139) [repeater_crosschunk_source_effect_activator_assert.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x60/repeater_crosschunk_source_effect_activator_assert.json#L167)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 兼容性风险：`r07/r08` 的 serial compare 依赖 prepare/verify 使用同一 source group 名称；本轮已把 restart 用例 source id 对齐到 prepare 分支，后续新增 restart case 时必须保持这一约束，否则 suite 会在 compare 阶段误报 `missing_group`。[repeater_crosschunk_source_restart_verify.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/r07/repeater_crosschunk_source_restart_verify.json#L48) [repeater_crosschunk_target_restart_verify.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/r08/repeater_crosschunk_target_restart_verify.json#L48)
- 扩展性风险：source-side `x60/r07` 目前不是“断言口径太严”，而是场景拓扑本身没有把 activator 放在关键路径上；如果后续继续沿这个拓扑补丁式放宽断言，只会把无效 case 误标成通过。建议下轮单独重画 source-side world，而不是继续在现有 `x60/r07` 上堆叠特判。[repeater_crosschunk_source_effect_activator_assert.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x60/repeater_crosschunk_source_effect_activator_assert.json#L149) [repeater_crosschunk_source_restart_verify.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/r07/repeater_crosschunk_source_restart_verify.json#L79)
- 语义风险：force-load 模式不应再用“空闲常在线”当成功标准；target-side 已按原有 activator 设计修正为“高态恢复 / 断电失活”，source-side 后续也必须沿这一语义做拓扑设计，而不是回退到“看 online 就算通过”。[repeater_crosschunk_target_effect_activator_assert.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x61/repeater_crosschunk_target_effect_activator_assert.json#L169) [repeater_crosschunk_target_restart_verify.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/r08/repeater_crosschunk_target_restart_verify.json#L159)

## 5. 并发冲突审查

- 共享状态风险低：本轮只改 dedicated bench case JSON 和文档，不触碰运行时代码的共享内存、线程边界或服务端并发结构；主要共享状态是 suite 的世界复用与 serial compare 规则。[repeater_crosschunk_target_restart_verify.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/r08/repeater_crosschunk_target_restart_verify.json#L37) [repeater_crosschunk_target_restart_verify.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/r08/repeater_crosschunk_target_restart_verify.json#L48)
- 读改写覆盖风险中等：`reuseExisting + compareSerialsTo` 要求 prepare/verify 对同一世界里的 source/target group 命名和坐标保持稳定；命名不一致不会造成世界损坏，但会在 suite 后处理中产生系统性假失败。本轮通过统一 source id 和补远端 `benchForceLoadZones` 已消除 target-side 这类冲突，source-side 仍待拓扑重构后再做同样收口。[repeater_crosschunk_source_restart_verify.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/r07/repeater_crosschunk_source_restart_verify.json#L11) [repeater_crosschunk_target_restart_verify.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/r08/repeater_crosschunk_target_restart_verify.json#L11)
- 风险等级：target-side 现为低风险可回归；source-side 现为中风险待设计重构，不建议在当前拓扑上继续追加断言修补。[repeater_crosschunk_source_effect_activator_assert.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x60/repeater_crosschunk_source_effect_activator_assert.json#L167) [repeater_crosschunk_target_effect_activator_assert.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x61/repeater_crosschunk_target_effect_activator_assert.json#L197)
