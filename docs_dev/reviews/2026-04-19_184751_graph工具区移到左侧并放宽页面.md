# graph工具区移到左侧并放宽页面

## 1. 功能与语义、架构设计

- 本次实现只调整 graph 编辑器的页面组织，不改 graph 数据结构、保存逻辑和编辑语义。原先位于画布上方的 `graph-toolbar-block` 被直接移动进 `graph-workspace` 左栏，中间仍是画布卡片，右侧仍是详情卡片，因此属于纯展示层重排，业务行为保持不变。[GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1843) [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2059) [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2221)
- graph 页面增加了专用宽度上限，使本页不再受录制页 `1380px` 统一宽度限制，而是单独扩到 `1720px`，满足“通过整页变宽而不是压画布”这一约束。[app.css](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L1167)
- 新增的左侧工具栏卡片被纳入现有 `future-command` 主题直角化规则，保证主题切换下的视觉一致性，不会出现左栏仍保留旧圆角的割裂问题。[app.css](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L237)

## 2. 关键数据结构和算法性能分析

- 本次没有引入新的 graph 计算、聚类、布局或序列化逻辑，性能影响主要来自 CSS 布局重排，属于浏览器原生网格布局成本，远低于任何 graph 数据重算或 React 额外派生状态引入的开销。[GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1843)
- 主工作区由两栏改为三栏，列定义采用“左固定宽度 + 中间弹性 + 右限制上界”的形式，避免工具区与详情区一起挤压画布，同时保持布局可预测性。[app.css](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L1333)
- 现有窄屏回退仍保留为单列，因此不会因为三栏布局在小窗口下持续触发水平拥挤；这属于对响应式性能和可用性的兜底，而不是另起一套布局算法。[app.css](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L1917)

## 3. 数据流或调用链

- 左侧工具栏中的显示模式、搜索、撤回草稿、重新布局和 Save 仍然直接调用原有事件处理函数，调用链未变；本次只是把同一批控件从顶层容器搬进左栏容器。[GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1843)
- 画布区域仍由 `graph-canvas-card` 承载，右侧详情仍由 `graph-detail-card` 承载，因此从“工具区操作 -> 状态更新 -> 画布/详情重新渲染”的既有数据流没有被打断。[GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2059) [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2221)
- 页面宽度与三栏规则全部集中在 `app.css`，未把布局常量散落到 TSX 逻辑中，样式职责与组件职责仍然分离。[app.css](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L1167) [app.css](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L1333)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全层面无新增接口、无新增后端调用、无新增持久化字段，因此没有引入额外输入面或权限风险；本次风险集中在前端布局兼容性。[GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1843)
- 兼容性风险主要是超窄桌面窗口下的可视区域拥挤。当前通过 `1720px` 专用宽度与 `980px` 以下单列回退做了兜底，但如果后续右栏继续增长，仍建议再细化中间断点而不是继续堆固定宽度。[app.css](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L1167) [app.css](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L1333) [app.css](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L1917)
- 扩展性上，本次把工具区整体包进独立左栏卡片，后续如果继续加“序号/频道子模式”或“批量操作辅助面板”，可以优先在左栏内部扩展，而不用再次调整画布和右栏的语义结构。[GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1843)

## 5. 并发冲突审查

- 本次未新增共享可变状态，也未引入新的异步请求、定时器或跨组件同步机制；所有现有 React 状态仍由 `GraphViewer` 原有事件处理路径维护，因此并发风险等级为低。[GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1843)
- 与用户已有改动的冲突面主要在同一前端目录下的脏工作树文件。此次实现只修改了 `GraphViewer.tsx` 和 `app.css`，没有回退或覆盖 `GraphPage.tsx`、`RecordingPage.tsx`、`ThemeSwitcher.tsx` 中现有未提交内容，读改写覆盖风险可控。
- 如果后续多人并行继续调整 graph 页面样式，建议优先复用现有 `graph-page-shell` 专用宽度与 `graph-workspace` 三栏入口，避免再次在通用 `recording-page-*` 规则上做页面级特化，降低样式覆盖冲突概率。[app.css](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L1167) [app.css](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L1333)
