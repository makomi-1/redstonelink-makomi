## 2. 关键数据结构和算法性能分析

本阶段没有新增业务数据结构，重点是让客户端状态提取在 26.1 下继续复用现有缓存和渲染状态，避免因迁移引入额外分配或重复计算。

- `HideNodeGhostRenderer` 继续把幽灵显示拆成展示态与模型态两层，只是在每帧抽取前清空旧模型态、按需更新并最终提交，避免渲染阶段重复拼装 block model，见 [HideNodeGhostRenderer.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/render/HideNodeGhostRenderer.java#L60)、[HideNodeGhostRenderer.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/render/HideNodeGhostRenderer.java#L73) 与 [HideNodeGhostRenderer.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/render/HideNodeGhostRenderer.java#L132)。
- 世界覆盖层仍按玩家所在区块做局部可视范围判断，迁移后只是把 `ChunkPos` 读取方式改为 `chunkPosition().x()/z()`，算法复杂度和可见区裁剪策略未变，见 [DirectionalFaceVectorWorldOverlayRenderer.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/render/DirectionalFaceVectorWorldOverlayRenderer.java#L49) 与 [QuickLinkWorldOverlayRenderer.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/render/QuickLinkWorldOverlayRenderer.java#L457)。
- 线框可视化仍沿用原渲染批次，只把深度比较常量迁到 26.1 的 `CompareOp.ALWAYS_PASS`，没有增加额外批次或缓冲结构，见 [QuickLinkVisualizedLineRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/render/QuickLinkVisualizedLineRenderSupport.java#L43)。
- HUD 文本项名称读取改为基于 `ItemStack` 的新签名，避免旧接口失效导致的额外 fallback 或异常路径，见 [LinkSerialOverlayRenderCommon.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/render/LinkSerialOverlayRenderCommon.java#L179) 与 [LinkSerialHudOverlayTextSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/render/LinkSerialHudOverlayTextSupport.java#L478)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 构建兼容性方面，本阶段额外显式引入了 26.1 的 `fabric-key-mapping-api-v1` 子模块，避免聚合依赖在当前客户端编译路径上缺失键位 API，见 [build.gradle](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/build.gradle#L93)。这一点属于 26.1 模块拆分后的新要求，后续新增客户端输入能力时应沿用相同依赖策略。
- 键位注册最终已收口到公开 `KeyMappingHelper`，没有把 `fabric.impl` 内部类固化到正式迁移结果里，见 [RedstoneLinkClient.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/RedstoneLinkClient.java#L171)。这降低了后续 Fabric API 再升级时的破裂风险。
- GUI 迁移的主要风险不在编译，而在运行时交互细节是否与旧版完全一致，例如抽取阶段的 tooltip、文本框和容器内容绘制顺序，当前已在结构上对齐 26.1，但还未做游戏内回归，见 [GuiTooltipRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/screen/GuiTooltipRenderSupport.java#L26)、[SmartNodeContainerScreen.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/screen/SmartNodeContainerScreen.java#L124)。
- 用户已明确“游戏内测试不需要迁移”，因此本阶段验收标准仅为 `compileClientJava` 通过；剩余风险集中在运行时视觉与交互一致性，而不是源码编译面。
