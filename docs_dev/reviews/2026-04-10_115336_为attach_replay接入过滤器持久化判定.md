## 1. 功能与语义、架构设计（关键方法和入口）
- 本轮新增了 replay 专用过滤门面 `allowsReplayByPersistedFilters(...)`，明确把 attach replay 的过滤判定收口到 `PlacedLinkFilterSavedData` 持久化真值，而不是依赖过滤器 block entity 是否已经附着。[LinkDispatchFilterService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkDispatchFilterService.java#L144) [LinkDispatchFilterService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkDispatchFilterService.java#L169)
- `target attach replay` 入口 `tryReplayTargetChunkLoad(...)` 现在会在发布前逐条重查 `triggerSource -> core` 组合是否通过持久化 send/receive 过滤器，只有放行的 pair 才继续进入 replay 发布器。[LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L260) [LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L305)
- `source attach replay` 入口 `replaySourceAttachSyncIfEnabled(...)` 也做了同样的持久化补判，并直接走已解析强度的发布 helper，避免再回到不带过滤门禁的通用 attach 发布器。[LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L332) [LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L380)
- 语义对齐结果：本轮命名和方向仍严格保持 `triggerSource/core` 与 `triggerSource -> core`，没有引入旧术语新输出，也没有新增 `com.makomi.api.v1.*` 依赖。影响点仅限 replay 判定入口，无残余语义漂移。[LinkDispatchFilterService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkDispatchFilterService.java#L144) [LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L318)

## 2. 关键数据结构和算法性能分析
- replay 过滤仍复用 `PlacedLinkFilterSavedData.collectFilters(...) + LinkFilterRuleEvaluator.allows(...)` 的既有索引与规则求值，不新增第二套过滤真值结构，保持单一路径和 O(命中过滤器数) 的判定成本。[LinkDispatchFilterService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkDispatchFilterService.java#L220)
- `target attach replay` 现在按“来源序列号遍历 -> 读取 replay 快照 -> 过滤 -> 发布”线性执行，单来源只解析一次快照；`source attach replay` 则按“目标序列号遍历 -> 过滤 -> 发布”执行，避免在通用 `publishLinkAttached(...)` 中对所有 pair 先发布后过滤。[LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L285) [LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L357)
- 持久化真值实例通过 `resolveSharedSavedData(...)` 统一从共享 overworld `SavedData` 获取，避免每个 replay 入口自行拼装上下文，职责边界更清晰。[LinkDispatchFilterService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkDispatchFilterService.java#L307)

## 4. 安全、性能、兼容性、扩展性风险分析与建议
- 稳定性方面，本轮核心收益是 replay 发布前终于纳入了持久化过滤真值，因此过滤器注册时序不再决定 attach replay 是否误放行；这正好对准“进入存档时 replay 先于过滤器恢复”的风险窗口。[LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L303) [LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L365)
- 兼容性方面，通用实时发布器 `publishLinkAttached(...)` 没有被改写，正常建链与运行期实时派发路径保持原行为；本轮仅缩小到 attach replay 入口层补判，避免语义外溢。[LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L260) [LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L332)
- 残余风险方面，若 replay 时 `LinkSavedData` 中某端节点快照缺失，当前实现会直接跳过该 pair；这是更保守的 fail-closed 选择，避免在坐标未知时错误放行。后续若要提升可观测性，可考虑为这类跳过增加诊断日志或 trace 钩子。[LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L281) [LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L348)
- 测试覆盖方面，本轮新增了“无过滤器放行、send 拦截、receive 拦截、双侧放行”四个门面测试，能稳定约束 replay 过滤语义，但尚未新增更重的生命周期集成测试；这属于可接受的后续增强项。[LinkDispatchFilterServiceTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/data/LinkDispatchFilterServiceTest.java#L88) [LinkDispatchFilterServiceTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/data/LinkDispatchFilterServiceTest.java#L107) [LinkDispatchFilterServiceTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/data/LinkDispatchFilterServiceTest.java#L137) [LinkDispatchFilterServiceTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/data/LinkDispatchFilterServiceTest.java#L167)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）
- 共享状态新增读取点主要是 `PlacedLinkFilterSavedData`，但本轮没有新增异步写线程；attach replay 仍在服务端生命周期/tick 消费线程内串行执行，读写边界与既有 `SavedData` 访问模型一致。风险等级：低。[LinkDispatchFilterService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkDispatchFilterService.java#L169) [LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L260)
- 本轮避免了“等待过滤器注册完成后再 replay”的同步阻塞方案，改为直接读取持久化真值，因此没有把新的阻塞点引入启动链路，也没有扩大 `SERVER_STARTED` 前后的线程耦合。风险等级：低。[LinkDispatchFilterService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkDispatchFilterService.java#L144) [LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L305)
