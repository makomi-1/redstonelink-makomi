# Graph 孤立节点池化与高扇出摘要节点

## 1. 功能与语义、架构设计（关键方法和入口）

- 本轮在 `GraphViewer` 中新增了“画布视图模型”层，先从真实 `effectiveGraphBundle` 派生出“主画布节点/边、摘要节点、孤立节点池”，再交给 ReactFlow 做布局与渲染，避免主画布继续直接消费全量真实节点 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L348)。
- 高扇出处理只聚合某个 `triggerSource` 下“incident edge 数为 1 的 `core` 叶子节点”，并生成虚拟摘要节点，保持真实 `triggerSource -> core` 保存语义不变 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L366)。
- 视图层摘要节点与孤立节点池的交互入口分别是画布点击联动 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1545) 和右侧孤立节点池面板 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1833)；摘要节点视觉和孤立池样式在 [app.css](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L1001) 与 [app.css](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L1018) 中补齐。

## 2. 关键数据结构和算法性能分析

- 关键数据结构是 `GraphCanvasView`，其中同时维护 `canvasNodes`、`canvasEdges`、`visibleActualNodeKeys`、`summaryNodes` 和孤立节点池列表，用来承接“真实图 -> 视图裁剪图”的中间层 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L78) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L348)。
- 算法复杂度主要分两段：
  - 视图裁剪阶段：统计 incident edge、构建 `triggerSource -> target cores` 映射、筛出可聚合叶子节点，复杂度约 `O(V + E)` [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L322) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L348)。
  - 布局阶段：对裁剪后的画布节点按连通分量分块并流式铺排，复杂度约 `O(V + E + V log V)`，其中排序成本来自稳定输出顺序 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L479) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L583)。
- 节点渲染与样式也被拆成“实际节点 / 摘要节点”两条路径，保证强制显示优先级和摘要节点视觉表达各自独立，不相互污染 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L622)。

## 3. 数据流或调用链

- 主链路仍然是 `baseGraphBundle + graphDraft -> effectiveGraphBundle -> draftDiff`，本轮是在此之后补了一层 `forcedVisibleNodeKeys -> graphCanvasView -> autoLayoutPositions -> ReactFlow nodes/edges` 的视图裁剪调用链 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1236) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1260)。
- 强制显示优先级来源于五类前端状态：当前选中节点、搜索命中节点、草稿差异节点、批量编辑选择节点、手动拉回画布的孤立节点；这些状态先合并成 `forcedVisibleNodeKeys`，再输入到 `buildGraphCanvasView(...)` [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1237)。
- 交互上，点击来源节点/摘要节点会切换局部展开状态，点击孤立节点池会把节点加入临时显示集合并触发聚焦；最终都通过同一套节点重建和定位逻辑进入画布 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1509) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1545) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1585)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 语义安全性方面，这次新增的摘要节点和孤立节点池都只存在于前端视图层，没有修改 `GraphDraft`、服务端保存接口或真实 `triggerSource -> core` 编辑语义，兼容边界保持不变 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L348) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L675)。
- 当前高扇出聚合只针对“degree=1 的 `core` 叶子节点”，这是为了避免共享 `core` 被错误折叠；如果后续扩到频道模式或更复杂的复用核心节点，建议继续沿着“只聚合纯叶子或纯视图虚拟节点”的边界扩展，而不是直接扩大聚合范围 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L370)。
- 验证方面，`buildWebapp` 成功，但全量慢测仍被既有性能基线挡住：`LinkSavedDataPerformanceSlowTest` 连续两次在 `save` 门限上失败，分别为 `72ms/71ms > 50ms`，失败点位于 [LinkSavedDataPerformanceSlowTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/data/LinkSavedDataPerformanceSlowTest.java#L72)；这与本轮前端 graph 改动路径无直接耦合，但当前无法把“全量自动化验证”标记为完全通过。

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- 新增共享状态主要是 `expandedTriggerSourceNodeKeys`、`pinnedIsolatedNodeKeys` 和 `pendingFocusNodeKey`，都属于 React 前端单线程状态，不跨线程共享，线程边界风险低 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1170)。
- 节点刷新继续采用 `setNodes((currentNodes) => ...)` 函数式更新，先保留当前已有坐标，再叠加新的画布视图模型，能降低“展开/收起与拖拽坐标相互覆盖”的读改写冲突 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1384)。
- 需要继续关注的重入点是“聚焦请求先于节点可见状态更新”：本轮通过 `pendingFocusNodeKey` 等待节点真正出现在 `nodes` 状态后再执行 `setCenter(...)`，降低了隐藏节点被强制显示时的竞态风险，当前风险等级为低 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1455)。
