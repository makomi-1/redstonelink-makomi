- 新增边入口仍保持原有链路：`applyPreparedReplace(...)` 在识别到 `addedTargets` 后调用 attach replay 发布入口，没有改写原有 replace 语义。[LinkSetExecutionService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkSetExecutionService.java#L430) [LinkSetExecutionService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkSetExecutionService.java#L434)
- 修复点集中在 `publishLinkAttached(...)`：先解析 replay 强度，再按 `triggerSource -> core` 配对补做 persisted `send/receive` 过滤判定，仅放行通过的 replay，保证新增边 replay 与其它 replay 路径语义一致。[InternalDispatchDeltaRuleSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/InternalDispatchDeltaRuleSupport.java#L162) [InternalDispatchDeltaRuleSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/InternalDispatchDeltaRuleSupport.java#L193) [InternalDispatchDeltaRuleSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/InternalDispatchDeltaRuleSupport.java#L297)
- 单目标 attach replay 入口被收口到集合实现，避免未来从另一条 attach 路径绕过过滤闸门。[InternalDispatchDeltaRuleSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/InternalDispatchDeltaRuleSupport.java#L277)

## 2. 关键数据结构和算法性能分析
- 本次没有新增持久化结构，只在单次 attach replay 发布过程中引入三个局部缓存：来源强度缓存、`triggerSource` 节点缓存、`core` 节点缓存，避免同一批新增边重复命中 `SavedData` 查询。[InternalDispatchDeltaRuleSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/InternalDispatchDeltaRuleSupport.java#L179) [InternalDispatchDeltaRuleSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/InternalDispatchDeltaRuleSupport.java#L180) [InternalDispatchDeltaRuleSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/InternalDispatchDeltaRuleSupport.java#L181)
- 节点缓存允许写入 `null`，这样缺失节点也只查一次；整体复杂度维持在对新增边数量的线性扫描，额外开销主要是常数级过滤判断。[InternalDispatchDeltaRuleSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/InternalDispatchDeltaRuleSupport.java#L364)
- 真正的过滤规则仍复用现有 persisted filter evaluator，不复制规则、不引入第二套判定逻辑，避免规则漂移。[LinkDispatchFilterService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkDispatchFilterService.java#L167) [LinkDispatchFilterService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkDispatchFilterService.java#L309)

## 3. 数据流或调用链
- 数据流起点是“边变化”：`replaceTriggerSourceTargets(...)` 计算出新增目标集合后，attach replay 进入 `publishLinkAttached(...)`。[LinkSetExecutionService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkSetExecutionService.java#L430) [LinkSetExecutionService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkSetExecutionService.java#L434)

## 4. 安全、性能、兼容性、扩展性风险分析与建议
- 安全与兼容性方面，本次没有新增写盘格式，也没有改动普通实时 dispatch，只补“新增边 attach replay”这一条发布条件，影响面受控。[InternalDispatchDeltaRuleSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/InternalDispatchDeltaRuleSupport.java#L162) [InternalDispatchDeltaRuleSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/InternalDispatchDeltaRuleSupport.java#L320)
- 当前实现对“服务端引用缺失、节点快照缺失”的异常态仍保留放行回退，以避免测试夹具或异常拓扑直接误伤 replay；这保证了兼容性，但也意味着极端异常态下仍可能保留旧行为。建议后续若要继续收严，应先补真实世界级夹具或 dedicated server 场景验证，再决定是否把该分支改为拒绝。[InternalDispatchDeltaRuleSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/InternalDispatchDeltaRuleSupport.java#L293) [InternalDispatchDeltaRuleSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/InternalDispatchDeltaRuleSupport.java#L329)
- 既有残余风险未变化：attach replay 仍依赖来源端当前可解析的 replay 强度；若来源运行态本身无法解析，事件不会发出，这不属于本次缺口，但需要在游戏内回归里继续关注。[InternalDispatchDeltaRuleSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/InternalDispatchDeltaRuleSupport.java#L189) [InternalDispatchDeltaRuleSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/InternalDispatchDeltaRuleSupport.java#L633)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）
- 本次新增状态全部是方法内局部 `HashMap`，生命周期局限在单次 attach replay 发布，没有跨调用共享，也不存在读改写覆盖问题。[InternalDispatchDeltaRuleSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/InternalDispatchDeltaRuleSupport.java#L179) [InternalDispatchDeltaRuleSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/InternalDispatchDeltaRuleSupport.java#L364)
- 共享数据访问仍是只读：`LinkSavedData` 只做节点快照查询，`PlacedLinkFilterSavedData` 只做 persisted filter 求值，没有新增并发写路径。[InternalDispatchDeltaRuleSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/InternalDispatchDeltaRuleSupport.java#L179) [LinkDispatchFilterService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkDispatchFilterService.java#L167)
