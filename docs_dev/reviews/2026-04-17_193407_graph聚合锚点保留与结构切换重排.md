# Graph 聚合锚点保留与结构切换重排

## 1. 功能与语义、架构设计（关键方法和入口）

- 本轮把核心聚合块从“仅折叠态存在的虚拟节点”改成了“折叠态和展开态都保留的锚点节点”，在 `GraphCanvasAggregateNode` 中显式增加 `expanded` 标记，并同步更新了文案和视觉状态，解决展开后失去收起入口的问题 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L69) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L145) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L275)。
- `buildGraphCanvasView(...)` 的聚合阶段不再在展开态直接丢弃聚合块，而是统一生成 `aggregateNodes`，折叠态只隐藏真实 `triggerSource -> core` 边，展开态则保留真实边并继续保留 `triggerSource -> aggregate` 聚合锚点边 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L512) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L557) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L639)。
- 展开/收起交互入口仍在画布点击链路内，但现在 summary 和 aggregate 的切换都会进入统一的“结构性刷新”通道，而不是只做普通状态切换，从而把布局与视口纠偏绑定到同一条交互链路上 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2013) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2071)。

## 2. 关键数据结构和算法性能分析

- 聚合判定的时间复杂度仍然保持在线性分组范围内，本轮没有引入新的高复杂度索引；主要变化是把聚合节点统一保存在 `aggregateNodes` 中，再根据 `expanded` 决定是否隐藏真实边 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L520) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L548)。
- 为避免展开中的聚合核心又被来源级摘要重新折回，本轮增加了 `expandedAggregateCoreNodeKeys` 口径，在 summary 阶段只允许未被聚合展开保护的真实节点继续参与高扇出折叠，避免形成“展开后又被下一层隐藏”的无效往返 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L548) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L673)。
- 结构性切换的性能取舍是明确的：当发生聚合或摘要展开/收起时，不再沿用旧坐标，而是全量采用自动布局坐标，这会牺牲局部手动拖拽位置保留，但能稳定消除旧坐标与新拓扑混用导致的重叠和漂移 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1859) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1888)。

## 3. 数据流或调用链

- 画布数据流现在是 `effectiveGraphBundle -> buildGraphCanvasView -> aggregateNodes/canvasNodes/canvasEdges -> buildGraphFlowNodes/buildEdges -> ReactFlow`，其中聚合展开态和折叠态都经由同一套 `aggregateNodes` 输出，因此不会再出现“点击后节点本身从输出链路消失”的情况 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L512) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L613) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L723)。
- 交互数据流新增 `requestStructureLayoutRefresh()` 作为结构变更入口，summary 点击、aggregate 点击以及可折叠 `triggerSource` 点击都会先改展开态集合，再标记“需要结构重排”和“需要视口归位” [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2013) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2071)。
- 布局和视口链路则拆成两段：先在节点同步 effect 中基于 `pendingStructureLayoutReset` 决定是否丢弃旧坐标，再在下一段 effect 中基于 `pendingStructureViewportFit` 执行 `fitView`，避免视口在旧布局上提前归位 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1859) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1926)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 语义边界保持不变：本轮仍只改前端视图层，真实保存语义继续只处理 `triggerSource -> core`，没有改 `snapshot`、`draft` 和服务端真值，也没有引入 `com.makomi.api.v1.*` 依赖 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L512) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L557)。
- 用户可见的取舍是：结构性切换后会覆盖此前手动拖拽得到的局部坐标。这是为修复“旧坐标残留导致展开布局错位和重叠”做的有意取舍，风险可接受，但需要后续人工体验确认是否足够自然 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1860) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1936)。
- 聚合锚点在展开态会继续保留 `triggerSource -> aggregate` 虚拟边，因此边数量会比“纯真实边展开”多一层提示边；这是为了稳定保留收起入口和布局锚点，后续如果用户觉得展开态视觉仍偏密，可再独立评估是否改成更轻量的锚点连线策略 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L639) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L647)。

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- 新增的 `pendingStructureLayoutReset` 和 `pendingStructureViewportFit` 都限定在 `GraphViewer` 组件内部使用，没有跨组件共享状态；它们分别控制“坐标是否重置”和“视口是否归位”，职责边界明确，风险低 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1604) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1605)。
- 结构切换采用“先置位标记，再在 effect 中消费并清空”的方式，避免在点击回调里直接依赖尚未更新的 `graphCanvasView` 或旧 `nodes` 快照，降低了快速连续点击时的闭包状态覆盖风险 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1888) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1936)。
- 当前残余风险主要是用户连续高速点击多个 summary/aggregate 节点时，`fitView` 会连续触发多次，造成视口动画频繁切换；这属于交互层的轻度抖动风险，不是共享状态一致性风险，等级低 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2013) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2079)。
