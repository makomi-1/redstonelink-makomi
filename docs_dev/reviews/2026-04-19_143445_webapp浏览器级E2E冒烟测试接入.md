# webapp浏览器级E2E冒烟测试接入

## 1. 功能与语义、架构设计（关键方法和入口）

- 本轮在 `webapp` 内新增 Playwright 第三层浏览器级测试入口，运行脚本集中定义在 [package.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/package.json#L6)，保持前端测试入口按“单测 / 组件测 / E2E”分层。
- Playwright 基础配置集中在 [playwright.config.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/playwright.config.ts#L6)，当前只启用 Chromium、单 worker、`webServer` 启动本地 `vite` 服务，目标是先建立稳定的最小冒烟链路。
- E2E 的 `/api/**` mock 集中封装在 [mockApi.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/e2e/support/mockApi.ts#L127)，由浏览器层统一劫持接口，不改业务代码，也不接真实 Minecraft bridge。
- 首批冒烟用例集中在 [graph.smoke.spec.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/e2e/graph.smoke.spec.ts#L14)，覆盖页面路由、搜索应用、预检与保存错误提示、视图切换和真实点击交互。
- 为了避免前两层 Vitest 误扫到 E2E 目录，本轮在 [vite.config.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/vite.config.ts#L15) 显式补充 `exclude`，并保留默认排除规则。

## 2. 关键数据结构和算法性能分析

- E2E 测试数据并没有再造一套独立 fixture，而是复用前两层已沉淀的测试工厂函数，再在 [mockApi.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/e2e/support/mockApi.ts#L16) 组合出同时包含 serial 与 channel 成员的默认 graph bundle，降低了重复维护成本。
- `installMockApi` 使用一个内存 `Map` 保存本地 draft 内容，在同一个浏览器上下文里模拟 `GET/POST/DELETE draft` 行为，成本低且足以覆盖 graph 页的真实前端副作用；实现见 [mockApi.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/e2e/support/mockApi.ts#L130)。
- Playwright 配置显式使用 `workers: 1` 和 `retain-on-failure trace`，牺牲少量速度换取稳定性和失败可追溯性，适合当前图编辑器这种交互较重页面的首轮 E2E；见 [playwright.config.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/playwright.config.ts#L7)。
- `.gitignore` 补充了 `webapp/test-results/` 与 `webapp/playwright-report/`，避免 E2E 产物把工作区污染成大量噪声文件；见 [.gitignore](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/.gitignore#L63)。

## 3. 数据流或调用链

- 路由冒烟测试走的是完整 `HomePage -> App 路由切换 -> GraphPage -> GraphViewer` 调用链，而不是只测单个组件；对应入口见 [graph.smoke.spec.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/e2e/graph.smoke.spec.ts#L15)。
- 搜索测试走 `GraphViewer 输入态 -> 应用态 -> 搜索结果刷新 -> 清空恢复` 这条真实页面链路，验证了前面做过的“输入态 / 应用态分离”在浏览器里确实成立；见 [graph.smoke.spec.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/e2e/graph.smoke.spec.ts#L42)。
- 预检 / 保存错误提示测试通过 mock `previewResponse/saveResponse`，把页面上 `apply alias -> preview -> Save -> 错误反馈` 的完整链路串起来；对应实现见 [mockApi.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/e2e/support/mockApi.ts#L151) 和 [graph.smoke.spec.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/e2e/graph.smoke.spec.ts#L70)。
- 视图切换与点击聚合块测试覆盖了 `序号 -> 频道 -> 序号 -> 点击聚合块 -> 详情区更新` 的真实鼠标交互链；见 [graph.smoke.spec.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/e2e/graph.smoke.spec.ts#L92)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 当前 E2E 仍然完全依赖 mock `/api/**`，优点是稳定、可重复、对本地 Minecraft 运行状态零依赖；代价是不能覆盖真实 bridge 的时序与传输异常。这个边界是有意保留的，后续如果要加第四层“真实 bridge 联调”，应该单独建立环境，不与当前冒烟层混跑。
- 目前 E2E 只跑 Chromium，适合作为首层浏览器回归，但还没有覆盖 Firefox/WebKit 差异。等用例规模稳定后，再考虑扩成多浏览器矩阵。
- 当前用例对 UI 文案有一定依赖，例如 `+2 grouped cores`、`channel #7`、错误提示文本；这能直接校验用户可见行为，但后续如果界面文案频繁改动，建议逐步补少量稳定 `data-testid`，避免测试跟着纯文案微调频繁抖动。
- `vite.config.ts` 的 `exclude` 现在已经显式合并 `configDefaults.exclude`；如果以后继续补新的测试目录，必须继续在默认排除规则之上追加，而不能整体覆盖，否则又会把 `node_modules` 依赖测试带进来。见 [vite.config.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/vite.config.ts#L21)。

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- 本轮改动全部位于前端测试、配置和忽略规则层，不进入生产运行时逻辑，因此对业务共享状态与服务端并发语义无直接影响，风险等级低。
- `installMockApi` 在每个 Playwright `page` 上独立注册 route，并把 draft 状态限定在各自测试页面的本地 `Map` 中，不存在跨测试共享可变状态；见 [mockApi.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/e2e/support/mockApi.ts#L133)。
- Playwright 当前配置为单 worker，规避了图编辑器页面在首轮 E2E 时可能出现的并发端口争抢、共享浏览器下载状态和时序抖动问题；见 [playwright.config.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/playwright.config.ts#L8)。
- 唯一实际遇到的并发类问题是浏览器安装被中断后残留全局安装锁，这属于工具链层共享资源竞争，而不是业务代码问题；已作为经验记录单独沉淀。
