# hide节点白色高亮修复

## 1. 功能与语义、架构设计（关键方法和入口）
- 本次修复仅调整隐藏节点客户端幽灵模型的提交方式，不改 `triggerSource/core` 业务语义，也不改贴图资源。入口仍是 `HideNodeGhostRenderer#submit(...)`，但不再把最后一个 `int` 当作“模型颜色”传给 `BlockModelRenderState.submit(...)`，而是改为自定义几何提交，避免 26.1 中该参数被解释成 `outlineColor`，导致 hide 节点渲染成白色高亮。[HideNodeGhostRenderer.java](/D:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/render/HideNodeGhostRenderer.java:99)
- 幽灵模型状态提取逻辑保持不变，仍由 `resolveGhostDisplayState(...)` 把 `hide_core` / `hide_sync_trigger_source` 映射为普通可见节点状态，确保迁移后功能设计继续以迁移对象为准。[HideNodeGhostRenderer.java](/D:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/render/HideNodeGhostRenderer.java:130)
- 新增的 `renderGhostModel(...)` 走 26.1 当前方块模型管线，使用 `ModelBlockRenderer#tesselateBlock(...)` 铺四边形，再在最终写顶点时只缩减 alpha，以恢复“原贴图半透明幽灵”的旧设计效果。[HideNodeGhostRenderer.java](/D:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/render/HideNodeGhostRenderer.java:149)

## 2. 关键数据结构和算法性能分析
- 复用单个 `MovingBlockRenderState`、`RandomSource` 与 `List<BlockStateModelPart>` 作为渲染器字段，避免每帧每节点反复分配临时对象；每次提交前只重置状态并清空列表，符合客户端热点路径最小分配原则。[HideNodeGhostRenderer.java](/D:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/render/HideNodeGhostRenderer.java:52)
- 顶点处理为线性遍历，每个 `BakedQuad` 仅复制一次 `QuadInstance` 颜色/光照并通过 `ARGB.multiplyAlpha(...)` 缩减 alpha，复杂度与原模型 quad 数量线性相关，没有引入额外的几何级放大。[HideNodeGhostRenderer.java](/D:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/render/HideNodeGhostRenderer.java:219)
- AO 选项读取使用客户端当前 `ambientOcclusion` 配置，避免强行切换 AO 模式导致模型视觉回归差异；该读取是 O(1) 并且只在 hide 幽灵模型提交时触发。[HideNodeGhostRenderer.java](/D:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/render/HideNodeGhostRenderer.java:212)

## 3. 数据流或调用链
- 数据流起点是 `extractRenderState(...)`：检查智能眼镜可见性后，把隐藏节点状态解析为普通显示状态，并继续填充 `ghostModelState` 作为“是否需要渲染”的判定依据。[HideNodeGhostRenderer.java](/D:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/render/HideNodeGhostRenderer.java:72)
- 到 `submit(...)` 时，如果存在幽灵显示状态且模型非空，则通过 `submitCustomGeometry(...)` 把渲染委托给 `renderGhostModel(...)`，不再走错误的 outline 色参数链；远距文本外显仍然复用 `farOverlayRenderer.submit(...)`，未改调用链末端行为。[HideNodeGhostRenderer.java](/D:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/render/HideNodeGhostRenderer.java:99)
- `renderGhostModel(...)` 内部调用链为：配置 `MovingBlockRenderState` -> 取 `BlockStateModel` -> `collectParts(...)` -> `ModelBlockRenderer.tesselateBlock(...)` -> `putGhostBakedQuad(...)`，最终在最后一步压 alpha 并提交到 `VertexConsumer`。[HideNodeGhostRenderer.java](/D:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/render/HideNodeGhostRenderer.java:149)

## 4. 安全、性能、兼容性、扩展性风险分析与建议
- 兼容性：本次修复明确对齐 26.1 的真实语义，避免继续把 `BlockModelRenderState.submit(..., int)` 的最后一个参数误当模型 tint 使用；这是迁移后接口语义修正，不是新设计扩展。[HideNodeGhostRenderer.java](/D:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/render/HideNodeGhostRenderer.java:105)
- 安全性：只涉及客户端渲染，不触碰持久化、网络包或服务器逻辑，无额外安全面。
- 性能风险：`renderGhostModel(...)` 每次提交都会重新 `collectParts(...)` 并走一次 `tesselateBlock(...)`，但该路径只在玩家佩戴智能眼镜且节点进入渲染范围时触发，当前成本可接受；若后续 hide 节点数量极大且出现客户端热点，可考虑把 `ghostModelParts` 与 quad 颜色处理进一步缓存到渲染状态层。[HideNodeGhostRenderer.java](/D:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/render/HideNodeGhostRenderer.java:167)
- 扩展性：当前 `configureGhostMovingBlockState(...)` 使用 `BlockPos.ZERO` 提供 tint/light 取样上下文，足以满足现有 hide 节点显示对象；如果未来 hide 节点外显扩展到依赖真实位置/生物群系的复杂着色方块，建议把真实方块坐标写入渲染状态后再传入此处。[HideNodeGhostRenderer.java](/D:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/render/HideNodeGhostRenderer.java:198)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）
- 当前共享状态主要是渲染器实例字段 `ghostMovingBlockState`、`ghostModelParts` 和 `ghostRandom`。它们只在客户端渲染线程内由 `renderGhostModel(...)` 顺序访问，没有跨线程共享或异步回调，风险等级为低。[HideNodeGhostRenderer.java](/D:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/render/HideNodeGhostRenderer.java:52)
- `ghostModelParts.clear()` 放在 `try/finally` 中，避免中途异常导致下一次提交读到脏列表，降低了重入污染风险。[HideNodeGhostRenderer.java](/D:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/render/HideNodeGhostRenderer.java:168)
- 当前实现默认 `submitCustomGeometry(...)` 的回调在提交消费阶段串行执行；若未来 Mojang/Fabric 在更高版本调整该消费线程模型，需要重新评估把可变字段提升为局部对象或写入 render state，以彻底消除潜在线程边界变化带来的共享状态风险。[HideNodeGhostRenderer.java](/D:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/render/HideNodeGhostRenderer.java:108)
