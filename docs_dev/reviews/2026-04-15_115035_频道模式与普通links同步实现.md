## 1. 功能与语义、架构设计（关键方法和入口）
- 本次实现把“频道模式”定义为节点的另一种连接配置真值，实际生效仍统一落到普通 `triggerSource -> core` 边；数据真值与纯查询推导集中在 [LinkSavedData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedData.java#L264)、[LinkConnectionMode.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkConnectionMode.java#L10)、[LinkSavedDataChannelSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataChannelSupport.java#L119)。
- 频道编辑不再引入第二套派发生命周期，而是先计算受影响的 triggerSource，再复用普通 replace/apply 闭环改边；主入口在 [LinkChannelEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkChannelEditingService.java#L30) 和 [LinkChannelEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkChannelEditingService.java#L130)。
- serial 写入口已做模式隔离：triggerSource 的 serial 编辑会在应用前清理自身频道配置，core 视角 serial 编辑会在批量应用前清理当前 core 的频道配置；关键收口在 [LinkSetExecutionService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkSetExecutionService.java#L139)、[LinkSetExecutionService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkSetExecutionService.java#L416)、[CoreLinkEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/CoreLinkEditingService.java#L165)、[CoreLinkEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/CoreLinkEditingService.java#L245)。

## 2. 关键数据结构和算法性能分析
- 频道真值采用“按类型的 `serial -> channel` 配置表 + `channel -> members` 运行时桶索引”结构，单节点写入/清理都是 O(1) 映射与桶调整，避免每次操作全图扫描；实现见 [LinkSavedDataChannelSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataChannelSupport.java#L78) 和 [LinkSavedDataChannelSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataChannelSupport.java#L100)。
- 目标集合推导采用“只重算受影响 triggerSource”的策略：triggerSource 改频道只影响自己；core 改频道则取“当前已连来源 + 旧频道桶 + 新频道桶”的并集，避免无关来源被重复 replace；关键逻辑在 [LinkChannelEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkChannelEditingService.java#L67) 和 [LinkChannelEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkChannelEditingService.java#L154)。
- 目标推导本身是按来源局部计算的：channel 模式直接取同频道 core 桶，serial 模式只过滤当前普通边中的 channel-mode core，不做额外展开；因此复杂度约为 `O(受影响来源数 + 受影响来源现有边数)`，对应实现为 [LinkSavedDataChannelSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataChannelSupport.java#L119)。
- 频道配置已并入存档编解码与已知序号修正，避免读档后 next serial 回退或桶索引缺失；入口在 [LinkSavedDataCodecSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataCodecSupport.java#L109)、[LinkSavedDataCodecSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataCodecSupport.java#L177)、[LinkSavedDataSerialSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataSerialSupport.java#L185)、[LinkSavedDataSerialSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataSerialSupport.java#L280)。

## 3. 数据流或调用链
- pairing 打开链路：服务端读取节点当前普通边快照、模式与频道后一起下发，客户端用同一屏幕做 serial/channel 双模编辑；调用链为 [PairingNetwork.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetwork.java#L96) -> [PairingNetworkPayloadSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkPayloadSupport.java#L31) -> [PairingNetworkClientHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/network/PairingNetworkClientHandlerSupport.java#L31) -> [AbstractMultiPairingScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/AbstractMultiPairingScreen.java#L1024)。
- pairing 提交链路：客户端把 mode/channel 与表达式一并提交，服务端按 mode 分流到 serial OCC 路径或频道编辑路径，最终仍复用普通 replace apply；关键位置是 [TriggerSourcePairingScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/TriggerSourcePairingScreen.java#L227)、[CorePairingScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/CorePairingScreen.java#L204)、[PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L68)、[PairingOccSubmissionSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingOccSubmissionSupport.java#L31)、[PairingOccSubmissionSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingOccSubmissionSupport.java#L127)。
- quick-link 链路：collect 会在 channel 模式下读取节点频道号，apply 则经 OCC 适配层分流到 serial 或 channel；核心路径为 [QuickLinkCollectService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/QuickLinkCollectService.java#L36)、[QuickLinkOccSubmissionSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/QuickLinkOccSubmissionSupport.java#L81)、[QuickLinkApplyService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/QuickLinkApplyService.java#L72)、[QuickLinkApplyService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/QuickLinkApplyService.java#L244)、[QuickLinkNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetworkServerHandlerSupport.java#L151)。
- 普通边副作用链保持原样：无论 serial 还是 channel，最终都经 [LinkSetExecutionService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkSetExecutionService.java#L416) 写回普通边并触发 attach/detach 与快照同步，因此没有为频道再接第二套生命周期服务。

## 4. 安全、性能、兼容性、扩展性风险分析与建议
- 安全/权限：频道编辑最终仍逐个来源走写控与权限校验，没有绕过 readonly/limited/protected；关键保证点在 [LinkSetExecutionService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkSetExecutionService.java#L139)、[LinkChannelEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkChannelEditingService.java#L82)、[PairingOccSubmissionSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingOccSubmissionSupport.java#L268)。
- 兼容性：旧存档没有频道字段时默认仍是 serial 模式，且现有普通 links 不会丢失；加载兼容点和回归断言在 [LinkSavedDataCodecSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataCodecSupport.java#L109)、[LinkSavedDataLoadCompatibilityTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/data/LinkSavedDataLoadCompatibilityTest.java#L31)。
- 扩展性：当前 GUI 与 quick-link 都已用统一 `LinkConnectionMode` token 透传，后续若要增加更多模式，只需扩展模式枚举与对应编辑服务，不需要重做网络协议骨架；参考 [LinkConnectionMode.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkConnectionMode.java#L10)、[PairingNetworkPayloadSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkPayloadSupport.java#L66)。
- 残余风险：当前 OCC 仍主要依赖普通边 revision；若频道配置被改成另一个“展开后普通边集合完全相同”的频道，理论上可能不会被 revision 冲突拦住。该风险目前只影响少量同构频道并发编辑，未影响普通边真值正确性；相关路径在 [PairingOccSubmissionSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingOccSubmissionSupport.java#L268) 和 [LinkChannelEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkChannelEditingService.java#L130)。

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）
- 共享状态：核心共享状态仍集中在 `LinkSavedData` 的普通边索引、频道配置表和频道桶索引；写入口都在服务端主线程同步执行，未引入新的异步共享容器，参见 [LinkSavedData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedData.java#L58)、[LinkSavedDataChannelSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataChannelSupport.java#L78)。
- 读改写覆盖：serial 写入采用“必要时先清频道配置，再 apply 普通边”，core serial 编辑采用“先清当前 core 频道配置，再批量 apply 受影响来源”，从而避免旧频道真值在本次写入后回流；关键实现为 [LinkSetExecutionService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkSetExecutionService.java#L416) 与 [CoreLinkEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/CoreLinkEditingService.java#L245)。
- 重入/线程边界：network handler 只在服务端线程内分流到 OCC 与编辑服务，客户端 screen 只负责采集输入并发包，没有把频道配置直接写到本地世界状态；边界点在 [PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L68)、[QuickLinkNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetworkServerHandlerSupport.java#L151)、[AbstractMultiPairingScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/AbstractMultiPairingScreen.java#L709)。
- 风险等级：中低。当前没有新增跨线程共享写入；主要剩余风险是前述“同构频道改写 OCC 盲区”，建议后续若要进一步收紧并发语义，可为频道配置单独补一个配置 revision，并在 pairing/quick-link 提交时一并校验。
