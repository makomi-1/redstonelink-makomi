# 清除旧的全局区块扫描实现

- 当前服务端主入口只注册现行生命周期主链 `LinkNodeLifecycleDispatchEvents`，未再接入任何基于全局 `CHUNK_LOAD` 扫描的残留服务；本次清理的目标就是把这两份死代码从仓库中彻底移除，避免与现行设计并存造成误读。[RedstoneLink.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/RedstoneLink.java#L36) [RedstoneLink.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/RedstoneLink.java#L49)
- 现行生命周期语义已经明确切换为“节点实例自发布 attach/detach + 服务端 tick 预算化消费”，不再依赖全局 `CHUNK_LOAD/CHUNK_UNLOAD` 扫描；删除旧扫描实现不会改变当前设计语义，只会移除历史残留实现面。[LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L27) [LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L53)
- 节点实例侧的 attach/detach 发布入口已经内聚在 `PairableNodeBlockEntity` 生命周期方法中，因此核心事件触发点仍完整保留，旧扫描服务并非现行必要依赖。[PairableNodeBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/PairableNodeBlockEntity.java#L217) [PairableNodeBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/PairableNodeBlockEntity.java#L241)

## 2. 关键数据结构和算法性能分析
- 现行实现的核心数据结构是 `LinkNodeLifecycleDispatchEvents` 内的 `STATE_BY_SERVER` 与每服 `pendingTasks`，消费时按预算 drain 并对 attach 任务有限重试；这比旧的 `CHUNK_LOAD` 扫描区块方块实体更接近命中式处理，常态复杂度由“区块内方块实体数”收敛为“待处理生命周期任务数”。[LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L44) [LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L131) [LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L143)
- `consumeAttachTask(...)` 在命中具体节点后直接完成在线登记、`core` 加载校正、`triggerSource` 输入静默重采样、source attach replay 与 target chunk load replay，不再需要先全块扫描再筛选。[LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L170) [LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L190) [LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L217)
- `core` 与 `triggerSource` 仍各自保留 pending 标记接口，但消费责任已经收敛到生命周期主链中；删除旧扫描服务不会丢掉这些状态位的语义承载。[ActivatableTargetBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/ActivatableTargetBlockEntity.java#L473) [LinkTriggerSourceBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/LinkTriggerSourceBlockEntity.java#L92)

## 3. 数据流或调用链
- 当前 attach 链路是：节点实例 `clearRemoved()` / `flushPendingContextAttachIfReady()` 发布 attach，生命周期桥接器在 tick 末消费任务并定位目标 block entity，再继续执行后续 replay / resync。[PairableNodeBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/PairableNodeBlockEntity.java#L181) [PairableNodeBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/PairableNodeBlockEntity.java#L241) [LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L64) [LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L170)
- attach 命中后，`core` 的加载校正通过 `consumePendingLoadBlockStateSync()` 完成，`triggerSource` 的加载后静默输入重采样通过 `resyncPoweredStateFromCurrentInputsWithoutTrigger(...)` + `clearPendingLoadInputStateResync()` 完成，说明旧扫描服务中的职责已经被现行主链吸收。[LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L193) [LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L197)
- target 侧 reload replay 仍通过 `CrossChunkDispatchService.notifyTargetChunkLoaded(...)` 唤醒等待中的 pending，然后按配置决定是否继续做 target chunk load replay；这条现行调用链与旧扫描服务无关，因此本次删除不会改变该路径行为。[LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L217) [CrossChunkDispatchService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CrossChunkDispatchService.java#L519)

## 4. 安全、性能、兼容性、扩展性风险分析与建议
- 安全与兼容性：本次改动没有变更配置键、存档结构、节点方向语义或外部 API，只是移除未注册的历史实现，因此运行时兼容风险低；`triggerSource/core` 方向语义保持不变。[RedstoneLink.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/RedstoneLink.java#L49) [LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L209) [LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L213)
- 性能：删除旧扫描实现后，仓库不再保留误导性的全块扫描备选路径；现行主链继续以命中式生命周期任务推进，避免未来维护时误把扫描式逻辑重新接回主路径。[LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L29) [LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L131)
- 扩展性：若后续还要补“异常恢复/诊断型扫描”，建议单独做显式诊断工具或 bench 辅助入口，不要再复活隐式 `CHUNK_LOAD` 扫描服务，以免再次与节点命中式生命周期主链并行。[RedstoneLink.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/RedstoneLink.java#L47) [LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L27)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）
- 现行生命周期共享状态集中在 `STATE_BY_SERVER` 与每服 `pendingTasks`，服务端停止边界用同步块清理，tick 消费则在服务端主线程执行；本次删除旧扫描服务后，没有新增共享状态，也没有引入新的读改写覆盖面。[LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L44) [LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L122) [LinkNodeLifecycleDispatchEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeLifecycleDispatchEvents.java#L131)

- 建议：继续把生命周期相关处理统一收束在 `LinkNodeLifecycleDispatchEvents` 主链与其显式子调用中，避免重新引入“同一语义两套入口”的并发/重入歧义。[RedstoneLink.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/RedstoneLink.java#L49) [PairableNodeBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/PairableNodeBlockEntity.java#L223) [PairableNodeBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/PairableNodeBlockEntity.java#L248)
