# hide扩展与幽灵渲染迁移

## 1. 功能与语义、架构设计（关键方法和入口）

- 本次迁移把 1.21.11 的 hide 扩展方块、方块实体、客户端幽灵渲染、容器分类与资源注册整体补齐到 26.1，注册总入口位于 [ModBlocks.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/registry/ModBlocks.java#L96)、[ModBlockEntities.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/registry/ModBlockEntities.java#L71) 与 [RedstoneLinkClient.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/RedstoneLinkClient.java#L128)。
- 语义层继续保持 `triggerSource/core` 基线不变，hide 只是普通节点的隐藏形态，不改变节点方向和内部类型映射；幽灵显示统一通过 [HideNodeSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/data/HideNodeSupport.java#L29) 判定并在 [HideNodeSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/data/HideNodeSupport.java#L64) 映射到普通显示状态。
- 客户端渲染采用“普通外显继续复用、hide 额外补一层半透明普通模型”的方式，过滤器与区块激活器分别落在 [HideFilterGhostRenderer.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/render/HideFilterGhostRenderer.java#L24) 与 [HideChunkActivatorGhostRenderer.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/render/HideChunkActivatorGhostRenderer.java#L24)，基础几何提交支撑位于 [HideGhostRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/render/HideGhostRenderSupport.java#L25)。

## 2. 关键数据结构和算法性能分析

- `HideNodeSupport` 只维护隐藏节点集合判定与状态映射，所有判断都是固定分支，复杂度为 O(1)；关键判定口位于 [HideNodeSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/data/HideNodeSupport.java#L36) 与 [HideNodeSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/data/HideNodeSupport.java#L50)。
- 幽灵模型渲染沿用 26.1 的 `BlockStateModelSet + ModelBlockRenderer` 管线，只对 vanilla 已计算的顶点颜色压缩 alpha，不重复做 tint 计算；关键实现位于 [HideGhostRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/render/HideGhostRenderSupport.java#L35) 与 [HideGhostRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/render/HideGhostRenderSupport.java#L107)。
- 智能节点容器只额外把 `HIDE_REPEATER` 归并到既有 `REPEATER` 分类，不新增新的容器种类和扫描结构，分类口仍为 O(1) 分支判断，落点在 [SmartNodeContainerData.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/data/SmartNodeContainerData.java#L223)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 兼容性方面，本次没有引入 `com.makomi.api.v1.*` 依赖，也没有新增旧术语输出；hide 触发源仍通过 `LinkNodeType.TRIGGER_SOURCE` 进入既有容器与配对逻辑，方向约束未被放宽，影响点集中在 [ModItems.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/registry/ModItems.java#L129)。
- 资源风险方面，hide 物品模型改为引用 `block/*_hide.png` 纹理后，如果缺失对应贴图，客户端会在资源烘焙阶段退化为紫黑占位；本次通过补齐 `textures/block/*_hide.png` 与配套 item/blockstate/model/recipe 资源解决，契约测试位于 [RecipeResourceLayoutTest.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/test/java/com/makomi/RecipeResourceLayoutTest.java#L26)。
- 渲染风险方面，26.1 已不兼容旧版直接取 `BlockRenderer` 的实现路径，因此后续凡是继续迁移类似 ghost/block-model 渲染，建议继续复用 [HideGhostRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/render/HideGhostRenderSupport.java#L46) 这套 26.1 原生模型提交链，而不要再回退到旧版接口。

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- hide 注册与资源迁移全部发生在模组初始化和资源加载阶段，没有引入新的跨线程共享可变状态；风险等级为低，入口集中在 [RedstoneLinkClient.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/RedstoneLinkClient.java#L93)。
- 智能节点容器的临时槽位写回仍然只在服务端主线程处理包时执行，并且先校验候选集合再写入，减少了非法索引覆盖已有容器状态的风险，关键校验口位于 [SmartNodeContainerNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/network/SmartNodeContainerNetworkServerHandlerSupport.java#L69)。
- 幽灵渲染状态对象是每个方块实体渲染帧内临时构造与填充，不向全局缓存回写方块状态；当前没有新增重入问题。后续若为性能引入模型缓存，应保持“缓存只读、状态每帧重算”的边界，避免不同 hide 方块间颜色或光照串用。
