# 配方生成

## 1. 功能与语义、架构设计

- datagen 入口现在由 `RedstoneLinkDataGenerator` 显式创建 `Pack` 并注册 `RedstoneLinkRecipeProvider`，把原来的空入口变成真实配方生成入口，集中维护 18 个配方定义。[RedstoneLinkDataGenerator.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/RedstoneLinkDataGenerator.java#L10) [RedstoneLinkRecipeProvider.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/datagen/RedstoneLinkRecipeProvider.java#L26)
- `RedstoneLinkRecipeProvider` 通过 `buildRecipes` 统一调度 shaped/shapeless 配方与 tag 依赖，避免再靠分散 JSON 人工维护入口逻辑。[RedstoneLinkRecipeProvider.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/datagen/RedstoneLinkRecipeProvider.java#L49)
- 运行时资源口径被 `RecipeResourceLayoutTest` 锁定为单数 `recipe/` 目录且固定 18 个文件，防止目录回退或配方缺失。[RecipeResourceLayoutTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/RecipeResourceLayoutTest.java#L23)

## 2. 关键数据结构和算法性能分析

- provider 内部只保留 3 个不可变 `TagKey<Item>` 常量和一组小型 helper，生成复杂度固定为 O(18)，不存在随运行时数据增长而扩张的路径。[RedstoneLinkRecipeProvider.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/datagen/RedstoneLinkRecipeProvider.java#L27)
- `buildLinkBaseRecipe`、`buildLinkerRecipe`、`buildTransparentCoreSwapRecipe` 复用了统一模板，减少重复定义和维护面，同时保持每个配方输出为常量时间构造。[RedstoneLinkRecipeProvider.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/datagen/RedstoneLinkRecipeProvider.java#L110)
- 目录契约测试使用 `Set<String>` 与 `TreeSet` 收集文件名，数据规模仅 18 个文件，排序和比较成本极低，适合作为 stable-core 门禁。[RecipeResourceLayoutTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/RecipeResourceLayoutTest.java#L24)

## 3. 数据流或调用链

- 构建时调用链为 `Gradle runDatagen -> fabricApi.configureDataGeneration -> RedstoneLinkDataGenerator.onInitializeDataGenerator -> RedstoneLinkRecipeProvider.buildRecipes`，数据输出不再依赖空入口或人工脚本拼接。[build.gradle](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/build.gradle#L62) [RedstoneLinkDataGenerator.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/RedstoneLinkDataGenerator.java#L17) [RedstoneLinkRecipeProvider.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/datagen/RedstoneLinkRecipeProvider.java#L50)
- 运行时资源仍然从 `src/main/resources/data/redstonelink/recipe` 读取，而不是直接依赖 datagen 目录；测试只验证资源布局与文件清单，确保发布路径和维护路径解耦。[RecipeResourceLayoutTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/RecipeResourceLayoutTest.java#L51)
- datagen 输出目录被切到 `build/generated/datagen` 且不自动并入资源源集，消除了“生成物和运行时资源重复打包”的处理链冲突。[build.gradle](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/build.gradle#L63)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 兼容性风险已从“目录猜测”改为“目录契约”，当前实现明确对齐本地 `1.21.1` 的单数 `recipe/` 口径；若未来 Minecraft/Fabric 改变目录规则，需要优先复核 datagen 实际输出，再调整测试和资源路径。[RecipeResourceLayoutTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/RecipeResourceLayoutTest.java#L47)
- 构建风险主要来自 datagen 输出与运行时资源重复打包，现已通过 `addToResources = false` 和独立 `build/` 输出目录隔离；建议后续继续保持“运行时资源手工保留，datagen 只做维护校验”的边界，不要重新接回资源源集。[build.gradle](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/build.gradle#L63)
- 扩展时若新增第 19 个配方，需要同步修改 provider 和 `EXPECTED_RECIPE_FILES`，否则 stable-core 会直接报警；这类强约束是有意的，用来阻止静默遗漏。[RedstoneLinkRecipeProvider.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/datagen/RedstoneLinkRecipeProvider.java#L50) [RecipeResourceLayoutTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/RecipeResourceLayoutTest.java#L26)

## 5. 并发冲突审查

- 本次改动全部位于构建期和测试期路径，没有触及 `LinkSavedData`、网络处理器或任何运行时共享状态；核心逻辑只是把配方常量写入 `RecipeOutput`，无读改写覆盖风险。[RedstoneLinkRecipeProvider.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/datagen/RedstoneLinkRecipeProvider.java#L50)
- `RedstoneLinkDataGenerator` 只在 datagen 初始化阶段注册 provider，不持有可变共享字段，也不存在重入入口。[RedstoneLinkDataGenerator.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/RedstoneLinkDataGenerator.java#L17)
- 风险等级评估为低；唯一需要持续关注的是构建链上的目录配置漂移，而这属于资源编排问题，不是线程边界问题，已经由 `build.gradle` 配置和 stable-core 测试共同兜底。[build.gradle](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/build.gradle#L63) [RecipeResourceLayoutTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/RecipeResourceLayoutTest.java#L63)
