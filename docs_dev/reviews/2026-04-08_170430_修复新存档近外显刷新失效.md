## 1. 功能与语义、架构设计（关键方法和入口）
- 本次修复收口在近外显服务端节流层：当单端切换新存档导致 `gameTime` 回绕时，先清除当前玩家残留的旧 tick，再继续按当前世界 tick 建立新的节流基线，避免“当前连接/最终 I/O”回包被旧世界窗口长期吞掉。关键入口见 [PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L266)、[PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L278)、[PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L292)。
- 为了把“新世界回绕”语义显式化，新增 `hasTickRewound(...)` helper，统一表达“当前世界 tick 小于历史基线”这一判定，避免负差值继续被解释成“仍在节流窗口内”。对应实现见 [PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L300)。
- 回归测试补上了两条核心语义约束：tick 回绕后必须放行，且回绕识别逻辑要能稳定命中单端新世界重开场景。对应测试见 [PairingNetworkServerHandlerSupportTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/network/PairingNetworkServerHandlerSupportTest.java#L45)、[PairingNetworkServerHandlerSupportTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/network/PairingNetworkServerHandlerSupportTest.java#L53)。

## 2. 关键数据结构和算法性能分析
- 现有节流仍沿用 `Map<UUID, Long>` 记录最近一次请求 tick，本次没有改变数据结构规模和访问复杂度；请求路径仍是 `O(1)` 查询/更新，关键点在 [PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L276)。
- 全局清理逻辑保留原来的按阈值定期裁剪策略，只是在检测到 tick 回绕时先整体清空两张节流表，随后再按当前 `nowTick` 重新建立清理节拍；这一步是有限大小 HashMap 的 `O(n)` 清理，但仅发生在世界重开边界，运行时成本可忽略。实现位置见 [PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L314)。
- 单条记录的失效判定从单纯“超过陈旧阈值”扩展为“超过阈值或 tick 回绕”，仍是常数时间判断，不增加近外显常规请求路径的额外复杂度。实现位置见 [PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L348)。

## 3. 数据流或调用链
- 客户端命中近外显节点后，会向服务端发送 `RequestCurrentLinksPayload` 或 `RequestRuntimeHudSnapshotPayload`；服务端统一经 `isOverlayRequestThrottled(...)` 做节流判定。修复后，若检测到 tick 回绕，会先重置旧世界残留状态再继续当前请求。关键链路见 [PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L266)、[PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L282)。
- 当世界级清理时钟也发生回绕时，`cleanupThrottleStateIfNeeded(...)` 会先清空“当前连接/最终 I/O”两类节流表，避免因为旧 `lastThrottleCleanupTick` 更大而永远跳过后续清理。关键逻辑见 [PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L315)、[PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L327)。
- 测试链路覆盖了“正常窗口内拒绝”“窗口边界放行”“非法间隔兜底”“tick 回绕放行”四类关键判定，保证这次修复不会破坏既有节流语义。测试入口见 [PairingNetworkServerHandlerSupportTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/network/PairingNetworkServerHandlerSupportTest.java#L22)、[PairingNetworkServerHandlerSupportTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/network/PairingNetworkServerHandlerSupportTest.java#L48)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议
- 安全性：本次不放宽权限门槛、不改协议字段、不改可见数据裁剪，仅修复错误节流，因此不会扩大“当前连接/最终 I/O”可见范围。相关入口仍受原有请求校验与权限控制约束，影响范围局限于节流行为，见 [PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L266)。
- 性能：tick 回绕检查是常数时间分支，只有世界重开边界会触发整表清空；相比原问题导致的新世界长时间反复空请求，这次修复反而减少了无效轮询成本。关键点见 [PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L315)、[PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L348)。
- 兼容性：不涉及 `triggerSource/core` 映射、不涉及存档 NBT、不涉及 API 依赖，属于纯运行时逻辑修复；旧档、新档和现有近外显协议都可直接复用。语义回归由测试覆盖，见 [PairingNetworkServerHandlerSupportTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/network/PairingNetworkServerHandlerSupportTest.java#L56)。
- 扩展性建议：如果后续其它网络节流模块也使用“静态 tick 基线 + 世界可重开”的模式，建议抽出统一的 tick 回绕工具，避免同类 bug 在 QuickLink/StatePanel 等链路重复出现。本次暂未外提，保持最小修复范围。

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）
- 共享状态：本次涉及的共享状态为 `LAST_CURRENT_LINKS_REQUEST_TICK_BY_PLAYER`、`LAST_RUNTIME_HUD_REQUEST_TICK_BY_PLAYER` 和 `lastThrottleCleanupTick`，它们仍是静态可变状态。关键位置见 [PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L278)、[PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L315)。
- 线程边界：服务端接包注册器已把处理统一切回 `player.server.execute(...)`，因此这些静态表的读改写仍发生在服务端主线程，不引入新的并发访问模型。相关入口见 [PairingNetworkRegistrationSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkRegistrationSupport.java#L76)、[PairingNetworkRegistrationSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkRegistrationSupport.java#L83)。
- 读改写覆盖风险：tick 回绕时会执行“按玩家移除旧记录”或“全表清空旧世界记录”，这些操作都以“旧世界状态不应跨世界继承”为前提，不会覆盖当前世界已建立的新基线；同一请求内移除后立即回写新 `nowTick`，状态闭环完整。实现见 [PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L278)、[PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L285)。
- 风险等级：低。原因是没有引入新的线程共享面，只是修正了旧静态状态跨世界复用的错误边界。
- 建议：后续若把近外显请求迁移到异步执行或独立调度线程，需要同步把这些静态表替换为线程安全容器或收敛到单线程 actor 模式；当前实现无需额外并发防护。
