# 修复频道迁回序号后首次add_remove基线

## 1. 功能与语义、架构设计（关键方法和入口）

本轮修复把“频道模式迁回序号模式后，第一次序号 `add/remove` 的显式边基线”从“导出图当前有效目标集合”收敛为“空的显式 serial 边集合”。实现上新增 `isTriggerSourceReturningToSerial(...)` 与 `resolveExplicitSerialBaseTargetSerials(...)`，统一识别“base 为 channel、草稿中 `triggerSource -> 0`”的来源节点；后续 `resolveEffectiveTargetSerials(...)`、`upsertReplaceTargetsDraft(...)`、`applyDraftToGraph(...)` 与 `buildDraftDiff(...)` 都复用同一口径，避免草稿折算、画布预览和差异统计各自漂移。[draft.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.ts#L107) [draft.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.ts#L135) [draft.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.ts#L149) [draft.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.ts#L210) [draft.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.ts#L351) [draft.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.ts#L495)

语义上，`replace` 仍然保持“整体覆盖显式目标集合”；普通 serial 来源节点的 `add/remove` 也不变，只有命中“频道迁回 serial”的来源节点，才会在首次显式编辑时从空集起算。[draft.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.ts#L287)

## 2. 关键数据结构和算法性能分析

新增的判断逻辑只围绕既有 `GraphDraft.operations` 做线性扫描，并利用现有数组/集合归一化流程，不引入新的高复杂度结构。`resolveExplicitSerialBaseTargetSerials(...)` 只是一个轻量分流：命中迁回场景直接返回空数组，否则继续沿用原有 `resolveBaseTargetSerials(...)`；整体复杂度仍由批量编辑时对来源节点的线性遍历主导。[draft.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.ts#L135) [draft.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.ts#L287)

`applyDraftToGraph(...)` 现在会在构造 `explicitEdges` 时额外过滤“迁回 serial 但尚未显式 replace”的来源节点旧边，这属于对已有边列表的一次常数级附加判断，不改变总体时间复杂度，仍是按节点和边线性扫描。[draft.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.ts#L351)

## 3. 数据流或调用链

本轮关键数据流为：`applyChannelEditToDraft(...)` 先写入 `SetNodeChannel` 草稿；当用户随后在序号模式执行 `add/remove` 时，`applyBatchEditToDraft(...)` 会通过 `resolveEffectiveTargetSerials(...)` 读取显式边基线，命中“迁回 serial”时直接按空集折算，再写入 `ReplaceTriggerSourceTargets`。之后 `applyDraftToGraph(...)` 用同一判定过滤掉旧频道边，使画布预览和实际草稿语义一致；`buildDraftDiff(...)` 则复用相同基线统计受影响节点，保证高亮与边差异不漂移。[draft.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.ts#L149) [draft.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.ts#L287) [draft.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.ts#L351) [draft.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.ts#L495)

测试层新增两条纯逻辑回归：一条验证迁回后当前目标集合与草稿图边都归零；另一条验证迁回后的第一次 `add` 只从空显式边开始追加，不再带入旧频道目标。[draft.test.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.test.ts#L66) [draft.test.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.test.ts#L106)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

安全层面，本轮只改前端草稿折算与本地预览，不触及后端协议、权限或持久化格式，风险低。兼容性方面，变化是有意的行为收敛：频道迁回 serial 后，第一次 `add/remove` 不再继承频道态旧目标；这会改变旧前端的隐式继承行为，但与“显式 serial 边编辑”语义更一致。[draft.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.ts#L107) [draft.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.ts#L287)

残余风险在于：如果未来需要支持“迁回 serial 时可选地保留频道当前有效目标并固化成显式边”，则不能再依赖当前的“空基线”策略，而应在迁回动作本身生成一份显式 `replace` 草稿。当前实现没有封死这条扩展路径，后续可继续在 `draft.ts` 增加新的模式分支，不必改后端协议。[draft.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.ts#L210)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

本轮改动全部位于前端纯函数层，没有新增 React 共享状态，也没有引入异步写回链路；输入是 `GraphSnapshotBundle + GraphDraft`，输出是新的草稿或派生图，因此不存在跨线程共享可变状态问题。风险等级为低。[draft.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.ts#L149) [draft.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.ts#L351)

需要关注的读改写边界主要是“同一来源节点的 `SetNodeChannel` 与 `ReplaceTriggerSourceTargets` 组合语义”。本轮通过统一 helper 收口，避免了不同函数各自读 `graphDraft.operations` 时出现“一个按空基线、一个按旧边基线”的逻辑覆盖，因此重入/顺序风险较前一版本更低。建议后续继续保持“迁回判定 helper 单点收口”的结构，不要在别处再复制条件判断。[draft.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.ts#L107) [draft.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.ts#L135)
