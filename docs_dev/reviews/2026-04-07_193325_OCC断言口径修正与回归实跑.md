# OCC 断言口径修正与回归实跑

## 1. 功能与语义、架构设计（关键方法和入口）

本轮没有改 OCC 提交实现，只修正 OCC functional case 对 `redstonelink link get` 返回文案的断言口径。`link get` 命令本身由 [LinkCommandRegistry.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkCommandRegistry.java#L149) 调用 `message.redstonelink.link.get` 输出，其中英文文案使用 `targets=%s`，[en_us.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/assets/redstonelink/lang/en_us.json#L287)；中文文案使用 `目标列表=%s`，[zh_cn.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/assets/redstonelink/lang/zh_cn.json#L287)。因此 4 个 OCC case 的 `link get` 断言统一改成兼容 `targets=` / `目标列表=`，避免继续把英文输出误判为失败，见 [occ_pairing_trigger_source_conflict.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/o01/occ_pairing_trigger_source_conflict.json#L68)、[occ_pairing_core_conflict.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/o02/occ_pairing_core_conflict.json#L68)、[occ_quick_link_trigger_source_conflict.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/o03/occ_quick_link_trigger_source_conflict.json#L68)、[occ_quick_link_core_conflict.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/o04/occ_quick_link_core_conflict.json#L68)。

## 2. 关键数据结构和算法性能分析

改动仅限 JSON 断言模板，不新增数据结构，也不改变 bench 执行流程。运行时新增成本仅是正则字面量由单分支变成双分支匹配，复杂度仍然是对单条命令响应做线性扫描，影响可忽略。涉及的正反断言位于 [occ_pairing_trigger_source_conflict.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/o01/occ_pairing_trigger_source_conflict.json#L69)、[occ_pairing_core_conflict.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/o02/occ_pairing_core_conflict.json#L69)、[occ_pairing_core_conflict.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/o02/occ_pairing_core_conflict.json#L79)、[occ_quick_link_trigger_source_conflict.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/o03/occ_quick_link_trigger_source_conflict.json#L69)、[occ_quick_link_core_conflict.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/o04/occ_quick_link_core_conflict.json#L69)、[occ_quick_link_core_conflict.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/o04/occ_quick_link_core_conflict.json#L79)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

本轮修复后，OCC 专项 suite 已能覆盖英文 `targets=` 与中文 `目标列表=` 两种 `link get` 输出，兼容 dedicated bench 常见的英文控制台源与本地中文环境。残余风险是还有旧 functional case 仍写着 `target_list` 英文断言，例如 [server_permission_read_write_basic.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/c07/server_permission_read_write_basic.json#L66)、[server_permission_read_write_basic.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/c07/server_permission_read_write_basic.json#L69)、[server_permission_read_write_basic.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/c07/server_permission_read_write_basic.json#L81)、[server_permission_read_write_basic.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/c07/server_permission_read_write_basic.json#L103)。这些文件若以后也通过英文命令源执行，仍可能出现同类误报，建议后续统一扫描并收敛 `link get`/`node get` 断言口径。

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

本轮改动不引入新的共享可变状态，风险等级为低。原因有两层：一是改动面只在静态 case JSON，不会改写 OCC 运行态共享数据；二是 dedicated suite 仍采用“每 case 一个新档”的隔离执行模型，[run-bench-suite.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/run-bench-suite.ps1#L5)、[run-bench-suite.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/run-bench-suite.ps1#L6)、[run-bench-suite.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/run-bench-suite.ps1#L9)、[run-bench-suite.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/run-bench-suite.ps1#L10)，配合专项 suite 的分 entry 调度 [occ-conflict-regression.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/suites/occ-conflict-regression.json#L10) 到 [occ-conflict-regression.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/suites/occ-conflict-regression.json#L22)，避免了多 case 共享世界导致的读改写覆盖。建议继续保持 dry-run 与 dedicated 实跑都使用独立 `SavePath` / world，避免把历史的路径竞争重新带回回归流程。
