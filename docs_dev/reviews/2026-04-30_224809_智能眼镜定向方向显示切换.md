# 智能眼镜定向方向显示切换

## 1. 功能与语义、架构设计（关键方法和入口）

- 本轮把“智能眼镜方向箭头持续显示”建模为客户端本地显示配置，新增到 `RedstoneLinkClientOverlayConfig` 中，而不是写入物品、节点或服务端状态，保持它作为纯观察层能力的边界。[RedstoneLinkClientOverlayConfig.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/config/RedstoneLinkClientOverlayConfig.java#L9)
- 客户端配置门面新增了开关读取与切换入口，所有状态切换都通过 `RedstoneLinkClientDisplayConfig` 聚合处理，避免在渲染器或物品 tooltip 中散落写配置逻辑。[RedstoneLinkClientDisplayConfig.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/config/RedstoneLinkClientDisplayConfig.java#L163)
- `RedstoneLinkClient` 新增了 `Ctrl + K` 的客户端按键分流：裸 `K` 仍切序号外显，`Ctrl + K` 只切智能眼镜方向箭头显示，从交互层面保持两个功能共键但不抢语义。[RedstoneLinkClient.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/RedstoneLinkClient.java#L79) [RedstoneLinkClient.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/RedstoneLinkClient.java#L185) [RedstoneLinkClient.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/RedstoneLinkClient.java#L252)
- 定向箭头显示判定被改成并集：手持定向面编辑工具，或智能眼镜持续显示开关开启，任一成立即可；但世界后置渲染层仍保留“必须佩戴智能眼镜”的总门槛，因此没有削弱 hide/overlay 的整体语义边界。[DirectionalFaceVectorRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/DirectionalFaceVectorRenderSupport.java#L76) [DirectionalFaceVectorWorldOverlayRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/DirectionalFaceVectorWorldOverlayRenderer.java#L41)
- 智能眼镜 tooltip 补充了 `Ctrl + K` 的用户入口提示，确保玩家不需要先读文档也能发现新功能。[SmartGlassesItem.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/item/SmartGlassesItem.java#L55)

## 2. 关键数据结构和算法性能分析

- 新增状态仅是 `overlay` 配置中的一个 `InputConstants.Key` 和一个 `boolean`，存储规模固定，解析和写回成本都是 O(1)，不会对客户端配置读写产生结构性负担。[RedstoneLinkClientOverlayConfig.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/config/RedstoneLinkClientOverlayConfig.java#L9)
- 配置解析器通过固定键名补读新字段，仍沿用现有的键解析和布尔解析路径，没有引入新的动态扫描或额外 I/O 轮次。[RedstoneLinkClientDisplayParser.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/config/RedstoneLinkClientDisplayParser.java#L15) [RedstoneLinkClientDisplayParser.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/config/RedstoneLinkClientDisplayParser.java#L50)
- 按键分流只是在客户端每 tick 的原有 `consumeClick()` 循环中多加一层 `Ctrl` 判断，复杂度仍与按键事件数线性相关，且一般只有常数级点击量，不构成性能热点。[RedstoneLinkClient.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/RedstoneLinkClient.java#L208) [RedstoneLinkClient.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/RedstoneLinkClient.java#L230)
- 渲染侧只是把“是否显示箭头”从单条件扩展为并集判断，没有增加新的世界扫描或额外渲染遍历，因此渲染成本只与原有箭头显示目标数量一致。[DirectionalFaceVectorRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/DirectionalFaceVectorRenderSupport.java#L76)

## 3. 数据流或调用链

- 调用链起点是客户端显示配置默认值：`defaults()` 给出基础键位 `K` 和默认关闭状态，随后 `load()` 通过解析器落成快照对象。[RedstoneLinkClientDisplaySnapshot.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/config/RedstoneLinkClientDisplaySnapshot.java#L16) [RedstoneLinkClientDisplayParser.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/config/RedstoneLinkClientDisplayParser.java#L37)
- `RedstoneLinkClient.registerClientKeyBindings()` 读取配置中的基础键位，注册独立 keybinding，并在客户端 tick 中按 `Ctrl` 分流到“序号外显切换”或“方向箭头切换”处理函数。[RedstoneLinkClient.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/RedstoneLinkClient.java#L185) [RedstoneLinkClient.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/RedstoneLinkClient.java#L252)
- 当方向箭头切换执行后，`RedstoneLinkClientDisplayConfig.toggleSmartGlassesFaceVectorEnabled()` 会刷新内存快照并写回客户端配置模板，保证重启后保持一致。[RedstoneLinkClientDisplayConfig.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/config/RedstoneLinkClientDisplayConfig.java#L170) [RedstoneLinkClientDisplayTemplate.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/config/RedstoneLinkClientDisplayTemplate.java#L43)
- 世界渲染链路中，`DirectionalFaceVectorWorldOverlayRenderer` 先验证“是否佩戴智能眼镜”，再调用 `DirectionalFaceVectorRenderSupport.shouldRenderFaceVectors()` 做并集判定，最终进入已有箭头渲染路径。[DirectionalFaceVectorWorldOverlayRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/DirectionalFaceVectorWorldOverlayRenderer.java#L41) [DirectionalFaceVectorRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/DirectionalFaceVectorRenderSupport.java#L76)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全性：本轮没有新增网络包、服务端状态或权限面，所有能力都停留在本地显示层，因此没有扩大 `triggerSource/core` 真值链的攻击面。[RedstoneLinkClient.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/RedstoneLinkClient.java#L252)
- 性能：持续显示方向箭头会提高玩家在佩戴智能眼镜时的箭头可见时间，但显示目标集合仍沿用原有“已在视野且可渲染的节点”范围，没有新增额外查询层。若后续需要进一步控量，可只在配置层再加距离或类别筛选，而无需重写当前入口。[DirectionalFaceVectorRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/DirectionalFaceVectorRenderSupport.java#L102)
- 兼容性：旧客户端配置文件没有新键时，会按默认 `Ctrl + K` 和关闭状态回退；因此本轮属于“读旧写新”，不会破坏现有本地配置文件。[RedstoneLinkClientDisplayParser.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/config/RedstoneLinkClientDisplayParser.java#L15) [RedstoneLinkClientDisplayParserTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/client/config/RedstoneLinkClientDisplayParserTest.java#L64)
- 扩展性：当前把方向箭头开关挂在 `overlay` 配置域中，后续若还想给智能眼镜继续扩“显示节点边界”“显示过滤范围”等观察型开关，可以沿用同一客户端显示配置模型，不需要再为每个显示项单独造持久化入口。[RedstoneLinkClientOverlayConfig.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/config/RedstoneLinkClientOverlayConfig.java#L9)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- 共享状态主要是客户端静态配置快照 `snapshot`。本轮切换逻辑仍然只在客户端主线程 tick 中调用，不涉及后台线程并发改写，因此没有新增跨线程竞争点；风险等级为低。[RedstoneLinkClientDisplayConfig.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/config/RedstoneLinkClientDisplayConfig.java#L17) [RedstoneLinkClientDisplayConfig.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/config/RedstoneLinkClientDisplayConfig.java#L170)
- `Ctrl + K` 与裸 `K` 共用同一物理键位，但这轮在客户端 tick 中用 `Screen.hasControlDown()` 做了显式分流，因此不会出现两个功能在一次按键中同时生效的语义冲突；风险等级为低。[RedstoneLinkClient.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/RedstoneLinkClient.java#L208) [RedstoneLinkClient.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/RedstoneLinkClient.java#L230)
- 配置写回仍是“读当前快照 -> 构造新快照 -> 覆盖旧快照 -> 写文件”的单线程流程，没有把部分字段拆成多入口独立写回，因此没有引入读改写覆盖的新增风险；风险等级为低。[RedstoneLinkClientDisplayConfig.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/config/RedstoneLinkClientDisplayConfig.java#L170) [RedstoneLinkClientDisplayTemplate.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/config/RedstoneLinkClientDisplayTemplate.java#L12)
