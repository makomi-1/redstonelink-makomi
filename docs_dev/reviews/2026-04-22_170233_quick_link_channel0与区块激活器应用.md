## 2. 关键数据结构和算法性能分析
- 区块激活器 quick-link 沿用现有“有序去重序号集合”策略，先解析缓存表达式，再基于三态 `replace/append/remove` 合成新的 active 节点集，关键构造逻辑在 [QuickLinkApplyService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/QuickLinkApplyService.java#L628) 与 [QuickLinkApplyService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/QuickLinkApplyService.java#L646)。
- 算法复杂度保持在线性级别：解析与归一化均是对最多 32 个区块激活器节点或配置允许长度内的 quick-link 输入做单次遍历，没有引入额外的图遍历或全表扫描；resident 容量预估复用现有服务，不额外缓存新索引，调用点在 [QuickLinkApplyService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/QuickLinkApplyService.java#L282) 与 [QuickLinkApplyService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/QuickLinkApplyService.java#L798)。
- `channel=0` 放行后，节点仍然复用既有 `LinkChannelEditingService` 覆盖计划，不增加新的批处理结构或额外命令成本模型，调用入口在 [QuickLinkApplyService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/QuickLinkApplyService.java#L370)。

## 3. 数据流或调用链
- quick-link apply 调用链现在是：客户端命中解析 -> 发 baseline 请求 -> 服务端校验目标 -> 按目标类型分发到节点 / 过滤器 / 区块激活器，主要链路可从 [QuickLinkNetworkClientHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/network/QuickLinkNetworkClientHandlerSupport.java#L89)、[QuickLinkNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetworkServerHandlerSupport.java#L108)、[QuickLinkNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetworkServerHandlerSupport.java#L125) 追踪。
- 区块激活器分支的数据落地流程是：构造新 active 配置快照 -> 校验 resident 上限 -> 通过方块实体统一应用并同步到持久化真值，分别对应 [QuickLinkApplyService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/QuickLinkApplyService.java#L263)、[QuickLinkApplyService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/QuickLinkApplyService.java#L275)、[LinkChunkActivatorBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/LinkChunkActivatorBlockEntity.java#L75)。
- 过滤器分支的数据流保持“只改目标配置，不改其它运行参数”，但放开了 `channel=0` 透传，入口在 [QuickLinkApplyService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/QuickLinkApplyService.java#L112)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议
- 安全：区块激活器 quick-link 与编辑器保存保持同一权限口径，仍要求命令权限，避免普通交互绕过配置写入限制，见 [QuickLinkApplyService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/QuickLinkApplyService.java#L223)。
- 兼容性：旧 quick-link `channel` 缓存为空时仍会被 `parseChannelOrZero()` 归一成 `0`，不会破坏现有物品数据读取；同时 `channel=0` 在节点侧明确映射为“切回序号模式”，降低了过去“被当成非法值”的行为偏差，见 [QuickLinkToolData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/QuickLinkToolData.java#L159) 与 [QuickLinkApplyService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/QuickLinkApplyService.java#L370)。
- 扩展性：区块激活器目标使用独立 token 接入 quick-link 协议，后续若还要给其它“非节点、非过滤器”的编辑型方块接入 apply，可复用同一解析分支结构；当前残余风险是过滤器 `channel=0` 仍保持“频道模式 + 空频道”结构，而不是显式切回序号模式，这次按现有过滤器语义保守处理，相关入口在 [QuickLinkNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetworkServerHandlerSupport.java#L289) 与 [QuickLinkApplyService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/QuickLinkApplyService.java#L112)。

- 线程边界：本次新增路径全部沿用服务端主线程网络处理与方块实体写回，没有引入异步任务、后台缓存或跨线程共享容器；关键写入点在 [QuickLinkNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetworkServerHandlerSupport.java#L125) 与 [LinkChunkActivatorBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/LinkChunkActivatorBlockEntity.java#L82)。
