## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全风险低：本次只涉及服务器命令读模型与 bench 工具链，没有新增权限提升、网络输入解析或文件覆盖路径。[NodeRuntimeProbe.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/NodeRuntimeProbe.java#L64) [repeater-delay-regression.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/suites/repeater-delay-regression.json#L7)
- 兼容性风险中低：转发器 `triggerSource` 现在通过专门分支接入 trace；后续如果再引入“单方块双身份”的虚拟来源节点，仍需同步扩充 probe 分支，否则 bench 会再次出现“支持放置但不支持 trace”的盲区。[NodeRuntimeProbe.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/NodeRuntimeProbe.java#L64) [NodeRuntimeProbe.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/NodeRuntimeProbe.java#L340)
- 语义风险已消除：本次最终没有把“source 可见 trace”错误地当作延迟基线，而是根据实现调用链改成“输入启动 tick -> 转发器输出”的直接断言；这避免了把 sync emitter 自身的可见输出延后 1tick 误算成转发器少延迟 1tick。[TriggerSourceBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/TriggerSourceBlockEntity.java#L65) [TriggerSourceBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/TriggerSourceBlockEntity.java#L71) [repeater_samechunk_delay_tick_assert.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x57/repeater_samechunk_delay_tick_assert.json#L185) [repeater_samechunk_delay_tick_assert.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x57/repeater_samechunk_delay_tick_assert.json#L214)
- 扩展性风险中低：当前用例仅覆盖同区块、单源、单目标、`directBatching=off` 场景；若后续要覆盖跨区块或批窗口开启后的口径，应新增独立 suite，而不是在本用例里叠加更多环境变量，避免基线语义被污染。[repeater-delay-regression.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/suites/repeater-delay-regression.json#L3) [repeater-delay-regression.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/suites/repeater-delay-regression.json#L7) [repeater_samechunk_delay_tick_assert.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x57/repeater_samechunk_delay_tick_assert.json#L2)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- 风险等级：低。转发器的 `pendingDispatchArmed / pendingDispatchTick / dispatchedOutputPower / nextDispatchSeq` 都只在服务端主线程生命周期内由 `onActiveChanged -> onDelayTick -> applyDispatchedOutputPower` 串行修改，没有看到跨线程写入路径。[LinkRepeaterBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/LinkRepeaterBlockEntity.java#L182) [LinkRepeaterBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/LinkRepeaterBlockEntity.java#L226) [LinkRepeaterBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/LinkRepeaterBlockEntity.java#L310) [LinkRepeaterBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/LinkRepeaterBlockEntity.java#L318)
- trace 采样与业务状态读取也处于同一服务端 tick 线程边界；`NodeStateTraceService` 只在 `END_SERVER_TICK` 读取快照并追加 ring buffer，不会反向改写游戏逻辑状态，所以与转发器派发状态不存在并发覆盖。[NodeStateTraceService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/NodeStateTraceService.java#L348) [NodeStateTraceService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/NodeStateTraceService.java#L507)
