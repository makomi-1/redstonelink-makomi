# agents与skill补实现后审查文档规则

## 1. 功能与语义、架构设计（关键方法和入口）
- 本轮把“详细实现分析”和“对用户的结果汇报”拆成两层：`AGENTS.md` 在交流规范里新增了审查文档硬约束，并明确任务汇报只保留简要总结，避免详细代码分析与面向用户的收尾信息混在一起。[AGENTS.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/AGENTS.md#L79) [AGENTS.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/AGENTS.md#L405)
- `AGENTS.md` 的文档化自动工作流新增了 `docs_dev/reviews/YYYY-MM-DD_HHmmss_任务名.md` 这一固定输出入口，同时把“实现完成即生成审查文档”纳入事件映射，保证该动作不再依赖临时记忆。[AGENTS.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/AGENTS.md#L93) [AGENTS.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/AGENTS.md#L113)
- `skills/docs-dev-docflow/SKILL.md` 同步新增了 review 文档的原则、触发时机、必填字段和映射规则，使 skill 执行路径与项目主规则保持一致，不会出现 AGENTS 与 skill 两套口径分叉。[SKILL.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/skills/docs-dev-docflow/SKILL.md#L27) [SKILL.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/skills/docs-dev-docflow/SKILL.md#L209) [SKILL.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/skills/docs-dev-docflow/SKILL.md#L286)

## 2. 关键数据结构和算法性能分析
- 本轮新增的核心“数据结构”不是程序对象，而是固定的四段式审查模板：功能与语义、数据结构与性能、数据流、风险建议。这个结构是常量规模的模板约束，生成成本是固定项，复杂度上不会随任务规模新增流程分支，只会把详细分析稳定落到四个槽位中。[AGENTS.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/AGENTS.md#L81) [SKILL.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/skills/docs-dev-docflow/SKILL.md#L217) [SKILL.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/skills/docs-dev-docflow/SKILL.md#L271)
- 事件流也被拆成“自动生成 review 文档”和“手动维护 xlsx 审查日志”两条路径，减少了过去“是否要写审查日志”与“是否要输出详细实现分析”混在一起的判断分支；自动化部分固定写 review，人工留痕仍保留在 xlsx。[AGENTS.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/AGENTS.md#L99) [AGENTS.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/AGENTS.md#L117) [SKILL.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/skills/docs-dev-docflow/SKILL.md#L274) [SKILL.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/skills/docs-dev-docflow/SKILL.md#L287)

## 3. 数据流或调用链
- 现在的标准调用链是：方案确认阶段给关键代码引用 -> 实现完成后立即生成 `docs_dev/reviews` 审查文档 -> 结果汇报阶段只输出简要结论 -> 提交前再提醒用户手动写 `docs_dev/审查日志.xlsx` 与 `docs_dev/测试记录.xlsx`。这条链路在主规则和 skill 中都已经对齐，后续执行时可以直接按同一顺序落地。[AGENTS.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/AGENTS.md#L79) [AGENTS.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/AGENTS.md#L93) [AGENTS.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/AGENTS.md#L117) [SKILL.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/skills/docs-dev-docflow/SKILL.md#L31) [SKILL.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/skills/docs-dev-docflow/SKILL.md#L209) [SKILL.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/skills/docs-dev-docflow/SKILL.md#L286)
- 输出链也被明确切开：审查文档承载完整实现分析，结果汇报只承载摘要、验证和风险，这样 agent 在面向用户回答时不需要重复铺开代码细节，避免结果反馈再次膨胀成技术审查正文。[AGENTS.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/AGENTS.md#L86) [AGENTS.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/AGENTS.md#L407) [SKILL.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/skills/docs-dev-docflow/SKILL.md#L32) [SKILL.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/skills/docs-dev-docflow/SKILL.md#L275)

## 4. 安全、性能、兼容性、扩展性风险分析与建议
- 兼容性风险主要在于外部未同步的规则文件可能仍保留旧口径；本轮只改了 `AGENTS.md` 与 `skills/docs-dev-docflow/SKILL.md`，因此后续执行时应以这两处更新后的主规则和 skill 规则为准，避免再次按“结果汇报直接附详细代码引用”的旧习惯输出。[AGENTS.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/AGENTS.md#L79) [SKILL.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/skills/docs-dev-docflow/SKILL.md#L31)
- 扩展性方面，这次把 `docs_dev/reviews/` 提升为独立文档类型后，未来如果还要新增固定审查维度，优先继续扩展 review 模板与 skill 的 `docs_dev/reviews/` 指引，不要再把详细分析塞回任务汇报正文，否则会重新破坏职责分层。[AGENTS.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/AGENTS.md#L99) [AGENTS.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/AGENTS.md#L408) [SKILL.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/skills/docs-dev-docflow/SKILL.md#L224) [SKILL.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/skills/docs-dev-docflow/SKILL.md#L274)
- 性能与安全风险都较低，因为本轮仅调整文档流程规则，没有引入新的运行时代码路径；实际成本主要是每轮多生成一份 markdown 审查文档，属于低频、固定规模 I/O，影响可忽略。[AGENTS.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/AGENTS.md#L99) [SKILL.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/skills/docs-dev-docflow/SKILL.md#L271)
