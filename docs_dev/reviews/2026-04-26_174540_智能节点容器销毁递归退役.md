# 智能节点容器销毁递归退役

## 1. 功能与语义、架构设计
- 新增容器销毁递归退役支撑类，将“识别智能节点容器”“解析容器内部节点”“调用既有退役主流程”三层职责收口到单一入口，避免在事件层散落容器特判。[SmartNodeContainerRetireSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/SmartNodeContainerRetireSupport.java#L17)
- `ENTITY_UNLOAD` 退役事件在原有“直接节点栈”路径命中失败时，新增智能节点容器递归退役分支；这样普通节点销毁语义保持不变，容器仅作为补充入口插入现有链路。[LinkNodeRetireEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeRetireEvents.java#L77)
- 智能节点容器物品在实体销毁前显式标记“伤害触发 DISCARDED”，确保后续卸载事件能区分“被拾取/主动丢弃”与“真实销毁”，覆盖容器物品此前没有退役钩子的缺口。[SmartNodeContainerItem.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/item/SmartNodeContainerItem.java#L117)

## 2. 关键数据结构和算法性能分析
- 容器内部退役目标先被收集为 `LinkedHashSet<RetireTarget>`，按“节点类型 + 序号”去重，避免同一序号在容器中重复出现时反复执行退役主流程；整体复杂度为 O(n) 收集 + O(m) 退役，`m <= n`。[SmartNodeContainerRetireSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/SmartNodeContainerRetireSupport.java#L85)
- 转发器在收集阶段统一映射为 `CORE` 目标，再交由 `LinkRetireCoordinator` 的双身份退役逻辑完成 `core/triggerSource` 同步清理，避免在容器层重复实现双身份算法。[SmartNodeContainerRetireSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/SmartNodeContainerRetireSupport.java#L91)
- 退役前会用 `LinkSavedData.findNode(...)` 检查同号节点是否仍在线，若在线则跳过；这能防止容器内历史拷贝反向退役已放置节点，代价是每个目标一次或两次映射查询，属于低频销毁路径可接受成本。[SmartNodeContainerRetireSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/SmartNodeContainerRetireSupport.java#L117)

## 3. 数据流或调用链
- 伤害销毁路径的数据流为：`SmartNodeContainerItem.onDestroyed(...)` 标记伤害丢弃 → `LinkNodeRetireEvents.ENTITY_UNLOAD` 识别 `DISCARDED/KILLED` → `SmartNodeContainerRetireSupport.retireContainedNodes(...)` 读取容器内容并构造退役目标 → `LinkRetireCoordinator.retireAndSyncWhitelist(...)` 执行节点退役、副作用清理与客户端同步。[SmartNodeContainerItem.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/item/SmartNodeContainerItem.java#L117) [LinkNodeRetireEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeRetireEvents.java#L95) [SmartNodeContainerRetireSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/SmartNodeContainerRetireSupport.java#L33)
- 单元测试绕开了物品注册表初始化，直接对“目标级退役”入口做断言，分别覆盖普通节点与转发器双身份语义，确保这条新增销毁链至少在数据层闭环成立。[SmartNodeContainerRetireSupportTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/data/SmartNodeContainerRetireSupportTest.java#L39)

## 4. 安全、性能、兼容性、扩展性风险分析与建议
- 安全性：新增逻辑未引入外部 API 依赖，也没有放宽任何“来源→目标”写入路径；本轮只处理退役和副作用清理，不触碰链接写入语义。[SmartNodeContainerRetireSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/SmartNodeContainerRetireSupport.java#L60)
- 兼容性：容器递归退役只在原有直接节点解析失败时触发，对普通节点物品的销毁退役兼容；空容器或内部节点仍在线时会显式跳过，不会误删在线实体。[LinkNodeRetireEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeRetireEvents.java#L105)
- 扩展性：当前容器内部可识别对象仍限定为 `PairableItem` 与转发器；若以后容器允许装入新的节点载体，需在 `collectRetireTargets(...)` 中增加映射规则，并同步补测试样例。[SmartNodeContainerRetireSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/SmartNodeContainerRetireSupport.java#L85)

## 5. 并发冲突审查
- 共享状态主要是 `LinkSavedData` 与 `LinkNodeRetireEvents` 的待退役状态表；当前调用链全部发生在服务端实体卸载事件与主线程退役协调器内部，没有新增异步线程，也没有跨线程共享写入点，重入风险低。[LinkNodeRetireEvents.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeRetireEvents.java#L77)
- 读改写覆盖风险主要在“同号节点仍在线”的并发语义：本实现先查在线节点，再执行退役；由于调用场景本身是实体销毁时的服务端事件，且退役协调器仍以保存数据为唯一真值，当前窗口足够小，风险等级评估为中低。[SmartNodeContainerRetireSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/SmartNodeContainerRetireSupport.java#L117)
- 建议后续若容器销毁链扩展到更多批处理场景，可考虑在 `LinkRetireCoordinator` 层补统一批量退役入口，避免同 tick 大量容器销毁时重复读取 `LinkSavedData` 与重复副作用分发。[SmartNodeContainerRetireSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/SmartNodeContainerRetireSupport.java#L60)
