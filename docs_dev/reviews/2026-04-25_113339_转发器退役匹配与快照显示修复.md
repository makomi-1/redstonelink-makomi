# 转发器退役匹配与快照显示修复审查

## 1. 功能与语义、架构设计（关键方法和入口）
- 服务端退役匹配现在把转发器统一序号视为同号 `triggerSource/core` 双身份，避免正常挖掘或掉落实体扫描时只匹配单侧身份而误退役，关键入口见 [LinkNodeRetireMatchSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeRetireMatchSupport.java#L114) 与 [LinkNodeRetireMatchSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeRetireMatchSupport.java#L158)。
- 转发器物品序号治理继续走内部实现路径，不依赖 `com.makomi.api.v1.*`；`ensureSerial(...)` 现在会在任一身份已退役时重分配统一序号，并清空旧连接摘要但保留自身延迟，同时用图真值统一别名，见 [RepeaterItemData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/RepeaterItemData.java#L63) 与 [RepeaterGraphSnapshotSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/RepeaterGraphSnapshotSupport.java#L61)。
- 客户端展示语义已和其它节点对齐：物品 tooltip 改为“序号+别名合并显示”，QTL 采集按当前缓存类型命中 `triggerSource/core`，近外显 HUD 新增双身份跨区块行，关键入口见 [RepeaterBlockItem.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/item/RepeaterBlockItem.java#L76)、[QuickLinkNetworkClientHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/network/QuickLinkNetworkClientHandlerSupport.java#L181)、[LinkSerialHudOverlayRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/LinkSerialHudOverlayRenderer.java#L140) 与 [LinkSerialHudOverlayTextSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/LinkSerialHudOverlayTextSupport.java#L247)。

## 2. 关键数据结构和算法性能分析
- 本轮没有新增持久化字段，而是继续复用 `RepeaterConfigSnapshot` 保存输入/输出表达式与延迟；清理旧连接摘要时只重建一个轻量快照对象，复杂度为 `O(1)`，见 [RepeaterItemData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/RepeaterItemData.java#L99)。
- 转发器统一别名解析采用“先 core、后 triggerSource、最后回退物品旧别名”的固定链路，不会扫描整图，也不会引入额外集合膨胀，见 [RepeaterGraphSnapshotSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/RepeaterGraphSnapshotSupport.java#L61)。
- 近外显 HUD 继续复用按目标键缓存的 lazy request 模式，现在只是把同一统一序号拆成 `triggerSource/core` 两次独立查询，优先命中缓存、过期后按节流补请求，避免每帧强制网络往返，见 [LinkSerialHudOverlaySnapshotSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/LinkSerialHudOverlaySnapshotSupport.java#L181)。
- QTL 对转发器的缓存类型判定只做一次常量时间分支，不引入额外图查询或客户端状态机，见 [QuickLinkNetworkClientHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/network/QuickLinkNetworkClientHandlerSupport.java#L247)。

## 3. 数据流或调用链
- 挖掘/掉落链路中，掉落物匹配先进入 `isMatchingStack(...)`，若是转发器则优先走双身份待退役匹配 helper，从而把“统一序号”正确映射到图中的 `triggerSource/core` 两个逻辑身份，见 [LinkNodeRetireMatchSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkNodeRetireMatchSupport.java#L158)。
- 物品快照链路中，`ensureSerial(...)` 先判断当前统一序号是否失效；若旧号任一身份已退役，则重新分配新号、清空旧连接表达式、保留 delay，并通过图真值刷新统一别名，随后 `syncItemSnapshot(...)` 会继续把展示摘要同步成当前图状态，见 [RepeaterItemData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/RepeaterItemData.java#L63) 与 [RepeaterGraphSnapshotSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/RepeaterGraphSnapshotSupport.java#L101)。
- 客户端命中链路分两支：QTL 采集时 `resolveQuickLinkTarget(...)` 读取工具缓存类型并映射到 `triggerSource/core` 身份，见 [QuickLinkNetworkClientHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/network/QuickLinkNetworkClientHandlerSupport.java#L181)；近外显渲染时 `renderRepeaterOverlay(...)` 分别拉取两侧当前连接快照，再由文本组装层输出“跨区块身份（t/c）”行，见 [LinkSerialHudOverlayRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/LinkSerialHudOverlayRenderer.java#L140)、[LinkSerialHudOverlayTextSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/LinkSerialHudOverlayTextSupport.java#L274) 与 [zh_cn.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/assets/redstonelink/lang/zh_cn.json#L350)。
- 自动化回归分别覆盖了双身份待退役匹配、旧号重分配后的物品快照清理、以及 QTL 对转发器采集身份选择，见 [LinkNodeRetireMatchSupportTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/data/LinkNodeRetireMatchSupportTest.java#L18)、[RepeaterItemDataTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/data/RepeaterItemDataTest.java#L40) 与 [QuickLinkNetworkClientHandlerSupportTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/client/network/QuickLinkNetworkClientHandlerSupportTest.java#L19)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议
- 安全性：本轮只调整内部数据路径、客户端展示和测试，不新增外部命令入口、脚本执行链，也没有引入被禁用的 `com.makomi.api.v1.*` 依赖，边界仍收敛在现有模块内，见 [RepeaterItemData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/RepeaterItemData.java#L63)。
- 兼容性：文案、tooltip、HUD 和 QTL 解析均统一使用 `triggerSource/core` 术语，旧术语没有向新增输出泄漏；同时转发器连接摘要改为跟随图真值与统一别名，降低“物品显示仍有连接、实际图已变更”的错觉，见 [RepeaterBlockItem.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/item/RepeaterBlockItem.java#L87)、[QuickLinkNetworkClientHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/network/QuickLinkNetworkClientHandlerSupport.java#L203) 与 [zh_cn.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/assets/redstonelink/lang/zh_cn.json#L348)。
- 性能：HUD 现在对转发器会发起两侧身份的懒加载查询，但仍受本地缓存与节流保护，正常悬停成本可控；若后续再为转发器增加更多运行态观测项，应优先复用同一缓存键体系，而不是再开新的高频查询通道，见 [LinkSerialHudOverlaySnapshotSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/LinkSerialHudOverlaySnapshotSupport.java#L181)。
- 扩展性：QTL 的转发器采集身份已被收敛成独立 helper，后续若要按更多缓存模式或编辑上下文切换命中身份，可在该 helper 上扩展而不必散落到多处分支，见 [QuickLinkNetworkClientHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/network/QuickLinkNetworkClientHandlerSupport.java#L247)。

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）
- 共享状态：服务端侧仍通过 `LinkSavedData` 维护统一序号分配、退役与转发器标记，本轮只是补齐“同号双身份”的匹配规则，没有新建并发容器；相关写入入口见 [RepeaterItemData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/RepeaterItemData.java#L63)。
- 读改写覆盖：转发器物品快照的连接表达式和别名会被 `ensureSerial(...)` 与 `syncItemSnapshot(...)` 两条路径更新，但两者目标一致，都是把物品展示收敛到当前图真值；当前风险主要是未来若新增第三条写路径，必须继续坚持“连接按图真值，其它按物品自身缓存”的边界，见 [RepeaterItemData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/RepeaterItemData.java#L78) 与 [RepeaterGraphSnapshotSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/RepeaterGraphSnapshotSupport.java#L101)。
- 重入与线程边界：HUD 快照请求发生在客户端渲染链路，当前实现仍是“先读缓存，必要时异步请求，当前帧只消费已有快照”，没有在渲染函数里直接阻塞等待网络结果，见 [LinkSerialHudOverlayRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/LinkSerialHudOverlayRenderer.java#L140) 与 [LinkSerialHudOverlaySnapshotSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/LinkSerialHudOverlaySnapshotSupport.java#L181)。
- 风险等级：低。现阶段主要风险不在并发，而在后续分支若再次分叉转发器退役规则或物品快照写入路径，容易重新出现“序号变了但连接摘要未清”的语义漂移，建议继续把转发器统一序号视为 `triggerSource/core` 双身份的单一事实源。
