# 快速连接工具扩展到过滤器应用与亮红描边

## 1. 功能与语义、架构设计

- 本轮在不改变 quick-link 既有“潜行右键打开编辑器、左键采集节点、站立右键应用”的主交互骨架下，把站立右键 apply 目标从“仅节点”扩展为“节点或过滤器”，同时保持过滤器仍不可采集。[QuickLinkNetworkClientHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/network/QuickLinkNetworkClientHandlerSupport.java#L122) [QuickLinkNetworkClientHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/network/QuickLinkNetworkClientHandlerSupport.java#L176)
- 服务端 apply 入口新增过滤器分支：过滤器目标走零 revision baseline + 直接配置写入，节点目标继续走 OCC 校验与建链写入，因此没有破坏现有节点 OCC 语义。[QuickLinkNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetworkServerHandlerSupport.java#L105) [QuickLinkNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetworkServerHandlerSupport.java#L179) [QuickLinkNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetworkServerHandlerSupport.java#L267)
- 过滤器应用只覆盖 `serialExpression`，其余 `nodeSetMode/signalThresholdSource/fixedSignalThreshold/signalMode` 全部保留；`send` 过滤器只接受 `triggerSource` 缓存，`receive` 过滤器只接受 `core` 缓存。[QuickLinkApplyService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/QuickLinkApplyService.java#L87) [QuickLinkApplyService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/QuickLinkApplyService.java#L375) [QuickLinkApplyService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/QuickLinkApplyService.java#L389)
- 客户端描边扩展到过滤器目标，节点保持原有亮蓝/亮橙，过滤器单独使用亮红色，以便玩家快速区分目标类型。[QuickLinkOutlineRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/QuickLinkOutlineRenderer.java#L25) [QuickLinkOutlineRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/QuickLinkOutlineRenderer.java#L48) [QuickLinkOutlineRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/QuickLinkOutlineRenderer.java#L88)

## 2. 关键数据结构和算法性能分析

- 网络载荷结构没有新增字段，过滤器目标复用现有 `typeToken + serial` 编码，约定为 `send/receive + 0`，避免新增协议通道和额外编解码复杂度。[QuickLinkNetworkClientHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/network/QuickLinkNetworkClientHandlerSupport.java#L173)
- 服务端过滤器应用沿用 `SerialParseUtil.parseTargetsOrdered` 做非法项、上限与去重校验，再回写规范化 `/` 分段表达式，复杂度与过滤器 GUI 保存一致，没有引入新的高复杂度路径。[QuickLinkApplyService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/QuickLinkApplyService.java#L114) [QuickLinkApplyService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/QuickLinkApplyService.java#L420)
- 节点 apply 仍复用原有 `LinkSetExecutionService` 与写控逻辑；过滤器 apply 不走写控/OCC，只执行一次配置快照覆盖，避免把过滤器编辑误并入链接图写入成本。[QuickLinkApplyService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/QuickLinkApplyService.java#L155) [QuickLinkNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetworkServerHandlerSupport.java#L179)

## 3. 数据流或调用链

- 客户端链路：`UseBlockCallback` 命中过滤器时，`resolveQuickLinkTarget` 会把过滤器编码为 `send/receive + 0` 并先请求 baseline，再自动续发正式 apply。[QuickLinkNetworkClientHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/network/QuickLinkNetworkClientHandlerSupport.java#L83) [QuickLinkNetworkClientHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/network/QuickLinkNetworkClientHandlerSupport.java#L157) [QuickLinkNetworkClientHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/network/QuickLinkNetworkClientHandlerSupport.java#L223)
- 服务端链路：`handleRequestApplyQuickLinkBaseline` 和 `handleApplyQuickLink` 统一经 `resolveRequestedApplyTarget` 分流到节点或过滤器；过滤器命中后直接进入 `QuickLinkApplyService.applyToFilterFromCache`。[QuickLinkNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetworkServerHandlerSupport.java#L105) [QuickLinkNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetworkServerHandlerSupport.java#L132) [QuickLinkNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetworkServerHandlerSupport.java#L267)
- 过滤器配置写入链路：`applyToFilterFromCache` 校验权限与缓存类型后，构造保留原配置的新 `LinkFilterConfigSnapshot` 并调用 `applySnapshot`，后续运行时刷新仍交给既有过滤器派发链路处理。[QuickLinkApplyService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/QuickLinkApplyService.java#L87) [QuickLinkApplyService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/QuickLinkApplyService.java#L389)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全边界已区分：节点 apply 继续受写控保护；过滤器 apply 改用 `server.command.permissionLevel`，避免通过 quick-link 绕开过滤器原有编辑权限。[QuickLinkApplyService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/QuickLinkApplyService.java#L95) [docs_dev/使用说明.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs_dev/使用说明.md#L42)
- 协议兼容风险主要在“同一 payload 同时表示节点和过滤器目标”；本轮通过注释和 payload 回归测试固化了 `send/receive + 0` 的编码语义，但后续若还有第三类目标，建议抽出更显式的 target kind 字段，而不是继续挤压现有 token 语义。[QuickLinkNetworkClientHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/network/QuickLinkNetworkClientHandlerSupport.java#L272) [QuickLinkNetworkPayloadTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/network/QuickLinkNetworkPayloadTest.java#L116)
- 当前过滤器应用只写 `serialExpression`，不支持 quick-link 一并改 `nodeSetMode` 或信号阈值，这符合本轮最小需求；如果后续要扩到批量配置写入，建议单独设计过滤器专用 payload，而不是继续复用 quick-link 节点 apply 语义。[QuickLinkApplyService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/QuickLinkApplyService.java#L389)

## 5. 并发冲突审查

- 风险等级低。本轮没有新增异步线程或共享缓存；客户端只是多识别了一类目标，服务端仍在主线程上顺序处理 quick-link 网络包。[QuickLinkNetworkClientHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/network/QuickLinkNetworkClientHandlerSupport.java#L47) [QuickLinkNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetworkServerHandlerSupport.java#L132)
- 节点 apply 的并发保护仍由 OCC 负责，过滤器 apply 则显式跳过 OCC，原因是过滤器配置不是链接图 revision 的一部分；这不会引入新的图写入覆盖风险，但若未来过滤器配置也需要多端并发编辑保护，应单独为过滤器配置设计 revision 或冲突提示层。[QuickLinkNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetworkServerHandlerSupport.java#L179) [QuickLinkNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetworkServerHandlerSupport.java#L378)
- 回归保护已经补到 payload 语义与过滤器配置保留两层，能覆盖这次最容易回退的协议/配置行为边界。[QuickLinkNetworkPayloadTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/network/QuickLinkNetworkPayloadTest.java#L116) [QuickLinkApplyServiceTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/data/QuickLinkApplyServiceTest.java#L71)
