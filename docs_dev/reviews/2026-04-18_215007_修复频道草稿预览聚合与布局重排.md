# 修复频道草稿预览聚合与布局重排

## 1. 功能与语义、架构设计

- 画布强制显示集合仍由选中节点、手动拉回节点、搜索命中节点和草稿差异节点组成，入口在 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L326)，之后统一交给 `buildGraphCanvasView` 做序号/频道模式分发，入口在 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L348)。
- 频道模式的修复点放在聚合块生成阶段：频道核心聚合和 triggerSource 聚合都会在成员被强制显示时自动切到展开态，避免折叠聚合与强制显示成员的语义冲突，入口分别在 [canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L943)、[canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L1068)、[canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L1122)。
- 批量“应用到草稿”后，`handleApplyBatchEdit` 在草稿实际变更成功时会追加一次结构重排请求，从而触发既有“重排时不复用旧坐标”的分支；批量编辑入口在 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1450)，结构刷新请求在 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1478)，旧坐标复用门控在 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L695)。

## 2. 关键数据结构和算法性能分析

- 新增的成员命中判断被抽成 `hasForcedVisibleAggregateMember`，只做一次线性扫描，不引入额外索引结构，定义在 [canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L403)。
- 序号模式和频道模式现在都用同一条“成员被强制显示则聚合展开”的规则，因此复杂度仍然是按聚合成员数做 `O(k)` 判断；序号模式应用点在 [canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L674) 和 [canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L824)，频道模式应用点在 [canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L1068) 和 [canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L1122)。
- 结构重排没有改动布局算法本体，而是复用现有 `pendingStructureLayoutReset` 控制位，只在必要时切换到“清空已有位置映射”的路径，避免把每次普通 UI 变化都升级成全量重排；控制位设置入口在 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L938)，消费位置复用分支在 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L695)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 兼容性：本轮没有改动真实持久化、服务端保存或 `draft` 文件结构，只是在前端视图层把“强制显示成员”解释为“聚合自动展开”，因此与既有 `triggerSource -> core` 真值语义兼容，聚合展开实现位于 [canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L1068) 与 [canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L1122)。
- 性能：新增判断只是在聚合块构建时多做成员集合扫描，量级与原本聚合分组同阶，风险低；真正的成本仍然主要在布局和 React Flow 渲染阶段，相关汇总口在 [canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L487)。
- 可用性风险：批量应用草稿后这次改为 `fitViewport: false`，能减少编辑时的视角跳变，但如果一次操作把节点移到很远的新上下文，用户可能需要手动重新布局或搜索定位；该取舍位于 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1478)。
- 扩展性：频道模式仍然复用与序号模式一致的聚合块语义，没有单独分叉新的可见性协议，后续若继续扩展频道编辑或频道专属聚合规则，建议仍优先复用 [canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L487) 这一层做统一收敛。

## 5. 并发冲突审查

- 共享状态主要是 `graphDraft`、`undoableGraphDraft`、`pendingStructureLayoutReset`、`pendingStructureViewportFit` 这几类 React state；草稿写入入口在 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1191)，结构刷新入口在 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L938)。
- 当前风险等级评估为低：这些状态只在前端单线程事件回调中串行更新，没有引入额外异步共享缓存，也没有跨线程写入。
- 仍需注意的重入边界是“连续快速点击应用到草稿”：虽然 React 会批处理状态，但 `handleApplyBatchEdit` 读取的是当前渲染闭包中的 `graphDraft` 和选区，理论上仍存在用户极快重复操作时以旧选区再次提交的交互风险；对应入口在 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1450)。建议后续若继续扩展编辑能力，可考虑在批量应用期间增加一次短暂按钮禁用或提交中标记。
