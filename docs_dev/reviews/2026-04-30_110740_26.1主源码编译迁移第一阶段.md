## 2. 关键数据结构和算法性能分析

本阶段没有引入新的热点结构，重点是避免迁移过程中退化现有索引和调度成本。

- `LinkSavedData` 的节点区块索引仍然使用 `long` 型区块键，只是由 `new ChunkPos(...).toLong()` 改为静态 `ChunkPos.pack(...)`，减少了不必要的临时对象构造，见 [LinkSavedData.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/data/LinkSavedData.java#L515)、[LinkSavedData.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/data/LinkSavedData.java#L579)。
- `PlacedLinkFilterSavedData` 的过滤器覆盖区块计算仍是按立方域展开区块桶，算法复杂度未变；迁移后同样使用 `ChunkPos.pack` 作为稳定键，见 [PlacedLinkFilterSavedData.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/data/PlacedLinkFilterSavedData.java#L219) 与 [PlacedLinkFilterSavedData.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/data/PlacedLinkFilterSavedData.java#L411)。
- `SavedDataTypeSupport` 是无状态静态 helper，不持有缓存，也不会改变 `SavedData` 生命周期，见 [SavedDataTypeSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/data/SavedDataTypeSupport.java#L18)。

## 3. 数据流或调用链

本阶段主要修的是框架入口，不改业务内部调用链，只保证旧链路能在 26.1 上重新接通。

- 世界级持久化链路仍是 `ServerLevel -> overworld data storage -> computeIfAbsent(TYPE)`，只是 `TYPE` 的构造由 helper 统一适配，见 [CrossChunkDispatchQueueSavedData.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/data/CrossChunkDispatchQueueSavedData.java#L53) 与 [LinkSavedData.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/data/LinkSavedData.java#L88)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 兼容性风险目前已从“主源码无法编译”降到“客户端侧 API 尚未迁完”；`compileJava` 通过不代表 `compileClientJava` 已通过，后续仍需继续处理渲染、HUD 和客户端命令入口，当前可参考 [ModItemGroups.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/registry/ModItemGroups.java#L19) 与 [StatePanelNetworkRegistrationSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/network/StatePanelNetworkRegistrationSupport.java#L28) 的迁移模式。
