# scheduler两阶段flush防重入修复

## 1. 功能与语义、架构设计（关键方法和入口）
- 本次修复保持现有 `triggerSource -> core` 批调度语义不变，只调整 `flushServerBatches(...)` 的执行相位：先遍历 `pendingByTarget` 收集本轮到期 flush plan，再在 map 迭代结束后统一 apply，避免下游再次入队时修改当前正在遍历的 scheduler map。[CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L232) [CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L244) [CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L264)
- `TargetBatchAccumulator` 新增 `detachDueBuckets(...)`，把“摘出已到期 bucket”和“真正调用目标实体批提交”拆开；原有 `flushDueBuckets(...)` 仅作为兼容入口复用该逻辑，避免测试和已有内部约束被打散。[CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L429) [CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L443)
- 新增 `TargetFlushPlan` 作为目标级临时 flush 快照，显式承接“脱离 map 后再 apply”的中间态，使修复集中在 scheduler 内部，不改 `enqueueLoadedTargetDispatch(...)` / `enqueueLoadedTargetDispatchBatch(...)` 的入口语义。[CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L112) [CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L154) [CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L488)

## 2. 关键数据结构和算法性能分析
- 主数据结构仍是 `SchedulerState.pendingByTarget -> TargetBatchAccumulator -> bucketsByDueTick -> DueTickBucket` 的四层聚合；本次没有引入新的全局索引，只在 flush 周期内额外分配一个 `List<TargetFlushPlan>` 和每个 plan 一份 `List<DueTickBucket>` 快照，空间开销与“本轮实际到期 bucket 数”线性相关。[CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L244) [CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L365) [CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L470)
- 算法复杂度仍保持原量级：遍历 `pendingByTarget` 一次、遍历每个到期 bucket 一次；与旧实现相比只是把 apply 延后到第二相位，没有增加额外的 map 扫描轮次。[CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L245) [CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L449)
- 对象池策略未改：accumulator 仍在目标摘空后立即回收，避免历史峰值常驻；由于 flush plan 已经复制了 bucket 列表，提前回收 accumulator 不会污染后续 apply。[CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L258) [CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L478) [CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L590)

## 3. 数据流或调用链
- 正常入口仍是 loaded direct / ready batch 写入 scheduler：`enqueueLoadedTargetDispatch(...)` 或 `enqueueLoadedTargetDispatchBatch(...)` 先根据窗口算 `dueTick`，再把条目合并进目标 accumulator。[CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L112) [CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L154) [CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L337)
- flush 时，scheduler 第一相位只做三件事：按当前 tick 摘出到期 bucket、把 flush plan 放进本地列表、把已空 accumulator 从 `pendingByTarget` 移除并回收；第二相位才通过 `TargetFlushPlan.apply()` 进入 `DueTickBucket.flush(...)`，最终落到 `core.applyDispatchBatch(...)`。[CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L244) [CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L254) [CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L488) [CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L554)
- 回归测试覆盖了两个关键断点：一条验证 `detachDueBuckets(...)` 会先把 bucket 从 accumulator 中摘走，另一条用 `ReentrantMutationTargetEntity` 在 apply 阶段模拟“下游再次写回 scheduler map”，确保不再触发 `ConcurrentModificationException`。[CoreDispatchBatchSchedulerTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/data/CoreDispatchBatchSchedulerTest.java#L317) [CoreDispatchBatchSchedulerTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/data/CoreDispatchBatchSchedulerTest.java#L331) [CoreDispatchBatchSchedulerTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/data/CoreDispatchBatchSchedulerTest.java#L634)

## 4. 安全、性能、兼容性、扩展性风险分析与建议
- 安全性：本次改动不涉及外部 API、持久化结构或权限路径，属于 scheduler 内部相位拆分，兼容风险集中在 flush 时序是否被无意改变；从现有实现看，`window=0` late-arrival 仍通过原入口触发，只是不再与 map 迭代耦合。[CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L206) [CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L232)
- 性能：新增的 flush plan 复制会带来一次短生命周期列表分配，但换来的是对 reentrant enqueue 的结构性隔离；对于当前按目标聚合的批大小，这个代价明显低于继续在 flush 中承受 map 迭代失稳风险。[CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L244) [CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L470)
- 兼容与扩展：若后续需要进一步处理“late-arrival 在 flush apply 期间再次请求立即 flush”的递归深度问题，建议优先在 scheduler 内部继续做 phase queue / deferred flush request，而不是把补 flush 直接改成另一条 direct dispatch 语义分支，以免扩大行为面。当前版本残余风险为“深层递归链仍可能存在，但已不再通过 map 迭代并发修改的方式崩溃”。[CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L232) [CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L488) [CoreDispatchBatchSchedulerTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/data/CoreDispatchBatchSchedulerTest.java#L331)
