## 1. 功能与语义、架构设计（关键方法和入口）

- 频道模式的核心扩展落在 `buildChannelGraphCanvasView`：它先生成 `channelHub` 两级投影，再在每个频道上补 `core` / `triggerSource` 两类聚合块，并把被聚合替代的频道边加入隐藏集合。[canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L876) [canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L968)
- 频道聚合块继续复用现有 `GraphCanvasAggregateNode` 语义：`memberNodeKeys` 仍表示真实成员节点，`connectedNodeKeys` 在频道模式下改为指向 `channelHub`，而 `connectedSerials` 保留对侧真实成员计数，用于聚合标签文案。[canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L1007) [canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L1060)
- 总入口 `buildGraphCanvasView` 现在会把 `forcedVisibleNodeKeys` 和 `expandedAggregateNodeKeys` 同时传入频道模式构建函数，保证频道聚合块也能沿用选中强制展开和展开记忆行为。[canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L1185)
- 右侧详情页新增了“画布节点”层面的 connected 映射，频道模式下聚合块可以直接展示并聚焦 `channelHub`，不再假设 connected 侧一定是真实节点。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L74) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L390) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2007)

## 2. 关键数据结构和算法性能分析

- 频道聚合按频道块逐个执行，时间复杂度主要来自每个频道内 `triggerSource/core` 的排序和一次性遍历，整体仍然是 `O(n log n)` 量级，且只作用于 `connectionMode=channel` 的节点子集。[canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L881) [canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L970)
- 两类聚合块分别隐藏 `channelHub -> core` 与 `triggerSource -> channelHub` 原始频道边，最终把高扇出频道压缩成 `triggerSource aggregate -> channelHub -> core aggregate` 的低边数表达，降低画布拥挤度。[canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L1014) [canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L1067) [canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L1074)
- 展开态仍复用原有 aggregate layout edge 与包围框计算，不为频道模式单独引入新布局算法，避免额外性能热路径。[canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L1133) [canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L1093)
- 搜索高亮新增 `matchedCanvasNodeKeys`，把匹配从真实节点扩展到 `channelHub/aggregate` 画布节点，避免频道模式下两端都被聚合后边线全部误判为“不匹配”而变暗。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L291) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L648)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全与语义边界：本轮只改网页前端显示层，没有接触服务端保存协议；`focusNode` 和详情增强只在画布节点范围内工作，不会把 `channelHub` 或聚合块写入真值。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L845)
- 兼容性：`buildEdges` 仍然只在 `serial` 模式叠加 removed-edge diff，频道模式只消费当前画布边，避免把 serial 草稿差异误投到频道聚合视图。[canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L1722) [canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L1753)
- 扩展性：频道模式的两类聚合块本质上是“按频道投影视图”的聚合，而不是按真实 serial 边重新聚合；后续如果要做频道编辑或混合视图，需要继续沿用这层边界，不要直接把 `channelHub` 混进真实保存模型。[canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L876)
- UI 解释完整性：频道模式图例和统计文案已增加聚合块与 `Channels / Groups` 说明，但如果后续继续增加频道专属节点类型，建议把顶部统计拆成独立字段，避免复合值增长后可读性下降。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1498) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1562) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1576)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- 风险等级：低。本轮仍在 React 单线程状态流内，没有新增跨线程共享状态。
- `matchedCanvasNodeKeys` 是纯派生集合，只依赖当前 `graphCanvasView` 和搜索命中，不会回写草稿或结构状态，因此不会与保存链路形成读改写冲突。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L291)
- 频道聚合块继续复用现有的展开状态 `expandedAggregateNodeKeys` 与聚焦状态 `pendingAggregateFocusNodeKey`；由于入口没拆分新状态机，不会额外引入“频道聚合展开态”和“序号聚合展开态”竞争覆盖的问题。[canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L879) [canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L994) [canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L1045)
- 仍需注意的唯一共享边界是 ReactFlow 选中态与本地批量编辑集合；不过频道模式本身仍是只读，选择同步门禁没有被放宽，因此本轮不会新增编辑态重入风险。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L648)
