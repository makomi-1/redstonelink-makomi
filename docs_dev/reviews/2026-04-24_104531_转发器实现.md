## 2. 关键数据结构和算法性能分析

转发器快照的核心数据结构仍然复用 `LinkSavedData` 的反向索引集合，`resolve(...)` 只对当前 serial 的输入集合和输出集合各做一次表达式拼装，时间复杂度与该转发器的入边/出边数线性相关，避免了全图扫描；对应实现见 [RepeaterGraphSnapshotSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/RepeaterGraphSnapshotSupport.java#L27) 和 [RepeaterGraphSnapshotSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/RepeaterGraphSnapshotSupport.java#L42)。

物品缓存刷新采用“仅在线玩家、仅命中 serial”策略：在线同步入口见 [RepeaterGraphSnapshotSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/RepeaterGraphSnapshotSupport.java#L98)，单栈判断与回写见 [RepeaterGraphSnapshotSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/RepeaterGraphSnapshotSupport.java#L79) 和 [RepeaterGraphSnapshotSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/RepeaterGraphSnapshotSupport.java#L144)。该路径的复杂度约为在线玩家数乘以其容器槽位数，属于别名变更或配对变更后的可接受后台同步成本。

运行态延迟派发仍然保持单节点常数成本：定时触发入口见 [LinkRepeaterBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/LinkRepeaterBlockEntity.java#L182)，实际输出提交与邻居通知见 [LinkRepeaterBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/LinkRepeaterBlockEntity.java#L318)。因为只在 armed 时才进入派发，且一次只处理当前节点的单个输出功率，所以没有引入额外批处理放大。

## 3. 数据流或调用链

已放置转发器或手持转发器打开编辑器时，会先通过 [RepeaterNetwork.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/RepeaterNetwork.java#L44) / [RepeaterNetwork.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/RepeaterNetwork.java#L70) 读取图真值快照，再把最小编辑器所需字段下发到客户端。客户端界面初始化后，在 [RepeaterEditorScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/RepeaterEditorScreen.java#L98) 完成控件布局，保存与配对分流分别走 [RepeaterEditorScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/RepeaterEditorScreen.java#L208) 和 [RepeaterEditorScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/RepeaterEditorScreen.java#L222)。

保存路径的数据流为“客户端提交最小表单 -> 服务端解析目标 -> 以当前图真值重建快照 -> 写回方块实体或物品缓存”，对应节点见 [RepeaterNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/RepeaterNetworkServerHandlerSupport.java#L36)、[RepeaterNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/RepeaterNetworkServerHandlerSupport.java#L179)、[RepeaterGraphSnapshotSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/RepeaterGraphSnapshotSupport.java#L42)、[LinkRepeaterBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/LinkRepeaterBlockEntity.java#L161)。

配对路径的数据流为“编辑器跳转 -> 旧 pairing 网络继续做 OCC 提交 -> 成功后刷新转发器物品摘要”，对应节点见 [RepeaterNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/RepeaterNetworkServerHandlerSupport.java#L117)、[PairingOccSubmissionSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingOccSubmissionSupport.java#L32)、[PairingOccSubmissionSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingOccSubmissionSupport.java#L129)、[PairingOccSubmissionSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingOccSubmissionSupport.java#L389)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

方向语义与兼容边界本轮已对齐为 `triggerSource/core`：图快照、界面文案、tooltip 与语言文件均不再输出旧术语，落点见 [RepeaterGraphSnapshotSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/RepeaterGraphSnapshotSupport.java#L59)、[RepeaterEditorScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/RepeaterEditorScreen.java#L170)、[zh_cn.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/assets/redstonelink/lang/zh_cn.json#L182)、[en_us.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/assets/redstonelink/lang/en_us.json#L182)。建议后续继续把任何新增调试日志也限制在同一术语集合内。

为避免转发器误落到频道模式，本轮通过显示上下文 token 和 UI 钩子硬性禁用了 repeater 配对界面的 channel 切换：token 定义见 [LinkGuiDisplayContext.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkGuiDisplayContext.java#L28) 与 [LinkGuiDisplayContext.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkGuiDisplayContext.java#L123)，父类钩子见 [AbstractMultiPairingScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/AbstractMultiPairingScreen.java#L506) 与 [AbstractMultiPairingScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/AbstractMultiPairingScreen.java#L973)，具体命中 repeater 的子类覆写见 [CorePairingScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/CorePairingScreen.java#L191) 和 [TriggerSourcePairingScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/TriggerSourcePairingScreen.java#L215)。这能阻断错误语义，但也意味着如果未来确实要支持新模式，需要先扩展 repeater 语义设计，再放开 UI。

残余兼容风险主要在客户端展示层：当前仍复用 [RedstoneLinkClient.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/RedstoneLinkClient.java#L122) 的通用 `LinkNodeFarOverlayRenderer`，它还没有对转发器“双身份同号”做专门外显，因此远外显可能仍偏向单身份呈现。建议后续若要做完整交互体验，再单独补一层 repeater 专用 HUD/overlay 解释。

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

本轮把“转发器编辑器保存”限定为别名与延迟写入，不允许在同一表单里直接改图，因此保存时不会绕开既有 pairing OCC 机制去覆写 `triggerSource/core` 连接集合。关键保障点是 [RepeaterNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/RepeaterNetworkServerHandlerSupport.java#L36) 只接收最小表单，再调用 [RepeaterGraphSnapshotSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/RepeaterGraphSnapshotSupport.java#L42) 以服务端当前图真值重建快照，最终由 [LinkRepeaterBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/LinkRepeaterBlockEntity.java#L161) 原子更新本地缓存。该路径风险等级为低。

真正修改连接图的路径仍统一走 pairing OCC 提交：`triggerSource` 视角入口见 [PairingOccSubmissionSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingOccSubmissionSupport.java#L32)，`core` 视角入口见 [PairingOccSubmissionSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingOccSubmissionSupport.java#L129)，成功后再通过 [PairingOccSubmissionSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingOccSubmissionSupport.java#L389) 触发转发器物品缓存同步。这样避免了“编辑器快照旧、图真值新”时的隐藏覆盖，但如果未来把更多写图能力重新塞回编辑器，需要继续复用同一 OCC 层，否则风险会重新升到中。

别名路径的共享状态位于全局 `NodeAliasSavedData`，当前通过 [RepeaterNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/RepeaterNetworkServerHandlerSupport.java#L88) 和 [RepeaterNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/RepeaterNetworkServerHandlerSupport.java#L138) 统一走 `RepeaterAliasMirrorSupport` 双身份镜像，并在服务端主线程网络回调中执行，线程边界明确。综合判断本轮新增并发冲突风险等级为低，建议继续保持“编辑器不直接写图、写图只走 pairing OCC”的约束。
