## 2. 关键数据结构和算法性能分析

- `coreRevision` 采用 `Map<Long, Long>` 运行时索引，读取是单次 HashMap 查询，复杂度与现有 `triggerSourceRevisions` 一致，不引入额外图遍历，见 [LinkSavedData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedData.java#L69)、[LinkSavedData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedData.java#L194)。
- 批量替换/清空时先收集 `changedCores`，再在 `markTopologyChanged(...)` 中每个受影响 `core` 只 bump 一次，避免同一批次按边重复递增；这让 `replaceTriggerSourceTargets` 和 `clearLinksForNode` 的 revision 成本保持在 `O(受影响来源数 + 受影响 core 数)`，见 [LinkSavedDataLinkIndexSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataLinkIndexSupport.java#L91)、[LinkSavedDataLinkIndexSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataLinkIndexSupport.java#L219)、[LinkSavedDataLinkIndexSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataLinkIndexSupport.java#L316)。
- `NodeLinksSnapshot` 与 `RevisionBaseline` 只是在原 DTO 上追加一个标量字段，不改变可见目标集合的归一化算法，也不新增序列化嵌套结构，见 [NodeLinksSnapshot.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/NodeLinksSnapshot.java#L16)、[NodeSnapshotQueryService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/NodeSnapshotQueryService.java#L155)、[LinkOccSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkOccSupport.java#L168)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全与语义边界：本轮没有放宽写入方向，`core` 视角仍只是在协议层表达编辑意图，真正落地依旧回到 `triggerSource -> core`，因此不会引入反向链路语义漂移，见 [PairingNetwork.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetwork.java#L212)、[PairingOccSubmissionSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingOccSubmissionSupport.java#L90)。
- 兼容性：`bench/internal` 旧的 `expectedGraphRevision` 仍可作为输入别名，但摘要字段、文案和新协议均改为 `expectedCoreRevision/coreRevision`，避免继续扩大旧语义外泄面，见 [BenchOccCommandRegistry.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/bench/BenchOccCommandRegistry.java#L374)、[BenchOccCommandRegistry.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/bench/BenchOccCommandRegistry.java#L466)、[zh_cn.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/assets/redstonelink/lang/zh_cn.json#L106)。
- 性能与扩展性：`coreRevisions` 是运行时常驻 Map，当前不会在 core 退役时主动清理；在现有序号规模下风险较低，但如果后续出现大量短生命周期 core，可评估在退役路径补一次回收，见 [LinkSavedData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedData.java#L70)、[LinkSavedDataSerialSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataSerialSupport.java#L106)。风险等级：低。

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- 共享状态：新增共享状态只有 `coreRevisions`，并且与现有 `triggerSourceToCores/coreToTriggerSources/triggerSourceRevisions` 一样，统一由 `markTopologyChanged(...)` 在同一写路径内推进，没有引入新的跨模块写入口，见 [LinkSavedData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedData.java#L70)、[LinkSavedDataLinkIndexSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataLinkIndexSupport.java#L316)。风险等级：低。
- 读改写覆盖：`core` 侧冲突判定从全图 revision 收缩到目标局部 revision，显著降低“无关 triggerSource 变更导致整图误拒绝”的概率；pairing、quick-link、bench 继续复用同一个 `LinkOccSupport`，避免不同入口的 OCC 判定分叉，见 [LinkOccSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkOccSupport.java#L59)、[QuickLinkNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetworkServerHandlerSupport.java#L251)、[BenchOccCommandRegistry.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/bench/BenchOccCommandRegistry.java#L466)。风险等级：低到中。
- 重入与线程边界：客户端新增的 `coreRevision` 只作为只读基线透传，`QuickLinkNetworkClientHandlerSupport` 的 pending apply 仍然只保存在客户端本地静态状态里；服务端真正修改 `LinkSavedData` 的路径没有新增异步写入。建议继续保持所有 OCC 写路径都在服务端主线程调用。相关位置见 [QuickLinkNetworkClientHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/network/QuickLinkNetworkClientHandlerSupport.java#L223)、[PairingNetworkClientHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/network/PairingNetworkClientHandlerSupport.java#L29)、[PairingOccSubmissionSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingOccSubmissionSupport.java#L30)。残余风险：无新的线程边界风险。
