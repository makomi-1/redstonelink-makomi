## 2. 关键数据结构和算法性能分析
- 这次没有改动模组运行时过滤判定算法，主要变更在 bench 编排层。性能关键点是把 `setupPhases` 放在 `spark` 之前执行，避免把 51 个 setup phase 的一次性命令成本混入正式测量窗口。[Bench.EntryPoint.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.EntryPoint.ps1#L127) [Bench.EntryPoint.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.EntryPoint.ps1#L256)
- `sharedOddSerials` 被抽成单一参数，8 个过滤器重复引用同一份长序号表达式，减少配置重复，也降低后续切换节点集模式时的维护成本。[sync_1024_to_1024_core_banded16_min_cover_nodeset_filters.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/performance/p26/sync_1024_to_1024_core_banded16_min_cover_nodeset_filters.json#L6) [sync_1024_to_1024_core_banded16_min_cover_nodeset_filters.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/performance/p26/sync_1024_to_1024_core_banded16_min_cover_nodeset_filters.json#L195)
- 最小覆盖布局采用 `2 x 2` 的 send 过滤器和 `2 x 2` 的 receive 过滤器，过滤器抬高到节点平面上方两格，既避免覆盖原节点，又仍然位于过滤半径内。[sync_1024_to_1024_core_banded16_min_cover_nodeset_filters.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/performance/p26/sync_1024_to_1024_core_banded16_min_cover_nodeset_filters.json#L46) [sync_1024_to_1024_core_banded16_min_cover_nodeset_filters.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/performance/p26/sync_1024_to_1024_core_banded16_min_cover_nodeset_filters.json#L118) [sync_1024_to_1024_core_banded16_min_cover_nodeset_filters.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/performance/p26/sync_1024_to_1024_core_banded16_min_cover_nodeset_filters.json#L343)

## 4. 安全、性能、兼容性、扩展性风险分析与建议
- 兼容性方面，`setupPhases` 是可选字段；旧性能 case 不提供该字段时，phase 执行器会退回原有 `phases` 读取方式，因此不会影响既有 case。[Bench.FunctionalTrace.Phases.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.Phases.ps1#L1720) [Bench.EntryPoint.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.EntryPoint.ps1#L127)
- 性能方面，长 `serialExpression` 目前仍依赖显式 slash-list，配置文件可维护性一般；若未来这类“隔 1 取 1”的节点集场景继续增长，建议为 bench 参数层补一个可生成 stepped serial 的辅助能力，而不是继续手写长串。[sync_1024_to_1024_core_banded16_min_cover_nodeset_filters.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/performance/p26/sync_1024_to_1024_core_banded16_min_cover_nodeset_filters.json#L7) [sync_1024_to_1024_core_banded16_min_cover_nodeset_filters.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/performance/p26/sync_1024_to_1024_core_banded16_min_cover_nodeset_filters.json#L195)
- 扩展性方面，这次复用功能 phase 执行器是正确方向，后续若还要在性能 case 中加入拓扑扰动、过滤器切换或命令注入，也可以继续复用 `setupPhases` 而不污染 `drive.steps` 语义。[Bench.FunctionalTrace.Phases.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.Phases.ps1#L1719) [Bench.EntryPoint.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.EntryPoint.ps1#L128)
- 风险等级：低。当前主要风险不是运行时正确性，而是配置维护成本；本轮 bench 实跑已证明该路径可用。
