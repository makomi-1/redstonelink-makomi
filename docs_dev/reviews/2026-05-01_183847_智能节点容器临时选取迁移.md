# 智能节点容器临时选取迁移

## 1. 功能与语义、架构设计（关键方法和入口）

- 本次迁移仅补齐智能节点容器的“临时槽位选取”与“过滤器/区块激活器潜行直接掉落”两条行为链，不扩展到 hide 新方块本体；核心数据入口在 [SmartNodeContainerData.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/data/SmartNodeContainerData.java#L42)，交互入口在 [SmartNodeContainerItem.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/item/SmartNodeContainerItem.java#L60)。
- 临时选取设计保持“只读旧写新”的容器内部语义：容器常驻放置类型仍然是 `triggerSource/core/repeater` 三态，新增的 `temporarySelectedSlotIndex` 仅作为一次性优先槽位覆盖，不改变现有放置类型基线，关键实现位于 [SmartNodeContainerData.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/data/SmartNodeContainerData.java#L124) 与 [SmartNodeContainerData.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/data/SmartNodeContainerData.java#L365)。
- 潜行右键命中过滤器/区块激活器时，容器不再尝试回收进箱，而是直接复用真实掉落链，这样与 1.21.11 目标行为一致，入口在 [SmartNodeContainerItem.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/item/SmartNodeContainerItem.java#L72) 和 [SmartNodeContainerItem.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/item/SmartNodeContainerItem.java#L325)。

## 2. 关键数据结构和算法性能分析

- 新增的 `temporarySelectedSlotIndex` 只是一个整型持久化字段，读写和校验成本恒定，相关字段定义与清洗逻辑位于 [SmartNodeContainerData.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/data/SmartNodeContainerData.java#L33) 和 [SmartNodeContainerData.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/data/SmartNodeContainerData.java#L447)。
- 临时槽位循环的候选集查找按容器内容线性扫描，复杂度为 O(n)，在 54 格固定容量下开销稳定；关键路径在 [SmartNodeContainerData.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/data/SmartNodeContainerData.java#L324) 与 [SmartNodeContainerData.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/data/SmartNodeContainerData.java#L341)。
- 直接掉落路径只在潜行命中特定方块时触发，主要成本为一次 `Block.getDrops` 与逐掉落物抛出，不会影响容器普通放置主链，关键实现位于 [SmartNodeContainerItem.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/item/SmartNodeContainerItem.java#L338)。

## 3. 数据流或调用链

- 容器放置链路为：`useOn` 进入 [SmartNodeContainerItem.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/item/SmartNodeContainerItem.java#L60) → 读取容器快照 → [SmartNodeContainerData.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/data/SmartNodeContainerData.java#L365) 解析优先槽位 → 放置成功后通过 [SmartNodeContainerData.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/data/SmartNodeContainerData.java#L78) 持久化，并清空一次性临时选择。
- 容器菜单持久化链路仍维持现有结构，只是把新参数同步补到写回口，落点在 [SmartNodeContainerMenu.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/menu/SmartNodeContainerMenu.java#L276)。
- 直接掉落链路为：潜行命中判定 [SmartNodeContainerItem.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/item/SmartNodeContainerItem.java#L317) → 进入 [SmartNodeContainerItem.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/item/SmartNodeContainerItem.java#L325) → 解析真实掉落 → 删除原方块并抛出掉落物。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 兼容性方面，本次没有修改 `triggerSource/core` 命名、映射和方向语义；新增字段只在智能节点容器内部消费，现有旧数据缺失该字段时会回退到 `-1`，兼容读取位于 [SmartNodeContainerData.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/data/SmartNodeContainerData.java#L447)。
- 行为风险方面，目前容器分类仍只识别现有 `LINK_REPEATER`，没有提前依赖尚未迁入的 hide repeater 常量，这保证了本步可以独立通过编译，但也意味着 hide repeater 迁入后还要回补分类口，相关暂存点在 [SmartNodeContainerData.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/data/SmartNodeContainerData.java#L223)。
- 扩展性方面，后续若继续迁移“中键循环临时槽位”的客户端交互，只需要在现有 `cycleTemporarySelectedSlot` 基础上补网络/界面入口，不必改动容器持久化结构，关键支撑已在 [SmartNodeContainerData.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/data/SmartNodeContainerData.java#L341) 预留完成。

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- 新增的临时槽位字段仍通过 `ItemStack` 自定义数据在服务端主线程内读改写，没有引入新的跨线程共享状态；风险等级为低，关键写口集中在 [SmartNodeContainerData.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/data/SmartNodeContainerData.java#L78)。
- 菜单与物品侧都能写回同一容器物品，因此本步专门把菜单持久化口也补齐到统一签名，减少“菜单清掉新字段、物品再写回”的覆盖风险，落点在 [SmartNodeContainerMenu.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/menu/SmartNodeContainerMenu.java#L287)。
- 直接掉落路径只在服务端 `useOn` 主链中执行，未引入异步掉落实体生成或额外缓存，当前没有新增重入风险；后续若给该路径增加网络反馈，应保持“服务端落地结果唯一、客户端只做展示”的边界。
