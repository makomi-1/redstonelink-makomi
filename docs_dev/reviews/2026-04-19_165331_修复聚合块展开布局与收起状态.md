# 修复聚合块展开布局与收起状态

## 1. 功能与语义、架构设计

- 本次修复将“节点保活显示”和“聚合块自动展开”拆成两套集合：`GraphViewer` 里新增 `aggregateAutoExpandNodeKeys`，只让搜索、批量编辑和手动揭示孤立节点参与自动展开，而 `selectedNodeKey` 仅保留画布上下文可见性。[GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L410) [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L423)
- 画布构建层新增了独立的聚合块自动展开入参，序号模式与频道模式都统一改为使用该口径，避免“仅因选中成员可见”就把聚合块撑开。[canvas.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L421) [canvas.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L507) [canvas.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L619) [canvas.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L973)
- 序号模式下，展开聚合块后的 `triggerSource/core` 两侧现在都关闭 jitter，展开后的成员块统一走整齐布局，不再出现只修正一侧的非对称表现。[canvas.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L1521) [canvas.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L1643)
- 另外补了一层展开态回收：当当前画布里的聚合块集合变化时，会把已失效的 `expandedAggregateNodeKeys` 从本地状态中裁掉，避免旧结构状态残留。[GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L452)

## 2. 关键数据结构和算法性能分析

- `aggregateAutoExpandNodeKeys` 与 `forcedVisibleNodeKeys` 都是 `Set<string>`，构建成本与“搜索命中节点数 + 批量编辑选区大小 + pinned 节点数”线性相关，属于轻量级前端集合运算。[GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L410) [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L423)
- `resolveCanvasAggregateVisibility(...)` 现在先收集边驱动的可见节点，再叠加“自动展开上下文”和“强制显示上下文”，整体仍然是对边和节点集合的线性扫描，没有引入新的高阶复杂度。[canvas.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L507)
- 展开态回收通过一次 `filter` 裁剪当前数组，时间复杂度为 O(k)，其中 k 为当前显式展开的聚合块数量，远小于整图节点数，适合挂在 `useEffect` 中做增量清理。[GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L456)
- 整齐布局修复只影响 `buildLaneLayout(...)` 的 `allowJitter` 判定，不改变布局网格规模和连通分量划分算法，因此不会额外放大自动布局开销。[canvas.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L1459) [canvas.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L1643)

## 3. 数据流或调用链

- 页面状态先在 `GraphViewer` 中根据搜索、编辑选区和当前选中节点生成两套可见性集合，再传给 `buildGraphCanvasView(...)` 生成当前模式的 `graphCanvasView`。[GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L410) [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L434)
- `buildGraphCanvasView(...)` 再分派到序号/频道模式构建函数，分别在聚合块生成阶段计算 `expanded`，并在最终可见性收敛阶段决定哪些成员、聚合块和边进入画布。[canvas.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L619) [canvas.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L973) [canvas.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L1270)
- 自动布局随后使用 `buildComponentLayout(...)`，在检测到组件内存在展开聚合块后，对序号模式两侧 lane 统一关闭 jitter，保证展开块成员排列规整。[canvas.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L1521) [canvas.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L1643)
- 单测覆盖了两条关键数据流：一条验证“选中成员仅保活可见但不自动展开”，另一条验证“展开的 triggerSource 聚合块成员位置保持整齐”。[canvas.test.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.test.tsx#L75) [canvas.test.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.test.tsx#L223)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全性方面，本轮仅改前端内存态和视图生成逻辑，不涉及服务端写入协议、权限或持久化结构变更，风险较低。[GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L434)
- 性能方面，新增逻辑主要是 `Set` 构建和状态裁剪，已经通过前端类型检查、纯逻辑测试、组件测试和整项目 Gradle 回归，当前未见明显性能回退迹象。[canvas.test.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.test.tsx#L75) [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L452)
- 兼容性方面，`buildGraphCanvasView(...)` 通过新增默认参数保持旧调用兼容，因此现有纯逻辑测试和其它未显式传入新参数的调用点不会被强制改写。[canvas.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L1270)
- 扩展性方面，如果后续还要细分“搜索驱动展开”“编辑驱动展开”“仅聚焦不展开”等更细的显示策略，现在这层拆分已经提供了稳定切入点，建议继续沿“显示集合”和“展开集合”分离的方式扩展，避免再次混用单一状态源。[GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L410) [canvas.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L507)

## 5. 并发冲突审查

- 共享状态主要集中在 React 状态：`expandedAggregateNodeKeys`、`selectedNodeKey`、`graphCanvasView`。本次新增的展开态回收使用函数式 `setState`，可以在 React 批量更新下避免直接覆盖并发写入，风险等级为低。[GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L452)
- 画布布局与可见性计算仍然保持纯函数链路，`canvas.tsx` 内没有新增可变共享缓存，因此不存在新的跨渲染重入污染点，风险等级为低。[canvas.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L507) [canvas.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L1521)
- 唯一需要持续关注的是：如果后续再引入新的“强制显示来源”但忘记同步决定其是否该参与 `aggregateAutoExpandNodeKeys`，仍可能出现显示与展开口径漂移。这个风险当前通过显式拆分得到控制，风险等级为中低，建议后续新增来源时始终同时评估“仅保活显示”还是“需要自动展开”。[GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L410) [GraphViewer.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L423)
