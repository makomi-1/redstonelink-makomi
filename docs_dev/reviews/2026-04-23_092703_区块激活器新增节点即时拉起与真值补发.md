## 4. 安全、性能、兼容性、扩展性风险分析与建议

安全与兼容性方面，本轮没有改变 `triggerSource/core` 语义边界，也没有引入反向写入；`triggerSource` replay 仍只按 `triggerSource -> core` 发布 `SYNC_SIGNAL UPSERT`，并继续经过持久化 send/receive 过滤器补判。[InternalDispatchDeltaRuleSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/InternalDispatchDeltaRuleSupport.java:731)

主要残余风险是“最后登记坐标可能已陈旧”。如果节点已被物理移除但运行态清理尚未完成，这次 resident/transient bootstrap 可能会对旧 chunk 补一次短生命周期票据。不过现有脏记录清理与下一个同步周期会把票据收回，因此风险主要是一次短暂误拉起，而不是长时间泄漏。[PairableNodeBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/PairableNodeBlockEntity.java:139) [ChunkActivatorImmediateEffectService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/ChunkActivatorImmediateEffectService.java:98) [ChunkActivatorImmediateEffectService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/ChunkActivatorImmediateEffectService.java:125)

扩展性方面，当前 replay helper 只对有稳定 sync 真值的 `triggerSource` 生效；`toggle/pulse` 仍不会被“补当前真值”强行恢复。这与现有设计一致，但如果未来希望扩到其它来源类型，建议继续沿用“先抽象 truth provider，再统一过滤和发布”的方式扩展，而不是在 activator service 内堆 if/else。[InternalDispatchDeltaRuleSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/InternalDispatchDeltaRuleSupport.java:731)

## 5. 并发冲突审查
