# 箭头外移与hide物品单层模型

## 1. 功能与语义、架构设计（关键方法和入口）

- 本轮继续沿用公共箭头渲染支持，只调整几何位置，不改方向真值与主题色分流逻辑。箭头仍通过 `renderEnabledFaceVectors` 读取面集，再按 `core/repeater` 与输入型节点分流显示方向，结构入口保持在共享支持中，避免各 renderer 再次分叉实现。[DirectionalFaceVectorRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/DirectionalFaceVectorRenderSupport.java#L31)
- 箭头外移通过上调 `ARROW_SHAFT_START/END` 完成，让整根箭头落在方块表面外部；调用链不变，因此 `hide` 与可见节点会一起获得相同外移效果。[DirectionalFaceVectorRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/DirectionalFaceVectorRenderSupport.java#L32)
- `hide` 物品模型从双层 `dual_layer_cube` 改为单层 `minecraft:block/cube_all`，仅保留 `_hide` 贴图，满足“块显示但只要最外层”的交互要求。[hide_core.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/assets/redstonelink/models/item/hide_core.json#L1) [hide_sync_trigger_source.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/assets/redstonelink/models/item/hide_sync_trigger_source.json#L1)

## 2. 关键数据结构和算法性能分析

- 箭头渲染仍是按当前方块状态的启用面列表做一次线段输出，时间复杂度保持 `O(f)`，其中 `f <= 6`，本轮只改起止坐标常量，不引入新的世界扫描或缓存结构。[DirectionalFaceVectorRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/DirectionalFaceVectorRenderSupport.java#L85)
- 单层 item model 仅减少了模型层数，不增加任何运行时逻辑；相对双层模型，GPU 侧面片数量更少，显示成本只会下降不会上升。[hide_core.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/assets/redstonelink/models/item/hide_core.json#L2)

## 3. 数据流或调用链

- 玩家佩戴智能眼镜并手持定向编辑器时，各 block entity renderer 仍会进入公共箭头渲染路径；本轮没有改这条调用链，只让最终落点从“方块内外混合”变成“完全在方块外侧”。[DirectionalFaceVectorRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/DirectionalFaceVectorRenderSupport.java#L73)
- `hide` 物品渲染链则从“item model -> dual_layer_cube -> outer+inner 纹理”收敛成“item model -> cube_all -> all 纹理”，输入贴图资源仍然是你已补好的 `_hide` PNG，没有改资源本体。[hide_sync_trigger_source.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/assets/redstonelink/models/item/hide_sync_trigger_source.json#L2)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全：本轮仅改客户端渲染与资源模型，不涉及服务端状态、存档格式或网络协议，安全风险为低。[DirectionalFaceVectorRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/DirectionalFaceVectorRenderSupport.java#L31)
- 性能：箭头外移只改常量，不引入额外 draw call；单层 item model 还减少了一个内层体，性能风险为低。[DirectionalFaceVectorRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/DirectionalFaceVectorRenderSupport.java#L35)
- 兼容性：`minecraft:block/cube_all` 是标准父模型，兼容性通常稳定；但它的 GUI 光照与之前双层模型可能略有差异，若后续实机对物品高光还有细节要求，可再补自定义单层 block model 细调。[hide_core.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/assets/redstonelink/models/item/hide_core.json#L2)
- 扩展性：当前箭头几何仍集中在公共支持里，后续若还要继续调可见度或长度，只需继续改这一处常量即可，不会再波及各 renderer 的分支逻辑。[DirectionalFaceVectorRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/DirectionalFaceVectorRenderSupport.java#L32)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- 共享状态：本轮没有新增共享可变状态；箭头参数仍是静态常量，item model 仍是静态资源文件，风险低。[DirectionalFaceVectorRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/DirectionalFaceVectorRenderSupport.java#L32)
- 读改写覆盖：修改仅限单个公共渲染支持和两个 item model；没有对运行时面集、节点序号或 SavedData 做读改写，覆盖风险低。[hide_sync_trigger_source.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/assets/redstonelink/models/item/hide_sync_trigger_source.json#L1)
- 重入/线程边界：渲染代码仍运行在客户端渲染线程，资源模型由资源加载系统读取；本轮未引入异步任务或跨线程协作，风险低。[DirectionalFaceVectorRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/DirectionalFaceVectorRenderSupport.java#L85)
- 建议：若后续继续做显示层微调，优先保持“公共 support 调常量”的路径，不要重新把几何参数散回各 renderer，避免并行修改时再次出现表现不一致。
