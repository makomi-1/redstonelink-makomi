# 主题切换收紧与页面紧凑化

## 1. 功能与语义、架构设计

本轮改动保留三套网页主题的切换能力，但把主题区从“预览模板”收敛成了真正的轻量工具条，同时把主题切换并入 graph / recording 页头部，减少主交互区之前的装饰层。整体架构没有变化，仍然是页面组件负责组织头部与主内容，`ThemeSwitcher` 只负责主题切换，不承载业务状态。

- 主题切换组件已改为紧凑按钮组，入口见 [ThemeSwitcher.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/ThemeSwitcher.tsx#L18)
- graph 页把主题切换直接并入头部工具条，见 [GraphPage.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app/GraphPage.tsx#L93)
- recording 页同样并入头部工具条，见 [RecordingPage.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app/RecordingPage.tsx#L79)

## 2. 关键数据结构和算法性能分析

本轮没有新增算法或数据结构，核心变化都在静态样式和组件结构层。性能影响非常低，因为主题切换器只是减少了渲染节点数量，布局收紧也主要体现在 CSS 间距和尺寸参数上，不会增加额外计算复杂度。相反，主题区从大卡片变成头部内联工具条后，页面首屏 DOM 更扁平。

- 主题切换器从大卡片内容变成轻量横向控件，样式入口见 [app.css](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L583) 与 [app.css](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L606)
- 头部与主内容区间距已统一收紧，见 [app.css](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L1071) 与 [app.css](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L1148)
- graph 工作区与录制图表卡片也同步收紧，见 [app.css](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L1327) 与 [app.css](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L1748)

## 3. 数据流或调用链

数据流和调用链保持不变，主题切换仍是页面把 `themeId` 传入 `ThemeSwitcher`，用户点击后触发父层 `onThemeChange`，再由页面容器上的 `data-theme` 驱动整套 CSS 变量生效。本轮没有改动 graph / recording 的数据加载或业务交互路径，只改变了这些控件在页面上的组织方式。

- 主题切换交互入口在 [ThemeSwitcher.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/ThemeSwitcher.tsx#L18)
- graph 页头部仍负责 graph 文件选择、刷新和主题切换整合，见 [GraphPage.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app/GraphPage.tsx#L93)
- recording 页头部仍负责 recording 文件选择、刷新和主题切换整合，见 [RecordingPage.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app/RecordingPage.tsx#L79)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

安全层面本轮不涉及接口、权限、持久化或脚本执行能力变化，风险低。性能层面属于纯前端布局收紧，风险也低。兼容性层面需要注意的是，主题切换器从说明卡片改成紧凑按钮后，未来若新增更多主题，头部横向空间会更容易拥挤；当前 CSS 已为折行和窄屏做了兼容，但若主题数量继续增加，建议再引入分组或下拉切换而不是继续堆按钮。

- 紧凑主题按钮的窄屏适配入口见 [app.css](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L1913)
- 根路由和主题状态回归测试仍然覆盖到了 graph 默认页，见 [App.test.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/App.test.tsx#L44)
- graph 页基础渲染与文件切换测试仍有效，见 [GraphPage.test.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app/GraphPage.test.tsx#L19)

## 5. 并发冲突审查

本轮没有新增共享可变状态，也没有新增异步并发写入路径。主题切换仍然沿用既有的单一 `themeId` 状态，页面布局只受该状态和 CSS 影响，不存在多源竞争写覆盖的问题。整体并发风险等级为低。

- 主题切换仍由单一组件回调触发，见 [ThemeSwitcher.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/ThemeSwitcher.tsx#L18)
