# 智能节点容器替代聚合壳与移除mixin

## 1. 功能与语义、架构设计
- 本次把“聚合壳”替换为一个真正的手持容器物品：注册入口位于 [ModItems.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/registry/ModItems.java#L169) 与 [ModItemGroups.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/registry/ModItemGroups.java#L43)，菜单类型注册位于 [ModMenuTypes.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/registry/ModMenuTypes.java#L15)。这意味着节点收纳、打开、排序和放置都不再依赖原先的聚合补丁链。
- 交互入口已经收敛为三件事：`B` 键打开容器、中键循环当前放置类型、主手右键从容器内按当前类型弹出一个节点并尝试放置；对应入口分别在 [RedstoneLinkClient.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/RedstoneLinkClient.java#L213)、[RedstoneLinkClient.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/RedstoneLinkClient.java#L297) 与 [SmartNodeContainerItem.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/item/SmartNodeContainerItem.java#L53)。
- 容器非空时，侧面外显现在完全由“当前切换到的放置类型”驱动，而不是按库存中是否存在该类型驱动；类型定义与模型状态值在 [SmartNodeContainerPlacementType.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/SmartNodeContainerPlacementType.java#L14)，非空判定后的 `custom_model_data` 写入在 [SmartNodeContainerData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/SmartNodeContainerData.java#L257)，模型覆盖链路在 [smart_node_container.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/assets/redstonelink/models/item/smart_node_container.json#L1)。
- mixin 已整体退场，Fabric 元数据里不再声明任何 mixin 配置，只保留主入口和客户端入口 [fabric.mod.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/fabric.mod.json#L18)；服务端初始化改为直接注册智能节点容器网络与菜单 [RedstoneLink.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/RedstoneLink.java#L47)。

## 2. 关键数据结构和算法性能分析
- 智能节点容器的核心持久化结构是一个固定 54 槽的 `NonNullList<ItemStack>`，并额外维护 `selectedType / autoSort / itemCount` 三个控制字段；读写入口集中在 [SmartNodeContainerData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/SmartNodeContainerData.java#L24) 与 [SmartNodeContainerData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/SmartNodeContainerData.java#L66)。这种设计直接保存完整节点 `ItemStack`，不会丢失序号、频道、别名或转发器参数。
- 准入过滤在 [SmartNodeContainerData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/SmartNodeContainerData.java#L130) 实现，只允许 `core / triggerSource / repeater` 三类节点进入容器，并显式拒绝历史聚合栈 `LinkItemData.isAggregated(stack)`；这让新容器系统和旧聚合数据模型保持隔离。
- 自动排序使用“类型优先、类内按序号升序”的稳定规则：类型顺序在 [SmartNodeContainerPlacementType.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/SmartNodeContainerPlacementType.java#L15) 固定为 `core -> triggerSource -> repeater`，排序实现位于 [SmartNodeContainerData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/SmartNodeContainerData.java#L175)。由于槽位上限固定为 54，排序成本稳定且很低。
- 容器外显状态同步是 O(1) 的：只要 `itemCount > 0`，就把当前选中类型映射成 `custom_model_data` 1/2/3；逻辑位于 [SmartNodeContainerData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/SmartNodeContainerData.java#L257)，不会引入额外扫描或渲染期计算。

## 3. 数据流或调用链
- 开箱链路：客户端在 [RedstoneLinkClient.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/RedstoneLinkClient.java#L586) 发送打开 payload，协议定义在 [SmartNodeContainerNetwork.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/SmartNodeContainerNetwork.java#L23)，服务端接包注册在 [SmartNodeContainerNetworkRegistrationSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/SmartNodeContainerNetworkRegistrationSupport.java#L27)，最终由 [SmartNodeContainerNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/SmartNodeContainerNetworkServerHandlerSupport.java#L20) 打开 [SmartNodeContainerMenu.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/menu/SmartNodeContainerMenu.java#L54)。
- 切换类型链路：客户端中键先在本地更新主手物品快照并提示文本 [RedstoneLinkClient.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/RedstoneLinkClient.java#L596)，服务端随后在 [SmartNodeContainerNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/SmartNodeContainerNetworkServerHandlerSupport.java#L33) 持久化切换结果并广播变化，最终触发 [SmartNodeContainerData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/SmartNodeContainerData.java#L109) 的模型状态同步。
- 菜单库存链路：服务端菜单构造时从主手容器读取 54 槽库存 [SmartNodeContainerMenu.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/menu/SmartNodeContainerMenu.java#L54)，槽位变更后经 [SmartNodeContainerMenu.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/menu/SmartNodeContainerMenu.java#L214) 分流到自动排序或直接持久化，最终统一写回主手物品 [SmartNodeContainerMenu.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/menu/SmartNodeContainerMenu.java#L248)。
- 放置链路：主手右键时，容器会读取当前选定类型、查找第一个匹配槽位、确保序号并调用原版 `BlockItem.place` 尝试放置；实现集中在 [SmartNodeContainerItem.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/item/SmartNodeContainerItem.java#L53)。放置成功后会回写库存、按需排序并广播菜单变化 [SmartNodeContainerItem.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/item/SmartNodeContainerItem.java#L93)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议
- 安全与权限边界方面，容器所有关键入口都坚持“主手必须是智能节点容器”校验：菜单有效性检查在 [SmartNodeContainerMenu.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/menu/SmartNodeContainerMenu.java#L92)，服务端开箱与切型检查在 [SmartNodeContainerNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/SmartNodeContainerNetworkServerHandlerSupport.java#L20) 和 [SmartNodeContainerNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/SmartNodeContainerNetworkServerHandlerSupport.java#L33)，不会因为客户端伪触发而越权操作其他物品。
- 兼容性方面，本次实现没有引入 `com.makomi.api.v1.*` 依赖；节点分类继续落在既有 `LinkNodeType.CORE / TRIGGER_SOURCE` 映射上，判断逻辑见 [SmartNodeContainerData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/SmartNodeContainerData.java#L140)。同时，旧聚合壳对应的 mixin 配置已经从元数据层移除 [fabric.mod.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/fabric.mod.json#L18)，这意味着旧的“聚合角标 / 菜单归并 / 创造栏 tooltip 补丁”是有意退场，不是遗漏。
- 性能方面，自动排序和持久化都只在 54 槽本地列表上执行；排序逻辑位于 [SmartNodeContainerData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/SmartNodeContainerData.java#L175)，菜单写回位于 [SmartNodeContainerMenu.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/menu/SmartNodeContainerMenu.java#L248)。在正常玩家交互频率下，这部分开销远低于世界交互和渲染成本。
- 扩展性风险主要有一个：当前双层模型的 `up/down` 都复用 `smart_node_container_bottom`，因为现有资源链只准备了 `bottom + side + type side`，模型定义见 [smart_node_container.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/assets/redstonelink/models/block/smart_node_container.json#L1) 与 [dual_layer_oriented_cube.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/assets/redstonelink/models/block/dual_layer_oriented_cube.json#L15)。如果后续要做独立顶面视觉，需要再补 `top` 纹理并拆分 `outer_end` 贴图位。

## 5. 并发冲突审查
- 共享状态集中在“主手容器物品 NBT + 菜单内 54 槽缓存”两处，写入入口已经收敛到 [SmartNodeContainerMenu.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/menu/SmartNodeContainerMenu.java#L248) 和 [SmartNodeContainerItem.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/item/SmartNodeContainerItem.java#L97)，没有新增跨玩家共享容器或全局缓存。
- 读改写覆盖风险主要来自“排序回调再次触发 setChanged”这一类重入问题，当前通过 [SmartNodeContainerMenu.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/menu/SmartNodeContainerMenu.java#L37) 的 `sortingContents` 标记和 [SmartNodeContainerMenu.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/menu/SmartNodeContainerMenu.java#L283) 的 `suppressCallback` 进行了隔离，能避免排序过程中的重复回写风暴。
- 线程边界方面，客户端网络接包后统一切回服务端主线程再执行真实逻辑，相关切换在 [SmartNodeContainerNetworkRegistrationSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/SmartNodeContainerNetworkRegistrationSupport.java#L27)。本次没有引入新的后台线程、锁或异步容器，因此线程安全风险等级低。
- 建议：如果后续要给智能节点容器继续叠加批量导入/导出或跨容器搬运功能，应继续沿用“所有真实写入都回到服务端主线程、所有物品状态都通过单一持久化入口落盘”的结构，避免客户端预测写入和菜单回调写入并存导致状态漂移；当前可复用入口分别是 [SmartNodeContainerData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/SmartNodeContainerData.java#L66) 与 [SmartNodeContainerMenu.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/menu/SmartNodeContainerMenu.java#L248)。
