## 1. 功能与语义、架构设计（关键方法和入口）
- 新增频道模式中间收口调度器，职责限定为“频道模式 loaded direct 路径先按频道收口，再按目标 core 分发到已有目标级批调度或直接批应用”，没有改动 pending/ready 队列和普通边持久化设计。[ChannelDispatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/ChannelDispatchScheduler.java#L31)
- 模组初始化阶段把频道调度器注册在 `CoreDispatchBatchScheduler` 之前，保证同 tick `END_SERVER_TICK` 时频道桶先 flush，再让 core 批窗口继续处理，避免同 tick 链路被额外拖后一拍。[RedstoneLink.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/RedstoneLink.java#L40) [RedstoneLink.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/RedstoneLink.java#L66)
- `LinkedTargetDispatchService` 新增“按来源解析目标”的派发重载，并在内部按来源模式自动选择 serial links 或 channel members；只有 `triggerSource -> core` 且来源处于频道模式时才进入频道中间层，保持方向语义仍是 `triggerSource/core`，旧术语没有新增落库或对外输出。[LinkedTargetDispatchService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkedTargetDispatchService.java#L75) [LinkedTargetDispatchService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkedTargetDispatchService.java#L273) [LinkedTargetDispatchService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkedTargetDispatchService.java#L566)
- 触发源方块、遥控器、同步遥控器和批量激活命令都已切换到新入口，不再先读取 `getLinkedCoresByTriggerSource(...)` 再派发，因此频道模式下不会被旧 serial links 预取短路；“未设置目标”的判断统一改用 `dispatchSummary.totalTargets() == 0`。[TriggerSourceBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/TriggerSourceBlockEntity.java#L86) [LinkerItem.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/item/LinkerItem.java#L354) [SyncLinkerItem.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/item/SyncLinkerItem.java#L95) [ActivateCommandRegistry.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/activate/ActivateCommandRegistry.java#L179)

## 2. 关键数据结构和算法性能分析
- 频道层状态按 `server -> (tick, graphRevision, channel)` 建桶，同一频道同 tick 的 loaded direct 事件只入一次频道桶，再在桶内按目标 `core` 聚合，避免频道模式直接走 `n × m` 的逐目标即时展开。[ChannelDispatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/ChannelDispatchScheduler.java#L58) [ChannelDispatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/ChannelDispatchScheduler.java#L188) [ChannelDispatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/ChannelDispatchScheduler.java#L220)
- 单目标累计器只保存 `stagedEntries` 和两份 scratch 列表，flush 时按配置分成“继续进 core batch”和“直接 applyDispatchBatch”两路，空间复杂度主要与“当前 tick 活跃频道数 × 命中的唯一目标数”相关，没有引入跨 tick 常驻大桶。[ChannelDispatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/ChannelDispatchScheduler.java#L271)
- 目标解析在 `LinkedTargetDispatchService` 内集中完成，serial 模式仍走普通边快照，channel 模式直接读频道成员索引，因此常规调用方不再各自预取和分支，减少了重复查询与分支散落。[LinkedTargetDispatchService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkedTargetDispatchService.java#L566)
- 为了不让单元测试 dummy server 触发非业务空指针，频道层与 core 批层的当前 tick 读取都增加了“未完整初始化 server 时回退”的保护；这不改变正式服路径，只降低测试/最小桩环境下的脆弱性。[ChannelDispatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/ChannelDispatchScheduler.java#L166) [CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L382)

## 3. 数据流或调用链
- 调用链现在是：触发入口调用 `LinkedTargetDispatchService` 新重载 -> 内部解析来源模式对应的目标集合 -> loaded target 若满足频道模式条件则转为 `LoadedChannelTarget` 列表 -> 写入 `ChannelDispatchScheduler` -> `END_SERVER_TICK` 或 late-arrival 补 flush 时转发到 `CoreDispatchBatchScheduler` 或直接目标批应用。[TriggerSourceBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/TriggerSourceBlockEntity.java#L117) [LinkedTargetDispatchService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkedTargetDispatchService.java#L273) [LinkedTargetDispatchService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkedTargetDispatchService.java#L443) [ChannelDispatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/ChannelDispatchScheduler.java#L131) [CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L155)
- `dispatchInternal(...)` 保留原有过滤器检查、pending queue 入队和跨区块提示统计，因此这次优化只改 loaded direct 的中间收口，不重写现有跨区块/过滤服务接入点。[LinkedTargetDispatchService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkedTargetDispatchService.java#L273)
- 新增测试覆盖了 late-arrival 判定和“频道桶 flush 后写入 core 批调度器”的关键链路，保证频道中间层不会停留在只靠人工推断的状态。[ChannelDispatchSchedulerTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/data/ChannelDispatchSchedulerTest.java#L52) [ChannelDispatchSchedulerTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/data/ChannelDispatchSchedulerTest.java#L66)

## 4. 安全、性能、兼容性、扩展性风险分析与建议
- 当前实现只收口频道模式的 loaded direct 路径，pending queue 的 ready drain 仍保持旧模型。这符合本轮最小范围目标，但如果未来希望让“目标区块恢复后的 ready release”也享受频道侧 `n -> 1 -> m` 收口，还需要追加独立设计和验证。[ChannelDispatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/ChannelDispatchScheduler.java#L28)
- 频道桶键里带了 `graphRevision`，同 tick 内若拓扑先变再发，旧桶不会与新拓扑混并；代价是拓扑抖动场景下会产生更多短生命周期小桶，但这是必要的正确性成本。[ChannelDispatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/ChannelDispatchScheduler.java#L78)
- `resolveDispatchTargets(...)` 只对 `triggerSource -> core` 的频道模式走频道成员索引，其他组合仍回退普通边；这与当前语义模型一致，但如果以后扩展新的合法方向，需要在这里和调用方一并补方向规则，而不是直接放宽查询条件。[LinkedTargetDispatchService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkedTargetDispatchService.java#L566)
- 兼容性方面，本轮没有引入 `com.makomi.api.v1.*` 依赖，也没有修改持久化键名、边存储结构和旧数据读取逻辑；语义对齐检查结果为：命名继续使用 `triggerSource/core`，方向仍是来源到目标单向，兼容层仍是“读旧写新”现状，无新增残余风险。

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）
- 频道调度器和 core 批调度器都继续通过 `ServerThreadGuard` 强制主线程访问，共享状态分别挂在 `IdentityHashMap<MinecraftServer, ...>` 上；并发风险仍主要来自越线程误入，当前保护等级为低风险。[ChannelDispatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/ChannelDispatchScheduler.java#L32) [ChannelDispatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/ChannelDispatchScheduler.java#L65) [CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L41)
- 频道层 flush 阶段是“遍历频道桶 -> 目标级累计器 flush -> 写入 core 批调度器”，不会在频道层内部再递归修改正在迭代的 `pendingByChannel`；core 批调度器本身已有 apply-phase 延迟 drain 机制吸收重入补 flush，请求链路仍是可收敛的。[ChannelDispatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/ChannelDispatchScheduler.java#L131) [CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L223) [CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L623)
- 读改写覆盖方面，频道层同目标累计器只是保留原始条目列表，真正的“同源同 kind 取最新”仍由 core 批调度器负责，因此不会在频道层过早丢语义；风险等级为中低，建议后续若把 ready drain 也纳入频道层时继续复用同样的“频道只收口、不提前裁决”原则。[ChannelDispatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/ChannelDispatchScheduler.java#L289) [CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L534)
