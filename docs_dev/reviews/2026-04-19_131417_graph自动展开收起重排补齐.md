# graph自动展开收起重排补齐

## 1. 功能与语义、架构设计（关键方法和入口）

- 本轮在 `GraphViewer` 中新增了 `buildCanvasStructureSignature(...)`，只抽取会影响自动布局的节点集合与布局边集合，显式忽略选中态、搜索高亮和文案变化，避免把非结构变化误判成重排请求。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L138)
- `previousCanvasStructureSignatureRef` 用于缓存上一轮画布结构签名，切图或重载 graph 时会被清空，从而避免把上一份图的结构误当成当前图的对比基线。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L241) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L723)
- 自动展开/收起的来源仍保持原有语义：`selectedNodeKey`、搜索命中、临时显示和编辑选区共同组成 `forcedVisibleNodeKeys`，并由 `canvas.tsx` 的聚合可见性收敛逻辑决定哪些聚合块进入视觉展开态。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L406) [canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L477)
- 语义对齐检查结果：本轮只补前端视图层重排行为，命名仍统一使用 `triggerSource/core`，真实保存方向与服务端真值协议保持不变，无新增旧术语泄漏。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1190)

## 2. 关键数据结构和算法性能分析

- 结构签名算法使用 `canvasNodes` 与 `layoutEdges` 的稳定 token 列表构成字符串签名，复杂度为 `O((V + E) log(V + E))`，其中排序只发生在画布结构变化相关的计算路径上，规模与当前可视节点/边一致，可接受。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L146)
- 主 `setNodes/setEdges` effect 现在把“显式结构重排请求”与“签名变化”统一折算为 `shouldResetPositions`；当且仅当该值为真时才丢弃旧坐标并重新应用自动布局，避免对普通高亮更新重复挤开。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L852)
- 现有聚合自动展开判断仍由 `resolveCanvasAggregateVisibility(...)` 完成，本轮没有重复实现这套逻辑，而是直接复用它的输出结果做结构签名，因此没有引入双份拓扑判定代码，保持了 DRY。[canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L505)

## 3. 数据流或调用链

- 搜索应用链路仍然是：`handleApplySearch()` 更新已应用搜索态，并在命中首个节点时调用 `focusNode(...)`；不同的是，搜索命中导致 `forcedVisibleNodeKeys` 改变后，`graphCanvasView` 的节点/布局边变化会被结构签名捕获，从而自动触发一次坐标重排。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1510) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L406) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L852)
- 手动展开/收起链路保持原状：`requestStructureLayoutRefresh(...)` 仍负责显式设置 `pendingStructureLayoutReset` 与上下文焦点；本轮只是补了自动结构变化也能走同一套坐标重算分支，没有替换原有入口。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1196)
- 自动聚焦链保持不变：普通上下文聚焦仍由 `focusNode(...) -> pendingFocusNodeKey` 触发，手动展开后的局部聚焦仍由 `pendingAggregateFocusNodeKey` 与 `pendingPostLayoutFocusNodeKey` 在重排后执行；本轮没有新增新的 `fitView` 入口。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L919) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L971) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1023)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全与兼容性：本轮未改服务端请求、未改 `GraphDraft` 结构、未改保存协议，只影响前端画布节点坐标如何在结构变化时更新，因此与现有预检/保存链路兼容。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1153)
- 性能：自动结构变化现在会多一次位置重排，但只在结构签名真的变化时触发，不会因为搜索高亮、选中态或 alias 文案变化反复重排；这比逐个入口强行 `requestStructureLayoutRefresh(...)` 更可控。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L856)
- 扩展性：后续若新增其他通过 `graphCanvasView.canvasNodes/layoutEdges` 体现出来的自动结构变化来源，将天然被当前方案覆盖；只有当未来布局依赖新增到这些集合之外时，才需要扩充签名内容。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L442)
- 残余风险：当前自动结构变化仍不会触发整图归位，这符合本轮约束，但意味着无焦点的自动收起场景只会重排、不主动把视角拉回全图；若后续产品预期变化，需要单独设计新的视口策略而不是在这里临时补 `fitView`。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L942)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- 共享状态主要是 `previousCanvasStructureSignatureRef`、`pendingStructureLayoutReset` 与 `nodes`。其中结构签名缓存使用 `ref` 而非 `state`，避免为了记录上一轮签名再引入额外 render；风险等级低。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L241) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L858)
- 读改写覆盖方面，主 effect 统一基于当前 render 的 `canvasStructureSignature` 与 `pendingStructureLayoutReset` 计算 `shouldResetPositions`，并且只在显式重排标记为真时回写 `setPendingStructureLayoutReset(false)`，避免自动结构变化把手动展开请求提前清掉；风险等级低。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L856) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L894)
- 线程边界方面，本轮逻辑全部在 React 前端主线程 effect 中完成，没有新增异步共享内存或跨线程访问；与现有 `requestAnimationFrame` 聚焦链的关系仍然是“先重排、后聚焦”，因此不会引入新的重入型视口竞争，风险等级低。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L971) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1023)
