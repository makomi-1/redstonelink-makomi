# GUI标题描边字统一

## 1. 功能与语义、架构设计
- 本次改动新增统一的标题描边渲染支持类，将“主标题 / 副标题”的八向描边逻辑集中封装，避免各个界面重复拼接文本渲染细节，入口在 [GuiTitleRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/GuiTitleRenderSupport.java#L15)。
- `AbstractMultiPairingScreen` 将主标题和序号副标题统一切到该 helper，因此 `core` 与 `triggerSource` 两类配对 GUI 会同步生效，调用入口在 [AbstractMultiPairingScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/AbstractMultiPairingScreen.java#L174)。
- 过滤器、快速连接工具、状态面板分别将各自顶部标题簇接入统一 helper，避免“某些 GUI 有描边、某些没有”的分裂表现，接入点在 [LinkFilterEditorScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/LinkFilterEditorScreen.java#L200)、[QuickLinkToolScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/QuickLinkToolScreen.java#L104)、[StatePanelToolScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/StatePanelToolScreen.java#L147)。

## 2. 关键数据结构和算法性能分析
- 关键数据结构是 `GuiTitleRenderSupport.TitleStyle`，只保存文字色与描边色两个值，逻辑简单且便于扩展到更多标题风格，定义见 [GuiTitleRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/GuiTitleRenderSupport.java#L85)。
- 描边算法采用 8 个方向偏移加 1 次正文绘制，总计 9 次批量文本提交；由于作用对象仅为每帧极少量标题文本，性能成本可控，核心绘制循环在 [GuiTitleRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/GuiTitleRenderSupport.java#L39)。
- 副标题描边色通过原文字颜色按比例压暗推导，保持不同 GUI 主题色的色相一致性，避免为每个副标题手写一套描边色常量，计算逻辑见 [GuiTitleRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/GuiTitleRenderSupport.java#L74)。

## 3. 数据流或调用链
- 配对 GUI 的调用链为：`render(...)` 进入标题绘制后调用 `GuiTitleRenderSupport.drawCenteredPrimaryTitle / drawCenteredSecondaryTitle(...)`，再由 helper 下沉到批量文本渲染，见 [AbstractMultiPairingScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/AbstractMultiPairingScreen.java#L183) 和 [GuiTitleRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/GuiTitleRenderSupport.java#L25)。
- 过滤器和快速连接工具的标题簇都复用同一个 helper，因此主标题和副标题的定位、居中宽度计算、描边批次提交完全共用一条调用链，见 [LinkFilterEditorScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/LinkFilterEditorScreen.java#L206) 和 [QuickLinkToolScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/QuickLinkToolScreen.java#L112)。
- 状态面板的单标题场景也接入同一渲染支持类，说明该 helper 同时覆盖“单标题”和“标题 + 副标题”两类调用模式，见 [StatePanelToolScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/StatePanelToolScreen.java#L154)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议
- 安全方面，本次只改客户端 GUI 文本渲染，不涉及网络包、持久化、权限判断或 `triggerSource/core` 方向语义，风险边界清晰，标题调用都位于各自 `render(...)` 中，见 [AbstractMultiPairingScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/AbstractMultiPairingScreen.java#L174)。
- 性能方面，描边会把单条标题扩展为 9 次批量绘制，但当前只作用在少量顶部标题，远低于列表、物品或大段文本渲染的压力级别，核心循环见 [GuiTitleRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/GuiTitleRenderSupport.java#L52)。
- 兼容性方面，当前只覆盖现有 4 个自定义 GUI；后续若新增新的 `Screen` 标题渲染，需显式接入 helper，否则不会自动获得描边效果，已接入界面范围可从 [LinkFilterEditorScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/LinkFilterEditorScreen.java#L200)、[QuickLinkToolScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/QuickLinkToolScreen.java#L104)、[StatePanelToolScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/StatePanelToolScreen.java#L147) 追踪。
- 编译输出仍提示 `GuiTitleRenderSupport` 命中过时 API 链路，构建已通过且行为正确；若后续要彻底消除此提示，建议单独用 `-Xlint:deprecation` 精确定位 Mojang 客户端文本批量接口的告警来源，排查入口在 [GuiTitleRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/GuiTitleRenderSupport.java#L39)。

## 5. 并发冲突审查
- 本次改动没有引入新的共享可变状态，`GuiTitleRenderSupport` 只包含常量和纯计算逻辑，不持有跨帧缓存，也不回写界面状态，见 [GuiTitleRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/GuiTitleRenderSupport.java#L15)。
- 各 Screen 仅在客户端主线程的 `render(...)` 阶段同步调用 helper，不涉及异步任务、回调重入或跨线程资源访问，调用点见 [AbstractMultiPairingScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/AbstractMultiPairingScreen.java#L174)、[LinkFilterEditorScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/LinkFilterEditorScreen.java#L200)。
- 风险等级：低。当前唯一需要注意的是未来若为标题渲染引入缓存或动画状态，需要明确缓存失效时机与线程边界；本次改动尚未引入该类风险。
