## 1. 功能与语义、架构设计

- 智能节点容器的放置入口仍集中在 [SmartNodeContainerItem.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/item/SmartNodeContainerItem.java#L59) 的 `useOn(...)`。本轮在放置成功后的槽位回写阶段新增了“创造模式手动消费”分支，确保 `creativeAutoConsumeEnabled` 开启时，创造模式也会真实消耗容器中的节点 [SmartNodeContainerItem.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/item/SmartNodeContainerItem.java#L108-L112)。
- 真实消费状态的判定被收口到 [SmartNodeContainerItem.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/item/SmartNodeContainerItem.java#L301-L305) 的 `resolveConsumedSlotReplacement(...)`，避免把创造模式特判散落在放置流程里。
- 定向编辑器的编辑入口仍集中在 [DirectionalFaceEditorItem.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/item/DirectionalFaceEditorItem.java#L37-L71) 的 `useOn(...)`。本轮在入口直接增加主手限制，使“副手仅显示箭头、主手才可编辑”成为单点规则 [DirectionalFaceEditorItem.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/item/DirectionalFaceEditorItem.java#L39-L40)。
- 定向编辑器贴图接入只改了 item model，不触碰贴图资源本体；当前 `layer0` 已切到 `face_editor` [directional_face_editor.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/assets/redstonelink/models/item/directional_face_editor.json#L4)。

## 2. 关键数据结构和算法性能分析

- 容器消费修复没有引入新的持久化字段或额外遍历，只是在已有单槽位回写路径上多做一次 `instabuild` 布尔判定 [SmartNodeContainerItem.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/item/SmartNodeContainerItem.java#L94-L112)。时间复杂度仍为 `O(1)`。
- `resolveConsumedSlotReplacement(...)` 只对单个 `ItemStack` 做分支归一化，不产生额外集合拷贝；它把“创造模式 `BlockItem.place(...)` 不扣临时栈”这一差异转换成固定的空槽位结果 [SmartNodeContainerItem.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/item/SmartNodeContainerItem.java#L293-L305)。
- 定向编辑器主手限制也是 `O(1)` 的前置拦截，减少了副手误触发后继续读取方块状态、编辑面集和刷新运行态的无效路径 [DirectionalFaceEditorItem.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/item/DirectionalFaceEditorItem.java#L37-L50)。
- 新增测试只覆盖两个关键消费分支，没有引入复杂测试夹具，执行成本低 [SmartNodeContainerItemTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/item/SmartNodeContainerItemTest.java#L14-L31)。

## 3. 数据流或调用链

- 智能节点容器放置链路：
  `SmartNodeContainerItem.useOn(...)` 读取容器快照与目标槽位 -> 复制出 `nestedStack` 参与 `BlockItem.place(...)` -> 放置成功后根据 `shouldConsumeOnPlacement(...)` 决定是否消费 -> 通过 `resolveConsumedSlotReplacement(...)` 统一回写槽位 -> `SmartNodeContainerData.write(...)` 持久化回容器 [SmartNodeContainerItem.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/item/SmartNodeContainerItem.java#L72-L124)。
- 定向编辑器编辑链路：
  `DirectionalFaceEditorItem.useOn(...)` 先校验必须主手 -> 校验目标节点是否支持面编辑 -> 读取当前模式并计算更新后的 `BlockState` -> 必要时落地新状态并刷新运行态 [DirectionalFaceEditorItem.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/item/DirectionalFaceEditorItem.java#L37-L71)。
- 贴图显示链路：
  物品栈渲染读取 `directional_face_editor.json`，其 `layer0` 现在直接指向 `redstonelink:item/face_editor`，因此 GUI、手持与物品栏都会使用新的工具贴图 [directional_face_editor.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/assets/redstonelink/models/item/directional_face_editor.json#L1-L5)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全性：本轮没有引入新的网络包、命令入口或外部输入解析；风险低。定向编辑器改为副手 `PASS` 还能把交互交还给原方块逻辑，避免副手隐藏改写节点状态 [DirectionalFaceEditorItem.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/item/DirectionalFaceEditorItem.java#L39-L40)。
- 性能：容器修复和主手限制都属于常数级判断，对放置和编辑热路径基本无可见开销 [SmartNodeContainerItem.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/item/SmartNodeContainerItem.java#L108-L112)。
- 兼容性：创造模式消费逻辑没有改动 `SmartNodeContainerData` 的结构和键名，因此旧容器物品无需迁移；可见/隐藏节点的 `triggerSource/core` 真值链也没有改动。风险低。
- 扩展性：`resolveConsumedSlotReplacement(...)` 已经把“放置成功后的槽位状态”抽成独立 helper，后续如果某些节点物品从单件槽位扩展成多件计数，可在这里继续细化而不必重写整个 `useOn(...)` 放置链 [SmartNodeContainerItem.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/item/SmartNodeContainerItem.java#L293-L305)。
- 建议：若后续还要覆盖更多创造模式容器场景，最好继续补一条更贴近真实放置链的集成测试，而不仅是当前的 helper 单测 [SmartNodeContainerItemTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/item/SmartNodeContainerItemTest.java#L14-L31)。

## 5. 并发冲突审查

- 共享状态：本轮唯一被写入的共享状态仍是容器物品内部内容列表与节点方块状态，写入口没有新增并发共享容器或静态缓存。
- 读改写覆盖：容器消费逻辑仍在服务端单次 `useOn(...)` 流程内完成“读取 contents -> 修改单槽位 -> `SmartNodeContainerData.write(...)` 回写”，没有引入跨 tick 的异步更新 [SmartNodeContainerItem.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/item/SmartNodeContainerItem.java#L83-L124)。
- 重入/线程边界：定向编辑器和容器逻辑都仍运行在主线程交互上下文，没有新开线程，也没有把客户端显示逻辑混入服务端状态写入。副手直接 `PASS` 也降低了双手同时触发同一编辑逻辑的重入概率 [DirectionalFaceEditorItem.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/item/DirectionalFaceEditorItem.java#L37-L71)。
- 风险等级：低。
- 建议：若后续要把节点容器的创造模式消费扩展到批量放置或网络同步预演，需重新审查“客户端预测放置 vs 服务端最终扣减”的覆盖关系，避免出现显示与库存回写时序不一致。
