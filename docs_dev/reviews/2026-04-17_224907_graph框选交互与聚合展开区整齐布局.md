# graph框选交互与聚合展开区整齐布局

## 1. 功能与语义、架构设计（关键方法和入口）

本轮前端改动把批量编辑选择的主入口从“节点点击 toggle”切到 ReactFlow 自带框选机制，仅允许真实 `triggerSource/core` 节点进入批量选择集合，聚合节点继续只承担展开/收起与聚焦职责，不参与批量选择。对应入口在 ReactFlow 事件绑定与选择同步函数中完成，保证视图交互增强但不改 `triggerSource -> core` 的真实保存语义。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2045) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2150) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2490)

展开聚合块后的 core 区布局则改为“仅在展开聚合所在组件内关闭 jitter”，这样普通拓扑区域仍保留轻度去规则化，聚合展开区恢复整齐排列，满足“展开区整齐、整图不过分僵硬”的折中目标。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L833) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L893)

## 2. 关键数据结构和算法性能分析

批量选择状态仍然落在 `selectedEditSourceSerials` / `selectedEditTargetSerials` 两组序号数组上，本轮新增 `selectedEditNodeKeys` 作为只读派生集合，用来把 ReactFlow 的受控选中态映射回画布节点，避免每次渲染反复做数组查找，时间复杂度从“按节点多次 `includes`”收敛为基于 `Set` 的 O(1) 判断。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1611) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1619) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1022)

`applyBatchSelectionFromNodeKeys` 会先按节点类型分流，再排序去重后回写数组，并通过 `sameNumberArray` 避免无效状态更新；`buildLaneLayout` 则只增加一个布尔分支来决定是否注入 jitter，没有引入新的高复杂度布局过程，因此这轮改动仍维持在选择集大小和组件节点数的线性级别。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L833) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2045)

## 3. 数据流或调用链

框选链路现在是：ReactFlow `onSelectionChange` 接收当前选中节点列表，调用 `applyBatchSelectionFromNodeKeys`，再回写 `selectedEditSourceSerials` / `selectedEditTargetSerials`，随后经 `selectedEditNodeKeys` 派生为受控 `selected` 状态，最终由 `buildGraphFlowNodes` 统一刷新节点的可选中态与视觉选中态。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1022) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1619) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2045) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2490)

聚合块链路保持原语义：点击聚合节点进入 `handleCanvasNodeClick`，只触发展开/收起和结构布局刷新；刷新后 `buildComponentLayout` 检测到组件内存在已展开聚合节点时，core 侧关闭 jitter，从而把聚合块内部成员整齐排开。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L893) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2150)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

安全层面，本轮仅调整本地前端状态与 ReactFlow 交互参数，没有新增服务端调用、没有改 snapshot/draft 真值写入路径，因此不会改变 `triggerSource -> core` 的真实持久化边界。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2045) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2150)

性能层面，框选事件会在选择变化时重建一次受控节点状态；对当前图规模这属于可接受成本，但若后续节点量继续上升，可以考虑把“批量选择高亮”和“详情选中高亮”拆分得更细，减少整表节点样式重建次数。兼容性层面，本轮使用 `SelectionMode.Partial` 和 `multiSelectionKeyCode`，满足当前左键框选与 `Ctrl/Shift` 追加多选要求；如果后续用户更强调严格包围式框选，可再切到 `SelectionMode.Full` 做行为收紧。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2490) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2505) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2508)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

本轮状态全部运行在 React 单线程事件循环内，没有引入跨线程共享状态。`applyBatchSelectionFromNodeKeys` 使用函数式 `setState` 并借助 `sameNumberArray` 抑制重复写入，降低了连续框选和点击时的无意义重渲染；聚合展开则仍通过独立的 `expandedAggregateNodeKeys` 与结构刷新状态驱动，和批量选择集合相互隔离，风险等级评估为“低”。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2033) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2045) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2146)

需要注意的唯一交互边界是：框选状态与聚合展开状态都可能触发同一轮画布重绘。如果后续继续叠加自动聚焦、局部缩放或更多批量操作入口，建议把“选择同步”和“结构刷新”进一步拆成更明确的状态机，避免未来出现先后顺序上的视觉抖动。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2033) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2490)
