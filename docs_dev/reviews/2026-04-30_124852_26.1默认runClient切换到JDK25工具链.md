# 26.1默认runClient切换到JDK25工具链

## 1. 功能与语义、架构设计（关键方法和入口）

本阶段目标是让用户直接执行 `.\gradlew.bat --no-daemon runClient` 时就能成功启动，不再依赖额外传入 `-Dorg.gradle.java.home=...`。

- 项目级 Java toolchain 现在在 [build.gradle](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/build.gradle#L14) 到 [build.gradle](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/build.gradle#L21) 统一钉到 Java 25，直接复用 Gradle 已探测到的本机 JDK 25。
- 编译阶段仍保持 [build.gradle](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/build.gradle#L221) 的 `release = 25`，但不再要求当前 Gradle JVM 本身就是 25。
- 运行阶段和测试阶段统一改为显式使用 `java25Launcher`，见 [build.gradle](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/build.gradle#L224) 到 [build.gradle](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/build.gradle#L230)，这样 `runClient`、`runClientModStack` 以及测试任务都会跟随同一套 Java 25 运行时。
- 底部原有 `java` 配置仍保留 `withSourcesJar` 和 `source/targetCompatibility`，继续与 toolchain 形成同一版本基线，见 [build.gradle](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/build.gradle#L387)。

## 2. 关键数据结构和算法性能分析

本阶段不改业务数据结构，也不改算法路径，核心只是 Gradle/JVM 选择逻辑。

- `java25Launcher` 是一个由 `javaToolchains.launcherFor(...)` 返回的 provider，不引入额外缓存结构，也不会改变业务代码执行复杂度，见 [build.gradle](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/build.gradle#L20)。
- toolchain 方案把“当前 shell 的 `JAVA_HOME`”和“项目要求的 Java 版本”解耦，避免编译期因为调用方 JVM 偏低而直接失败，这属于构建稳定性修复，不是性能路径变更。

## 3. 数据流或调用链

本阶段修的是构建与运行链路，而不是模组业务调用链。

- 命令入口仍是 `gradlew.bat -> Gradle -> runClient`，但 Gradle 在进入编译和运行任务后，会通过 toolchain/provider 切换到 Java 25，见 [build.gradle](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/build.gradle#L14)、[build.gradle](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/build.gradle#L20)、[build.gradle](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/build.gradle#L224)。
- 资源准备链路没有变化，`runClient` 仍依赖 `prepareClientResourcesDir`，见 [build.gradle](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/build.gradle#L205) 与 [build.gradle](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/build.gradle#L217)。
- 实际验证结果表明，原命令下 Fabric Loader 已经在启动日志中识别到 `java 25`，说明运行期 JVM 也已经被正确切换。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 兼容性收益最大：用户不需要再记住附加 JVM 参数，项目自己承担 Java 25 选择责任，降低了迁移分支的使用门槛。
- 相比把 `org.gradle.java.home` 绝对路径写进公共 `gradle.properties`，toolchain 方案更可移植；只要目标机器上存在可探测的 JDK 25，就能自动工作，见 [build.gradle](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/build.gradle#L14) 到 [build.gradle](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/build.gradle#L21)。
- 残余风险较低：如果后续机器上没有可探测到的 JDK 25，Gradle 会回到“找不到合适工具链”的显式错误，但这比当前默默用 JDK 21 编译到一半才报 `release 25` 不支持更可诊断。
