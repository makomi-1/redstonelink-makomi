# Sodium兼容穿透显示分支

## 1. 功能与语义、架构设计（关键方法和入口）

- 本轮没有改动任何实际渲染算法，而是把客户端“是否启用兼容渲染分支”的判定范围从“仅 Iris”扩展为“Iris 或 Sodium”。唯一代码入口仍然集中在 `IrisRenderCompatSupport.shouldUseCompatibilityBranch()`，这样 quick-link 线框、连线、描边，以及定向箭头这些已有兼容路径都可以统一吃到新判定结果。[IrisRenderCompatSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/IrisRenderCompatSupport.java#L5)
- 类名保持 `IrisRenderCompatSupport` 不变，避免无意义的大范围 rename；但类注释与方法注释已同步修正为 “Iris / Sodium 渲染兼容判定支撑”，使职责与实现保持一致。[IrisRenderCompatSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/IrisRenderCompatSupport.java#L5)

## 2. 关键数据结构和算法性能分析

- 本轮只是把一个布尔条件从单次 `isModLoaded("iris")` 扩展为两次常量时间查询：`isModLoaded("iris") || isModLoaded("sodium")`。这属于客户端启动后极低频的常量成本，不会形成渲染或逻辑热点。[IrisRenderCompatSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/IrisRenderCompatSupport.java#L19)
- 没有新增集合、缓存或额外状态，也没有改动任何线段构造、世界扫描和 block entity 渲染流程，因此算法复杂度和内存占用保持不变。[IrisRenderCompatSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/IrisRenderCompatSupport.java#L19)

## 3. 数据流或调用链

- 客户端在渲染期调用 `shouldUseCompatibilityBranch()`，获得“是否进入兼容分支”的单一布尔结果。[IrisRenderCompatSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/IrisRenderCompatSupport.java#L19)
- 这个结果随后继续被既有的 quick-link 和定向箭头入口复用，因此本轮虽然只改了一个文件，但会影响：
  - quick-link 当前命中描边
  - quick-link preview 线框
  - quick-link 第三形态连线
  - 定向面箭头  
  这些入口的控制点本身没有变化，仍统一读取同一判定方法。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全性：本轮只改客户端只读环境判定，不涉及网络、权限、存档或服务端逻辑，安全风险为无。[IrisRenderCompatSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/IrisRenderCompatSupport.java#L19)
- 性能：兼容分支会在 `Sodium-only` 环境下也被启用，因此该环境会和 `Iris` 一样采用当前的兼容穿透渲染观感；这不会增加新的算法层，但会让更多客户端命中这条已有分支。[IrisRenderCompatSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/IrisRenderCompatSupport.java#L19)
- 兼容性：未装 `Iris/Sodium` 时仍走原 vanilla 路径，不受影响；已装 `Iris` 的行为也保持不变。本轮本质上只是在 “Sodium-only” 场景下复用已验证过的兼容方案。[IrisRenderCompatSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/IrisRenderCompatSupport.java#L19)
- 扩展性：若后续还发现其它客户端渲染优化模组也需要命中同一分支，可以继续在这里集中追加判断，而不需要到每个 renderer 分别打补丁。[IrisRenderCompatSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/IrisRenderCompatSupport.java#L19)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- 本轮没有新增共享可变状态，也没有修改任何静态缓存或配置快照。`FabricLoader.getInstance().isModLoaded(...)` 只是读取已加载模组集合，属于只读查询，不会引入新的共享状态竞争；风险等级为低。[IrisRenderCompatSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/IrisRenderCompatSupport.java#L19)
- 没有读改写覆盖问题，也没有跨线程重入边界变化；本轮仅改变判定条件，不改变调用时机和渲染线程边界；风险等级为低。[IrisRenderCompatSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/IrisRenderCompatSupport.java#L19)
