# graph自动聚焦上下文优先级修复

## 1. 功能与语义、架构设计

- 本轮修复只动前端视口控制，不改 graph 真值、聚合逻辑和布局算法。核心目标是让“节点/聚合块的上下文聚焦”优先于“整图自动 `fitView`”，对应新增的抑制引用状态在 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L196)。
- 上下文聚焦入口仍然保持原语义：普通节点通过 `focusNode(...)` 触发，聚合块展开通过 `requestStructureLayoutRefresh(...)` 触发，只是在进入这些路径时先声明“跳过本轮整图归位”，见 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L932) 与 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L938)。
- 释放策略也保持最小闭环：上下文聚焦完成后不立即清掉抑制，而是在下一帧释放，保证同一轮由节点变化带来的整图 `fitView` 不会反向覆盖上下文聚焦，见 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1214)。

## 2. 关键数据结构和算法性能分析

- 新增的数据结构只有两个 `useRef`：一个布尔抑制位，一个释放抑制的动画帧句柄，都是 `O(1)` 状态，不引入新的集合扫描或布局计算，见 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L196)。
- 两条整图 `fitView` effect 只是多了一次常量时间判断，分别位于首帧/节点数量变化归位和结构刷新归位处，见 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L757) 与 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L780)。
- 聚合块上下文聚焦仍然走原来的局部 `fitView`，只是完成后补了一次释放抑制操作，因此性能特征与原实现基本一致，见 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L820)。

## 3. 数据流或调用链

- 普通节点聚焦调用链变为：用户动作 -> `focusNode(...)` 开启整图归位抑制 -> `pendingFocusNodeKey` effect 调 `setCenter(...)` -> 下一帧释放抑制，对应代码在 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L932)、[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L863) 与 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1214)。
- 聚合块展开调用链变为：点击聚合块 -> `requestStructureLayoutRefresh({ focusAggregateNodeKey, fitViewport: false })` 开启抑制 -> `pendingAggregateFocusNodeKey` effect 局部 `fitView(...)` -> 下一帧释放抑制，对应实现位于 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L943)、[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L801) 与 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L841)。
- 整图自动归位链路则被降级为“只有当前不存在上下文聚焦抑制时才执行”，否则本轮直接跳过；结构刷新归位还会同步消费 `pendingStructureViewportFit`，避免抑制释放后补跑一次整图归位，见 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L784)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全风险低：本轮没有新增网络请求、保存协议或服务端状态写入，只是前端视口控制收口。
- 性能风险低：新增逻辑主要是常量时间布尔判断和一次动画帧调度，不会放大现有布局和渲染复杂度。
- 兼容性风险主要在交互层：如果未来新增更多自动视口动作，也应统一接入这套“上下文优先、整图降级”的控制，而不是再直接调用裸 `fitView(...)`。当前入口已经集中在 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1203)。
- 建议后续如果继续扩展，可把这套抑制/释放机制进一步抽成单独 hook，减少 `GraphViewer.tsx` 里视口相关副作用继续膨胀的风险。

## 5. 并发冲突审查

- 共享状态主要是 React 组件内的 `pendingFocusNodeKey`、`pendingAggregateFocusNodeKey` 和新增的抑制引用状态；这些状态都仍运行在单线程 UI 事件循环中，没有跨线程共享风险。
- 读改写覆盖风险已明显降低：此前问题就是整图 `fitView` 在后续帧覆盖上下文聚焦，现在通过抑制位明确阻断了同一轮覆盖，关键点在 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L757) 与 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L780)。
- 重入风险可控：释放抑制时会先取消旧帧句柄，避免多次连续聚焦造成旧释放任务把新一轮聚焦抑制提前清掉，见 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1205) 与 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1215)。
- 风险等级：低。当前剩余风险主要是人工交互回归覆盖面，而不是并发一致性或共享状态损坏。
