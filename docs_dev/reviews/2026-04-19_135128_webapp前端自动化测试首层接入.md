## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 当前组件测试的接口模拟采用手写 fetch mock，优点是轻量，但当 `/api/**` 端点继续增多时，测试维护成本会抬升；后续若页面继续扩展，建议把响应路由逐步沉到统一 helper，必要时再引入 MSW。当前入口见 [http.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/test/http.ts#L1) 和 [GraphViewer.test.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.test.tsx#L63)。
- `jsdom` 只能覆盖 DOM/状态流，无法真实复刻 ReactFlow 的几何布局与浏览器绘制细节，因此这轮测试更适合作为逻辑回归门禁，不替代实际网页手测；配置与 mock 边界见 [vite.config.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/vite.config.ts#L15) 和 [setup.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/test/setup.ts#L13)。
- 测试类型声明已并入 `tsconfig`，能防止 `jest-dom` matcher 与 Vitest 全局类型漂移，但若后续拆分为独立 `tsconfig.vitest.json`，要同步维护 `vite/client` 类型，否则会影响现有前端构建；见 [tsconfig.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/tsconfig.json#L2)。

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- 这轮改动只新增测试、测试配置和 lockfile，不触碰运行时业务共享状态，也没有把测试辅助逻辑注入生产代码路径，运行时并发风险低；脚本与配置入口见 [package.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/package.json#L6) 与 [vite.config.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/vite.config.ts#L15)。
- 测试中的全局对象修改集中在 setup，且通过 `cleanup + restoreAllMocks + afterAll unstubAllGlobals` 收束，避免不同测试文件之间互相污染；见 [setup.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/test/setup.ts#L48)。
- 组件测试内部的 fetch mock 都在各自测试中局部声明，未引入跨文件共享可变缓存；目前唯一要注意的是后续若加入 fake timers 或共享 mock server，需要继续保持“每测例自清理”原则。当前局部 mock 入口见 [App.test.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/App.test.tsx#L43) 和 [GraphViewer.test.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.test.tsx#L63)。
