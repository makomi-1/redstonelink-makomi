## 3. 数据流或调用链

- 游戏内合成链路是：配方 JSON 被资源加载器读取后进入正常配方表，玩家可直接通过工作台/无序合成获得新增物品或方块。[hide_core.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/data/redstonelink/recipe/hide_core.json#L1) [hide_sync_trigger_source.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/data/redstonelink/recipe/hide_sync_trigger_source.json#L1) [directional_face_editor.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/data/redstonelink/recipe/directional_face_editor.json#L1)
- 静态配方页的数据流是：HTML 内置配方卡片/输出 ID -> `classifyRecipeByOutput` 分类 -> 纹理/名称映射表解析资源路径 -> 页面展示。新加的隐藏节点和工具沿用这条既有链路，没有单独特判分支。[recipe_sheet.html](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs/recipe_sheet.html#L69) [recipe_sheet.html](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs/recipe_sheet.html#L598) [recipe_sheet.html](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs/recipe_sheet.html#L1774)
- 图鉴页的数据流是：`items` 数据条目定义 -> 纹理覆盖映射 -> 页面渲染器按 `path/category/render` 展示说明卡；这次只是补齐了隐藏节点和工具条目，不改原有渲染入口。[item_guide.html](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs/item_guide.html#L758) [item_guide.html](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs/item_guide.html#L830) [item_guide.html](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs/item_guide.html#L1001)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全性风险低：本轮只涉及静态文档、资源和配方声明，不触碰运行时网络、权限或持久化逻辑；运行时影响主要局限在资源加载层。[hide_sync_trigger_source.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/data/redstonelink/recipe/hide_sync_trigger_source.json#L1) [recipe_sheet.html](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs/recipe_sheet.html#L598)
- 兼容性风险主要在“文档/图鉴与真实实现脱节”。这次通过同时更新使用说明、图鉴、配方页和资源布局测试，把这一风险压回到较低水平。[usage_guide_cn.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs/usage_guide_cn.md#L41) [item_guide.html](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs/item_guide.html#L1039) [RecipeResourceLayoutTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/RecipeResourceLayoutTest.java#L62)
- 扩展性上，后续如果继续添加可制作节点，除了配方 JSON 本身，还需要同步两类静态索引：`recipe_sheet` 的映射表/分类表，以及 `RecipeResourceLayoutTest` 的白名单集合；否则会再次被测试门禁拦住。[recipe_sheet.html](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs/recipe_sheet.html#L780) [recipe_sheet.html](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs/recipe_sheet.html#L1774) [RecipeResourceLayoutTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/RecipeResourceLayoutTest.java#L23)
- docs 侧 `chest` 本地贴图已补到 `docs/recipe/minecraft/block/chest.png`，静态页面不再依赖外部资源兜底。残余风险：该贴图来自本地 Minecraft 客户端资源，后续若页面改成更严格的 item/block 区分，可能需要再换成专门的 GUI 展示贴图。

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- 本轮改动以静态资源和文档为主，不新增共享可变运行时状态，也不引入新的线程边界；运行时配方 JSON 只在资源加载期读取，页面 HTML/映射表只在文档浏览期由前端单线程消费，并发风险低。[hide_core.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/data/redstonelink/recipe/hide_core.json#L1) [recipe_sheet.html](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs/recipe_sheet.html#L594)
- 需要注意的“读改写覆盖”风险主要在静态索引同步：新增配方时若只写 JSON、不更新白名单测试或文档映射，会在构建期或展示期出现不一致。本轮通过同步更新 `RecipeResourceLayoutTest` 和文档映射消除了这类冲突。[RecipeResourceLayoutTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/RecipeResourceLayoutTest.java#L27) [item_guide.html](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs/item_guide.html#L545) [recipe_sheet.html](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs/recipe_sheet.html#L598)
- 风险等级：低。建议继续保持“新增正式配方时同步更新资源测试白名单和静态页映射”的协作习惯，避免后续重复踩坑。
