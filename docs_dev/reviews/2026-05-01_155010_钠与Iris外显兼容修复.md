# 钠与Iris外显兼容修复

## 1. 功能与语义、架构设计
- 这轮修复没有改动 quick-link、连线或定向箭头的业务判定，而是修正了它们在 `Sodium/Iris` 兼容分支下共用的穿透四边形管线状态：兼容分支把线段展开成单面四边形后，必须显式关闭剔除，否则容易在兼容渲染器下整批不可见。[SeeThroughWorldGeometryRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/SeeThroughWorldGeometryRenderSupport.java#L47)
- 当前架构仍保持“vanilla 分支走正常 world overlay 管线，`Sodium/Iris` 兼容分支走特殊几何出口”的设计，不改 `triggerSource/core` 语义，不改显示对象筛选逻辑。[SeeThroughWorldGeometryRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/SeeThroughWorldGeometryRenderSupport.java#L51)

## 2. 关键数据结构和算法性能分析
- 本轮没有新增算法结构，只调整了兼容渲染管线的 GPU 状态位。`withCull(false)` 的代价是带状四边形不再被背面剔除，但这些外显本来就是低面数 overlay，性能影响可忽略。[SeeThroughWorldGeometryRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/SeeThroughWorldGeometryRenderSupport.java#L47)
- 兼容分支保持原有的 ring buffer、一次构建一次 draw call 结构，没有引入额外 CPU 侧集合转换或更高频的缓冲重分配。[SeeThroughWorldGeometryRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/SeeThroughWorldGeometryRenderSupport.java#L56) [SeeThroughWorldGeometryRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/SeeThroughWorldGeometryRenderSupport.java#L232)

## 3. 数据流或调用链
- quick-link 描边、连接可视化和定向箭头在兼容分支下最终都会落到“线段展开为四边形，再交给穿透四边形管线”的链路上；本轮修复点就在这条公共出口，而不是各业务入口分散修补。[SeeThroughWorldGeometryRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/SeeThroughWorldGeometryRenderSupport.java#L106)
- 渲染调用链仍是：业务入口整理线段数据 -> `renderFilledQuads/renderLines` -> `finishAndDraw` -> `RenderPass` 提交；这次只是把管线状态从“可能剔除单面 quad”修成“显式保留双面可见”。[SeeThroughWorldGeometryRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/SeeThroughWorldGeometryRenderSupport.java#L92) [SeeThroughWorldGeometryRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/SeeThroughWorldGeometryRenderSupport.java#L131) [SeeThroughWorldGeometryRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/SeeThroughWorldGeometryRenderSupport.java#L296)

## 4. 安全、性能、兼容性、扩展性风险分析与建议
- 安全风险无，这次不涉及网络、存档或权限路径。
- 性能风险低，外显 quad 数量有限，关闭剔除对这类调试/辅助可视化的影响很小。[SeeThroughWorldGeometryRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/SeeThroughWorldGeometryRenderSupport.java#L47)
- 兼容性收益明确：这次修的是 `Sodium/Iris` 对单面兼容几何的可见性问题，vanilla 路径不受影响。
- 建议后续若继续细修 `Sodium/Iris` 外显观感，优先在公共兼容出口统一处理，不要把状态分散写回各个业务渲染入口。

## 5. 并发冲突审查
- 这轮没有引入新的共享可变状态，也没有修改事件注册顺序和客户端缓存结构；风险等级为低。
- 变更只落在静态管线定义，运行时不会增加新的跨线程读改写点，也不会改变 quick-link / 箭头缓存生命周期。[SeeThroughWorldGeometryRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/SeeThroughWorldGeometryRenderSupport.java#L39) [SeeThroughWorldGeometryRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/SeeThroughWorldGeometryRenderSupport.java#L47)
