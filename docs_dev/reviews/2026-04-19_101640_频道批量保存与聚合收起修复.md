# 频道批量保存与聚合收起修复

## 1. 功能与语义、架构设计

- 后端把频道保存从“逐节点独立 prepare/apply”改成“整批最终态一次 prepare/apply”，由 [GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L391) 收口频道操作，再委托 [LinkChannelEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkChannelEditingService.java#L69) 生成批量计划，提交阶段统一执行 [GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L105)。
- 频道最终目标集合仍严格落在 `triggerSource -> core` 真实边语义上，批量推导只是在 prepare 阶段把多节点覆盖合并为同一份最终视图，核心推导入口在 [LinkSavedDataChannelSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataChannelSupport.java#L151)。
- 前端把“草稿变更高亮”和“聚合自动展开”解耦：强制显示只保留选中、搜索命中和批量编辑选区 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L364)，草稿变更提升为 aggregate/channelHub 级别高亮 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L403) 与 [canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L238)。

## 2. 关键数据结构和算法性能分析

- 批量频道保存使用 `PreparedChannelBatchUpdate` 保存 `overrides + changedOverrides + preparedOperations + totalCommandCost`，避免对同一批次内重复受影响的 triggerSource 重复建计划，定义在 [LinkChannelEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkChannelEditingService.java#L420)。
- `validateChannelOperations` 先按节点去重，再一次性构造 `ChannelOverride` 列表并汇总受影响的 triggerSource/core，减少了旧实现按请求条目重复 prepare 的成本，见 [GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L391)。
- 前端画布侧不再把 `draftDiff.changedNodeKeys` 直接并入 `forcedVisibleNodeKeys`，从而避免每次草稿应用都把全部变更成员重新塞回画布；只对 aggregate/channelHub 做一次成员扫描并映射到画布节点高亮，复杂度是按可见聚合节点线性扫描，见 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L403)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全/语义：本轮仍只写 `triggerSource -> core` 真值边，没有引入新的持久化真值结构；频道只是 prepare 阶段的辅助视图，语义边界保持稳定，参考 [LinkSavedDataChannelSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataChannelSupport.java#L151)。
- 性能：批量去重后可显著降低“同一频道内多节点一起保存”时的重复 prepare 成本，但最终仍按真实受影响 triggerSource 的总写入成本计入限流 [GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L508)；超大批次仍可能命中 `LINK_RW` 限流，这是当前残余风险。
- 兼容性：前端只是修改聚合显示口径与高亮路径，没有变更 snapshot/draft/server 返回结构；现有搜索、选中、批量编辑仍复用原节点键体系，入口在 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L364) 与 [canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L611)。
- 扩展性建议：若后续需要真正支持“超大规模频道批量保存”，建议在服务端补充更低成本的频道专用批处理提交原语，而不是继续把所有改动折算成普通边逐条计费。

## 5. 并发冲突审查

- 共享状态：频道配置真值与普通边真值仍集中在 `LinkSavedData`，批量 apply 先写频道配置，再批量执行普通边替换 [LinkChannelEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkChannelEditingService.java#L176)，共享状态集中且边界明确。
- 读改写覆盖：批量 prepare 前仍对每个节点执行 OCC 校验，避免旧 revision 覆盖新状态，入口在 [GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L391)；风险等级为中低，前提是请求都通过该入口。
- 重入/线程边界：当前实现默认运行在服务端主线程语义下，没有额外锁；`GraphWriteService` 先 acquire rate limit，再 apply，避免部分提交后失败 [GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L499)。若未来引入异步保存，需要把 `LinkSavedData` 写入与批量边替换封装成单线程任务队列。
