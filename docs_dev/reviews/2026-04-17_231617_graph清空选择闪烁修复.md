# graph清空选择闪烁修复

## 1. 功能与语义、架构设计（关键方法和入口）

本轮修复只作用于 graph 前端视图层的批量选择同步链路，没有改 `triggerSource/core` 真值、snapshot、draft 或服务端保存语义。核心做法是在程序化清空选择时，临时挂起 ReactFlow 的选区回写，再统一清空批量选择数组和画布节点的 `selected` 状态，避免“清空后又被旧选区回写”的反馈环。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2056) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2183) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2543)

入口仍然保留在 `GraphViewer` 内部，`handleClearBatchSelection` 负责程序化清选，`handleCanvasNodesChange` 和 `onSelectionChange` 负责拦截清选期间的旧选中事件回流，符合“只修当前交互问题、不扩散业务语义”的最小改动原则。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2072) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2183) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2538)

## 2. 关键数据结构和算法性能分析

这次没有引入新的复杂数据结构，只新增了两个 `ref` 作为轻量级同步闸门：一个标记当前是否挂起画布选区同步，另一个保存恢复同步的帧句柄。这样可以在不触发额外渲染的前提下，稳定跨过 ReactFlow 内部选区事件的回流窗口，时间与空间开销都非常小。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1574) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2056)

`handleCanvasNodesChange` 在挂起窗口中仅过滤 `select` 类型变更，其余节点变更仍正常透传，因此不会意外影响节点拖拽、位置更新或布局修正。程序化清空节点选中态时则只对当前 `selected` 节点做浅拷贝更新，避免整表无差别重建。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2072) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2183)

## 3. 数据流或调用链

修复后的清空链路是：用户点击“清空选择”按钮，进入 `handleClearBatchSelection`；函数先调用 `temporarilySuspendCanvasSelectionSync` 挂起选区同步，再清空来源/目标数组并清空当前节点的 `selected` 状态；随后 ReactFlow 即使还发出一轮旧的 `onNodesChange` 或 `onSelectionChange`，也会在挂起窗口内被过滤或忽略，等两个动画帧后再恢复正常同步。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2056) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2072) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2183) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2538)

正常框选链路不变：非挂起状态下，ReactFlow 继续通过 `onSelectionChange` 把当前选中节点同步回批量编辑集合，因此这次修复只改变“程序清空”这一个特殊窗口，不影响日常框选和追加多选行为。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2087) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2543)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

安全与语义层面，本轮仅调整前端受控状态同步，没有新增 API 依赖，没有改动 `triggerSource -> core` 的真实持久化路径，兼容当前语义约束。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2087) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2183)

性能层面，双 `requestAnimationFrame` 的挂起窗口非常短，只在点击“清空选择”时触发，影响可忽略。兼容性风险主要在于 ReactFlow 内部事件时序如果后续升级发生变化，这个“挂起两个动画帧”的经验值可能需要重新校准；但当前实现已经把影响面限制在最窄的清空分支，后续调整成本低。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2056) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2543)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

前端仍运行在 React 单线程事件循环内，没有新增跨线程共享状态。本轮风险点在于“本地批量选择数组”和“ReactFlow 内部选区事件”对同一组选中态进行读改写覆盖；修复通过 `ref` 闸门把程序化清空窗口做成原子段，避免同一窗口内发生状态回写打架，风险等级评估为“低”。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1574) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2056) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2072)
