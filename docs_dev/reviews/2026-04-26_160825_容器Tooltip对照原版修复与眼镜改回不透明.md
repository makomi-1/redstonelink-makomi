# 容器Tooltip对照原版修复与眼镜改回不透明

## 1. 功能与语义、架构设计

- 智能节点容器界面现在不再依赖父类内部维护的 `hoveredSlot` 来显示物品提示，而是在 screen 自己的 `render(...)` 末尾统一绘制 tooltip，这样右侧扩展面板不会再把 tooltip 命中链路绑死在父类状态上。[SmartNodeContainerScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/SmartNodeContainerScreen.java#L105) [SmartNodeContainerScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/SmartNodeContainerScreen.java#L162)
- 槽位命中逻辑对照原版 `AbstractContainerScreen` 的矩形判定方式，直接使用菜单里已有的槽位坐标与 `16x16` 命中框重新解析悬停对象，覆盖容器区、背包区和热键栏。[SmartNodeContainerScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/SmartNodeContainerScreen.java#L174) [SmartNodeContainerMenu.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/menu/SmartNodeContainerMenu.java#L166) [SmartNodeContainerMenu.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/menu/SmartNodeContainerMenu.java#L182)
- 智能眼镜穿戴渲染已按用户要求废弃半透明方案，回退为标准不透明护甲部件渲染，只保留“自定义穿戴贴图链路”这一个职责。[SmartGlassesArmorRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/SmartGlassesArmorRenderer.java#L14) [SmartGlassesArmorRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/SmartGlassesArmorRenderer.java#L37) [RedstoneLinkClient.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/RedstoneLinkClient.java#L148)

## 2. 关键数据结构和算法性能分析

- 容器 tooltip 的悬停解析是一次线性扫描 `menu.slots`，复杂度为 `O(n)`；当前 6 行箱子加玩家库存总槽位量较小，这个开销与原版容器界面同量级，足够轻量。[SmartNodeContainerScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/SmartNodeContainerScreen.java#L177)
- 重新命中使用的是已有槽位坐标与固定矩形判定，没有引入额外缓存、状态同步或 NBT 读写，因此不会放大菜单 tick 成本。[SmartNodeContainerScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/SmartNodeContainerScreen.java#L179)
- 智能眼镜渲染回退到 `ArmorRenderer.renderPart(...)` 后，性能路径与标准护甲部件一致，避免了自定义半透明缓冲在透明像素稀疏贴图上的额外可见度与维护成本。[SmartGlassesArmorRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/SmartGlassesArmorRenderer.java#L53)

## 3. 数据流或调用链

- 智能眼镜客户端初始化时仍由 `RedstoneLinkClient.registerArmorRenderers()` 注册专用护甲渲染器；进入渲染回调后，仅在头部槽位命中时绘制眼镜贴图部件。[RedstoneLinkClient.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/RedstoneLinkClient.java#L151) [SmartGlassesArmorRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/SmartGlassesArmorRenderer.java#L33) [SmartGlassesArmorRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/SmartGlassesArmorRenderer.java#L47)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 兼容性：tooltip 逻辑现在与父类 `hoveredSlot` 解耦，能规避 screen 扩展后父类内部状态不稳定的问题；但若未来引入自定义缩放槽位或非 `16x16` 槽位，需要同步调整命中尺寸。[SmartNodeContainerScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/SmartNodeContainerScreen.java#L175)
- 扩展性：眼镜渲染已回退到标准不透明路径，后续若再尝试透明/发光等特殊效果，建议不要在当前类上继续叠加条件分支，而是另起独立渲染策略，避免再次混入失败方案残留。[SmartGlassesArmorRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/SmartGlassesArmorRenderer.java#L17)
- 风险提示：智能眼镜当前注册属性仍只有 `stacksTo(1)`，没有普通头盔式耐久；这不是本轮改动引入的问题，但如果后续希望它像防具一样损耗，需要显式补 `durability(...)` 而不是依赖 `ArmorItem` 自动推导。[ModItems.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/registry/ModItems.java#L164)

- 共享状态：本轮没有新增跨线程共享状态；容器 tooltip 命中只读 `menu.slots`，眼镜渲染只读当前实体与物品渲染上下文。[SmartNodeContainerScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/SmartNodeContainerScreen.java#L177) [SmartGlassesArmorRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/SmartGlassesArmorRenderer.java#L38)
- 读改写覆盖：screen 渲染阶段不写回菜单或物品数据，护甲渲染阶段也不修改 `ItemStack`，不存在本轮新增的读改写覆盖风险。[SmartNodeContainerScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/SmartNodeContainerScreen.java#L162) [SmartGlassesArmorRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/SmartGlassesArmorRenderer.java#L53)
- 重入与线程边界：两处变更都位于客户端主线程渲染链路，未引入异步任务、网络回调重入或共享容器写入，风险等级为低。建议后续如加入动画或延迟加载资源时，再单独复核线程边界。[SmartNodeContainerScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/SmartNodeContainerScreen.java#L106) [RedstoneLinkClient.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/RedstoneLinkClient.java#L151)
