# 转发器quicklink图写入修正与缓存方框加粗

## 1. 功能与语义、架构设计（关键方法和入口）
- 本轮核心修复在 [QuickLinkApplyService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/QuickLinkApplyService.java#L324)：转发器 quick-link 不再只改本地 `RepeaterConfigSnapshot`，而是把缓存类型映射到真实图目标语义后，复用 `applyFromCache(...)` 写入真实 `triggerSource -> core` 图关系。
- 新增的映射入口 [QuickLinkApplyService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/QuickLinkApplyService.java#L660) 明确了：
  - `triggerSource` 缓存映射到 `core` 目标语义，对应转发器输入侧
  - `core` 缓存映射到 `triggerSource` 目标语义，对应转发器输出侧
- 缓存对象穿墙预览方框加粗在 [QuickLinkOutlineRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/QuickLinkOutlineRenderer.java#L48) 与 [QuickLinkOutlineRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/QuickLinkOutlineRenderer.java#L51) 实现，通过自定义 `LineStateShard` 仅影响 quick-link 预览外显，不波及其它渲染路径。
- 根因判定依据来自转发器编辑器读取链：编辑器打开时通过 [RepeaterNetwork.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/RepeaterNetwork.java#L93) 调用 [RepeaterGraphSnapshotSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/RepeaterGraphSnapshotSupport.java#L42) 按 `LinkSavedData` 图真值构建输入/输出表达式，因此仅修改本地方块实体缓存不会反映到编辑器中。
- 回归测试在 [QuickLinkApplyServiceTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/data/QuickLinkApplyServiceTest.java#L179) 和 [QuickLinkApplyServiceTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/data/QuickLinkApplyServiceTest.java#L187) 补充了转发器缓存类型映射断言。

## 2. 关键数据结构和算法性能分析
- `applyToRepeaterFromCache(...)` 现在改为复用现有 `applyFromCache(...)` 图写入逻辑，没有新增图遍历或持久化结构，只是把目标语义在进入写入前做了一次常量时间映射，见 [QuickLinkApplyService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/QuickLinkApplyService.java#L340)。
- 线框加粗没有增加外显扫描量，仅在既有预览 `RenderType` 上替换线宽状态，因此客户端复杂度与原实现一致，见 [QuickLinkOutlineRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/QuickLinkOutlineRenderer.java#L48)。
- 转发器编辑器读取的图真值构造仍由 `RepeaterGraphSnapshotSupport.resolve(...)` 完成，输入/输出表达式分别来自 `getLinkedTriggerSourcesByCore(serial)` 与 `getLinkedCoresByTriggerSource(serial)`，数据来源清晰且与真实图一致，见 [RepeaterGraphSnapshotSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/RepeaterGraphSnapshotSupport.java#L51)。

## 3. 数据流或调用链
- 现在的转发器 quick-link 调用链是：命中转发器 → 服务端 quick-link 路由 → `QuickLinkApplyService.applyToRepeaterFromCache(...)` → `resolveRepeaterTargetType(...)` → `applyFromCache(...)` → 实际图写入，见 [QuickLinkApplyService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/QuickLinkApplyService.java#L324)。
- 转发器编辑器打开链仍是：`RepeaterNetwork.openEditor(...)` → `buildOpenEditorPayload(...)` → `RepeaterGraphSnapshotSupport.resolve(...)`，因此只要真实图关系写对，编辑器摘要和配对界面都会自然一致，见 [RepeaterNetwork.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/RepeaterNetwork.java#L93) 与 [RepeaterGraphSnapshotSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/RepeaterGraphSnapshotSupport.java#L42)。
- 缓存对象外显链路仍是：`AFTER_TRANSLUCENT` → `onAfterTranslucent(...)` → `QUICK_LINK_PREVIEW_RENDER_TYPE`，只是线宽更粗，见 [QuickLinkOutlineRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/QuickLinkOutlineRenderer.java#L120)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议
- 语义风险已收敛：本轮没有改动 `triggerSource/core` 对外语义，只是让转发器 quick-link 的内部写入路径真正落到图真值；输入/输出仍按既有转发器设计表达，见 [RepeaterConfigSnapshot.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/RepeaterConfigSnapshot.java#L6)。
- 兼容性方面，本轮未引入 `com.makomi.api.v1.*`，也没有新增旧术语输出。残余风险：无。
- 性能方面，线宽加粗不会扩大扫描范围，但全量门禁仍失败于既有慢测性能基线 [LinkSavedDataPerformanceSlowTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/data/LinkSavedDataPerformanceSlowTest.java#L29)，这次实测结果为 [TEST-com.makomi.data.LinkSavedDataPerformanceSlowTest.xml](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/build/test-results/testSlow/TEST-com.makomi.data.LinkSavedDataPerformanceSlowTest.xml#L5) 中的 `save=53ms, load=47ms, query=3ms`，其中 `save cost 53ms` 超过阈值 `50ms`。该失败点与本轮改动面不直接重叠，但仍是当前工作区的残余风险。
- 扩展性建议：如果后续还要让 quick-link 直接支持更多“复合节点/双身份节点”，建议把“缓存类型 -> 真实目标语义”的映射抽成统一语义层，避免在 `network/data` 两层分别维护同一套映射。

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）
- 风险等级：低。本轮没有新增异步任务或后台线程；转发器 quick-link 仍在服务端主线程处理，图写入复用现有 `applyFromCache(...)` 路径，见 [QuickLinkApplyService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/QuickLinkApplyService.java#L344)。
- 共享状态方面，变更只作用于现有 `LinkSavedData` 图关系，未新引入额外缓存层；之前“本地快照与图真值不一致”的问题正是通过减少本地缓存写入职责来消除的。
- 客户端渲染侧仅新增了一个固定线宽状态对象 [QuickLinkOutlineRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/QuickLinkOutlineRenderer.java#L48)，不参与跨线程共享，不存在额外读改写竞争。
- 建议：后续若继续扩展转发器 quick-link 反馈文案，可继续保持“真实图写入成功后再包装 UI 提示”的顺序，避免再次出现“提示成功但图真值未变”的重入式错觉。
