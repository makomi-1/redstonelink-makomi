# hide配方与块状贴图修复

## 1. 功能与语义、架构设计
- 这轮修复分成两层：一层是把 `hide` 系列配方改回当前 `1.21.11` 资源格式，避免运行时按空列表解析失败；另一层是保留 `hide` 物品的块状渲染设计，同时把物品模型切换到 `block` 图集引用，避免块状物品在新版本下紫黑。[hide_send_filter.json](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/main/resources/data/redstonelink/recipe/hide_send_filter.json#L2) [hide_core.json](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/main/resources/assets/redstonelink/models/item/hide_core.json#L2) [hide_send_filter.json](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/main/resources/assets/redstonelink/models/item/hide_send_filter.json#L2)
- 设计上没有改变 `hide` 方块的世界表现，世界侧仍由空 blockstate + 客户端幽灵渲染承担；这次只修运行时资源入口和物品显示入口，不改变 `triggerSource/core` 语义与节点方向设计。[hide_core.json](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/main/resources/assets/redstonelink/models/item/hide_core.json#L2)

## 2. 关键数据结构和算法性能分析
- 这次没有新增运行时代码算法，关键变更都落在静态资源结构上。配方层改成字符串形式后，资源解析直接命中当前工程已使用的 shapeless recipe 结构，避免旧对象数组格式在新版本里走到空列表分支。[hide_send_filter.json](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/main/resources/data/redstonelink/recipe/hide_send_filter.json#L4)
- 物品渲染层继续使用 `minecraft:block/cube_all`，只把贴图来源切到 `redstonelink:block/*_hide`，这属于图集寻址修复，不引入额外顶点提交、状态切换或运行时对象分配成本。[hide_core.json](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/main/resources/assets/redstonelink/models/item/hide_core.json#L2) [hide_send_filter.json](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/main/resources/assets/redstonelink/models/item/hide_send_filter.json#L4)

## 3. 数据流或调用链
- 数据包加载链路现在是：资源管理器读取 `data/redstonelink/recipe/hide_*.json`，按当前 shapeless recipe 结构解析 `ingredients` 与 `result`，再注册到运行时配方表；这也是这次修掉 `List is too short: 0` 的直接入口。[hide_send_filter.json](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/main/resources/data/redstonelink/recipe/hide_send_filter.json#L2)
- 物品显示链路现在是：物品模型 `hide_*.json` 解析 `minecraft:block/cube_all`，从 `redstonelink:block/*_hide` 读取贴图，最终进入 `blocks` 图集完成块状渲染；这与 `1.21.11` 的图集行为保持一致。[hide_core.json](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/main/resources/assets/redstonelink/models/item/hide_core.json#L2) [hide_send_filter.json](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/main/resources/assets/redstonelink/models/item/hide_send_filter.json#L2)

## 4. 安全、性能、兼容性、扩展性风险分析与建议
- 安全风险无。这次不涉及网络包、命令、存档结构或权限路径。
- 性能风险极低，变更只影响资源加载期，不会增加持续帧开销。[hide_core.json](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/main/resources/assets/redstonelink/models/item/hide_core.json#L2)
- 兼容性风险主要在资源维护上：`hide` 贴图现在同时存在 `textures/item/` 与 `textures/block/` 两份，后续若调整美术资源，必须同步更新两处，否则块状物品和其它引用入口会出现偏差。当前模型已经明确绑定 `block` 侧贴图，所以后续维护应以 `block` 图集适配为准。[hide_send_filter.json](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/main/resources/assets/redstonelink/models/item/hide_send_filter.json#L4)
- 扩展性上，这个修法可直接复用于后续所有“保持块状渲染的物品模型”，避免再次误用 `item` 图集。

## 5. 并发冲突审查
- 这轮没有引入新的共享可变状态，也没有改动异步渲染、网络同步或存档读写逻辑；风险等级为低。
- 配方文件和物品模型都属于资源加载期静态输入，不存在运行时读改写覆盖问题，客户端只在重载资源时重新读取这些 JSON，不涉及多线程并发修改。[hide_send_filter.json](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/main/resources/data/redstonelink/recipe/hide_send_filter.json#L2) [hide_core.json](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/main/resources/assets/redstonelink/models/item/hide_core.json#L2)
