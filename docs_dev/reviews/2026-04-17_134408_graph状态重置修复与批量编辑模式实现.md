## 2. 关键数据结构和算法性能分析

- 批量编辑的核心状态是三个前端局部状态：`editMode`、`selectedEditSourceSerials`、`selectedEditTargetSerials`。它们不进入服务端，也不修改 graph snapshot 原始数据，只在页面内部决定“如何把点选行为折算成草稿操作”。这种设计将交互状态和持久化状态分层，能避免协议被 UI 细节污染。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L555) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L556) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L557)
- `applyBatchEditToDraft` 是本轮的关键算法。它会遍历选中的 `triggerSource`，按模式把当前有效目标集合变换为下一目标集合：`add` 做并集，`remove` 做差集，`replace` 直接覆写。然后调用既有 `upsertReplaceTargetsDraft` 生成最终草稿。复杂度约为 `O(S * T)`，其中 `S` 是选中来源数，`T` 是目标集合规模，当前阶段足够轻量。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L349) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L387)
- 图中选中高亮没有引入新的节点结构，而是通过 `selectedEditSourceNodeKeys` / `selectedEditTargetNodeKeys` 这两个 `Set` 参与节点样式计算。这使高亮渲染保持 `O(1)` 集合查询，不需要改动图节点数据本身。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L79) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L118) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L592) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L596)
- 样式层新增批量编辑面板、双列选择汇总区和目标 chip 按钮，但都复用现有 `graph-target-list` / `metric-chip` 一类轻量 DOM 结构，没有引入额外渲染库。性能影响主要体现在图节点高亮和右侧 chip 列表，成本较低。[app.css](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L747) [app.css](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L772) [app.css](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L952)

## 3. 数据流或调用链

- 页面加载时，`App` 先从本地资产条目构造稳定的 `graphBundle`，再把它传入 `GraphViewer`。`GraphViewer` 根据当前 graph 文件名生成 draft 文件名、加载本地 draft、决定是否恢复历史草稿，并在成功后建立 `baseGraphBundle + graphDraft` 的双层状态。[App.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/App.tsx#L202) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L563) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L646)
- 用户在查看模式下点击节点，只会更新 `selectedNodeKey` 供详情面板使用；在编辑模式下，点击事件还会根据节点类型把序号加入来源或目标选择集合。这两个集合只存在于前端，不直接改草稿。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L841) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L850) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L856)
- 点击“应用到草稿”后，`handleApplyBatchEdit` 会把当前模式和选集交给 `applyBatchEditToDraft`，统一折算为 `ReplaceTriggerSourceTargets` 操作写入 `graphDraft`。这一步只更新本地草稿，不立刻触发服务端写入。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L871) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L879)
- 最终仍由显式 `Save` 走既有链路：`submitGraphSave` 把草稿序列化成请求 JSON，经 bridge 和网络发送到服务端，服务端应用后返回 `updatedNodes`，前端再刷新 `baseGraphBundle` 并清空草稿。也就是说，本轮只是增强了“草稿是如何生成的”，没有改变保存主链路。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L521) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L893) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L918)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全方面，本轮没有新增服务端写协议，也没有绕过既有的权限、OCC 或限流机制；所有批量编辑最终仍落到现有 `ReplaceTriggerSourceTargets` 服务端校验链路中。风险等级低。[GraphWriteJsonSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteJsonSupport.java#L336)
- 性能方面，当前批量编辑是“点选后一次性应用到草稿”，而不是每次点击都立即重算整图真值并发请求，这对前端和服务端都更稳。随着 `n -> m` 规模变大，主要成本会体现在前端多次 `resolveEffectiveTargetSerials` 和节点重绘，但对当前 serial 模式第一版仍可接受。风险等级低到中。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L349)
- 兼容性方面，本轮没有引入 `com.makomi.api.v1.*`，也没有改变 graph draft 文件格式的核心兼容边界；旧 draft 中已有的 `RenameNodeAlias` / `ReplaceTriggerSourceTargets` 仍能被解析。新增的是页面内的模式状态，不进入持久化格式。风险等级低。[graphTypes.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/graphTypes.ts#L77) [graphTypes.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/graphTypes.ts#L171)
- 扩展性方面，本轮的模式化编辑已经为后续 `channel` 编辑或更复杂的批量编辑奠定了入口层结构，但当前批量选择仍然只服务于 `serial` 模式，不包含自由拉线或频道中转节点展开/折叠。后续若进入 `channel` 模式，建议继续复用“模式状态 + 点选集合 + 最终折算为结构化草稿”的框架，而不是重新引入另一套交互模型。风险等级中。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L964) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1078)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- 前端状态重置问题本质上是父组件重渲染引发的“伪并发覆盖”：`graphBundle` 重新解析后，子组件把它当成新文件，覆盖了当前编辑中的 draft 和选中节点。本轮通过稳定 `graphBundle` 引用和收紧 effect 依赖，消除了这类前端自覆盖。风险等级从中降为低。[App.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/App.tsx#L202) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L646)
- 本轮新增的批量选择集合只存在浏览器本地组件状态，彼此之间没有跨线程共享；按钮点击、图节点点击和草稿应用都在同一前端事件线程内完成，没有新引入的异步共享可变对象。风险等级低。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L828) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L841)
- 真值层并发风险没有上升。虽然前端现在可以一次对多个 `triggerSource` 生成 replace 操作，但它们依然通过既有保存主链路进入服务端，因此并发冲突仍由服务端 revision/OCC 负责，不会因为批量编辑模式而变成前端最后写入者覆盖。风险等级低到中，取决于多人同时编辑同一来源节点的频率。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L871) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L893) [GraphWriteJsonSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteJsonSupport.java#L336)
