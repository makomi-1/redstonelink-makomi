# 触发源配对结构化提交收口

## 1. 功能与语义、架构设计（关键方法和入口）

- 本轮把 `triggerSource` 配对界面的提交与清空从命令字符串迁到结构化 `C2S`/`S2C` 协议，新增 `SubmitTriggerSourcePairingPayload` 与 `PairingFeedbackPayload`，并保持打开界面与近外显查询协议不变，入口见 [PairingNetwork.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetwork.java#L127) 与 [PairingNetwork.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetwork.java#L153)。
- 协议注册层把新 payload 挂到 `PairingNetworkRegistrationSupport`，服务端收到后统一切回主线程处理，避免网络线程直接触达世界数据，入口见 [PairingNetworkRegistrationSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkRegistrationSupport.java#L28) 与 [PairingNetworkRegistrationSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkRegistrationSupport.java#L60)。
- 服务端执行层不再在 `PairingNetwork` 内复制 `link set` 规则，而是直接复用已抽出的 `LinkSetExecutionService.prepareConfirmedReplace/applyPreparedReplace`，并补上根命令权限、写控权限和静默限流校验，主流程见 [PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L36) 与 [LinkSetExecutionService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkSetExecutionService.java#L45)。
- 命令链路仍保留 `confirm` 包装和原有反馈发送逻辑，说明共享执行服务已经可以同时服务命令与网络两条入口，关键点见 [LinkCommandRegistry.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkCommandRegistry.java#L184) 与 [LinkCommandRegistry.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkCommandRegistry.java#L256)。
- 语义对齐说明：本轮新增命名与协议均只使用 `triggerSource/core`，且结构化迁移只覆盖 `triggerSource -> core` 正向写入；`core` 配对继续走父类默认命令兼容路径，没有扩大旧方向语义面，相关入口见 [AbstractMultiPairingScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/AbstractMultiPairingScreen.java#L217) 与 [TriggerSourcePairingScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/TriggerSourcePairingScreen.java#L97)。

## 2. 关键数据结构和算法性能分析

- `LinkSetExecutionService` 仍以 `Set<Long>` 维护目标集合、旧集合和受影响集合，解析、去重、在线态筛查与写控评估都是按目标数线性执行，复杂度保持在 `O(n)`，关键结构见 [LinkSetExecutionService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkSetExecutionService.java#L77) 与 [LinkSetExecutionService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkSetExecutionService.java#L148)。
- 覆盖写入的命令成本继续由 `PreparedReplaceOperation.commandCost` 预计算，网络入口直接复用，避免再做一套成本估算逻辑，关键点见 [LinkSetExecutionService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkSetExecutionService.java#L176) 与 [PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L62)。
- 新增 payload 编解码全部是顺序写入/顺序读取，提交包成本与输入字符串长度线性相关，反馈包成本与参数数量线性相关，没有引入额外索引或缓存，关键实现见 [PairingNetworkPayloadSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkPayloadSupport.java#L70) 与 [PairingNetworkPayloadSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkPayloadSupport.java#L88)。
- 相关稳定契约测试已覆盖新增 payload 的归一化、不可变拷贝与 round-trip，能约束协议对象不被后续改动悄悄破坏，见 [PairingNetworkPayloadTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/network/PairingNetworkPayloadTest.java#L59) 与 [PairingNetworkPayloadTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/network/PairingNetworkPayloadTest.java#L132)。

## 3. 数据流或调用链

- 打开配对界面时，服务端仍按来源类型下发打开界面包，客户端进入 `TriggerSourcePairingScreen/CorePairingScreen`，入口见 [PairingNetworkClientHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/network/PairingNetworkClientHandlerSupport.java#L27)。
- `triggerSource` 界面提交时，父类的“提交/清空”钩子被 `TriggerSourcePairingScreen` 覆写为结构化发送；`core` 则继续使用父类默认命令入口，因此本轮不会改动 `core` 行为，见 [AbstractMultiPairingScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/AbstractMultiPairingScreen.java#L217) 与 [TriggerSourcePairingScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/TriggerSourcePairingScreen.java#L97)。
- 服务端接到提交包后，由 `PairingNetworkRegistrationSupport` 切到主线程，再进入 `handleSubmitTriggerSourcePairing`，完成权限校验、准备写入、限流、应用写入和反馈回传，见 [PairingNetworkRegistrationSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkRegistrationSupport.java#L61) 与 [PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L36)。
- 服务端反馈通过 `PairingFeedbackPayload` 回到客户端后，由 `PairingNetworkClientHandlerSupport` 统一展示到聊天栏，保证界面关闭后仍能看到成功、去重、离线保存或失败原因，见 [PairingNetworkClientHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/network/PairingNetworkClientHandlerSupport.java#L37) 与 [PairingNetworkClientHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/network/PairingNetworkClientHandlerSupport.java#L93)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全与权限方面，新网络入口已经补齐根命令权限、写控权限与速率限制，避免客户端绕过 `/redstonelink` 根命令保护直接写链路，关键代码见 [PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L40) 与 [PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L62)。
- 兼容性方面，`AbstractMultiPairingScreen` 默认命令入口被保留下来，因此 `core` 配对界面仍兼容旧命令链路；这保证了本轮改动只缩小风险面，没有把未收口的 `core` 方向语义带进新协议，见 [AbstractMultiPairingScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/AbstractMultiPairingScreen.java#L217)。
- 残余风险：`core` 配对仍走旧命令路径，其旧方向语义尚未完全收口；如果后续继续推进协议统一，必须继续坚持“只读旧写新”和方向隔离，不能让 `core -> triggerSource` 旧术语/旧行为在新协议层扩散。当前残余风险结论：有，且范围仍限于 `core` 配对链路。
- 扩展性方面，本轮把执行闭环抽到 `LinkSetExecutionService` 后，后续若需要给 quick action、GUI 或 bench 工具追加“已确认覆盖写入”入口，可以直接复用同一服务而不是复制命令逻辑，依据见 [LinkSetExecutionService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkSetExecutionService.java#L45)。

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- 服务端接包器统一通过 `player.server.execute(...)` 切回主线程后再访问 `LinkSavedData` 和世界对象，因此新增网络写入链路没有把共享存档状态暴露到 Netty 线程，线程边界控制见 [PairingNetworkRegistrationSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkRegistrationSupport.java#L61)。
- `LinkSetExecutionService.applyPreparedReplace` 内部会做 replace、增删事件派发和客户端快照同步，这些操作仍在服务端主线程串行执行，没有新增锁竞争或多线程读改写覆盖点，见 [LinkSetExecutionService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkSetExecutionService.java#L196)。
- 客户端反馈展示也通过 `context.client().execute(...)` 回到客户端主线程，再调用聊天显示 API，未引入新的 UI 线程竞争，见 [PairingNetworkClientHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/network/PairingNetworkClientHandlerSupport.java#L37)。
- 风险等级评估：低。当前实现没有新增跨线程共享集合或缓存；唯一需要继续关注的是未来若把 `core` 配对也迁到新协议，必须继续复用同一主线程执行模型，避免出现命令链路和网络链路在不同线程下写同一份 `LinkSavedData`。
