## 4. 安全、性能、兼容性、扩展性风险分析与建议
- 安全性：服务端现在至少会复核“玩家是否满足智能眼镜 broad gate + 站立 + 请求携带 Ctrl 标记”，防止客户端完全绕过新增门槛；但由于服务端无法像读取潜行那样独立感知 `Ctrl`，它仍依赖请求里携带的瞬时布尔值，这个残余风险已明确记录为“仅限观察类入口可接受”。[QuickLinkNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetworkServerHandlerSupport.java#L149) [QuickLinkNetwork.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetwork.java#L219) [保留问题.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs_dev/保留问题.md#L10)
- 兼容性：`Shift+B` 清空明确保持原语义，文档中也显式写明“不要求 Ctrl”，避免用户误把清空入口理解成也被 Ctrl 收紧。[usage_guide_cn.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs/usage_guide_cn.md#L48) [usage_guide_en.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs/usage_guide_en.md#L48) [item_guide.html](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs/item_guide.html#L951)
- 扩展性：如果未来要把 `Ctrl` 这类临时输入扩展到真实写入路径，应单独设计稳定的输入同步协议，而不是继续沿用请求内瞬时布尔标记；当前专用 `encode/decodeVisualizeSnapshotRequestPayload(...)` 已经把这种边界隔离在 visualize 请求自身，不会污染其他 quick-link 协议。[QuickLinkNetworkPayloadSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetworkPayloadSupport.java#L116) [QuickLinkNetwork.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetwork.java#L229)
