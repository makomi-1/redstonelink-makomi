## 2. 关键数据结构和算法性能分析

- `Expand-CaseConfigWithParameters(...)` 现在通过 `Set-BenchObjectProperty(...)` 统一回写 `id/parameters`，避免 PowerShell 5 下 `PSCustomObject` 在参数化 suite 场景直接因为动态属性赋值失败而中断；这属于低成本兼容修复，没有改变 case 展开复杂度。[Bench.Matrix.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.Matrix.ps1#L31) [Bench.Matrix.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.Matrix.ps1#L220)
- `x20` 由 `anchorTickStrategy=end` 改为 `start` 后，latency 采样锚点重新与 `input start` 返回的 `jobStartTick` 对齐，避免整批 1024 样本全部错位为 0 匹配率；这是观测基准修正，不增加额外运行成本。[sync_samechunk_latency_1024_to_1024_banded16_square.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x20/sync_samechunk_latency_1024_to_1024_banded16_square.json#L81) [sync_samechunk_latency_1024_to_1024_banded16_square.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x20/sync_samechunk_latency_1024_to_1024_banded16_square.json#L97)
- `x23` 全组合断言把 `trace_read_tick_assert.limit` 提到 512，与 mount capacity 保持一致，避免长链串行执行后旧 tick 被挤出 trace 环形缓冲区，导致前几拍样本缺失；代价是单次 trace read 返回更长，但换来了稳定的逐 tick 验证窗口。[mixed_samechunk_direct_combinations_tick_assert.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x23/mixed_samechunk_direct_combinations_tick_assert.json#L103) [mixed_samechunk_direct_combinations_tick_assert.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x23/mixed_samechunk_direct_combinations_tick_assert.json#L554)
- 权限专项 `c07` 的修复只更新响应匹配字段从旧 `target_list=` 到现行 `targets=`，没有扩大断言范围，也没有改变服务器权限/限流配置，所以不会引入额外性能负担。[server_permission_read_write_basic.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/c07/server_permission_read_write_basic.json#L60) [server_permission_read_write_basic.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/c07/server_permission_read_write_basic.json#L97)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全/语义：本轮新增和修复的测试仍全部围绕 `triggerSource -> core` 单向链路，未引入旧术语作为输出字段，也没有新增 `com.makomi.api.v1.*` 依赖。语义对齐结果为通过，残余风险为无。[send_filter_runtime_sync_reconcile.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x24/send_filter_runtime_sync_reconcile.json#L3) [receive_filter_runtime_sync_reconcile.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x26/receive_filter_runtime_sync_reconcile.json#L3)
- 兼容性：`Bench.Matrix.ps1` 的兼容修复明确针对 PowerShell 5 参数化 case 回写，不影响已有非参数化 case；这是对 bench 运行环境差异的防御性修补。[Bench.Matrix.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.Matrix.ps1#L31)
- 性能：`x23` 把读取窗口提升到 512 后，逐 tick suite 的单次 trace 返回量会上升；若后续继续扩展组合规模，建议优先拆阶段重挂载，而不是无限抬高 limit。[mixed_samechunk_direct_combinations_tick_assert.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x23/mixed_samechunk_direct_combinations_tick_assert.json#L103)
- 扩展性：权限专项已证明 Prism bench client 路径可用，后续新增玩家态 suite 时应继续复用 `run-bench-suite.ps1` 的 server/client 同步和 player bridge，而不是分散出新的启动脚本。[BenchSuite.EntryPoint.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/BenchSuite.EntryPoint.ps1#L106) [BenchSuite.EntryPoint.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/BenchSuite.EntryPoint.ps1#L328)

## 5. 并发冲突审查

- 共享状态：本轮改动集中在 bench JSON case、suite 入口脚本和本地文档，没有新增业务层共享内存或世界态并发写入点。风险等级：低。[Bench.Matrix.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.Matrix.ps1#L31)
- 读改写覆盖：`c07/x20/x23` 的问题都属于测试口径漂移或观察窗口不足，修复方式是更新断言和采样参数，而不是修改业务实现，因此没有引入新的读改写覆盖风险。[sync_samechunk_latency_1024_to_1024_banded16_square.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x20/sync_samechunk_latency_1024_to_1024_banded16_square.json#L85) [server_permission_read_write_basic.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/c07/server_permission_read_write_basic.json#L60)
- 重入/线程边界：权限专项运行时仍由 dedicated server 主线程处理命令，bench client 只通过既有 command bridge 发命令，没有直接越过原有线程边界。风险等级：中低，主要关注点仍是测试环境启动/回收，而非业务线程竞态。[BenchSuite.EntryPoint.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/BenchSuite.EntryPoint.ps1#L328)
- 建议：后续再扩展大型 trace suite 时，优先把“读取窗口需求”作为 case 参数显式建模，并在新增权限/输出断言时同步核对当前实际响应字段，避免同类假失败再次出现。
