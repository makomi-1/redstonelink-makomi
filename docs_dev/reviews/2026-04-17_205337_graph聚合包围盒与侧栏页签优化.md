## 2. 关键数据结构和算法性能分析

包围盒算法的关键输入是“当前已定位节点”，不是纯自动布局结果。这样在用户拖拽节点后，包围盒仍会跟随现有位置重新计算，而不会退回自动布局坐标。算法本身只对展开态 `aggregate` 做一次成员节点聚合，按 `min/max` 计算边界，复杂度接近 `O(expandedAggregates * members)`，对于当前视图层数据量是轻量的。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L162) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1615)

右侧页签切换没有复制数据源，而是继续复用现有的 `selectedNode`、`graphCanvasView`、批量编辑选择集合等派生状态，因此不会引入新的重型计算路径。图例和包围盒样式也都停留在静态 CSS 层，渲染开销基本受控。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1469) [app.css](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L836) [app.css](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L943)

## 3. 数据流或调用链

主画布仍然由 `graphCanvasView -> buildGraphFlowNodes -> ReactFlow` 这条链路驱动，但本轮新增了 `displayNodes` 作为最终传给 ReactFlow 的可视节点集合：真实画布节点先进入 `nodes` 状态，再由 `displayNodes` 把展开聚合块的包围盒节点叠加进去，因此布局、拖拽和包围盒表意被拆成两层而不是互相污染。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L935) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1615) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2263)

交互侧的数据流则是：节点点击继续走 `handleCanvasNodeClick` 处理展开/选中逻辑，若当前处于 `view` 模式则顺带切回详情页签；编辑模式切换则通过 `handleEditModeChange` 切换 `activeSidebarPanel`，把批量编辑入口显式抬到当前视图中。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1916) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1938)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

安全与兼容边界没有变化：本轮仍只改 `webapp` 视图层，没有触碰 `snapshot`、`draft`、服务端保存和真实 `triggerSource -> core` 语义。边文字被移除后，视觉噪音下降，但如果未来确实需要在某些模式下恢复边注释，建议走“按模式开关显示”的方式，而不是直接恢复全量常显文本。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L986)

当前残余风险主要有两点。其一，包围盒使用固定节点宽高估算范围，若后续节点尺寸出现显著变化，需要同步更新包围盒边界计算或改为读取真实宽高。其二，右侧页签虽然解决了纵向堆叠，但功能被折叠到单面板后，用户需要切换页签才能同时看到孤立节点池和详情，这是有意的空间换取；后续如果使用频率差异明显，再考虑更细的布局优化。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L162) [app.css](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L983) [app.css](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L995)

## 5. 并发冲突审查

本轮新增的共享状态只有 `activeSidebarPanel`，它和已有的 `selectedNodeKey`、`editMode` 一样，全部运行在 React 单线程状态更新模型下，并通过 `useMemo` 派生 `displayNodes`，没有引入新的跨线程共享资源；风险等级评估为“低”。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1469) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1615)
