## 2. 关键数据结构和算法性能分析

- 配方资源与文档补齐都是静态资源改动，运行时不引入新集合、索引或持久状态；其成本主要在构建期和页面渲染期，可忽略。[link_repeater.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/data/redstonelink/recipe/link_repeater.json#L1) [recipe_sheet.html](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs/recipe_sheet.html#L517)
- 前端布局新增的核心数据只有一个常量 `EXPANDED_REPEATER_INTERNAL_LAYER_GAP_X` 与一个 `resolveComponentLaneGapX(...)` 纯函数；两者都属于 `O(1)` 查值，不改变现有连通分量拆分、lane 排布和排序的复杂度。[types.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/types.ts#L14) [canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L470)
- 真正参与布局的位置仍是既有 lane 归位循环，只是在相邻 lane 之间改成“按 lane 类型决定 gap”；因此复杂度仍然是“节点过滤 + lane 排布 + 坐标归位”的线性流程，没有新增图搜索或递归布局器。[canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L1986) [canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L2098)
- 回归侧新增了配方契约测试与前端间距断言，分别锁定“资源存在且输入正确”和“内部 gap 小于外部 gap”，测试粒度小、执行成本低，但能覆盖本轮最容易回退的契约点。[LinkRepeaterRecipeContractTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/LinkRepeaterRecipeContractTest.java#L15) [canvas.test.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.test.tsx#L202)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 语义兼容性：本轮没有修改 `triggerSource/core` 的真实写入方向，也没有改变转发器双身份设计，只是补齐合成入口、文档说明与前端视觉表达。风险低。[usage_guide_cn.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs/usage_guide_cn.md#L143) [canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L470)
- 文档一致性风险：`recipe_sheet.html` 需要同时维护静态卡片、分类函数、贴图映射和名称映射；若后续再改转发器命名或贴图，只改其中一处会导致页面显示不一致。建议继续保持“卡片 + 分类 + 资源映射”同步修改。[recipe_sheet.html](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs/recipe_sheet.html#L358) [recipe_sheet.html](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs/recipe_sheet.html#L517) [recipe_sheet.html](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs/recipe_sheet.html#L1697)
- 前端布局风险：当前只压缩了转发器内部两段相邻 gap，没有做更重的转发器级嵌套布局，因此在多个展开态转发器同屏时，仍沿用现有全局 lane 排布。现阶段满足需求，风险低到中。[canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L1986) [canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L2098)
- 资源兼容性：这次把“同步触发器”落实为现有物品 `link_sync_emitter`，没有引入新物品名或新 tag，因此不会扩大运行时兼容面。风险低。[link_repeater.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/data/redstonelink/recipe/link_repeater.json#L12)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- 配方与文档改动都是静态资源和静态页面配置，不涉及共享可变状态、异步回调或线程边界。并发风险低。[link_repeater.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/data/redstonelink/recipe/link_repeater.json#L1) [item_guide.html](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs/item_guide.html#L746)
- 前端新增的 `resolveComponentLaneGapX(...)` 是纯函数，输入仅为当前 render 周期内的 lane 类型；没有跨 render 缓存、没有共享写状态，也没有引入新的异步数据源。并发风险低。[canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L470)
- 测试侧只增加资源读取断言和布局结果断言，不会与运行时代码共享状态，也不会引入新的重入路径。建议后续若继续扩展转发器局部布局，保持这种“纯派生、不持久缓存”的实现方式。风险等级：低。[LinkRepeaterRecipeContractTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/LinkRepeaterRecipeContractTest.java#L22) [canvas.test.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.test.tsx#L202)
