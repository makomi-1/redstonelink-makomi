# graph保存无关对象冲突放宽

## 1. 功能与语义、架构设计（关键方法和入口）

- 本轮核心改动是把网页端 graph 保存的冲突入口从“整图先拦截”收敛为“对象级 OCC 校验优先”。`GraphWriteService.preparePlan(...)` 现在在权限校验后直接进入 alias、channel、replace 的逐对象校验，不再因为无关对象推动了 `graphRevision` 就提前整体失败。[GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L262) [GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L279) [GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L290)
- `replace` 路径仍保持 `triggerSource -> core` 的正向写入语义，只按被编辑 `triggerSource` 的 `expectedSourceRevision` 与当前 `sourceRevision` 判定真实冲突，没有引入反向持久化或整图覆盖。[GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L420) [GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L441) [GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L466)
- `channel` 路径继续按节点类型走对象级 revision 校验：`triggerSource` 比较 `expectedSourceRevision`，`core` 比较 `expectedCoreRevision`，因此本轮只是去掉误拒绝，没有放宽真实冲突边界。[GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L505) [GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L525) [GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L531)
- 语义对齐说明：新增与修改内容均使用 `triggerSource/core` 命名；真实写入方向仍为 `triggerSource -> core`；未引入 `com.makomi.api.v1.*` 依赖；兼容层仍是“读旧写新”。残余风险：无新增语义漂移风险。

## 2. 关键数据结构和算法性能分析

- 本轮没有新增新的索引结构或全图扫描。删除整图 `baseGraphRevision` 预拦截后，请求仍然复用现有 `validatedChannelBatchOperation` 和 `validatedReplaceOperations` 的逐对象校验流程，性能成本主要取决于请求中实际涉及的节点数量，而不是整图大小。[GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L290) [GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L314)

## 3. 数据流或调用链

- `replace` 调用链现在是“网页请求携带 `expectedSourceRevision` -> 服务端读取当前 `sourceRevision` -> 命中不一致则返回 `source_revision_conflict`，否则继续准备覆盖计划”。关键入口见 [GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L441) [GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L445) [GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L466)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全与一致性：本轮没有把真实冲突变成“最后写入者覆盖”，只是让无关对象的 graphRevision 变化不再误拒绝。因此同对象 stale 写入仍会被 `source_revision_conflict/core_revision_conflict` 明确挡住，安全边界维持不变。[GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L442) [GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L531)
- 兼容性：请求协议里的 `baseGraphRevision` 字段仍保留，前端与 bench 构造请求的结构无需同步变更；也就是说本轮是服务端判定收敛，不是协议破坏性变更。相关入口见 [GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L218)。
- 扩展性：如果后续要继续推进“同对象非真实冲突自动合并”，需要前端保留 add/remove 的原始编辑意图，而不是只折算成最终 replace 集合；否则自动重放仍可能覆盖他人并发改动。当前实现尚未具备这层能力，本轮没有冒进放开。风险等级：中。
- 建议：后续若要做“重新导出和自动加载入口”，优先补局部刷新或自动重基线能力，而不是在现有最终 replace 模型上直接重放 stale 结果。

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- 共享状态：共享真值仍是 `LinkSavedData` 里的连接索引与 revision 三元组；本轮未新增新的共享可变状态，只调整了 `preparePlan(...)` 读取这些状态的时机与拦截粒度。[GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L279) [LinkSavedDataLinkIndexSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataLinkIndexSupport.java#L316)
- 读改写覆盖：主要收益是去掉了“无关对象变更导致整批误拒绝”的覆盖式保守策略；真实覆盖风险仍靠对象级 revision 阻断，尤其是 `replace` 的 `sourceRevision` 和 `channel` 的 `source/coreRevision`。风险等级：低到中。[GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L441) [GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L525)
- 重入/线程边界：测试与实现都没有引入新的异步写入路径；`preparePlan(...)` 仍是服务端同步读取当前真值后构建计划，再由后续 apply 阶段写回。当前没有新增线程边界风险。风险等级：低。[GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L53) [GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L66)
- 残余风险：批量请求中只要命中一个真实对象冲突，当前仍是整批失败，不支持部分对象提交；这是现有事务边界，非本轮新增问题。建议后续若需要进一步降低冲突成本，再单独设计“部分成功 + 草稿回写”的协议。
