## 2. 关键数据结构和算法性能分析
- 边界提取算法按“外露面 -> 2D 边界 -> 3D 去重 -> 共线合并”执行，核心逻辑位于 [QuickLinkPreviewOutlineSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/QuickLinkPreviewOutlineSupport.java#L25) 与 [QuickLinkPreviewOutlineSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/QuickLinkPreviewOutlineSupport.java#L85)。复杂度与缓存方块数线性相关，且只在 TTL 失效后重算，不会按每帧重复全量扫描。
- 转发器展示同步只在命中转发器统一序号时触发，且通过 [RepeaterGraphSnapshotSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/RepeaterGraphSnapshotSupport.java#L153) 定位单个已加载方块实体，不会做无界世界扫描；玩家物品同步继续沿用既有库存遍历，入口仍是 [RepeaterGraphSnapshotSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/RepeaterGraphSnapshotSupport.java#L98)。
- 编辑器摘要不再从原始 `serialExpression` 直接显示，而是优先用展示文本列表拼接，逻辑在 [RepeaterEditorScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/RepeaterEditorScreen.java#L312)；这只是展示层格式化，没有改变持久化结构和 OCC 口径。
- 网络编解码新增的输入/输出展示文本列表位于 [RepeaterNetworkPayloadSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/RepeaterNetworkPayloadSupport.java#L29) 与 [RepeaterNetworkPayloadSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/RepeaterNetworkPayloadSupport.java#L173)，长度和数量都受既有上限保护。

## 4. 安全、性能、兼容性、扩展性风险分析与建议
- 兼容性方面，本轮没有修改 `triggerSource/core` 存储语义，也没有改变 OCC 冲突口径；展示文本只是附加到打开编辑器 payload 中，旧的保存 payload 结构仍保持独立，参见 [RepeaterNetworkPayloadSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/RepeaterNetworkPayloadSupport.java#L80)。
- 性能方面，外框边界提取虽然比直接 `VoxelShape.or(...)` 更复杂，但仍只对当前缓存命中的已加载方块做一次短 TTL 扫描，且共线合并后最终顶点数更少，见 [QuickLinkPreviewOutlineSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/QuickLinkPreviewOutlineSupport.java#L25)。
- 展示同步方面，目前已覆盖“图关系变化后刷新转发器摘要”；若后续出现“仅节点别名变化但图关系未改，转发器 node-set 展示仍需立即刷新”的需求，可继续把 `NodeAliasServerSupport` 的别名同步链扩展到转发器依赖节点集。当前残余风险为低。
- 掉落方面，本轮通过显式 loot table 兜底保证基本自掉落；而序号/配置保留仍由 [LinkRepeaterBlock.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/LinkRepeaterBlock.java#L80) 的 `getDrops(...)` 完成，若后续 MC 版本调整 loot 调用链，优先回归这两层组合行为。
