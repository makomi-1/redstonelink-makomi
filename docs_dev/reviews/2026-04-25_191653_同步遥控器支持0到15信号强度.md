## 2. 关键数据结构和算法性能分析

- 同步遥控器强度仍然只占一个物品标签整数字段，写入路径保持 O(1)，没有引入额外集合或扫描逻辑，见 [LinkItemData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkItemData.java#L550)。
- pairing 布局扩展采用“显式控制行数量 -> 一次性计算布局”的方式，避免在 `render` 阶段反复测量或遍历控件树，布局计算仍然是常量时间，见 [AbstractMultiPairingScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/AbstractMultiPairingScreen.java#L906)。
- 客户端滚轮快捷调节只做一次主手物品判断、一次强度 clamp、一次本地 NBT 写入和一次网络发送，事件处理为 O(1)，见 [RedstoneLinkClient.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/RedstoneLinkClient.java#L313)、[RedstoneLinkClient.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/RedstoneLinkClient.java#L338)。
- 网络编解码只增加一个 `expectedSerial + signalStrength` 的轻量 payload，不会对现有 pairing 大包造成额外复杂度，见 [PairingNetworkPayloadSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkPayloadSupport.java#L238)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全性：服务端保存入口只接受当前主手同步遥控器，且允许用 `expectedSerial` 拦截“界面打开后换物品”的误写风险，见 [PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L226)。当前风险等级为低。
- 兼容性：为保持现有资源边界，没有扩展 16 档物品贴图，而是继续沿用 `0=默认 / 1~15=active` 的二态模型镜像。这保证资源兼容，但意味着视觉上不能区分 1 与 15。若未来需要精细外观，再单独扩贴图与模型即可。对应逻辑在 [LinkItemData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkItemData.java#L568)。
- 输入兼容性：客户端滚轮快捷调节通过低层 GLFW scroll callback 包装实现，优点是 `no-mixin` 分支也可落地；代价是它依赖与原有回调链正确衔接。当前实现只在命中同步遥控器快捷手势时吞掉滚轮，未命中时继续透传上一层回调，见 [RedstoneLinkClient.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/RedstoneLinkClient.java#L313)。风险等级为中低。
- 扩展性：`AbstractMultiPairingScreen` 的附加控制行钩子已经抽出来，后续如果还有其它 triggerSource 类物品需要加一行专用控件，可以复用 [AbstractMultiPairingScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/AbstractMultiPairingScreen.java#L531)、[AbstractMultiPairingScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/AbstractMultiPairingScreen.java#L906)，不必复制整套 pairing 布局。

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- 服务端线程边界：同步遥控器强度保存 payload 仍通过注册层切回服务器主线程，再在主线程内修改主手物品与容器同步，见 [PairingNetworkRegistrationSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkRegistrationSupport.java#L89)、[PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L226)。共享状态风险等级低。
- 客户端线程边界：GUI 按钮与滚轮快捷调节都运行在客户端主线程/窗口事件线程上下文，写的是客户端物品镜像副本，然后再发包让服务端落真值；不存在跨线程共享集合或锁竞争。相关入口见 [TriggerSourcePairingScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/TriggerSourcePairingScreen.java#L345)、[RedstoneLinkClient.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/RedstoneLinkClient.java#L338)。风险等级低。
- 读改写覆盖：客户端先写本地镜像、服务端再写真值，理论上存在“本地先显示，服务端因物品切换而拒绝保存”的短暂分叉窗口；当前通过 `expectedSerial` 做了主手序号校验，把风险收敛到“用户换物品的极短时序”。风险等级中低，现阶段可接受。
- 重入建议：若后续同一窗口回调链还要接入更多滚轮逻辑，建议把当前同步遥控器滚轮处理抽成集中式路由，避免多个功能各自包一层 GLFW callback 导致回调链维护复杂化。
