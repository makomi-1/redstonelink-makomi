## 1. 功能与语义、架构设计（关键方法和入口）
- 本轮只调整跨区块提示口径，不改实际 dispatch/queue/force-load 逻辑。核心入口仍是 `LinkedTargetDispatchService.buildCrossChunkNotifyMessages(...)`，负责把 `DispatchSummary` 翻译为玩家可见消息。[LinkedTargetDispatchService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkedTargetDispatchService.java#L106)
- `DispatchSummary` 现有的 `forceLoadTargetSerials` 与 `relayTargetSerials` 被完整利用：header 改为统计 `crossChunkHandledCount()`，relay 分支会输出“目标所在区块已卸载，当前缓冲等待恢复”的提示。[LinkedTargetDispatchService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkedTargetDispatchService.java#L114) [LinkedTargetDispatchService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkedTargetDispatchService.java#L130)
- 方块入口 `TriggerSourceBlockEntity` 发送提示的门槛从 `hasForceLoadHandled()` 对齐为 `hasCrossChunkHandled()`，与 `LinkerItem` / `SyncLinkerItem` 当前行为一致，避免 relay-only 场景静默。[TriggerSourceBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/TriggerSourceBlockEntity.java#L118)

## 3. 数据流或调用链
- 调用链保持不变：`dispatchActivation/dispatchSyncSignal -> dispatchInternal -> DispatchSummary`，然后由各入口在 `notifyEnabled` 下调用 `buildCrossChunkNotifyMessages(...)` 发送系统消息。[LinkedTargetDispatchService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkedTargetDispatchService.java#L45) [LinkedTargetDispatchService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkedTargetDispatchService.java#L136) [TriggerSourceBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/TriggerSourceBlockEntity.java#L118)

## 4. 安全、性能、兼容性、扩展性风险分析与建议
- 安全：本轮没有调整权限、白名单、resident 或强加载判定，只是更精确地暴露已有 dispatch 结果，风险低。[LinkedTargetDispatchService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkedTargetDispatchService.java#L106)
- 性能：额外只是一行 relay 文本构造，且仅在跨区块接管发生时触发，不在常规热路径上循环扩张，风险低。[LinkedTargetDispatchService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkedTargetDispatchService.java#L130)
- 兼容性：现有语言 key 没有改名，只改了 `relay_targets` 文案，因此不会破坏已有调用方；`DispatchSummary` 字段结构也未变化。[zh_cn.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/assets/redstonelink/lang/zh_cn.json#L249) [en_us.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/assets/redstonelink/lang/en_us.json#L249)
- 扩展性建议：如果后续要继续细分“区块已卸载但 queue 关闭导致未接管”的失败提示，可以在 `QueueResult` 增加更细粒度原因码，而不是继续复用二值布尔位。

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）
- 共享状态方面，本轮没有新增全局可变状态；`buildCrossChunkNotifyMessages(...)` 只消费不可变 `DispatchSummary` 快照并生成新的 `Component` 列表，不参与读改写共享容器。[LinkedTargetDispatchService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkedTargetDispatchService.java#L106) [LinkedTargetDispatchService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkedTargetDispatchService.java#L138)
- 线程边界未变化：提示仍在服务端主线程的交互/触发链路中发送，本轮没有引入异步消息拼装或后台状态同步。[TriggerSourceBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/TriggerSourceBlockEntity.java#L118)
- 读改写覆盖风险低：语言资源修改为静态文本替换，测试通过 `TranslatableContents` 断言 key/args，避免未来把 relay 行重新退化为模糊提示时无人察觉。[LinkedTargetDispatchServiceTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/data/LinkedTargetDispatchServiceTest.java#L106) [LinkedTargetDispatchServiceTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/data/LinkedTargetDispatchServiceTest.java#L119)
- 风险等级：低。残余风险在于“queue 关闭且未命中强加载”时仍会落回 `no_reachable_targets`，这一层不属于本轮已实现范围。
