# 批量选区多数类型聚焦与频道新增成员聚合修复

## 1. 功能与语义、架构设计

- 本轮先在前端解析层增加 `connectionMode` 归一化：当节点 `channel > 0` 时统一按频道成员解释，避免回包字段不稳定时把节点错误排除在频道视图之外；入口位于 [graphTypes.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/graphTypes.ts#L129) 、[graphTypes.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/graphTypes.ts#L247) 和 [graphTypes.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/graphTypes.ts#L296)。
- `GraphViewer` 的搜索集、频道详情绑定和批量编辑后聚焦，统一改为消费归一化后的 `isChannelConfiguredNode/isSerialConfiguredNode` 结果，避免“节点已写入频道但当前视图仍按序号节点处理”的分叉；关键位置在 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L230) 、[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L317) 和 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L467)。
- 批量“应用草稿”后的上下文聚焦不再只看单个 `selectedNodeKey`，而是按当前批量选区里 `triggerSource/core` 哪一类更多来选聚焦目标，并把该目标通过结构重排入口传下去；实现点位于 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L317) 、[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1017) 和 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1531)。
- 序号/频道两套画布构建入口也统一改用相同的成员判定辅助函数，确保新增频道成员会进入正确的频道聚合分组，同时不会残留在序号视图；对应位置在 [canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L595) 和 [canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L947)。

## 2. 关键数据结构和算法性能分析

- `normalizeConnectionModeToken()` 只是基于 `channel` 与 `connectionMode` 的常数时间判定，不引入额外集合或排序成本；定义见 [graphTypes.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/graphTypes.ts#L129)。
- `searchableNodes` 仍是对当前 `effectiveGraphBundle.nodes` 的一次线性筛选，`batchEditFocusNodeKey` 也是对当前选区节点的线性计数，没有改变主画布布局的时间复杂度；实现见 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L230) 和 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L317)。
- 序号视图和频道视图的节点入桶阶段现在都先按配置模式过滤，再进入后续聚合逻辑，因此能减少错误节点进入错误视图后再被后续逻辑反复处理的浪费；入口见 [canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L600) 和 [canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L952)。
- 本轮没有改动 `triggerSource -> core` 真值存储算法，也没有新增布局推开或聚合展开算法；改动集中在前端解析与视图选择口径，性能影响主要限于一次性前端筛选，风险较低。

## 3. 数据流或调用链

- 快照/保存回包进入前端后，先由解析层归一化节点的 `connectionMode`，随后产出前端使用的 `GraphSnapshotBundle/GraphWriteResponse`；链路见 [graphTypes.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/graphTypes.ts#L247) 和 [graphTypes.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/graphTypes.ts#L296)。
- 视图层读取归一化后的节点集合：`GraphViewer` 先生成当前模式下的 `searchableNodes`，再由 `buildSerialGraphCanvasView/buildChannelGraphCanvasView` 决定主画布节点、边和聚合块；对应位置在 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L230) 、[canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L595) 和 [canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L947)。
- 频道详情面板在选中真实节点时，会通过该节点的频道号回查 `channelHub`，因此只要节点被正确识别为频道成员，就能绑定到正确频道上下文；调用见 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L467)。
- 批量应用链路为：选区节点统计多数类型 -> 生成 `batchEditFocusNodeKey` -> `handleApplyBatchEdit()` 写入草稿 -> `requestStructureLayoutRefresh()` 以该节点作为重排后聚焦目标；实现见 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L317) 、[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1017) 和 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1531)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 语义兼容性：本轮仍只使用 `triggerSource/core` 术语，且只修前端视图口径与交互聚焦，未改服务端真值、`snapshot` 持久化结构或 `triggerSource -> core` 写入方向；归一化只是前端读口径容错，不改变真实保存语义。
- 风险边界：如果后端后续真的导出 `channel=0` 且 `connectionMode` 也不是 `channel`，前端仍不会把该节点纳入频道聚合；也就是说，本轮修的是“频道字段已有值但前端分桶失真”的问题，不覆盖“导出真值本身缺失”的情况。相关解析位置在 [graphTypes.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/graphTypes.ts#L129)。
- 可扩展性：`isChannelConfiguredNode/isSerialConfiguredNode` 已成为统一判定入口，后续如果频道编辑、聚合或搜索还要复用“当前节点属于哪个视图”的逻辑，可以直接沿用同一辅助函数，减少模式判断分散；定义在 [graphTypes.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/graphTypes.ts#L137) 和 [graphTypes.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/graphTypes.ts#L144)。
- 验证风险：自动化回归里 `testSlow` 仍有既有性能基线失败，失败点是 `LinkSavedDataPerformanceSlowTest` 的 `save cost 87ms exceeds limit 50ms`，目前看与本轮前端改动无直接耦合，但本轮不能标记为“全量自动化全绿”。

## 5. 并发冲突审查

- 共享状态主要集中在 `selectedEditSourceSerials`、`selectedEditTargetSerials`、`selectedEditChannelNodeKeys`、`selectedNodeKey` 和结构重排挂起状态；其中多数类型聚焦是纯 `useMemo` 派生值，不会引入新的共享可变容器，相关位置在 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L257) 、[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L272) 、[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L306) 和 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L317)。
- 当前风险等级评估为低：所有状态更新都发生在 React 前端单线程事件流里，本轮没有新增异步并发写共享数据结构的路径。
- 需要注意的竞态边界是“批量应用后立即再次切换视图或编辑模式”。当前实现把最终聚焦目标折叠为单个 `focusNodeKey` 传入结构重排入口，因此即使批量选区较大，重排链路仍只有一个上下文焦点，覆盖面明确；入口见 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1017) 和 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1559)。
