# graph展开后框选失效修复

## 1. 功能与语义、架构设计（关键方法和入口）

本轮修复只作用于 graph 前端视图层，不改 `triggerSource/core` 真值、snapshot、draft 和服务端保存语义。核心调整是保留“框选预览态 / 应用态分离”的结构，但把预览态的真实选区来源从不稳定的 `onSelectionChange` 回切到 ReactFlow 的 `select` 增量事件，这样即使画布里存在展开后的聚合块与包围盒，最终提交到批量编辑集合的仍然只是真实 `triggerSource/core` 节点。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2066) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2079) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2155) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2201) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2662)

入口仍集中在 `GraphViewer`：框选开始时先快照当前正式选区，框选过程中由 `handleCanvasNodesChange` 消费 `NodeSelectionChange` 增量，框选结束后在下一帧一次性调用 `applyCanvasSelectedNodeKeys` 和 `applyBatchSelectionFromNodeKeys` 提交正式结果。这样把“预览缓存”和“业务选区提交”重新拆开，同时避免展开块节点污染最终选区。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2111) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2201) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2210)

## 2. 关键数据结构和算法性能分析

本轮没有新增 React 状态，只继续使用 `selectionPreviewActiveRef`、`pendingSelectionNodeKeysRef` 和 `finalizeSelectionFrameRef` 这三个 `ref` 保存高频拖框过程中的临时状态，避免框选每一帧都触发 React 重渲染。这种做法对高节点量场景更稳妥，符合当前 graph 视图的性能诉求。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1571) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1573)

算法上，`collectSelectableActualNodeKeysFromCanvasNodes` 在框选开始时做一次当前真实选区快照，`applySelectionPreviewNodeChanges` 再对后续 `select` 增量做集合增删，复杂度保持在线性级别，不会比原先每次都扫描完整选区更差。同时入口过滤了非真实节点，降低了展开场景下无效节点参与运算的比例。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2066) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2079)

## 3. 数据流或调用链

修复后的调用链是：`onSelectionStart` 触发 `handleSelectionPreviewStart`，先从当前画布节点状态提取真实正式选区；拖框过程中，`onNodesChange` 进入 `handleCanvasNodesChange`，其中 `select` 增量被 `applySelectionPreviewNodeChanges` 吸收为预览候选集合，而非 `select` 变更仍继续交给 ReactFlow 原生处理；`onSelectionEnd` 再统一提交最终真实节点集合到画布选中态与右侧批量编辑集合。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2066) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2155) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2201) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2210)

非框选场景下，`onSelectionChange` 仍保留普通点击选择的即时同步；但在预览阶段它会直接返回，不再参与候选选区计算，职责边界比上一轮更清晰。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2662)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

安全和语义层面，本轮没有新增 API 依赖，没有改持久化结构，也没有改变 `triggerSource -> core` 的真实保存边界，符合当前项目的命名和方向隔离约束。风险主要仍集中在 ReactFlow 事件时序：当前实现默认 `select` 增量会在 `onSelectionEnd` 前或同帧内到达，因此继续保留“在下一帧正式提交”的缓冲策略，以降低末帧事件顺序抖动带来的影响。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2079) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2217) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2662)

扩展性上，如果后续继续增加“追加框选”“条件批量选中”“辅助节点可见但不可选”等交互，建议沿用当前入口过滤策略：辅助节点可以参与显示，但不得进入真实业务选区集合，否则会再次把展示层节点混入编辑层语义。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2052) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2079)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

前端仍处于 React 单线程事件循环，本轮没有引入新的跨线程共享状态。主要冲突点在于“预览态选区”和“正式业务选区”对同一批节点的读改写覆盖：上一轮问题是预览态没有稳定真源，导致提交态读取到错误集合；本轮通过 `ref` 保存预览缓存，并在 `onSelectionEnd` 统一提交，避免了中途读写互相覆盖。当前风险等级评估为低。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1571) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2155) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2210)
