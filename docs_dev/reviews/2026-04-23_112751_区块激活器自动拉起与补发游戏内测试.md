## 2. 关键数据结构和算法性能分析

- `buildPlan(...)` 仍然只基于“前后节点集差集”决定新增成员，复杂度为 O(n)，不会因为 resident 语义修正而把整个节点集重复补发或重复拉起。[ChunkActivatorImmediateEffectService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/ChunkActivatorImmediateEffectService.java#L70) [ChunkActivatorImmediateEffectService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/ChunkActivatorImmediateEffectService.java#L90)
- resident 票据同步仍是“收集期望票据 + 原地 diff”两步，`residentDesiredTicketsScratch` 与 `residentTickets` 都按 resident 节点数线性增长，没有引入额外的嵌套扫描或跨 tick 临时对象堆积。[CrossChunkDispatchTicketSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CrossChunkDispatchTicketSupport.java#L111) [CrossChunkDispatchTicketSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CrossChunkDispatchTicketSupport.java#L226) [CrossChunkDispatchService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CrossChunkDispatchService.java#L678)

- 运行时调用链是：区块激活器配置/激活完成 upsert 后进入 `applyAfterUpsert(...)`，再由 `buildPlan(...)` 分流到 `bootstrapResidentTicket(...)` 或 replay 分支；resident 与 replay 从入口处就已经解耦。[ChunkActivatorImmediateEffectService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/ChunkActivatorImmediateEffectService.java#L26) [ChunkActivatorImmediateEffectService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/ChunkActivatorImmediateEffectService.java#L39) [ChunkActivatorImmediateEffectService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/ChunkActivatorImmediateEffectService.java#L45)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 兼容性风险：`triggerSource/resident` 不再即时 replay，任何把 resident 当成 replay 通道的旧断言都会失效；当前已通过专门单测把 resident 与 force_load 的计划差异固定下来。[ChunkActivatorImmediateEffectServiceTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/data/ChunkActivatorImmediateEffectServiceTest.java#L46) [ChunkActivatorImmediateEffectServiceTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/data/ChunkActivatorImmediateEffectServiceTest.java#L75)
- 运行风险：resident 票据现在按持久化节点位置保持，这与设计一致，但也意味着节点删除/失活路径必须继续正确回收 resident refcount，否则区块可能短时多保持在线；当前 refcount 增减逻辑仍集中在 `PlacedChunkActivatorSavedData`，风险等级低。[PlacedChunkActivatorSavedData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/PlacedChunkActivatorSavedData.java#L279) [PlacedChunkActivatorSavedData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/PlacedChunkActivatorSavedData.java#L297)
- 扩展性建议：`x54` 已把“拉起区块”和“重算高态”拆成独立观察点，后续如果 core 重算时序有变化，只需调整等待窗或断言层次，不应再回退 resident 只负责拉起区块的设计边界。[chunk_activator_core_resident_auto_replay.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x54/chunk_activator_core_resident_auto_replay.json#L157) [chunk_activator_core_resident_auto_replay.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x54/chunk_activator_core_resident_auto_replay.json#L169)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- `CrossChunkDispatchService` 对 resident 同步、目标区块通知和状态访问都显式要求服务端线程，`DispatchState` 的 `residentTickets` / `residentDesiredTicketsScratch` 属于单服单线程缓存；共享状态竞争风险低。[CrossChunkDispatchService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CrossChunkDispatchService.java#L523) [CrossChunkDispatchService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CrossChunkDispatchService.java#L627) [CrossChunkDispatchService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CrossChunkDispatchService.java#L678)
- `ChunkActivatorImmediateEffectService.buildPlan(...)` 是纯差集计算，副作用执行前先把 resident/replay 成员集确定下来，避免在执行阶段对同一 activator 配置反复读改写；重入风险低。[ChunkActivatorImmediateEffectService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/ChunkActivatorImmediateEffectService.java#L56) [ChunkActivatorImmediateEffectService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/ChunkActivatorImmediateEffectService.java#L97)
- 建议后续继续维持“resident 只改票据、补发/重算走生命周期链路”的分层，避免再次把加载职责和补发职责混入同一个入口，降低跨线程观察与竞态排查复杂度；当前风险等级为低。[ChunkActivatorImmediateEffectService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/ChunkActivatorImmediateEffectService.java#L13) [CrossChunkDispatchService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CrossChunkDispatchService.java#L506)
