# graph中键拖拽整页滚动修复

## 1. 功能与语义、架构设计（关键方法和入口）

本轮修复只作用于 graph 前端视图层的中键交互，不改 `triggerSource/core` 真值、snapshot、draft 和服务端保存语义。核心入口是 `handleCanvasMiddleMouseEvent`：在画布外层容器上拦截中键默认行为，仅执行 `preventDefault()`，从而阻止浏览器启动整页自动滚动，同时保留事件继续传递给 ReactFlow 的中键平移逻辑。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2040) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2531) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2576)

样式层则在 `.graph-canvas` 上补充 `overscroll-behavior: contain;`，把滚动影响收敛在图窗口内部，避免外层页面承接滚动链。[app.css](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L915)

## 2. 关键数据结构和算法性能分析

这次没有新增数据结构，也没有改变图布局、节点集合或边集合的计算，只在事件入口增加了一个常量级判断：仅当 `event.button === 1` 时才执行拦截。时间复杂度和渲染复杂度基本不变，不会引入额外的图计算成本。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2040)

样式侧新增的 `overscroll-behavior` 也属于浏览器滚动行为约束，不会增加 React 状态更新、节点重建或布局重排的算法负担。[app.css](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L915)

## 3. 数据流或调用链

修复后的中键链路是：用户在 `graph-canvas` 容器内按下中键时，容器先执行 `handleCanvasMiddleMouseEvent` 拦截浏览器默认自动滚动；随后事件继续进入 ReactFlow，ReactFlow 依据现有 `panOnDrag={[1]}` 配置执行画布内部平移。这样默认页面滚动和图内平移被明确拆开，行为边界更清晰。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2040) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2532) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2576)

样式侧的 `overscroll-behavior: contain` 进一步保证即使容器内发生滚动边界行为，滚动链也不会外溢到整页，形成第二层防线。[app.css](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L915)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

安全与语义层面，本轮没有引入新的 API、没有更改 graph 保存路径，也没有改变 `triggerSource -> core` 的真实业务含义，属于纯前端交互修复。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2040)

兼容性风险较低，主要在于不同浏览器对中键默认行为的触发时机略有差异；当前同时在容器上处理 `onMouseDownCapture` 和 `onAuxClick`，覆盖了常见 Windows 浏览器的中键自动滚动入口。后续如果还发现个别环境残留页面滚动，再考虑补充更底层的指针事件拦截即可。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2532) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2533)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

这次改动没有新增 React 状态，也没有引入跨线程共享状态，属于同步事件处理逻辑。事件处理只调用 `preventDefault()`，不修改节点、边、布局或批量选择状态，因此不存在与现有 graph 状态机的读改写覆盖问题，风险等级评估为“低”。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2040)

后续若继续增加更多鼠标手势，建议统一在 `graph-canvas` 外层集中管理浏览器级默认行为，而不要把同类拦截逻辑分散到多个子节点，避免不同交互入口之间出现事件顺序冲突。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2531) [app.css](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L915)
