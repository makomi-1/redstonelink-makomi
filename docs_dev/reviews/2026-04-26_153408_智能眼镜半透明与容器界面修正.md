# 智能眼镜半透明与容器界面修正

## 1. 功能与语义、架构设计
- 智能眼镜现在把“连线显示”和“连线操作”拆成两套条件：显示只要求穿戴眼镜，操作仍要求穿戴眼镜且主手空；判定集中在 [SmartGlassesAccessSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/SmartGlassesAccessSupport.java#L52) 与 [SmartGlassesAccessSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/SmartGlassesAccessSupport.java#L62)。这样主手拿 QLT 等工具时，第三形态连线仍能继续显示，但不会误触清空或增删。
- 连线显示入口和操作入口已经分流：第三形态穿墙线与悬停 HUD 改为只看显示条件，见 [QuickLinkOutlineRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/QuickLinkOutlineRenderer.java#L202) 与 [QuickLinkOutlineRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/QuickLinkOutlineRenderer.java#L304)；增删显示对象的客户端交互和服务端验权仍只看操作条件，见 [QuickLinkNetworkClientHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/network/QuickLinkNetworkClientHandlerSupport.java#L380)、[QuickLinkNetworkClientHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/network/QuickLinkNetworkClientHandlerSupport.java#L410) 与 [QuickLinkNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetworkServerHandlerSupport.java#L151)。
- 智能眼镜穿戴半透明效果通过客户端专用护甲渲染器实现，不改头盔模型，只改渲染层和 alpha；注册与实现分别位于 [RedstoneLinkClient.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/RedstoneLinkClient.java#L89)、[RedstoneLinkClient.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/RedstoneLinkClient.java#L151) 与 [SmartGlassesArmorRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/SmartGlassesArmorRenderer.java#L25)。
- 智能节点容器的物品模型改成“节点式内层 + 类型侧面”：内层统一回到节点常用的 `component_core_block`，类型区分通过侧面贴图承担，见 [smart_node_container.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/assets/redstonelink/models/block/smart_node_container.json#L1)、[smart_node_container_core.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/assets/redstonelink/models/block/smart_node_container_core.json#L1)、[smart_node_container_triggersource.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/assets/redstonelink/models/block/smart_node_container_triggersource.json#L1)、[smart_node_container_repeater.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/assets/redstonelink/models/block/smart_node_container_repeater.json#L1)。
- 智能节点容器 GUI 右侧新增独立控制区，把“当前放置类型 / 自动排序”从槽位上方挪开，避免压到大箱子槽位区域；实现见 [SmartNodeContainerScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/SmartNodeContainerScreen.java#L19)。

## 2. 关键数据结构和算法性能分析
- 智能眼镜显示/操作条件拆分没有引入新状态，只是在既有布尔判定上拆出 `canRenderQuickLinkVisualization` 和 `canOperateQuickLinkVisualization` 两个常数级判断；实现位于 [SmartGlassesAccessSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/SmartGlassesAccessSupport.java#L62) 与 [SmartGlassesAccessSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/SmartGlassesAccessSupport.java#L72)。
- 第三形态渲染与悬停命中算法本身未变化，仍复用原有的线段收集和最近点求解；本轮只放宽了显示前置条件，不增加额外几何扫描或集合结构，关键路径在 [QuickLinkOutlineRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/QuickLinkOutlineRenderer.java#L740) 与 [QuickLinkOutlineRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/QuickLinkOutlineRenderer.java#L799)。
- 智能眼镜半透明渲染复用传入的头盔 `HumanoidModel`，只切换为 `RenderType.entityTranslucent(...)` 并传入半透明颜色 `0xB8FFFFFF`；这一层渲染是单次头部模型绘制，开销固定且很低，见 [SmartGlassesArmorRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/SmartGlassesArmorRenderer.java#L26) 与 [SmartGlassesArmorRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/SmartGlassesArmorRenderer.java#L58)。
- 智能节点容器 GUI 的右侧信息区是纯客户端绘制矩形和字符串，没有新增菜单同步字段，也不影响容器 54 槽结构；绘制成本为常数级，见 [SmartNodeContainerScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/SmartNodeContainerScreen.java#L103)。

## 3. 数据流或调用链
- 连线显示链路：玩家穿戴智能眼镜后，`QuickLinkOutlineRenderer.onLast` 允许继续绘制第三形态穿墙线 [QuickLinkOutlineRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/QuickLinkOutlineRenderer.java#L202)；未命中普通近外显目标时，`LinkSerialHudOverlayRenderer` 继续从 `QuickLinkOutlineRenderer.resolveHoveredVisualizedTarget(...)` 读取悬停线目标 HUD [LinkSerialHudOverlayRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/LinkSerialHudOverlayRenderer.java#L295)。
- 连线操作链路：客户端 Attack/Use 回调先通过 `isVisualizeMode` 和 `hasSmartGlassesVisualizationContext` 判断是否允许增删显示对象 [QuickLinkNetworkClientHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/network/QuickLinkNetworkClientHandlerSupport.java#L191)；服务端接包后再由 [QuickLinkNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetworkServerHandlerSupport.java#L147) 复核操作门槛，形成客户端和服务端的双层保护。
- 清空连线链路：`Shift+B` 入口先在客户端判断当前是否满足“可操作第三形态”，满足则清空本地可视化集合 [RedstoneLinkClient.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/RedstoneLinkClient.java#L282)；若主手不空，则继续回到 QLT 原本的缓存清空逻辑。
- 智能眼镜半透明穿戴链路：客户端初始化时注册护甲渲染器 [RedstoneLinkClient.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/RedstoneLinkClient.java#L89)，穿戴到头部时由 [SmartGlassesArmorRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/SmartGlassesArmorRenderer.java#L42) 接管渲染。
- 容器外显与 GUI 链路：物品 `custom_model_data` 仍由容器数据层决定类型状态，模型覆盖走 [smart_node_container.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/assets/redstonelink/models/item/smart_node_container.json#L1)；screen 渲染时，原版箱子底图负责 54 槽与玩家背包，右侧信息区由 [SmartNodeContainerScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/SmartNodeContainerScreen.java#L73) 额外绘制。

## 4. 安全、性能、兼容性、扩展性风险分析与建议
- 安全与权限方面，本轮没有放宽第三形态的“操作”门槛，只是放宽了“显示”门槛；真正会改动显示对象集合的入口仍要求主手空，并且服务端仍复验同一条件 [QuickLinkNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetworkServerHandlerSupport.java#L151)。
- 兼容性方面，本轮没有引入 `com.makomi.api.v1.*` 依赖，也没有改 `triggerSource/core` 语义键名；相关显示和文案只是把现有逻辑拆成“显示/操作”两层，不改变节点方向和持久化结构，判定入口见 [SmartGlassesAccessSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/SmartGlassesAccessSupport.java#L62)。
- 性能方面，半透明护甲渲染会比完全不透明多一次半透明通道绘制，但对象仅限头部一个模型，成本可控；第三形态连线显示仍沿用原有连接线收集与线段最近点算法，没有新增大范围扫描，渲染热点仍在 [QuickLinkOutlineRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/QuickLinkOutlineRenderer.java#L767)。
- 扩展性方面，智能节点容器现在已经把“内层表现”和“类型侧面表现”分离开了；后续若要再加 `top` 独立贴图或更多类型，只需扩展模型纹理位，不必再改 UI 或容器持久化结构。当前侧面/内层接线点见 [smart_node_container_core.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/assets/redstonelink/models/block/smart_node_container_core.json#L3)。
- 已执行验证是全标签自动化：`test testIntegration testClient testSlow --no-daemon` 已通过；尚未覆盖的是游戏内目测半透明观感与容器 GUI 实际交互手感，建议用户再做一轮手工检查。

## 5. 并发冲突审查
- 共享状态方面，本轮没有新增新的全局可变容器；连线显示集合仍复用原来的 `visualizedObjects` 映射 [QuickLinkOutlineRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/QuickLinkOutlineRenderer.java#L113)，只是放宽了显示读取条件，没有新增第二份缓存。
- 读改写覆盖方面，第三形态“显示”和“操作”被显式拆开后，主手非空场景只读不写，反而降低了误清空或误增删的覆盖风险；客户端操作门槛收口在 [QuickLinkNetworkClientHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/network/QuickLinkNetworkClientHandlerSupport.java#L380)。
- 线程边界方面，护甲渲染和 screen 绘制都只发生在客户端渲染/UI 主线程；服务端第三形态查询仍在原有网络主线程/服务器线程链路内执行，没有新增异步任务、锁或跨线程共享状态。风险等级低。
- 建议：后续如果还要让智能眼镜承接更多“只读显示但禁止操作”的可视化能力，应继续沿用“显示条件单独函数 + 操作条件单独函数”的结构，不要再让渲染层和交互层复用同一个布尔开关；当前可复用入口见 [SmartGlassesAccessSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/SmartGlassesAccessSupport.java#L62) 与 [SmartGlassesAccessSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/SmartGlassesAccessSupport.java#L72)。
