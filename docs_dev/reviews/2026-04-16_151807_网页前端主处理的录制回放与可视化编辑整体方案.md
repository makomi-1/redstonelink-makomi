# 网页前端主处理的录制回放与可视化编辑整体方案

## 1. 功能与语义、架构设计（关键方法和入口）

- 当前状态面板已经是“游戏内入口 + 服务端快照回包”的薄壳模型，`录制` 仍停留在占位反馈阶段，因此把“录制配置与起停”留在游戏内 GUI、把“主展示与主处理”转交网页端，和现有入口职责一致，见 [StatePanelNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/StatePanelNetworkServerHandlerSupport.java#L216) 与 [StatePanelNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/StatePanelNetworkServerHandlerSupport.java#L248)。
- 客户端状态面板当前只负责开屏、套快照和显示反馈，没有额外业务真值，因此后续把复杂时间轴、拓扑画布、编辑草稿迁到网页端，不会破坏现有 Screen 边界，见 [StatePanelNetworkClientHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/network/StatePanelNetworkClientHandlerSupport.java#L19)。
- 单节点读模型已经拆成“身份 + 可见连接 + 运行态”，且连接快照带有 `graphRevision/sourceRevision/coreRevision`，适合作为网页导出 DTO 的服务端基线，见 [NodeSnapshotQueryService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/NodeSnapshotQueryService.java#L25) 与 [NodeSnapshotQueryService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/NodeSnapshotQueryService.java#L173)。
- `NodeLinksSnapshot` 已把可见边列表与 revision 基线收敛在同一 DTO 中，这支持后续网页“导出快照”和“显式保存”共用同一版本口径，见 [NodeLinksSnapshot.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/NodeLinksSnapshot.java#L16)。

## 2. 关键数据结构和算法性能分析

- `StatePanelToolData` 当前只把订阅集合持久化到物品 NBT，并做去重与排序；这说明 NBT 非常适合承载轻量入口上下文，但不适合承载大体积录制结果、图快照或前端草稿，见 [StatePanelToolData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/StatePanelToolData.java#L20)。
- `NodeStateTraceService` 已具备“动态挂载 + 立即采一条当前样本 + 有界 ring buffer”的结构，天然适合作为录制会话底座；从复杂度上看，读最近 N 条样本和列出挂载点都维持在可控范围，见 [NodeStateTraceService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/NodeStateTraceService.java#L22) 与 [NodeStateTraceService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/NodeStateTraceService.java#L94)。
- 图编辑保存若继续复用现有结构化写入路径，服务端可在提交前统一做输入长度、目标规模、目标合法性与写控判定，避免网页端直接回传整图覆盖，见 [LinkSetExecutionService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkSetExecutionService.java#L48) 与 [LinkSetExecutionService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkSetExecutionService.java#L241)。

## 3. 数据流或调用链

- 当前状态面板数据流是：主手工具 -> 服务端刷新 -> 服务端组装快照 -> S2C 回包 -> 当前 Screen 应用快照；这条链路本质上已经是“服务端导出读模型 -> 客户端展示”的雏形，后续改为“服务端导出 bundle -> 客户端本地缓存 -> 网页端展示”是自然扩展，见 [StatePanelNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/StatePanelNetworkServerHandlerSupport.java#L248) 与 [StatePanelNetworkClientHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/network/StatePanelNetworkClientHandlerSupport.java#L45)。
- 连接读模型调用链是：`NodeSnapshotQueryService.queryLinks(...)` 读取原始边 -> `CurrentLinksPrivacyService.resolveVisibleLinksSnapshot(...)` 做隐私裁剪 -> `withRevisions(...)` 叠加 revision 基线；这正适合生成网页图快照，见 [NodeSnapshotQueryService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/NodeSnapshotQueryService.java#L41) 与 [CurrentLinksPrivacyService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CurrentLinksPrivacyService.java#L109)。
- 录制与输入播放当前已显式分层：`NodeStateTraceService` 负责样本采集，`InputPlaybackService` 负责输入 job 生命周期，因此本轮方案把“录制结果导出”和“输入播放”拆开是正确的，不会把历史观测回放误写成输入重放，见 [NodeStateTraceService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/NodeStateTraceService.java#L39) 与 [InputPlaybackService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/input/InputPlaybackService.java#L32)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全与隐私：图快照导出必须继续走 `CurrentLinksPrivacyService`，否则网页资产会把本应 masked/hidden 的连接固化下来；建议后续所有网页导出接口都以当前玩家上下文构建 bundle，见 [CurrentLinksPrivacyService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CurrentLinksPrivacyService.java#L144)。
- 一致性与冲突：显式保存模式若不带 revision 基线，会让本地未保存草稿在保存时静默覆盖他人更新；建议继续复用 `LinkOccSupport` 的 `sourceRevision/coreRevision` 判定，不新增另一套网页 OCC 口径，见 [LinkOccSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkOccSupport.java#L20) 与 [LinkOccSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkOccSupport.java#L93)。
- 扩展性：`LinkSetExecutionService` 当前对真实写入方向收口为 `triggerSource -> core`，且目标类型通过语义映射得出；因此第一版网页编辑器坚持“结构化 `n -> m` 编辑，不做自由拉线”是更稳的扩展路线，见 [LinkSetExecutionService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkSetExecutionService.java#L139)。
- 性能：录制结果和大图快照若直接并入 NBT 或世界级 `SavedData`，会把玩家上下文型大对象错误提升成世界真值；建议保持“服务端运行时生成 DTO、客户端本地文件落盘”的分层，不把录制 bundle 和图草稿写回真值层，相关保留问题已补充到 [保留问题.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs_dev/%E4%BF%9D%E7%95%99%E9%97%AE%E9%A2%98.md#L11)。

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- `NodeStateTraceService` 使用 `IdentityHashMap<MinecraftServer, TraceState>` 维护服务端级共享状态，默认依赖主线程 tick 与生命周期回调串行访问；在当前模型下风险等级为“低”，但后续若把网页桥接直接接到异步线程，必须避免跨线程直接读写 trace 状态，见 [NodeStateTraceService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/NodeStateTraceService.java#L22)。
- `InputPlaybackService` 同样以 `IdentityHashMap<MinecraftServer, InputState>` 持有运行态 job，并明确绑定 `END_SERVER_TICK` 与停服回调清理；这说明录制与网页桥接新增缓存时也应遵循“服务器主线程内维护、停服时主动释放”的边界，风险等级为“低”，见 [InputPlaybackService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/input/InputPlaybackService.java#L34)。
- `StatePanelNetworkServerHandlerSupport` 中的 `LAST_REFRESH_TICK_BY_PLAYER` 也是服务端共享状态，但当前只在服务端接包执行路径内读写；若后续录制 GUI 与网页桥都复用类似节流表，仍应保持服务端主线程更新，避免异步 HTTP 线程绕开主线程边界，风险等级为“中低”，见 [StatePanelNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/StatePanelNetworkServerHandlerSupport.java#L31)。
- 真正需要重点防守的并发冲突不是 Java 线程级数据竞争，而是“本地未保存草稿与服务端 revision 漂移”的语义冲突；该风险等级为“中”，建议网页前端保持 `dirty / saving / conflict` 状态机，保存时始终带上基线 revision，并在冲突后保留本地草稿而非静默丢弃，依据见 [LinkOccSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkOccSupport.java#L103) 与 [LinkOccSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkOccSupport.java#L123)。
