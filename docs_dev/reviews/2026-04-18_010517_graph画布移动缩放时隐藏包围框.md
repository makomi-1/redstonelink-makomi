# graph画布移动缩放时隐藏包围框

这一实现没有新增新的状态分叉，而是继续使用现有挂起深度计数统一处理“节点拖拽 / 选中组拖拽 / 画布移动 / 画布缩放”四类高频交互，职责边界仍然清晰：包围框只在静止态展示，高频视口操作期间暂时退出热路径。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1595) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2101)

## 2. 关键数据结构和算法性能分析

本轮没有新增复杂数据结构，仍沿用 `aggregateOutlineSuspended` 和 `aggregateOutlineSuspendDepthRef` 两个状态/引用控制包围框是否并入 `displayNodes`。因此实现成本极低，且不会改变 graph 主数据、布局或选区算法。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1588) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1595)

性能收益来自于把画布平移和缩放也纳入“交互期间不渲染包围框”的策略，进一步减少视口变换时大面积装饰节点的重绘机会。由于只是事件接线，没有引入额外遍历或布局计算，时间复杂度基本不变。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2091) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2740)

## 3. 数据流或调用链

修复后的调用链是：ReactFlow 在节点拖拽、选中组拖拽、视口平移或缩放开始时，统一调用 `suspendAggregateOutlineRendering`，把包围框从 `displayNodes` 中临时移除；当对应交互结束时，再通过 `resumeAggregateOutlineRendering` 成对恢复显示。这样所有高频交互都复用同一条装饰层挂起链路。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2091) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2101) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2736)

因为包围框展示链路没有再区分“拖拽专用”和“移动缩放专用”，后续维护时只需要验证这一套挂起深度计数是否仍与 ReactFlow 事件顺序保持一致即可。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1595) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2740)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

安全与语义层面，本轮没有新增 API 依赖，没有改持久化结构，没有改 `triggerSource -> core` 的真实保存边界，符合项目当前语义约束。风险仍主要集中在 ReactFlow 的事件时序：当前实现依赖 `onMoveStart / onMoveEnd` 与其他拖拽结束事件成对触发，因此未来升级 ReactFlow 时，应优先回归这类视口交互时的包围框恢复时机。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2091) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2101) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2740)

扩展性上，这种“所有高频交互统一挂起装饰层”的策略可以继续复用到未来新增的背景板、辅助标签、分组阴影等纯展示层元素，避免它们重新回到视口交互热路径。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2091)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

前端仍处于 React 单线程事件循环，没有新增跨线程共享状态。本轮主要关注的是多类交互事件可能重叠触发时，包围框是否会被过早恢复。当前仍由 `aggregateOutlineSuspendDepthRef` 统一计数，因此节点拖拽与视口移动事件即便相邻或重叠，也不会因为单个结束事件先到而把包围框过早放回画布，风险等级维持低。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1595) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2091) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2101)

后续如果再接入其他高频视口事件，建议继续复用这套深度计数，而不是为每种交互单独建立布尔开关，否则很容易在恢复时机上产生新的覆盖冲突。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1595)
