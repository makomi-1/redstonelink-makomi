# Graph 交互布局与类型搜索优化

## 1. 功能与语义、架构设计（关键方法和入口）

- 本轮把搜索维度从“仅自由文本”扩成了“文本 + 类型筛选”，新增 `GraphSearchTypeFilter`、类型标签格式化和结果文案生成函数，使 `triggerSource/core` 能在重复序号场景下被显式区分 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L52) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L127) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1836)。
- `清空临时显示` 的残留问题改成“只回收仅依赖临时显示集合保活的选中孤立节点”，避免一刀切清空所有选中态，同时修复临时拉回节点被选中态顶住的问题 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1366) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1744)。
- 自动布局从分量级全局双列提升为“多列 lane + 按来源锚点排序”的组件布局：`triggerSource` 与 `core/summary` 仍然保持左右语义分层，但同层内部可分多列展开，更贴近用户要的“横向利用率”和“有序展开” [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L559) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L625) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L698)。

## 2. 关键数据结构和算法性能分析

- 布局核心新增 `resolveLaneRowCount(...)` 和 `buildLaneLayout(...)`，把单条长 lane 切成多列网格，时间复杂度仍为线性 `O(N)`，只是把节点位置从单列映射改为“列索引 + 行索引”映射 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L562) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L578)。
- `buildComponentLayout(...)` 通过 `connectedSourceOrdersByNodeKey` 给 `core/summary` 节点打上来源锚点顺序，再按平均顺序和最小顺序排序，使展开出来的目标节点围绕关联来源节点附近排布，而不是纯按序号堆成一列 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L632) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L645)。
- 搜索匹配仍然是对节点字段做包含判断，只是在 `matchedNodes` 的派生前多加了一层 `matchesSearchType(...)`，不会引入更重的索引或额外持久化结构 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L138) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1320)。

## 3. 数据流或调用链

- 搜索数据流现在是 `searchText + searchTypeFilter -> matchedNodes -> matchedNodeKeys -> forcedVisibleNodeKeys -> graphCanvasView`，因此只有同时满足文本命中和类型条件的节点才会进入搜索强制显示链路 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1287) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1320) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1390)。
- 临时显示清空链路现在会先判断当前选中节点是否还有其他可见性来源，再决定是否回收选中态，避免“pinned 清空了但 selected 继续顶住”的链路残留 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1366) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1744)。
- 布局链路仍保持 `graphCanvasView -> autoLayoutPositions -> ReactFlow`，但 `buildAutoLayoutPositions(...)` 现在会把每个连通分量的边一并带入 `buildComponentLayout(...)`，从而在布局阶段利用来源锚点信息做局部有序展开 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L698)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 本轮仍只改前端视图层与样式，不改 snapshot、draft、服务端真值，也没有引入 `com.makomi.api.v1.*` 依赖；真实保存方向仍然保持 `triggerSource -> core`，语义边界未变化 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1320) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1744)。
- 布局改造提升了横向利用率，但也会让大分量在宽度上扩得更开；当前通过 `AUTO_LAYOUT_MAX_ROW_WIDTH` 和 lane 行数上限做了约束，残余风险是极端大图下仍需用户依赖 `fitView` 和缩放操作 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L33) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L562)。
- 搜索筛选控件和结果样式已在现有工具栏视觉体系下落位，没有额外引入新组件体系；如果后续再增加频道、在线状态之类的高级过滤，建议继续沿用同一组 chip 交互，不要把过滤入口分散到多个区域 [app.css](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L698) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1836)。

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- 本轮新增的 `searchTypeFilter`、`selectedNodeHasNonPinnedVisibilityReason` 仍然都是 React 组件内状态或派生值，没有引入跨组件共享状态，线程边界继续维持在单线程渲染语义内，风险低 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1287) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1366)。
- `handleClearPinnedIsolatedNodes(...)` 先判断、再同步回收 `selectedNodeKey` 与 `pendingFocusNodeKey`，避免清空后仍对一个即将不可见的节点继续居中或保活，降低了交互重入时的残留状态风险 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1744)。
- 自动布局仍然统一从 `graphCanvasView` 派生位置，不存在“搜索态用一套位置、展开态用另一套位置”的并发写入路径；当前剩余风险主要是用户在拖拽后立即点击重新布局时的视觉跳转，而不是共享状态冲突，风险等级低 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L698) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1865)。
