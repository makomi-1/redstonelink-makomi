## 1. 功能与语义、架构设计

- 本轮实现的核心不是改业务派发语义，而是给 bench 增加一个可复用的 `occ_channel_partition` setup phase，用来把一组 `triggerSource/core` 节点按固定分块批量切到频道模式，并保持 `triggerSource -> core` 的方向隔离；入口在 [Bench.FunctionalTrace.Phases.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.Phases.ps1#L554) 与分发表注册 [Bench.FunctionalTrace.Phases.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.Phases.ps1#L1854) [Bench.FunctionalTrace.Phases.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.Phases.ps1#L1869)。

## 2. 关键数据结构和算法性能分析

- `occ_channel_partition` 的分块算法是按 serial 有序列表做一次线性扫描，频道号通过 `channelBase + floor(index / partitionSize)` 计算得到，时间复杂度 `O(n)`、额外状态常数级；实现见 [Bench.FunctionalTrace.Phases.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.Phases.ps1#L635)。
- 对本 case 而言，`n=1024`，`partitionSize=16`，因此稳定得到 `64` 个频道，每个频道 `16 triggerSource + 16 core`，最终展开为 `64 * 16 * 16 = 16384` 条边，和 `P18 banded16` 等价；频道分块定义见 [sync_1024_to_1024_core_channel_banded16_equivalent.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/performance/p27/sync_1024_to_1024_core_channel_banded16_equivalent.json#L33) [sync_1024_to_1024_core_channel_banded16_equivalent.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/performance/p27/sync_1024_to_1024_core_channel_banded16_equivalent.json#L44)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 兼容性边界：当前 `occ_channel_partition` 默认 `expectedRevision=0`，适用于 fresh world 或已知 OCC 基线；如果未来把它拿去复用到复跑世界，revision 漂移会直接导致命令拒绝，需要在 case 上显式覆写 revision，而不是隐式放宽检查。校验点见 [Bench.FunctionalTrace.Phases.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.Phases.ps1#L594) [sync_1024_to_1024_core_channel_banded16_equivalent.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/performance/p27/sync_1024_to_1024_core_channel_banded16_equivalent.json#L39)。
- 语义风险：这个对比成立依赖“serial 顺序稳定且两侧按同样的 16 分块”，因此它证明的是“等边集下频道模式的分发优化收益”，不是任意频道拓扑都优于序号模式；如果未来 serial 分配策略变化，`P27` 需要同步复核。当前分块依赖点见 [Bench.FunctionalTrace.Phases.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.Phases.ps1#L578) [Bench.FunctionalTrace.Phases.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.Phases.ps1#L635)。
- 性能口径：本 suite 固定 `batchWindowTicks=0`，因此结论针对“关闭额外窗口延迟、保留频道模式中间层优化”的场景；它不覆盖 `batchWindowTicks > 0` 或频道 setup 成本，也不直接外推到 mixed/pulse/toggle。口径固定点见 [performance-channel-vs-serial-1024.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/suites/performance-channel-vs-serial-1024.json#L9)。
- 安全与扩展性：本轮没有引入 API 依赖，也没有写入生产持久化结构，只新增 bench 脚本与测试 case，风险集中在测试编排层；后续若要扩到更多频道拓扑，建议继续复用 `occ_channel_partition`，避免复制黏贴多份 OCC 提交逻辑。新增入口见 [Bench.FunctionalTrace.Phases.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.Phases.ps1#L554)。

## 5. 并发冲突审查

- 共享状态面：`occ_channel_partition` 内部只操作局部变量，并通过串行 RCON 命令逐个提交 OCC pairing，没有在脚本层引入新的并发容器或后台任务；对应实现见 [Bench.FunctionalTrace.Phases.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.Phases.ps1#L633) [Bench.FunctionalTrace.Phases.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.Phases.ps1#L646)。
- 读改写覆盖风险：频道提交本质是对节点配置做写入，如果同一世界里并行跑多个 suite/case 或外部手工修改相同 serial，仍可能触发 revision 冲突；但这属于 OCC 预期保护，不是新增 race。revision 约束与命令断言见 [Bench.FunctionalTrace.Phases.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.Phases.ps1#L594) [Bench.FunctionalTrace.Phases.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.Phases.ps1#L658)。
- 线程边界：本轮新增内容运行在 bench 编排线程与 dedicated server 命令边界上，没有修改 Java 侧派发线程模型；因此并发风险等级评估为“低”，主要残余风险仍是“复用旧档时 revision 不匹配”与“serial 顺序变化导致等价拓扑失配”，不是线程安全缺陷。case/suite 绑定位置见 [sync_1024_to_1024_core_channel_banded16_equivalent.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/performance/p27/sync_1024_to_1024_core_channel_banded16_equivalent.json#L31) [performance-channel-vs-serial-1024.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/suites/performance-channel-vs-serial-1024.json#L12)。
