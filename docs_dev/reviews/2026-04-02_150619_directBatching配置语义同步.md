# directBatching配置语义同步

- 配置解析保持“读旧写新”：解析器优先读取 `crosschunk.directBatching`，缺失时回退 `crosschunk.directSyncBatching`；值解析同时兼容新值 `all_direct` 和旧值 `all_sync`，因此旧配置文件无需立即迁移也能保持原行为。[RedstoneLinkCrossChunkConfigParser.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/config/RedstoneLinkCrossChunkConfigParser.java#L23) [RedstoneLinkCrossChunkConfigParser.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/config/RedstoneLinkCrossChunkConfigParser.java#L51) [RedstoneLinkConfig.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/config/RedstoneLinkConfig.java#L120)
- 业务调用点也已跟名，不再从配置快照读取旧 accessor；`InternalDispatchDeltaProjector` 与 `LinkedTargetDispatchService` 统一使用 `directBatchingMode()`，运行时行为边界不变，仍由 `off / queued_only / all_direct` 控制 loaded direct 链路是否进入目标级 batch。[InternalDispatchDeltaProjector.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/InternalDispatchDeltaProjector.java#L123) [InternalDispatchDeltaProjector.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/InternalDispatchDeltaProjector.java#L149) [LinkedTargetDispatchService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkedTargetDispatchService.java#L167) [LinkedTargetDispatchService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkedTargetDispatchService.java#L518)

## 2. 关键数据结构和算法性能分析
- 这轮改动不引入新的运行时聚合结构，核心变化集中在配置解析层与枚举分支：`fromConfigValue(...)` 只是把值别名从 `all_sync` 扩展到 `all_direct`，仍为常量级字符串匹配，运行时成本可忽略。[RedstoneLinkConfig.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/config/RedstoneLinkConfig.java#L120)
- 解析器的兼容策略是单次“新键优先、旧键回退”读取，不会形成多轮扫描或额外映射表；其复杂度和原先直接 `getProperty(...)` 基本等价，同时把兼容逻辑集中在解析入口，避免业务层分散判断旧键名。[RedstoneLinkCrossChunkConfigParser.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/config/RedstoneLinkCrossChunkConfigParser.java#L23) [RedstoneLinkCrossChunkConfigParser.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/config/RedstoneLinkCrossChunkConfigParser.java#L51)
- 默认配置模板与运行示例配置都已写出新键 `crosschunk.directBatching=all_direct`，从后续新生成配置开始不会继续扩散旧键名；这降低了长期配置噪声和排障时的语义误判成本。[RedstoneLinkConfigTemplate.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/config/RedstoneLinkConfigTemplate.java#L285) [redstonelink-server.properties](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/run/config/redstonelink-server.properties#L271)

- 配置读取链现在是：`RedstoneLinkCrossChunkConfigParser.parse(...)` 先解析 `directBatchingRaw`，再交给 `CrossChunkDirectBatchingMode.fromConfigValue(...)` 归一化，最终写入 `RedstoneLinkCrossChunkConfig.directBatchingMode()`，供业务层读取。[RedstoneLinkCrossChunkConfigParser.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/config/RedstoneLinkCrossChunkConfigParser.java#L23) [RedstoneLinkCrossChunkConfigParser.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/config/RedstoneLinkCrossChunkConfigParser.java#L51) [RedstoneLinkCrossChunkConfig.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/config/RedstoneLinkCrossChunkConfig.java#L19)
- loaded direct 派发链继续通过 `InternalDispatchDeltaProjector.shouldBatchLoadedDelta(...)` 与 `LinkedTargetDispatchService.shouldBatchLoadedDispatch(...)` 判定，只是它们读取的配置 accessor 已切换到 `directBatchingMode()`；因此 direct `sync/toggle/pulse` 的 batching 行为不会因为这轮改名发生语义漂移。[InternalDispatchDeltaProjector.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/InternalDispatchDeltaProjector.java#L149) [LinkedTargetDispatchService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkedTargetDispatchService.java#L518)
- 用户侧输出链也已经统一：当前示例配置写新键，使用说明把配置说明、默认值和推荐组合全部改成 `crosschunk.directBatching=all_direct`，同时明确标注旧键旧值仅做兼容读取。[redstonelink-server.properties](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/run/config/redstonelink-server.properties#L274) [使用说明.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs_dev/使用说明.md#L1143) [使用说明.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs_dev/使用说明.md#L1174)

## 4. 安全、性能、兼容性、扩展性风险分析与建议
- 兼容性风险已被压到最小：配置解析测试显式覆盖了“新键优先”和“旧键旧值回退”两条路径，确保旧配置不会因为本轮重命名直接失效。[RedstoneLinkConfigInteractionAndCrossChunkParseTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/config/RedstoneLinkConfigInteractionAndCrossChunkParseTest.java#L232)
- 行为回归风险主要在 direct batching gate；本轮同时保留了 projector 和 dispatch service 的行为测试，并把枚举与常量切换到新命名，回归证明 `queued_only / off / all_direct` 三档逻辑没有漂移。[InternalDispatchDeltaProjectorTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/data/InternalDispatchDeltaProjectorTest.java#L60) [LinkedTargetDispatchServiceTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/data/LinkedTargetDispatchServiceTest.java#L145)
- 残余风险在历史资料层：旧计划文档、旧 bench case 名称和旧审查文档仍可能保留 `directSyncBatching` / `all_sync` 字样。本轮按“只读历史、不重写历史”处理，当前有效配置与使用说明已对齐；若后续需要进一步清理认知负担，可单独做一次历史文档检索与迁移，但不建议混入本轮配置改造范围。

### 并发冲突审查（补充）
- 审查结论：当前提交未引入新的独立工作线程，主要仍依赖服务端主线程串行执行；并发风险重点在多入口读改写导致的后写覆盖前写，而非 JVM 级数据竞争。
- 审查范围：共享可变状态访问、批量写入原子性、事件发布链路重入风险、网络入口主线程切换边界。
- 风险等级：默认低到中；若后续把同一节点写入扩展到异步线程或跨入口并行提交，风险会升至中到高。
- 建议：新增写入口时优先补 sourceRevision/expectedRevision 乐观并发校验，并在事件分发前使用快照副本以避免可变集合外泄。
