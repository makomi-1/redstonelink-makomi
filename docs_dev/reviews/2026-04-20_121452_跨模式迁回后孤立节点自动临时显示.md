## 1. 功能与语义、架构设计（关键方法和入口）

## 2. 关键数据结构和算法性能分析

核心算法发生在 `resolveAutoPinnedCrossModeSerialNodeKeys`。它先对“应用后的草稿快照”构建下一态图，再基于 `Map<nodeKey, node>` 与 `edgeCountByNodeKey` 做一次筛选，因此整体复杂度主要是“构造下一态图 + 建边数量索引 + 按迁移节点数过滤”。这类计算只在用户点击“应用到草稿”的瞬间执行，不在每次渲染热路径中重复触发，符合当前交互频率下的性能预期。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L129)

临时显示集合的合并使用 `mergeUniqueSortedStrings`，通过 `Set` 去重后统一排序，保证 `pinnedIsolatedNodeKeys` 的稳定性与可比较性，避免因数组顺序抖动导致额外回流。这里的开销与本次新增节点数线性相关，并附带一次排序，规模远小于整图布局本身。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L116) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2050)

## 3. 数据流或调用链

## 4. 安全、性能、兼容性、扩展性风险分析与建议

安全层面，本次改动完全位于前端本地草稿视图，不触及服务端写入协议、权限口径或存档格式，风险低。兼容性层面也未改变 `serial/channel` 的真实存储语义，只是补齐了序号模式主画布对“新迁回但无边节点”的可见性处理，因此不会影响已有保存链路。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2002)

当前残余风险在于：自动并入的孤立节点会沿用手动 pin 的生命周期，只有在整图重置或用户主动清空临时显示时才回收，不会在一次跨模式操作结束后自动释放。这符合“最小改动、复用现有语义”的策略，但如果用户连续做多轮跨模式迁回，临时显示集合可能逐步累积。若后续需要进一步收敛显示范围，可以在不破坏现有接口的前提下，为 auto-pinned 节点补一层来源标签或一次性回收策略。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L907) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1922)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

本次共享状态主要是 `pinnedIsolatedNodeKeys`、编辑选区与布局刷新相关的 React state。实现中使用了函数式 `setPinnedIsolatedNodeKeys((currentValues) => ...)` 合并新旧节点键，避免了在 React 批量更新或同一事件回合内出现“后写覆盖前写”的典型读改写冲突；`requestStructureLayoutRefresh` 只负责设置待处理标记，不直接依赖同步布局结果，因此重入风险较低。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2050) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1402)
