# 近外显服务端节流与网络解包限长

## 1. 功能与语义、架构设计（关键方法和入口）

- 本轮继续完成第 12 项 `P2`：一是给 `Pairing` 近外显查询增加服务端节流，防止恶意客户端绕过本地轮询间隔后持续打服务端；二是给 `QuickLink/StatePanel` 的 payload 解包补显式长度上限，把超长字符串挡在 codec 层。关键入口见 [PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L99)、[QuickLinkNetworkPayloadSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetworkPayloadSupport.java#L25)、[StatePanelNetworkPayloadSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/StatePanelNetworkPayloadSupport.java#L52)。
- 近外显服务端节流被收口在 `PairingNetworkServerHandlerSupport`，只影响 `RequestCurrentLinksPayload` 和 `RequestRuntimeHudSnapshotPayload` 的读请求链路，不改写权限、定位校验与回包结构；客户端仍按原有懒请求逻辑发包，见 [LinkSerialHudOverlaySnapshotSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/LinkSerialHudOverlaySnapshotSupport.java#L207) 与 [LinkSerialHudOverlaySnapshotSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/LinkSerialHudOverlaySnapshotSupport.java#L226)。
- `QuickLink` 和 `StatePanel` 的 payload 契约本身未改字段语义，只是在 encode/decode 两端明确了 token、维度键、表达式、反馈键和反馈参数的长度上限，避免继续依赖业务层后置校验，见 [QuickLinkNetwork.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetwork.java#L63) 与 [StatePanelNetwork.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/StatePanelNetwork.java#L69)。
- 语义对齐说明：本轮没有新增写入方向，也没有引入旧术语；`triggerSource/core` 映射与方向语义保持不变，影响范围仅限网络边界保护，残余风险为 `core` 配对旧兼容链路仍未完全收口。

## 2. 关键数据结构和算法性能分析

- 近外显节流使用两个 `Map<UUID, Long>` 分别记录“当前连接查询”和“最终 IO 查询”的上次处理 tick，并用固定 `5 tick` 最小间隔做判定，单次判断与更新复杂度为 `O(1)`，实现见 [PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L29) 与 [PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L228)。
- 为避免把节流表本身做成新的积累点，服务端在固定清理周期内删除长期未触达的玩家 UUID 记录，这比 `StatePanel` 现有的“只增不清”节流表更稳，见 [PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L258)。
- `QuickLink/StatePanel` 的 codec 限长仍是线性顺序解包，但通过 `readUtf(max)` 把最大输入直接压到常量或配置上限，避免超长字符串继续流入业务层，关键点见 [QuickLinkNetworkPayloadSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetworkPayloadSupport.java#L66) 与 [StatePanelNetworkPayloadSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/StatePanelNetworkPayloadSupport.java#L60)。
- 纯逻辑与契约测试已覆盖节流窗口判定、超长表达式拒绝和超长维度键/反馈键拒绝，能直接约束这次 `P2` 防护不被后续回退，见 [PairingNetworkServerHandlerSupportTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/network/PairingNetworkServerHandlerSupportTest.java#L18)、[QuickLinkNetworkPayloadTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/network/QuickLinkNetworkPayloadTest.java#L109)、[StatePanelNetworkPayloadTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/network/StatePanelNetworkPayloadTest.java#L114)。

## 3. 数据流或调用链

- 近外显读取链现在是：客户端懒请求命中节点后发送 `RequestCurrentLinksPayload / RequestRuntimeHudSnapshotPayload`，服务端先做权限判定，再做服务端节流，随后继续走已有的节点定位校验与快照查询，见 [LinkSerialHudOverlaySnapshotSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/LinkSerialHudOverlaySnapshotSupport.java#L214)、[LinkSerialHudOverlaySnapshotSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/LinkSerialHudOverlaySnapshotSupport.java#L233)、[PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L99)、[PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L134)。
- `QuickLink` 解包链现在在 `Open/Save/Collect/Apply/Feedback` 五类 payload 上都显式限制了字符串长度，因此恶意上行或异常回执会在 codec 层直接失败，而不会继续进入 `QuickLinkCollectService/QuickLinkApplyService`，见 [QuickLinkNetworkPayloadSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetworkPayloadSupport.java#L25)、[QuickLinkNetworkPayloadSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetworkPayloadSupport.java#L95)、[QuickLinkNetworkPayloadSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetworkPayloadSupport.java#L120)。
- `StatePanel` 解包链同样把订阅表达式、节点类型 token、快照节点类型和反馈键/参数上限前移到 codec 层，服务端业务入口只处理已经通过基础长度门禁的 payload，见 [StatePanelNetworkPayloadSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/StatePanelNetworkPayloadSupport.java#L52)、[StatePanelNetworkPayloadSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/StatePanelNetworkPayloadSupport.java#L104)、[StatePanelNetworkPayloadSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/StatePanelNetworkPayloadSupport.java#L152)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全收益：近外显现在不再完全依赖客户端自律节流；即使客户端绕过本地 250ms 轮询，也会被服务端按玩家限速拦住一层。对应实现见 [PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L207)。
- 安全收益：`QuickLink/StatePanel` 的字符串输入不再默认接受“任意长度再后置校验”，这能减少超长 payload 在解包链路上的内存与异常面，见 [QuickLinkNetworkPayloadSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetworkPayloadSupport.java#L134) 与 [StatePanelNetworkPayloadSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/StatePanelNetworkPayloadSupport.java#L166)。
- 兼容性风险：本轮没有新增 payload 字段，也没有改协议 id；但是因为 encode/decode 都切成了带上限版本，client/server 仍必须使用同一构建版本，避免一端继续按旧无上限实现解包。影响入口见 [QuickLinkNetwork.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetwork.java#L63) 与 [StatePanelNetwork.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/StatePanelNetwork.java#L206)。
- 残余风险：近外显服务端节流当前是固定常量、按玩家全局维度做最小间隔保护，还没有做到“按目标或按会话粒度配置化”；这已经收口了 `P2` 风险，但仍为后续可优化点。另一个残余风险是 `core` 配对旧兼容语义仍在本轮之外。

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- 近外显节流表只在服务端主线程的网络 handler 内读写，且请求在注册层已切回 `player.server.execute(...)`，因此 `Map<UUID, Long>` 不会跨线程并发访问，见 [PairingNetworkRegistrationSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkRegistrationSupport.java#L70) 与 [PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L228)。
- codec 限长改动都是无状态纯函数，没有引入新的静态缓存、引用逃逸或共享集合，线程风险等级低，见 [QuickLinkNetworkPayloadSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetworkPayloadSupport.java#L14) 与 [StatePanelNetworkPayloadSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/StatePanelNetworkPayloadSupport.java#L14)。
- 这次新增的测试也都只验证纯逻辑窗口判定和 codec 异常，不依赖真实并发环境，因此不会引入测试侧共享状态污染，见 [PairingNetworkServerHandlerSupportTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/network/PairingNetworkServerHandlerSupportTest.java#L18)、[QuickLinkNetworkPayloadTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/network/QuickLinkNetworkPayloadTest.java#L124)、[StatePanelNetworkPayloadTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/network/StatePanelNetworkPayloadTest.java#L127)。
