## 3. 数据流或调用链
- 调用链保持为：源侧 dispatch 生成 `EventMeta(timeKey=eventTick)` -> batch scheduler 按 `dueTick = enqueueTick + windowTicks` 延迟 flush -> target 端按原始 `eventMeta.timeKey` 做仲裁；本次只修正 pulse 回落后 `NONE` 态的 fallback 边界，不改前半段数据流。[LinkedTargetDispatchService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkedTargetDispatchService.java#L166) [CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L269)
- 当 pulse 到期时，`onPulseTick()` 会重算 pulse/toggle 真值，再用新的 fallback 时间键重算 authority；后续若 delayed pulse 仍处于窗口内，会继续进入正常 `acceptByPriority` 与 pulse 桶写入路径，而不会被当前 tick 的空窗边界提前拦截。[ActivatableTargetBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/ActivatableTargetBlockEntity.java#L418) [ActivatableTargetBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/ActivatableTargetBlockEntity.java#L421)
- 测试侧通过反射直接读取 fallback 时间键，并复用 `expirePulseWindow(...)` 模拟 pulse 回落重算，验证了修复后的 authority 边界确实与窗口值对齐。[ActivatableTargetBlockEntityInternalTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/block/entity/ActivatableTargetBlockEntityInternalTest.java#L406) [ActivatableTargetBlockEntityInternalTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/block/entity/ActivatableTargetBlockEntityInternalTest.java#L703)

## 4. 安全、性能、兼容性、扩展性风险分析与建议
- 安全性：本次没有放宽到“保留上一次真实 authority”，而是只放宽到 `now - windowTicks`，因此窗口外旧事件仍会被拒绝，stale guard 仍保留明确上界。[ActivatableTargetBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/ActivatableTargetBlockEntity.java#L438) [ActivatableTargetBlockEntityInternalTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/block/entity/ActivatableTargetBlockEntityInternalTest.java#L419)
- 兼容性：`window=0` 下 fallback 仍等于当前 tick，旧行为不变；`window=1/2` 只恢复窗口内合法 delayed pulse，不改 `triggerSource/core` 语义与事件时间键模型。[ActivatableTargetBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/ActivatableTargetBlockEntity.java#L445) [CoreDispatchBatchScheduler.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CoreDispatchBatchScheduler.java#L266)
- 扩展性：如果后续需要支持大于 2 的 batch window 或 slot 级时间粒度，建议继续沿用“源事件时间键不变、NONE 边界按允许迟到窗口回退”的模式，而不是把 batched event 的时间键整体改成 `dueTick`，这样更容易维持仲裁语义稳定。[ActivatableTargetBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/ActivatableTargetBlockEntity.java#L437) [LinkedTargetDispatchService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkedTargetDispatchService.java#L166)

### 并发冲突审查（补充）
- 审查结论：当前提交未引入新的独立工作线程，主要仍依赖服务端主线程串行执行；并发风险重点在多入口读改写导致的后写覆盖前写，而非 JVM 级数据竞争。
- 审查范围：共享可变状态访问、批量写入原子性、事件发布链路重入风险、网络入口主线程切换边界。
- 风险等级：默认低到中；若后续把同一节点写入扩展到异步线程或跨入口并行提交，风险会升至中到高。
- 建议：新增写入口时优先补 sourceRevision/expectedRevision 乐观并发校验，并在事件分发前使用快照副本以避免可变集合外泄。
