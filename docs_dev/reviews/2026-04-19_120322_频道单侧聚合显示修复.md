# 频道单侧聚合显示修复

## 1. 功能与语义、架构设计（关键方法和入口）

本轮修复落在频道模式画布构建入口 `buildChannelGraphCanvasView(...)`。改动前，频道 `core aggregate` 和 `triggerSource aggregate` 都要求“对侧至少存在 1 个成员”才生成；改动后，两类聚合块都只按“本侧成员数是否达到门槛”决定是否出现，因此频道里即使只有 `core` 或只有 `triggerSource`，也能通过 `channelHub` 显示对应聚合块。[canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L961) [canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L1068) [canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L1114)

撤回机制这轮没有改代码，但现状可以明确：本地草稿变更统一经由 `applyLocalDraftChange(...)` 进入；这里只在草稿真实变化时，把“变更前整份 `graphDraft`”写入 `undoableGraphDraft`，并没有记录操作栈。执行撤回时，`handleUndoDraft()` 直接恢复这份旧草稿后清空单槽，因此它本质上是“一级草稿快照撤回”，不是多级命令式 undo/redo。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1390) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1423)

## 2. 关键数据结构和算法性能分析

频道聚合的性能模型没有变化，仍然是按频道桶遍历成员、构造 `channelHub`，再在每个频道上派生两类聚合块。此次只是放宽生成条件，没有新增额外遍历层级，整体复杂度仍受频道成员数线性控制。[canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L961)

一步撤回的数据结构是单个 `GraphDraft | null` 状态槽，而不是数组或双栈。它的优点是实现简单、恢复成本低；代价是只能回退最近一次本地草稿变化，且后一次变更会覆盖前一次撤回快照。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L176) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1394)

## 3. 数据流或调用链

频道视图的数据流仍然是“频道成员节点 -> `channelHub` -> 频道两类聚合块 -> 可见性收敛 -> 画布节点/边”。本轮改动只影响中间的“频道两类聚合块”生成条件，不影响 `channelHub` 本身，也不影响后续展开/收起和布局边补充链路。[canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L990) [canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L1185)

撤回链路是：别名编辑、批量拓扑编辑、频道覆盖编辑都先生成 `nextDraft`，再统一走 `applyLocalDraftChange(...)`；撤回按钮触发 `handleUndoDraft()` 后直接恢复上一个 `GraphDraft`。切换图、重新加载 draft、保存成功时会清空撤回槽，保证它只服务当前未保存的本地草稿上下文。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L680) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1390) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1423) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1723)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

安全与真值语义风险低。本轮没有触碰服务端保存、预检、OCC、限流或 `triggerSource -> core` 真值结构，只改前端频道模式的聚合显示门槛，因此不会影响真实连接写入方向与服务端真值一致性。[canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L961)

兼容性上的主要变化是：某些原先在频道模式下显示为多个离散实际节点的“单侧频道”，现在会折叠成一个聚合块。这是修复目标本身，但如果后续用户希望“单侧频道不折叠、双侧频道才折叠”，就需要再引入频道模式专属阈值，而不是继续复用序号模式常量。

扩展性上，现有撤回机制适合“单步补救”，不适合复杂的连续编辑会话。如果未来要做多级撤回，建议把 `undoableGraphDraft` 升级为草稿快照栈，或记录标准化 `GraphWriteOperation` 差异栈；当前实现不具备这种能力。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L176) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1394)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

频道单侧聚合修复只作用于纯函数 `buildChannelGraphCanvasView(...)`，没有新增共享可变状态，线程边界风险极低。该函数仍由 React 渲染阶段纯计算调用，输入固定、输出稳定，不存在并发读写覆盖问题。[canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L961)

撤回相关共享状态主要是 `graphDraft` 与 `undoableGraphDraft` 两个 React state。当前风险等级为“低到中”：不会出现跨线程问题，但存在“新草稿覆盖旧撤回槽”的预期内覆盖行为，所以用户连续改多次后只能回到最近一个快照，而不能逐步回退更早历史。这是当前设计边界，不是实现 bug。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L176) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1390) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1423)
