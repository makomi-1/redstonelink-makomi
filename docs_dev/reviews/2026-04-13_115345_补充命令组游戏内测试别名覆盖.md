## 2. 关键数据结构和算法性能分析
- 本轮主要改动仍然是 bench phase 数组的线性扩展，没有引入新的递归、嵌套遍历或高阶组合结构；`C08` 从少量 phase 扩展为 23 个检查点，运行成本仍与 phase 数线性相关，且仅发生在 dedicated bench 测试阶段，不影响游戏运行时路径。[server_permission_rate_limit_basic.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/c08/server_permission_rate_limit_basic.json#L31)
- `Test-BenchResponseLooksLikeFailure` 与 `Test-FunctionalCommandAssertHardFailure` 只是各自追加了少量正则模式，复杂度仍是“响应文本长度 × 常数级模式数”；相较于网络 I/O、世界复制和服务端启动耗时，这部分增量可忽略。[Bench.Rcon.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.Rcon.ps1#L119) [Bench.FunctionalTrace.Common.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.Common.ps1#L463)
- suite 覆盖项只调整了几个标量配置键，不新增持久化结构，也不会改变业务数据布局；它的性能影响仅体现在 `C08` 所在的独立测试世界里。[server-basic-permission.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/suites/server-basic-permission.json#L29)

## 3. 数据流或调用链
- `C08` 的 dedicated 验证链路是：suite entry 提供 `serverConfigOverrides` -> `BenchSuite.EntryPoint` 把覆盖项写入 `redstonelink-server.properties` -> 载入 `server_permission_rate_limit_basic` case -> `command_assert` phase 走 failure classifier 判定是否满足 `expectFailureResponse`。其中 suite 覆盖是权限/限流场景成立的前置条件，不能被 direct `CaseIds + matrix` 路径替代。[server-basic-permission.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/suites/server-basic-permission.json#L27) [BenchSuite.EntryPoint.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/BenchSuite.EntryPoint.ps1#L175) [BenchSuite.EntryPoint.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/BenchSuite.EntryPoint.ps1#L223)
- `command_assert` 的结果判定先读取规范化后的响应，再调用 `Test-FunctionalCommandAssertHardFailure`；后者又会优先委托给 `Test-BenchResponseLooksLikeFailure`。这意味着别名失败文案若不在模式表中，`expectFailureResponse=true` 就会落成 `expected_failure_missing`，本轮正是沿着这条链路补齐了识别规则。[Bench.FunctionalTrace.Phases.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.Phases.ps1#L687) [Bench.FunctionalTrace.Common.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.Common.ps1#L458) [Bench.Rcon.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.Rcon.ps1#L119)
- `C02/C06/C08` 三个 case 的职责也已经分层清楚：`C02` 负责别名读链路，`C06` 负责别名边界拒绝，`C08` 负责 alias 查询在权限限流环境中的行为，不互相混叠。[node_query_retire_audit_basic.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/c02/node_query_retire_audit_basic.json#L70) [command_boundary_matrix.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/c06/command_boundary_matrix.json#L67) [server_permission_rate_limit_basic.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/c08/server_permission_rate_limit_basic.json#L165)

## 4. 安全、性能、兼容性、扩展性风险分析与建议
- 风险一：bench 对“失败响应”的识别仍然依赖自然语言文案。如果后续国际化文案或英文提示改写，而没有同步更新模式表，functional case 仍可能再次误判。建议后续逐步引入稳定错误码或结构化 marker，降低文案耦合。[Bench.Rcon.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.Rcon.ps1#L119) [Bench.FunctionalTrace.Common.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.Common.ps1#L463)
- 风险二：权限/限流类 case 强依赖 suite 覆盖环境。若以后有人直接用 `functional-matrix.json` 单跑 `C08`，会因为缺少 `serverConfigOverrides` 得到错误结论。建议继续通过 `server-basic-permission.json` 入口运行这类用例，避免环境口径漂移。[server-basic-permission.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/suites/server-basic-permission.json#L27) [BenchSuite.EntryPoint.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/BenchSuite.EntryPoint.ps1#L223)
- 风险三：`C08` 当前阈值与 suite 覆盖项绑定。如果后续再调整 `actorGroup.other` 容量公式，需要同步改 case phase 数，否则又会出现“实现正确、断言过时”的测试漂移。[server_permission_rate_limit_basic.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/c08/server_permission_rate_limit_basic.json#L47) [server-basic-permission.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/suites/server-basic-permission.json#L39)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）
- 共享状态一：suite 运行期间会改写同一个 `mcserver` 的 `server.properties` 与 `redstonelink-server.properties`，并在结束后恢复。当前脚本流程是串行安全的，但不适合并行跑多个 suite；本轮改动没有增加新的共享文件，只是增加了 `c08` 覆盖键数量。风险等级：中。[BenchSuite.EntryPoint.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/BenchSuite.EntryPoint.ps1#L223) [server-basic-permission.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/suites/server-basic-permission.json#L29)
- 共享状态二：bench client request/response 文件和 Prism 实例 `mods` 目录是单实例共享资源。当前改动仍沿用既有单实例串行模式，没有新增并发写点，但若未来并行跑多个外部客户端 suite，仍会在 bridge 文件和客户端模组同步上互相覆盖。风险等级：中。[Bench.Rcon.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.Rcon.ps1#L404) [server-basic-permission.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/suites/server-basic-permission.json#L27)
