# Graph 空搜索强制显示修复

## 1. 功能与语义、架构设计（关键方法和入口）

- 本轮把搜索命中的空查询语义改成“无命中”而不是“全量命中”，避免空搜索直接把整张图注入强制显示集合，修复高扇出收起和清空临时显示失效的问题 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L123)。
- 入口仍然保持在 `GraphViewer` 的搜索派生链路：`searchText -> hasSearch -> matchedNodes -> matchedNodeKeys -> forcedVisibleNodeKeys -> graphCanvasView`，只是现在只有真实搜索条件才会参与可见性放大 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1203) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1245) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1269)。
- 搜索结果区仍然只在 `hasSearch` 为真时展示，因此这次改动没有改变非空搜索的交互入口，也没有引入旧术语，语义继续保持 `triggerSource/core` 基线 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1736)。

## 2. 关键数据结构和算法性能分析

- `matchesSearch(...)` 保留原有字段匹配集合，只把空白查询提前短路为 `false`，因此搜索算法复杂度仍是线性的字段包含判断，没有新增额外数据结构 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L123)。
- `matchedNodes` 现在在 `hasSearch === false` 时直接返回空数组，避免空搜索仍然遍历全部节点并分配 `Set`，减少了无效扫描与下游派生计算 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1203)。
- `forcedVisibleNodeKeys` 的组装逻辑没有扩散改动，仍只汇总选中节点、临时拉回节点、草稿差异和编辑选择；这意味着性能和影响面都被限制在最小范围 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1245)。

## 3. 数据流或调用链

- 当前数据流是 `searchText` 先折算出 `hasSearch`，再决定是否生成 `matchedNodes`，最后才汇入 `forcedVisibleNodeKeys`，因此空搜索不会再沿着命中集合一路传到画布裁剪层 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1203) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1245)。
- `graphCanvasView` 仍然只消费 `forcedVisibleNodeKeys` 和展开集合，这保证了高扇出摘要节点的展开/收起逻辑继续由现有视图模型统一驱动，不需要额外分叉判断 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1269)。
- 搜索结果按钮仍绑定现有 `matchedNodes` 集合，所以用户点击搜索命中时仍然只会聚焦真实命中节点，不会在空搜索下误把全部节点当成命中项 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1736)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 本轮只改前端派生可见性，不改 snapshot、draft、服务端真值，也没有引入 `com.makomi.api.v1.*` 依赖；真实保存语义仍然只处理 `triggerSource -> core` [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1245) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1269)。
- 兼容性风险较低，因为非空搜索的匹配字段和 UI 入口都未变化；唯一显式行为变化是“空搜索不再等同于全部命中”，这正是当前缺陷修复目标 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L123) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1736)。
- 后续如果还有别的派生集合要复用搜索结果，建议继续坚持“空查询显式归零”的做法，而不是依赖字符串包含函数对空串的默认行为，否则类似泄漏会再次把局部视图放大成全量显示 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L123) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1203)。

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- 本轮没有新增共享可变对象，只调整了 `useMemo` 派生条件，因此线程边界仍然维持在 React 单线程渲染语义内，并发风险低 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1203)。
- `forcedVisibleNodeKeys` 仍然每次基于当前状态重新构造，不存在额外的异步读改写覆盖；这次只是把搜索分支从“全量注入”收敛为“按需注入” [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1245)。
- `graphCanvasView` 对展开状态和强制显示集合的消费方式未变，因此点击 source / 摘要节点时不会引入新的重入路径；剩余风险主要还是用户真实数据规模下的交互体验，而不是状态竞争，风险等级低 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1269)。
