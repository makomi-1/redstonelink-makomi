# core配对链路迁移

## 1. 功能与语义、架构设计
- 本轮把 `core` 配对界面的提交从命令兼容路径迁移到结构化 `C2S` 协议：客户端 `CorePairingScreen` 直接发送 `SubmitCorePairingPayload`，服务端在 `PairingNetworkServerHandlerSupport.handleSubmitCorePairing(...)` 中接收并处理。[CorePairingScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/CorePairingScreen.java#L85) [PairingNetwork.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetwork.java#L156) [PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L110)
- 新提交协议没有把 `core` 固化为真实来源，而是把 `core` 仅作为编辑上下文；真正写入仍统一落到 `triggerSource -> core`，并继续复用共享写入服务 `LinkSetExecutionService`。[PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L177) [LinkSetExecutionService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkSetExecutionService.java#L104) [LinkSetExecutionService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkSetExecutionService.java#L132)

## 2. 关键数据结构和算法性能分析
- `buildChangedCoreTargetsByTriggerSource(...)` 以 `LinkedHashSet` 和 `LinkedHashMap` 组织“期望 triggerSource 集合”“受影响 triggerSource 顺序”“变更后的目标集合”，只为发生变化的来源生成写入计划，避免对未变化来源重复执行 `replace`。[PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L550)
- 共享写入服务新增结构化目标集合入口后，仍沿用原有的目标校验、离线检查、写控判定和命令成本计算，复杂度主要由“变更来源数 × 单来源目标集合大小”决定，没有引入额外全局扫描。[LinkSetExecutionService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkSetExecutionService.java#L132) [LinkSetExecutionService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkSetExecutionService.java#L257)

## 3. 数据流或调用链
- 提交流程现在是：`CorePairingScreen.submitPairingRequest(...)` -> `SubmitCorePairingPayload` -> `PairingNetworkRegistrationSupport` 切回服务端主线程 -> `handleSubmitCorePairing(...)` 解析与构建差异 -> 对每个变更来源调用 `LinkSetExecutionService.prepareConfirmedReplace(...)/applyPreparedReplace(...)` -> 返回聚合反馈。[CorePairingScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/CorePairingScreen.java#L85) [PairingNetworkRegistrationSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkRegistrationSupport.java#L69) [PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L200) [LinkSetExecutionService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkSetExecutionService.java#L276)
- 副作用同步仍沿用既有闭环：每次 `applyPreparedReplace(...)` 后继续发布 delta，并同步受影响节点快照与玩家物品快照，所以运行时派发与客户端显示口径没有分叉。[LinkSetExecutionService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkSetExecutionService.java#L298) [LinkSetExecutionService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkSetExecutionService.java#L320) [LinkCommandSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkCommandSupport.java#L136)

## 4. 安全、性能、兼容性、扩展性风险分析与建议
- 安全与权限方面，`core` 新入口继续复用根命令权限、写控权限和 `LINK_RW` 限流，不会因为改成结构化发包而绕过原有控制边界。[PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L115) [PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L217)
- 性能方面，当前实现对每个变更来源仍单独调用一次 `applyPreparedReplace(...)`，因此当一个 `core` 关联大量 `triggerSource` 时，会重复触发节点快照同步；语义正确，但如果后续出现批量编辑热点，可再考虑把快照同步从“逐来源”收敛成“批后合并”。[PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L226) [LinkSetExecutionService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkSetExecutionService.java#L320)
- 兼容性方面，本轮只迁移 GUI/网络提交链路，显式兼容命令 `link set core ...` 仍保留在命令层；这意味着旧方向语义没有在仓库中彻底清零，只是范围收缩到了显式兼容入口。后续如要彻底收口，应单独清理命令和说明文档。[LinkCommandRegistry.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkCommandRegistry.java#L204)
- 扩展性方面，新的 `SubmitCorePairingPayload` 与 `buildChangedCoreTargetsByTriggerSource(...)` 已把“UI 视角”和“真实写入方向”解耦，后续如果还要保留其它兼容视图，也应沿用“视图层请求 -> 服务端拆成正向写入”的模式，而不是继续复制反向协议。[PairingNetwork.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetwork.java#L156) [PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L550)

## 5. 并发冲突审查
- 本轮新增的 `core` 提交处理仍通过 `PairingNetworkRegistrationSupport` 先切回 `player.server.execute(...)`，随后才进入 `handleSubmitCorePairing(...)`；因此变更集合构建、写控判定和实际写入都发生在服务端主线程，不存在新的跨线程共享状态读改写风险。[PairingNetworkRegistrationSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkRegistrationSupport.java#L69) [PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L110)
- 请求内使用的 `feedbacks`、`preparedOperations`、`changedTargetsByTriggerSource` 等容器都是方法内局部对象，不跨请求复用；`LinkSetExecutionService` 继续只操作世界级 `LinkSavedData`，线程边界与现有命令链路一致。风险等级评估为低。[PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L167) [LinkSetExecutionService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkSetExecutionService.java#L276)
- 纯逻辑测试已覆盖“按 core 视角生成变更来源集合”的关键差异算法，payload 契约测试已覆盖新增 `SubmitCorePairingPayload` 的规范化与编解码回归；当前剩余并发风险主要仍来自既有主线程写入闭环，而不是本轮新增逻辑。[PairingNetworkServerHandlerSupportTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/network/PairingNetworkServerHandlerSupportTest.java#L49) [PairingNetworkPayloadTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/network/PairingNetworkPayloadTest.java#L76)
