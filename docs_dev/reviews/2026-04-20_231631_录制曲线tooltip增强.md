# 录制曲线tooltip增强

## 1. 功能与语义、架构设计

- 本次改动把录制曲线 tooltip 完整收敛在 `RecordingChart` 内部，没有改动 `RecordingViewer` 的时间窗、节点选择或页面路由语义；组件入口仍是 [RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L83)。
- tooltip 状态通过局部 React state 承载，并在重建图表前主动清空，避免旧 plot 残留提示信息；对应状态与重建入口在 [RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L109) 和 [RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L149)。
- 具体实现路径是复用 `uPlot hooks.setCursor`，把当前 cursor 命中的横坐标和值折算成 tooltip 结构，再由 React 渲染绝对定位浮层；桥接点在 [RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L261)，tooltip DOM 在 [RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L458)。
- tooltip 的样式完全放在页面样式层，使用现有主题变量，不引入新的主题配置分支；样式入口在 [app.css](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L1836)。

## 2. 关键数据结构和算法性能分析

- tooltip 相关数据结构由 `RecordingTooltipSeriesEntry`、`RecordingTooltipRow` 和 `RecordingChartTooltipState` 组成，分别负责“曲线元信息”“单行展示项”“浮层整体状态”；定义位置在 [RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L44)。
- 在构建图表数据时，同时构建一份与 `uPlot` series 下标对齐的 `tooltipSeriesEntries`，这样 cursor 更新时只需按下标回读，不必重新解析节点语义；构建逻辑在 [RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L188) 和 [RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L205)。
- `resolveRecordingChartTooltipState` 的时间复杂度是 `O(可见曲线数)`，每次 cursor 更新仅线性扫描当前 data 数组，不会重新排序或重算全量 x 轴；核心逻辑在 [RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L527)。
- 定位算法只做基础左右钳制和上下放置判定，避免引入额外 DOM 测量循环；横向钳制与值格式化在 [RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L599) 和 [RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L609)。

## 3. 数据流或调用链

- 页面把节点样本与时间窗参数传入 `RecordingChart`，组件先生成 `uPlot.AlignedData` 和 tooltip 元信息，再实例化 plot；构建入口在 [RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L180) 与 [RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L241)。
- 鼠标移动后，`uPlot` 触发 `setCursor` hook，组件将当前 `cursor.idx` 对应的数据折算为 `RecordingChartTooltipState`；桥接路径在 [RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L263) 与 [RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L540)。
- 鼠标离开 plot 覆盖层时，`mouseleave` 会直接清空 tooltip，避免悬浮提示锁在旧位置；交互收口在 [RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L387)。
- 组件测试通过 mock `uPlot` 的 `setCursor` 回调链路，验证“命中样本显示 tooltip / 清空 cursor 隐藏 tooltip”两条主路径；测试入口在 [RecordingChart.test.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.test.tsx#L5) 和 [RecordingChart.test.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.test.tsx#L100)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全性风险低：本次改动只读本地录制数据，不引入新的网络接口、脚本注入点或 HTML 拼接；tooltip 文本全部经 React 文本节点渲染，入口仍在 [RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L468)。
- 性能风险低到中：tooltip 状态会在 cursor 移动时频繁更新，但处理量仅与当前可见曲线数成线性关系，且录制页当前限制节点选择规模较小，短期可接受；若未来放宽节点数量，可优先考虑节流或 `requestAnimationFrame` 合帧，当前热点在 [RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L263)。
- 兼容性风险中等：tooltip 位置基于固定宽度估算和常量高度阈值，而不是实时测量 DOM 尺寸；现有样式下足够稳定，但若后续 tooltip 内容显著变长，可能需要改成实际测量。相关钳制在 [RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L576) 与样式宽度约束 [app.css](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L1839)。
- 扩展性较好：后续若要增加“原始 tick / 节点别名 / 多轴值”显示，只需扩展 `RecordingChartTooltipState` 和 `resolveRecordingChartTooltipState`，不会影响缩放和平移逻辑；扩展点集中在 [RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L59) 与 [RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L527)。

## 5. 并发冲突审查

- 共享状态范围局限在组件实例内：`plotRef`、`dragStateRef`、`tooltipState` 都是 `RecordingChart` 私有状态，不与外部全局存储共享；对应状态定义在 [RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L100) 与 [RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L109)。
- 读改写覆盖风险低：图表重建前会先销毁旧 plot 并清空 tooltip，避免旧实例继续写入新状态；清理顺序在 [RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L155)。
- 重入/线程边界风险低：`uPlot` hook、DOM 事件和 React state 更新都运行在浏览器主线程，没有跨线程共享写入；当前没有引入 `setTimeout`、worker 或外部订阅源。主事件边界在 [RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L325)。
- 风险等级评估为低：当前唯一需要持续关注的是“高频 cursor 更新导致的重复 render”，但这属于性能侧而非并发一致性问题，短期无额外并发修复项。
