# graph别名输入态与多级草稿撤回

## 1. 功能与语义、架构设计（关键方法和入口）

- 本轮在 `GraphViewer` 内新增了两个前端本地状态：`aliasDraftValue` 负责承接当前选中真实节点的别名输入态，`undoDraftHistory` 负责承接最多 10 条整份草稿快照的撤回历史；同时引入 `GRAPH_DRAFT_UNDO_HISTORY_LIMIT` 作为硬上限，语义边界清晰且未触碰服务端保存协议。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L74) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L182)
- 别名输入态通过选中节点同步 effect 收口：只有当前选中的是可编辑真实节点时，输入框才回填其当前已应用 alias；否则清空输入态，避免跨节点串值。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L738)
- 真正写入草稿的入口被统一收口到 `applyLocalDraftChange(...)` 和 `handleApplyAliasDraft()`：输入框不再直接落 `RenameNodeAlias`，而是显式点击“应用到草稿”后，才调用 `upsertAliasDraft(...)` 生成本地草稿操作。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1410) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1664) [draft.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.ts#L122)
- 语义对齐检查结果：内部与 UI 文案仍统一使用 `triggerSource/core`，真实保存方向仍然只处理 `triggerSource -> core`，本轮仅改前端本地草稿与撤回表现，无服务端真值语义漂移。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1923) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2031)

## 2. 关键数据结构和算法性能分析

- 撤回历史采用 `GraphDraft[]` 快照栈，而不是操作 diff 栈；每次真实应用草稿时才压入一次“变更前草稿”，并用 `slice(-10)` 强制裁剪到最近 10 条，空间复杂度被明确限制在常数量级。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1414)
- 历史去重依赖 `sameGraphDraft(...)`，底层仍以序列化后的整稿比较保证语义一致；虽然这是 O(n) 比较，但现在调用频率已从“别名每次输入变化”降到“每次点击应用一次”，实际热路径开销显著下降。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1418) [draft.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.ts#L26)
- 别名差异比较新增了本地 `normalizeAliasInput(...)`，与 `draft.ts` 中 `normalizeAlias(...)` 的去首尾空白语义保持一致，避免“只输入空格”制造无效草稿或无意义历史记录。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L77) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L499) [draft.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.ts#L30)

## 3. 数据流或调用链

- 别名编辑的新链路是：详情面板输入框先写 `aliasDraftValue`，不会改 `graphDraft`；点击“应用到草稿”后，`handleApplyAliasDraft()` 调 `upsertAliasDraft(...)` 生成 `RenameNodeAlias`，再经 `applyLocalDraftChange(...)` 写入 `graphDraft` 并压入撤回历史。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2610) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1664) [draft.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.ts#L122)
- 撤回链路是：顶部“撤回草稿”按钮触发 `handleUndoDraft()`，从 `undoDraftHistory` 末尾弹出最近一条整份草稿并恢复到 `graphDraft`，从而让 `effectiveGraphBundle`、画布和保存预检自然按既有依赖链重算。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1454) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1875)
- 生命周期收口点有两类：切图/重载 graph 时会同时清空 `aliasDraftValue` 与 `undoDraftHistory`，保存成功后也会清空撤回历史，避免把旧图或已落真值的草稿继续留在本地历史里。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L675) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1756)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全与兼容性：本轮没有新增网络请求、没有改保存 payload，也没有改 `GraphDraft` 文件结构；因此现有预检、保存和本地草稿持久化接口保持兼容。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1081) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1115) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1734)
- 性能：别名输入不再触发 `graphDraft`、预检请求和画布重算，明显降低了输入过程的抖动与无效计算；性能热点从“每次输入”降到了“每次应用”。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1065) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2614)
- 扩展性：当前多级撤回覆盖所有经 `applyLocalDraftChange(...)` 进入草稿的本地编辑动作，因此后续若继续增加别的“应用到草稿”入口，可以零额外协议成本复用同一套历史栈。建议未来若要做 redo，再在此基础上补一条对称的前进栈即可。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1414)
- 残余风险：未应用的别名输入在切换节点时会被重置，这符合当前“显式应用才算提交”的设计，但若用户后续希望跨节点暂存临时输入，需要再引入按 `nodeKey` 分桶的输入缓存，而这会提高状态复杂度。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L738)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- 共享状态主要集中在 `graphDraft`、`undoDraftHistory` 和 `aliasDraftValue`。其中历史栈写入与弹出都使用函数式 `setState`，避免在 React 批处理下出现基于旧数组的覆盖写风险；风险等级评估为低。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1418) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1464)
- 读改写覆盖方面，`handleApplyAliasDraft()` 读取当前渲染帧里的 `selectedNode` 与 `aliasDraftValue` 后一次性提交，不与输入框 `onChange` 并发写同一份 `graphDraft`；同时因为别名输入不再直接写稿，已经规避了此前“逐字符抢占草稿状态”的问题，风险等级为低。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1664) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2617)
- 线程边界方面，本轮逻辑全部发生在前端主线程和既有 fetch 回调内，没有新增跨线程共享内存。保存成功后主动清空撤回历史，避免“已持久化版本”和“本地旧历史”并存导致的跨阶段回退歧义；风险等级为低，建议保持这一清空策略不要在未引入 revision 级 redo 前放松。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1760)
