# IrisSodium兼容渲染分支

## 1. 功能与语义、架构设计（关键方法和入口）

本轮实现把原 `1.21.1` 工作区里剩余的 `Iris / Sodium` 兼容渲染分支迁到了当前 `1.21.11` 渲染接口上，且保持了原设计语义：只在兼容模组存在时切到特殊分支，其余路径继续走当前已经稳定的默认外显实现。兼容分支入口在 [IrisRenderCompatSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/IrisRenderCompatSupport.java#L19)，它统一判定 `iris` 或 `sodium` 已加载时启用兼容路径。

`quick-link` 相关外显的事件入口集中在 [QuickLinkWorldOverlayRenderer.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/QuickLinkWorldOverlayRenderer.java#L205)。当前设计把普通路径继续放在 `BEFORE_BLOCK_OUTLINE / BEFORE_TRANSLUCENT`，但在兼容分支里拦截原版白框并延后到 `END_MAIN` 统一重绘，核心逻辑分别落在 [QuickLinkWorldOverlayRenderer.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/QuickLinkWorldOverlayRenderer.java#L92)、[QuickLinkWorldOverlayRenderer.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/QuickLinkWorldOverlayRenderer.java#L145)、[QuickLinkWorldOverlayRenderer.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/QuickLinkWorldOverlayRenderer.java#L742)、[QuickLinkWorldOverlayRenderer.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/QuickLinkWorldOverlayRenderer.java#L773)。

定向箭头世界外显保持“世界后置统一收集后再提交”的设计，只是兼容分支从普通线段管线切到直接绘制支撑，入口在 [DirectionalFaceVectorWorldOverlayRenderer.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/DirectionalFaceVectorWorldOverlayRenderer.java#L25) 与 [DirectionalFaceVectorWorldOverlayRenderer.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/DirectionalFaceVectorWorldOverlayRenderer.java#L72)。

真正的迁移适配核心在 [IrisDirectLineRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/IrisDirectLineRenderSupport.java#L29)：旧版依赖直接写线段缓冲的实现方法，在当前版本不再直接可用，因此这里改成“把世界线段展开成面向相机的细长四边形，再复用现有穿透四边形管线提交”的方式，以保留原设计里的“兼容模组下稳定可见”目标。

## 2. 关键数据结构和算法性能分析

本轮最关键的数据结构是穿透公共渲染支撑里的 [SeeThroughWorldGeometryRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/SeeThroughWorldGeometryRenderSupport.java#L346) `ColoredLineSegment`，以及在兼容分支里即时展开出来的四边形顶点数据 [IrisDirectLineRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/IrisDirectLineRenderSupport.java#L119)。这使得 `quick-link` 描边、第三形态连线和定向箭头都能先统一沉淀为“世界空间线段”，再由不同渲染管线消费。

算法上，兼容分支的主要开销来自 [IrisDirectLineRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/IrisDirectLineRenderSupport.java#L55) 的线段转四边形过程。它对每条线段做一次方向归一化、一次视线叉积和一次宽度求解，整体是严格的 `O(n)`，不会引入额外的图遍历或排序复杂度。相比旧版直接交给线段渲染目标，这里顶点数量会放大，但换来的是在兼容模组下更稳定的显示结果。

底层缓冲复用由 [SeeThroughWorldGeometryRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/SeeThroughWorldGeometryRenderSupport.java#L255) 的 `ensureRingBuffer(...)` 负责，它会按需扩容并复用 `MappableRingBuffer`，避免每帧重新创建 GPU 顶点缓冲。绘制提交则统一收敛到 [SeeThroughWorldGeometryRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/SeeThroughWorldGeometryRenderSupport.java#L231)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

安全层面，本轮仅涉及客户端渲染路径，没有新增网络入口、磁盘写入格式或持久化语义风险。兼容性层面的主要收益是避免继续依赖已经被兼容模组改写过的默认世界线段目标，这个设计直接体现在 [IrisRenderCompatSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/IrisRenderCompatSupport.java#L19) 与 [IrisDirectLineRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/IrisDirectLineRenderSupport.java#L12)。

性能层面的主要代价是：兼容分支把每条线段展开为一个细长四边形，理论上比普通线段路径消耗更多顶点带宽，关键热点在 [IrisDirectLineRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/IrisDirectLineRenderSupport.java#L55)。不过当前外显对象数量本身受玩家视距、智能眼镜门槛和可见连接数限制，短期内这部分代价是可接受的。

扩展性层面，这次迁移把兼容模组特殊处理集中到了两个类：判定类 [IrisRenderCompatSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/IrisRenderCompatSupport.java#L12) 和直绘支撑类 [IrisDirectLineRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/IrisDirectLineRenderSupport.java#L16)。后续如果还要把别的描边/连线外显接入兼容分支，优先复用 `ColoredLineSegment -> drawWorldSegments(...)` 这一层，不要再各自单独维护一套模组分支逻辑。

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

共享状态主要有两类：一类是 `quick-link` 渲染器内部缓存和显示对象状态，在释放路径 [QuickLinkWorldOverlayRenderer.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/QuickLinkWorldOverlayRenderer.java#L347) 统一清理；另一类是公共穿透支撑内部的静态分配器与 ring buffer [SeeThroughWorldGeometryRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/SeeThroughWorldGeometryRenderSupport.java#L55)。

当前这些状态都由世界渲染事件入口驱动，线程边界仍是客户端主渲染线程，入口集中在 [QuickLinkWorldOverlayRenderer.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/QuickLinkWorldOverlayRenderer.java#L205) 与 [DirectionalFaceVectorWorldOverlayRenderer.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/DirectionalFaceVectorWorldOverlayRenderer.java#L25)。因此本轮并发冲突风险等级评估为“低”。

需要注意的残余风险是：如果未来把这些显示对象的增删改移动到异步线程，或者在资源重载/客户端退出之外的新时机调用清理逻辑，就必须重新审查 `SeeThroughWorldGeometryRenderSupport.close()` 与 `QuickLinkWorldOverlayRenderer.close()` 的线程归属，避免在非渲染线程关闭 GPU 缓冲 [SeeThroughWorldGeometryRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/SeeThroughWorldGeometryRenderSupport.java#L147)、[QuickLinkWorldOverlayRenderer.java](/d:/OpenProjects/RedstoneLink/rl-fabric-1.21.11/src/client/java/com/makomi/client/render/QuickLinkWorldOverlayRenderer.java#L347)。
