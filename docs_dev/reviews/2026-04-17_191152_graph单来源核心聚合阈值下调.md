# Graph 单来源核心聚合阈值下调

## 1. 功能与语义、架构设计（关键方法和入口）

- 本轮唯一实现改动是将核心聚合块的来源门槛从 `2` 下调到 `1`，使单个 `triggerSource` 指向多个 `core` 时，也能进入现有的核心聚合块折叠链路 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L46)。
- 聚合入口仍然位于 `buildGraphCanvasView(...)` 前半段，先按 `core` 反查来源集合并生成同输入签名，因此单来源多核心场景会优先被聚合，而不是进入后面的单来源 `summary` 收起 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L504) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L523) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L542)。
- 交互语义保持不变：聚合块依旧通过点击 `aggregate:*` 节点本身展开或收起，没有新增 `triggerSource` 与单来源聚合块的联动入口 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2021) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2028)。

## 2. 关键数据结构和算法性能分析

- 当前聚合仍要求 `core` 数量至少为 `2`，因此只是放宽来源维度，不会把单个 `core` 误包装成聚合块，时间复杂度和原先一致，仍然是按节点和边做线性扫描与分组 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L46) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L47) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L543)。
- 对 1 对多场景的收益点在于边压缩：当一个 `triggerSource` 连接多个“同输入集合完全一致”的 `core` 时，折叠态会以一个聚合块替代多条真实边，减少画布上同时渲染的边数量 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L524) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L527)。
- 后续单来源高扇出 `summary` 逻辑仍保留，只有未被前置聚合链路吸收的目标集合才会进入这层折叠，因此本轮是“前置扩容”，不是新增一套并行算法 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L643) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L667)。

## 3. 数据流或调用链

- 调整后的调用链仍是 `effectiveGraphBundle -> buildGraphCanvasView -> collapsedAggregateNodes -> phaseCanvasNodes/phaseCanvasEdges`，唯一变化是更多单来源多核心组合现在能在 `sourceNodes.length` 检查处通过 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L504) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L523) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L524)。
- 若来源未进入聚合块，画布仍会在后续阶段为高扇出 `triggerSource` 计算 `summaryNodes` 与 `aggregatableTriggerSourceNodeKeys`，因此原有来源级展开收起链路没有被删改 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L647) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L648) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L670)。
- 交互层的数据流也未变化，聚合块点击仍只切换 `expandedAggregateNodeKeys`，保证单来源聚合只是扩大命中范围，而不是改写展开状态模型 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2017) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2030)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 语义边界保持不变：本轮只改前端视图层阈值，没有调整真实保存语义，也没有改变 `triggerSource -> core` 的方向约束 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L46) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L523)。
- 兼容性风险较低，因为只是放宽已有判定条件，没有引入新的节点类型、持久化字段或接口依赖；残余风险是单来源多核心场景的默认展开入口变成“聚合块本身”，不是来源节点本体，这符合当前实现但需要人工交互回归继续确认 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2028) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2040)。
- 如果后续还要让单来源场景点击 `triggerSource` 也能同时控制对应聚合块，这应作为独立交互需求另做，不建议在当前阈值调整里顺手拼接，以免污染现有 `summary` 与 `aggregate` 的职责边界 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2022) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2028)。

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- 本轮没有新增任何 React 状态，只改了一个常量，因此不存在新的共享状态、读改写覆盖或线程边界变化，风险低 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L46)。
- 既有聚合块展开状态 `expandedAggregateNodeKeys` 和来源摘要展开状态 `expandedTriggerSourceNodeKeys` 仍保持独立，这意味着本轮不会引入状态互相踩踏的问题 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2017) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2024)。
- 残余并发风险仍来自用户快速连续点击触发的前端重绘抖动，但这一风险与本轮阈值下调无新增耦合，等级维持低 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2028) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2030)。
