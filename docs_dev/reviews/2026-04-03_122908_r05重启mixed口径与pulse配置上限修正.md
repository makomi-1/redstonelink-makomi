## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 兼容性：`pulseDurationTicks` 上限从 `40` 放到 `240` 后，旧配置完全兼容；风险主要是“极端长脉冲”会让激活态持续更久，但这仍属于显式配置选择，不会改变默认值 `4` 的行为。[RedstoneLinkConfigParser.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/config/RedstoneLinkConfigParser.java#L36) [RedstoneLinkConfigInteractionAndCrossChunkParseTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/config/RedstoneLinkConfigInteractionAndCrossChunkParseTest.java#L61)
- 语义边界：当前实现下，“`pulse` 已持久化”不等于“mixed restart 且 `sync replay` 后仍可参与仲裁”；只要 replay 走 `SYNC_SIGNAL`，历史 `pulse` 就会被清掉。这条边界已经通过内部测试锁住，但后续若要做“restart 后保留 pulse”的产品设计，必须先调整 `SYNC` 路径对 `pulse` 的清理策略，而不是只改 bench 断言。[ActivatableTargetBlockEntityInternalTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/block/entity/ActivatableTargetBlockEntityInternalTest.java#L375) [ActivatableTargetBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/ActivatableTargetBlockEntity.java#L938)
- 回归风险：专项 suite 仍保留 `server.pulseDurationTicks=240`，这样 `x25` 继续能覆盖“长 pulse 窗口确实已落盘”的链路；`r05` 则只验证当前实现真实会发生的 restart 后 `sync -> toggle -> none`。这能同时覆盖配置修复与运行时语义两条线。[restart-mixed-replay.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/suites/restart-mixed-replay.json#L10) [restart_mixed_replay_redstone_verify.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/r05/restart_mixed_replay_redstone_verify.json#L3)
- 建议：若后续还要新增“跨重启保留 `pulse`”专项，应单独建一个“无 `sync replay` 干扰”的 restart case，避免再次把“配置窗口问题”和“`SYNC` 语义会清理 `pulse`”混在一起排查。[InternalDispatchDeltaRuleSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/InternalDispatchDeltaRuleSupport.java#L536) [ActivatableTargetConcurrentBucketComponent.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/ActivatableTargetConcurrentBucketComponent.java#L153)
