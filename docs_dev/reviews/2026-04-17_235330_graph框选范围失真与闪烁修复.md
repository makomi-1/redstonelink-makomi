## 1. 功能与语义、架构设计（关键方法和入口）

本轮修复只作用于 graph 前端视图层的框选命中与状态同步，没有改 `triggerSource/core` 真值、snapshot、draft 和服务端保存语义。核心设计调整是把“框选命中”“业务选择”“主画布可见性”三层解耦：批量选择结果不再反向驱动画布可见节点集，节点重建时保留 ReactFlow 当前真实选中态，而不是再用业务集合强控 `selected`。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1023) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1654) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1811)

## 2. 关键数据结构和算法性能分析

这次没有引入新的复杂数据结构，主要是对现有状态依赖做收缩。`forcedVisibleNodeKeys` 现在只保留选中详情节点、手动拉回孤立节点、搜索命中和草稿差异，避免批量选择集合在拖框过程中不断改变 `graphCanvasView` 的节点集和聚合展开状态，直接降低了框选时的连锁重算与闪烁。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1638) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1654)

在节点重建链路中，当前节点的 `selected` 状态通过 `existingSelectedByNodeKey` 轻量缓存并回填，这样既能保留 ReactFlow 内部真实选区，又不会把业务选择集合再次反向写成全量选中，时间复杂度仍然是线性扫描当前节点集合的 O(n)。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1817) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1833) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2133)

## 3. 数据流或调用链

修复后的主链路是：ReactFlow 依据 `SelectionMode.Full` 给出真实命中的选区，`onSelectionChange` 将这些节点交给 `applyBatchSelectionFromNodeKeys`，后者再写回右侧批量编辑使用的来源/目标数组；与此同时，画布节点重建不再依据这些业务数组去扩张主画布节点集，也不再把它们直接写成 `selected`，而是保留当前 ReactFlow 内部选区状态。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1811) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2071) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2543) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2560)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

安全与语义层面，本轮仍然只动前端视图层，没有新增 API 依赖，也没有改变 `triggerSource -> core` 的真实保存边界，符合当前项目语义约束。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2071)

性能层面，问题的主要来源不是算法慢，而是拖框过程中不断改写主画布可见节点集导致的重复重建；这次把批量选择集合从 `forcedVisibleNodeKeys` 中剥离后，这个放大器被拿掉，框选过程会比之前稳定。兼容性层面，`SelectionMode.Full` 会比以前更严格，只选完全落入框内的节点，这正是本轮所需；如果后续用户再次希望“擦到也算命中”，可以明确再切回 `Partial`，但那应当是有意识的交互选择，而不是默认行为。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1654) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2560)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

前端仍运行在 React 单线程事件循环内，没有新增跨线程共享状态。本轮真正的冲突点是三套前端状态之间的读改写覆盖：ReactFlow 内部选区、右侧批量选择数组、主画布可见节点集。修复后批量选择数组不再参与可见节点计算，节点 `selected` 也不再由业务数组反向强控，冲突链被切成单向流，风险等级从“中”下降到“低”。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1654) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1811) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2056)

后续如果继续扩展“程序化追加选择”“程序化反选”或“按条件批量选中”，建议继续复用当前这套单向数据流：ReactFlow 负责真实选区，业务数组负责业务含义，主画布可见性只由搜索、详情、草稿差异和手动拉回控制，不要重新把三者耦合回去。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1654) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2071) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2543)
