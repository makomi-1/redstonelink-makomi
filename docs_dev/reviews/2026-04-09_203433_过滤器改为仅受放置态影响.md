# 过滤器改为仅受放置态影响

## 1. 功能与语义、架构设计（关键方法和入口）
- 本轮把过滤器真值从“当前已加载方块实体”转为“已放置过滤器持久化条目”，核心入口是 [PlacedLinkFilterSavedData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/PlacedLinkFilterSavedData.java#L35) 和 [LinkDispatchFilterService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkDispatchFilterService.java#L18)。`LinkDispatchFilterService` 现在只负责 façade 式的 upsert/remove/query，不再自持纯运行时静态索引。[LinkDispatchFilterService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkDispatchFilterService.java#L39)
- 过滤器方块实体的生命周期改成“加载时补登记、普通脱附不删、物理移除才删”。这一点由 [AbstractLinkFilterBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/AbstractLinkFilterBlockEntity.java#L175) 和 [LinkFilterLifecycleState.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/LinkFilterLifecycleState.java#L13) 共同完成，语义上与节点的物理移除区分保持同类思路。
- 方块层改为在 `onPlace/neighborChanged` 刷新已放置过滤器真值，在 `onRemove` 只标记真实物理移除，不再直接把区块卸载视作过滤器失效。[AbstractLinkFilterBlock.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/AbstractLinkFilterBlock.java#L50)

## 2. 关键数据结构和算法性能分析
- `PlacedLinkFilterSavedData` 内部结构是 `entriesByKey + chunkIndex` 双表：前者保存过滤器真值，后者按 `dimension -> filterKind -> chunkKey -> filterKeys` 做区块倒排索引，查询复杂度保持为“同区块候选数线性”，避免全维扫描。[PlacedLinkFilterSavedData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/PlacedLinkFilterSavedData.java#L54) [PlacedLinkFilterSavedData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/PlacedLinkFilterSavedData.java#L138)
- 持久化条目 `FilterEntry` 缓存了解析后的 `serials` 与最近一次邻居输入采样值，避免每次过滤查询都重新解析序号表达式或回读 block entity；`toRuntimeView()` 直接构造规则求值器视图，属于常数级封装开销。[PlacedLinkFilterSavedData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/PlacedLinkFilterSavedData.java#L327)
- 覆盖区块集合仍按半径 8 的立方域计算，最坏覆盖 4 个 chunk 列，保持了原设计的局部查询特征；upsert/remove 只在过滤器配置变更、邻居变化、附着恢复或物理移除时执行，写路径频率可控。[PlacedLinkFilterSavedData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/PlacedLinkFilterSavedData.java#L305)

## 3. 数据流或调用链
- 数据写入链现在是：`AbstractLinkFilterBlockEntity.applySnapshot()/clearRemoved()/refreshPlacedFilterState()` -> `LinkDispatchFilterService.upsertFilter(...)` -> `PlacedLinkFilterSavedData.upsert(...)`。[AbstractLinkFilterBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/AbstractLinkFilterBlockEntity.java#L78) [LinkDispatchFilterService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkDispatchFilterService.java#L39) [PlacedLinkFilterSavedData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/PlacedLinkFilterSavedData.java#L87)
- 数据删除链现在是：`AbstractLinkFilterBlock.onRemove()` 标记物理移除 -> `AbstractLinkFilterBlockEntity.setRemoved()` 通过生命周期状态机判断 -> `LinkDispatchFilterService.removeFilter(...)` -> `PlacedLinkFilterSavedData.remove(...)`。[AbstractLinkFilterBlock.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/AbstractLinkFilterBlock.java#L73) [AbstractLinkFilterBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/AbstractLinkFilterBlockEntity.java#L182) [LinkFilterLifecycleState.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/LinkFilterLifecycleState.java#L37)
- 查询链现在是：`TriggerSourceBlockEntity/LinkedTargetDispatchService` 继续调用 `LinkDispatchFilterService.allowsSend/allowsReceive(...)`，但底层候选过滤器改为由 `PlacedLinkFilterSavedData.collectFilters(...)` 提供，因此区块未加载时也能命中已持久化过滤器条目。[LinkDispatchFilterService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkDispatchFilterService.java#L86) [PlacedLinkFilterSavedData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/PlacedLinkFilterSavedData.java#L138)

## 4. 安全、性能、兼容性、扩展性风险分析与建议
- 安全性方面，本轮只动过滤器生命周期与持久化真值，不涉及权限判定、命令写入裁决或 `triggerSource/core` 方向逻辑，方向语义保持不变。[LinkDispatchFilterService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkDispatchFilterService.java#L83)
- 性能方面，过滤器查询不再依赖 `level.getBlockEntity(...)`，避免了因区块未加载导致的候选缺失；但代价是邻居输入阈值来源现在依赖“最近一次已知采样值”，不是离线实时世界态。这一取舍使“放置态有效”优先于“离线实时采样”。[PlacedLinkFilterSavedData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/PlacedLinkFilterSavedData.java#L281) [AbstractLinkFilterBlock.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/AbstractLinkFilterBlock.java#L127)
- 兼容性方面，旧世界里在本次更新前已放置、但尚未再次加载过区块的过滤器，首次重启后不会立刻出现在新的 `SavedData` 中；需要这些过滤器所在区块至少加载一次，才会通过 `clearRemoved()/neighborChanged()` 补登记。这是本轮实现的已知迁移边界。[AbstractLinkFilterBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/AbstractLinkFilterBlockEntity.java#L175)
- 扩展性方面，当前 `PlacedLinkFilterSavedData` 已把条目保存、倒排索引和查询都收口在一个类里；若后续过滤器需要更多放置态字段，可以优先扩展 `FilterEntry`，无需回退到 block entity 运行时扫描路径。[PlacedLinkFilterSavedData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/PlacedLinkFilterSavedData.java#L327)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）
- 共享状态主体从原来的静态 `STATE_BY_SERVER` 迁移为 `PlacedLinkFilterSavedData` 实例内部的 `entriesByKey/chunkIndex`，它们继续运行在 Minecraft 服务端主线程的 block entity、block update 和派发查询路径上，没有引入新的异步写入入口，并发风险低。[PlacedLinkFilterSavedData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/PlacedLinkFilterSavedData.java#L54)
- 生命周期状态机 `LinkFilterLifecycleState` 仅保存当前方块实体的瞬时布尔状态，不与其他过滤器共享，也不存在跨线程读改写；风险主要在逻辑判定是否准确，已由状态机单测覆盖“普通脱附不删”“物理移除才删”。[LinkFilterLifecycleState.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/LinkFilterLifecycleState.java#L20) [LinkFilterLifecycleStateTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/block/entity/LinkFilterLifecycleStateTest.java#L17)
- 持久化查询与零邻居输入仍参与过滤的关键边界由新增单测覆盖，当前没有发现重入或共享状态覆盖问题；风险等级评估为低。后续若把过滤器真值写入扩展到异步批处理，再单独复查 `SavedData` 的线程边界。[PlacedLinkFilterSavedDataTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/data/PlacedLinkFilterSavedDataTest.java#L28)
