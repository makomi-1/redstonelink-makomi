## 1. 功能与语义、架构设计

- 本轮把“具体节点类型标题”拆成两层职责：共享层先由 [LinkGuiDisplayContext.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkGuiDisplayContext.java#L15) 把物品/方块/旧 token 归一化为稳定短 token，再由客户端头部解析层 [GuiHeaderContextSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/GuiHeaderContextSupport.java#L23) 映射成双语标题和图标语义，避免每个 screen 直接耦合注册名判断。
- 共享头部渲染能力集中在 [GuiHeaderRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/GuiHeaderRenderSupport.java#L17)，统一处理描边标题、副标题、图标左右上角锚点和最小包围盒；配对抽象基类 [AbstractMultiPairingScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/AbstractMultiPairingScreen.java#L257) 通过可覆写的 `headerTitle/headerIcon/headerSpec` 钩子接入，保持可复用和可覆写。
- pairing 开屏链路扩展了 `displayContextToken` 字段，服务端入口 [PairingNetwork.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetwork.java#L81) 与 payload 契约 [PairingNetwork.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetwork.java#L155) [PairingNetwork.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetwork.java#L198) 一起升级，客户端接包后在 [PairingNetworkClientHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/network/PairingNetworkClientHandlerSupport.java#L92) 构造具体 screen，保证“具体类型标题”在服务端真实开屏和本地手持开屏两条路径都成立。
- quick link、过滤器、状态面板分别通过 [QuickLinkToolScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/QuickLinkToolScreen.java#L271) [LinkFilterEditorScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/LinkFilterEditorScreen.java#L580) [StatePanelToolScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/StatePanelToolScreen.java#L513) 复用同一头部规格，保持与 core/triggerSource 配对界面一致的图标和双语标题风格。

## 2. 关键数据结构和算法性能分析

- `LinkGuiDisplayContext` 的 token 归一化是常量级字符串裁剪加 `switch` 分派，[LinkGuiDisplayContext.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkGuiDisplayContext.java#L46) [LinkGuiDisplayContext.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkGuiDisplayContext.java#L90) 只发生在“打开 GUI”时，不进入 tick 热路径，也不引入额外持久化结构。
- 头部渲染的额外成本仅为 1 次标题包围盒计算和 1 次小图标 blit，[GuiHeaderRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/GuiHeaderRenderSupport.java#L34) [GuiHeaderRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/GuiHeaderRenderSupport.java#L55) 只处理固定数量文本和 16x16 贴图，没有集合遍历或缓存失效问题。
- payload 编解码在原有字段后追加一个短 token，[PairingNetworkPayloadSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkPayloadSupport.java#L70) [PairingNetworkPayloadSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkPayloadSupport.java#L93)，带宽增量固定且很小，对现有网络量级可忽略。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 兼容性方面保留了旧的 public 开屏入口和旧反射测试依赖的私有重载，[PairingNetwork.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetwork.java#L69) [PairingNetwork.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetwork.java#L118)，因此旧调用点不需要一次性全部迁移。
- 扩展性风险主要在“新增可配对节点类型时必须补 token 映射和双语键”；如果遗漏，会自动回退到通用 `triggerSource/core` 标题，而不会崩溃，兜底逻辑见 [LinkGuiDisplayContext.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkGuiDisplayContext.java#L46) 和 [GuiHeaderContextSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/GuiHeaderContextSupport.java#L23)。
- 性能风险低，当前实现只增加 GUI 打开时的 token 解析和每帧固定量渲染；没有把 registry 解析、字符串分支或网络对象构造搬进频繁热路径。建议后续若继续增加头部变体，优先保持 token 归一化表驱动，不要把具体 screen 判断散落回各界面。
- 资源兼容性上，本轮没有改动任何贴图资源，只复用了现有 `textures/gui` 图标与背景，因此不存在资源回退和像素变更风险。残余风险：新双语标题比旧标题更长，虽然背景包围盒已经跟随头部自动扩张，但极窄窗口下可能仍出现视觉紧凑，需要后续人工进游戏确认极端分辨率表现。

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- 网络线程边界已明确，客户端开 screen 仍然统一经由 [PairingNetworkClientHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/network/PairingNetworkClientHandlerSupport.java#L28) [PairingNetworkClientHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/network/PairingNetworkClientHandlerSupport.java#L41) 的 `context.client().execute` 切回主线程，避免网络线程直接改 UI；风险等级：低。
- payload 仍然对目标列表做不可变拷贝，并新增了 `displayContextToken` 稳定字段，相关稳定性由 [PairingNetwork.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetwork.java#L179) [PairingNetwork.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetwork.java#L222) 与回归测试 [PairingNetworkPayloadTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/network/PairingNetworkPayloadTest.java#L128) [PairingNetworkPayloadTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/network/PairingNetworkPayloadTest.java#L157) 共同覆盖；风险等级：低。
- 服务端开屏时对 stack/block 只读解析 registry path，不写共享业务状态；真正写状态的链路仍然是原有 pairing 提交，不受本轮影响。当前未引入新的跨线程共享容器或读改写覆盖路径；风险等级：低。建议后续若把标题上下文继续扩展到更多网络包，继续沿用“服务端只下发稳定 token、客户端只做显示映射”的单向模式，避免把 UI 枚举反向渗透到存档和业务层。
