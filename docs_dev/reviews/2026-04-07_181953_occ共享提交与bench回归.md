## 2. 关键数据结构和算法性能分析
- `BenchOccCommandRegistry` 本身没有引入新的持久化结构；snapshot 与 summary 构造只读取一次 `RevisionBaseline` 和当前链接数量，额外开销基本是 O(1) 加一次既有集合 `size()`。[BenchOccCommandRegistry.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/bench/BenchOccCommandRegistry.java#L340) [BenchOccCommandRegistry.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/bench/BenchOccCommandRegistry.java#L418) [BenchOccCommandRegistry.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/bench/BenchOccCommandRegistry.java#L451) [BenchOccCommandRegistry.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/bench/BenchOccCommandRegistry.java#L484)

## 4. 安全、性能、兼容性、扩展性风险分析与建议
- 兼容性：`captureRegex` 是可选字段，旧 case 不配置时仍沿用原 `expectedPrefix / expectedRegex / rejectRegex` 路径，不会被强制迁移到 captures 机制。[Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L2358) [Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L2526)
- 安全性：`bench occ snapshot` 对未分配或已退役 serial 直接返回失败并拒绝输出 baseline，符合测试入口“只观测合法在线语义对象”的口径；若未来需要审计退役节点历史，应单独设计只读审计命令而不是放宽当前入口。[BenchOccCommandRegistry.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/bench/BenchOccCommandRegistry.java#L340)
- 扩展性：OCC 冲突回归已独立成 `occ-conflict-regression`，后续继续扩 stale baseline 场景时只需要加 case 并挂到同一 suite，不必污染默认 `regression-core/full` 的运行时长与职责边界。[occ-conflict-regression.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/suites/occ-conflict-regression.json#L1) [使用说明.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs_dev/使用说明.md#L457)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）
- 共享状态：真正的读改写竞争仍集中在 `LinkSavedData` 的 `graphRevision/sourceRevision` 与链接集合；本轮没有新增绕过 OCC 的写路径，bench 与网络入口都先走同一 OCC 判定。风险等级：中，属于业务天然并发，但当前策略是显式拒旧提交而不是静默覆盖。[BenchOccCommandRegistry.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/bench/BenchOccCommandRegistry.java#L160) [QuickLinkOccSubmissionSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/QuickLinkOccSubmissionSupport.java#L35) [PairingOccSubmissionSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingOccSubmissionSupport.java#L61) [PairingOccSubmissionSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingOccSubmissionSupport.java#L134)
- 方向与覆盖风险：`core` 视角编辑仍通过 `buildChangedCoreTargetsByTriggerSource` 拆回若干 `triggerSource -> core` 正向写入，没有引入反向持久化或整图盲写。风险等级：低。[PairingNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingNetworkServerHandlerSupport.java#L446) [PairingOccSubmissionSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/PairingOccSubmissionSupport.java#L180)
- bench 工具链并发：`RunFunctionalCase -DryRun` 并行共用默认 `SavePath` 时，会在世界清理阶段互删目录，属于脚本运行环境的共享路径竞争，不是 OCC case 语义错误。风险等级：中，建议 dry-run 并发时显式拆分 `-SavePath` 或串行执行。[Bench.World.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.World.ps1#L286)
