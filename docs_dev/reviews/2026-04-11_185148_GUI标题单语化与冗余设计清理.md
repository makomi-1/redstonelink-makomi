## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 兼容性风险低：客户端头部渲染接口和 pairing token 透传都没有回退，只是标题来源从“专用 header 键”改成“既有国际化键”；既有 screen 调用面不受影响。
- 语言切换行为现在符合 Minecraft 常规预期：同一键在 `zh_cn/en_us` 下分别出单语文本，不会再出现中文环境显示英文拼接、英文环境显示中文拼接的问题；这降低了文案维护噪音。
- 残余风险主要在 pairing 具体标题当前复用了 `item.redstonelink.*` 键，前提是对应 item/block 名称继续保持一致；如果未来出现“物品名”和“GUI 标题名”需要故意分离，再单独引入一层 GUI 专用键会更合适。
- 建议后续继续保持“能复用现有国际化键就不新增一层 header 键”的原则，避免 GUI 文案系统再次膨胀。
