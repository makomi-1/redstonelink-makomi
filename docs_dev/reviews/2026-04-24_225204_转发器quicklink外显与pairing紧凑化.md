## 2. 关键数据结构和算法性能分析
- `CachedPreviewOutlineState` 以“维度 + 缓存类型 + 序号表达式 + 玩家区块 + 渲染距离”为键做 6 tick TTL 缓存，避免每帧重复遍历已加载区块，关键结构见 [QuickLinkOutlineRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/QuickLinkOutlineRenderer.java#L338)。
- `scanPreviewOutlineShapes(...)` 只扫描客户端当前已加载区块，并用 `LinkedHashSet` 去重目标序号、用 `Shapes.or(...)` 合并同色 unit cube，能自然消去相连方块的内部边，仅保留最外轮廓，见 [QuickLinkOutlineRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/QuickLinkOutlineRenderer.java#L244)。
- `resolveRepeaterOccTargetType(...)` 采用常量时间映射完成转发器输入/输出配置到 OCC 目标身份的切换，不引入额外图遍历或持久化结构，见 [QuickLinkNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetworkServerHandlerSupport.java#L573)。
- 紧凑布局仍复用原有 `MultiPairingLayout` 记录体，只改 panel 高度和输入区纵向计算，不会引入新的 GUI 状态同步成本，见 [AbstractMultiPairingScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/AbstractMultiPairingScreen.java#L854)。

## 3. 数据流或调用链
- quick-link 应用链路现在为：客户端命中解析 `resolveQuickLinkTarget(...)` → 请求 baseline → 服务端 `resolveRequestedApplyTarget(...)` → `sendApplyBaseline(...)` → 正式 apply → 转发器走 `applyQuickLinkToRepeater(...)`，普通节点仍走 `QuickLinkOccSubmissionSupport.submit(...)`，对应代码见 [QuickLinkNetworkClientHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/network/QuickLinkNetworkClientHandlerSupport.java#L180) 与 [QuickLinkNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetworkServerHandlerSupport.java#L226)。
- 缓存对象外显链路为：渲染事件 `AFTER_TRANSLUCENT` → `resolvePreviewOutlineShapes(...)` → `scanPreviewOutlineShapes(...)` → `LevelRenderer.renderVoxelShape(...)`，见 [QuickLinkOutlineRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/QuickLinkOutlineRenderer.java#L110)、[QuickLinkOutlineRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/QuickLinkOutlineRenderer.java#L176) 与 [QuickLinkOutlineRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/QuickLinkOutlineRenderer.java#L244)。
- 转发器上下文 pairing GUI 链路为：screen `init/render/renderBackground` 统一读取 `layoutDensity()` → `resolveLayout(..., LayoutDensity.COMPACT)` → 去除模式行预留，见 [AbstractMultiPairingScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/AbstractMultiPairingScreen.java#L300)、[AbstractMultiPairingScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/AbstractMultiPairingScreen.java#L347) 与 [AbstractMultiPairingScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/AbstractMultiPairingScreen.java#L394)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议
- 语义兼容性：本轮没有引入旧术语输出，业务语义仍是 `triggerSource/core`；`link_repeater` 只作为 quick-link apply 的内部目标 token 使用，不改变持久化或对外业务命名，相关入口见 [QuickLinkNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetworkServerHandlerSupport.java#L33)。
- 渲染边界：缓存对象预览只覆盖客户端已加载区块，未加载区块中的缓存对象不会显示，这与本轮方案边界一致，但若后续需要“跨未加载区块预告”，需要另行引入服务器同步或 saved-data 投影层，见 [QuickLinkOutlineRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/QuickLinkOutlineRenderer.java#L244)。
- 性能风险：预览扫描仍与玩家渲染距离成平方关系，虽然已加短 TTL 缓存，但超大渲染距离下仍可能有客户端开销；如果后续继续扩展到更多对象类型，建议改为订阅式客户端索引，见 [QuickLinkOutlineRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/QuickLinkOutlineRenderer.java#L176)。
- 回归风险：全量门禁中 `testSlow` 的 [LinkSavedDataPerformanceSlowTest.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/test/java/com/makomi/data/LinkSavedDataPerformanceSlowTest.java#L72) 仍失败，表现为 `save/load` 性能基线超阈值；失败面与本轮 `quick-link / GUI` 改动不直接重叠，但当前工作区不能宣称“全门禁全绿”。建议后续单独排查该慢测环境波动或重新校准基线。残余风险：有。
- API 约束：本轮未新增 `com.makomi.api.v1.*` 依赖。残余风险：无。

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）
- 风险等级：低。服务端 quick-link baseline 与 apply 仍在主线程串行执行，新增逻辑只是在既有主线程路径上补充转发器分支，不引入异步读改写，见 [QuickLinkNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetworkServerHandlerSupport.java#L530)。
- OCC 冲突口径已针对转发器的双身份做显式反向映射，避免把输入配置误按 `triggerSource` 校验、或把输出配置误按 `core` 校验造成覆盖，见 [QuickLinkNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/QuickLinkNetworkServerHandlerSupport.java#L573)。
- 客户端新增的 `cachedPreviewOutlineState` 是渲染线程上的静态短生命周期缓存，不与网络线程共享，也不写入持久化数据；当前没有发现跨线程竞争点，见 [QuickLinkOutlineRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/QuickLinkOutlineRenderer.java#L65)。
- GUI 紧凑布局只改纯函数式布局计算，不额外引入共享可变状态；`CorePairingScreen/TriggerSourcePairingScreen` 仅在读取 display context 后选择 `COMPACT`，无重入风险，见 [CorePairingScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/CorePairingScreen.java#L205) 与 [TriggerSourcePairingScreen.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/screen/TriggerSourcePairingScreen.java#L229)。
