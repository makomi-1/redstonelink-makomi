## 1. 功能与语义、架构设计（关键方法和入口）
- 本轮新增 `C07`，把“玩家上下文命令”和“控制台命令”放在同一 functional case 内编排，先用 `tag + deop/op` 切换玩家权限，再分别断言 `masked` 读控与 `limited/protected` 写控的拒绝/放行结果，覆盖的是“同一主体权限变化后的行为差异”，而不是单纯的配置读写。[server_permission_read_write_basic.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/c07/server_permission_read_write_basic.json#L36) [Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L2330)
- 本轮新增 `C08`，专门验证 `OTHER` 组命令限流在低权限桶内命中、提权后切到更高权限桶后恢复通过，保持与现有限流服务“按权限等级 + 主体身份 + 命令组分桶”的设计一致。[server_permission_rate_limit_basic.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/c08/server_permission_rate_limit_basic.json#L31) [CommandRateLimitService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/CommandRateLimitService.java#L91)
- 新增专项 suite `server-basic-permission.json`，通过 entry 级 `serverConfigOverrides` 固定根命令权限、other 权限、privacy/write control/rate limit 配置，使权限专项与现有 `regression-core/full` 解耦，不改变现有推荐回归入口的执行前提。[server-basic-permission.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/suites/server-basic-permission.json#L1) [functional-matrix.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/functional-matrix.json#L15)

## 2. 关键数据结构和算法性能分析
- 本轮主要新增的是声明式 JSON case/suite，没有引入新的生产算法或持久化结构；运行时仍复用 `command_assert` 的模板展开与上下文包装逻辑，解析成本与 phase 数量线性相关，规模很小，对 bench 自身执行时长影响可控。[Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L2330) [server_permission_read_write_basic.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/c07/server_permission_read_write_basic.json#L36)
- `C08` 的性能意义主要在“验证已有分层限流实现”，而不是新增新的频控算法；现有限流仍是 `HashMap + WindowCounter` 的 O(1) 读写路径，权限变化只会命中新 `tier/actor/actorGroup` 键，不会放大单次命令复杂度。[CommandRateLimitService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/CommandRateLimitService.java#L99) [server-basic-permission.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/suites/server-basic-permission.json#L27)
- `C07` 的读控与写控断言完全复用现有生产语义：读控仍走 `CurrentLinksPrivacyService`，写控仍走 `LinkCommandSupport -> LinkWriteControlService`，因此没有新增线上性能负担，只有测试覆盖增强。[CurrentLinksPrivacyService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CurrentLinksPrivacyService.java#L81) [LinkCommandSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkCommandSupport.java#L66)

## 3. 数据流或调用链
- suite 执行链路为：`server-basic-permission.json` 选择 entry 并注入 `serverConfigOverrides` -> `functional-matrix.json` 解析 case 路径 -> `RunFunctionalCase` 读取对应 `C07/C08` -> `command_assert` 根据 `skipPlayerContext` 决定是借玩家上下文还是直接走控制台上下文执行命令。[server-basic-permission.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/suites/server-basic-permission.json#L8) [functional-matrix.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/functional-matrix.json#L15) [Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L2330)
- `C07` 的关键调用链是：控制台 `mask/protected add` 建立策略前置条件 -> 玩家低权限读取/写入 -> 生产侧分别经过当前连接读控与写控判定 -> 控制台 `op` 后，同一玩家重新执行读取/写入并通过。[server_permission_read_write_basic.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/c07/server_permission_read_write_basic.json#L50) [CurrentLinksPrivacyService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CurrentLinksPrivacyService.java#L99) [LinkCommandSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkCommandSupport.java#L75)
- `C08` 的关键调用链是：低权限玩家重复执行 `node list` -> `CommandRateLimitService.tryAcquireOrSendFailure` 在低权限 `OTHER` 组桶内累计并命中限流 -> 控制台 `op` 后，玩家进入更高权限桶并恢复通过。[server_permission_rate_limit_basic.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/c08/server_permission_rate_limit_basic.json#L45) [CommandRateLimitService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/CommandRateLimitService.java#L105)

## 4. 安全、性能、兼容性、扩展性风险分析与建议
- 安全与兼容性：本轮没有引入 `com.makomi.api.v1.*` 依赖，也没有修改线上业务实现、贴图资源或现有公共 suite，只新增权限专项 case/suite 和文档入口，外部行为风险集中在测试数据本身。[server_permission_read_write_basic.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/c07/server_permission_read_write_basic.json#L2) [server_permission_rate_limit_basic.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/c08/server_permission_rate_limit_basic.json#L2)
- 当前残余风险是 dedicated server 真机实跑仍依赖真实在线玩家；本机已完成 `DryRun` 和 Gradle 全标签测试，但由于缺少可直接复用的 bench client/在线玩家环境，尚未在 dedicated server 上完成最终实跑闭环。建议后续在具备 `-AsPlayer` 的环境下优先跑 `server-basic-permission.json`。 [使用说明.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs_dev/使用说明.md#L134) [使用说明.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs_dev/使用说明.md#L138)
- 扩展性方面，当前 suite 已把读控、写控、限流拆成两个独立 case；后续若要补 `readonly`、`crosschunk.command.permissionLevel` 或更多 `other/link_rw` 分组权限矩阵，可以继续沿用同一 entry 覆盖方式扩展，而不必改 bench 框架。[server-basic-permission.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/suites/server-basic-permission.json#L8)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）
- 共享状态主要来自 dedicated server 的运行时权限状态、tag 状态与命令限流窗口。`C07/C08` 都将这些共享状态限制在“单 case 新档 + 单玩家”范围内，不与现有其它 suite 共享世界数据，风险等级为低。[server_permission_read_write_basic.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/c07/server_permission_read_write_basic.json#L36) [server_permission_rate_limit_basic.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/c08/server_permission_rate_limit_basic.json#L31)
- `skipPlayerContext` 的引入点是现有 bench 框架已有能力，本轮只是显式使用它来切换“玩家命令/控制台命令”，没有新增线程、异步或重入边界；命令仍按 phase 串行执行，风险等级为低。[Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L2330)
- 命令限流自身使用静态内存计数器，但 case 级 dedicated suite 是“每 entry 一个新服务端生命周期”，不会把本轮权限专项的数据污染到其它 case；若后续把该专项并入长生命周期 suite，需要继续保持单 entry 独立配置或显式清空环境。风险等级为中低。[CommandRateLimitService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/CommandRateLimitService.java#L30) [server-basic-permission.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/suites/server-basic-permission.json#L8)
