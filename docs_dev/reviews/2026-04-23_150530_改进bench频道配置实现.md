# 改进bench频道配置实现

## 1. 功能与语义、架构设计（关键方法和入口）

- bench OCC 命令树新增了 `triggerSource/core` 两个批量频道 partition 入口，并统一收敛到 `executeChannelPartitionSubmit(...)`，避免脚本侧继续逐节点调用单条频道提交命令。[BenchOccCommandRegistry.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/bench/BenchOccCommandRegistry.java#L79) [BenchOccCommandRegistry.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/bench/BenchOccCommandRegistry.java#L122) [BenchOccCommandRegistry.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/bench/BenchOccCommandRegistry.java#L426)
- 批量 bench 写入没有新增一套频道真值逻辑，而是直接复用现有 `LinkChannelEditingService.prepareConfirmedBatchSetChannel(...)` / `applyPreparedBatchSetChannel(...)`，保持 `triggerSource/core` 方向语义和普通频道编辑路径一致。[BenchOccCommandRegistry.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/bench/BenchOccCommandRegistry.java#L480) [LinkChannelEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkChannelEditingService.java#L70) [LinkChannelEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkChannelEditingService.java#L181)
- 新增的 bench summary `occ_channel_partition_submit` 把批量规模、频道范围、OCC 结果和变更计数固定成 machine-readable 输出，供脚本和回归结果稳定消费。[BenchOccCommandRegistry.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/bench/BenchOccCommandRegistry.java#L883) [BenchOccCommandRegistry.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/bench/BenchOccCommandRegistry.java#L998)

## 2. 关键数据结构和算法性能分析

- `buildChannelPartitionOverrides(...)` 先一次性把 ordered serial 序列映射成 `ChannelOverride` 列表，再交给批量频道服务处理，使 1024 节点场景从 1024 条 bench 命令收敛成 1 次批量提交，直接降低 RCON 往返和单节点 prepare/apply 开销。[BenchOccCommandRegistry.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/bench/BenchOccCommandRegistry.java#L555) [Bench.FunctionalTrace.Phases.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.Phases.ps1#L554) [Bench.FunctionalTrace.Phases.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.Phases.ps1#L671)
- 批量 prepare 阶段复用了 `BatchTargetResolutionContext` 对同频道 `core` 结果的缓存，避免在大频道覆盖场景里为每个 `triggerSource` 重复重建同一频道目标集合，复杂度明显优于逐节点单发时的重复推导。[LinkChannelEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkChannelEditingService.java#L98) [LinkSavedDataChannelSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataChannelSupport.java#L177) [LinkSavedDataChannelSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataChannelSupport.java#L299)
- 批量结果中继续区分 `changedChannelNodeCount` 与 `changedTriggerSourceCount`，能分别反映“多少节点频道值真的改了”和“多少普通边重排被触发”，便于后续性能分析继续对准真正的写放大来源。[LinkChannelEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkChannelEditingService.java#L422) [LinkChannelEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkChannelEditingService.java#L447) [BenchOccCommandRegistry.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/bench/BenchOccCommandRegistry.java#L998)

## 3. 数据流或调用链

- 当前 `occ_channel_partition` 的调用链变为：phase 收集 serial batch -> 构造一次 bench 批量频道命令 -> `executeChannelPartitionSubmit(...)` -> `submitChannelPartitionBatch(...)` -> `LinkChannelEditingService.prepareConfirmedBatchSetChannel(...)` -> `applyPreparedBatchSetChannel(...)`。[Bench.FunctionalTrace.Phases.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.Phases.ps1#L554) [Bench.FunctionalTrace.Phases.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.Phases.ps1#L669) [BenchOccCommandRegistry.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/bench/BenchOccCommandRegistry.java#L426) [LinkChannelEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkChannelEditingService.java#L181)
- OCC 冲突处理仍然保留在批量提交入口前置环节：整批先逐节点核对 `expectedSourceRevision/expectedCoreRevision`，一旦命中冲突就整体拒绝，不会进入后续批量 prepare/apply。[BenchOccCommandRegistry.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/bench/BenchOccCommandRegistry.java#L480) [LinkOccSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkOccSupport.java#L183)
- bench 结果侧现在能直接观测到 `executedCommandCount=1`，说明同一个 partition phase 已按新调用链完成批量提交，而不是退回逐节点命令。[Bench.FunctionalTrace.Phases.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.Phases.ps1#L671)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 性能收益明确，但当前批量 OCC 语义仍沿用“整批共用一个 expected revision”的约束；这与旧 phase 的逐节点脚本实参保持一致，但若后续要支持混合 revision 批次，需要再扩展参数模型。[BenchOccCommandRegistry.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/bench/BenchOccCommandRegistry.java#L426) [BenchOccCommandRegistry.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/bench/BenchOccCommandRegistry.java#L480)
- 兼容性风险低：旧 `occ_channel_partition` phase 名称和 case JSON 不需要变，只是内部改成发新命令，因此现有 `p27` 场景可以直接复用并通过。[Bench.FunctionalTrace.Phases.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.Phases.ps1#L554) [sync_1024_to_1024_core_channel_banded16_equivalent.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/performance/p27/sync_1024_to_1024_core_channel_banded16_equivalent.json#L33)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- 风险等级低：新批量命令没有引入额外线程或异步队列，仍然在命令执行线程内顺序完成 OCC 校验、batch prepare 和 batch apply，不存在新的跨线程共享状态。[BenchOccCommandRegistry.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/bench/BenchOccCommandRegistry.java#L480) [LinkChannelEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkChannelEditingService.java#L181)
- 读改写覆盖风险低：批量写入先通过 `normalizeOverrides(...)` 对同节点重复覆盖做顺序去重，再计算 `changedOverrides` 与 `preparedOperations`，避免同一批内部自相覆盖导致多次落库。[LinkChannelEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkChannelEditingService.java#L70) [LinkChannelEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkChannelEditingService.java#L248)
- 重入边界清晰：`applyPreparedBatchSetChannel(...)` 先统一写频道配置，再批量 flush 普通边替换结果，未引入新的全局缓存写回点；新加的 `ChannelPartitionBatchSubmissionResult` 也是纯命令期临时结构，不参与世界真值持久化。[LinkChannelEditingService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkChannelEditingService.java#L181) [BenchOccCommandRegistry.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/bench/BenchOccCommandRegistry.java#L998)
