# hide节点命中门槛与箭头增强

## 1. 功能与语义、架构设计

- 本轮把 `hide` 节点的“是否可被普通玩家命中”显式收口成一条规则：只有佩戴智能眼镜的玩家，才会拿到完整交互形状；其他上下文统一视为空形状。共享规则集中在 [HideNodeShapeAccessSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/HideNodeShapeAccessSupport.java#L21)。
- `HideCoreBlock` 与 `HideSyncTriggerSourceBlock` 都把这条规则接到了 `getShape(...)` 与 `getVisualShape(...)`，从而让未戴眼镜的普通准星命中、白框选中与普通破坏路径一并消失；对应入口在 [HideCoreBlock.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/HideCoreBlock.java#L55)、[HideSyncTriggerSourceBlock.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/HideSyncTriggerSourceBlock.java#L47)。
- 启用面箭头仍然留在 `HideNodeGhostRenderer` 内，没有新开世界级扫描器；只是把线渲染层改成了更粗、无深度测试的专用 `RenderType`，并放大箭头几何参数，见 [HideNodeGhostRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/HideNodeGhostRenderer.java#L32)、[HideNodeGhostRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/HideNodeGhostRenderer.java#L42)。

## 2. 关键数据结构和算法性能分析

- 本轮没有新增持久化状态，也没有改动 `triggerSource/core` 图数据；新增的 `HideNodeShapeAccessSupport` 只是一个常数级访问工具，从 `CollisionContext` 解出实体，再判断是否佩戴智能眼镜，见 [HideNodeShapeAccessSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/HideNodeShapeAccessSupport.java#L28)、[HideNodeShapeAccessSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/HideNodeShapeAccessSupport.java#L35)。
- 箭头渲染仍是 `O(enabledFaces)`，每个启用面固定绘制 1 根箭杆和 4 根箭头头部短线，上限 6 面、30 条线段；对应实现见 [HideNodeGhostRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/HideNodeGhostRenderer.java#L145)、[HideNodeGhostRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/HideNodeGhostRenderer.java#L169)、[HideNodeGhostRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/HideNodeGhostRenderer.java#L243)。
- 与上一版相比，本轮主要是把线宽从默认值提升到 `4.0`，并关闭深度测试；这会增加一点点像素填充成本，但只在“佩戴智能眼镜 + 主手面编辑器 + 命中 hide 节点渲染范围内”生效，整体开销仍很低，配置点见 [HideNodeGhostRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/HideNodeGhostRenderer.java#L39)、[HideNodeGhostRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/HideNodeGhostRenderer.java#L49)。

## 3. 数据流或调用链

- 命中链路现在是：客户端射线检测进入 `hide` 方块的 `getShape(...)`，再由 `HideNodeShapeAccessSupport` 判断当前实体是否为佩戴智能眼镜的玩家；通过时返回完整方块形状，否则返回空形状，见 [HideCoreBlock.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/HideCoreBlock.java#L55)、[HideSyncTriggerSourceBlock.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/HideSyncTriggerSourceBlock.java#L47)、[HideNodeShapeAccessSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/HideNodeShapeAccessSupport.java#L28)。
- 显示链路现在是：`HideNodeGhostRenderer.render(...)` 先判断智能眼镜门槛，再渲染幽灵模型，最后在“主手持有面编辑器”时用专用线层绘制启用面箭头；关键入口与门槛见 [HideNodeGhostRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/HideNodeGhostRenderer.java#L67)、[HideNodeGhostRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/HideNodeGhostRenderer.java#L136)。
- 单面箭头的数据流是：读取启用面 -> 计算外伸箭杆 -> 计算头部四向偏移 -> 写入无深度测试线层；对应实现见 [HideNodeGhostRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/HideNodeGhostRenderer.java#L157)、[HideNodeGhostRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/HideNodeGhostRenderer.java#L180)、[HideNodeGhostRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/HideNodeGhostRenderer.java#L217)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全与语义：本轮没有改动 `triggerSource -> core` 写入链，也没有新增 `com.makomi.api.v1.*` 依赖；只是把 `hide` 节点客户端命中门槛收紧到“必须佩戴智能眼镜”。
- 兼容性：未戴眼镜时，`hide` 节点对白框选中和普通准星近似消失，这能避免误破坏与误操作；同时佩戴智能眼镜后仍保留正常编辑/回收入口，对现有玩法兼容性更好。
- 性能：本轮全量回归已通过，包含 `testSlow`；说明新增 shape 判断和箭头渲染没有压坏既有基线。由于箭头只在特定交互语境下出现，其实际渲染面很窄。
- 扩展性：`HideNodeShapeAccessSupport` 可继续被后续的香草编辑工具、红石场发生器托管节点复用；同样，`HideNodeGhostRenderer` 的专用线层也可以继续拿去渲染可见节点的面向量提示，入口分别见 [HideNodeShapeAccessSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/HideNodeShapeAccessSupport.java#L21)、[HideNodeGhostRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/HideNodeGhostRenderer.java#L42)。

## 5. 并发冲突审查

- 共享状态：新增的 `HideNodeShapeAccessSupport` 无可变状态，只做纯读取判断，见 [HideNodeShapeAccessSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/HideNodeShapeAccessSupport.java#L21)。
- 读改写覆盖：方块 shape 入口只读取 `CollisionContext` 与玩家装备状态，不写世界状态；箭头渲染也只读 `BlockState` 和主手物品，不写客户端缓存，因此不存在读改写覆盖风险，见 [HideNodeShapeAccessSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/HideNodeShapeAccessSupport.java#L35)、[HideNodeGhostRenderer.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/render/HideNodeGhostRenderer.java#L145)。
- 重入/线程边界：`getShape(...)` 属于同步世界查询；`HideNodeGhostRenderer.render(...)` 属于客户端渲染线程。本轮没有引入异步任务、全局缓存写入或跨线程回调；并发风险低。
- 风险等级：低。主要剩余风险只在游戏内观感微调，而非状态一致性或线程安全。
