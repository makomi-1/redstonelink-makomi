## 2. 关键数据结构和算法性能分析
- `x49` 仍沿用 3 节点定长布局，性能开销主要来自常量数量的 `setblock/forceload/node get` phase，新增用例不会改变 bench 的复杂度阶；相关布局与预加载窗口见 [chunk_activator_resident_union_trigger_source_core.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x49/chunk_activator_resident_union_trigger_source_core.json#L7)、[chunk_activator_resident_union_trigger_source_core.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x49/chunk_activator_resident_union_trigger_source_core.json#L27)、[chunk_activator_resident_union_trigger_source_core.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x49/chunk_activator_resident_union_trigger_source_core.json#L38)。
- `x50` 的关键性能点在于用 stepped cuboid 稀疏布局，把 3 个 core 拉开到每隔 4 个 chunk，避免 resident 票据加载半径互相串扰；这仍然只生成 3 个目标节点，放置和序号探测保持 O(节点数)；相关定义位于 [chunk_activator_resident_core_nodeset_reconcile.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x50/chunk_activator_resident_core_nodeset_reconcile.json#L7)、[chunk_activator_resident_core_nodeset_reconcile.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x50/chunk_activator_resident_core_nodeset_reconcile.json#L42)、[chunk_activator_resident_core_nodeset_reconcile.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x50/chunk_activator_resident_core_nodeset_reconcile.json#L49)。
- `x50` 同时将 bench force-load 拆成 4 段独立 chunk，避免把未观测节点误留在同一连续票据区内；相关配置见 [chunk_activator_resident_core_nodeset_reconcile.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x50/chunk_activator_resident_core_nodeset_reconcile.json#L7)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议
- 这两类用例都用“节点 online/offline”作为 resident 贡献的外部观测口径，因此布局必须显式规避 chunk ticket 加载半径串扰；`x49` 通过收紧预加载范围去掉额外 chunk，`x50` 通过 4-chunk 间隔稀疏布局规避串扰，相关实现位于 [chunk_activator_resident_union_trigger_source_core.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x49/chunk_activator_resident_union_trigger_source_core.json#L7)、[chunk_activator_resident_core_nodeset_reconcile.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x50/chunk_activator_resident_core_nodeset_reconcile.json#L7)、[chunk_activator_resident_core_nodeset_reconcile.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x50/chunk_activator_resident_core_nodeset_reconcile.json#L49)。
- `x50` 依赖 `data merge block` 后再触发一次非供能邻居更新，以把新 NBT 重同步到已放置激活器真值；如果未来区块激活器引入更直接的配置变更事件，这一刷新 phase 可以收敛掉；当前实现位于 [chunk_activator_resident_core_nodeset_reconcile.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x50/chunk_activator_resident_core_nodeset_reconcile.json#L158)、[chunk_activator_resident_core_nodeset_reconcile.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x50/chunk_activator_resident_core_nodeset_reconcile.json#L169)。
- 扩展建议：后续若继续补区块激活器 resident 类 dedicated 用例，优先复用“独立 bench force-load 分段 + 稀疏 stepped layout”模式；若后续新增 bench 调试命令，可直接断言激活器 resident 聚合集合，降低对在线态口径的依赖。参考 [chunk_activator_resident_core_nodeset_reconcile.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x50/chunk_activator_resident_core_nodeset_reconcile.json#L7)、[chunk_activator_resident_core_nodeset_reconcile.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/functional/x50/chunk_activator_resident_core_nodeset_reconcile.json#L49)。
