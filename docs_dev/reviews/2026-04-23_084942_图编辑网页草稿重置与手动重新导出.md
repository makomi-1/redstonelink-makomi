## 1. 功能与语义、架构设计（关键方法和入口）

本轮在 graph 编辑页补了两个显式入口：`重置草稿` 和 `重新导出最新 graph`。前者用于强制删除当前 graph 对应的本地 draft 文件并把页面回退到当前基线图，后者用于在游戏里的 graph 已变化后，手动重新导出并载入最新 graph，同时先清掉当前草稿，避免旧 draft 污染新基线。核心入口都集中在 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1925) 与 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1966)，按钮挂载在 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2606) 和 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2622)。

架构上没有新增后端接口，继续复用已有 `/api/graph/refresh` 与 graph draft 删除链路，只是在前端把原本隐式的“草稿为空时才自动 DELETE”补成了用户显式可触发的清理动作。显式删除 helper 放在 [draft.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.ts#L655)，而已有加载/持久化路径仍保留在 [draft.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.ts#L612) 和 [draft.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.ts#L632)。

## 2. 关键数据结构和算法性能分析

这次没有引入新的复杂数据结构，重点是把“草稿状态重置”和“graph 基线替换”做成稳定的状态收口函数。`resetDraftStateToBaseGraph(...)` 在 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1864) 统一清理内存草稿、撤销历史、预检状态和批量选择状态，避免多个按钮各自拼状态清理逻辑。`applyRefreshedGraphEntry(...)` 在 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1886) 统一负责解析刷新回来的最新 graph 条目并替换当前基线。

性能上两条新交互都只是单次 HTTP 请求：重置草稿只触发一次 draft `DELETE`，重新导出则是一次 draft `DELETE` 加一次已有的 `/api/graph/refresh`。它们不会改变原有 graph 渲染复杂度，也不会引入轮询或持续订阅，因此额外成本是常量级。相关网络调用落在 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1921) 和 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1990)。

## 3. 数据流或调用链

草稿重置链路是：用户点击 `重置草稿` -> [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1925) 确认是否丢弃未保存草稿 -> `resetCurrentDraft(...)` 在 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1917) 先把页面回退到当前基线图，再调用 [draft.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/draft.ts#L655) 显式删除当前 draft 文件。

手动重新导出链路是：用户点击 `重新导出最新 graph` -> [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1966) 在必要时先确认并清掉当前草稿 -> 调用现有 refresh API -> 由 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1886) 解析并替换基线图。保存成功后的既有 refresh 分支也复用了同一个基线替换 helper，见 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2455)。自动化验证补在 [GraphViewer.test.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.test.tsx#L469) 与 [GraphViewer.test.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.test.tsx#L617)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

安全与兼容性方面，本轮没有改动 `triggerSource/core` 语义，也没有改变后端 graph refresh 协议，只是新增前端显式入口，因此对现有网络协议和存档结构没有兼容性风险。用户风险主要是“误点后丢失未保存草稿”，这已经通过确认框拦住，见 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1930) 和 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1971)。

仍然存在的边界是：网页端目前不会因为游戏内 graph 变化而自动推送刷新，这次只补了手动重新导出入口，没有引入自动轮询或自动重载。这样做的好处是不会和未保存草稿产生静默冲突；如果后续确实需要自动同步，建议在现有显式 refresh 入口的基础上再加“只在没有脏草稿时自动刷新”的策略，而不要直接做无条件自动重载。

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

这次的并发风险主要在前端本地状态重入：如果用户在保存、重置草稿和重新导出之间连点，可能互相覆盖 `graphDraft`、`saveMessage` 和预检状态。为此本轮增加了 `graphSyncPhase`，统一把“重置中/刷新中”视为忙态，再和 `savePhase === "saving"` 合并成 `graphActionBusy`，相关保护在 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L358) 与 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L2600)。

共享状态层面没有新增跨页面的全局可变缓存，所有改动都限制在当前 `GraphViewer` 组件内，风险等级评估为“低”。唯一需要注意的是：`resetCurrentDraft(...)` 会先在内存里清空草稿，再请求删除本地 draft 文件，相关顺序在 [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L1917)；如果删除失败，页面仍会回到干净基线，但会通过错误消息保留失败信息。这个折中是合理的，因为它优先保证当前交互不会继续带着脏草稿污染后续操作。
