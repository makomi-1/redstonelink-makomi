## 1. 功能与语义、架构设计（关键方法和入口）

- 本轮新增共享支撑 `PlacedPairableNodeGuiOpenSupport`，把“已放置节点 reopen GUI 前的 serial 自愈”收口到一个服务端 helper 中，统一复用现有放置链路的 serial 解析规则，而不是在五个方块里继续各写一套 `serial <= 0` 判断。[PlacedPairableNodeGuiOpenSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/PlacedPairableNodeGuiOpenSupport.java#L19)
- `core` 侧两个 GUI 打开入口已经统一改为通过共享 helper 解析 reopen 时的有效 serial，再继续调用配对网络打开界面；其中普通核心走 [LinkCoreBlock.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/LinkCoreBlock.java#L172)，红石粉核心走 [LinkRedstoneDustCoreBlock.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/LinkRedstoneDustCoreBlock.java#L278)。
- `triggerSource` 侧三个 GUI 打开入口同样统一接线到该 helper，避免按钮、发射器、同步拉杆各自保留旧分支。[LinkButtonBlock.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/LinkButtonBlock.java#L151) [LinkSignalEmitterBlock.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/LinkSignalEmitterBlock.java#L168) [LinkSyncLeverBlock.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/LinkSyncLeverBlock.java#L190)
- 语义上仍保持 `triggerSource/core` 二分，不新增反向路径，也没有修改网络层 payload、客户端 GUI 或命令退役语义；只是让“已放置节点 reopen GUI”与既有“物品 ensure / 放置 resolve”保持一致。[LinkSavedData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedData.java#L111)

## 2. 关键数据结构和算法性能分析

- 关键数据结构仍是 `LinkSavedData` 内的已分配 serial 集、retired serial 集与在线节点映射；新 helper 不引入新的持久化结构，只复用既有治理数据。[LinkSavedData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedData.java#L111)
- reopen 时的核心算法仍由 `resolvePlacementSerial(...)` 承担：先判定“未分配 / 已退役”，再补登记分配集合，最后检查当前位置冲突，整体是常数次集合/映射访问，没有新增遍历型热路径。[LinkSavedDataSerialSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataSerialSupport.java#L34)
- 只有当解析结果与当前 block entity serial 不一致时，helper 才调用 `setLinkData(...)` 触发注销旧节点、注册新节点与客户端同步，避免每次打开 GUI 都做无意义回写。[PlacedPairableNodeGuiOpenSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/PlacedPairableNodeGuiOpenSupport.java#L35) [PairableNodeBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/PairableNodeBlockEntity.java#L86)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全性：本轮没有引入外部输入拼接、权限放宽或新网络入口，风险主要仍是服务端本地状态修复，未看到新增安全面。[PlacedPairableNodeGuiOpenSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/PlacedPairableNodeGuiOpenSupport.java#L35)
- 性能：helper 只在玩家主动打开 GUI 时执行，不在 tick 热路径循环触发；其内部也只做常量级查表与必要时一次 `setLinkData(...)`，性能风险低。[LinkSavedDataSerialSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedDataSerialSupport.java#L34)
- 兼容性：`LinkRedstoneDustCoreBlock.tick()` 里的 `ensureCoreSerialAssigned(...)` 仍保持“只补未分配 serial”的旧职责，没有顺手扩大成“后台自动修 retired”；本轮刻意把修复范围限制在“reopen GUI 时自愈”，避免改变非 GUI 场景的既有行为。[LinkRedstoneDustCoreBlock.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/LinkRedstoneDustCoreBlock.java#L262) [LinkRedstoneDustCoreBlock.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/LinkRedstoneDustCoreBlock.java#L300)
- 扩展性：后续若还有其他“已放置节点打开 GUI”入口，只需复用 `PlacedPairableNodeGuiOpenSupport`，不需要再复制 serial 判定逻辑；这是本轮最主要的可维护性收益。[PlacedPairableNodeGuiOpenSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/PlacedPairableNodeGuiOpenSupport.java#L19)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- 共享状态主要是 `LinkSavedData` 内的 serial 分配/retired/在线节点登记，以及 `PairableNodeBlockEntity` 自身的 `serial` 字段；本轮没有新增第二份缓存或镜像状态，仍沿用单一真值源。[LinkSavedData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkSavedData.java#L111) [PairableNodeBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/PairableNodeBlockEntity.java#L86)
- 读改写覆盖方面，helper 先解析 serial，再仅在 serial 发生变化时调用 `setLinkData(...)`；而 `setLinkData(...)` 本身已先注销旧节点再注册新节点，能够避免同一方块实体残留旧映射。风险等级：低。[PlacedPairableNodeGuiOpenSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/PlacedPairableNodeGuiOpenSupport.java#L35) [PairableNodeBlockEntity.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/PairableNodeBlockEntity.java#L86)
- 线程边界方面，入口都在服务端玩家交互路径中执行，本轮未引入异步任务、并行集合或跨线程回调；与现有 `LinkSavedData` / block entity 使用方式保持一致。建议继续维持“所有 serial 自愈都走服务端主线程入口”的约束，不要在客户端或异步线程复制这套修复逻辑。[LinkCoreBlock.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/LinkCoreBlock.java#L172) [LinkButtonBlock.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/LinkButtonBlock.java#L151)
