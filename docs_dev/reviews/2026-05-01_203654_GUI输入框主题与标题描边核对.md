## 2. 关键数据结构和算法性能分析

- `StyledMultiLineEditBox.Style` 继续作为主题参数载体，仅保存背景色、边框色、聚焦边框色和计数字色，新增装饰层渲染不会引入额外状态同步复杂度。[StyledMultiLineEditBox.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/screen/StyledMultiLineEditBox.java#L71)
- 容量计数计算仅基于 `box.getValue().length()` 和 `font.width(counterText)` 做 O(n) 文本宽度测量，其中 n 为计数字串长度，常数极小，且只在 GUI 渲染帧内按单控件执行，不构成热点。[ShadowlessCounterMultiLineEditBox.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/screen/ShadowlessCounterMultiLineEditBox.java#L70)
- 主题边框绘制只新增两次 `fill` 调用，属于纯矩形批次；相较旧版子类覆写没有额外布局或遍历成本。[StyledMultiLineEditBox.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/screen/StyledMultiLineEditBox.java#L50)
- 无阴影 hint 的判断链为常量时间，仅在输入为空、未聚焦、控件可见时补画一次文本，不会放大现有输入性能开销。[StyledEditBox.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/screen/StyledEditBox.java#L120)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 兼容性核心差异已确认：26.1 的 `MultiLineEditBox` 构造器为私有，无法按 1.21.11 那种同包子类方式接管 `extractDecorations`，因此本轮改成屏幕层装饰是基于版本机制差异的必要迁移，不是行为偏离。[ShadowlessCounterMultiLineEditBox.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/screen/ShadowlessCounterMultiLineEditBox.java#L11)
- 当前屏幕层主题壳依赖界面在 `extractBackground` 中主动补画；若后续新增新的多行输入框界面但未复用这套装饰调用，可能回退到原版无主题表现。建议后续新增界面时复用同一模式，或再收敛出更高层的统一 helper。[QuickLinkToolScreen.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/screen/QuickLinkToolScreen.java#L318)
- 标题描边方面，26.1 底层虽存在 `drawInBatch8xOutline`，但在当前 `GuiGraphicsExtractor` 抽取链下缺少稳定安全的直达调用面；强行改接更底层 buffer 路径存在标题丢失或渲染层错乱风险，因此本轮保留四向轻描边。残余风险为极少数字体下视觉厚度仍不及 8 向描边，但当前稳定性优先级更高。[GuiTitleRenderSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/screen/GuiTitleRenderSupport.java#L62)
- 语义方面未触碰 `triggerSource/core` 方向约束、命名和 payload 结构，仅限 GUI 皮肤与文本表现层，无业务语义扩散风险。[AbstractMultiPairingScreen.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/screen/AbstractMultiPairingScreen.java#L559)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- 本轮改动全部位于客户端 GUI 渲染与控件状态层，执行线程仍是客户端渲染线程，未新增后台线程、异步回调或跨线程共享容器。风险等级：低。[QuickLinkToolScreen.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/screen/QuickLinkToolScreen.java#L154) [StyledEditBox.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/screen/StyledEditBox.java#L81)
- `shadowlessHint` 仅在 `setHint` 和同线程渲染阶段读写，不存在竞态写覆盖；多行输入框装饰也只读取控件当前快照值，不会回写业务状态。风险等级：低。[StyledEditBox.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/screen/StyledEditBox.java#L50) [ShadowlessCounterMultiLineEditBox.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/screen/ShadowlessCounterMultiLineEditBox.java#L70)
- 各界面对输入框的背景与计数补画是纯幂等读取操作，即使在 resize / re-init 后重复执行也不会覆盖其他共享状态。风险等级：低；建议保持“构造控件只负责行为，屏幕层负责装饰”的职责边界，避免未来再次把状态和绘制逻辑耦合回控件内部。[AbstractMultiPairingScreen.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/screen/AbstractMultiPairingScreen.java#L790)
