## 1. 功能与语义、架构设计（关键方法和入口）

- 本次修复没有改 graph 数据结构和保存语义，而是针对 `ReactFlow` 渲染入口做最小修复：`GraphViewer` 仍然以 `effectiveGraphBundle` 生成节点和边，但在图实例就绪后增加一次自动 `fitView`，确保首帧能把图带入可见区域。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L563) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L580) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L609) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L856)
- 画布容器 `.graph-canvas` 改为显式高度容器，不再只依赖 `min-height`。这样 `ReactFlow` 的内部 100% 高度布局能获得稳定的父容器尺寸，避免图层不渲染而外侧普通 DOM 仍正常的情况。[app.css](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L800)
- 整体架构仍保持原状：外层 `GraphViewer` 负责 graph 页面渲染和交互，`ReactFlow` 负责图层显示，CSS 负责画布可见区域尺寸；本次只修 UI 渲染层，不碰保存链路或 `triggerSource/core` 语义层。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L444) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L845) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L856)

## 2. 关键数据结构和算法性能分析

- 本轮没有新增持久化结构或协议，只复用已有 `nodes`、`edges` 和 `reactFlowInstance` 状态，因此性能影响集中在新增的一次 `fitView` 调用，而不是数据规模变化。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L460) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L461)
- 自动归位 effect 只依赖 `draftLoading`、`reactFlowInstance`、`graphBundle.snapshotId` 和节点数量，不跟随节点拖拽位置状态反复触发，因此不会在用户拖动画布或节点时持续抢夺视口控制权。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L609)
- CSS 显式高度采用 `clamp(680px, 72vh, 920px)`，用固定下限保证桌面端可视化区域足够大，用视口比例保持不同屏幕高度下的稳定性，再用上限避免极高屏幕下无意义拉长。这个策略比单纯 `min-height` 更利于 `ReactFlow` 正确计算尺寸。[app.css](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L800)

## 3. 数据流或调用链

- graph 数据仍按原链路流入：`graphBundle` 进入 `GraphViewer` 后，先根据有效图数据生成初始节点和边，再同步更新搜索和详情使用的同一份 `effectiveGraphBundle`。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L449) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L468) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L567)
- 新增调用链是在图数据和实例都准备好后，浏览器通过 `requestAnimationFrame` 延后一帧调用 `reactFlowInstance.fitView(...)`。这一步把“数据已生成但画布未稳定布局”的窗口期避开，从而让图层首次进入可见区域。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L609)
- 样式层调用链则是 `graph-canvas -> react-flow`：父容器先建立真实高度，内部 `ReactFlow` 画布再填满该区域并显示节点、边、背景网格和控件。[app.css](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L800) [app.css](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L812) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L845)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全方面，本轮未触及服务端和写入链路，不引入新的权限面或数据注入面。风险等级低。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L609)
- 性能方面，新增 `fitView` 只在图实例初始稳定时触发一次，成本可控；但如果后续 graph 页面引入更复杂布局或超大图，仍建议保留“只在首次稳定时自动归位”的策略，避免把自动聚焦绑到所有节点变化上。风险等级低。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L609)
- 兼容性方面，显式高度能稳定桌面端渲染，但在极小视口下会让页面整体更高并产生滚动条；当前这是可接受取舍，因为首要目标是保证图层可见。后续若要进一步优化窄屏体验，可在媒体查询中对 graph 专门降低高度下限。[app.css](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L800)
- 扩展性方面，本次修复没有和具体 graph 模式耦合，后续无论继续 `serial` 还是扩展 `channel`，都可以复用这套“父容器明确高度 + 首帧自动归位”的渲染基座。风险等级低。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L845) [app.css](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L800)
