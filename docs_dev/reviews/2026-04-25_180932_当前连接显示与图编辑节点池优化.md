## 2. 关键数据结构和算法性能分析
- `CurrentLinksDisplayFormatUtil` 以对齐后的 `(serial, displayText)` 条目线性扫描构建分段，时间复杂度为 `O(n)`，只在纯 `#序号` 且连续时合并为 `#A:#B`，对别名节点直接落单，逻辑简单且可预测。[CurrentLinksDisplayFormatUtil.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/util/CurrentLinksDisplayFormatUtil.java#L32) [CurrentLinksDisplayFormatUtil.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/util/CurrentLinksDisplayFormatUtil.java#L214)
- 多行 tooltip 的换行与剩余数量追加同样按分段线性处理，没有引入额外排序或图遍历；单段截断时通过本地 helper 预留 suffix 空间，避免产生错误的 `(+n)` 展示。[CurrentLinksDisplayFormatUtil.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/util/CurrentLinksDisplayFormatUtil.java#L155) [CurrentLinksDisplayFormatUtil.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/util/CurrentLinksDisplayFormatUtil.java#L273)
- 孤立转发器池直接复用 `resolvedRepeaterNodes`，按 `connectedNodeKeys.length === 0` 过滤，无需再重复扫描原始边集，增量成本很低。[canvas.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/graphViewer/canvas.tsx#L1298)
- 录制曲线 tooltip 仅放宽固定宽度和 CSS 布局，没有引入测量循环或 DOM 读写反馈；JS 仍沿用常量宽度做位置钳制，保持实现稳定。[RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L73) [app.css](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L1867)

## 4. 安全、性能、兼容性、扩展性风险分析与建议
- 兼容性：新格式化工具对展示文本数量不匹配的旧快照会回退为 `#序号`，因此不会因旧 NBT 或旧同步包缺字段而炸掉展示层，风险低。[CurrentLinksDisplayFormatUtil.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/util/CurrentLinksDisplayFormatUtil.java#L214)
- 扩展性：当前“纯序号可压缩”的识别规则基于 `^#(\\d+)$`，如果未来出现新的纯序号显示样式，需要只改这一处解析规则即可，不必改所有 GUI/HUD 入口。[CurrentLinksDisplayFormatUtil.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/util/CurrentLinksDisplayFormatUtil.java#L297)
- 前端可用性：孤立池切换按钮当前把数量拼进按钮文本，测试稳定，但若未来要做更复杂国际化，建议把数量拆成独立 badge，降低选择器和文案耦合。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L3088)
- 性能回归验证：本轮首次全量回归曾出现 `testSlow` 的单次性能基线抖动，后续单测复核与全量重跑均通过，说明当前更偏向环境抖动而非功能退化；后续如果该慢测继续波动，建议单独审视基线阈值或运行环境噪声。
