## 1. 功能与语义、架构设计

- 本次重构把原先超长的 `Invoke-FunctionalPhases` 收敛为“初始化执行状态 -> 遍历 phase -> 调用分发器 -> 写回结果”的薄入口，核心入口职责明显单一，见 [Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L3558)。
- 新增 `New-FunctionalPhaseExecutionState`、`Add-FunctionalCheck`、`Resolve-FunctionalPhaseSerialContext`，把连接、serial map、check 集合、phase 上下文等共享依赖集中管理，避免 handler 之间重复拼装同类状态，见 [Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L1848) 、[Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L1868) 、[Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L1884)。
- phase 分发从大 `switch` 主体迁移到独立 `Invoke-FunctionalPhaseHandler`，高复杂度 phase 如 `command_assert`、`trace_read_tick_assert`、`trace_sync_latency_collect` 也分别独立成函数，保持了原有 phaseResult / check 结构不变，见 [Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L2401) 、[Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L2884) 、[Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L3160) 、[Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L3532)。

## 2. 关键数据结构和算法性能分析

- 执行态仍然沿用 `System.Collections.Generic.List[object]` 累积 `checks` / `failedChecks` / `phaseResults`，没有引入额外的高频复制；共享状态只是从散落变量收敛到执行上下文对象，性能复杂度未提升，见 [Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L1848) 、[Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L3558)。
- `trace_mount`、`trace_unmount`、`trace_sync_latency_collect` 的批处理分段、暂停间隔、sample 汇聚逻辑均保持原样，只是迁移到独立 handler，因此时间复杂度仍主要由 serial 数量、chunkSize 和 RCON 往返次数决定，见 [Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L1901) 、[Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L1967) 、[Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L3160)。
- `trace_read_tick_assert` 仍保留按容量渐进扩张 trace read limit 的策略，没有因为拆函数改变搜索窗口或匹配算法；这一点对避免大容量 trace 读取时的无谓放大很关键，见 [Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L2884)。

## 3. 数据流或调用链

- 总调用链现在是：`Invoke-FunctionalPhases` 初始化执行状态后遍历 case phase，调用 `Invoke-FunctionalPhaseHandler` 做 kind 分发，再通过 `Add-FunctionalPhaseResult` 写回结果和 phase name 索引，见 [Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L3558) 、[Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L3532) 、[Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L1231)。
- 需要 phase 间引用的逻辑仍通过 `Resolve-FunctionalPhaseResult` 读取共享 phaseContext，例如 `trace_read_tick_assert` / `trace_sync_latency_collect` 继续从 `mountRef`、`anchorRef`、`referencePhaseRef` 回查前置 phase 结果，见 [Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L1250) 、[Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L2884) 、[Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L3160)。
- check 数据流现在统一经过 `Add-FunctionalCheck`，把“登记全部检查项”和“登记失败项”两条支路放在同一入口，减少不同 handler 手写漏记风险，见 [Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L1868)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 兼容性方面，本次没有调整 phase kind、命令文本、result 字段名、DryRun 行为和 check 结构，已通过 dedicated regression full suite 做了实际运行回归；兼容风险主要从“语义改动”转为“后续新增 handler 是否忘记接入分发器”，见 [Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L3532)。
- 运行环境方面，Windows PowerShell 5.1 对无 BOM `.ps1` 文件中的非 ASCII 注释存在解析兼容性风险，本次已把相关注释改为 ASCII；后续对 bench `.ps1` 继续演进时应优先保持 ASCII 注释并补真实点载 smoke，见 [Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L1848)。
- 扩展性方面，新 phase 只需新增独立 handler 并在分发器补一条映射即可；建议后续若再增加多类 phase，可继续按“命令执行型 / 断言型 / 采集型”分组，而不是回退到单函数堆叠，见 [Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L3532)。

## 5. 并发冲突审查

- 当前 bench functional 执行链路仍是单线程顺序执行；`checks`、`failedChecks`、`phaseContext` 和 `phaseResults` 虽然被收敛进执行上下文，但底层仍是普通 `List` / `Hashtable`，默认并不具备并发安全性，见 [Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L1848) 、[Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L3558)。
- 本次实现没有引入新的异步、后台 job 或并发写入，因此共享状态的线程边界与重入语义保持原样，当前风险等级为“低”。
- 若后续要把 phase 执行并行化，必须先替换 `List` / `Hashtable` 为并发安全容器，或显式拆分每个 phase 的局部结果后再统一归并；否则 `Add-FunctionalCheck` / `Add-FunctionalPhaseResult` 会成为直接的数据竞争点，见 [Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L1868) 、[Bench.FunctionalTrace.ps1](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/lib/Bench.FunctionalTrace.ps1#L1231)。
