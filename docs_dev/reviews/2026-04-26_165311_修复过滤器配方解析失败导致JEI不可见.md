这里没有引入新的运行时数据结构，核心变化只是静态资源 JSON 和 datagen 生成逻辑。运行时配方加载仍由 Minecraft 原生 `RecipeManager` 完成，复杂度与之前一致；datagen 侧仅新增两个常规 `ShapedRecipeBuilder` 路径，不会引入可感知性能开销。[RedstoneLinkRecipeProvider.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/datagen/RedstoneLinkRecipeProvider.java#L148) [RedstoneLinkRecipeProvider.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/datagen/RedstoneLinkRecipeProvider.java#L165)

## 3. 数据流或调用链

修复后的调用链是：datagen 源按独立过滤器模板定义配方 -> 运行时资源使用同样的 shaped 结构 -> Minecraft 启动时成功解析这两个 recipe -> JEI 从已加载的 `RecipeManager` 结果中展示配方。之前断链点在运行时 JSON 的 ingredient 格式，导致配方根本未进入 `RecipeManager`，JEI 自然无从显示。[RedstoneLinkRecipeProvider.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/datagen/RedstoneLinkRecipeProvider.java#L50) [RedstoneLinkRecipeProvider.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/datagen/RedstoneLinkRecipeProvider.java#L158) [link_send_filter.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/data/redstonelink/recipe/link_send_filter.json#L18) [link_receive_filter.json](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/resources/data/redstonelink/recipe/link_receive_filter.json#L18)
