# 录制曲线页新增阶跃式显示模式

## 1. 功能与语义、架构设计

- 本轮在录制页面的共享类型层新增了 `RecordingChartRenderMode = 'linear' | 'stepped'`，把“折线/阶跃”限定为显式枚举，避免页面状态与图表组件之间继续使用字符串散落传递。[recordingTypes.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/recordingTypes.ts#L3)
- 查看页入口 `RecordingViewer` 新增全局渲染模式状态，并通过工具栏“显示”行提供 `折线 / 阶跃` 切换，再把该状态透传给 `RecordingChart`，保持模式切换只在页面状态层发生一次，不侵入录制数据结构。[RecordingViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingViewer.tsx#L42) [RecordingViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingViewer.tsx#L362) [RecordingViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingViewer.tsx#L391)
- 图表组件 `RecordingChart` 新增 `renderMode` 参数，并在构造 `uPlot.Series` 时为每条功率曲线按模式决定是否挂载阶跃路径构造器，原有 Input/Output 配色、虚线样式和时间窗恢复逻辑保持不变。[RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L24) [RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L145) [RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L167) [RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L178)

## 2. 关键数据结构和算法性能分析

- 关键新增数据结构只有一个前端枚举类型 `RecordingChartRenderMode`，不引入新的录制文件字段、样本数组格式或持久化结构，因此不会增加录制文件体积，也不会影响现有 JSON 解析流程。[recordingTypes.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/recordingTypes.ts#L3)
- 图表重建阶段仍沿用原有流程：先收集全部横坐标、再对每个节点构造输入/输出数组，时间复杂度仍主要受“选中节点数 × 样本数”影响。本轮只是为每条 `series` 附加可选 `paths`，没有改变核心复杂度。[RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L126) [RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L147)
- 阶跃路径选择通过 `resolveSeriesPathBuilder` 统一封装，避免在每条曲线对象上重复散写条件逻辑，保持构造过程可读且后续若扩展更多模式也只需增量修改这一处路由点。[RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L387)

## 3. 数据流或调用链

- 用户在 `RecordingViewer` 工具栏点击“折线/阶跃”按钮，更新 `recordingChartRenderMode` 页面状态。[RecordingViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingViewer.tsx#L362)
- `RecordingViewer` 将当前模式作为 `renderMode` prop 传给 `RecordingChart`，不改变 `recordingWindow`、`visibleRecordingMetrics` 和 `recordingXAxisMode` 这些既有状态的职责边界。[RecordingViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingViewer.tsx#L391)
- `RecordingChart` 在 `useEffect` 的图表重建阶段读取 `renderMode`，通过 `resolveSeriesPathBuilder` 选出默认折线或阶跃路径，再生成新的 `uPlot` 实例，并在重建后继续回灌当前时间窗，防止模式切换时把可视窗口打回异常小范围。[RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L145) [RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L183) [RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L227)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全性方面，本轮没有引入外部输入执行、文件写回或网络请求，风险主要限于前端显示正确性，等级低。
- 性能方面，阶跃模式复用了 `uPlot` 内置路径构造器，没有新增额外数据预处理循环；在当前“最多五个节点同坐标系”约束下，性能风险低。[RecordingViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingViewer.tsx#L16)
- 兼容性方面，旧录制文件无需迁移，因为模式状态完全留在前端运行时；构建验证已通过 `npm run build` 与 `.\gradlew.bat test testIntegration testClient testSlow --no-daemon`。
- 扩展性方面，`resolveSeriesPathBuilder` 已把渲染模式路由集中化，后续如果继续加入例如平滑曲线或柱状模式，可优先在该函数内扩展，避免继续膨胀 `series.push(...)` 分支。[RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L387)
- 残余建议：当前阶跃模式使用 `align: 1`，语义上更接近“当前采样值保持到下一个 tick 再跳变”；若后续用户希望改成“左对齐保持”或“边界延伸到视窗末端”，可继续在这里补充可配置项。[RecordingChart.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L394)
