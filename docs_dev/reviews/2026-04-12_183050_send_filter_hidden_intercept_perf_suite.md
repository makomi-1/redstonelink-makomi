## 1. 功能与语义、架构设计
- 本轮将设计空白的 send 过滤器隐藏拦截态沉淀为三组 `performance case`，分别覆盖持久高电平、`2 tick` 方波输入和“重进持久输入世界”三条路径；三个 case 统一保持最小 `triggerSource -> core` 拓扑，并把 send filter 的 `nodeSetMode=blocklist + signalThresholdSource=neighbor_max_input + signalMode=upper_bound` 固定为边界触发条件。[persistent case](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/performance/p27/send_filter_hidden_intercept_persistent_sync.json#L2) [persistent case](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/performance/p27/send_filter_hidden_intercept_persistent_sync.json#L46) [square case](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/performance/p27/send_filter_hidden_intercept_sync_square_2tick.json#L2) [reload case](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/performance/p27/send_filter_hidden_intercept_reload_replay.json#L2)
- suite 层把 `a -> b -> c` 编排固定下来，其中 `c` 通过 `reuseWorldFrom` 明确复用 `a` 的世界态，保证“重进 a”不是重新摆放新档，而是重启同一物理世界继续观察。[suite](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/suites/send-filter-hidden-intercept-perf.json#L3) [suite](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/suites/send-filter-hidden-intercept-perf.json#L11)
- 新场景已接入 `crosschunk-stress` 矩阵，并在使用说明中明确其验收口径只看 spark，不把功能外显固化为通过条件。[matrix](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/matrix-crosschunk-stress.json#L20) [usage](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs/使用说明.md#L797) [usage](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs/使用说明.md#L845)

## 2. 关键数据结构和算法性能分析
- 三个 case 都将拓扑规模刻意压到 `1 triggerSource -> 1 core + 1 send filter`，避免把结果污染为“规模压测”，从而把观测重点压缩到边界状态机本身的开销变化；这符合“只关注是否存在异常热点”的目标。[persistent case](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/performance/p27/send_filter_hidden_intercept_persistent_sync.json#L18) [square case](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/performance/p27/send_filter_hidden_intercept_sync_square_2tick.json#L18)
- `a` 与 `b` 都在 drive 中显式插入一次过滤器周围方块刷新，把“隐藏拦截态”与“邻居刷新后继续观察”压进同一条 spark 窗口；`b` 额外用 `input_start_square_triggerSource + periodTicks=2/highTicks=1` 固定 2 tick 方波驱动，不再引入额外红石结构噪声。[persistent case](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/performance/p27/send_filter_hidden_intercept_persistent_sync.json#L72) [square case](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/performance/p27/send_filter_hidden_intercept_sync_square_2tick.json#L72)
- `c` 通过 `clearArena=false + reuseExisting=true + links=[]` 复用现有世界和建链结果，只保留“重启后等待 + 刷新 + 再观察”的最小成本路径，避免把重复放置/重复建链成本混入 reload 观察窗口。[reload case](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/performance/p27/send_filter_hidden_intercept_reload_replay.json#L6) [reload case](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/performance/p27/send_filter_hidden_intercept_reload_replay.json#L19) [reload case](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/performance/p27/send_filter_hidden_intercept_reload_replay.json#L43)

## 4. 安全、性能、兼容性、扩展性风险分析与建议
- 本轮没有修改运行时代码路径，风险主要来自“把设计空白边界正式纳入回归后，后续是否会误把功能外显当成功能基线”；使用说明已经明确禁止这么做，保留问题也把该场景定性为持续性能观察项。[usage](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs/使用说明.md#L845) [retained issues](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs_dev/保留问题.md#L21)
- 本次 dedicated server suite 已实际跑通三组 case，spark 结果显示 `TPS` 均稳定在约 `20.02~20.04`，采样窗口 `msptMedian` 约 `0.30~0.63ms`，`com.makomi` 相关热点仅在 `0.12%~0.28%` 的量级，未看到持续性热点放大迹象；但仍应继续多轮复测，尤其关注 reload 路径下的偶发尖峰与内存趋势。设计资产对应位置如下。[persistent case](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/performance/p27/send_filter_hidden_intercept_persistent_sync.json#L72) [square case](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/performance/p27/send_filter_hidden_intercept_sync_square_2tick.json#L72) [reload case](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/performance/p27/send_filter_hidden_intercept_reload_replay.json#L44)
- 兼容性上，本轮只新增 bench 资产与文档，不改现有 API、配置键和持久化结构；扩展性上，后续若要补更多变体，继续沿 `p27` 同族或独立 suite 扩展即可，不会影响现有功能矩阵。[matrix](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/matrix-crosschunk-stress.json#L20) [retained issues](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs_dev/保留问题.md#L21)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）
- 代码层面本轮没有新增共享可变状态，也没有改动运行时并发逻辑；所有改动都在 bench JSON 与文档层，线程边界风险主要体现在 suite 运行时对 dedicated server 世界目录的串行复用，而不是仓库代码本身的并发实现。[suite](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/suites/send-filter-hidden-intercept-perf.json#L11) [reload case](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/cases/performance/p27/send_filter_hidden_intercept_reload_replay.json#L19)
- `reuseWorldFrom` 只在第三个 entry 上使用，suite 执行顺序也是串行，因此不存在并发写同一世界目录的情况；当前并发风险等级评估为“低”。[suite](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/suites/send-filter-hidden-intercept-perf.json#L20)
- 后续若想并行跑同类 suite，不应复用同一 `reuseWorldFrom` 世界，也不应让多个外部流程同时指向同一 `rl-cases` 世界目录；保持“每次 suite 单独世界根 + reload 仅串行复用”即可继续维持低风险。[suite](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/suites/send-filter-hidden-intercept-perf.json#L11) [matrix](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/tools/bench/matrix-crosschunk-stress.json#L20)
