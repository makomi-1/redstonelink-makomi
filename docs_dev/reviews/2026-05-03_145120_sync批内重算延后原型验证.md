## 2. 关键数据结构和算法性能分析

关键数据结构仍是 `StructuredBatchMutationAccumulator`。它现在承担“批次是否接受过事件、是否真的改动过桶、是否需要补做 pulse truth、批末 authority fallback 取哪条最新事件”的累计职责，避免每条 `SYNC` 都重复做全量真值合并。[ActivatableTargetDispatchSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/ActivatableTargetDispatchSupport.java#L510)

性能收益来自复杂度变化：旧路径下，单批中的每条 `SYNC`/失效都会触发一次 `recomputeSyncTruthFromConcurrentBuckets()`，在 `1024 -> 1` 高 fan-in 场景接近批内重复全量扫描；新路径下，同一批只在 `finalizeStructuredBatchMutation(...)` 里统一重算一次 `sync truth`、一次 `authority` 和一次派生态，显著减少重复 merge 成本。[ActivatableTargetDispatchSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/ActivatableTargetDispatchSupport.java#L340) [ActivatableTargetDispatchSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/ActivatableTargetDispatchSupport.java#L456)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

性能上，这次原型已经验证收益显著：`p15_sync_1024_to_1` 的 MSPT 1m mean 从 `47.025` 降到 `6.243`，`p18_sync_1024_to_1024` 从 `31.135` 降到 `22.304`。同时，`x17/x18/x19` 和 `x22` dedicated functional 回归均通过，说明对 direct batching、pending batching、force-load preload batching 以及 samechunk mixed direct 逐 tick 语义未引入已观测回归。

兼容性风险主要在两点。第一，`ACTIVATION` 仍保留即时重算，这使当前实现是“只优化 sync 类批路径”的最小原型，后续若继续扩展到 mixed 组合，需要重新审视 `toggle/pulse` 中间态语义。[ActivatableTargetDispatchSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/block/entity/ActivatableTargetDispatchSupport.java#L372) 第二，本轮 `x23` 与 `x20/x21` 未形成有效通过结论：`x23` 暴露出 samechunk 组合场景下的独立问题，而 `x20/x21` 当前主要仍被 bench 玩家桥/玩家上下文超时阻塞，不能直接用作业务语义失败结论。

## 5. 并发冲突审查
