## 2. 关键数据结构和算法性能分析

- 前端核心状态是 `GraphDraft`：它只保留草稿身份、快照基线、graph revision、布局版本与结构化操作列表，不把服务端真值直接镜像到浏览器可写状态；保存结果则通过 `GraphWriteResponse` 仅回填必要的 `updatedNodes`。这使草稿与真值解耦，便于本地离线暂存和冲突回滚。[graphTypes.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/graphTypes.ts#L81) [graphTypes.ts](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/graphTypes.ts#L91) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L358)
- 服务端核心请求模型是 `GraphWriteRequest`、`RenameNodeAliasOperation`、`ReplaceTriggerSourceTargetsOperation` 和 `UpdatedNodeState`。这些 record 都在构造时做规范化，包含文本清洗、非负约束、目标序号去重等，可把输入脏数据尽早挡在应用层边界外。[GraphWriteJsonSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteJsonSupport.java#L284) [GraphWriteJsonSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteJsonSupport.java#L310) [GraphWriteJsonSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteJsonSupport.java#L336) [GraphWriteJsonSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteJsonSupport.java#L370)
- `ReplaceTriggerSourceTargetsOperation` 在请求层通过 `LinkedHashMap` 做目标序号去重；`validateReplaceOperations` 再按 `triggerSourceSerial` 去重，避免同一来源节点在一次保存里多次覆盖。整体复杂度主要取决于别名操作数 `A`、替换操作数 `R` 和目标集合规模 `T`，约为 `O(A + R + T)`，对当前“单个 triggerSource 编辑”的第一版规模足够轻量。[GraphWriteJsonSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteJsonSupport.java#L346) [GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L260)
- `applyUpdatedNodeStates` 在前端不是整图重建，而是仅把服务端返回的最新节点状态并回当前基线图，再生成新草稿基线。这降低了保存后的页面重载成本，也让 alias/revision 回写范围更可控。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L358) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L734)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全方面，本轮已经接入两级权限和限流：alias 保存走 `OTHER` 权限与速率组，拓扑保存走 `LINK_RW` 权限与速率组，能覆盖大部分误操作和滥用场景；但更细的“可编辑范围”权限目前尚未落地，后续若开放命令入口或多人协作网页编辑，应增加基于节点集合或维度的写权限设计。[GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L134) [GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L139) [GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L339)
- 一致性方面，本轮采用“graphRevision + sourceRevision”的双层 OCC：整图 revision 保护拓扑基线，单来源 revision 保护单个 `triggerSource` 连接集，因此 alias-only 保存不会被无关拓扑变化误伤，拓扑编辑也能在并发写入时返回冲突而不是静默覆盖。这一策略正确，但会要求用户在冲突后重新导出 graph 文件，后续可考虑增加差量刷新接口降低重试成本。[GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L145) [GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L281) [GraphWriteJsonSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteJsonSupport.java#L94)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- 共享状态 1：浏览器本地 draft 文件。`GraphViewer` 会在变更后定时写 draft，本地 bridge 也允许显式删除 draft，因此同一文件存在“自动保存”和“保存成功后清空/重建草稿”的时序交错可能。当前通过单页内的 `draftLoading`、220ms 防抖和保存成功后重置基线来降低风险，但跨页面或多窗口同时打开同一 draft 仍没有锁。风险等级：中。建议后续在 draft JSON 中加入 `updatedAt` / `sessionId` 并在 bridge 层增加简单覆盖告警。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L634) [LocalWebAppBridgeService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/web/LocalWebAppBridgeService.java#L287)
- 共享状态 2：客户端待响应 RPC 表。`LocalWebGraphSaveRpc` 使用 `ConcurrentHashMap<String, CompletableFuture<String>>` 保存等待中的请求，并在 `finally` 和 `completeResponse` 两侧都做移除，能承受正常并发请求；若未来开放真正批量保存或多窗口同时编辑，建议继续保持 requestId 唯一性并补充容量观测。风险等级：低。[LocalWebGraphSaveRpc.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/web/LocalWebGraphSaveRpc.java#L27) [LocalWebGraphSaveRpc.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/web/LocalWebGraphSaveRpc.java#L36) [LocalWebGraphSaveRpc.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/web/LocalWebGraphSaveRpc.java#L70)
- 读改写覆盖风险主要集中在服务端真值层。本轮没有采用“按网页图整体回写”，而是使用 OCC + 结构化操作应用，因此并发下更像命令式更新而不是最后写入者覆盖。整图 revision 冲突和来源 revision 冲突都能显式返回给前端。风险等级：低到中，取决于多人同时编辑同一 `triggerSource` 的频率。[GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L145) [GraphWriteService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphWriteService.java#L281)
- 线程边界方面，本地 HTTP 线程不会直接碰 Minecraft 连接对象，而是经 `minecraft.execute` 切回客户端主线程发送网络包；网络回包也通过 `context.client().execute` 切回主线程再完成 promise。服务端处理仍在网络/主线程安全边界内调用现有保存逻辑，没有额外引入异步共享可变状态。风险等级：低。[LocalWebGraphSaveRpc.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/web/LocalWebGraphSaveRpc.java#L41) [StatePanelNetworkClientHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/network/StatePanelNetworkClientHandlerSupport.java#L53) [StatePanelNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/network/StatePanelNetworkServerHandlerSupport.java#L310)
- 结论：本轮并发模型以“本地草稿最终由用户主动保存 + 服务端 OCC 拒绝冲突覆盖”为核心，符合第一版最小可交付目标。残余风险主要在浏览器多窗口/多实例同时编辑同一 draft 的本地覆盖问题，建议放到后续权限与限流补齐阶段一并处理。
