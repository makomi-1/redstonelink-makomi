# 网页前端主处理整体方案补充前端框架与分期步骤

## 1. 功能与语义、架构设计（关键方法和入口）

- 本次补充把网页前端技术栈明确收口为 `React + TypeScript + Vite + React Flow`，并在整体方案中给出 `P0 ~ P7` 的落地顺序，使“离线打包、显式保存、未保存提醒、结构化编辑”这些先前已确认的交互边界，落到可执行的工程分期上，见 [2026-04-16_151307_网页前端主处理的录制回放与可视化编辑整体方案.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs_dev/plans/2026-04-16_151307_%E7%BD%91%E9%A1%B5%E5%89%8D%E7%AB%AF%E4%B8%BB%E5%A4%84%E7%90%86%E7%9A%84%E5%BD%95%E5%88%B6%E5%9B%9E%E6%94%BE%E4%B8%8E%E5%8F%AF%E8%A7%86%E5%8C%96%E7%BC%96%E8%BE%91%E6%95%B4%E4%BD%93%E6%96%B9%E6%A1%88.md#L359) 与 [2026-04-16_151307_网页前端主处理的录制回放与可视化编辑整体方案.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs_dev/plans/2026-04-16_151307_%E7%BD%91%E9%A1%B5%E5%89%8D%E7%AB%AF%E4%B8%BB%E5%A4%84%E7%90%86%E7%9A%84%E5%BD%95%E5%88%B6%E5%9B%9E%E6%94%BE%E4%B8%8E%E5%8F%AF%E8%A7%86%E5%8C%96%E7%BC%96%E8%BE%91%E6%95%B4%E4%BD%93%E6%96%B9%E6%A1%88.md#L396)。
- `Vite` 作为静态资源构建器，与当前 `processResources` 把运行时资源打进 Jar 的 Gradle 路径天然匹配；该方向和本地 Bridge 提供 Jar 内网页资源的设计是一致的，见 [build.gradle](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/build.gradle#L91)。
- `React Flow` 被放在 `serial` 模式只读分析器和后续结构化编辑器阶段，而不是在 `P0` 就过早引入复杂业务逻辑；这种“先底座、后录制、再图展示、再保存”的顺序能降低第一次接入网页端时的耦合风险，见 [2026-04-16_151307_网页前端主处理的录制回放与可视化编辑整体方案.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs_dev/plans/2026-04-16_151307_%E7%BD%91%E9%A1%B5%E5%89%8D%E7%AB%AF%E4%B8%BB%E5%A4%84%E7%90%86%E7%9A%84%E5%BD%95%E5%88%B6%E5%9B%9E%E6%94%BE%E4%B8%8E%E5%8F%AF%E8%A7%86%E5%8C%96%E7%BC%96%E8%BE%91%E6%95%B4%E4%BD%93%E6%96%B9%E6%A1%88.md#L430)。

## 2. 关键数据结构和算法性能分析

- 本次文档补充没有新增真值结构，但把“前端主框架”和“推荐分期”与既有数据结构明确挂钩：录制仍以 `RecordingBundle` 为目标产物，图编辑仍以 `GraphDraft + GraphWriteIntent` 为本地草稿模型，因此前端框架选型没有改变之前“DTO 导出 + 本地缓存 + 显式保存”的数据边界，见 [2026-04-16_151307_网页前端主处理的录制回放与可视化编辑整体方案.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs_dev/plans/2026-04-16_151307_%E7%BD%91%E9%A1%B5%E5%89%8D%E7%AB%AF%E4%B8%BB%E5%A4%84%E7%90%86%E7%9A%84%E5%BD%95%E5%88%B6%E5%9B%9E%E6%94%BE%E4%B8%8E%E5%8F%AF%E8%A7%86%E5%8C%96%E7%BC%96%E8%BE%91%E6%95%B4%E4%BD%93%E6%96%B9%E6%A1%88.md#L77) 与 [2026-04-16_151307_网页前端主处理的录制回放与可视化编辑整体方案.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs_dev/plans/2026-04-16_151307_%E7%BD%91%E9%A1%B5%E5%89%8D%E7%AB%AF%E4%B8%BB%E5%A4%84%E7%90%86%E7%9A%84%E5%BD%95%E5%88%B6%E5%9B%9E%E6%94%BE%E4%B8%8E%E5%8F%AF%E8%A7%86%E5%8C%96%E7%BC%96%E8%BE%91%E6%95%B4%E4%BD%93%E6%96%B9%E6%A1%88.md#L179)。
- `NodeStateTraceService` 仍是录制底座的最佳候选，因为它已经提供有界 ring buffer 和挂载生命周期；本次新增的 `P2` 分期正是围绕这一点收口，而不是另起一套更重的实时流式协议，见 [NodeStateTraceService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/NodeStateTraceService.java#L39) 与 [NodeStateTraceService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/NodeStateTraceService.java#L94)。
- `React Flow` 被用于图展示层而不是持久化层，这与当前“状态面板订阅只存在轻量 NBT、重资产走客户端本地文件”的思路一致，可避免把布局坐标和大图缓存塞回真值层，见 [StatePanelToolData.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/StatePanelToolData.java#L20)。

## 3. 数据流或调用链

- 本次补充分期后，调用链更加清晰：`P0/P1` 只负责网页静态资源和 Bridge 通道，`P2` 才让状态面板录制入口真正导出录制资产，`P3/P4/P5` 再逐步把图快照、草稿保存与冲突处理接上；这比“同时开录制、图展示、图编辑、权限限流”更符合现有调用链演进节奏，见 [2026-04-16_151307_网页前端主处理的录制回放与可视化编辑整体方案.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs_dev/plans/2026-04-16_151307_%E7%BD%91%E9%A1%B5%E5%89%8D%E7%AB%AF%E4%B8%BB%E5%A4%84%E7%90%86%E7%9A%84%E5%BD%95%E5%88%B6%E5%9B%9E%E6%94%BE%E4%B8%8E%E5%8F%AF%E8%A7%86%E5%8C%96%E7%BC%96%E8%BE%91%E6%95%B4%E4%BD%93%E6%96%B9%E6%A1%88.md#L400)。
- 图展示和图保存后续仍应分别复用现有读模型与写入闭环：读侧走 `NodeSnapshotQueryService + CurrentLinksPrivacyService`，写侧走 `LinkSetExecutionService + LinkOccSupport`。本次文档补充没有改动这一主链，而是把它们纳入 `P3/P4/P5/P7` 的分期安排，见 [NodeSnapshotQueryService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/NodeSnapshotQueryService.java#L41)、[CurrentLinksPrivacyService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/CurrentLinksPrivacyService.java#L109)、[LinkSetExecutionService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/command/link/LinkSetExecutionService.java#L139) 与 [LinkOccSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkOccSupport.java#L93)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全与权限：用户已明确同意“限流与权限后补”，本次把它们延后到 `P7`，但文档仍明确要求继续复用现有写控、读控和 OCC，而不是让网页端独立长出一套权限体系；这样虽然把安全补齐延后，但没有丢失边界，见 [2026-04-16_151307_网页前端主处理的录制回放与可视化编辑整体方案.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs_dev/plans/2026-04-16_151307_%E7%BD%91%E9%A1%B5%E5%89%8D%E7%AB%AF%E4%B8%BB%E5%A4%84%E7%90%86%E7%9A%84%E5%BD%95%E5%88%B6%E5%9B%9E%E6%94%BE%E4%B8%8E%E5%8F%AF%E8%A7%86%E5%8C%96%E7%BC%96%E8%BE%91%E6%95%B4%E4%BD%93%E6%96%B9%E6%A1%88.md#L470)。
- 兼容性：`Vite` 产出的静态资源和本地 Bridge 模型更适合当前 Fabric 客户端离线分发场景；若改用 SSR 框架，会把运行时复杂度提前拉高，但并不会给当前功能带来实质收益，因此文档中明确不选 `Next.js/Nuxt` 是合理的，见 [2026-04-16_151307_网页前端主处理的录制回放与可视化编辑整体方案.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs_dev/plans/2026-04-16_151307_%E7%BD%91%E9%A1%B5%E5%89%8D%E7%AB%AF%E4%B8%BB%E5%A4%84%E7%90%86%E7%9A%84%E5%BD%95%E5%88%B6%E5%9B%9E%E6%94%BE%E4%B8%8E%E5%8F%AF%E8%A7%86%E5%8C%96%E7%BC%96%E8%BE%91%E6%95%B4%E4%BD%93%E6%96%B9%E6%A1%88.md#L370)。
- 扩展性：把图框架先收口到 `React Flow`，再把录制波形图延后到“后续补轻量图表库”，能避免在第一阶段同时处理两类重前端依赖；这是合理的扩展顺序，见 [2026-04-16_151307_网页前端主处理的录制回放与可视化编辑整体方案.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs_dev/plans/2026-04-16_151307_%E7%BD%91%E9%A1%B5%E5%89%8D%E7%AB%AF%E4%B8%BB%E5%A4%84%E7%90%86%E7%9A%84%E5%BD%95%E5%88%B6%E5%9B%9E%E6%94%BE%E4%B8%8E%E5%8F%AF%E8%A7%86%E5%8C%96%E7%BC%96%E8%BE%91%E6%95%B4%E4%BD%93%E6%96%B9%E6%A1%88.md#L375)。

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- 本次补充没有新增新的共享状态真值，但 `P4/P5` 明确把网页编辑器的核心冲突点定义为“本地 draft 与服务端 revision 漂移”，而不是浏览器线程上的普通竞态；这一点与现有 `LinkOccSupport` 的设计保持一致，风险等级为“中”，见 [LinkOccSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkOccSupport.java#L20) 与 [LinkOccSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/LinkOccSupport.java#L123)。
- 录制和图快照的大对象仍应保持“服务端运行时生成 -> 客户端本地缓存”，不要因为前端框架确定了就把缓存塞回 NBT 或世界 `SavedData`；否则会把玩家本地交互状态错误提升成共享状态，风险等级为“中”，相关保留问题已在 [保留问题.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs_dev/%E4%BF%9D%E7%95%99%E9%97%AE%E9%A2%98.md#L11) 记录。
- `P7` 把权限与限流放在功能可用后补齐，意味着在真正实施前期阶段时，必须控制接口只在受信任最小范围内开放，避免本地 Bridge 在未限流前过早暴露重导出和重保存能力；建议后续实现时把 Bridge 默认能力做到最小化，待 `P7` 再系统放开。风险等级为“中低”，依据见 [2026-04-16_151307_网页前端主处理的录制回放与可视化编辑整体方案.md](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/docs_dev/plans/2026-04-16_151307_%E7%BD%91%E9%A1%B5%E5%89%8D%E7%AB%AF%E4%B8%BB%E5%A4%84%E7%90%86%E7%9A%84%E5%BD%95%E5%88%B6%E5%9B%9E%E6%94%BE%E4%B8%8E%E5%8F%AF%E8%A7%86%E5%8C%96%E7%BC%96%E8%BE%91%E6%95%B4%E4%BD%93%E6%96%B9%E6%A1%88.md#L470)。
