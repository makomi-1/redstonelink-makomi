## 2. 关键数据结构和算法性能分析

- 服务端缓存核心是 `EXPORT_CACHE`，按 `UUID -> CachedGraphExport` 映射保存当前玩家最近一次 graph 导出结果。缓存命中时只做一次 map 查询和 revision 比较，复杂度 `O(1)`；缓存未命中或 revision 变化时才回落到原有导出流程。对比每次重新构建 graph snapshot，这一改动显著降低了重复打开 graph 页时的 CPU 与网络成本。[GraphSnapshotExportService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphSnapshotExportService.java#L23) [GraphSnapshotExportService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphSnapshotExportService.java#L31)
- `ExportBundle` 新增 `reusedExisting` 标记，用于区分“完整导出”与“本地复用打开”两种传输语义，但没有改变 graph bundle 内容本身。这样既能保持调用方接口简洁，又不需要额外扩张 payload 结构。[GraphSnapshotExportService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphSnapshotExportService.java#L231)
- 前端差异计算 `buildDraftDiff` 的复杂度主要由边集合对比和草稿操作遍历组成，近似 `O(E + O)`，其中 `E` 是边数、`O` 是草稿操作数。实现上通过 `Map/Set` 做 edgeKey 比较和 nodeKey 收集，避免反复线性扫描。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L511) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L539) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L545)
- 图层渲染仍然使用 ReactFlow 的节点/边数组，但 `buildEdges` 现在会把“当前有效边 + 草稿移除边”一起输出。这样虽然边总数会比纯 effective graph 略大，但在 serial 模式和当前目标规模下成本可控，换来更直观的差异可视化。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L200) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L221)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 安全方面，本轮没有新增真值写入口，也没有绕过现有权限/OCC/限流逻辑。revision 复用仅作用于 graph 只读导出链路，风险较低。[GraphSnapshotExportService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphSnapshotExportService.java#L31)
- 性能方面，revision 复用能显著降低同一玩家连续打开 graph 页时的重复导出、压缩和网络传输成本；但缓存是按玩家保存最近一次导出结果，没有做容量淘汰。当前规模下问题不大，后续如多人长期在线可考虑在玩家离线时清理缓存或改为有界缓存。风险等级中。[GraphSnapshotExportService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphSnapshotExportService.java#L23) [GraphSnapshotExportService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphSnapshotExportService.java#L251)
- 兼容性方面，复用命中时依赖客户端本地已有同名 graph 文件。若本地文件被用户删除，而服务端仍命中缓存，则客户端只能失败反馈，无法自动回退到重新上传。当前这属于已知残余风险，后续若需要更稳妥，可在客户端失败时补一个“请求重传 graph”的回退链路。风险等级中。[StatePanelNetworkClientHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/network/StatePanelNetworkClientHandlerSupport.java#L171)
- 扩展性方面，本轮没有裁剪 graph snapshot 字段，也没有扩到 `channel` 模式；差异模型和 revision 复用都与 channel 拓扑不冲突，后续扩展时可以继续沿用当前框架。风险等级低。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L511)

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- 服务端共享状态新增了一份 `EXPORT_CACHE`。它使用 `ConcurrentHashMap`，读写线程安全；缓存内容仅依赖 `graphRevision`，不参与世界真值写回，因此不会引入真值覆盖问题。风险等级低。[GraphSnapshotExportService.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/main/java/com/makomi/data/GraphSnapshotExportService.java#L23)
- 客户端 graph 接包依旧存在一个 `PENDING_GRAPH_EXPORTS` 聚合状态。zero-chunk 分支在进入聚合器前就直接返回，不会和完整分块流程争抢同一组 chunk 数组，因此不会把“复用打开”和“完整写文件”路径混在一起。风险等级低。[StatePanelNetworkClientHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/src/client/java/com/makomi/client/network/StatePanelNetworkClientHandlerSupport.java#L129)
- 前端草稿差异着色只读取 `baseGraphBundle`、`effectiveGraphBundle` 和 `graphDraft` 三个现有状态，没有新增异步共享可变状态；它随 React 渲染同步更新，不涉及跨线程并发。风险等级低。[GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L683) [GraphViewer.tsx](/d:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/GraphViewer.tsx#L684)
