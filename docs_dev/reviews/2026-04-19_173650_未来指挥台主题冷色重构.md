# 未来指挥台主题冷色重构

## 1. 功能与语义、架构设计

本轮改动没有调整主题系统架构，而是在现有主题切换框架上，把 `future-command` 从“默认暖色基底”拆成显式主题覆写，保证主题名“未来指挥台”和实际视觉语义一致。主题元数据仍由前端主题列表提供，页面层继续只传递 `themeId`，样式变化完全落在 CSS 变量层，因此属于低耦合的视觉修正。

- 主题默认值与页面分发入口仍在 [App.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/App.tsx#L12) 与 [App.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/App.tsx#L36)
- 主题选项渲染入口仍在 [ThemeSwitcher.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/ThemeSwitcher.tsx#L34)
- “未来指挥台”的元数据已与冷色方案对齐，见 [theme.ts](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app/theme.ts#L24)
- `future-command` 的显式主题 token 覆写入口在 [app.css](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L129)

## 2. 关键数据结构和算法性能分析

这次没有新增算法，核心仍是 CSS 自定义属性查值。运行时成本基本等同于原方案，因为只是把原先散落在基础样式里的颜色常量改成了 `future-command` 独立变量组；主题切换仍是一次 `data-theme` 属性切换，不引入额外状态计算。

- 基础主题 token 容器仍在 [app.css](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L26)
- 冷色未来指挥台 token 组在 [app.css](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L129)
- 主题卡片的预览色条同步对齐在 [app.css](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L604)
- 录制图表仍通过主题变量解析颜色，没有新增复杂度，见 [RecordingChart.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/RecordingChart.tsx#L438)

## 3. 数据流或调用链

当前调用链仍然是“主题元数据定义 -> `App` 持有当前主题 ID -> 页面容器写入 `data-theme` -> CSS 变量控制页面/图网络/录制视觉”。这次改动只替换了其中 `future-command` 这套 token 的内容，因此不会改变既有页面行为，只会改变最终解析出来的颜色。

- 主题元数据来源于 [theme.ts](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app/theme.ts#L24)
- `App` 继续以默认主题初始化并向页面下发主题 ID，见 [App.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/App.tsx#L36)
- 主题切换控件继续遍历主题列表生成选项，见 [ThemeSwitcher.tsx](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/components/ThemeSwitcher.tsx#L34)
- 页面上的最终视觉解析点是 [app.css](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L129) 与 [app.css](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L604)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

安全层面本轮没有接口、存储、权限变化，风险很低。性能层面只改静态样式，未引入额外渲染循环。兼容性层面的主要观察点是：未来指挥台现在显式覆盖了大量 token，后续如果继续新增主题 token，需要保持三套主题字段完整，否则容易出现某些组件退回基础暖色。扩展性方面，这次把未来指挥台从基础样式中拆出来是正确方向，后续若继续扩展模板，建议把基础 `.app-shell` 再收敛成真正的中性 fallback。

- 显式主题覆写集中在 [app.css](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L129)
- 未来指挥台说明文案已同步，避免 UI 语义漂移，见 [theme.ts](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app/theme.ts#L26)
- 主题色条也已同步，避免“名称改了但预览仍偏旧风格”，见 [app.css](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L604)

## 5. 并发冲突审查

本轮不存在多线程共享状态改写，主要风险来自前端样式层的“并发含义冲突”，即基础 `.app-shell` token 与 `future-command` 覆写 token 同时存在时，后续维护者可能误把基础样式继续当成未来指挥台来改，造成视觉回退。该风险属于低等级配置冲突风险，不是运行时并发错误。建议后续继续把基础样式语义明确为 fallback，避免再次出现“主题名和默认样式绑死”的问题。

- 基础 fallback token 仍在 [app.css](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L26)
- 未来指挥台显式覆写在 [app.css](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app.css#L129)
- 主题元数据入口在 [theme.ts](/D:/OpenProjects/RedstoneLink/rl-release-no-mixin/webapp/src/app/theme.ts#L24)
