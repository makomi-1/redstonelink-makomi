# 转发器正整数延迟迁移

## 1. 功能与语义、架构设计（关键方法和入口）

- 本次迁移把转发器延迟从 `1/2 tick` 固定档位扩展为“仅允许大于 `0` 的正整数 tick”，核心值对象入口位于 [RepeaterDelay.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/data/RepeaterDelay.java#L15)。
- 客户端编辑界面从“双按钮选档”改为“单输入框录入 + 保存时校验 + 规则 tooltip”，并保持 26.1 现有 `extractRenderState/extractBackground` 绘制管线不回退，入口位于 [RepeaterEditorScreen.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/screen/RepeaterEditorScreen.java#L121) 与 [RepeaterEditorScreen.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/screen/RepeaterEditorScreen.java#L247)。
- 语义层没有改动 `triggerSource/core` 方向边界；转发器仍然只是保留输入侧 `triggerSource` 集与输出侧 `core` 集，本次只放宽“延迟 tick 数的表示能力”，不改变连接方向和图结构写入约束。

## 2. 关键数据结构和算法性能分析

- `RepeaterDelay` 改为不可变记录值对象，解析 token 时只走一次正则匹配和一次 `int` 解析，复杂度保持 O(1)，关键点在 [RepeaterDelay.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/data/RepeaterDelay.java#L78)。
- HUD 和物品 tooltip 不再对枚举做 `switch`，而是统一通过值对象暴露的显示翻译键和参数决策口，避免后续新增 `3/5/8 tick` 时继续扩散条件分支，落点在 [LinkSerialHudOverlayTextSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/render/LinkSerialHudOverlayTextSupport.java#L691) 与 [RepeaterBlockItem.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/item/RepeaterBlockItem.java#L124)。
- 编辑界面输入侧采用 26.1 已存在的“`EditBox.setResponder()` 即时归一化数字字符 + 保存时二次校验”模式，不引入新的 UI 基类能力，热点成本只是单行字符串过滤，落点在 [RepeaterEditorScreen.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/screen/RepeaterEditorScreen.java#L303)。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 兼容性方面，旧 `1tick/2tick` token 仍可解析，新 token 只是在此基础上放宽到任意正整数；非法值继续回退 `1 tick`，兼容入口在 [RepeaterDelay.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/data/RepeaterDelay.java#L78) 与 [RepeaterDelay.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/data/RepeaterDelay.java#L97)。
- 本次没有引入 `com.makomi.api.v1.*` 依赖，也没有新增旧术语输出；界面文案仍然围绕 `triggerSource/core` 展示输入/输出关系，不会把旧 `source/target` 重新泄漏出来。
- 风险点主要在测试环境：当前分支已有的物品数据契约测试在 `ItemStack` 初始化阶段会触发 “Components not bound yet” 的既有问题，本批次只补了与转发器延迟相关的测试案例，但未在本轮内完成整个 `ItemStack` 测试基座修复；相关影响局限于测试环境，不影响本批次编译与客户端冒烟验收。

## 5. 并发冲突审查（共享状态、读改写覆盖、重入/线程边界、风险等级与建议）

- `RepeaterDelay` 作为不可变值对象，不引入共享可变状态；风险等级为低，构造和解析都只在调用栈内完成。
- 客户端界面的状态消息与延迟输入只在渲染线程/UI 线程内读写，没有新增跨线程共享；关键边界位于 [RepeaterEditorScreen.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/client/java/com/makomi/client/screen/RepeaterEditorScreen.java#L247)。
- 服务端保存链仍然通过既有转发器保存包在主线程处理，本次只把 payload 里的 delay 字段从“固定枚举语义”提升为“正整数值对象语义”，没有新增重入或并发写覆盖风险，入口位于 [RepeaterNetworkServerHandlerSupport.java](/d:/OpenProjects/RedstoneLink/rl-fabric-26.1/src/main/java/com/makomi/network/RepeaterNetworkServerHandlerSupport.java#L99)。
