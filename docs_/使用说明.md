# 正文

## 使用范围
- 该副本只收录“已经按当前实现核对过”的高频条目。
- 未收录或尚未整理完成的内容，暂时仍以 `docs_dev/使用说明.md` 为准。
- 文中“默认值”优先按配置解析默认值与模板口径整理；若你的世界已改过 `config/redstonelink-server.properties`，以实际文件为准。

## 语义对齐
- role 只表示方向语义：`source` = 来源，`target` = 目标。
- type 只表示节点类型：`triggerSource` = `LinkNodeType.TRIGGER_SOURCE`，`core` = `LinkNodeType.CORE`。
- 方向规则固定为 `triggerSource -> core`；`triggerSource` 只能做来源，`core` 只能做目标。
- `crosschunk.whitelist.sourceTypes/targetTypes` 与 `crosschunk.preset.<name>.sources/targets` 仅接受标准类型写法 `triggerSource/core`，不接受 `button`、`trigger_source` 等旧别名。

## 配对与当前连接
- 配对 GUI、悬停 tooltip、可配对物品 tooltip 当前统一显示结构化序号表达式：支持 `N` 与 `A:B`，分隔符为 `/`。
- 配对输入框支持多行输入；客户端发送前会把换行折叠为 `/`，服务端解析语义不变。
- 输入框最大长度受客户端 `client.pairingInputMaxLength` 限制，默认 `1024`。
- 已放置方块打开配对 GUI 默认要求潜行；若需要关闭该门槛，可把 `interaction.requireSneakToOpenPairing` 设为 `false`。
- 当前配对 GUI 已接入乐观并发保护：
1. 打开界面时，服务端快照会带上 `graphRevision/sourceRevision`。
2. `triggerSource` 视角提交时校验 `sourceRevision`。
3. `core` 视角提交时校验 `graphRevision`。
4. 若版本不一致，服务端会拒绝本次提交并提示重新打开界面后再试。

## 快速连接工具
- 当前实际可用工作流围绕“序号缓存”展开；`channel` 模式仅预留接口，当前不可真正应用。
- 基础交互：
1. 潜行且左手为空时右键：打开缓存编辑界面。
2. 左键命中可连接节点：采集当前节点到缓存。
3. 站立右键命中可连接节点：把当前缓存应用到命中节点。
4. 鼠标中键：清空序号缓存与频道缓存，但保留当前模式和序号缓存类型。
- 方向规则：
1. 实际写入方向固定为 `triggerSource -> core`。
2. 缓存类型与命中节点类型相同时，直接判定为方向不合法，不执行应用。
3. `core` 缓存应用到 `triggerSource` 时，会把该 `triggerSource` 的目标集合整体覆盖为缓存中的 `core` 集合。
4. `triggerSource` 缓存应用到 `core` 时，会把缓存里的每个 `triggerSource` 覆盖为“仅连接当前命中的这个 `core`”。
- 限制规则：
1. 序号缓存为空时不能应用。
2. 快速连接工具缓存输入长度仍复用 `server.command.linkSet.maxInputLength`。
3. 应用到 `core` 时，`triggerSource` 缓存数量上限复用 `server.maxTargetsPerSetLinks`。
4. 快速连接工具应用同样受服务端写控限制；命中只读、limited 或 protected 拒绝时，前端统一提示“没有足够权限”。
- 客户端配置：
1. `client.quickLinkSerialCacheMaxLength`：序号缓存输入长度上限，默认 `1024`。

## 状态面板工具
- 主手持有并右键：打开状态面板。
- 面板内当前提供 `订阅 / 刷新 / 录制 / 清空` 四个动作；`录制` 仍是未来预留入口。
- 订阅输入支持 `N` 与 `A:B`，分隔符为 `/`，并可在 `core` 与 `triggerSource` 两类之间切换。
- 新增订阅当前只接受：
1. 已分配节点
2. 未退役节点
3. 通过隐私读控的节点
- 现有重复订阅不会重复占位；成功新增后服务端会自动回传一次最新快照。
- 手动刷新受 `server.statePanel.refreshHz` 节流，默认 `5 Hz`。
- 若历史订阅当前已受隐私读控限制，该行仍保留在列表中，但状态列显示为“已隐藏（隐私读控）”。
- 配置项：
1. `server.statePanel.refreshHz`：状态面板整体刷新节流频率，默认 `5`。
2. `server.statePanel.maxSubscriptions`：总订阅上限（`core + triggerSource` 合计），默认 `50`。

## 当前连接隐私与写控
- 当前连接隐私配置：
1. `server.currentLinksPrivacy.mode`：`hidden|masked|plain`，默认 `masked`。
2. `server.currentLinksPrivacy.overlayResponsePermissionLevel`：是否回近外显包所需最低权限，默认 `0`。
3. `server.currentLinksPrivacy.viewPermissionLevel`：查看 `masked` 受控连接所需权限，默认 `2`。
4. `server.currentLinksPrivacy.managePermissionLevel`：管理 `link privacy current_links mask` 命令所需权限，默认 `2`。
- `link privacy current_links mask` 的 `type` 仅支持 `triggerSource|core`。
- `masked` 模式下，命中受控名单的来源节点与受控目标会一起走隐私过滤；配对 GUI、近外显、`node get`、`link get` 与状态面板新增订阅都复用这套读控。
- 状态面板若保留了历史订阅，但当前玩家已失去读取权限，该行不会被删掉，只会显示隐藏态。
- 链接写控配置：
1. `server.linkWriteControl.mode`：`full|limited|readonly`，默认 `limited`。
2. `server.linkWriteControl.limited.permissionLevel`：越过 limited 最大设置量所需权限，默认 `2`。
3. `server.linkWriteControl.limited.maxSetSize`：limited 模式允许的“设置后目标总数”，默认 `64`。
4. `server.linkWriteControl.protected.permissionLevel`：命中 protected 名单后允许写入所需权限，默认 `2`。
5. `server.linkWriteControl.protected.managePermissionLevel`：管理 protected 名单命令所需权限，默认 `2`。
- `limited` 按“set 后目标总数”限流，不按本次增量条数限流。
- `full` 当前实现下会直接放行，不再受 protected 名单约束。
- GUI 配对提交、快速连接应用与相关命令写入都会继续受这套写控规则约束。

## 跨区块常用配置
- 常用方向与类型限制：
1. `crosschunk whitelist` 的 `role` 用 `source/target`，`type` 用 `triggerSource/core`。
2. 默认允许白名单类型：`crosschunk.whitelist.sourceTypes=triggerSource`、`crosschunk.whitelist.targetTypes=core`。
- 常用恢复与派发配置：
1. `crosschunk.queue.enabled=true`：默认开启持久派发队列。
2. `crosschunk.forceLoad.enabled=true`：默认允许强制加载。
3. `crosschunk.forceLoad.mode=whitelist`：默认只对白名单或 preset 生效。
4. `crosschunk.syncTargetChunkLoadReplay.enabled=true`：目标区块加载时默认会做 `sync` 补发。
5. `crosschunk.syncTargetChunkLoadReplay.immediateAttemptFirst=true`：默认先在 `CHUNK_LOAD` 当 tick 尝试一次。
6. `crosschunk.syncSourceAttachReplay.enabled=false`：默认不在 `triggerSource` 重新 attach 时额外重放一次 `sync`。
7. `crosschunk.directBatching=all_direct`：loaded direct `sync/toggle/pulse` 与异步 loaded `sync` 默认统一进目标级批提交。
8. `crosschunk.dispatch.batchWindowTicks=0`：默认保持当前 tick 对齐，并允许 `END_SERVER_TICK` 后 same-tick late flush。
- 常用 resident 规则：
1. `crosschunk whitelist add/set ... resident` 支持离线序号，适合先配置后上线。
2. 离线期间不会真的持有 resident 票据；节点重新上线后才会恢复生效。
3. 节点退役会强同步清理对应的白名单与 resident 标记。

## Bench 场景自动化
- 主要矩阵：
1. `tools/bench/matrix.json`：轻量纯性能。
2. `tools/bench/matrix-baseline-256.json`：`256 -> 256` 正式纯性能基线。
3. `tools/bench/matrix-performance-heavy.json`：重压性能。
4. `tools/bench/matrix-crosschunk-stress.json`：crosschunk / loading stress。
5. `tools/bench/matrix-physical-world.json`：物理世界端到端观察。
- dedicated server 前置条件：
1. `server.properties` 开启 `enable-rcon=true`。
2. bench 模板世界已安装 datapack。
3. 若要完全无人值守，建议同时开启 `server.command.benchmarkMode.enabled=true`。
4. 纯性能输入器依赖 `server.command.input.enabled=true`。
- 当前高频入口：
1. 定向跑 `mixed_1024_to_1024_core_banded16`：
```powershell
powershell -ExecutionPolicy Bypass -File .\tools\bench\run-bench-suite.ps1 `
  -ServerRoot 'D:\OpenProjects\RedstoneLink\mcserver' `
  -TemplateWorldPath 'D:\OpenProjects\RedstoneLink\mcserver\rl-bench-template' `
  -ServerStartCommand '.\start.bat' `
  -BenchAction RunCase `
  -MatrixPath '.\tools\bench\matrix-performance-heavy.json' `
  -CaseIds mixed_1024_to_1024_core_banded16 `
  -RconHost 127.0.0.1 `
  -RconPort 25575 `
  -RconPassword redstonelink-bench `
  -ServerWindowMode Hidden `
  -StartupTimeoutMs 240000
```
2. 跑服务器基本权限专项并强制使用客户端直发命令桥：
```powershell
powershell -ExecutionPolicy Bypass -File .\tools\bench\run-bench-suite.ps1 `
  -ServerRoot 'D:\OpenProjects\RedstoneLink\mcserver' `
  -TemplateWorldPath 'D:\OpenProjects\RedstoneLink\mcserver\rl-bench-template' `
  -ServerStartCommand '.\start.bat' `
  -SuitePath '.\tools\bench\suites\server-basic-permission.json' `
  -RconHost 127.0.0.1 `
  -RconPort 25575 `
  -RconPassword redstonelink-bench `
  -AsPlayer BenchBot `
  -AutoStartBenchClient `
  -BenchClientPlayerName BenchBot `
  -BenchClientCommandBridgeDispatchMode client_direct_command
```
- 行为口径：
1. `run-bench.ps1` 负责单世界单 case；`run-bench-suite.ps1` 负责 dedicated server 外层生命周期编排。
2. 纯性能矩阵统一通过输入器驱动 `triggerSource/core`，默认性能窗口为 `1600 tick = 80 秒`，其中 `warmup=400`、`measure=1200`。
3. 纯性能矩阵结束后会自动执行 `redstonelink input clear`，避免输入 job 污染下一 case。

## Spark 报告直连分析
- 判读顺序：
1. `?raw=1`：优先看 `TPS/MSPT/内存/CPU` 等聚合指标。
2. `?raw=1&full=1`：看线程树、热点树和本地二次聚合。
3. `spark-usercontent`：长期归档原始 `.sparkprofile` 文件。
- 当前 bench 分析建议：
1. 先确认是否真的压穿 `20 TPS`，不要只看 viewer 页面观感。
2. 需要做热点归因时，优先对 `Server thread` 做树结构或调用链聚合。
